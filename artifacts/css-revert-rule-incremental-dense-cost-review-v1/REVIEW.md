The actual f130a3 AB baseline does not skip all same-layer Rule declarations. apply_one_longhand returns from Rule without setting seen or adding a RevertState/longhand bit; the Rule priority predicate returns true, and DeclarationIterator walks parent nodes normally. Thus baseline already processes allN unlayered Rules before the layered floor. Each generated block has opacity:revert-rule plus a unique custom marker, with no same-block opacity alias sibling. Baseline gets this fixture's final value without the identity exclusion needed generally. The gap is not an unavoidable N-versus1 semantic traversal expansion; it also does not justify restoring defective alias/substitution behavior.

AB allocates none of the C-specific metadata for admitted literal Rules. Eager C creates a box, owner map, temporary visited-block set and full-key exclusion set. Incremental adds a prefix set and retains visited blocks alongside growing exclusions. These are allocation families, not measured allocator-call counts. Tables can grow repeatedly. Both indexes insert every declaration in visited blocks, including the custom markers. Dense chains consume most relevant blocks, losing much of the suffix-avoidance advantage.

For a later fresh Rule block with an existing prefix, contains probes the prefix, misses the owner cache, inserts into the visited-block set, reserves/inserts the block entries, probes owners again, then tests the full exclusion key. The Rule arm subsequently gets the same owner again, reinserts the already-known prefix, and inserts the full key. Incremental also enters the reverted-property guard and usually-empty ordinary-cutoff map where AB's Rule did not set that fast bit. These are concrete source operations; no profile or allocator measurement attributes the timing gap among them. The compiled incremental proof establishes representation/lookup/gate invariants, not instruction counts or allocator costs.

Best first trial: remove the separate visited-block HashSet. Under existing unique ownership, stable block contents and completed whole-block insertion, a nonempty block is already indexed iff its first original entry is in owners. Reuse that lookup for deduplication; consume empty blocks without indexing. This removes one allocated/growing table and its insertions, at the cost of probing the larger owner map. It needs a small refinement proof accounting for empty blocks' ghost visited state and noncontinuation after allocation failure/panic. No threshold, new per-declaration field or equality weakening is needed. No speedup is presumed.

A separate later trial could carry the successful full key resolved during admission into the same call's Rule insertion, avoiding repeated owner get and duplicate prefix insertion. It must retain the original identity across substitution and use monotone prefix/exclusion state; first-Rule/absent-prefix paths still resolve owners. Do not combine that with trial1 or add a small-list threshold now: isolate one cost change. Grouped inner sets add per-prefix allocations, particularly for all:revert-rule, and are not the preferred discriminator.

The dense ratio alone neither establishes real-world severity nor mandates blocking delivery: it is a bounded synthetic Rule-heavy cost while C repairs actual failures. Disclose it as a measured tradeoff and judge feature exposure/workloads. It cannot honestly be dismissed as required extra N-versus1 traversal.
