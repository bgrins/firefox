# First resumable substitution caller in the retained cascade

The smallest reusable integration is the existing selected non-custom declaration path, not a special parser for font-size:var(--size). Put the provider continuation in the retained selected-entry attempt and yield its actual lookup requests to the same Context that owns the graph. Keep semantic discovery and final value consumption distinct. This report pins f0d/90ac and the sealed continuation; it implements no adapter and claims no new native result.

## Concrete ownership and call sites

`resume_font_selection` currently verifies the waiting UnparsedValue Arc, calls `substitute_variables_if_needed` synchronously, clears waiting, then retains the parsed declaration. Replace that single synchronous boundary with a retained attempt containing the exact declaration occurrence/cursor and Arc, longhand, owner/session identity, context/flags guard, `ResumableSubstitution<'static>`, and a terminal parsed-result slot. The static lifetime is available for this caller: the actual `UnparsedValue::substitution_property_id(longhand)` returns `PropertyIdRef<'static>` for the true longhand or shorthand. It need not borrow a Name stored beside itself. Custom-property callers would need a separate owned-consumer solution; do not fabricate a static lifetime for them.

An attempt belongs to `MetricPreparation`, whose rollback cursor and prepared declarations already survive a wait. It must not live in a global cache or only in `MetricReferences`, which `perform_metric_action` currently takes and drops when the discovery walk completes. Do not hold mutable map/context/cache borrows inside the engine. Its owned VariableValue/Arc snapshots survive scheduler writes.

Add a lookup-yielding preparation/drain result carrying the declaration occurrence, raw Arc and current SubstitutionLookup identity. The action driver must return that reply only to the matching retained attempt. Existing graph-closed Arc acknowledgement may authorize starting evaluation; it cannot impersonate the result of a lookup. While a request waits, keep waiting/cursor/revert and the engine intact. After terminal substitution, parse once, retain the owned PropertyDeclaration, then use the existing retain/advance logic. A resolved revert/revert-layer/revert-rule therefore advances the actual rollback chain; failed parsing becomes the existing terminal inherited/initial result. Pending does neither.

Factor `VariableDeclaration::substitute_variables` in properties/mod.rs at the real `SubstitutionResult { css, attr_taint }` boundary. Preserve its terminal invalid_non_custom_properties check and source-Arc shorthand cache lookup before starting the attempt. A reused cache result must also have the same authorized input/context generation; the current source-Arc key alone does not certify that stronger condition, so an unproven hit cannot bypass the new lookup protocol. Reuse the existing ParserContext/property identity/CSS-wide/longhand/shorthand tail to finish a completed result; do not create a second parser. Parsed shorthand entries become visible only after successful whole parsing, with the existing source Arc and writing-mode mapping. A new controlled candidate would normally change properties/mod.rs as well as cascade.rs and custom_properties.rs; the old two-file execution owner must not silently omit that role.

The cascade wrapper's uncacheable and Display/Content dependency marks occur once when a selected attempt starts. Preserve them on a same-context pause. Actual lookup evaluation, partial output/taint/token/budget state and typed-attribute raw presence live in the existing continuation. Final property parsing, shorthand insertion, random occurrence indexing and declaration retention happen once on terminal completion. Existing graph/setup attribute queries remain separate effects: the promise is no repeated query by this attempt, not one DOM query globally across discovery and substitution.

## Lookup authority, not map-presence shortcuts

| Request/state | Reply and required authority |
|---|---|
| Custom variable with SemanticOpen, CycleUnsettled, Pending or Applying node | Pending; preserve the exact request. Retain/drive its existing child frame in the same session when possible. A semantic back-edge does not become substitution invalidity merely because the scheduler cannot progress. |
| Custom variable with Complete node, or fully settled cycle | Read its final effective map outcome under the same registration and context guard. Return owned Value for a resolved value, including a valid empty value; return Invalid only for authoritative terminal absence/guaranteed-invalid. A registered cycle can install a valid registered initial value, so CycleSettled is not synonymous with Invalid. |
| Custom variable with no graph node | Neither `visited(None)` nor `start_frame(...)=Complete` proves terminal absence. The latter currently short-circuits absent maps and already-typed values together. Require a receipt from completed custom selection/initialization for that name and current input generation, or schedule/retain unresolved work. A false `seen` has several causes, including reuse of inherited/initial state; it is evidence to interpret with initialization, not a universal validity bit. |
| Unresolved universal alias | In the scheduler-backed adapter, request completion of the custom node and then return its final Value. Do not use Expand to bypass an active registered node or numeric computation. Expand remains the provider's explicit legacy recursive-universal compatibility route; it requires owned selected raw input and appropriate recursive semantics, and is not a settled computed-value certificate. Supporting aliases does not require forcing this legacy route: normal child publication handles them generically. |
| Environment | Call the actual environment getter once for the reached request and retain its owned Value or terminal Invalid under a fixed device/environment/URL context. Do not turn missing style-map entries into an env wait: this API obtains its value independently. Preserve the original env behavior rather than recursively expanding it as a custom variable. |
| Raw attribute | Query once for the request's known namespace, return Attribute(Some/None), and retain that result across later typed-cache Pending. Unknown namespace returns Attribute(None) without a DOM query. Missing raw attr is an observed result, not an absent typed cache. The provider retains the original omitted-type/omitted-fallback empty-string behavior. |
| Typed attribute, raw present | Use the expanded-name node's settled publication to authorize the substituted cache value. Unresolved/unvisited/setup-only cache state yields Pending, even if get_attr returns None. `contains_attr` distinguishes key presence but includes None bookkeeping entries and is not finality. Terminal cycle removal may authorize Invalid; completed substituted text is Value and is then parsed by the existing requested attr syntax. Raw snapshot/cache result must belong to the same element and input generation. |

Guard failure is an invalidated caller attempt, not `SubstitutionLookupValue::Invalid`: the latter authorizes fallback. Do not feed it into the engine merely to escape a stale context. The synchronous `read_current` adapter in the prototype intentionally maps absence to Invalid and unresolved variables to Expand; it must not be used unchanged for this caller.

A size facet is likewise not a general terminal variable reply. It may permit the custom node's typed computation under its existing demand-specific contract; only the resulting completed custom value can answer var(). Generic lookup must not convert VisitResult::ComputedSize into Complete.

## Same-session driving and provenance that still needs implementation

Reuse the action driver's retained depth/semantic-floor boundary for a requested custom/attribute node, without replacing `frame_root` or resetting Context. Factor the existing child poll operation so both discovery and substitution can use it, but retain separate reply kinds: a graph acknowledgement changes lowlink/discovery state; a final lookup reply consumes a value. Do not add generated scheduling prerequisites to CSS SCC edges. Foreign SemanticOpen or nested unsupported work remains an explicit wait; lack of progress is not a cycle policy.

Context currently forgets node publication states at reset, and custom selection discards skipped declarations after applying the current included_cascade_flags filter. The maps retain no general selection-generation or negative-absence receipts. Therefore the adapter needs explicit settled-name/input-generation authority for no-node inherited/initial/absent cases and for any result retained across roots. This is a real missing representation, not a fact that can be inferred from an Arc or a string comparison. For the first integration, keep attempts within the owning session and invalidate on context/flag changes; do not claim this alone establishes reusable cross-root or APPEARANCE_BASE stability.

To relax that restriction later, retain custom selection provenance and the evaluated/skipped prefix: reached gated candidates, exact input outcomes (including negative reads), rollback states, namespace/registration identity and final parsed result. The dynamic FontSize prefix checker must consume those actual receipts alongside the existing skipped-prefix eligibility check. An absolute final AST remains an explicit facet limit; aliases, selected fallbacks and dynamic rollback need no special input grammar. A changed binding cannot be excused merely because the resulting CSS happens to match once.

The actual provider terminal API is sufficient for this non-custom parse tail because it returns CSS plus AttrTaint. A wholesale replacement of custom-property publication is larger: `apply_substituted_value` consumes richer substitution token/taint information and performs registered computation/defaulting. That producer must retain its own readiness boundary. Container-query typed-attribute handling also intentionally bypasses the cache; the selected-cascade adapter must preserve, not silently generalize, that branch.

## First distinguishing implementation tests

Use actual retained selection and the actual property parser, with controlled scheduler publication replies. Evaluate `font-size:calc(attr(data-prefix px) + var(--later, attr(data-fallback px)))`: after prefix3 and Pending --later, repeated polls must not query fallback, requery the prefix, parse/cache a declaration, advance rollback or publish. Complete --later with17px and compare exact CSS/taint and the parsed result with uninterrupted evaluation. Then use authoritative Invalid and require the distinct fallback999px route. Measure substitution-attempt query deltas separately from existing setup/discovery queries.

Add final registered-cycle initial20px versus unregistered-cycle Invalid, present-empty versus Invalid, and no-node absent-but-not-yet-selected versus settled absence controls. Test an alias completed through the retained graph, an actual dynamic revert followed by another declaration, and same-shorthand/different-source cache isolation. A stale flags/session/registration/raw-attribute generation reply must invalidate the attempt without selecting fallback or publishing its cached parse. These controls would reject both naive map-presence admission and unconditional CycleSettled-to-Invalid.

The completed-prefix model's `checked_selection_and_reads_stable` and `checked_visited_rollback_trace_stable` require immutable settled bindings; the resumption model's `done_refines_existing_resolver` and `pending_poll_preserves_entire_machine` cover its abstract resolver. Their premises do not establish these native selection generations, parser effects or map publication authority. The concrete next implementation is the selected-entry continuation plus terminal lookup/finalizer protocol above; true metric feedback, missing prerequisite producers and the new sizeforms crash remain separate, unproven progress obligations.
