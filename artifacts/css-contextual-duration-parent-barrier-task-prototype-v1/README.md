# Explicit traversal-task handoff prototype

`native.patch` is a concrete four-file Rust prerequisite for the parent-publication design. Only artifact copies change. It does not implement a parent barrier, alter root/child traversal order, add a pass, install a native overlay or claim a test repair. Existing callers continue through traverse_dom; no public C ABI is added. The separate four-source base-timing trial is unaffected.

SequentialTaskList::take_tasks transfers queued tasks without running them. A private driver helper finishes the pool scope, collects statistics, extracts task vectors in slot/insertion order, then drops every traversal context before returning to traverse_dom, which executes those tasks immediately. AnimationTaskStyle distinguishes legacy Published input from explicit Prepared(Option<Arc<ComputedValues>>). Existing constructors select Published. A future preparer can consume a task with with_prepared_style; None means an explicitly unstyled target, never a fallback read. The new Gecko trait method uses the owned input directly. The legacy method clones the current primary Arc and releases its ElementData borrow before invoking the same native FFI.

No native caller currently selects Prepared. Current finish_restyle still publishes before descendants and tasks. Selecting a prepared style without private publication would not create a barrier. The next implementation must split resolution/task discovery from publication and release child work only after actual rule sampling and final cascade. This package implements the task boundary without an inline callback holding TLS/ElementData borrows; it does not disguise the remaining phase split as completed.

## Legacy-path semantic change

Previously, dropping ScopedTLS's slot array dropped each ThreadLocalStyleContext in order: its sharing-cache/bloom guards were released, its task-list destructor ran tasks, and later contexts still existed. The prototype removes all tasks first, drops all contexts, then runs tasks in the same slot/insertion order. Task order is preserved on ordinary completion; cache/Arc release relative to other slots' tasks deliberately moves earlier. Sharing caches and bloom filters clear during Drop; rule-cache values are released. This removes outstanding traversal-context borrows before any main-thread task. Actual native compilation/testing must validate the wider cleanup-order change. No equivalence claim covers panic/unwind/OOM paths.

Statistics reporting stays before context destruction and tasks; task time remains excluded. finish_restyle, data.set_styles, Device root publication, child hints and note_children are untouched. Root metrics therefore still publish during traversal before tasks, as before. This patch cannot be cited as fixing that order; there is no re-evaluation or fixed-pass budget.

Published tasks still choose the then-current primary style at execution, rather than snapshotting it at enqueue. The extra Arc protects the selected ComputedValues through the unchanged Gecko_UpdateAnimations call. Before-change and prepared after-change Arcs stay owned by the call frame until it returns. Flags and transition before-change inputs pass unchanged. The old no-data path and Prepared(None) both pass a null after-change pointer; downstream null/display:none handling is not replaced or broadened.

SendElement remains a non-owning E wrapper, not an owning DOM reference. Accordingly the collecting helper is private: its only caller immediately executes the returned tasks within the existing traversal/style transaction. No new batch is exposed to C++ or allowed to survive that transaction. An externally stored prepared batch would require owning target/pseudo handles, generation validation and cancellation/work-coverage rules; this patch does not supply them. Untransferred task lists retain their Drop behavior; transfers empty the list to prevent double execution.

## Source and validation boundaries

Bases exactly match frozen closure captures. context.rs, dom.rs and wrapper.rs also match original build pins. The reviewed current read-only captures join context/wrapper/driver; dom.rs is supported by frozen/build identity, not a new current read. driver.rs lacks a separate build pin. SOURCE-ROLES records these distinctions. Indexed caller discovery found one task constructor in matching.rs. Changed execution/mutation matches enumerate both task variants and both style-input variants. No matching.rs or animation admission predicate changes.

Static3b66f0/0 applies/reverses the patch in owned scratch with zero fuzz/offsets, parses all four full candidates with Rust2024 rustfmt, and compiles exact extracted SequentialTask/SequentialTaskList methods plus the driver's transfer tail against mock interfaces using rustc1.97.1. Six tests pass: late Published selection; owned Prepared input despite exclusive published-data borrow; explicit null; all-context release before ordered tasks; extraction without double execution; legacy untransferred Drop. Two compiled mutants fail: reading Published instead of Prepared, and running tasks before contexts drop. The harness uses std::sync::Arc/mock TElement/TLS, not Servo Arc, Gecko ElementData, the real pool or generated bindings. This is not a Stylo crate build, browser test or native lifetime proof.

Initial parser run e8b6c8 used Rust2021 and rejected existing let-chains in unchanged dom.rs. Rust2024 produced7204ed/0; making the helper private was followed by final3b66f0/0. No installed toolchain changed; scratch was removed. The checker writes only artifact harness/logs/receipt and owned temporary files, so do not rerun after sealing without a successor.
