The source declares `GridItemInfo::mBaselineOffset` as `PerLogicalAxis<nscoord>` and both frame properties as small nscoord values. The SetProp lambda first selects either the offset or zero, then replaces a negative adjustment by zero, and only otherwise negates for last baseline. Thus a defined signed32 input gives an encoded value in [−2147483647, 2147483647]. INT32_MIN input follows the clamp branch and removes the property; it never reaches the negation. Zero is removed, not stored. `encode` and `stored` preserve this order, including zero and content=false/last=true combinations.

For present values from this writer, the reader's positive/start or negative/end choice gives the mathematical magnitude safely: the possible minimum negative stored value is −2147483647. The target's magnitude at zero is harmless as a mathematical extension, but the actual absent-property path does not execute the reader's side update or set its flags. No target clause claims those other side effects. The unconditional positive-first/last and nonnegative-magnitude identities also apply mathematically outside signed32; their native interpretation still needs the input bound.

Grid-axis to child-property mapping is a permutation: orthogonal children exchange I/B properties, otherwise they retain them. InitOffsets initializes padding first and then applies the block property at most once unless grid-measuring, and the inline property at most once unless shrink-wrapping. These affect distinct logical axes. The single-delta per-axis bound matches that schedule; it is not a sum of both grid offsets into one axis. Suppressed applications and the later scrollbar zeroing only reduce the relevant contribution; other lifecycle/reset assumptions remain outside the model.

The range constants are correct. Starting from arbitrary signed32 padding, adding a magnitude in [0, 2147483647] gives [−2147483648, 4294967294]. Adding one signed32 border gives [−4294967296, 6442450941]. Four signed32 side values plus one baseline magnitude give [−8589934592, 10737418235]. These are useful wider bounds, not nscoord-fit claims. The positive original-padding premise in `nonnegative_side` is explicit and does not assert that all native padding overrides satisfy it.

The three witnesses are jointly concrete and strong enough for their stated purposes: maximum positive offset becomes the largest-magnitude negative stored value; minimum signed32 offset is removed; maximum padding plus a valid delta of one exceeds signed32. The last is an admitted model state, not a demonstrated browser state. `border_reconstruction` is an exact integer cancellation identity; it is invalid as a justification for subtracting previously wrapped narrow fields. Acquisition and composition must be widened before the operations.

Scope remains appropriately limited. Prior baseline-offset computation, theme/style conversions, supplied padding/border, property lifetime and additional writers are not proved. A signed32 declared field alone cannot rescue earlier undefined arithmetic. Once offset or property producers widen, the fixed constants require rederivation; widening padding/border also invalidates the composite bounds. Even safe clamp-before-negation on a wider signed type would not make arbitrary same-width padding-plus-delta total. The target must not be used to discharge full containing-block range, unconditional padding nonnegativity or native execution.
