# Snapshot verification cost probe — prepared, unexecuted

Open `index.html` as a local file and press Run. Loading the page or a URL fragment never starts a trial. No server, test harness, receiver or dependency download is required. JSON can be copied from the textarea or downloaded by a separate button. This is an exploratory local cost comparison, not a performance acceptance threshold or replacement for controlled CI profiling.

The page creates fresh CSS-animated elements per case, pauses their animations at 750ms, and waits two frames before initial inspection. Default masked mode has a fixed 32px font animation and a contextual fade duration; unmasked mode has only the contextual fade. Two workloads alternate a container class: outline-color transparent↔blue (unchanged duration input) and authored font 16↔32px (changed contextual duration input). Both use the same descendants and selector shape. No pseudo cases are included.

Each warm-up/measured iteration waits for a frame, then synchronously times one batch class mutation and one explicit `getComputedStyle(lastTarget).opacity` read. The read is the requested style-flush boundary. It is not proof that the engine performs exactly one internal flush, visits every target, or runs the new verifier. There are no geometry, timing-object or membership reads inside that measured region. The report separates mutation, style-read and total durations; total is the main comparison, since extra performance.now calls and timer quantization can dominate short subintervals. Raw samples preserve direction, index and observed last-target opacity. Each case has min/p10/median/p90/p95/max/mean, not an absolute pass threshold.

Setup/allocation, initial animation acquisition, settling frames, warm-up, frame waits, final inspection and cleanup are outside the samples. Timing excludes paint, but prior paint/GC/system activity can affect later samples. Final inspection reads every target and reports opacity/font/outline/fade-duration/progress histograms plus first/last examples and held-time checks. It may itself process additional work; inspect the per-iteration opacity before attributing a final histogram to the timed boundary. The masked relevant-input workload can produce different semantic outputs across builds; those differences must remain visible rather than being treated as a faster equivalent computation. There is no numerical correctness verdict or hidden native-causality claim.

Settings can be shared in a fragment, for example:

`index.html#label=original&count=200&iterations=50&warmup=10&rounds=3&order=outline&mask=yes`

Limits are 3000 elements, 500 iterations, 100 warm-up iterations, 10 rounds and 3 million element-iterations per workload. These are operator workload bounds, not timing thresholds. Small/larger presets only change controls. Stop is checked at a frame boundary. Becoming hidden marks the run incomplete when the next frame returns; a background page may wait for visibility before requestAnimationFrame resumes. Do not reuse incomplete/hidden results for paired timing claims. Errors retain prior completed cases and measured partial samples when available; setup errors can occur before a case record exists.

## Original/candidate comparison protocol

1. Root supplies separately authenticated original and candidate binaries built in the same configuration, with the exact source delta recorded outside this page. A user-agent string and editable label are not build provenance. Never reuse this probe to bypass the native build/restoration owner.
2. Use the same machine, power settings, profile policy, viewport, display scale, foreground state and page bytes. Disable unrelated workloads; do not compare a stock release build against a local optimized build to attribute snapshot overhead.
3. Start with the small preset to validate acquisition and final histograms. Then choose one fixed workload size that is large enough relative to timer resolution. Record all samples, including outliers; do not select only the fastest run.
4. Run a balanced original→candidate→candidate→original block (and reverse in a later block), with identical count/iterations/warm-up/rounds/mask. The page alternates workload order across rounds; also reverse the starting order across blocks. Save each JSON. Repeat unmasked mode separately, not pooled with masked mode.
5. Check complete=true, becameHidden=false, expected case/sample counts and allReportedAnimationsHeld. Compare each workload/direction/config separately using per-round medians and full distributions. Report raw millisecond differences and ratios only when nonzero baselines and sufficient resolution permit. Check final values and per-iteration opacity before calling workloads equivalent. No one-run significance or universal performance claim follows.

The unmatched cost includes selector matching, animation updates, style flush machinery and JavaScript, not solely GetBaseContextForElement. Allocation and GC from the verifier may appear in distributions; isolating that mechanism would require a separate authenticated profile. Root/rem cache and collection correctness remain separate tests. Existing nine-case and preservation fixture bytes are untouched.

Static preparation: node syntax 95b464/0; pure checker 7a7051/0 covers summary interpolation, valid bounds/nine invalid configurations and the single explicit mutation/read in the timed region. No DOM, browser, build, native, Git or profile operation was executed. Layout/appearance is unverified until an explicitly requested browser run.
