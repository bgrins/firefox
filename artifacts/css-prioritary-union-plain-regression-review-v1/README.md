# Candidate regression: plain identifier union

The completed ordinary lane changes `Selected identifier color-scheme dependency: union-plain` from original PASS to candidate FAIL. The candidate records `--v: normal` and `color-scheme: normal` in both phases, where the unchanged fixture expects light and then dark. The original PASS does not carry those individual samples. Raw callback records agree with the saved behavior comparison. The repair observation gate remains false. This review reads only the two completed ordinary lanes approved by root; the whole candidate owner was still active, and no terminal or restoration outcome is inferred.

The frozen V3 source explains the failure through an interaction between an existing conservative edge and a newly discovered selected edge:

1. The fixture registers `--v` as `<custom-ident> | <color>`, initial `normal`, and selects the valid identifiers `light` and `dark`. Its winning declaration is `color-scheme: var(--v)`.
2. Unchanged `find_non_custom_references` adds `--v → ColorScheme` solely because the registration can accept COLOR. Neither selected identifier actually requires scheme-dependent color computation.
3. V3's `NonCustom` traversal examines the eligible winning declaration and calls `visit_value_references`, adding `ColorScheme → --v`. This selected reference is real; it is not an overridden declaration or an unused fallback.
4. The resulting two-node SCC invokes `handle_loop`: the custom property takes its invalid/default route, and ColorScheme is marked invalid. Its prepared chain is discarded and the invalid-priority path applies. The recorded `normal`/`normal` endpoint matches this source path.

This is a source-derived explanation, not an instrumented observation of the SCC. The original collector's `might_have_non_custom_or_attr_dependency` accepted plain variable declarations only for FontSize/LineHeight; other properties needed an ATTR flag. Plain ColorScheme therefore had no recorded return edge in the original graph. The unused-attr fixture variants do pass that collector filter. V3 removes this accidental distinction by inspecting the selected declaration directly, exposing the pre-existing coarse union edge in another case. The demonstrated plain-case regression belongs to the candidate; these records do not establish that shipping Firefox fails this plain case.

The smallest defensible next experiment is to compose V3's selected-declaration traversal with the existing COLOR-only selected-AST/default refinement, without adding pure-Image eligibility. Preserve first-success syntax selection, retained specified AST computation, metadata, CSS-wide/invalid-initial handling and the late cyclic-default dependency hook. For this fixture the retained CustomIdent has no ColorScheme dependency, so the false outgoing edge disappears while the legitimate winning `var(--v)` edge remains.

The existing implementation of that refinement uses provider/value helpers shared with the image work. Those helpers are a dependency of that implementation; the image-only bugfix is not a semantic prerequisite for this regression. A separately authored equivalent classifier/default repair could be independent, but no smaller complete repair has been established. Skipping plain winning-variable edges, checking only literal `light`/`dark`, or excluding ColorScheme from selected traversal would restore a graph omission or special-case the fixture. Clearing all COLOR edges would lose genuine system-color/light-dark dependencies and default ordering.

The proposed composition is not yet a patch or a validated merge. In particular, A-only was exercised with the older collector. Its prepared custom-value lifetime, pre-pop late-default hook, changed NonCustom identity and V3's post-pop invalid-priority publication must be reviewed together. Preserve all existing controls and compare a fresh original/candidate suite, including genuine cycles and contextual defaults. Separate passing experiments do not establish correctness of the composed graph. No native, browser, Git/index, control or runtime file was changed.
