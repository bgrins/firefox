Artifact-only WPT proposal for shadow descendants losing state during moveBefore(). No native change, index mutation, or signing action is included.

The CSS animation page has 12 synchronous callbacks: root/light-child/shadow-child crossed with no move, self-reference, original-gap and cross-parent/restoration. Every case calibrates a paused CSSAnimation at 375 ms (3.75px margin), keeps the declaring tree and keyframes unchanged, and checks animation/effect/target identity, playback state/time and computed style. All three snapshots are collected before outcome assertions; failures include complete phase JSON. Root/light and no-move cases are positive controls. No animation.ready or animation-frame wait is used.

The separate custom-element page adds five synchronous callbacks: root/light self-reference controls, single-shadow self-reference, and nested-shadow self/cross-parent restoration. It requires connectedMoveCallback instead of disconnected/connected callbacks and records the same target/tree/position before assertions. It deliberately omits the already existing single-shadow cross-parent test.

Known coverage: upstream custom-element-move-reactions.html already tests a custom element inside a moved shadow root. Its Gecko metadata explicitly marks that callback FAIL (Searchfox c8af90/d2a472). WPT sync bug 2064889 / PR62065 lists that failure; later sync bug2080017 also records it. These sync tasks do not establish a native defect-tracking ID or novelty. The new cases add animation identity and self/nested coverage for the same diagnosed context-loss family, not separate accepted bugs.

Existing continue-css-animation-left.html checks a moved animation on the root. css-transition-cross-shadow.html moves the animated element into a different shadow tree. Neither is equivalent to preserving an internal descendant with its own unchanged declaring shadow root; this is a bounded suite check, not a global novelty claim.

Spec basis: the DOM move algorithm visits shadow-including inclusive descendants through moving steps, without insertion/removal steps. HTML custom-element reactions invoke connectedMoveCallback for a moved custom element; disconnect/connect fallback applies when that callback is absent. CSS Animations retains a running animation while its animation-name and applicable keyframes remain present.
