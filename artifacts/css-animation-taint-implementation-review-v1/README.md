The recursive-alias case is a particularly useful falsifier. With --alias:var(--d,3s) and animation-duration:var(--alias,1.5s), an active tainted --d should first give a tainted alias; the outer sink then selects1.5s under the literal rule. Propagating the final duration property_id into unresolved alias computation and rejecting the inner var too early could incorrectly select3s and clear the metadata. Both already-computed and partially-resolved alias routes need equivalent outcomes. A further alias hop, cycles/guaranteed-invalid, and a fallback that itself references a tainted property should follow the existing resolver's dependency processing, not a new animation resampling loop. Whether unused fallback references count toward infectious marking needs an explicit spec interpretation; this design does not quietly equate syntactic references with selected replacement values.

The smallest plausible independently reviewable fix is therefore a substitution feature, independent of timing snapshots: unregistered same-element direct marking plus infectious aliases, metadata-preserving computation, non-animatable-sink fallback, and semantic invalidation tests. Producer, propagation and consumer must land together to deliver observable behavior. It should not modify nsAnimationManager duration selection, task ABI, EffectCompositor, native timing ownership, parent-publication or descendant scheduling. A tiny consumer-only guard or marking only animation-origin values is not a correct implementation of property-level scope. Conversely, adopting value-level scope merely because it is easier is a policy decision requiring compatibility/spec agreement. No compile-ready patch is offered while that decision is open.

For a name-based implementation, the missing source-of-truth design is substantial: stylesheet/tree-scope visibility, keyframe edits/removal/renaming, rule activation, ordinary important winners, and base recascade must agree on the marked set. Deriving it only from already-created animations can miss initial animation-name/duration substitution and create a bootstrap dependency. A process-global interned-name flag would leak between documents/shadow scopes and is not justified. For a value-based implementation, parser/effect-produced provenance plus infectious resolved values is mechanically smaller, but loses taint when the animated declaration is absent from the selected cascade; that is precisely the policy split now exposed. Inherited taint, inactive/unused keyframe rules, var references merely appearing inside keyframes, registered properties, WAAPI effects and transitions remain explicit scope questions. Do not claim this active CSS case settles them.
