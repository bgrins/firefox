# Enclosing grammar rollback after successful typed parsing

This is a post-discovery model of the observed grid shorthand counter leak. Source inspection found the compound failure, then the browser confirmed one-row and two-row offsets; Lean did not discover the native defect. No new bug count or native acceptance follows from this artifact.

Rollback.lean is byte-identical to the sealed random-index-audit-v2 model. Enclosing.lean adds a sequence of locally successful typed parses, then an enclosing grammar decision. Each typed success commits its index increments, as the existing transaction definition requires. If the enclosing grammar rejects its temporary value, cursor rollback alone leaves the accumulated count. A retry then starts after that leaked prefix. The outer transaction restores the entry count instead; it must not reset an arbitrary prior counter to zero. If the enclosing parse succeeds, all its committed indices remain.

The seven declarations establish: arbitrary chunk sequences advance by their sum; each inner success corresponds to the existing transactional select; a rejected outer attempt without its own guard shifts retry indices by that sum for arbitrary prior state; an enclosing guard restores the exact entry state; accepted outer parses preserve all indices; positive failed-prefix consumption changes the retry result; and the observed 1/2/1 offsets yield keys2,3/4,2/3 while the guarded two-row case yields1/2. Three false controls independently reject inner-only equivalence, resetting the entry counter to zero and rolling back successful outer parses.

Premises and limits: State.count uses unbounded Nat, not native i32. Cursor is an abstract consumed-input position, not a token/byte offset model. Each chunk summarizes a successful typed parse that increments by its number of random functions. The enclosing rejection discards all owned parsed values without exposing an AST; other parser side effects, diagnostics, failure unwinding/panics and arbitrary alternative callers are outside this model. Retried selected parsing is modeled successful. Keys are the existing one-based positional keys; no PRNG, sample inequality, CSS geometry, borrow checker or native refinement is proved. The local-success-to-advance law is proved, but no automatic correspondence from Rust control flow is asserted.

Native mapping: grid::parse_value tentatively calls grid_template::parse_grid_template. Successful row track parsing precedes column failure on auto-flow. The rejected tuple does not escape. Counter restoration belongs around that entire try_parse call. The seven typed-finalizer wrappers restore their own Err outcomes, so they correctly keep these successful row increments and cannot cover the later caller failure. The actual fix must call the helper through ParserContext.property_declaration_context; the earlier v3 draft's wrong receiver was a separate caught compile defect and is not validated by this model.

Browser evidence is the sealed css-random-grid-caller-observation-v1: three indexed discrepancies and four controls, all28 expressions supported. The model's examples reflect those index offsets, not the sampled numerical outputs. The normative key rule and shorthand grammar are traced in the sealed caller-transaction audit. The current v4 native source remains subject to actual compilation/behavior testing.

Scratch is removed. No canonical Lean library, browser, build, source, index or epoch is changed. Standard logical axioms are reported explicitly; this is not an axiom-free blanket claim.
