# Pending progress: bounded source audit

No starvation defect is established here. The tri-state proposal distinguishes Pending from DispatchAttempted, but does not itself arrange a future attempt for every Pending producer. This audit identifies an existing non-author retry path and a narrower property-only validation boundary. It changes no native source, runtime, Git, application or canonical state.

## Paths that consume or retry

The frozen matching.rs candidate queues CSS_ANIMATIONS | EFFECT_PROPERTIES when computed animation properties change during animation-only traversal. Rust SequentialTaskList destruction executes those tasks before traversal returns. This is distinct from ServoStyleSet::RunPostTraversalTasks, whose indexed task cases concern font loading.

The frozen StyleDocument runs compositor PreTraverse before ordinary traversal and explicitly again after its first traversal. Eligible Pending entries can therefore be consumed in the same flush. Its explicit final traversal has no unconditional additional compositor pass. StyleNewSubtree likewise has a FinalAnimationTraversal boundary. RestyleManager clears the restyle root around post-traversal processing and at exit; StyleDocument returns before PreTraverse when there is no restyle root. These facts do not prove that a particular residual entry lacks another scheduling source.

A changed applied duration has such a source: SetSpecifiedTiming → NotifyEffectTimingUpdated → Animation::UpdateTiming → UpdateEffect(IfNeeded), then NotifyAnimationUpdated when a timeline exists. DocumentTimeline inserts the animation and requests a refresh update. AnimationTimeline ticks it once even when it no longer needs continuing ticks, then removes it if appropriate. Thus paused does not mean that a timing update cannot arrange a later request. On that tick, KeyframeEffect requests Standard or Throttled only when progress/iteration differs from the last WillComposeStyle marker. Throttling, timeline visibility/eligibility and target/context guards still apply. WillComposeStyle stores a preparation marker; it does not prove composition occurred. [Animation timing implementation](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/dom/animation/Animation.cpp)

The tri-state RequestRestyle retries Pending only outside Servo traversal, compositor pre-traversal and style refresh. Forced-throttled posting selects only Throttled, preserving prior admission rather than automatically waking Pending. HasPendingStyleUpdates is a presence test. Computed-style logic additionally checks pending ancestor work, and UpdateOnlyAnimationStyles still enters the root-dependent StyleDocument path; neither is an unconditional drain. [Computed-style flush selection](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/layout/style/nsComputedDOMStyle.cpp)

## Property-only boundary

UpdateProperties can request Layer after changed base values or resolved keyframe properties. NotifyEffectPropertiesUpdated only considers replacement checking; it does not perform the timing-update timeline registration. In the CSS animation manager, script-owned duration is retained. If other timing fields remain equal, SetSpecifiedTiming returns early, while EFFECT_PROPERTIES can still rebuild values. This narrows the unproven scheduling assumption: property-only work generated late in traversal is not covered merely by pointing to the duration-update tick. It is not evidence that the entry is actually lost. [CSS timing ownership](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/layout/style/nsAnimationManager.cpp)

## Focused observations

Keep two separate experiments:

* The sealed acyclic two-hop probe uses a fixed root-font driver, a rem-duration middle font animation, and an em-duration child opacity animation. Initial values are middle1000ms/font28px and child1750ms/opacity3/7; final values are middle2000ms/font22px and child1375ms/opacity6/11. Child reads precede membership and seek interventions. Root-rem invalidation may broaden traversal, so PASS would not identify the internal consumer.
* The proposed property-only probe changes a parent's font16→32px. A child's CSS duration calc(1em / 16px * 1s) changes1→2s to exercise the candidate task guard, while updateTiming owns its applied2000ms duration at currentTime750/progress.375. Width keyframes1em→3em resolve16→48px initially and32→96px finally, yielding28→56px. Drain initial one-off ticks before the trigger. Collect child width first, then passive sampled frames, before timing/membership or rescue. Ordinary font mutation and literal px keyframe controls distinguish setup and value resolution. No middle timing change is needed.

Computed getters themselves may flush. Bounded frame observations are not an autonomous-progress proof, and no request is identified with one model step. Null timelines, hidden/frameless targets, cross-document movement, replacement, reentrancy and general feedback convergence remain outside this audit. No self-feedback fixed-point oracle, native refinement, accepted fix or new bug count is claimed.
