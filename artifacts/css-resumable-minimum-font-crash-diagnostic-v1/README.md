# Integrated minimum-font crash diagnostic

The saved integrated-v2 candidate completed the 21 core callbacks and four size-form callbacks, then minimum_off crashed with zero callbacks. minimum_on and inputs did not run. The native panic is the unchanged `substitute_all` / `run_one` assertion requiring Complete or CycleSettled. The stack enters run_one from the custom-property root iteration. The saved log contains no root name, action progress, or computed-size readset branch, so it does not establish which selected form or prerequisite caused the stall. This is a prototype failure, not evidence of a released Firefox defect.

This separate three-source candidate adds diagnostic output only. Cascade is based byte-for-byte on integrated-v2 b6d9af3c except the logging delta; provider52a35022 and properties/mod7ae98c9e are unchanged. The published DeclarationIndex u32 change remains. The full patch applies to the same published three-file baseline as the parent. No fixture, preference, expectation, owner, or live native file is changed.

Eight ComputedSizeReadset exits have distinct labels. The existing nonterminal action arm reports its actual progress, root, owner, index and target before breaking with the same VisitResult. Before the same terminal assertion, a snapshot reports the retained root/result, frames and waits, pending lookup kind/name, size selection completion/cursors, and complete/active/claimed/ensured/seen states for the size/family/appearance/language/text-scale/minimum-ratio/zoom priorities. Output reads borrowed state; it does not take, clone, clear, resume or re-evaluate a substitution. Formatting may allocate and changes stderr output/timing; it is diagnostic instrumentation, not a semantic repair. No additional Arc API or Debug derivation is introduced.

The fixture contains both registered --metric:1ch and --len:1em, with keyword-derived omission/inherit/percentage cases and an Appearance attr dependency. Concrete branches to distinguish are an unresolved nested lookup, a generated ordinary prerequisite, and a rejected computed-size readset such as Family already complete before Appearance. These are hypotheses, not observed branch assignments. A readset rejection must not be fixed by treating Pending as invalid, suppressing the assertion, or relaxing the certificate after consumers used size. The next repair depends on the recorded branch and must preserve selected declarations, effect ownership and final-value stability.

The existing graph extraction replaces computed_size_ready and accepts_computed_size with false and uses a native-unit readiness facade. It cannot reproduce this native computed-size/minimum/family path faithfully. No extracted failing native case is claimed here. The new check instead verifies the instrumentation boundary: removing only the diagnostic additions exactly reconstructs parent source; two mutation controls reject removal of the terminal assertion and insertion of a state-clearing effect. Both parent and full native patches apply and reverse with zero fuzz/offset in removed owned scratch; rustfmt passes. This is not a Rust typecheck or a browser run.

The page buffers multiple measurements before reporting callbacks. Zero callbacks alone does not identify the failed getter/form. The unchanged fixture is deliberately retained; if the root/action snapshot still leaves ambiguity, a separate fixture-only marker successor can print immediately before existing getters without adding reads or changing expected results. That successor is not part of this package.
