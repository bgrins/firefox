# Static contextual easing and sharing diagnostic

This is a separate, unexecuted follow-up to the sealed 293-case paired plan. It must not delay or silently change that plan. The callable observeContextualEasingSharing function returns ten cases, thirty phase snapshots and ninety target records, retaining unsupported cases as diagnostics rather than treating them as success.

For both animation-timing-function and transition-timing-function it checks sibling-index Steps, sibling-count Steps, Bezier y, Linear output and Linear second input. Three identical-class div targets use the same rule: two share a parent, while the third has a different parent and sibling count. They have animation-name:none and transition-property:none. No animation is created; each sample records getAnimations().length and both disabling properties. This removes the active-animation exclusion present in the earlier lifecycle tests, but does not assert that native style sharing actually occurred.

The first holder starts with target indices1/2 and count2; the second target has index3/count3. Prepending to the first holder and appending to the second yields indices2/3/3 and counts3/3/4. Removing both extras restores the original arrangement. Thus the second holder's count changes while its target index stays fixed. All literal references for inputs1–4 are created once before sampling in a separate holder; there are no reference style writes during mutation phases. The only intervening writes are the two sibling additions/removals. Target elements have no ordinary contextual property that would independently install sibling dependency flags.

Evaluation requires admitted CSS, nonempty literal calibrations, computed values equal to the independently canonicalized literal references, repeat stability, exact recorded DOM index/count sequences, and zero active animations. Original rejection is a diagnostic baseline, not a new defect count. A candidate mismatch could indicate value computation, dependency invalidation or sharing trouble; this browser probe alone cannot identify which or prove the internal cache path. The existing source audit reports sharing guards for active animations, sibling-index and cross-parent sibling-count, so no missing guard is asserted in advance.
