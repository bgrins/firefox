This small unexecuted WPT package adds six active-value taint controls on two pages. It preserves the earlier generic sink fixtures. All drivers use literal 2s duration, pause at 750ms after ready, and avoid animation-duration variable inputs. No native patch, browser run or new execution framework is included.

The alias page uses active --v:horizontal-tb, --a:var(--v,vertical-rl), and --b:var(--a,vertical-rl). Its alias and alias-hop writing-mode declarations use outer fallback vertical-lr; a third callback uses literal vertical-lr. All three calibrate computed --v, --a and --b as horizontal-tb. Thus rejecting too early while resolving a custom property, and selecting its inner vertical-rl fallback, cannot satisfy the alias calibration even if the final sink happens to look correct. The ordinary --v declaration changes vertical-rl→vertical-lr while the active value remains horizontal-tb. The sink must retain the distinct outer fallback vertical-lr.

The metadata page initially has only constant opacity:.5 in the active hold keyframes and ordinary --v:vertical-rl. Direct and alias writing-mode initially use vertical-rl; the literal control is vertical-lr. A single style-text mutation adds --v:vertical-rl to the same active keyframes while retaining opacity:.5. The custom-property tokens stay vertical-rl, but the now-animation-tainted direct and alias references must select outer fallback vertical-lr. Both initial and final declared values are calibrated; the current animation/effect and fixed timing are retained. This challenges equality/cache paths that ignore a taint change when tokens are unchanged. It is not a proof of any native cache key or producer path.

Both pages collect the first sink read and three passive-frame sink reads before timing details and current membership. Assertions run after complete normal collection and attach the full trace to failures. Acquisition errors may still stop collection. Passing assertions do not archive a full numeric trajectory without an external receiver. Getter flushes and frame samples do not establish native traversal counts or general liveness.

Current [Variables animation taint](https://drafts.csswg.org/css-variables-1/#animation-tainted) includes references through other custom properties. [Replacement steps 3–4](https://drafts.csswg.org/css-variables-1/#replace-a-var-function) reject tainted inputs only at a non-animatable receiving property and choose its supplied fallback. [Writing-mode](https://www.w3.org/TR/css-writing-modes-3/#propdef-writing-mode) is such a sink; custom properties themselves remain animatable. These fixtures actively apply the changed keyframes on the same element, and do not depend on inherited taint, inactive unrelated rules, registered-property behavior, or a pre-own timing exception. Under either property-name or active-value taint policy, the tested new active value is tainted.

Ordinary-winning-value preservation (for example an important ordinary declaration overriding an animated value) is deliberately outside these normative assertions. Its compatibility policy is disputed between draft name-level wording and Blink value-level behavior. Any such follow-up must be a separately labeled observation, not silently added as a required PASS here.
