# Declaring-root lookup: known ordinary animation boundary

This is a compact diagnostic of existing WPT coverage, not a newly discovered defect, a candidate fix, or a new accepted count. No native source, browser, build, Git index, or runtime state was changed. The current accepted ledger (144 accepted / 145 tracked) has no animation-name declaring-root lookup repair; its related keyframe invalidation, interpolation and easing fixes do not claim this scope.

[CSS Shadow 1 name resolution](https://drafts.csswg.org/css-shadow-1/#shadow-names) makes animation-name a reference carrying the stylesheet root. Global lookup starts there and then searches ancestors. Thus an outer ::part rule selecting an animation must not switch to a same-name rule in the target's inner tree.

Current lookup_keyframes(name, element) instead asks lookup_element_dependent_at_rule for the first applicable rule data containing the name. Its first candidate is the element's containing tree, and the interface receives no declaring reference root. A new (rule, scope) return value can correctly describe this selected rule while still retaining the preexisting winner mismatch. That transport must not be presented as full normative lookup repair.

Existing tests already isolate this: animation-name-in-shadow-part-outer-match.html declares green outer and blue inner keyframes but applies animation from outer ::part. Its reference expects green; Gecko metadata explicitly expects FAIL. The complementary inner-match test applies the declaration inside and expects its green inner rule. The broader animation-name-in-nested-shadow.html also has expected FAIL metadata. CHECK.json pins the current exact tests/metadata without duplicating their bodies.

`await observeAnimationNameDeclaringRoot()` returns nine snapshots from three literal-only cases. Outer collision must stay green; inner-declaration control must be blue, green, blue when its inner definition is removed/restored; outer-only control stays green. Direct literal references, support, actual animation count/name/keyframe colors, repeated computed values, and finally iframe cleanup are recorded. Expected current failure is the outer collision choosing inner blue before removal and after restoration. This is a source prediction until root executes. No contextual math, easing admission, tree-counting fallback, or proposed scope transport is needed.

This diagnostic does not prove nested-slot/exportparts/UA/user lookup completeness. No new formal model is warranted for simply restating this existing three-case selection counterexample. The wider integration still needs root-preserving references, correct selected declaration scope in evaluation, dependency publication, and animation-only/self-dependency policy.
