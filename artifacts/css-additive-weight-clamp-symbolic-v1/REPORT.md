# Additive post-clamp versus generic pre-clamp

Two new counterexample queries are UNSAT: for every binary32 leaf bit pattern, local `max(Integer::resolve(...), 0)` equals the generic NonNegative clamp followed by Integer resolution, separately for historical HEAD90 rounding and accepted118 rounding. One omitted-local-clamp query is SAT and retains its exact model. These are Z3 symbolic IEEE/bitvector results, not Lean certificates, compiler refinement, browser evidence, or canonical coverage credit.

The complete common.smt2 is byte-identical to the reviewed css-integer-range-symbolic-v1. The only new arithmetic is `postNonnegative`, a signed bitvector comparison against zero followed by zero or the existing rounded/saturated i32 value. Both obligations fix the shared mode to NonNegative and compare this result with `round32(candidate)` or `round64(candidate)`, where candidate is the existing pre-resolution clamp. There is no restriction on raw bits: NaNs, both infinities, signed zeros, subnormals, and finite/saturating values are included. Independent zero-sign choices in the inherited max model remain unconstrained.

The actual source route matters: Integer::resolve obtains `calc.as_number()?.get()`, and NoCalcNumber::get normalizes NaN to zero and bounds infinities to finite f32 extrema BEFORE rounding/casting. The inherited SMT get function models precisely that boundary. Thus NaN does not literally reach the native cast, and infinity reaches it only through finite extrema and subsequent saturation. The earlier local proposal POLICY.md's direct-special-value-to-cast table reaches the same final values but is a hypothetical arithmetic shortcut; this capsule supplies the accurate source-route clarification without modifying that sealed proposal.

The source bridge requires the SAME already-resolved Number leaf in both routes and the pinned normalization, arithmetic, floor and signed32 saturation semantics. It does not prove arbitrary calc tree resolution, contextual availability, parser admission, compiler lowering, or that every bit pattern is reachable through a CSS spelling. The local helper's unresolved None case is unchanged and outside the leaf equality query. Inline already-valid nonnegative integer weights require no floating-point conversion. The preexisting conditional list-ordering model is reused conceptually; none of its results is recounted here.

Historical f32 addition may still round certain positive inputs incorrectly. Both compared routes in that epoch retain the same old rounding expression; equivalence is not correctness of historical CSS integer rounding. Accepted118's promoted expression is modeled separately, not silently substituted into HEAD90.

The SAT omission witness is a finite negative input below signed32 minimum: both old epochs saturate to MIN, while the local helper produces zero. Replay independently checks the model's bit pattern and signed outputs; it does not compile a new native facade. The concrete witness establishes nonvacuity of the new post-clamp, not new browser reachability.

Replay uses the existing pinned Z3 binary, 55-second solver and 60-second process timeouts, retained stdout/stderr, strict expected status, and authenticated query/source references. Final evidence is results-final/RESULT.json and WITNESS.json; the earlier results directory records the same three query outcomes before the additional witness/source-reference checks. Unknown, timeout, solver error or nonzero exit cannot pass. No native, index, browser, canonical library or build products were changed.
