# Unpublished animation restyle and publication prerequisite

This is a concrete two-file artifact patch over the sealed task-handoff context and experimental base-timing matching postimage. It is not a live native patch, compiled Stylo crate or complete parent publication barrier. The base matching policy remains experimental; composing these artifacts does not establish that timing policy is normative or ready to land.

The new path performs actual existing operations, rather than returning an invented completion certificate:

1. prepare_restyle retains the old primary/eager-pseudo Arcs, original publication flags and owned ResolvedElementStyles. It invokes animation_update_task on a clone of old ElementStyles, retaining existing transition-before-change processing on the provisional new styles. The result is one optional explicit-input task, not a task added to TLS and not a data.set_styles call. Its after-change Arc is selected after transition preparation may have replaced the provisional primary.
2. After the caller releases every traversal/data borrow and executes that task, PendingRestyle::recascade_animation_rules derives ElementCascadeInputs from the unpublished primary and eager pseudos. It calls the real replace_rules for CSS animation/transition levels and the real StyleResolverForElement cascade with default parents. No process_animations or transition discovery occurs in this recascade. Animation-only context is required. Exact-target compositor preparation remains an external prerequisite; this method does not implement it.
3. try_publish reacquires the stored target's ElementData, rejects missing data or changed original primary/pseudo Arc identities, and requires the original publication flags. On rejection it returns both PendingRestyle and the proposed resolved result, without publication. On success it marks restyled state and invokes the extracted publish_restyle body. That body is byte-identical to the original commit/root Device cache/damage logic after task discovery. Publication does not discover tasks again.

Existing finish_restyle still calls task discovery once followed immediately by publication. The new animation_update_task is an exact transformation of both original enqueue branches to return Option; the old process_animations wrapper enqueues that same optional task. The native ordinary path therefore retains its immediate-publication sequence. No driver currently calls prepare_restyle. Nothing in this package changes the first-read result or releases children at a new point yet.

## Required caller contract

PendingRestyle contains a nonowning TElement plus owning styles. It must remain inside the owning document/style transaction; there is no new C ABI or owning DOM handle. The style-pointer check is only an old-style checkpoint. It does not validate parent/root/layout/timeline/rule generations, prove a supplied resolved result came from this target, or certify completion. The caller must validate those inputs, own target/pseudo lifetimes and handle rejected work before using this path. The public Rust methods are internal implementation seams, not safe cross-transaction storage APIs.

Recascade uses fresh short-lived contexts after main-thread updates, but with the same settled parent/root inputs. The animation-only context used for rule replacement must not be accidentally reused for publication if the original flags differ; that could suppress damage through FinalAnimationTraversal. The explicit flags check rejects that misuse. Traversal flags alone do not validate all SharedStyleContext inputs.

Only CSS animation and transition rule levels are replaced. A provisional SMIL rule remains as captured. This is not all-origin freshness or complete EffectProperties resampling. Rebuilding relative endpoints may need additional target-local ordering from the parent-barrier design. Pseudos newly created or removed during preparation, display:none cancellation, transition start/reversal, timeline scopes and layout-dependent inputs still require a real staged driver contract. None is waived because a PendingRestyle exists.

## Exact remaining driver blocker

The current compute_style inserts matching/cascade results into sharing caches before finish_restyle. recalc_style_at immediately consumes finish_restyle's child hint, reads the now-published display value, may clear descendant data, propagates/clears hint bits and calls note_children. DomTraversal::process_preorder and parallel::style_trees expose child callbacks rather than a suspended-node result. Dropping contexts after this existing path is too late: descendants have already been admitted.

A specialized staged traversal must return an owned pending-node continuation before finish_restyle/publication and before any display:none clearing or note_children. It must isolate provisional cache entries until contexts are dropped, retain initial-style/flags/hint bookkeeping, execute tasks without borrows, perform exact-target compositor preparation, recascade the unpublished inputs, publish, then run the existing child/hint continuation. Failure/invalidation must preserve that continuation. Merely replacing finish_restyle with prepare_restyle while returning an empty child hint would lose descendants and invalidation work; publishing provisionally then recascading would retain the observed ordering defect. No such incorrect bridge is supplied here.

These APIs remove the previously indivisible task-discovery/publication obstacle. The next missing implementation is that specialized continuation plus selective compositor preparation, not another number of full-tree passes. The fixed-endpoint inherited family admits structural parent-before-child progress only after these boundaries and complete child admission are implemented; cycles, endpoint feedback and layout dependencies are outside that conditional argument.

## Validation

Actual c12b76/0 applies and reverses the patch with zero fuzz/offsets in owned scratch, parses both full candidate Rust files, checks the publication body byte-for-byte and task-discovery transformation exactly, and compiles the exact new PendingRestyle methods/prepare method against explicit mock interfaces. Seven tests pass: no provisional publication, staged inputs used by rule recascade/final-only commit, primary/pseudo identity invalidation, absent data, wrong publication flags and wrong composition flags. Three compiled semantic mutants fail for reading old published rule inputs, ignoring publication flags and substituting value equality for Arc identity. Scratch was removed.

The harness substitutes std Arc, mock element/data/task/resolver/native rule operations and numeric values. It tests the API/control-flow contracts, not actual Gecko rule composition, generated bindings, Servo Arc or native lifetimes. No real Stylo compile, browser, main-thread compositor phase, native installation or new fix acceptance is claimed. The initial artifact generation attempt8318be stopped on a non-unique comment anchor before any candidate file was written; the corrected generator produced b4c297 and the flags addition c0e9f7. The saved checker rewrites only its artifact outputs and owned scratch; do not rerun after sealing without a successor.
