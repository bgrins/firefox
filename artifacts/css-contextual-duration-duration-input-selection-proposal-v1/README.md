# Duration-only input-selection experiment

This is an uncompiled policy variant on immutable eight-source snapshot V2 proposal 43420e3b. It is not an execution owner, native installation, acceptance claim or standards resolution. `POLICY-DELTA.patch` contains the entire incremental change: five edits in nsAnimationManager.cpp. Seven other V2 source postimages are referenced unchanged. `native.patch` is the combined eight-file patch from the original frozen preimages, for a later separately reviewed experiment.

DoUpdateAnimations already copies the fresh base context's complete typed animation-duration list into the local `durationInput` array. New static BuildAnimations and BuildAnimation parameters borrow that same array for their synchronous calls. The single timing-duration selection uses the array entry at `animIdx % Length()` when nonempty. List repetition therefore selects from exactly the list compared with and later stored in the collection snapshot. Auto handling remains the existing IsAuto→Nothing conversion. The local array is not moved into the collection until after building, at the existing collection-swap boundary; no borrowed pointer escapes.

If the fresh base context is absent, the array remains empty. BuildAnimation explicitly falls back to composed `aStyle.GetAnimationDuration(animIdx)`. The unchanged missing-input admission remains conservative, and the collection retains an empty/unknown snapshot rather than recording composed fallback as a certified base key. Valid computed CSS duration lists are nonempty; this is not support for an empty authored duration list. Null/display-none destruction and verify-only absent-collection return remain unchanged.

The change applies to creation, ordinary full update and changed-input verification through their common build path. Equal-input verification still skips the manager. Full-update reasons still win. The manager still receives composed UIReset for names, delays, iteration counts, direction, fill, play state, timelines and timing functions. ServoCSSAnimationBuilder still receives composed ComputedStyle for keyframe construction. Existing matching/reuse and `UpdateOldAnimationPropertiesWithNew` with `PropertiesOverridenByJS` remain byte-identical: script duration overrides still take precedence. The stored input is the selected CSS source, not script-owned applied duration.

Existing nine callbacks, three preservation callbacks and the standalone partial24/32 page remain unchanged. Normal-restyle admission still excludes animation-only traversal; no parent/root freshness, finite-depth completion, feedback convergence, input-generation or device-cache proof is added.

The sealed partial-base design decision `fd552498150f228ad6dffd90bbdfa91a955f9920fa1ef26976561e94d06fd371` motivates this experiment. Stock Firefox/Chrome observations distinguish retained/composed/pre-own choices but do not determine normative policy. This manager-only change does not change Gecko's composed computed-CSS animation-duration serialization. It can produce effect 1500ms while CSS serialization remains 2s, unlike Chrome's complete observable result. Standards/compatibility decisions remain open; this is not a landable general contextual-duration fix.

Custom-property animation taint is an additional unresolved input-selection boundary. The frozen base resolver removes animation-origin rules before recascading; animated custom-property values can therefore differ from the composed context. That does not prove taint metadata is cleared or that the base list preserves the composed substitution/invalid-at-computed-value outcome. The [published 2022 CSS Variables snapshot](https://www.w3.org/TR/2022/CR-css-variables-1-20220616/#animation-tainted) restricts animation-tainted var() substitution into non-animatable properties. The fetched October 2026 editor draft does not expose the same animation-tainted term; this bounded check did not resolve that version difference or trace current branch taint propagation. No normative conclusion follows. A separate control should compare unregistered/registered animated custom-property duration inputs and a literal fallback, retaining custom-property serialization, CSS duration and applied timing. This patch adds no taint special case or expectation and must not be assumed safe for that class merely from passing em-only cases.

Existing V2 ABI widening remains inherited and requires an actual successful build; this variant adds no FFI or header signature.
