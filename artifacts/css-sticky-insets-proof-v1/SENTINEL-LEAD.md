# Finite sticky sentinel: independent source prediction and later root confirmation

The initial artifact was a source/model counterexample. Root subsequently confirmed the reachable case in separate browser artifacts; these were not browser executions performed by this companion. It is independent of H1/H2 and present in all four retained variants. Do not include it as an additional repaired case.

`StickyScrollContainer::ComputeStickyLimits` initializes stick limits to origin `nscoord_MIN / 2 = -536870911`, extent `nscoord_MAX = 1073741823`, therefore far edge `536870912`. `DoComputePosition` applies those finite edges even when an axis has no explicit inset. With normal position 700000000 and a containing-position interval including that normal, the far clamp can move the frame to 536870912. `StickyNumeric.finite_sentinels_are_not_infinity` separately proves the early-return/missing-offset version; it does not establish browser reachability.

A stronger reachable-source proposal uses a fully reflowed sticky frame with both insets auto. It does not require missing computed offsets. `nsIFrame::HandlePrimaryFrameStyleChange` registers `position:sticky` frames without testing whether an inset is non-auto (excluding non-display/SVG layout frames). The normal must come from preceding content, not a huge margin: the latter changes the containment lower edge and can mask the effect. Layout saturation remains an untested provider boundary.

Suggested root-only browser diagnostic: two equivalent 100px-tall overflow:auto scrollports, each with a 17000000px containing block, a preceding 11666666px spacer and a 10px target. One target uses `position:sticky;inset:auto`, the other `position:relative`. At scrollTop 0 compare target tops relative to their containing blocks, as well as resolved spacer/CB heights. At 60 app units per CSS px, the spacer is 699999960 app units and the finite far sentinel is 8947848.5333 CSS px; both intended block extents remain below nscoord_MAX. Include small-spacer controls and a second equivalent static target. No request should be made to an external endpoint. Browser confirmation must establish the actual normal/CB sizes, not infer them from specified CSS.

Missing-offset conditions are different: `ComputeStickyLimits` explicitly returns early when `ComputedOffsetProperty` is absent because scroll-frame reflow has not computed it. `PositionContinuations` also returns without movement when its first continuation has no stored normal position. Thus a missing-offset counterexample alone does not prove that ordinary rendering calls the clamp in the required lifecycle state.

The exact source snapshots and helper extraction are in `inputs/evidence/css-sticky-writing-mode-fix-v1/matrix-*-v1-sources/`. The registration source is retained as `discovery/frame-upstream.txt`; current sentinel aliases are retained as `discovery/layout-constants-upstream.h`. The proof keeps explicit representable-normal and intermediate-arithmetic premises instead of treating sentinel values as mathematical infinity.

## Root confirmation and separate repair

Root reports `css-sticky-sentinel-probe-v1/candidate-v2/RESULT.json` and `release-v2/RESULT.json`: 42 rows, six sticky discrepancies and 36 matching controls, including 28 static/relative controls. The actual spacer and containing-block sizes were measured. The first diagnostic used an overly strict subpixel tolerance; v2 retains the correction to at most 2px, and its 28 controls calibrate the source prediction. Root independently owns the later four-offset-mask positional repair and its native/WPT/proof review. All four H1/H2 archived variants here still use the original unconditional clamps.
