# Preserve root identity in animation conversion

The original e86 browser computes animated root `font-size` rem/rlh using the configured underlying root metrics, although ordinary root font-size and animated root em controls use calibrated initial metrics. This package independently replays all 16 saved diagnostic observations (eight font-size, eight variation). Variation observations remain research evidence and are not the standalone repair oracle. Root separately reports the same calibrated result on installed Firefox 158; this package pins the archived e86 replay.

The proposed one-file repair supplies actual target identity to `create_context_for_animation` in `servo/ports/geckolib/glue.rs`. The helper sets only its local `StyleBuilder.is_root_element`. It does not change generic `StyleBuilder::for_derived_style`, computed styles, registration/attribute behavior, parent metric policy, invalidation admission or FFI signatures. Candidate SHA 554d1fb2ab9e0e8865b3cc3f0b0c111e4ac6fd5877cffe1070dbdc5479563dec derives from exact e86 glue 83cc1e6f. No taint or variation-parent repair is included.

All four helper calls are updated. Computed keyframes and `ContextForSubstitution` combine actual document-root identity with absence of a pseudo-element. SMIL `Servo_GetAnimationValues` and direct `Servo_AnimationValue_Compute` pass the actual target's root identity. The existing `selectors::Element` import provides `GeckoElement::is_root`; its e86 implementation rejects content-parent and disconnected elements, then checks the document root. Parent absence, inherited style flags and a root originating element alone do not substitute for target identity.

The e86 C++ direct caller `AnimationValue::FromString` obtains primary computed style for its actual element, then invokes `ServoStyleSet::ComputeAnimationValue`. `SMILCSSValueType::ValueFromStringHelper` passes the actual target element to `GetAnimationValues`. These APIs have no originating-element/pseudo split. `ContextForSubstitution` carries that split explicitly and retains it in the new Boolean. SOURCE-MAP.json records Searchfox discovery and saved source paths; exact saved hashes, rather than newer indexed line numbers, define this candidate.

The direct primitive `AnimationValue::from_declaration` path retains this builder into native conversion. `FontSize::to_computed_value` already selects inherited font and line-height bases. Root rem/rlh branches in `NoCalcLength::reference_font_size_and_length` use those bases when root identity is true; with the old false field they instead query Device root values. `resolve_line_height_length` uses current font but inherited line-height: root line-height rem remains relative to its own font size, while root line-height rlh takes initial line-height. The proposal preserves these converters and their zoom/cache behavior. It does not establish arbitrary font-axis correctness or a full native API/lifetime proof.

## Normative boundary

Scenario: a connected document element has a paused active font-size or line-height keyframe effect with explicit midpoint currentTime. Axes are horizontal, and the target is not a pseudo-element. Endpoints are 1rem→3rem or 1rlh→3rlh. Initial font size and initial normal line-height are independently measured, not hard-coded.

1. Web Animations, calculating computed keyframes, computes property values in the target element's context (computed-keyframe procedure step 2.2). That target is the document element, not an anonymous derived style or its pseudo-element. SPEC-KEYFRAMES.md preserves the current section and hash.
2. CSS Values 4, font-relative lengths, makes font-affecting values on the element they reference use parent metrics, or initial font/line-height metrics when no parent exists. Root font-size takes the latter branch. The separate line-height clause applies that rule to lh/rlh in line-height; the following sentence preserves own-font resolution for other font-relative units in line-height. SPEC-VALUES.md preserves both clauses and its current hash.
3. A child or root-host pseudo is different from the root referenced by rem/rlh. Its normal resolution continues to use actual root metrics. Root-host pseudo width is discriminating: an incorrect root bit would instead use its explicitly different pseudo metrics.

Verdict: REACHED for initial-metric root font-size rem/rlh and root line-height rlh. Root line-height rem and nonroot/pseudo cases are preservation controls. This is a targeted section/step trace, not a claim that an index enumerated every cross-spec path. No cyclic font, variation-parent, axis or unrelated invalidation oracle is bundled.
