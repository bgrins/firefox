# Native obligations for prepared publication

This is a source-to-model review of frozen candidate cascade a6f4, not a repair, a new observed failure, or a proof of the actual generated-ensure trace. This note was written during the root-owned portable original/candidate pair and did not alter it. The later saved outcome review records two new candidate regressions; this note supplies no additional runtime evidence. The sealed publication model 582537 proves a sufficient condition; it does not establish that the current Rust satisfies that condition.

| Model premise | Concrete native obligation |
| --- | --- |
| Target initially default and not already published | An active graph-owned priority must not be applied by the ordinary ensure route before its prepared result is ready. `ensure_prioritary_property` and `apply_prepared_priority` insert `ensured_prioritary` before generated prerequisites, so that bit alone means neither fully computed nor finally published. The graph's active-node state lives in its traversal Context; ordinary ensure needs an explicit ownership/readiness contract across that boundary. |
| No premature dependent observation | Prevent consumers from using provisional builder Appearance, APPEARANCE_BASE eligibility, font/scheme state or custom results. A guard that merely returns from ordinary ensure can leave its caller computing with an unfinished field. Marking a property ensured without applying it has the same risk. Readiness must be established before the actual read, or failure to establish it must propagate before mutation/consumption. |
| Agreement at every reached selection decision | The NonCustom branch computes `eligible` before recursive reference visits. `apply_prepared_priority` later debug-asserts only retained entries. Protect the relevant seen/reverted/included flags and substitution/adjustment inputs during that interval, or reconsider the affected selection prefix, including skipped entries and rollback transitions. Rechecking only the retained winner cannot recover a formerly excluded higher candidate. |
| One final publication with unchanged prepared result | Commit the retained substitution/adjustment once, including its deferred accumulator effects. Do not silently re-substitute after dependency/default mutations. Initial's `can_skip_apply` is sound only while its non-inherited field still contains the initial value. Forcing an Initial write repairs that field but does not retract already-consumed font/scheme/custom results or selection flags. |
| Intervening work is unrelated | This classification must be justified against actual computation reads, not generated scheduling metadata alone. Conversely, absence of target writes is insufficient: a dependent can read the initial value before a later literal publication, as the model's no-write counterexample demonstrates. |

Attribute readiness is part of the second and third obligations. A cached entry can contain unresolved raw variable syntax, and a missing entry can reflect deferred preparation rather than an absent DOM attribute. Neither condition may be silently interpreted as a completed typed parse failure. The existing raw/ready/invalid distinctions and consumer context need a source-supported contract before changing the final consumer. This note does not propose a new cache representation or solve the broader contextual-attribute work.

The narrow next implementation decision belongs at the generated-ensure/active-graph boundary: establish whether the required descendant computation can finish without consuming the active ancestor, using its actual prerequisites, or preserve a pending result until those reads become ready. Literal pixel FontSize is not automatically independent: text zoom/scaling and other conversion behavior must remain accounted for. The source agent is tracing those concrete computation paths separately. No literal-only suppression, blanket removal of generated dependencies, or promotion of all scheduling links into semantic SCC edges is justified here. Genuine selected cycles must retain the existing invalid/default behavior.

Simply moving the ensured insertion later is also not a complete repair: the earlier insertion participates in recursive scheduling termination. A readiness contract must distinguish an active computation from a completed publication without introducing new recursion or allowing unfinished values to escape. Likewise, clearing a final Appearance-base flag, skipping a prepared declaration after discovering seen state, or restoring only the builder value leaves earlier consumers potentially stale.

The proof's semantic publication log is not a count of physical writes. Monotonic cache/bookkeeping effects need their own preservation argument; they need not all be postponed merely to match the toy store. Its arbitrary finish decoder, reached-evaluation agreement and abstraction of native side effects remain explicit premises.
