# Fragmentation unforced-break pilot

## Scoped result

Five Lean modules define and check a concrete rule/grid component against the pinned CSS Break3 Editor Draft. The exact audit roster contains 34 results, including 16 concrete witnesses; these counts are not CSS coverage percentages. All source interpretation and native/provider limits in SCOPE.md apply.

The useful closed model gates are:

- Executable before/after avoidance and ancestor/line checks agree with the quantified constructor-based relation, including combined page/column break kinds.
- The finite ordered evaluator succeeds iff the independently quantified **grid** placement relation is inhabited. Selection returns a valid placement and makes finite content-cursor progress for an ordinary cut.
- Stage scanning derives a first-success certificate with every preceding stage geometrically infeasible in the grid model. An allowed-but-too-far opportunity distinguishes this from testing whether any allowed opportunity exists.
- End-side clone truncation precedes start-side truncation; ordinary decorations remain. Concrete examples inhabit all five stages.
- Successful emergency slicing of one grid graphic consumes positive bounded extent and decreases the remaining natural-number measure. A history of admitted positive bounded steps ending at zero preserves total coverage and has a bounded number of steps. Existence of such a full CSS history is not proved.

No theorem establishes that grid feasibility means CSS “sufficient break points.” `SufficiencyCorrespondence` is explicitly uninstantiated. No theorem selects the CSS emergency opportunity region, proves actual layout/continuation inputs, or establishes whole §4.4 conformance.

## A substantive admission distinction

During model review, treating a positive content index as “below the top” was rejected: a zero-sized prefix can advance the index while remaining at geometric top. The final emergency predicate derives a grid offset from prefix extents and retained ordinary start decoration. A kernel witness preserves the zero-prefix case.

A second witness retains the unresolved region decision. Two boxes have extents4 and1 with capacity2, and a valid ordinary opportunity after the first box. Including that beyond-capacity point versus excluding it changes the emergency guard, although both candidate lists satisfy a weak subset/bounds check. That check does not establish the exact normative region. The model deliberately does not choose the convenient one.

## Replay and mutation evidence

The source-only checker authenticates the closed roster before creating output, validates complete-source slice bindings, compiles all five modules, and audits every named theorem exactly. Only standard Lean foundations are allowed. It then compiles nine single-definition mutants and requires each unchanged kernel gate to pass baseline and fail semantically on the mutant. These discriminate ancestor-guard weakening, type conflation, widow threshold error, premature avoidance relaxation, premature start truncation, ignoring fit, zero emergency progress, leaving a fitted zero box behind and dropping the region guard.

The checker also reauthenticates inputs after replay. Source/package tampering is distinct from those semantic mutant gates. The closed roster rejects extra directories, nonregular filesystem entries and duplicate JSON keys; outputs must be outside the capsule. Generated outputs are external; no native/Firefox/WPT/browser tests were run. Lean executable identity is pinned; runtime, standard library, Python and source-to-model interpretation remain in the trust base.
