# Approved scope and remaining admissions

Root approved implementation after SCOPE-PROPOSAL.md with these explicit decisions:

1. Visible Rule 4 B/C wording is a named interpretation, not resolution of its class-A hyperlink discrepancy.
2. Ancestor controls initially admit only auto/avoid; type-specific ancestor handling is an extension.
3. Line counts derive from supplied current-fragment/block content. Actual inline-layout and continuation correspondence remains open.
4. Fitting-prefix feasibility is a concrete grid relation, not established CSS sufficiency. `SufficiencyCorrespondence` is an uninstantiated interface obligation.
5. The emergency candidate region remains supplied with exact semantic admission open. Competing region witnesses must remain; prove conditional emergency progress only.

The earlier proposal is retained as design history, not an assertion that every proposed interface was implemented. This checkpoint implements rule, placement and stage-selection semantics, not native CSS layout.

## Concrete domain

Natural-number exact grid extents; fixed capacity; ordered finite already-laid-out content; supplied opportunities with A/B/C tags, controls and ancestor lists. A B opportunity carries enclosing-block identity. Line counts filter the current content prefix/suffix by that identity, including line ordinal labels. Those are supplied current-fragment contents, not proven Gecko continuations. Positive computed widows/orphans and completeness/validity of opportunities must be established by a future adapter.

Before/after controls include auto, avoid, avoid-page/column/region and a force marker. Active break kinds are a set of three booleans, permitting combined page/column breaks. Force is retained for Rule 1's permission formula but rejected by the ordinary evaluator. A whole-flow CSS admission must exclude forced events, including named-page changes and other events not represented by those controls. Filtering a forced opportunity out of a list is not a full forced-break dispatch algorithm.

Ancestor lists support auto/avoid only. Common-ancestor lists for Rule 2 and all-ancestor lists for B/C remain supplied relational inputs. No theorem derives them from a DOM/box tree. Kind tags, opportunity ordering/completeness, line identity/readiness and ancestor propagation are explicit providers; the executable model does not derive A/B/C classifications from actual box layout.

Decorations have ordinary or cloned start/end extents. The model retains all ordinary extents and progressively removes only cloned extents. One decoration list is shared by all candidate cuts. Input admission must establish that this same active-decoration representation is valid for every evaluated candidate, not select it retrospectively from the winning cut. Supplied extents must already reflect applicable margin truncation. Negative margins, floats, varying inline sizes, parallel flows, partly occupied fragmentainers and arbitrary real-valued geometry are outside this grid model. Actual layout can change the placement candidates; none of those changes is proved absent by these input types.

## Output and observation

A stage evaluation returns either complete placement, one ordinary cut, or none. None means no modeled grid placement, not invalid CSS. The stage scan chooses the first successful stage and returns a kernel-derived certificate of all prior grid failures. The selector has a simple source-order policy; optional optimization/avoid weighting is not a mandated unique output.

For already fitted zero-extent box records, the cut cannot leave the immediately following zero box behind. This is a scoped earlier-side condition with records whose total admitted extent is zero. The after-overflow exception and decoration/source correspondence stay open. Zero-extent lines/graphics are not automatically treated as this box condition.

Emergency evaluation is separate from the stage scan. It accepts a caller-supplied region and only handles one finite grid graphic. A successful slice consumes positive extent bounded by remaining content and available capacity; the remaining natural-number measure strictly decreases. A two-box input with a valid beyond-capacity opportunity inside versus outside the supplied region gives different guards; both lists satisfy only the weak subset/bounds admission. Below-top uses derived grid offset, not a positive content index: a zero-sized prefix can remain at the top. No choice of region is asserted correct for CSS. `SliceHistory` describes only admitted positive bounded slice steps ending at zero, deriving coverage and a step bound; it does not prove every CSS input produces such a history or that real-valued positive progress terminates.
