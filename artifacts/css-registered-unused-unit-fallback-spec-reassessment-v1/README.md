# Unused relative-unit fallback: normative reassessment

As of 2026-10-30. This challenges the earlier probe's unconditional current-draft REACHED conclusion; it does not change the sealed fixture or authorize a native fix.

**Question:** Must a registered `<length>` value `--v: var(--size, 1em)` avoid a FontSize dependency when `--size` supplies valid `20px`, then `30px`, and `font-size: var(--v)` consumes it?

**Scenario:** `--v` is non-inherited with independent initial `0px`. The parent font changes from `11px` to `17px`. There are no animations, custom functions, or early spread substitutions. Missing-primary and literal-value controls isolate selection from genuine relative-unit cycles.

1. [Values 5, property replacement, steps 1–4](https://drafts.csswg.org/css-values-5/#property-replacement) substitutes with a property context, checks invalidity, parses the result, and replaces the property value. Its [ordering rule](https://drafts.csswg.org/css-values-5/#resolve-property) places substitution “before any other value transformations or introspection can occur.” This strongly supports inspecting selected tokens for unit dependencies.

2. [Variables 1, var replacement, steps 2, 4, 5](https://drafts.csswg.org/css-variables-1/#using-variables) fetches the named property's computed value. Step 4 substitutes the second argument only if that result is guaranteed-invalid; step 5 returns the result. For a valid `--size`, this route produces `20px`/`30px`; `1em` is not selected. This conclusion concerns substitution itself, before deciding when the separate PVAPI edge rule runs.

3. [PVAPI §2.4](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation-of-computed-values) parses the registered syntax and computes its value. [§2.7.1](https://drafts.css-houdini.org/css-properties-values-api-1/#dependency-cycles), however, adds a FontSize edge if the property “contains any of the following units”, including `em`. It does not identify the inspected value stage or call property replacement. This is the unresolved join: does that additional cycle constraint inspect the substituted value, or augment cycle detection while substitution is still being scheduled?

4. If inspection follows replacement, the defined-primary case has no unit backedge: `font-size → --v → --size`, yielding `20px`/`30px`. If raw fallback units contribute before replacement, `--v → font-size` closes the cycle and produces the observed initial/inherited result. The second reading requires treating PVAPI's additional constraint as an exception to Values 5's general ordering; that exception is not explicit. Conversely, merely quoting the general ordering does not supply the missing PVAPI integration step.

5. With the primary missing, replacement selects `1em`; both readings add the backedge. PVAPI's explicit em-cycle example requires `font-size` to behave as `unset`. With this registration, the corresponding custom value defaults to `0px`; inherited font is `11px`/`17px`. A literal `20px`/`30px` control creates no unit edge under either reading.

The historical custom-reference rule must not be conflated with the unit rule. The [published Variables 1 CR, 16 June 2022, §2.3](https://www.w3.org/TR/2022/CR-css-variables-1-20220616/#cycles) explicitly includes references “including in the fallback argument of var()”. It concerns `var()` references, not literal units. The **current** Variables ED instead says “Made var() short-circuiting” in [its changes](https://drafts.csswg.org/css-variables-1/#changes). [Issue 11500](https://github.com/w3c/csswg-drafts/issues/11500) discussed ignoring untaken branches, and [PR 12165](https://github.com/w3c/csswg-drafts/pull/12165) merged guarded dynamic-cycle machinery on 5 May 2025. Thus eager unused-custom-reference edges are not an invariant that can simply be imported into the current ED. Neither that change nor the old CR separately specifies the literal-unit scan's placement. The bounded issue search found no directly deciding unit-fallback resolution; it was not exhaustive.

**Verdict: INCONCLUSIVE** — the current substitution route strongly favors the probe's selected-only unit expectation, but PVAPI's additional relative-unit cycle rule lacks an explicit timing bridge to that route. Classify this as shared implemented behavior with an unresolved specification-integration question, not a settled Firefox-only defect or proven intended behavior. Ask CSSWG whether §2.7.1 inspects the post-replacement value and request a direct unused-unit example; retain the failing tentative probe meanwhile.
