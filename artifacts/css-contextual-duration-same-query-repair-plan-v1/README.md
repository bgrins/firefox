# Same-query completion repair plan

The next repair belongs in central animation/style completion, not a second getComputedStyle call or an initial NeedFlush workaround. All four stale first queries already admitted a flush. Within that query, the middle key was consumed, then the child became Pending during Servo traversal and remained unconsumed when the getter returned. WITNESSES.json retains exact full keys, query IDs and event sequences from the authenticated 258-query/204-posted-value join. The original instrumentation and source/spec lead preceded this plan; no new native patch, acceptance or browser execution is claimed.

The observed sequence is the same for ordinary and animated lh/rem cases: child absent on entry; shell gate need=true; middle pre-remove-consumed; child request-state=Pending with Servo/style-refresh true; no child consumption before return; root null/style0/throttle0/layout1 at return; serialized child opacity0.428571. Passive frames later supply0.545455. The trace does not identify every traversal iteration, prove actual composition from WillComposeStyle, or tag which input/effect caused a request. The latter gap matters for a safe completion algorithm.

The exact branch scheduling bodies explain a concrete seam. ServoStyleSet::StyleDocument returns immediately without a restyle root, otherwise performs a traversal and one conditional additional compositor PreTraverse/traversal. RestyleManager::DoProcessPendingRestyles keeps style-refresh active around traversal and post-traversal tasks, clears the document root, and repeats for roots produced by existing invalidations. The tri-state compositor correctly retains late work while dispatch is unsafe, but Pending does not itself recreate a root. The outer function can therefore finish with eligible map work. Merely testing Pending in PresShell::NeedFlush would not fix these already-entered flushes. Nor should Pending be treated as throttled work: that would change forced-throttled behavior and can wake feedback during style reads.

The intended repair contract is: at a safe existing traversal boundary, before publishing the query's resolved style, complete all newly generated non-throttled work whose input dependencies are acyclic for this style-update transaction. The work's applicability and current input generation must survive the handoff from sequential update tasks to compositor consumption. Reacquire valid targets/documents after invalidating operations; do not dispatch recursively through PresShell while Servo/pre-traverse/style-refresh guards forbid it. Keep actual post-traversal/frame work distinct from the presence of another animation demand; StyleDocument's return value must not be repurposed blindly. Throttled eligibility, disconnected/pseudo handling, script-owned timing and independent frame/layout invalidations retain their existing contracts.

This requires a progress argument based on dependencies, not an iteration count. For a known finite acyclic dependency graph, settling predecessors before consuming a dependent permits any finite depth; each final input version is processed without an arbitrary extra-pass limit. A frontier ordered by strict ancestor dependencies is a plausible optimization for the demonstrated inherited/rem/lh chains, but is not a general dependency proof. Newly generated work must be considered at the central boundary even when the prior restyle root was cleared. The missing native hooks/capture listed below determine whether this can be implemented using existing machinery or needs explicit provenance.

Do not implement a bare while(PreTraverse), a constant pass cap, or a consumed-element set. Pending currently records scheduling state, not input causality. Repeated demand for a key is not evidence of a cycle. A discriminating unexecuted example is two animations on one element: fixed2s font-size interpolation16→32px, plus opacity0→1 with duration calc(1em /16px *1s), both paused750ms. If contextual input propagation applies, font22px must feed only the opacity duration1375ms and opacity6/11. This is a finite cross-property chain on the same compositor key; a once-per-key rule can suppress legitimate work. Multiple predecessor paths can also revisit a dependent before its final input settles. Conversely, processing every newly changed numeric value until repetition does not bound slowly converging or divergent self-feedback usefully.

A meaningful cycle policy must identify an actual dependency backedge or strongly connected component, at sufficiently fine effect/property/input granularity. A conservative implementation can restrict the new same-query completion to dependencies it can prove acyclic and preserve existing treatment for uncertified feedback. That does not satisfy a claim of all arbitrary acyclic graphs until the classification covers them. Alternatively, a fully specified transaction can freeze cyclic-component inputs at an agreed sampling boundary while propagating its chosen outputs to downstream acyclic components. That is a proposed policy requiring specification/compatibility review, not an existing Gecko rule, a proved fixed point or a license to choose whichever numerical iteration finishes. No production patch should adopt either policy merely because the four current witnesses pass.
