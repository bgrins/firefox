# Native completion choices and outstanding proof obligations

The smallest scheduling change is at ServoStyleSet::StyleDocument's existing compositor follow-up traversal, coordinated with the enclosing RestyleManager::DoProcessPendingRestyles transaction. EffectCompositor::PreTraverse already converts eligible non-throttled demand into explicit animation hints through PostRestyleEventForAnimations; it can recreate a restyle root without recursively calling PresShell. Its existing target/pseudo/disconnection checks and forced-throttled selection must remain intact. The captured StyleDocument currently admits only one follow-up traversal, and returns before PreTraverse when no restyle root exists. Merely calling StyleDocument again with late Pending and no root will do nothing.

A candidate implementation therefore needs an explicit completion admission before that root-empty return, or a distinct transaction completion entry that calls the existing compositor admission and then invokes the ordinary traversal/post-traversal machinery. Do not call the full PreTraverse path twice accidentally: it includes font/stylist synchronization and SMIL handling. Do not repurpose StyleDocument's boolean as “pending animations”; it signals required post-traversal/frame processing. Newly generated dirty roots must receive that processing before final style sources are used. Preserve the existing shell/document lifetime protection in DoFlushPendingNotifications and the no-reentrant-flush scope in DoProcessPendingRestyles.

A finite work budget proportional to relevant effect/property nodes is a plausible smaller mechanism than maintaining a complete dependency graph. It differs materially from a fixed “one more pass” rule. For a fixed finite DAG with N nodes, a full propagation round that evaluates every demanded node from settled predecessor outputs reaches the fixed acyclic result within its longest path length, at most N. The order within a round may be conservative; it must not starve a demanded node. This is a conditional algorithm argument, not a native theorem: the captured queue key combines target/pseudo/cascade level, and neither its size nor trace-event count establishes N.

Before implementing that bound, establish all of the following:

- Define a stable node universe covering all relevant effects, animated properties, timing inputs and dependency intermediates, including nodes not initially Pending. Counting only current map entries misses later descendants; counting only targets conflates same-element effects. A conservative overcount is acceptable if its construction and cost are bounded.
- Show that one admitted round makes the required edge progress. All eligible work must be evaluated; sequential task updates and effect timing must be reflected by the next composition. WillComposeStyle records computed timing and is not alone evidence of completed composition. Fixed paused time in the current fixtures is stronger than a general moving timeline; sampling time must not move between rounds and manufacture new demands.
- Keep the budget for the entire style-update transaction, not per StyleDocument call. The enclosing loop can re-enter after frame/container invalidations. Replenishing the whole budget on each such call defeats the intended termination bound. Creating/removing effects or pseudos requires a specified accounting rule rather than automatic unlimited growth.
- State what happens at exhaustion. It is not evidence of a fixed point or proof of a cycle; it can also expose a missed edge or incomplete node universe. Consuming/clearing unprocessed Pending loses work. Retaining it requires a later scheduling rule, while that synchronous return must not be advertised as fully settled. A chosen last-iteration value is an observable cyclic policy and needs compatibility/spec review.

With those obligations satisfied, the mechanism can bound feedback independently of assuming all content is acyclic and still complete arbitrary finite DAG depth. Without them, it is only a bounded diagnostic prototype. In particular, choosing N from the active-effect count plus a guessed multiplier is not a justified dependency bound.

The inspected existing container-query implementation is instructive: nsPresContext::UpdateContainerQueryStylesAndAnchorPosLayout iterates shallowest first, postpones a descendant if an ancestor is scheduled, and tracks mUpdatedContainerQueryContents to allow only one update per element per flush. Its comment expressly identifies unstable layout prevention. This policy exploits a structural ancestor relation; same-element cross-effect animation dependencies do not have that structure. Use the transaction-scoped state pattern if appropriate, not the once-per-target rule. This extra function is a public upstream capture only; any native use needs exact branch applicability.

A stronger alternative is dependency-aware processing with cycle detection at effect/property granularity. Acyclic components can settle in topological order; cyclic components could use a specified frozen-input or deferred-next-sample policy. The current tri-state map has no dependency edges or input generations, so this is a larger native change. It must not be presented as a small queue-only patch. Conversely, a narrowly proven inherited-ancestor frontier could repair the demonstrated chains but would explicitly exclude same-element/cross-property graphs until covered.

The practical next discriminator is the prepared same-element acyclic two-effect observation plus the discontinuous self-feedback observation. The old linear feedback model is already available and is not duplicated. Follow those observations with an explicit choice of transaction boundary, node accounting and cyclic exhaustion semantics; then produce one source patch against the authenticated semantic bases. The existing four stale first-query traces justify fixing completion, but do not justify selecting a cycle policy by whichever numerical pass happens to terminate.
