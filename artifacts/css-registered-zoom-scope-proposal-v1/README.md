# Scoped registered-value computation proposal

Captured two-file native proposal; not installed, compiled, or browser-tested. This is one integration piece, not a complete zoom repair. The admission candidate remains held and accepted fixes remain 137.

`Context::in_registered_value(&self) -> bool` exposes a private Cell<bool>. `Context::with_registered_value<R>(&self, f: impl FnOnce(&Self) -> R) -> R` sets it while invoking the synchronous callback. A local Drop guard restores the previous value on normal return and panic unwinding; nested scopes save true and restore true until the outer scope restores false. It does not mutate StyleBuilder, zoom, font size, device state or container state. All five existing Context constructors initialize false. Abort does not unwind, but no continued execution is claimed after process abort. The Cell adds no new Sync capability; Context already contains RefCell state. No panic or concurrency tests were executed.

The outer `properties_and_values::Value<Component>` replaces only its ToComputedValue derive with a manual implementation. The generic bound is exactly Component:ToComputedValue and the associated result is Value<Component::ComputedValue>. The v, url_data and attr_tainted fields still call the same conversion trait; only to_computed_value runs inside the scope. from_computed_value remains the same fieldwise reverse conversion and introduces no normalization. All other derives, animation behavior, parsing, URL provenance, attribute taint, universal values and initial/inherited copying remain unchanged.

The fetched style_derive/to_computed_value.rs was compared to the local exact file (CHECK.json records equality and hashes). Its generic path adds one ToComputedValue bound per generic parameter and dispatches that trait on every field in each direction; this matches the proposed manual bounds/calls without adding Clone or ToCss constraints. ValueInner and component/list recursion retain their generated implementations.

The common outer trait boundary includes SpecifiedValue::compute (which parses then calls value.to_computed_value), prepared values computed through that same trait, direct typed values and parsed animation values when they use Value's trait conversion. Nested images, transforms and component lists execute while the flag is active. Existing already-computed canonical initial/inherited copies do not invoke this trait and are not renormalized here. Any producer that bypasses the outer Value boundary or stores raw ComputedValueComponents directly still requires the separate producer audit; this patch does not establish completeness of that audit.

Integration requires root's specified length/math leaf conversions to honor the getter, normalization of inherited/root/font/line-height/viewport/container values in their actual coordinate systems, and the custom-property CSSOM export changes. Container semantics remain under active audit. Numeric matrix conventions, percentages and non-length fields must remain correct. No finite/clamp policy was added. Until those consumers are implemented and validated, setting the flag alone does not make values canonical and cannot fix the observed regression.

The base captures were authenticated byte-for-byte against the current native files. SOURCE-ROLES.json pins both exact bases and proposed postimages; native.patch touches only value.rs and computed/mod.rs. CHECK.json records forward/check/reverse/reapply transport in an owned scratch directory and five-constructor/static checks. Rustfmt parsed/formatted both files through stdin using the repository's Servo configuration; the initial file-mode rustfmt attempt failed because child modules are not captured, so no successful full-crate format/typecheck is claimed. No compile, lint, browser, runtime, live source, index or reference mutation occurred. Temporary transport files were removed.

Searchfox first identified Context and Value's derives. Sandbox file-fetch attempts then failed DNS; a network-enabled Searchfox fetch obtained the exact derive body. Empty failed-capture files are retained only as provenance, not source authority. The Firefox web-standard implementation skill was applied; no new WebIDL interface or algorithm claim is introduced by this scoped implementation fragment.
