No branch-specific semantic prerequisite was identified for the one-line native change plus the two-case landing-v2 WPT. The patch applies and reverses unchanged against the freshly captured Searchfox computed-context source (`ba5a85/0`), adding exactly the same exclusion already used by upstream `query_sibling_index`. This is source transport evidence only, not a clean-upstream build, browser result or arbitrary cherry-pick guarantee. The CLI capture has an authenticated body hash but no revision identifier; no guessed permalink is supplied.

The landing test uses ordinary width/opacity, `sibling-count()` arithmetic, literal references, two parents and sibling insertion/removal. It does not use contextual easing, line-height, random keys, Round/ModRem, custom-property registration or the held provider. Its two callbacks therefore do not acquire the accepted141 line-height prerequisite. The broader 36-case experiment deliberately includes accepted141's two tree-counting line-height controls as preservation evidence; those controls are not part of the two-path landing payload and need not be transplanted to upstream. Historical source definitions, tested branch prerequisites and upstream source transport remain different claims.

[CSS Values 5 tree counting](https://drafts.csswg.org/css-values-5/#tree-counting) defines count using the parent's element children and specifies DOM-tree rather than flat-tree counting. Ordinary pseudo-elements use the ultimate originating element; real element-backed pseudos use that real element. The currently served draft still prints failed-scope zero. The authenticated [June 24 resolution in issue13736](https://github.com/w3c/csswg-drafts/issues/13736#issuecomment-4791604896) instead selects one, which current upstream and the preservation WPT implement. The direct issue fetch failed in this turn; the previous exact primary comment capture is explicitly referenced. The landing test avoids this disputed draft wording by using ordinary same-tree elements.

The native change does not change count selection, scope fallback, pseudo origin or root behavior: it only disables a reset-cache insertion when count computation is reached. Even where the resolver returns a constant default (root/no-parent or failed-scope), marking uncacheable is conservative. Inherited-only computation may also suppress insertion because the setter is unconditional; the existing index path has the same shape. No CSS rule requires this internal cache optimization, and this change cannot alter the returned integer. Its performance cost is unmeasured; this review does not claim performance neutrality. Separate publication of tree-counting flags and the monotone exclusion lifetime remain unchanged.

The minimal payload is `servo/components/style/values/computed/mod.rs` plus `testing/web-platform/tests/css/css-values/tree-counting/sibling-count-cross-parent-invalidation.html`. Current branch's complete actual paired validation remains root-owned; this artifact does not replace it or assign an acceptance ID.

Next narrow audit suggestion: move the same already-styled count-dependent element between two equal-style parents, then move it back, checking both the moved element and stationary siblings. Existing landing and focused mutation cases insert/remove siblings around stationary targets; a reparent operation additionally crosses inherited-style, selector-flag and cache-lifetime boundaries. Start with ordinary width/opacity and count-only values, then a separately calibrated pseudo if justified. Expected counts should be derived from both parents' actual children; preserve the same target declaration and collect all phases before assertions. This is an unvalidated boundary proposal, not a new failure prediction, and does not repeat the known nested-pseudo limitation or rejected failed-scope-zero hypothesis. Do not expand the current 36-case roster for it.
