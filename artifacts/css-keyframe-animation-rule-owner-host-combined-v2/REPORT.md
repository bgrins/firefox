# Compact owner and host proposal rebased after transition correction

This is a local experimental successor to the authenticated owner-host-combined-v1 package. It targets the captured current working bodies after the presentation regression and one-line transition descriptor correction. It is not a claim of landability, complete memory reporting, provider-resolution correctness, or new bug acceptance. No native files, index, ledgers or canonical sources were edited, and no compiler or browser was run.

The full incremental `native.patch` still changes seventeen paths. Exactly one preimage differs from combined-v1: `layout/style/test/gtest/rust/lib.rs` now contains the appended `endpoint_transition_cases` module. The successor keeps that entire current file as its prefix, then appends the exact owner and descriptor-bulk module sections from the old package. The remaining sixteen candidate files are byte-identical to combined-v1. `COMPOSITION-DELTA.patch` shows the sole candidate difference; `PREIMAGE-DELTA.patch` shows the sole baseline difference. Neither delta is an additional patch to apply cumulatively.

The existing transition correction in `KeyframeEffect::ReplaceTransitionStartValue`, `TestKeyframePresentation.cpp`, and `endpoint_transition_cases.rs` are untouched prerequisites. Their captured hashes match the separately sealed transition proposal's candidate bytes, including `mFromEndpoint = nullptr`. `PRESERVED-SOURCE-PINS.json` also captures the existing host modules, Cargo input and GTest registration file. The patch modifies none of those guarded files except the separately listed `lib.rs` integration point. This proposal does not replay the native correction or overwrite the presentation fixture.

`GTEST-SELECTION.json` contains seventeen distinct registrations: the original ten operation/sample tests, all five added owner/descriptor tests from combined-v1, and `KeyframePresentation.LiteralOpacity` plus `KeyframePresentation.TransitionConcreteEndpoint`. It explicitly includes `KeyframeEndpoint.OwnedSourceAssociation`. All eight Rust host modules are declared once. Existing C++ host bodies and both old append sections are unchanged. The two presentation bodies and transition observer are supplied by the already applied prerequisite, not a duplicate new module in this patch. The actual combined execution counts remain null; a future run must execute and pass all seventeen tests, not merely exit successfully.

The source checker authenticated referenced package payloads, proved the exact prefix/append composition and sixteen unchanged postimages, joined transition preservation to its sealed source, counted registrations/modules, and applied then reversed the full patch in disposable scratch with exact byte comparisons. Scratch was removed. Replay: `python3 -I -S -B artifacts/css-keyframe-animation-rule-owner-host-combined-v2/check.py`. The retained CHECK records this successful source/transport replay. The checker reads archives, not live native state; root must independently verify current preimages and preservation pins before later activation. This is not a current execution-epoch receipt and has no HEAD assumption.

Owner behavior remains unchanged: safe pointer-sized `ArcUnion` storage for owned `StyleSource`, the old longhand storage where no sampled association is used, and the existing borrowed-view/collection growth. Public map and commitStyles composition stay concrete. No pending producer, recipe fallback, provider resolver, SCC handling or node pruning is introduced. Retained unreachable arena nodes and conservative cache behavior remain costs to evaluate. Gecko compilation, the expanded host run and cascade/public-route browser validation remain necessary. The non-Gecko/Servo feature has not been compiled; missing local prerequisites identified in earlier research are not cured by this rebase.

Memory reporting remains incomplete. The referenced integration plan identifies an all-live-effect discovery root, orphan/unlink handling, shared allocation identities across reporting entrypoints and windows, and declaration-block deduplication as prerequisites. Neither the combined owner patch nor its host tests implement or measure those obligations. The current endpoint-clear correction fixes a separate prototype metadata invariant and does not make the reporting plan complete.
