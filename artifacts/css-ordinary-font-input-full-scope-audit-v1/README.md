# Route from seven retained font inputs to all 21

This source audit supports extending the action design, not blanket-widening its admission predicate. The sealed seven-input candidate is unchanged. INPUTS.json enumerates the exact 21 scanner entries: seven currently admitted, twelve additional identity-like values, and two numeric setting lists. No new candidate, native run, browser result or accepted bug is claimed.

## Twelve identity-like inputs

| Inputs | Actual value representation/conversion |
| --- | --- |
| font-language-override | Parsed OpenType tag stored as u32; specified reuses computed type |
| font-palette | Atom wrapper with identity ToComputedValue |
| font-variant-alternates | Owned list of identifier-bearing alternatives; derived identity conversion |
| font-variant-east-asian, font-variant-numeric | Bitflags with identity conversion |
| font-variant-caps, font-variant-emoji, font-variant-position | Enumerated values with identity conversion |
| math-style, math-shift, -moz-osx-font-smoothing, -moz-math-variant | Enumerated values with identity conversion |

The pinned generated font setters use ordinary field assignment/copy/reset for these properties. Their literal conversions do not themselves fetch font metrics, language, zoom or a system font. Palette/alternates can affect later font-resource lookup; a clone at conversion is not proof of immutable fonts or measured metric values. MathStyle is not MathDepth: the latter's AutoAdd reads parent math style/depth, so no child-own-size prerequisite is inferred merely from the name.

They still require the real selected declaration, CSS-wide/revert handling, shorthand cache, reference generation and application identity. The existing retained controller can be reused after controls establish those boundaries; only checking the type enum is insufficient. A dynamic declaration of an identity-valued property can contain attr()/var() and suspend before that value exists. A waiting custom property must not become invalid or cause its outer owner to be discarded.

## Numeric settings are not context-free numbers

FontFeatureSettings contains Integer components; FontVariationSettings contains Number components. The ordinary parser accepts a CalcNumeric AST of number type, not only literals. Number/Integer::to_computed_value calls calc.resolve with the real Context; Integer additionally applies native rounding. Calc Leaf conversion can read lengths using CurrentStyle font and line-height bases, tree counting, or RandomKey. Dimensional cancellation can leave a number-typed expression containing relative-length leaves. Candidate controls such as `"wdth" calc(100 * 1ch / 1px)` must first confirm actual parser support; this audit did not execute that string. It cannot be classified as independent of font metrics merely because the final type is Number. The exact feedback policy when a font-setting conversion itself reads current font metrics is still an open native/spec correspondence obligation; no numeric result is invented here.

`random()` and sibling functions are pref- and context-gated in the saved parser. RandomKey::auto uses property ID and the current random occurrence index; parse increments the index and parse_number wraps parsing with random-index rollback. Retained parse state must preserve that identity. Actual Context::random_base_value hashes the key, optional element identity and document seed into a fresh deterministic PRNG: it does NOT consume a mutable global random stream. Element-scoped evaluation nevertheless sets USES_ELEMENT_SCOPED_RANDOM and makes the rule uncacheable. Sibling-index/count likewise set their own dependency flags and uncacheable status, and read the current element/pseudo tree-counting result. Stable output alone does not prove these effects were preserved. Context::resolve_tree_counting_result also tests current_scope().shadow_order() before using its mutable element-context cache; the nonmatching scope returns the default count/index. apply_one_longhand temporarily installs the selected declaration's cascade scope around native dispatch. Precomputing a settings value under the ambient scheduler scope can therefore use the wrong tree count even with the same element. AST classification must not perform that conversion speculatively; native evaluation must retain the exact selected scope.

FontSettings converts every entry before sorting/deduplicating tags, retaining the last duplicate. Thus a discarded duplicate can still contribute dependency/cache effects. A proposed optimization that deduplicates first is not equivalent. A concrete distinguishing control is an enabled, supported random or sibling expression on the first occurrence of a tag, followed by a literal duplicate: final numeric value alone is insufficient; dependency effects must also match the real native path. For random use a stable explicit key to distinguish identity preservation from statistical coincidence.

## System-font route into the scanner

The real font::parse_value SystemFont branch gives special system variants only to Family, Size, Style, Width and Weight. It resets twelve scanner properties to their native initial specified values: kerning, language override, alternates, east-asian, emoji, ligatures, numeric, position, feature settings, optical sizing, caps and variation settings. Other scanner properties are outside that shorthand branch. Therefore this branch does reach ordinary inputs, but through initial declarations, not a hidden SystemFont variant in every scanner type. The separately prioritary properties still perform Gecko_nsFont_InitSystem/cache resolution and text scaling; those effects cannot be bypassed. A variable-containing font shorthand must retain its actual substitution/parse and share only the source-identity-keyed shorthand result, not recompute the system font for each ordinary reset field.

## Completion and ordering

`resume_font_selection` retains cursor, flags, revert state, owned substitution engine and exact value/generation reply checks. It calls note_variable_substitution once when beginning that engine, then finish_retained_substitution only at terminal completion. The latter parses under the actual property identity and can populate a shorthand cache. `publish_prepared_metric` checks completion, waiting state, flags, seen/revert and prioritary dependencies before applying retained declarations through apply_one_longhand. Only successful publication enters completed_font_inputs. These are existing mechanisms, not newly proven native effects.

A conditional failure shape exists: if flags change after an ordinary input is applied, import_priority_completion clears its completion bit while cascade.seen remains; resume/publish then reject that seen property. This is not an established reachable bug. The actual data.py dependencies give FontSize→XTextScale→Family→Appearance, and each of Weight/Width/Style/SizeAdjust→Appearance. Ordinary FontMetrics admission requires those completed properties, whereas the early ComputedSize-only facet bypass does not request these scanner inputs. Under sound completion bits and the current flag-writer path, Appearance is finalized before ordinary input application. ORDERING.json records those exact paths. There is no reason to add an unconditional new wait on arbitrary orientation inputs to repair a hypothetical flag transition.

The invariant must remain explicit: a completion receipt is valid for the declaration selection/flags that produced it, and a post-application change cannot be handled by replaying native effects after consumers used old metrics. For a future path that admits a new flag writer, either finalize that writer before publication, or prove the selected declaration and effects unchanged using a retained receipt. Detection after consumption is not repair. Likewise, a seen property already applied through another legitimate route needs a matching completion receipt, not an arbitrary mark-complete or repeated application. No such new route is implemented here.

## Small coherent implementation sequence

1. Extend the retained action to the twelve identity-like inputs only with source-mapped literal, inherit/initial/unset, revert/layer, shared-shorthand and suspend/resume controls. Preserve exact owner/generation checks, flags and declaration selection. Keep the seven-input patch independently testable.
2. For settings, classify the actual selected numeric AST before native application. Acquire only its real prerequisites: constants need none; length leaves need their actual CurrentStyle metric/root/viewport dependencies; tree/random leaves need stable Context identity and their native effects. Preserve all list entries through conversion and native duplicate ordering. Do not blanket-wait on all font inputs, which can add false cycles.
3. Give nested work an explicit suspended outer bundle and action-tagged replies as described in the existing child-action design. Retain parser/drain state; after an input completes, restore and resume its outer owner. No invalid fallback for Pending and no restart of a parser that has already produced effects.
4. Preserve the once-only application boundary and publish a completion receipt with the selected longhand/declaration/revert/flags identity. Audit any non-action ordinary application that can precede scanner publication. Add controls for same-value but changed identity, post-publication invalidation, already-seen input and inactive @appearance-base declarations.
5. Compile the real three-source Context and run unchanged minimum_off plus the full source-bound matrix and new all-input controls. Numeric pref/parse prerequisites and dependency effects must be observed, not assumed. All 21 inputs and supported dynamic forms remain required; unsupported Pending is an implementation boundary, not the finished design.

The exact native getter behavior for relative length conversion, typed-arithmetic parser cases and the resulting feedback/cycle policy remains to be validated. This report narrows the hard cases and excludes an alleged general system-font or reachable ledger-reset defect; it does not close those broader obligations.
