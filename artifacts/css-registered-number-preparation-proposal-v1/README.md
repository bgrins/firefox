# Registered-number preparation proposal: live pending overlay

This artifact proposes changes to the two captured live native files after fix 138, based on signed HEAD `eb9c04b94cf3007d4f4b4d45ba99cd826829e455` plus the existing uncommitted prototype. It requires the separately pinned numeric collector. It is not a validated fix, a compile result or a standalone patch against committed HEAD. The ordinary-path sibling artifact supplies the committed-HEAD variant without the pending prototype.

`fix.patch` changes only `custom_properties.rs` and `properties/cascade.rs`. The collector supplies `SpecifiedValue::number_context_references() -> Option<ReferenceFlags>` in a third native file. No prototype content is silently copied into this patch. `BASE.json` records live and committed hashes; `head-base` preserves the committed comparison bodies. `CONTEXT-PINS.json` authenticates the actual local parser/math sources, which match the older research captures byte-for-byte. Searchfox syntax lookup succeeded; a subsequent value.rs retrieval failed DNS. This is recorded rather than represented as a fresh upstream capture.

The ordinary dependency prefilter explicitly includes exact scalar `<number>` registrations. This admits real numeric length operands to the graph without depending on the prototype's broad `DataType` widening. The other prototype numeric classifications remain unchanged.

The graph visitor now reports whether each visited primary var/typed-attribute node has left the Tarjan stack. It checks actual node identity after traversal. A root with `lowlink == index` is insufficient: a mutual component can still contain open providers. Preparation is eligible only for an exact scalar number registration and a settled visit. Open components retain the previous traversal and cycle handling.

Preparation performs existing selected substitution and actual `SpecifiedRegisteredValue::parse` with unchanged URL, namespace argument, property identity, computational-dependence permission and attr-taint inputs. It retains an owned Invalid, CSSWide or parsed Value result in the current traversal frame. The existing CSS-wide match is extracted unchanged into a shared helper. An invalid selected number clears only its own contextual expression edges; it does not undo custom/attribute graph edges or settled cycle failures.

For a supported admitted scalar, the collector's flags replace the lexical accumulator rather than being ORed into it. Invalid and CSS-wide preparations have no unit context requirement. Collector `None` preserves the original graph accumulator; a selected-token scan supplies the previous pending-prioritary fallback. `Some(empty)` means no representable font/line-height graph edges, not no context reads whatsoever: absolute lengths still use existing zoom handling. Unsupported numeric AST forms remain conservative.

The prepared value is computed/published only after the unchanged SCC pop and cycle-invalidity return. Any demand or detected cycle drops the traversal-local cache. A later retry prepares again; no cache spans provider completion or style epochs. The pending application path uses the same parsed result and semantic flags before requesting pending prioritary context, preserving demand as distinct from invalidity. Substitution/attribute primitives themselves are byte-identical to the captured live base; they are not replaced by the Lean model.

This targets the release-observed unused-fallback and selected-invalid-number family as well as the additional WIP direct-invalid-em path. It retains real `calc(1em / 1px)` scheduling. A numeric self-font-cycle remains subject to the existing graph's handling; this proposal does not claim a normative default for the unresolved spec integration question. Compared with committed HEAD, routing numeric length math through that graph can expose that policy where the old type mask did not. Record this as observation, not an assertion oracle.

Validation here is limited to Rust syntax/formatting, exact two-path patch apply/reverse/reapply on owned scratch, and static preservation checks. Both source files parse under rustfmt with edition 2024. The CSS-wide match is unchanged modulo whitespace; substitution primitives are unchanged; the publication point remains after cycle settlement. These checks do not establish type correctness, borrows, native semantics, scheduling completeness or absence of effects before publication.

Before acceptance, the owner must build the combined collector/preparation proposal, run controlled original/candidate WPTs including true self/mutual and typed-attribute cycles, verify both ordinary and pending paths, preserve CSS-wide and taint behavior, and retain noncyclic numeric-math font-mutation assertions. The exact eight defensible oracles and observation-only self-cycle distinction remain in the pinned trace. No new Lean theorem or native correspondence is claimed by this patch.

All changes were made to artifact copies. No live native source, epoch, browser, objdir, Git index or HEAD changed. Owned transport scratch was removed.
