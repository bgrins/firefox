# Reachable registered font-demand provider

This experimental source successor connects the real retained-frame entry to font-demand classification and prerequisite dispatch. It is not a complete metric repair or a native-validation candidate. Unsupported waits reach the existing terminal assertion; this is a deliberate development tripwire, never proposed shipping behavior. No native source, app, browser, Git or canonical state was changed.

The parent is the sealed action slice 77112247; the full patch uses published cascade 5b7204 and provider bb13. The custom-properties postimage is exactly the earlier reviewed transport prototype 90acb505: four-level None/ComputedSize/FontMetrics/OrientedMetrics demand, widened flags, unchanged three semantic cycle identities. The new cascade changes are separate in PARENT-DELTA.patch.

The registered frame derives demand from its retained own/reference flags after reference traversal. Unregistered aliases retain resolved token flags; typed-attribute raw values contribute flags before their registered consumer substitutes and computes; a registered alias must finish its own computation before its dependent resumes. The classifier uses the existing root-aware semantic iterator to project demand. It neither adds new CSS graph nodes nor removes unused-fallback inventory. Initial/default, invalid grammar and branch-selection precision remain bounded by the existing inventory; an excessive inventory can suspend work conservatively. This is not a claim to settle the unused-unit-fallback timing question.

At actual FramePhase::Publish, computed size requires a completion certificate, metrics requests Weight/Width/Style/SizeAdjust, and oriented metrics then requests Direction/WritingMode/TextOrientation. The actual root loop dispatches each retained action and resumes after successful publication. Generated and selected-reference waits remain Pending without an invented ready reply or cycle classification. The owner payload is not consumed until the provider returns Ready. COLOR/Image preparation can perform typed-attribute substitution before Publish. Only the actual preparing branch with ATTR plus font demand checks early readiness; otherwise pure syntax/AST preparation remains before the unchanged semantic unit links. An unresolved early ATTR read suspends explicitly. Pending retains the COLOR_SCHEME marker, so another poll cannot silently skip preparation. No conservative font edge was moved ahead of selection.

Cascade now records ordinary completion after apply_one_prioritary_property returns, and only when all generated prerequisites are certified and the declaration chain contains no WithVariables. The early ensured bit is still not a certificate. Completion records are invalidated if included_cascade_flags changes, so an Appearance flag change cannot certify an earlier excluded declaration. The Context imports these records; successful staged actions add their completed publications. This is a conservative bridge for actual literal/default ordinary application, not a general proof of dynamic priority finality. Invalidated completed work is not automatically recomputed: the existing early ensured bits and retained computation may force an explicit unresolved stop. No rollback of already observed custom values is claimed.

The seven action properties do not establish complete font readiness. UNTRACED-FONT-INPUTS.json is generated from the frozen font-struct metadata; any own declaration for a non-priority font field conservatively leaves metric demand unresolved after the supported actions. Field existence alone does not prove metric influence. Searchfox discovery in METRIC-BODY/GET-METRICS/FONT-STYLE captures traces the current query through nsFont and nsFontMetrics, where synthesis flags, language override, font features and variations enter the font setup. These captures are discovery, not a fresh-branch source join or proof that every field affects every metric. The actual 13-case fixture sets font-synthesis:none, so this prototype intentionally does not claim to finish that matrix. Selected non-priority font-input preparation is the next concrete producer to integrate, reusing the retained rollback/reference state.

Nine extracted Rust tests exercise the actual flag/classifier/provider, ordinary completion code and staged action methods with controlled Stylo/declaration doubles. They cover unit/root/alias-flag joins, independent size completion, seven actual literal action publications in order, early-bit and dynamic-chain rejection, unresolved selected references, and eligibility-flag invalidation. Two route tests execute the exact Prepare/Units/Publish arm bodies: pure union 1em retains the AST before emitting FontUnits and computes after completion; repeated ATTR waits retain the marker and resume only after external completion. Those route tests stub parse/application and supply the semantic child completion; they do not prove a native font value. Ten compiled mutations fail behavioral assertions. The first source-string extraction error and first control run (which exposed a missing mixed em+rch assertion) are retained. The final tests disable debug assertions and remove scratch directories.

The harness extracts the actual preparation and publication arms but does not execute the full native reference parser, DOM attribute lookup, complete frame traversal, real font computation or Context lifetimes. The parent packages provide separately bounded traversal/action tests. The test list’s alias case joins flags; it is not a browser alias test. check.py authenticates exact extracted bodies, the unchanged recursive eager traversal, both two-file forward/reverse patch roundtrips, pinned formatting, test receipts and provider equality. Native typechecking is still required. Real generated/selected-reference producers, non-priority font-input staging, computation invalidation/restart and terminal true-cycle policy remain unfinished; none is silently marked ready to pass observations.
