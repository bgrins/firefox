# All-property declaration chains over a shared heap

This closes the predecessor model's simultaneous-property gap. A single executable builder now maintains all per-property heads and tails over one shared next-index heap. The proof derives disjoint chain membership from the declaration stored at each vector index and a fixed property mapping; it does not assume that writes for another property preserve a chain. Actual Lean run3 (4166af / 48117 / 224d48, exit 0) audited 19 theorems and rejected six genuine false controls. Root's full proof review 09bf1d cleared this scope. No native or browser result is claimed.

`State` holds the complete declaration vector, per-property head/tail functions and one next heap. `mapping : Nat → Option Nat` abstracts the generated longhand-to-prioritary-id function; None denotes an unrelated longhand. It is fixed for the entire build. The model permits different longhands to map to the same target and does not assume the mapping is injective. Concrete generated ids and array bounds remain native correspondence obligations.

`note` implements the actual operations: initialize the fresh vector index's next to zero; append every declaration; for a mapped property below the sentinel bound, either initialize its MAX head/tail or link its previous tail to the new index and advance its tail. Other property heads and tails are untouched. Nonmapped and over-capacity declarations still remain in the full vector. Natural-number indices represent the logical behavior under the native guard, not machine arithmetic or allocation.

The global invariant pairs a linked `Path` representation with `Owned` for every property. `Owned` states that each chain index actually looks up a declaration whose fixed mapping names that property. `owned_append` and `owned_advance` preserve that fact from real vector appends. `owned_chains_disjoint` then derives that two distinct mapped properties cannot share a member index. In `note_preserves`, the selected property's chain extends through the predecessor's proved tail-update lemma. For every other property, the touched old tail belongs to the selected chain, so derived disjointness permits the existing off-path heap-write lemma. A new zero-initialized index is beyond every existing allocated tail. No chain-preservation or disjointness premise is imported as an assumption.

`build_preserves` lifts those concrete updates through arbitrary finite declaration lists. `fresh_global_invariant` starts from empty heads/tails and no ownership facts. `all_chains_read_admitted` proves every property's actual modeled traversal equals its admitted projection. `all_chains_complete` gives the full projection when the complete vector length is at most the sentinel. `final_chains_disjoint`, `final_head_tail_bounds` and `all_vector_entries_retained` expose the global consequences. The executable interleaved example places two properties around an unmapped declaration, yielding independent chains [0,3] and [1,4] in the same heap.

The six separately compiled false controls reject cross-property tail contamination, loss of an earlier chain on another property's append, dropping unmapped vector entries, counting only a property's declarations for capacity, treating head zero as absent, and overlapping mapped-property chain membership. They target the global builder directly. Each fails by Lean's decide-false diagnostic, not a parse error or missing name.

## Correspondence and limits

The native builder excerpt and candidate are pinned in REFERENCES.json and SOURCE-MAP.json. Native code updates the old tail before pushing the new zero-initialized entry; the model initializes the fresh heap slot first. The derived old-tail < new-index fact makes these distinct writes agree. The prior exact Path/read proofs are imported unchanged, as is the earlier finite-capacity model.

The formerly external all-property shared-heap induction is now proved within this functional model. Remaining external obligations are concrete Rust vector/SmallVec memory behavior, integer representation and guard/cast correspondence, the generated mapping and array bounds, and browser matching that supplies the declaration vector. The heap and property maps are total mathematical functions, not allocations or pointers. The native traversal may stop after a winner or use CSS rollback decisions; these theorems concern the complete index chains, not winner selection or semantic evaluation. Widening u16 to u32 still raises a finite bound; neither this proof nor the candidate establishes unbounded capacity.

The reused pinned runner compiles two unchanged imports, the new module, and the audit/negative modules in an owned temporary directory. Run1 contained record-syntax and proof-elaboration failures; run2 needed explicit unfolding in two noninterference branches. Those failed attempts remain archived. Run3 has no proof warnings, all three scratch directories are absent, and no .olean/.pyc output remains in the package. Its audits use only propext and Quot.sound; no axioms, sorry, unchecked native evaluator, or assumptions of desired update behavior were introduced.
