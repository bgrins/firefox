# Semantic closure and publication ownership

This is an artifact-only source integration slice above sealed `css-font-metric-pending-integration-v1`, whose published cascade base is `5b7204f8`. Unlike the preceding added helpers, this patch changes the actual nested traversal, post-SCC publication and root-retirement call sites in `substitute_all`. It does not enable scheduling suspension or repair font metrics. No native build, browser run, live source read or canonical/Git mutation occurred.

Each indexed node now owns a `NodePublication<ClosedValue>`. Removing its name from the Tarjan stack does not make its value computed. An acyclic closed node retains either the prepared custom AST, the original raw value Arc and substitution identity, or the priority ID. `publish_closed` consumes that exact retained payload once and marks completion only after the existing application operation returns. A lookup consults node state before the map shortcut, distinguishing semantic ancestry, computation-pending, completed value, and settled cycle. Applying is computation-pending for reentry. The semantic lowlink update still accepts only an active semantic index.

For a cyclic component, each original `handle_loop` call remains in its original pop order. Cycle members are marked settled only after all those calls complete. `CycleSettled` certifies that this existing synchronous invalid/default publication has run, not that future contextual metric defaults have satisfied a new scheduler. A scheduling wait is never inserted as a CSS graph edge. The context cannot reset between roots or retire its last root with an active stack or unfinished publication. The existing stack/index maps remain owned by the one `substitute_all` context; no second traversal borrows or renumbers a suspended stack.

The synchronous compatibility boundary is deliberate and visible: `publish_closed` calls `take_ready(true)` because it still invokes the existing eager native publication operation. This is not a proof of final metric prerequisites. A `ComputationPending` result reaching the old recursive `visit_link` is rejected explicitly, and the root requires a completed outcome. There is no reachable new Pending producer that returns past publication in this slice. These guards are integration tripwires, not a terminal CSS cycle policy and not a valid way to enable suspension.

Real suspension still needs owned parent frames retaining the exact reference/fallback cursor, lowlink/self-reference state and prepared AST. The previous `ReferenceWalk` is not attached here. Adding `?` to the recursive calls would drop those locals, so that shortcut is absent. The generated ensure/application path, per-consumer readiness certificate and final drain must resume those frames before Pending can be enabled. Settled-cycle replies require completed invalid/default map outcomes, and suspended contexts require stable inputs or explicit invalidation. Whole-font consumer coverage and genuine metric wait-cycle policy remain open. The patch therefore cannot be promoted as a runnable metric repair or evidence that the release wrong-weight failures are fixed.

`PARENT-DELTA.patch` is the complete delta from the preceding slice; `native.patch` includes that earlier preparation against the published base. The frozen provider captures authenticate the actual `PreparedCustomValue` ownership and `ComputedValue` Arc types used here. Rustfmt parses the full proposed source, and both patches apply/reverse with zero fuzz. Stylo typechecking remains pending.

The doubles do not prove real parsing, builder finality, Tarjan reachability or generated ensure behavior.
