# CSS log clear special-value proposal

Recommend one standalone native-and-WPT fix for the two clear logarithm dispatch rules. They are independently observable, but share the same operation, two implementation call sites, and an interacting precedence rule: `log(1, 1)` must remain NaN rather than taking the argument-one shortcut. Splitting is technically possible, but would stage an incomplete exceptional-value dispatch and duplicate the same integration/testing surface. This recommendation does not assign an accepted ID or claim two new discoveries: the existing WPT already records base-one and zero-sign failures.

The [CSS argument-range rules](https://drafts.csswg.org/css-values-4/#exponent-infinities) reject base one and prescribe positive zero for argument one. `native.patch` introduces one private helper and calls it from `CalcNode::resolve_internal` and `CalcNode::simplify_and_sort_direct_children`. Base one returns NaN first. Argument one returns positive zero only when the base is positive; all remaining cases delegate to the unchanged floating-point logarithm. This leaves negative and NaN bases on their prior NaN-producing path, preserves NaN arguments, and leaves natural logarithms and all type/leaf eligibility checks unchanged.

In particular, both signed zero bases still reach `a.log(b)`, even for argument one. Arguments zero/infinity with a base strictly between zero and one also reach it unchanged. No new test asserts an answer for those unresolved boundaries. The explicit positive-base restriction is necessary to avoid accidentally changing base-zero behavior while implementing the clear argument-one case. Base-one invalidity is unambiguous even at argument zero/infinity and is included.

The patch preimage is accepted pow's `calc.rs`, SHA b291d6e9a30e486fd42ff0cb3cda00cfead0ee7f7149761d8685a8cc85889576; SOURCE.json records the candidate hash. It was applied only in disposable scratch and reconstructed that exact candidate. It must be reconciled with any subsequently installed MinMax change before execution; this artifact does not supersede that work or claim a clean-upstream application.

The proposed installed test path is `testing/web-platform/tests/css/css-values/log-clear-special-values.html`. Its 24 authored callbacks comprise seven literal targets, three deferred targets, and fourteen controls. That partition is a source expectation, not observed browser evidence. Five controls calibrate NaN, both infinities and both zeros with four opacity components: the expression, its negation, reciprocal and negated reciprocal. Generated negative zero is `-1 * 0`. This reuses the earlier audit's complete five-class observer; ordinary finite tests instead use the existing numeric-testcommon scale helper. NaN cannot pass the positive-zero expectation, and either zero cannot pass the NaN expectation.

Four contextual callbacks sample font sizes 0, 2 and 0 pixels. They cover a base reaching one, a valid base below/above one, an argument reaching one, and invalid-base precedence. Each sample creates an element and assigns the expression, so this is deferred contextual evaluation coverage, not a retained-declaration invalidation test. No instrumentation establishes native-path coverage yet. The remaining controls cover NaN/negative-base precedence, natural log, valid base two, and ordinary logarithms with increasing/decreasing bases.
