L218: 
L219: For all elements, the user agent must match the following to the 【91†element color scheme】:
L220: 
L221:   * the default colors of scrollbars and other interaction UI
L222: 
L223:   * the default colors of form controls and other "specially-rendered" elements
L224: 
L225:   * the default colors of other browser-provided UI, such as "spellcheck" underlines
L226: 
L227:   * the value of 【86†system colors†www.w3.org】
L228: 
L229:   * the value of the 【92†light-dark()†www.w3.org】 function
L230: On the root element, the 【91†element color scheme】 additionally must affect the surface color of the 【121†canvas†www.w3.org】, and the viewport’s scrollbars.
L231: In order to preserve expected color contrasts, in the case of embedded documents typically rendered over a transparent 【121†canvas†www.w3.org】 (such as provided via an HTML `【97†iframe†html.spec.whatwg.org】` element), if the 【91†element color scheme】 of the element and the element color scheme of the embedded document’s root element do not match, then the UA must use an opaque canvas of the 【122†Canvas†www.w3.org】 color appropriate to the embedded document’s root element’s element color scheme instead of a transparent canvas.
L232: This rule does not apply to documents embedded via elements intended for graphics (such as `【98†img†html.spec.whatwg.org】` elements embedding an SVG document); their canvases remain the default transparent regardless.
L233: Note: Aside from the small list of adjustments given above, user agents generally do not further adjust a page to match the user’s preferred 【68†color scheme】, because the chance of accidentally ruining a page is too high. However, when particular color choices are required by the user (for accessibility reasons, for example), more invasive changes might be applied; see 【40†§ 3 Forced Color Palettes】.
L234: ### 2.5. Overriding the Color Scheme
L235: If the user has indicated an 【120†overriding preference】 for a particular color scheme that the author does not explicitly support, and the author has not disallowed this (by using the 【119†only】 keyword), the user agent must override the color scheme: in addition to the effects described in 【38†§ 2.4 Effects of the Used Color Scheme】, it must also auto-adjust other colors into this chosen 【68†color scheme】, such as by inverting their brightness, while preserving any color contrast necessary for readability of the page.
L236: In this case, UA may also auto-adjust colors within replaced elements, background images, and other external resources as appropriate.
L237: Note: The specifics of such auto-adjustments are UA-defined, and can differ from UA to UA. But it is not intended to force all colors into a fixed palette, as 【70†forced colors mode】 does, only to force all colors on the page to conform to either a 【84†dark】 or 【83†light】 color scheme.
L238: 
L239: For example, a UA might have a “dark room” mode, which forces all pages into a 【84†dark】 color scheme.
L240: For pages that already support 【84†dark】 color schemes, and have indicated so using the 【69†color-scheme】 property or `【94†color-scheme†html.spec.whatwg.org】` `【123†meta†html.spec.whatwg.org】` name, this has no effect other than reporting a 【124†dark†www.w3.org】 value for the 【73†prefers-color-scheme†www.w3.org】 【76†media query†www.w3.org】 and selecting a dark 【95†used color scheme】.
L241: But for pages that do not explicitly support a 【84†dark】 color scheme, and have not explicitly forbidden this auto-adjustment by specifying 【69†color-scheme: only light】, this mode triggers auto-adjustment of the page’s colors to force the page to conform to the desired dark color scheme.
L242: ## 3. Forced Color Palettes
L243: 
L244: Forced colors mode is an accessibility feature intended to increase the readability of text through color contrast. Individuals with limited vision often find it more comfortable to read content when there is a particular type of contrast between foreground and background colors.
L245: Operating systems can provide built-in color themes, such as Windows’ high contrast black-on-white and high-contrast white-on-black themes. Users can also customize their own themes, for example to provide low contrast or hue contrast.
L246: In 【70†forced colors mode】, the user agent enforces the user’s preferred color palette on the page, overriding the author’s chosen colors for specific properties, see 【41†§ 3.1 Properties Affected by Forced Colors Mode】. It may also enforce a “backplate” underneath text (similar to the way backgrounds are painted on the 【125†::selection†www.w3.org】 pseudo-element) to ensure adequate contrast for readability.
L247: To enable pages to adapt to 【70†forced colors mode】 user agents will match the 【75†forced-colors†www.w3.org】 media query and must provide the required color palette through the CSS system colors (see 【126†[CSS-COLOR-4]】).
L248: Additionally, if the UA determines, based on Lab lightness, that the 【122†Canvas†www.w3.org】 color is clearly either dark (L < 33%) or light (L > 67%), then it must match the appropriate value of the 【73†prefers-color-scheme†www.w3.org】 media query and express a corresponding user preference for 【69†color-scheme】. This will allow pages that support light/dark color schemes to automatically adjust to more closely match the forced color scheme. Behavior between the above dark vs.
L249: light thresholds is UA-defined, and may result in assuming either light or dark as the user’s preferred color scheme.
L250: If 【127†get emulated forced colors theme data】 is not "`【128†none】`", the user agent should bypass the above operating system color themes, and instead act as if the user has enabled 【70†forced colors mode】 with the 【129†forced colors mode emulation color palette】 defined for the resulting value of 【130†emulated forced colors theme data】.

L1240: ### 6.1. Naively Converting Between Uncalibrated CMYK and sRGB-Based Color
L1241: 
L1242: To naively convert from CMYK to RGBA:
L1243: 
L1244:   * `red = 1 - min(1, cyan * (1 - black) + black)`
L1245:   * `green = 1 - min(1, magenta * (1 - black) + black)`
L1246:   * `blue = 1 - min(1, yellow * (1 - black) + black)`
L1247:   * Alpha is same as for input color.
L1248: 
L1249: To naively convert from RGBA to CMYK:
L1250:   * `black = 1 - max(red, green, blue)`
L1251:   * `cyan = (1 - red - black) / (1 - black), or 0 if black is 1`
L1252:   * `magenta = (1 - green - black) / (1 - black), or 0 if black is 1`
L1253:   * `yellow = (1 - blue - black) / (1 - black), or 0 if black is 1`
L1254:   * alpha is the same as the input color

L1311: ## 8. Dynamically specifying a text color with adequate contrast: the 【96†contrast-color()】 Function
L1312: 
L1313: When colors are created dynamically, it can often be a challenge to specify a text color that provides adequate contrast with them when used as a background color. The 【96†contrast-color()】 function automatically provides a color with guaranteed color contrast when used as a text color on a solid background of the specified color.
L1314: Note: Legibility is a complex topic, and sufficient color contrast is only one piece of the puzzle. Having a color pair with sufficient contrast does not guarantee that the text will be legible, as that also depends on a variety of factors, such as the font, the size of the text, the surrounding colors, etc.
L1315: 
L1316:     contrast-color() = contrast-color( 【100†<color>】 )
L1317: 【96†contrast-color()】 resolves to either 【378†white】 or 【379†black】, whichever produces maximum color contrast for text when the input color is used as a solid background. If both white and black produce the same contrast, it resolves to white.
L1318: 
L1319: The precise color contrast algorithm for determining whether to output a light or dark color is UA-defined at this level.
L1320: Note: Future versions of this specification are expected to introduce more control over both the contrast algorithm(s) used, the use cases, as well as the returned color.
L1321: UAs are advised to not simply use the WCAG 2.1 【380†section 1.4.3 Contrast (Minimum)†www.w3.org】 contrast ratio algorithm to decide between light and dark colors, as it has 【381†several known issues†www.cedc.tools】. However, colors returned by this function should still meet the WCAG 2.1 【380†section 1.4.3 Contrast (Minimum)†www.w3.org】 for AA large text, as many authors need to meet legal requirements that mandate this.
