# Separating dependency preservation from forced color-scheme serialization

Reviewed 2026-10-30 against the sealed two-callback forced-color fixture. No fixture, runtime, or native state was modified or read live.

The existing auto expectation has a normative basis: [Color Adjustment §3.1](https://drafts.csswg.org/css-color-adjust-1/#forced-colors-properties) makes auto's color-scheme compute to light dark. The reference opts out of palette forcing and explicitly declares that support list. With the same preference and support, [scheme resolution](https://drafts.csswg.org/css-color-adjust-1/#used-color-scheme) selects the same element scheme. Color forcing acts on used colors; it does not replace the computed color expression with the palette color. [Color 5's light-dark rule](https://drafts.csswg.org/css-color-5/#light-dark) therefore selects the same red/blue computed value for both.

Removing only auto's target scheme assertion does **not fully isolate** the dependency test from the known literal color-scheme failure. If an implementation computes normal and also uses the default light scheme while the explicit light-dark reference chooses dark, their colors differ without a custom-property cycle. Matching the specification's intended support is not evidence that a known-broken implementation actually used the same scheme.

Recommended successor: preserve the current opt-out reference as a normative diagnostic and add a matched dependency reference with a separate registered `<color>` property, the same light-dark(red,blue) expression, literal forced-color-adjust:auto, and literal phase color-scheme:dark/light. It must have no losing variable declaration. Compare the target's registered computed value against that reference, retaining initial registration and red/blue calibration. Collect target first plus passive samples before reading controls. Record both schemes and both references. This compares against the already-covered literal behavior even if that behavior is separately wrong; it is a preservation discriminator, not full forced-colors conformance.

Keep none's literal phase-scheme assertion and its existing opt-out reference. Keep tracked test 51 and its expected-FAIL metadata unchanged. Retain all auto custom-value checks; do not skip a callback or accept green merely because the scheme is already wrong. Green differs from both candidate branches and is useful evidence of defaulting, although it does not itself prove the internal cause.
