# Preserve deferred Sign dependencies and intermediate special values

This artifact successor addresses the concrete HOLD on v1; it is not accepted and has not been compiled as Gecko or run in a browser. The original four-case/233-control diagnostic remains unchanged. The patch is independently applicable to HEAD90 and contains four Rust files and one fourteen-case WPT.

## Native scope

The generic `CalcNodeLeaf::sign_from` gate uses `canonical_value`, retaining relative-length and unresolved-percentage dependencies until evaluation. This is the original v1 change. The successor also separates actual length evaluation from normalization at a property-value boundary. New `NoCalcLength::to_computed_value_for_math` performs the existing per-unit arithmetic and provider acquisition without its terminal censoring. The existing public `to_computed_value_with_base_size` wraps it with exactly the old policy: viewport units normalize NaN only, while other units normalize and clamp to finite f32. Direct length/font callers still use that wrapper.

Both calculation mappers use the uncensored result: `specified::calc::Leaf::to_computed_value` for numeric results and `specified::CalcLengthPercentage::to_computed_value_with_zoom` for length-percentage results. The latter retains its existing text-zoom step. Existing final numeric conversion and `LengthPercentage::new_calc`/final percentage resolution retain their boundary normalization. The change applies to length leaves inside calculations generally, not only a direct child of Sign; it therefore covers compound operands and deliberately changes preexisting early censorship in other enclosing calculations. This broader intermediate-value contract needs full existing-math-suite preservation, not only fourteen new passes.

No provider is reconstructed from the value of a coefficient of1. Font reference selection and cache flags are unchanged. Viewport calculation retains zoomed AU multiplied by the original coefficient in f64, truncation, division by AU_PER_PX and f32 projection in their existing order. Container calculation retains its f64 product. Absolute units retain zoom. Internal ServoCharacterWidth retains its i32 cast and affine calculation; it is not treated as an authored multiplicative CSS unit. Only terminal normalization moves into the ordinary wrapper. The private per-unit helper bodies are otherwise unchanged. Searchfox identifier/text discovery found their calls only within this dispatcher; the external base-size callers remain on the existing wrapper.

## Why both parts are necessary

Old parsing can fold sign(1em) using coefficient1 before a zero font basis is known. Deferring that fold fixes finite zero-basis cases but v1 then feeds relative NaN into `.finite()`, changing NaN to0 before Sign. The enclosing opacity can change from0 to0.5, a new regression. Infinity multiplied by a zero font basis produces NaN too; an early raw-NaN special case alone cannot address it. The raw calculation conversion preserves those values through Sign and enclosing arithmetic, until the existing outer boundary censors them. Negative-infinity outer zero on the old path can be an accidental match despite an incorrect inner Sign.

This follows the independently pinned CSS Values4 resolved-argument Sign, numeric-dimension conversion, NaN propagation and outermost censoring trace. The normative trace and source-shaped IEEE experiments are separate from an observed browser traversal. There is no universal IEEE/refinement theorem or new canonical model in this capsule.

## Controls and evidence

The WPT is byte-identical to the separately sealed special-controls capsule: original four entries, direct/compound NaN and both infinities in six opacity entries, and four width-result entries covering the second mapper. Each has16→0→16 font history, copied first/repeat values, computed font and independent1em geometry calibration. Warm and restored expected results precede the final zero-font assertion. They are real preservation gates: a positive-basis NaN regression cannot be relabeled as an expected zero-font failure. No baseline failure count is assumed. The existing233-control suite and its retained metadata remain necessary, alongside broader calculation/length controls selected before native comparison.

`check.py` authenticates source/candidate pins and immutable dependencies, checks exact private helper/provider-body deltas, and runs455 scalar per-unit/terminal-policy cases at Rust optimization levels0 and2. Inputs include NaN, both infinities, both zeros, finite values, smallest subnormals and f32 endpoints; bases include both zeros and positive fractions. Actual `calc_sign`, `normalize`, `finite` and `normalized` definitions are extracted. Unit arithmetic uses explicit scalar adapters for supplied provider outputs; this does not compile the context/provider/type machinery. It checks original wrapper policy preservation, the uncensored Sign result and the finite viewport counterexample to coefficient1 rescaling. These finite tests are not an all-f32 proof. Temporary compiler products are removed.

Scratch Git check/apply/reverse-check/reverse verifies exact candidate postimages and restored sources without touching the parent index. Fixture syntax and fourteen inert registrations were checked in the special-controls capsule. Six HEAD90 source/support copies are retained; only four native paths are modified. Full Gecko compilation, browser observations, unchanged finite/provider behavior and paired old-test preservation remain open gates. No live native/WPT, index, canonical library, Gecko build or browser changes occurred.
