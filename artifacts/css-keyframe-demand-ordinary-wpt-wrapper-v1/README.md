# Four ordinary-substitution WPTs

Prepared for the completed typed-demand GTest epoch at HEAD `87445004c1ae44d9c1e2873b91f01414cf75cbb2`. No browser or Mach command was executed while preparing this wrapper. The existing registered-unused-fallback audit remains a separate lead; this wrapper does not run it.

`run.py` authenticates its own manifest, the reviewed roster and helper sources, and an externally supplied digest of the completed runtime epoch. It uses the project's existing root/nested preservation verifier and process cleanup helper. Both normal Firefox and normal XUL must match that epoch; GTest-specific XUL is not required to equal normal XUL. The entire epoch is rechecked afterward, including source bodies, installed identities, committed research, root/nested indexes, and binary pins. Extra WPT runner inputs, actual profile files, mozinfo, source/resource/header/metadata presence and absence are pinned before and after execution.

The owned output directory contains exact copies of the four test files, their directly referenced resources and headers, and all present inherited/per-file metadata from the roster. The runner manifest is reduced to those four existing entries. The owned runner config changes only test/metadata/manifest locations, makes the profile/run-info paths explicit, and confines unused synchronization output to the artifact. Tests remain at their original URL paths. The existing shared server configuration is never changed: all server ports in the owned `tests/config.json` use WPT's `auto` allocation. WPT's existing Firefox launcher chooses a free Marionette port. A tools symlink points to the existing WPT implementation; no new browser harness is substituted. Actual testharness-report/message-queue implementation files are pinned because WPT serves a generated reporting route instead of the source tree's generic report file.

The command is headless, single-process, and explicitly disables manifest update/download. `--include` selects the four original URL paths and suppresses Mach's macOS default CSS exclusion. The subprocess owns a new process group and an isolated short temporary directory. After normal completion, cancellation, or the 600-second deadline, the existing helper terminates/reaps that group; the wrapper removes only its own identity-checked temporary directory. If group cleanup fails, it preserves the temporary directory and records failure. Raw JSONL events and the unfiltered process log are retained.

`ASSESSMENT.json` records the actual test starts, every named subtest status, test ends, platform/build run_info, expected/intermittent fields, and counts derived from those events. Lifecycle and infrastructure checks are reused from the prior WPT helper. The wrapper rejects duplicate identities, absent selected files, empty subtest results, incomplete/non-OK harness endings, missing run_info, changed expected-FAIL metadata, and exit/result disagreement. It does not predeclare subtest counts or claim an exhaustive source-derived subtest inventory. Three revert-layer fallback expectations remain FAIL exactly as in the existing metadata; expected FAIL is not converted to PASS. Unexpected PASS and FAIL both fail the regression gate.

The `attr-cycle` oracle caveat from the original roster remains in force: matching its current upstream expectation is ordinary regression evidence, not proof of conformity with the newer raw-attribute short-circuit semantics. No test body or expectation is altered. This narrow run does not validate pending-demand producer behavior, accept a native fix, or add normative coverage.

Run the command template in `COMMAND.txt` from the Firefox checkout after root review, replacing `<WRAPPER_FILES_SHA256>` with the externally supplied capsule digest. Its output directory must be absent. If the epoch digest changes, stop and rebind to a reviewed epoch; do not substitute a digest simply to bypass a failed guard. Execution results belong to a separate runtime artifact; keep this prepared capsule immutable.

Preparation validation used only Python parsing, read-only preservation checks, and four synthetic raw-log parser controls. It did not execute the WPT command or start any browser.
