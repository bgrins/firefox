# Attribute context and custom-reference boundary

This isolated finite semantic model distinguishes `Attr` from `Ref`: Attr evaluates its primary in the caller's context, while Ref evaluates its primary in custom-property context and then applies the caller's taint guard. Every returned Attr value, including its fallback result, marks attr-security provenance without erasing animation provenance. These are explicit semantics supplied to the model, not proved facts about Gecko or an adjudication of the alias-through-attr spec question.

Tokens 1/2/3 stand for horizontal-tb, vertical-lr, vertical-rl. The direct nested-fallback discriminator returns token 2; resetting attr evaluation to custom context returns token 1; rejecting the whole tainted attr returns token 3. Even a cache retaining both taint bits cannot recover the lost token-2 fallback from its context-independent final result.

Four public results cover ready/deferred custom-reference equivalence; arbitrary finite custom-alias chain depth followed by nested-attr depth, with distinct direct versus outer-custom-reference decisions (not every mixed expression); impossibility of a shared final value for both contexts on the discriminator; and exact cache-reset/whole-attr-rejection counterexamples with parse-failure and fallback-context controls. The arbitrary-depth statement assumes the chosen successful parses. The parse Boolean is an external result, not a CSS parser.

The tree is finite and acyclic, dependencies are supplied as complete expressions, and inputs do not mutate during evaluation. No attribute-name/namespace cycle graph, unresolved map state, registered/default/CSS-wide rule, inheritance, URL restriction, concatenation, or scheduling is modeled. Attr-security provenance is a separate Boolean; preserving it here does not prove native security handling. The custom alias-through-attr result is conditional on the modeled metadata propagation; primary-spec policy for that bridge remains separately unresolved.
