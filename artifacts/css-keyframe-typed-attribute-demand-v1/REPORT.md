# Typed attributes and pending endpoint context

This five-path source proposal replaces the preceding blanket typed-attribute stop with on-demand preparation through the actual Stylo substitution and SCC code. It remains unapplied and uncompiled. It does not enable normal pending animation production, resolve the four existing browser failures, or add an accepted fix or canonical proof result.

`native.patch` is incremental on css-keyframe-demand-substitution-v1's candidate, plus the captured current cascade.rs. `stack-native.patch` includes that preceding demand proposal and this change against its original native preimages. Both are source artifacts. The scheduler/adapter from css-keyframe-winning-provider-completion-v1 is still separate and is not silently added to either patch.

## Attribute request and retry

At an actual typed attr evaluation, substitution checks the attribute map's expanded-name membership. If no prepared entry exists, it returns an owned request containing the name, AttributeData and URL data. An unknown namespace uses existing CSS fallback behavior. A request is not CSS invalidity: it propagates through recursive substitution and does not take fallback.

The endpoint handles the request by calling KeyframeCustomPropertiesBuilder::resolve_requested_attribute. This method obtains current target attribute text with the existing tracker/parser, seeds only the requested attribute, and invokes the existing SCC walker rooted at that attribute. It does not preseed or traverse every lexical fallback in the endpoint declaration. A failed attribute read/parse writes the existing explicit None entry; contains_attr then distinguishes completed invalidity from an unprepared attribute and prevents endless request/retry. Chained attribute reads use the same sentinel in pending mode.

The walker now returns Result and carries the supplied pending provider set. Its Custom-name entry checks that set before get_var/as_universal shortcuts, so a stale typed value or an absent map entry cannot make pending work look completed. A provider demand propagates through visit_link, reference traversal, nested attribute resolution and final substitution. The callback returns it to the owner without publishing a computed endpoint. An inner attribute request that unexpectedly survives SCC preparation remains an explicit ContextPreparation failure rather than CSS defaulting.

The pending endpoint clears the isolated attribute map before its first attempt, so previously prepared attribute entries cannot bypass current-target preparation. After successful attribute preparation, the endpoint retries its original retained tokens in the same isolated context. Completed attribute entries are retained within that attempt. Only newly reached attributes require preparation. Used and unused fallbacks follow the existing primary-first behavior: var(--ready, attr(...)) never requests the unused attribute; var(--missing, attr(...)) reaches it. The ordinary SCC path supplies no pending provider set and an empty pending-prioritary set; its existing primary classification, fallback traversal, lowlink operations and invalidation are retained. Result plumbing does touch that code, so native regression tests are still required. This is source preservation analysis, not a proof of ordinary-cascade equivalence.

## Prioritary dependencies

The fuller resolve_registered_with_pending_context entry point accepts the current set of unresolved prioritary properties separately from custom names. The existing convenience entry point delegates with an empty set; production must use the full entry point whenever the sample can contain unresolved context properties.

Before registered-value conversion, the pending route reparses the actual substituted token stream with VariableValue::parse and reuses find_non_custom_references. This is after used-fallback selection, rather than scanning all original fallbacks. Font-relative length, line-height and color-scheme requirements use the current native classifier. first_pending_prioritary follows the generated property prerequisite sets transitively and reports the first unresolved requirement. The SCC's own prioritary-application point uses the same check before calling ensure_prioritary_property. A pending font-size is consequently reported before converting a typed attribute's 2em into a registered length.

This check schedules nothing itself. The owner must complete the requested prioritary input, update the current context coherently and retry with an updated readiness set. Empty readiness sets are a caller assertion that the supplied context is ready, not evidence derived by this patch. Reparse/classification failure is an internal ContextPreparation result, never registered initial/default CSS. The proposal inherits the native dependency classifier's scope and does not prove that it captures every context-dependent numeric expression or future property type.

## Proposed actual-resolver host tests

The retained-endpoint presentation test grows from ten to 22 real FFI calls. It constructs each descriptor with data=40, then mutates or removes that attribute before resolution. Existing provider, wrong-type and invalid-order controls remain. Added cases cover unused typed fallback with a pending provider (20), taken typed fallback whose current attribute references that provider (Provider demand), direct/chained attribute demands, unused fallback inside attribute text, pending work not converted into an attr fallback, invalid referenced variables, genuinely absent attributes with and without fallback, an attribute self-cycle whose internal fallback cannot rescue it, and pending/ready font-size for a registered length (demand versus 40px). The testing FFI takes a narrow pending-font-size switch; the real method accepts a full prioritary set.

The separate v1-fallback-test-supplement.patch adds only the two originally requested cases to the sealed prior proposal: unused typed fallback resolves20; taken typed fallback reports that proposal's AttributePreparation gate. It is not part of native.patch. The new implementation instead resolves independent attributes or reports the actual provider/context dependency. None of these host test expectations has been executed.

## Ownership, remaining work and cost

The native endpoint still consumes an isolated computed context; demands discard its partial map with that attempt. The current ready custom-provider map and prioritary readiness set are caller obligations; attribute entries are cleared by this entry point itself. AttributeTracker and cacheability/watch effects can be updated before a later demand. The caller must supply a fresh tracker and discard/buffer all incomplete effects, as required by the preceding completion owner. No style publication is added. Pending providers must come from actual winning cascade admission; this proposal does not substitute a preselected winner table for that integration.

Ordinary SCC fallback short-circuiting already exists in Stylo and is preserved here. The versioned trace distinguishes current Editor's Draft behavior from the 2022 published graph rule. This proposal does not define the animation owner's cycle policy or prove that endpoint/SCC/whole-property contexts compose correctly. Cross-owner cycles, complete authored endpoint scope, implicit-base freshness, declaration priority/revert gates, successful-effect merging and memory reporting remain open. The generic scheduler currently lacks native prioritary-node completion; callers must extend it before production activation.

Retries can rescan the endpoint and nested attribute graph. The extra substituted-token parse only runs for registered values when the pending-prioritary set is nonempty; the ordinary path skips it. No performance claim or memory bound is made. Source-level API review checked IdSet copy/insertion/iteration and the generated dependency return type using actual fetched upstream files; those snapshots are supporting API evidence, not a build of the current native crate.
