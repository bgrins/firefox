# Registered initial-value ordering risk

The sealed selected-color draft must not be tried unchanged. Its `Invalid` preparation state drops the ColorScheme edge, but the unchanged invalid-value handler can compute a registration’s initial value using the current element context. This is a concrete source-level scheduling gap, not an observed native regression.

The exact admitted `PropertyRegistration::validate_initial_value` rejects missing required initial values, substitution references, and CSS-wide keywords. It then calls the registered-value parser with `AllowComputationallyDependent::No`. That parser translates the argument into a parsing-mode flag and delegates a `<color>` clause to `Color::parse`. The admitted color parser explicitly accepts SystemColor and recursively parses `light-dark()` without testing that flag. Thus `light-dark(red, blue)` and `CanvasText` are reachable color initial values in these bodies; the mode name alone does not establish rejection. The `@property` registration caller in the same admitted rule file invokes this validator. The separately retained historical script-registration caller does likewise; its full current-body applicability is not newly asserted here. A real test must require successful registration rather than silently treating rejection as evidence about defaults.

For a registered property with `inherits:false`, `handle_invalid_at_computed_value_time` calls `compute_value` on `registration.initial_value`, then inserts that newly computed result. `light-dark()` selects its branch from `context.builder.color_scheme`; system-color computation also receives the context. This differs from CSS-wide `inherit`, which copies the parent’s computed wrapper, and CSS-wide initial selection, which uses the stylist’s computed initial map. The draft’s statement that these are all already-computed selections is too broad. Its sealed bytes remain unchanged; this finding is a separate correction.

In the previous scheduler, possible COLOR adds the ColorScheme dependency before calling the invalid handler. In draft V1, an invalid selected substitution produces `PreparedCustomKind::Invalid`, whose dependency predicate returns false. After the resulting SCC closes, applying that state calls the same handler. Consequently, a contextual initial value can be computed without the ordering previously supplied by the color edge. The same retained-AST argument that works for a successful selected value does not cover this default path.

A minimal preservation discriminator should register `--c` as `<color>`, non-inheriting, with initial value `light-dark(red, blue)`. Use a light parent and a subject with explicit `color-scheme: light`, `--c: var(--missing-a)`, and literal `color: light-dark(red, blue)`. Capture `--c` before the scheme/literal getters. Change the subject to `color-scheme: dark` and `--c: var(--missing-b)`, with both referenced names absent. Again capture `--c` first, then the computed scheme and literal color. Changing the missing name forces a new authored declaration without changing the invalid substitution route. A separate valid `--c: light-dark(red, blue)` control checks ordinary selected-color computation; a `CanvasText` variant can compare to a literal system-color property without hard-coding platform RGB values. Require registration success and supported literal syntax before interpreting any result. This is a preservation test proposal, not a browser observation or a new normative ruling on initial-value timing.

Relative lengths inside selected images are a separate validation boundary. The frozen reference walker accumulates unit flags before preparation, and those edges are traversed before the retained AST is converted. Direct gradient `em`/`lh` stops and selected typed attributes therefore have an ordering path; no early-computation counterexample was found there in this read. However, the inventory includes unused or type-rejected fallback units, and `light-dark()` computes only its chosen image branch while unit inventory covers both. Exact non-color dependency selection remains unproved and must not be inferred from the selected ColorScheme classifier. These limits do not excuse the reachable invalid-default path above.
