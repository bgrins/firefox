# C rule provenance with lower common-case storage

A feasible alternative to C's per-declaration block pointer is **cold block-membership exclusion**: retain source blocks only for Rule rollbacks that actually occur. This preserves the old C block/normalized-priority equivalence relation without growing every buffered Declaration. It trades memory on ordinary cascades for work on cascades using revert-rule; no performance-neutrality or native compilation claim follows. A+B+D rebasing remains separate.

## What the reviewed source actually does

The old `fix-c-after-a-b-d-v1.patch` carries a `PropertyDeclarationBlock` reference through DeclarationIterator and the generic apply_declarations input, stores its pointer in every buffered longhand, and remembers exclusions keyed by physical longhand, unimportant priority and block pointer. Both prioritary and ordinary longhand paths pass that source to apply_one_longhand. Custom-property cascading is unchanged by C. Important and normal occurrences of one block can be separated in the rule chain, so a monotonically increasing occurrence number or “last block” pointer is insufficient.

The recorded actual Gecko24→32-byte Declaration measurement belongs to historical integration sources, not signed e86. e86 explicitly asserts CascadePriority is the size of u32; DeclarationIndex is u32, and Declaration consists of one reference plus those two fields. On the recorded64-bit target ordinary natural layout therefore suggests16→24 bytes after a new block pointer, but that is a source-derived estimate, **not a fresh Gecko layout measurement**. The proposed pointer still plausibly adds8 bytes per slot/512 for64 inline slots; do not recycle the historical absolute sizes as current evidence. A u32 block ID is not a free padding solution here: the present fields already fill16 bytes on that layout, and another u32 would require padding/alignment and an identity table. Narrowing the existing next_index would also undo the accepted declaration-capacity boundary.

## Preferred bounded alternative

Keep Declaration's representation unchanged. Give the cascade a borrowed source view: the existing rule node plus guards for normal rule-tree cascading, or the actual single block for Stylist::compute_for_declarations. That second caller deliberately bypasses the rule tree; searching only its root node would lose provenance. A small enum/callback is a design choice, not an implemented API here.

When substitution produces an actual Rule rollback, retain the **original buffered declaration reference**, before apply_one_longhand shadows it with a substituted Cow. Find the containing immutable block by scanning the applicable style sources and comparing references with std::ptr::eq against `block.declarations()`. DeclarationIterator already reads those blocks under the appropriate origin guard; the public declarations() API exposes a borrowed slice, so this needs no pointer arithmetic, unsafe dereference, new style computation or substitution. A missing source must fail an internal invariant, not silently mean a different rule. Borrowed blocks must remain protected/alive for the cascade, as in C's existing pointer-lifetime premise.

Store the resulting block reference and normalized priority only in that physical property's Rule exclusions. Before evaluating a later candidate for that property, compare its normalized priority, then check whether the **original** declaration reference belongs to any excluded block's slice. This is equivalent to C's key test under its existing source-allocation grouping assumption: declarations in the same block compare equal by membership; declarations in different blocks do not, even when their textual values or priority agree. The existing declaration reference is sufficient to query membership; no extra per-entry source field is needed. The first Rule trigger incurs a source scan; later checks may scan each relevant excluded block. A lazy declaration-address→block cache may be added only if actual cold-path cost warrants it, but is not needed to make the design feasible.

Without Rule rollback there is no source scan or populated exclusion allocation; the buffer retains its old size. There is still constant per-cascade source-view/exclusion-container overhead and a branch at the existing rollback guard. With many Rule rollbacks or long blocks, time can be worse than the old pointer/hash lookup. This design does not establish a net speedup, and it must not eagerly pre-scan the stylesheet on every cascade to claim a memory win.

## Consumer and identity constraints

- Keep the shared apply_one_longhand exclusion guard after seen/flags and accumulated A+B+D cutoffs, but before substitution. Both linked prioritary-property traversal and sequential ordinary traversal use it. Do not infer contiguous visitation from the buffer: prioritary indices jump between rule blocks.
- For ordinary logical declarations, keep mapping to the physical longhand using the computed writing mode before the exclusion key. Preserve the existing writing-mode dependency observation even for later-blocked declarations; physically deleting declarations before that bookkeeping is not equivalent.
- Normalize importance exactly as C currently does; retain origin/layer/flags and block identity. Cross-important/normal same-block aliases must remain excluded; separate-rule declarations at equal cascade priority must remain eligible. A raw rule-node address fails this because importance may produce separate nodes for one block.
- Do not key on the substituted declaration, UnparsedValue allocation, textual equality, or shorthand-cache output. They can be temporary or shared across distinct original declarations. The original buffered reference remains the source witness through var/attr or shorthand substitution.
- Preserve cascade_custom_property's A+B+D cutoff accumulation and Rule no-op behavior. C did not add a custom block map: PropertyDeclarationBlock documents deduplicated property IDs, and custom properties have no logical/physical alias pair. This design must not reset custom cutoffs or assume the streamed custom consumer shares the buffered longhand representation. Keyframe custom-property preparation remains outside a new claim of universal rollback semantics.
- Preserve the generic direct-block caller, visited cascades and pseudo restrictions. Capture/replay of source membership is structural only; it must not rerun value evaluation, alter included flags or change order of dependency observations.

This alternative preserves the **existing C quotient**, not a proof that allocation identity always equals normative rule identity. Shared declaration blocks across distinct semantic rule occurrences, animation-origin rollback and the retained cycle-policy issues remain the same review obligations. A unique sequential run token is not a substitute for proving that quotient across split importance and contexts.

A secondary alternative is a side vector of `(first-buffer-index, block)` runs, with binary lookup for prioritary jumps and a cursor for ordinary traversal. It also leaves Declaration unchanged, but allocates metadata for all participating blocks even without revert-rule and can exceed per-declaration overhead when rules contain one declaration. Without a lazy admission mechanism it is less attractive for the requested common case. Avoid shrinking the inline declaration capacity merely to offset C's extra pointer: that changes spill behavior rather than removing provenance cost.
