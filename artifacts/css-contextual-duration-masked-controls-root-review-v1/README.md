# Disabled root verifier for the one-source masked controls trial

This narrowly adapts the executed base-timing root verifier. The candidate changes only matching.rs; original compositor/manager bodies remain protected context pins. The exact two pages contain seven callbacks, with no private records or calibration receiver. Original raw replay, candidate raw replay and exact OUTCOMES paired rows/endings remain required.

This owner defines success as build, complete observation and restoration. An ordinary callback FAIL produces browser exit1 but can correctly produce owner exit0, lifecycle success and owner backup removal. Comparison PASS is independent of all callbacks passing: preserved original failures can compare equal, and repaired original failures can differ from the original strict signatures. The verifier retains the raw assessor's verdict/errors and all seven statuses; it never derives comparison success from a PASS count. ROOT-TERMINAL includes owner exit, browser exit, all_callbacks_passed and the explicit success scope. No native acceptance is inferred.

Only complete ordinary PASS/FAIL observations with successful lifecycle/restoration are supported. Infrastructure/build/partial-stream/restoration failures stop before any root publication or epoch update and require a separately reviewed recovery. The executed owner removes its own verified backup on lifecycle success even when callbacks fail; this verifier requires that removal, exact original backup size accounting and absence of the backup path. It does not delete a retained backup. Reusing the old comparison-failure deletion branch would incorrectly equate a failed comparison with failed lifecycle, so that branch is intentionally absent.

The source/app/extra/index/group-absence checks and full restored-state reconstruction before backup handling are unchanged from the executed predecessor. Both PHASES snapshots must additionally equal the compiled snapshot. Compiled source/binary hashes, copied fixture/manifest bytes, all accepted claims and current original context sources are checked. Raw-index reconciliation alone uses the exact existing owned-claim/write/verify/rollback tail; OWNED and ROLE must remain byte-identical. Saved failed test statuses are not rewritten. ROOT-REPLAY records OUTCOMES hash instead of a nonexistent record-comparison receipt.

Execution is disabled. Root may bind the actual activated owner manifest, then review and enable only after its actual terminal; no terminal/result is assumed. Required root arguments remain --session, --terminal, --exit and --result-sha256. Source/app/native/Git/canonical operations occur only if root runs the enabled verifier. Saved check.py imports definitions and exercises synthetic outcomes only; it does not execute main or touch live runtime. Sixteen combinations distinguish comparison result from callback counts, paired-row mutations reject altered observations, and byte comparisons protect the original restoration prefix and raw-only publication tail.
