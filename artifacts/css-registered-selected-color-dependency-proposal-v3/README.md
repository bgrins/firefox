# Selected-color dependency proposal V3: repository formatting

This successor changes only the formatting of the three native postimages in sealed V2 (`1f17d8d750a71a14c8401196e3201e44de76f1146bc2df286bbe38c59d440481`). V2 remains unchanged. `FORMAT-DELTA.patch` is the complete V2-to-V3 difference; `native.patch` applies the formatted candidate to the same three original preimages. No live source, build, browser, index, controls or application was touched.

The exact Servo configuration is copied as `rustfmt.toml`: edition 2024, trailing commas on match blocks, and reordered imports. The repository lint declares a minimum rustfmt version of 1.4.12, rather than an exact toolchain version. With no RUSTFMT override or mozbuild formatter present, `rustup which rustfmt` selected installed stable rustfmt 1.8.0 (rustc 1.92.0). That binary and the previously used installed 1.97.1 toolchain's rustfmt 1.9.0 are pinned by hash in `TOOLCHAIN.json`; both produced byte-identical postimages with no warnings. No toolchain was installed or changed.

The complete formatting delta wraps expressions and arguments, expands two match-arm expressions into equivalent blocks, adds trailing commas, removes one blank line, and moves the existing `crate::{FxHashMap, Namespace}` import according to repository ordering. It adds no behavior or changes to dependency selection, post-edge cycle handling, invalid/default computation, parsing, taint or publication. This is a reviewed formatting claim, not a formal Rust semantic-equivalence proof.

`format_check.py` authenticates V2 and input pins, reconstructs each formatted postimage with both binaries in removed scratch, checks idempotence, and reproduces the exact delta. `check.py` reuses V2's sixteen classifier tests and four rejected mutants unchanged, now checking actual repository formatting; it also replays and reverses the complete native patch in removed scratch. Those isolated tests use substituted AST types. They do not compile Stylo, run its parser or SCC/default application, or establish browser correctness.

All V2 semantic limitations and validation requirements remain. The intended native comparison uses the unchanged five-case bug fixture, 23 preservation cases and 14 cycle/default cases (42 callbacks across three pages). No WPT was rerun for this formatting-only successor. The original run remains root-owned. Native compilation and before/after results are still required.

The added pure-image admission remains a possible separate bugfix boundary: if original/candidate evidence establishes a distinct pure-image repair, separate that production change and its WPT from the color-union fix. Recursive image classification can still be required for mixed image/color registrations. Formatting does not settle that split.
