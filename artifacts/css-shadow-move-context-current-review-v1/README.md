# Shadow move-context current review

The sealed three-file proposal still matches the current source at 2fe2ced22a525a4348286bddaa7dcb0168d72905. All three bases and five context-source pins were joined to immutable Git bodies. No native files, index, epoch, builds or browsers were changed. The proposal is suitable for controlled paired validation, not yet acceptance.

Only IsMove crosses the shadow boundary. ShadowRoot retains its fresh BindContext (SubtreeRootChanges false, InUncomposedDoc false) and its own UnbindContext root, original-parent, document and batch facts. Consequently shadow children do not become unbind roots. Nested hosts propagate the bit recursively. Constructor attachment, cycle unlink and Unattach retain the default false. Connectivity, directionality, parent-chain notifications and binding work still run; this is not a request to skip all restyling. Existing animation collections are retained on move, while ordinary removal still clears them.

The current [DOM move algorithm](https://dom.spec.whatwg.org/#concept-node-move), step 25, traverses shadow-including descendants and distinguishes the moved root from descendants. [HTML callback enqueueing](https://html.spec.whatwg.org/multipage/custom-elements.html#enqueue-a-custom-element-callback-reaction), step 3, falls back to disconnect/connect only without a connectedMoveCallback. The [CSS animation model](https://drafts.csswg.org/css-animations-1/#animations) supports retained playback for matching animations; it does not promise unchanged computed style when inheritance or applicable rules change. This is a manual primary-source trace, not formal/native equivalence or exhaustive history review.

The sealed 12 animation cases keep their declaring tree and keyframes stable and calibrate paused time 375 ms, nonpending state and 3.75px before sampling. Root/light and no-move cases are useful positive controls. Five reaction cases test nested/self/cross-parent move delivery. All phases precede outcome assertions. The existing seven-case custom-element-move-reactions page supplies six strict fallback/order controls and the already-known single-shadow failure as an improvement target. The historical system-browser failures are one context-loss family, not seven new bugs.

Remaining focused validation obligations: ordinary shadow-host removal/reinsertion must still disconnect/reconnect and cancel old CSS animations; a shadow custom element without a move callback must retain HTML fallback; moving a host between differing inherited font/color contexts must update descendant computed styles without replacing an otherwise matching animation. The current 17 cases do not prove these obligations. Existing connected-callbacks and disconnected-callbacks pages cover ordinary shadow insertion/removal, but each expands to 40 callbacks across eight document kinds. Their helper also fetches resources/empty-html-document.html. A small separately reviewed control page may be more proportionate than importing 80 callbacks. The earlier 70 controls remain useful but their inherited-style animation case concerns a moved root, not an internal shadow descendant.

No concrete API/context-root defect was found in this review. Debug assertions, frame lifecycle, privileged widgets, and arbitrary CSS dependency invalidation remain outside the evidence until actual candidate execution. No new formal coverage or accepted-fix count is assigned.
