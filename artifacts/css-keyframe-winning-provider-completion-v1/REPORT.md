# Owned acyclic winning-provider completion

This package implements and tests a demand-driven completion engine, plus an uncompiled adapter using the native style types and existing operation arena. It advances the pending-provider path beyond an API sketch, but does not enable pending production, modify the real cascade, or fix the four browser failures yet. `native.patch` adds two private Gecko modules and their declarations; no existing composition or completion behavior changes.

## Implemented ownership and completion

`WinningProviders<Context, Name, Value, Recipe>` owns one sample context, the already-computed provider map, and the actually admitted winners. Names use generic Eq/Hash identity; the native alias uses Stylo `Name`, not strings or numeric stand-ins. Pending recipes and values are moved into the owner. Duplicate admission returns the rejected owned input without overwriting the previous winner.

Provider lookup checks admitted winners before the initial map. A pending winner masks an old value even when its name is present and typed in that map. `ready_values()` excludes all such shadowed entries; `pending_names()` lets the native context builder explicitly retain the unresolved set. Missing, pending and ready are distinct states. The native value is `Option<ComputedValue>`, so an admitted guaranteed-invalid `Ready(None)` is also distinct from a missing winner and an unresolved request.

An evaluator can complete a property, request another pending provider, or return an error. The work stack resolves requested providers before retrying their consumer. An acyclic chain of any finite length therefore does not rely on another whole-style traversal. Already-completed providers are reused within this sample. A request for a ready/missing provider is a protocol error, preventing a non-progressing retry. An active-stack edge returns the concrete cycle path; it does not choose a CSS invalidation owner or numeric default.

Endpoint effects are buffered privately with the completed values. Only resolution of every admitted winner constructs `CompleteProviders`, whose consuming `into_parts` yields the context, full provider map and effects. Error and cycle returns own an `IncompleteProviders` with no publication method. It retains partial work/effects until discarded. There is no resume-across-samples API that could accidentally reuse old resolved values after registration or context changes.

The two compiler-negative controls establish the actual Rust API boundary: incomplete work has no `into_parts`, and callers cannot forge `CompleteProviders` through private fields. This is not a proof against an evaluator that publishes side effects itself. Native evaluation must use isolated, discardable endpoint contexts; the sample context must remain coherent despite interior mutability being possible in Rust. Those are explicit caller obligations, not hidden theorem premises.

## Actual native adapter

`native_provider_completion.rs` uses `SampledAnimationProperty<servo_arc::Arc<KeyframeEndpoint>>`, `Name`, `AnimationValue` and `Option<ComputedValue>`. It does not reimplement Add, Accumulate, interpolation, selection or native error fallbacks. Once its endpoint inputs complete, it calls the existing real `SampledAnimationProperty::resolve` and checks that the resulting custom property's name matches the admitted key. It takes the computed value directly from `CustomAnimatedValue`, retaining the native value/taint/URL ownership rather than serializing or uncomputing it into a substitute declaration.

The caller supplies an ordered complete computation scope separately from the selected arithmetic root. Each descriptor is retained by Arc. Within one attempt, identical descriptor allocation identities share a computed result; equal numbers or equal provider names do not establish identity. Raw addresses are only local hash keys while those Arcs remain alive, never dereferenced or treated as global identities. The native endpoint callback must be idempotent for that descriptor within the coherent attempt and must return unpublished dependency effects. If an arithmetic root references an endpoint absent from the supplied scope, the adapter returns `MissingComputation`; it never falls back to its cached value. Unselected computation inputs are evaluated before composition. A demand/error drops that attempt's local value/effect buffers.

This adapter is source-level code only. Its native imports and field access were checked against `API-SOURCE-PINS.json`, including crate-visible `CustomAnimatedValue.name/value` and the owned operation-root API. It has not been typechecked inside style or linked. The isolated tests compile the exact scheduler core, not this adapter.

## Where the real cascade still has to connect

The admission API does not pretend to implement CSS priority. The real `Cascade::cascade_custom_property` must remain the authority: reverted-priority permission, included flags, then vacant seen entry; pending admission must happen before concrete value-equality elimination. A pending-only source item must first survive the actual rule iterator and those gates. Existing ordinary revert handling must still remove the seen entry/update revert state. A synthetic Boolean gate or a test inserting only the desired winner is not evidence for this native integration.

The completing callback is also not implemented here. It must obtain current registration and target context, prepare typed attributes, and request pending dependencies before ordinary substitution can treat an absent/typed map entry as finished. It must return real invalid-at-computed-value defaulting as a native result, while internal unsupported work remains an error. Current `KeyframeEndpoint::resolve_registered` assumes a complete provider snapshot and cannot itself issue these demands. Invoking it blindly on `ready_values()` with unresolved dependencies omitted would incorrectly convert pending work into missing/initial values and is forbidden.

The public cascade still returns `Arc<ComputedValues>`. It cannot unwrap, ignore, panic on, or default an incomplete result. Normal pending producer activation must wait until the real iterator, collection, resolver and final publication are connected. Cycles remain explicitly unresolved; this package is not permission to ship an error result for cyclic CSS. Complete keyframe computation scope, prioritary/font/color dependencies, watch/cacheability merging, ordinary versus animated SCC ownership, and implicit-base semantics remain necessary integration work.

## What the tests establish

Actual isolated replay 29359 exited 0 at 9d3585 using rustc 1.92.0, single-thread execution and disposable outputs. Thirteen tests exercise pending-over-stale lookup, safe ready-map enumeration, a reverse-insertion-order acyclic chain, shared-provider completion, dynamic mock histories, missing/invalid/wrong-type distinction, used/unused fallback requests, exact cycle paths, duplicate admission, evaluator error refusal, invalid-demand refusal, buffered-effects disposal, and borrowed-context ownership. Two additional compilations reject incomplete publication and forged completion with their intended E0599/E0451 diagnostics. Exact scratch patch apply/reverse passed; scratch was removed. The earlier 12-test replay is retained separately as historical evidence.

The endpoint callback in these tests is deliberately mocked. It uses a small typed token enum to exercise the scheduler protocol and the externally supplied 20→wrong-type→20 expectations. It does not parse CSS, call the native endpoint resolver, establish CSS defaulting, test actual cascade winner gates, or repair a browser result. The existing ten-case browser fixture remains the future vertical gate, including both creation orders and consumer-first reads. No native/browser/canonical/index/ledger modification occurred.

## Cost and remaining gates

The scheduler allocates winner/base maps, insertion order, active stack and buffered effects. With a coherent evaluator that asks only for a genuinely pending dependency, each successful demand completes another node or reports a cycle; it does not repeatedly traverse the whole style tree. Re-evaluation may rescan an endpoint's earlier dependencies, so total evaluator work can be quadratic in a long expression's dependency count. The native adapter retains the existing per-root arena allocation/scanning cost, potentially O(properties × arena nodes), and does not yet share generic recipe-resolution caches across roots. Whole-arena retention, descriptor scopes and memory-reporting roots remain open. No performance or landability claim is made.

Next concrete work is the demand-capable native endpoint context/resolver and the actual iterator/admission handoff. Host tests must then use real rule nodes, losing important/revert winners, real descriptors, actual endpoint defaulting, and native composition. A successful scheduler mock is not a substitute for those tests or the four browser repairs.
