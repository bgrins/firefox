# Masked duration: animation API before opacity

This unexecuted standalone WPT corroborates the existing opacity-first test through a different entry point. It does not replace or modify the sealed seven-callback suite, the original first-opacity fixture, or the V81 checkpoint.

Immediately after setting the authored font to 32 px, the first observation is `target.getAnimations()`. Only then does the test query the **retained** opacity effect with `getTiming()` and `getComputedTiming()`, followed by computed opacity. The recorded expectations are duration 2000 ms, local time 750 ms, progress .375 and opacity .375, with two current animations, retained animation/effect identities, unchanged currentTime and paused state.

The API choice is deliberate. [CSS Animations 2 pending-style requirements](https://drafts.csswg.org/css-animations-2/#requirements-on-pending-style-changes) expressly covers Web Animations operations returning CSS-animation objects or state, and its example specifically uses `getAnimations()`. The normative requirement is the preceding prose; the example is illustrative. The test does not assume that `getTiming()` alone initiates style processing, and its result cannot distinguish which later API internally triggered an update if the first API did not. It tests the combined observable API-first sequence. A separately instrumented or narrower experiment would be required to assign internal causality to `getAnimations()`.

As in the opacity-first predecessor, the base font starts at 16 px under a constant 32 px font animation. Both effects are acquired and paused at 750 ms; three setup frames and the masked 32 px font are checked. There is **no initial opacity or contextual-duration numeric oracle**. After the authored change, both candidate timing-input policies have the same 32 px basis, giving `calc(1em / 16px * 1s) = 2s`. No script duration override or effect replacement applies. The initial unequal-input policy remains unresolved.

All final timing and opacity values are captured before assertions. Timing queries precede opacity, so a later opacity style flush cannot retroactively alter the captured numeric timing fields. Later identity checks verify the same retained effects. Values are sequential observations, not an atomic snapshot.
