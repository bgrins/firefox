# Font sampling diagnostic proposal

The conformance baseline's animated-font callback stopped at getComputedStyle.fontSize (10px instead of 15px), before the getter assertion. Preserve that complete evidence. This separate proposal does not change the expected font or attribute the discrepancy to nearby font bugs.

Three promise-test callbacks compare original CSS font+margin, CSS font-only, and matching WAAPI font+margin. Each emits five KFONT-V1 records: synchronous seek, ready settled, actual 25%-then-50% reseek, unrelated color style invalidation, and two animation frames. Records include first font/current-style read, timing/play/pending state, full getKeyframes output, subsequent style/state, and whether the explicit ready observer ran. Require fifteen unique ID/phase records; all values remain observations.

CSS setup preserves the failing branch: append target with font-size 16px, assign 100s linear paused both, getAnimations, seek 50000, then read fontSize. There is deliberately no initial getComputedStyle preflush and no ready getter before that first record. The dump availability assertion and callback type do not flush style. The first read happens synchronously before the first await. The ready flag means its observer ran, not proof that an unobserved promise was unresolved.

Read order matters: first fontSize is saved before margin/color and timing reads, then getKeyframes runs, then styles/state are read again. These are sequential observations; getters can flush, so before/after differences identify an observation boundary, not an atomic native transition. If sync font is 10px but later reads are 15px, isolate the specific getter next. If only ready repairs it, examine pending readiness; if reseek, timing restyle publication; if explicit invalidation, style invalidation. Font-only versus dependent-margin and WAAPI controls narrow the path without establishing a bug from differences alone.

No native/provider patch, conformance oracle edit, metadata, browser/build/Git action occurs here. Syntax and inert registration checks pass. Root should review before execution. All three callback results should PASS plus one OK harness, while font/margin/timing/frame values have no guessed assertions. A future wrapper must require complete raw records and retain restoration evidence. Independently, root can replace the animated-font prerequisite in a new main conformance version with an explicit changed font-size context; this diagnostic remains separate and v1 stays immutable.
