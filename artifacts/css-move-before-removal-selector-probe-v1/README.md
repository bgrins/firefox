# Old-parent removal selector diagnostic

Eighteen observation callbacks compare appendChild with moveBefore across first-child, last-child, only-child, nth-child(2), adjacent and general sibling selectors, parent :has and :empty, and sibling-index when moving the first child. This is not a native repair or acceptance suite by itself.

Each callback moves the selected existing node to a different parent and restores its exact original position. Ordinary restoration uses insertBefore; state-preserving restoration uses moveBefore. The source's stationary target is observed, or the source parent itself for :has/:empty. The moving-first index case changes stationary index 2→1→2, unlike the earlier moved-last index control.

A visible iframe, explicit body, precreated literal widths, exact child-id topology, retained node identity/connectivity, and stable repeated reads calibrate the setup. All three phases are captured before assertions; every phase's topology, literal computation/geometry and selector truth is checked before actual width/geometry equality. Selector matches() is measured after computed style and geometry reads, following independent review f53bc9. No phase changes declarations. Full three-snapshot JSON accompanies failures; passing callbacks do not export a separate record corpus. Unsupported API or selector syntax fails explicitly.
