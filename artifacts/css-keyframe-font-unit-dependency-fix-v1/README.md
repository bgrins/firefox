## Change

Only data.rs and traversal.rs change. Normal traversal queries the existing element.has_animations only when RESTYLE_IF_AFFECTED_BY_WM_OR_ANCESTOR_FONT is present. The existing needs_to_recascade_self predicate accepts that hint when either the ordinary style's relative-unit bit is set or the element has relevant animations. The normal restyle then uses the existing animation processing and EFFECT_PROPERTIES task; it does not invent new effect values or mutate shared ComputedValues.

The new animation condition is false for animation-only traversal. Its previous ordinary-style checks are unchanged. Exact e86 RestyleHint::propagate removes only animation hints and the two animation recascade hints during that traversal; it does not consume the ancestor-font/WM hint. Normal propagation carries that ancestor hint through descendants. The new query therefore neither claims that animation-only cascading regenerates effect properties nor removes the normal work it requires. The coalesced seek/root-mutation WPT is an observable check of this ordering boundary; full native scheduling still needs execution.

This intentionally over-approximates the dependency set. A literal-only animation is also recomputed after an ancestor-font/WM hint. The additional membership query is short-circuited for all other hints and for animation-only passes. There is no new per-frame query solely because time advances, persistent bit, effect flag, cache key or invalidation watcher. Performance under frequent ancestor font/WM changes is an explicit review cost; no speed claim is made. Exact per-effect dependency transport could optimize this later, but is not necessary to preserve the required recomputation.

## Membership and lifecycle correspondence

The saved e86 Gecko TElement implementation calls has_any_animation, which checks the existing node fast flag and Gecko_ElementHasAnimations. The latter maps element/pseudo identity through AnimationUtils::GetElementPseudoPair and checks the corresponding EffectSet. The fast flag's pseudo path consults the parent for pseudo-elements whose animation state is stored there.

KeyframeEffect::UpdateTargetRegistration registers an effect when its Animation is relevant. Its assertion relates that cached relevance to IsCurrent or IsInEffect and a non-removed animation. Paused effects within their active interval and effects applying through fill are not filtered by running playback. UnregisterTarget removes the effect and destroys an empty set. Retargeting uses the existing registration transition; the candidate caches no membership result between traversals. Detached/dormant or removed effects are not promised unnecessary recomputation; when they become relevant again the existing target/property setup computes their values. This report does not replace validation of that native lifecycle with the extracted membership double.

Normal matching.rs::process_animations schedules EFFECT_PROPERTIES for has_animations, independently of whether the animation came from WAAPI or generated CSS keyframes. EffectCompositor::UpdateEffectProperties forwards to each KeyframeEffect. UpdateProperties rebuilds before comparing values, so equal-valued keyframe replacement does not authorize stale dependency assumptions. The source candidate preserves all these routines byte-for-byte. Searchfox discovery found the traversal call as the sole restyle_kind call site; actual native compilation remains required to validate the full checkout/API integration.
