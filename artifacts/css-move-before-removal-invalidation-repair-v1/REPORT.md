`PresShell::ContentWillBeRemoved` takes an early return for an element moving to a styled, non-display-none element parent. It calls `DestroyFramesForAndRestyle` and bypasses `RestyleManager::ContentWillBeRemoved`. The latter is responsible for source-container removal invalidation, including relative selectors, empty/edge/nth handling and tree-counting recascades. Destination insertion still notifies its container. When source and destination coincide, destination invalidation can cover stationary siblings too; same-parent PASS therefore does not clear the missing old-container path.

Blindly invoking ordinary removal is unsafe: `DestroyFramesForAndRestyle` intentionally retains root Servo data so its pending reframe can be observed, while clearing descendants and posting subtree restyle. Ordinary `ContentWillBeRemoved` clears the root as well. The proposed three-source patch adds a default-false `aPreserveRootStyle` parameter and uses the existing `IncludeRoot::No` clearing mode only for that new call. PresShell invokes it after existing frame teardown, before the early return. All existing container invalidation then runs; this is not a tree-count-only workaround. Ordinary callers keep the default and the original root-clearing behavior. The existing ordinary-removal comment is retained with one move-specific exception sentence.

The API uses a named boolean because the existing IncludeRoot enum is declared later in the header; no unrelated declaration relocation is needed. Descendant clearing may repeat the prior helper's clearing, while the moved root and its restyle/reframe bits remain. Undisplayed-cache generation invalidation stays conservative. This is a source-level proposal requiring native compilation and behavior validation, not proof that all move-state contracts are preserved.
