# Minimal complete boundary to investigate

Use one canonical, unscaled representation for registered computed lengths. The smallest coherent boundary appears to be the outer `Value<Component>` computation itself, not just `SpecifiedValue::compute`: replace its generated `ToComputedValue` conversion with an explicit implementation that performs the existing inner conversion and then normalizes the completed typed value using the computation's actual effective zoom. Retain inner `ValueInner`/component/list conversions, so nested lengths are normalized once at the outer boundary. This would cover ordinary direct values, substituted/deferred values, retained admitted ASTs and parsed animation declarations that call `to_computed_value` directly. Actual call-site and trait-bound coverage must be checked before implementing; the proposal is not a proven exhaustive producer audit.

The required pure operation maps all computed typed length leaves. Scalar CSSPixelLength supports the arithmetic; LengthPercentage has an existing private map_lengths that preserves percentages, calc structure and clamping mode. Add a narrow pure method using it. Registered components must recurse over multiplier lists, transforms (Translate/Perspective and nested interpolation/accumulation lists), and images (gradient stops/radii/positions and nested images). Copy colors, URLs, resolutions, numbers, angles, metadata and taint unchanged. Matrix/Matrix3D Number fields need a separate convention audit, not blanket numeric scaling. A scalar-only workaround would leave incompatible representations inside one registered value type.

Copy already canonical initial/inherited/CSS-wide values unchanged. Initial values that are recomputed go through the same outer local computation boundary. Preserve from_computed_value and to_declaration_value round trips: canonical computed lengths become canonical specified px and are normalized exactly once after their next computation. Animation on stored canonical components should remain in that representation; explicit animated conversion paths need checking because CSSPixelLength::to_animated_value currently unzooms ordinary lengths. The source's CustomAnimatedValue from_declaration/from_computed paths are the next concrete audit targets.

Once every producer is canonical, custom-property CSSOM must stop removing final style zoom from those length leaves. Keep legitimate color/other resolved conversion. A scoped resolved-context/custom-property length handling at CSSPixelLength can preserve the existing recursive resolver without using that resolver as the storage normalizer; Au delegates to CSSPixelLength and LengthPercentage maps through it. Verify that all custom CSSOM callers carry the correct custom-property identity, and that no ordinary property uses this bypass. `Value::to_variable_value` can then serialize canonical storage directly, and an ordinary consumer applies its own zoom once.

Do not merely ensure Zoom earlier, divide by final Zoom, mutate builder.effective_zoom to one, or globally skip resolution. The first leaves doubled var consumption, the second can remove a different scale from computation, the third leaves differently scaled font/line-height/reference inputs, and the fourth can change color semantics. The existing Lean model proves only the contract conditional on correct input/context factoring and inverse scaling. It does not prove these proposed Rust boundaries, floats, or all relative units.

Before activation, validate literal/provider/defaulting, zoom mutation, cross-zoom inheritance and recascade, initial cache, animation, multiplier lists, mixed length-percentage, nested transforms/images, relative lengths, and color/tainted-URL preservation. All A/B and sign evidence must remain intact, and the narrow zoom tuples must pass on both direct and deferred paths. No source changes are included in this report.
