# Retained custom-value path audit

No new observable mismatch was established in this bounded audit of sealed V4. Six extracted base/candidate blocks are byte-identical after trimming outer whitespace: registered compute/parse, first-success parsing, the registered computation-context wrapper, substitution-to-value, invalid handling and the extracted application suffix. `EQUIVALENCE.json` records exact delimiters and hashes. This is source equivalence for those operations, not proof that graph scheduling always supplies the same computed context.

The original typed path is `substitute_internal → into_value → compute_value → SpecifiedValue::compute → parse → to_computed_value`, followed by OR-ing substitution attr taint. The prepared path performs the same substitution and parse earlier, retains that AST, then invokes the same computation method and taint OR. Its arguments match: selected CSS, original URL data, no namespace map, AllowComputationallyDependent::Yes, whole-value AttrTaint when needed, and the actual custom property ID. The owned substitution also preserves first/last token types. The typed output already regenerated serialization through its specified/computed representation in the original path; retaining that AST does not newly discard a token representation.

The unchanged component parser tries syntax alternatives in order and stops at the first success. Each attempt uses the existing random-index rollback helper, and the parser constructs its declaration context locally with the same property ID. Retaining the selected AST therefore does not rerun or bypass first-success/random-index assignment. The unchanged `Value::to_computed_value` still enters `with_registered_value`; direct invocation does not bypass this computation wrapper. No random-cache stability or full parser transaction theorem is inferred. Searchfox discovery for the local rollback identifier returned no match; historical random audits were useful context, not substituted for applicability evidence.

CSS-wide results use `Existing` and the byte-identical application suffix, including cached initial/inherited value selection and INHERITS_RESET_STYLE bookkeeping. They do not take the newly parsed invalid-initial route. Invalid typed/substitution results prepare an initial only for non-universal registrations with `!inherits || root`, using the registered initial's CSS/URL, default attr taint and the same parser inputs. This mirrors the existing invalid handler. Inherited copy, absent initial and parse failure stay with that handler. `Initial.apply` intentionally does not OR taint from the discarded expression, matching the original invalid/default behavior.

Parsing a cyclic default for classification does not itself call `to_computed_value`; the existing invalid handler later computes it. The already-documented unresolved boundary is computation timing: SCC popping may compute a contextual initial before eventual invalid-priority publication. Likewise this audit does not close generated scheduling/Zoom behavior or prove that the dependency classifier covers every context read. These are not newly established counterexamples, and no native or browser outcome is claimed.

No test or current77 oracle was changed. A future focused random preservation control could place a numeric random expression in `<length> | <number> | <color>`, exercising a rejected first alternative while entering the COLOR-capable prepared path, and compare its selected key with the existing independent same-key reference. That would test the retained-AST boundary; this audit supplies neither a new failure prediction nor an executed result.
