# Endpoint refresh is separate from installed animation style

The existing Entry/Handoff proofs establish normal traversal admission and, with explicit forwarding and a route-length budget, visitation. Provider proves revision coherence of the metric producer. None establishes that rebuilt keyframe endpoints have been applied to the style returned by a getter. This separate model imports Entry unchanged and adds that missing boundary; it does not add a native implementation or native correctness claim.

`Application.lean` keeps an endpoint generation/value, an installed generation/value, and a finite queue of application snapshots for one fixed identity. Changed endpoints increment their generation and enqueue an application. An application installs only when its generation is still current. The invariant preserves both bounded/coherent queued generations and coverage: the current endpoint is either already installed or represented in the queue. The invariant holds through arbitrary finite accepted refresh/dispatch/drain histories, rather than assuming the final installed value equals the endpoint.

The concrete accepted history starts with installed/endpoints 46. A pass drains existing work and then refreshes endpoints; the first pass has unchanged 46, and the second refreshes to 64. After two passes the endpoint is generation 1/value 64, the installed value remains generation 0/value 46, and generation 1 is queued. `normal_route_is_insufficient` combines the existing complete-route theorem with this non-ready state. These are compatible abstract components, not a proof that native route visitation caused this exact history. A third **quiescent** pass installs 64; another changing pass can enqueue more work and remain non-ready. This is a counterexample to a fixed two-pass readiness guarantee under the modeled ordering, not a recommendation to add exactly one pass.

The numeric payload is a single endpoint/result descriptor, chosen to mirror the paused constant-endpoint fixture. Interpolation, easing, composite order, base values and animation-rule installation are not implemented here. `ready` is a sufficient conservative condition, not a minimal observer barrier: it requires the abstract queue to be empty even if only harmless stale jobs remain.

The model makes the termination condition explicit. Each dispatch consumes one queued job; `dispatch_decreases` supplies the natural-number measure. `drainValues` structurally traverses that finite queue. `stable_drain_ready` proves that such a drain reaches the current endpoint under the invariant. `finite_changes_then_quiescent_pass_ready` permits any finite prior change sequence, followed by a pass that creates no new endpoint change. It does **not** infer that a native pass is quiescent from entry, a nonempty traversal, stable current root size, or a fixed pass budget.

An implementation-level ready-observer contract must ensure all of the following before returning the style observation:

- The selected metric provider and all inputs used to rebuild these endpoints are current, with no unprocessed invalidation relevant to this getter.
- Pending relevant endpoint/application obligations are conserved across traversal boundaries and selected for execution. Coalescing must retain the newest obligation, and delayed work must not overwrite a newer result.
- Composition and style installation have completed for the same target/pseudo/effect lifetime and endpoint generation; a queued event, a rebuilt endpoint, or `WillComposeStyle` alone is insufficient.
- The readiness check and observation cannot be separated by an unaccounted invalidation. This model has no cancellation, retargeting, identity reuse, concurrent publication or observer interleaving.

For a finite-depth dependency graph, termination additionally needs a source-backed finite-change/rank argument: providers must stabilize, dependency propagation must be scheduled fairly, each selected operation must terminate, and downstream changes must decrease a well-founded outstanding-work measure. Finite depth alone does not rule out cycles, repeated transition creation, external invalidations, or feedback from installed font values. The present theorem takes a finite change sequence and a final no-change pass as explicit premises. It proves neither a native depth bound nor fairness nor convergence for CSS animation/font feedback. For example, a root-to-animated-child-to-animated-grandchild chain can generate a new downstream refresh after an upstream application; a fixed third pass is not established by the single-child witness. A production loop would need the work-conservation/rank obligations and a defined cycle policy; this artifact does not propose one.

The native source mapping is deliberately incomplete. `KeyframeEffect::UpdateProperties` assigns changed properties and requests Layer restyling. `EffectCompositor` uses coalesced target/cascade-level entries, **not** this FIFO of versioned snapshots. Its selection, `WillComposeStyle`, composition and installation require a simulation relation to the abstract application step. `StyleDocument` supplies the candidate drain/traversal ordering, but the original RFST log did not record outer-pass ordinal or queue state. The sealed causal review motivates this model with 64px changed-endpoint rebuilds and later unchanged rebuilds; it does not prove the native history used in the two-pass counterexample. New queue/pass instrumentation is separate pending evidence.
