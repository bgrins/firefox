# Contextual attribute integration successor

This unfinished artifact-only successor corrects the confirmed request-key defect in checkpoint1 and changes when cyclic priority results are published. It is not ready for native installation. The original checkpoint and the six-theorem ancestry model remain immutable. No native checkout, build, browser, Git or canonical control was changed.

Prepared requests now distinguish the graph owner index, reference occurrence address, full active attribute-request ancestry, parser property ID, sink suppression and URL data. Admission retains the raw input Arc; final graph substitution must find that exact admitted occurrence. The address is only an ephemeral equality key, never dereferenced or persisted as a native receipt. Examined Custom, priority and Attr paths retain the same Arc-backed reference through preparation and consumption. Physical recurrence still compares attribute name and namespace before result reuse, independently of these contextual identities. Dynamic invocations outside preparation receive fresh IDs, so a later invocation cannot overwrite another occurrence's completed cache entry merely because both use the same physical attribute/context.

The result session is cleared after each closed DFS root and before the next root; outside-graph public substitution starts a fresh result session. Raw strings and accumulated queried-attribute references remain on AttributeTracker. This follows the saved keyframe lifecycle: one tracker spans multiple fresh builders, each builder resolves its custom map, then final AnimationValue conversion consumes the supplied computed context after that builder drops. Final conversion uses a fresh result session, rather than carrying contextual results from a prior keyframe. No new native generation field is added. The premise is a fixed synchronous raw attribute snapshot per tracker and stable resolved dependencies within each prepared node; if a caller violates those premises, these boundaries do not establish correctness. Inspector's missing property ID and the broader container computed-input contract remain separately limited.

Cyclic-priority publication is a distinct correction. The SCC is completely marked and popped first. All prepared priority declarations in that SCC are discarded. Only then are its priority IDs sent through the existing ensure/application path before returning to outside dependents. The admitted VariableDeclaration wrapper checks invalid_non_custom_properties before shorthand-cache lookup or substitution, so variable declarations do not retry the cycle against newly defaulted custom values. Literal declarations bypass that wrapper and retain the existing literal application behavior: this is publication of existing cycle-handling results and bookkeeping, not blanket defaulting of every marked priority. A debug assertion checks that generated outgoing dependencies are already ensured or marked invalid. Generated ordering edges versus exact semantic dependencies and literal members of a generated-dependency SCC still need focused native preservation evidence.

Selected-token staging and the other checkpoint1 changes are retained. In particular, selected unit flags are obtained after substitution instead of from unused fallback inventory. The existing registration-union ColorScheme edge remains conservative; this patch does not turn that policy into a proof of exact selected-value dependence. The active-value taint producer and alias-through-attr provenance copy remain experimental policy choices, not a complete implementation of the specification's property-name wording. Chained namespace limitations are retained.

The full ancestry vector is an intentional correctness-first representation with a visible cost. A valid chain of n nested requests stores 0+1+...+(n−1)=n(n−1)/2 ancestor IDs: 28 at depth8,8128 at128 and523776 at1024, excluding the other key fields. Linear request lookup and vector comparisons add further cost. A future interned invocation-parent representation must justify the ancestry implication and session lifetime; shortening the key to a parent name/context is disproved by the model. No performance acceptance follows from these operation counts.
