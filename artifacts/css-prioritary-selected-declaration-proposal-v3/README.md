# Preserve Appearance bootstrap eligibility

This committed-base-relative experimental successor changes one V2 condition: while the APPEARANCE_BASE flag is absent, Appearance itself does not recursively request Appearance to decide eligibility of its gated declaration. It skips that currently unavailable declaration through the existing eligibility test and can select its ordinary bootstrap declaration. Other reached properties, including FontSize, retain their Appearance selection dependency. Already-included APPEARANCE_BASE behavior is unchanged. All rollback, ForcedColorAdjust, prepared application and SCC handling bodies remain exact V2.

The uncovered route is an Appearance declaration inside a UA @appearance-base rule, above an ordinary `appearance:var(--missing,base)` declaration. A registered2em value demands FontSize; its reached gated declaration demands Appearance. V2 then visits Appearance→Appearance, invalidates the property, discards its prepared chain, and the existing invalid wrapper changes the lower ordinary variable declaration to Initial/None. Base skips the unavailable gated entry and evaluates the ordinary fallback to base appearance. The separate three-case Mozilla supplement compares that variable bootstrap, a literal bootstrap, and omission of the gated Appearance entry. It does not change the frozen74 suite.

Root-admitted rule_parser.rs and stylist.rs match HEADecfe. AppearanceBase requires chrome-enabled parsing, then uses normal nested rules; the nested style rule enters CssRuleType::Style and ordinary declaration parsing. The stylist attaches APPEARANCE_BASE to the containing rule. Frozen longhand metadata includes Appearance with initial None; VariableDeclaration::substitute_variables checks invalid_non_custom_properties before ordinary substitution. Thus the parser and frozen source support this potential V2-introduced regression. Actual original/V2/V3 browser outcomes and exact first-demand scheduling remain unexecuted for the supplement. This is not a newly discovered shipping Firefox bug.

The delta adds no parser/value/default policy and does not promote generated scheduling edges to semantic cycles. It does not claim to fix other appearance prerequisites or the documented inherited scheduling boundary. It is justified by matching the original bootstrap eligibility ordering, not a general proof that self-dependencies can always be discarded.
