## Source and contract

Searchfox identified the helper; six Git-authenticated source inputs cover the patch and supporting C++ helper, source-step construction, generation and serialization. The normative route is captured in the earlier `css-named-range-group-order-review-20261110-v1` primary snapshots: CSS Animations 2 groups identical selector/easing/composition tuples, keeps the earliest group position, and cascades later declarations within the group. Named-range computed ordering preserves that specified order. Equal finite used offsets preserve the computed tie order. See [CSS Animations 2 keyframe processing](https://drafts.csswg.org/css-animations-2/#keyframe-processing), [named-range selectors](https://drafts.csswg.org/scroll-animations-1/#named-range-keyframes), and [Web Animations getKeyframes](https://drafts.csswg.org/web-animations-1/#dom-keyframeeffect-getkeyframes).

`KeyframesAnimation::from_keyframes` emits named-range steps in original rule/selector order. Therefore enumerating its vector before reversing supplies the relevant positions. Percentage-only steps have a separate vector and existing sort; this patch changes neither that path nor its helper.

`GetOrCreateKeyframe` returns an existing array index on a match, otherwise appends one frame and returns the **new array length** as sentinel. The range wrapper preserves that contract and does not rotate. Hence, on reuse, `matched_idx < frame_count == position_count`; on creation, the index equals the new frame count and one position is appended. The new vector cannot have an uninitialized slot under this helper contract. The returned frame reference remains valid while a separate position vector is modified; this does not move its backing frame array. No new FFI or unsafe block is introduced.

Reverse traversal visits strictly decreasing source positions. Each new group records its first encountered position; each match overwrites only that group's coordinate. Its final coordinate is the earliest occurrence. Different groups have different coordinates because each source occurrence belongs to exactly one tuple. Consequently `sort_unstable_by_key` is adequate: there are no equal keys whose stability matters.

Crucially, all frame positions remain fixed until `remove_duplicated_property_value_entry` consumes the saved reused-index set. Its existing declaration iteration and property deduplication are byte unchanged. Logical-to-physical conversion, reverse declarations, non-animatable/important filtering, and later-value precedence retain their existing behavior. Sorting afterward moves whole `(Keyframe, position)` records, preserving every declaration/timing/composition/offset payload. The later `extend` transfers owned frames; no frame references or saved indices escape that stage. Blindly rotating during construction would invalidate earlier saved indices and is correctly avoided.

The length assertion before `zip` is debug-only. Source induction establishes equal lengths on all current helper paths; absent that contract, release `zip` could truncate. This is an explicit cross-language assumption to preserve in future changes, not a claim that the assertion independently protects release behavior. Empty range arrays remain empty; unique groups produce the previous source order. Existing later stable computed-offset sorting and endpoint generation are unchanged. This review does not settle the broader draft/implementation questions for unequal resolved offsets or unresolved ranges.

## Proof and validation boundaries

Root's `PositionModel.lean` models keyed metadata updates over a reversed enumerated source list. `record_matches_first` proves each key's final position is its first occurrence; comparison and consumer equality follow. This maps to the new assignment on each reuse, conditional on native group-slot identity matching the abstract key. The consumer theorem does not itself verify Rust's sort or payload movement.

Author's `Slots.lean` proves local list-length alignment, valid reuse indices, new-sentinel distinction, decreasing-position freshness, uniqueness preservation and equal-length zip cardinality. These are useful obligations for the position vector, but they are not a mechanically coupled simulation of native frame arrays, FFI matches and saved-index set. The abstract model uses total list update while native indexing can panic if its caller invariant is violated. The native helper contract and stable slots bridge that distinction by source reasoning. Neither model proves C++/Rust memory behavior, declaration precedence or the standard library sort implementation. Reported kernel audits/mutants are author/root results; this reviewer inspected the model source rather than repeating the full Lean replay.

Independent `review.py` authenticates the patch/source bytes, checks scratch forward/reverse replay, unchanged native exterior/declaration loop and post-dedup reorder placement. A separate finite abstract check compares 55,987 sequences over three group keys and two property identities, lengths zero through six, against a forward first-group/last-property oracle. It also rejects the A,B,C,B,A early-rotation stale-slot shortcut. This is bounded validation of the reasoning, not native execution or a universal theorem. `REVIEW.json` and `INPUTS.json` bind those checks.

## Cost and remaining gates

The range path adds a position vector and an owned pair vector; these may allocate O(g) extra storage. Final ordering becomes O(g log g) comparisons/moves instead of a linear reverse, while existing grouping searches remain potentially quadratic in source/group count. Frame payloads are moved, not explicitly cloned. No allocation count or performance equivalence is claimed. This tradeoff is localized to named-range construction and avoids per-occurrence index remapping.

Real compilation must validate Rust type inference, FFI bindings and owned collection operations; optimized runtime must verify the intended changes and preserve the existing controls. There is no newly identified assertion-dependent behavior requiring a blanket debug gate for this narrow ordering repair, but debug is unrun coverage. This conclusion does not relax the independent missing-pseudo CSSOM debug gate. No new bug count, standalone repair acceptance, or release-exposure conclusion is made before the runtime and delivery review.
