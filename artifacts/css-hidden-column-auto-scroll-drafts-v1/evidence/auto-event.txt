# CSS-CONTAIN-2#content-visibility-auto-state-change

**Detecting content-visibility: auto state changes: the contentvisibilityautostatechange event** (heading)

**SHA**: hash:d3d2a6aead18ef518d694f62280f5a8cd01c52e0a817546858760c002f240cee

## Content

The **`contentvisibilityautostatechange`** event is fired on an element with [content-visibility: auto](CSS-CONTAIN-2#propdef-content-visibility) style when the rendering state changes and the element either becomes or stops being [relevant to the user](CSS-CONTAIN-2#relevant-to-the-user).

Description of ContentVisibilityAutoStateChangeEvent attributes:

**`skipped`**, of type [boolean](WEBIDL#idl-boolean), readonly 

Set to true if target changed state to [skip its contents](CSS-CONTAIN-2#skips-its-contents), and false otherwise.

Description of ContentVisibilityAutoStateChangeEventInit members:

**`skipped`**, of type [boolean](WEBIDL#idl-boolean), defaulting to `false` 

See the description of the [`skipped`](CSS-CONTAIN-2#dom-contentvisibilityautostatechangeevent-skipped) attribute.

Note that elements in [content-visibility: auto](CSS-CONTAIN-2#propdef-content-visibility) subtrees remain semantically relevant even for elements that [skip its contents](CSS-CONTAIN-2#skips-its-contents). This means that it is inappropriate to use this signal to indefinitely skip DOM updates in the subtree that is skipped. Instead, it should be used to deprioritize updates, but ensure that the content remains semantically relevant and reasonably up-to-date. This is particularly important for assistive technologies which consume this content even when the ancestor is set to skip its contents.
