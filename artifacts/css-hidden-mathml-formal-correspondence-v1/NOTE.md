# MathML correspondence to existing readiness proofs

No new mathematical lemma is needed for the proposed one-line readiness repair. The remaining work is native correspondence and regression validation, not another conditional closure theorem. This note adds no Lean code and does not rerun a compiler. BINDINGS.json pins the existing modules, captured trace and proposed patch.

The proposed `MarkSubtreeDirty()` runs on the skipped mrow. Project its owned frame tree to `Subtree.Tree`, with `dirty` = IS_DIRTY, `hasDirtyChildren` = HAS_DIRTY_CHILDREN and `eligible` = their disjunction. The mrow query is path `[]`; the mspace query is the selected owned-child path `[j]`. The native principal-child pointer supports this relation for the observed pair; a full ownership-tree extraction is not proved.

| Step | Existing exact lemma | Correspondence and limit |
|---|---|---|
| Old first/repeat queries do nothing | `Hidden.clean_query_is_noop` | Both targets have dirty=0, dirtyChildren=0 and take native `query-clean-reject`. Map model dirty to native eligibility, not solely IS_DIRTY. |
| A clean leaf fails to force its ancestor | `Hidden.clean_descendant_does_not_force_ancestor` | Explains why the leaf query leaves the empty mrow unrepaired even though the leaf retains its own size. The arbitrary `forceSubtree` parameter does not prove what forced native layout would do. |
| Marking admits the mrow | `Subtree.root_is_eligible` | `markRoot` makes the selected root eligible. |

These support the selected clear-path premise. No universal `rootClosure` for unobserved children is inferred. |
| An admitted query obtains provider output | `Subtree.selected_query_recovery` | Conditional on the same located target, actual hidden ancestry and successful native forced-provider correspondence; this composes `Hidden.dirty_query_uses_actual_provider`. It yields `layout key`, not asserted desired CSS geometry. |
| Completed reflow permits a cheap repeat | `Subtree.selected_query_completion`, then `Hidden.clean_query_is_noop` | Conditional completion clears modeled eligibility, so the repeat preserves the recovered result. Native completion/lifetime still needs correspondence. |

The finite trace supports the critical clean-path premise directly: c1 events641–644 and c3 events1354–1357 show clean row and leaf across input construction and the actual hidden return. Empty-output publication and clean DidReflow return occur at652/654 and1365/1367. Both first/repeat query gates reject the clean targets. The proposed marking itself was not part of that trace. Hidden DidReflow's preservation of newly set bits therefore comes from source reasoning and must survive the native candidate execution; the old trace only shows the same branch preserving already-clear bits.

`Subtree.already_dirty_root_clean_leaf` already records the short-circuit counterexample. The observed failing history avoids that barrier; it does not establish global dirty coherence for every MathML history. `Subtree.root_coverage_exact` precisely describes the wider closure requirement and should not be weakened or assumed merely because this fixture has one visible principal child.

`LineReady.selected_descendant_ready` and `LineReady.actual_provider_recovery` provide the corresponding conditional composition for the existing skipped-block-line repair. They explain the separate root-block interaction controls, whose native path may bypass MathML Reflow entirely. Do not instantiate `LineReady.Line` as a MathML mrow or transfer its counted-line-child traversal proof to this guard. `LineReady.line_flag_not_query_bit` reinforces the separation between container bookkeeping and queried-frame eligibility, but is not a proof about MathML owner flags. Final standalone coverage remains the four internal-owner cases; root-block cases retain their separate interaction role.

Two semantic limits matter. First, `Hidden.measure` models a cache-reuse/miss decision; MathML's captured caller unconditionally caches and publishes the returned output. Its cache-miss lemmas are not an exact native MathML correspondence. Second, `Hidden.Frame.geometry` is a `Size`, not a rectangle. The leaf's wrong x/y is outside that geometry representation. The existing readiness theorem can justify forcing a provider under its assumptions; it cannot prove that provider computes RTL placement, baseline alignment or the correct viewport rectangle.

Unproved native obligations remain: ChildLists/parent-path and selected-frame identity, preservation of the new bits through callbacks and scheduling, hidden-ancestor forcing and successful full-owner traversal, provider correctness, frame lifetime/no intervening mutation, and arithmetic/coordinate conversion. The trace supports one finite old history, not these universal properties. A genuine future extension for full positional correctness would model rectangle/provider composition and its native refinement; merely restating “closure implies ready” would add nothing for this patch. Use the isolated comparison and relevant WPT controls to test the native bridge before accepting the repair.
