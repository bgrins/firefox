# Rule occurrences and shared declaration allocations

No differing-result counterexample was found in this bounded source audit. Distinct stylesheet instances **can share declaration allocations**, so semantic rule uniqueness is not a valid unconditional premise for C. The existing ordered-block quotient is the useful argument: repeated occurrences need stable actions, ordered partitions and preserved observations, not unique allocations. This report narrows its native premises; it does not prove the full native evaluator quotient or add a browser bug.

Authority is immutable `8b26f6a764bfa926ffea5d71c17e26c5d42f9363` and the separately hashed frozen indexed candidate. `SOURCE.json` contains nine source-object hashes, eighteen exact excerpts and hashes of reused evidence. Upstream discovery used bounded Searchfox queries. No live native files, browser, build, index or previous artifact was changed. This audit ran no Lean or browser tests; previously compiled theorems remain evidence for their stated models only.

## Concrete sharing producers

* `CascadeData::add_styles` clones one declaration-block Arc into each selector's `Rule`. A selector list `.target, #target` with an intervening `.target.other` competitor can generate nonadjacent repeated-block visits at equal full normalized priority. These copies belong to the same semantic style rule; their existence alone is not an incorrect exclusion.
* `Loader::CreateSheet` clones a completed cache entry. `StyleSheet`'s copy constructor retains `mInner(aCopy.mInner)` and calls `AddSheet`; it forces a unique inner only when CSSOM has already forced uniqueness. `StyleSheet::RawContents` and `GeckoStyleSheet::raw_contents` expose that shared inner's Rust contents. Thus distinct wrappers for cache-reused external stylesheets can share rule/declaration allocations. This is a concrete allocation-sharing path, not a claim that an uninstrumented page is guaranteed to hit the cache.
* `CascadeData::add_stylesheet` deduplicates consecutive identical contents only. An intervening effective different sheet prevents that shortcut. It deliberately does not retain the previous-sheet dedup key when an implicit scope root was seen. Scoped copies therefore require reasoning about matching, rather than assuming sheet-pointer identity supplies an identical root.
* `DocumentOrShadowRoot::OnSetAdoptedStyleSheets` retains only the last duplicate sheet occurrence in the active style list. `[shared, competitor, shared]` in `adoptedStyleSheets` is unsuitable as a witness for two active shared copies.

## Which occurrence distinctions survive evaluation

| Distinction | Audited boundary |
| --- | --- |
| Specificity, source order, scope proximity | `ApplicableDeclarationBlock::sort_key` uses these to order candidates; `for_rule_tree` retains source and priority. They are not supplied as occurrence-specific inputs to longhand substitution. Different order remains relevant and is retained; the quotient allows interleaved competitors. |
| `@scope` root | `find_scope_proximity_if_matching` sets the scoped-style dependency flag, tries roots and returns the first matching candidate's proximity. It does not emit one value-evaluation context per matching root. Implicit roots may change eligibility/order before the cascade. C's guard does not remove matching or its dependency bookkeeping. |
| Tree context, layer, origin, eligibility flags | These remain in the full normalized `CascadePriority` key. Equality includes flags even though ordering ignores flags. Equal cutoff order is insufficient for exclusion identity. |
| Tree-scoped computed values | `apply_one_longhand` sets `context.scope` from the retained cascade level only immediately around terminal `do_apply_declaration`, then restores it. A Rule trigger returns before this mutation. A shared allocation does not erase a different cascade level. |
| Custom properties, `var`, `env`, `attr` | Longhand substitution uses the receiving builder's substitution functions and context, not a per-rule custom-property provider. Custom/prioritary resolution can mutate this state between properties; it is not globally immutable. The same-property prioritary walk is contiguous and performs postprocessing only after a terminal declaration. Reuse the observation audit's narrower stable-input premise. |
| `@position-try` | `resolve_position_try` looks up one fallback, replaces the `PositionFallback` rule-tree level and invokes a separate cascade. The try tactic is applied in style adjustment after property cascading. Different invocations do not share C's exclusion state. This audit does not establish a universal provider theorem for every synthetic origin. |
| Visited and physical mapping | Visited resolution uses another `cascade_rules` invocation; C state is fresh. The exclusion key is the physical property after logical mapping. Equal source alone cannot suppress other properties or other invocations. |

## Bridge to the existing quotient

`compute_rule_node` removes only adjacent equal `(source, full priority)` entries. `insert_ordered_rules_with_important` then inserts every surviving normal source, including empty normal partitions. For an Author/User/UA block containing important declarations it queues the same source with `priority.important()`. Important entries are stably sorted. This gives a concrete paired-source-roster argument for these main CSS origins: every important block copy has its normal partner; omitted important visits for blocks with no important declarations would be empty. This is not a proof for arbitrary callers of `insert_ordered_rules` or arbitrary synthetic origins.

`DeclarationIterator` traverses each block backwards and filters its importance partition. Its pseudo restriction is fixed for the invocation; equal full priority also retains the origin exception. Thus the native path preserves the ordered-block structure used in `constructed_stream_quotient` for this provider.

The trigger argument remains conditional but is stronger than “identical text”: for a fixed physical property and priority class, an admitted concrete value or invalid-at-computed-value fallback marks the property seen, making a later Rule unreachable. An admitted Layer/Origin rollback rejects its own priority class thereafter. A genuinely reached Rule therefore cannot have an earlier admitted terminal or same-class self-cutoff prefix in that search. Genuine Rule parsing returns before terminal scope mutation, prioritary postprocessing and shorthand-cache insertion. Stable substitution inputs make a later identical trigger repeatable. The existing observation audit separately covers repeated attribute-dependency support, idempotent flags/cache conditions, and the forced-color path that can append an ordered deferred value then become Origin rollback. Do not replace deferred action lists with sets.

The important-to-normal boundary still needs the complete paired roster and monotone cutoffs; a local statement about one repeated Rule cannot replace it. The existing Lean model proves this boundary for its constructed stream. Its counterexamples for a missing important occurrence, changed action, reordered block, and exact observation multiplicity remain applicable warnings about hypotheses, not discovered native bugs.

## Smallest useful next witness

Use two same-URL external sheets separated by an effective competing sheet, versus independently parsed identical-content controls. Avoid reading `cssRules` or changing rules before measurement because CSSOM can force unique inners. Confirm the shared declaration pointer and full normalized priority in a bounded native trace; a successful network request or equal CSS text does not establish sharing.

Exercise (1) nonadjacent selector-list copies, (2) cache-cloned sheet copies, and (3) cache-cloned implicit-scoped copies with differing proximity. Each should include an important Rule trigger plus ordinary fallback in the same block, an interleaved competitor, and logical/physical aliases. Drive the trigger through a receiver custom property or `attr()` and mutate it after the initial calculation to check retained dependencies. Compare shared and independent controls through both importance phases; record the actual active source roster. A separate context/layer/flag case should demonstrate that distinct keys are not merged. These are proposed coverage obligations, not executed results or independently established numeric specification oracles.
