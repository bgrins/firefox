# Union and image repair commit packaging

Recommend a dependent two-bug stack: research/evidence publication, union native+WPT commit A, image research/evidence publication, then image native+WPT commit B. Each native commit contains only source and its focused WPT; no artifact inventories, runners, copied harness, metadata overrides or research documentation. Bug IDs/reviewers/signing remain the root publication workflow. This package creates no commits and does not assert landability.

A supplies the retained selected AST/parser, actual-default selection, recursive image/color classifier and common application extraction because COLOR-capable unions can select images. These helpers are required by A; including them in A does not import Image-only admission. Provider and value postimages are identical in A, standalone image-only and combined V5. The second native patch changes only cascade.rs and reuses those helpers. A is base-relative; B depends on A. Calling both patches independent original-base cherry-picks would be false. Actual patch replay rejects applying the complete standalone image alternative on A: it duplicates shared edits. Never resolve that by blindly choosing one whole file.

The tested-byte A→combined delta broadens initial admission to COLOR or IMAGE, but also removes the eligibility gates around selected preparation and cyclic-default classification altogether. It therefore is not textually just Image-only enablement. NARROW-VS-TESTED.patch makes this distinction reviewable.

The proposed narrow second patch keeps a selected_dependency_eligible guard at both traversal hooks, computed as registration COLOR eligibility OR an Image syntax component. Initial admission is the exact combined find_non_custom_references function. Thus eligibility is C∨I, the union of A's C and the standalone image alternative's I∧¬C. It admits direct images without contextual colors, preserves the existing length/reference walk, includes images already deferred through var/attr, includes image/color unions, and keeps the cyclic invalid-initial hook for both classes. Prepared/default application and all source ownership remain unchanged. Outside C∨I, traversal retains A's original path; the common provider extraction still exists, so this is not a claim that every source instruction is original.

Frozen DataType::dependent_types marks Color as COLOR and leaves Image empty. The retained classifier reads used color scheme for Color and Image branches, recursively through image components; all other scalar variants return false. TransformList recursion exists but its parsed component domain remains a source/type obligation. No inspected source establishes an intentional need for broad preparation/default classification on registrations containing neither COLOR nor IMAGE. That is a bounded finding, not a proof of equivalence for all parser shapes, raw attr values, malformed/default/cyclic values or shared SCC interactions. The narrow version changes when substitution/parsing/default classification runs outside the eligible set. It needs actual native45 validation and review, even though each intended class has a previously tested alternative. It is deliberately not byte-equal to combined V5.

## Prerequisite and validation decision

A separate shared refactor is not required for the proposed dependent order. Copying the full common provider/value changes into an allegedly behavior-neutral prerequisite would add unused prepared/default/classifier machinery, and ordinary provider calls already pass through a new helper. No standalone refactor baseline has been run or proved. If reviewer requirements demand independently applicable A and B above a common prerequisite, first design that prerequisite explicitly and validate its native build/full baseline behavior before either bug commit. The present alternative successes do not establish neutrality.
