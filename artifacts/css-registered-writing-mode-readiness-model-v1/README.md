# Admission before writing-mode publication

A small Lean witness separates an acyclic dependency graph from safe evaluation order. It models the existing unexecuted provider-readiness draft: a noninherited registered keyword provider selects bogus, fails its registration and defaults to vertical-rl. A line-height helper can nevertheless apply writing-mode before this admission, consume bogus directly, inherit horizontal-tb and cache that result. Later provider admission does not repair the cached writing-mode.

Kernel-checked bad order produces ready vertical provider, cached horizontal writing-mode and360px. Admitting first produces vertical writing-mode and220px. The six-node selected dependency graph is acyclic by a strict rank argument over arbitrary positive-length paths. Thus the bad order is not excused by a real graph cycle.

The general sufficient condition is a ready provider plus an absent or already coherent writing-mode cache. Ready alone is insufficient after a stale value has been published. The illustrative guarded API refuses pending providers and correctly publishes a fresh ready keyword; it does not claim to implement or verify a production scheduler. Two false claims are decisively rejected: graph ranking alone implies the bad schedule computes vertical, and later readiness repairs an ensured horizontal result.
