# Sizeforms crash: bounded source review

The completed candidate sizeforms stream contains zero `test_status` callbacks and one page-level CRASH. The saved stack identifies `substitute_all`'s terminal assertion accepting only Complete or CycleSettled. It does not record the root name, retained frame, action result, element, JavaScript stage or computed values. This is not a literal-control PASS, nor evidence that any particular unsupported form was executed. Core21 success is separate evidence reported by root; this review does not recompute that aggregate or attest live restoration.

The staged HTML is byte-identical to the sealed sizeforms probe, and its staged harness serializes promise-test bodies through `tests.promise_tests`. Registering four callbacks in a for-loop does not itself construct all four iframes. The variable, percentage and inherited test bodies are therefore not eagerly launched alongside the literal body. Zero reported callbacks alone still cannot prove which body or statement was active: the raw stream is an observation boundary, not an execution trace.

Even the first literal-control body has a wider styling environment than its target declaration. It first appends an iframe containing a div parent/target and two reference divs with an empty stylesheet, waits for load, registers --len and queries its initial computed value before installing any explicit size. Each phase then styles a literal-sized parent and target, a literal-sized reference, and an attr-reference with an absolute registered --len and typed width but no explicit font-size. Rendering and computed-style flushes may process these elements and iframe defaults. Both 20px and 30px phases and three animation-frame waits per phase occur before test completion. Consequently “literal control first” does not exclude inherited/default-size paths during setup or controls. None is established as the crash cause by the current log.

In frozen f0d, `prepare_computed_size` admits only a retained selected absolute FontSize operation and stable static input prefixes. It rejects an empty/default selected operation, percentage and eligible WithVariables forms; ordinary dependency processing remains the fallback. `substitute_all::run_one` stops on unresolved work without an action, or on an action result other than Published/AlreadyComplete, then asserts. The stack confirms this terminal boundary, but does not select among those routes. The static restrictions are relevant hypotheses, not a reconstructed native root or a new normative-cycle finding.

Pair this with the existing terminal-only native diagnostic pattern adapted to f0d: print the already-computed root/result, retained frame/node publication, pending action and its already-computed progress, FontSize ensured/completed/facet/deferred state, and static-selection rejection reason.
