# Bounded compatibility argument

For currently admitted Linear syntax, all output/start/end resolve calls succeed under unchanged parser guards. The old parser feeds the builder an output and optional first coordinate, then the same output with its second coordinate when present. The new from_stops traversal feeds exactly that ordered sequence after successful whole-function parsing. ToPercentage in the authenticated source delegates directly to Percentage::resolve, so the coefficient values are the same. These read-only resolve methods receive neither mutable context nor an element; this reasoning depends on their stable classification, not on an arbitrary later contextual evaluation. Stop count and minimum authored-entry rule remain unchanged.

Successful known parsing then stores Resolved with the same built PiecewiseLinearFunction. Specified ToCss delegates directly to the same payload's ToCss, and computed conversion returns its clone. Thus the exact canonical serialization implementation and input are preserved; this is a source-level equality argument, not an executed browser serialization comparison. All current parsed Linear values and from_computed values are Resolved, so derived equality compares the same canonical payload. Failed parses publish no partially built value. The extra temporary AST allocation/work on known parsing is unmeasured and is not called performance-neutral.

For a future Contextual variant, both percentages remain in their authored stop, and the second coordinate duplicates that stop's output when fed to the same builder. Builder interpolation/order logic is untouched. Mapping through Number/Percentage::to_computed_value records real conversion effects in the supplied Context. This alone does not publish them onto every effect owner: the old keyframe handoff must be rebased, with selected declaration scope and invalidation/ordering gaps resolved before activation.

The compatibility expect method still has two named existing caller classes: Gecko CSS keyframe extraction and Servo IntermediateComputedKeyframe. The API parser has already been changed to the fallible method in this slice. Migrate both keyframe callers through actual Context and remove the expect wrapper before any parser guards open; do not rely on the current closed-guard invariant afterward.
