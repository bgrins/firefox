# False-edge admission repair with selected-token obligations

Version 2 keeps the full generalized A scope and removes the specified-AST context collector from the native patch. The patch changes only `custom_properties.rs` and `properties/cascade.rs`. All six collector files remain at their original source bodies. The earlier eight-file v1 proposal is historical and unapplied.

The real registered grammar still admits the selected substitution, including alternatives and repetitions. The result is owned Invalid, CSSWide or a parsed specified value, held until SCC settlement before computation/publication. All selected providers must have left their graph components before preparing; open components retain the existing traversal. Custom/attribute/provider links and guard poisoning are unchanged. URL data, namespaces argument, property identity, taint and CSS-wide effects use the same existing paths.

After admission, the obligation mask comes solely from `VariableValue::parse` over the selected substituted token stream, plus intrinsic descriptor COLOR_SCHEME. There is no `context_references()` call. Thus a selected `sign(1em)` token remains a lexical FONT obligation even if the registered specified parser folds its AST to Number(1). This avoids relying on unresolved optimizer-sensitive cycle policy. Unsupported AST forms do not become empty masks; the AST is retained only for later computation. HEAD preserves the prior mask on an unexpected selected-token parse failure; the pending prototype retains ContextPreparation demand on that failure.

The old prefilter is byte-identical. The graph update is only `value_non_custom_refs &= references`, so it cannot add an edge to the accumulated local mask. Genuine selected-token obligations survive even when their admitted AST simplifies. Unused fallback tokens and values rejected by the actual grammar no longer retain false FONT/LH obligations. Invalid retains intrinsic COLOR_SCHEME because its existing handler can recompute the registration's initial value; CSSWide copies existing initial/parent values and preserves INHERITS_RESET_STYLE through the unchanged helper. Native initial computation may still read other context such as zoom; no blanket context-free claim is made.

This local mask property is conditional. Existing substitution of typed attributes parses and serializes specified values before the selected-token scan, and can itself normalize token text. Version 2 does not change that primitive or claim to preserve pre-substitution lexical units. Dynamic provider/fallback graph construction, parser effects, and typed-attribute normalization remain outside the fixed-graph Lean projection theorem. Targeted runtime and specification checks remain required before any broader cycle-correctness claim.

Mechanism B, missing direct typed-math scheduling, remains separate pending work. A does not widen initial registration dependency admission or decide numeric self-font defaults. The existing 76-case registered-numeric-relative-units lead is not counted again. The broad original browser probe calibrated false-edge cases across scalar types, alternatives, repetitions and five scalar-provider conversions; percentage-to-number conversion failed its independent literal calibration and is excluded from that attribution. Noncyclic direct/provider math failures are B observations, not A acceptance targets.

Static checks authenticate source captures, apply/reverse/reapply the exact two-path patch in removed scratch, parse both Rust files, and preserve the original prefilter, substitution/defaulting helpers and SCC settlement. No native typecheck, build, browser, live source, epoch or Git mutation was performed. Fresh deeper URL/image effect inspection was unavailable as recorded in SEARCHFOX.json; the existing captured parser API/call-chain audit is not an exhaustive proof of parser purity.

The ordinary variant is the standalone committed-HEAD candidate. The prototype variant preserves the unaccepted pending integration; its pending Value obligations intersect the existing selected-value prefilter and keep the prototype's preexisting scheduling breadth. Pending demand remains distinct from Invalid and prioritary requirements are checked before computation.
