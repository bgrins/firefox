# Animated-cycle ownership: independent manual trace

**Question:** Does the current algorithm chain determine whether a cycle between registered numeric animation keyframes defaults only a keyframe endpoint or the final animated property?

**Verdict: INCONCLUSIVE.** The ordinary cycle rule applies, but the examined algorithms do not establish which substitution invocation owns final animated-value computation. Endpoint-only defaulting is a plausible reading of the value-computation call; final-property SCC defaulting needs an additional ownership rule. Neither numerical policy is admitted as a WPT oracle here.

**Scenario:** Same element, registered non-inherited `<number>` properties x/y with initial values 10/20 and literal underlying values 77/88. Separate paused, replace-composited, linear effects have x endpoints `[var(y), 100]` and y endpoints `[200, var(x)]`, sampled halfway. No important winner, implicit keyframe, fallback, registration change, or external invalid syntax confounds the core case.

1. [Web Animations computing property values](https://drafts.csswg.org/web-animations-1/#computing-property-values) takes a property, specified value and target element. It resolves the individual value in the element's computed context. The note says the element's computed values “are not affected by this algorithm.” Dependencies must be calculated first. This distinguishes computing endpoint K(x,k) from replacing the published current value C(x).
2. [Computed keyframes, step 2](https://drafts.csswg.org/web-animations-1/#calculating-computed-keyframes) invokes that operation for every specified property in every keyframe, adding each result to a new computed keyframe. [Effect-value computation, step 5](https://drafts.csswg.org/web-animations-1/#the-effect-value-of-a-keyframe-animation-effect) obtains those frames before selecting interpolation endpoints. No cycle-specific return or property removal appears in those steps.
3. [var replacement, step 2](https://drafts.csswg.org/css-variables-1/#replace-a-var-function) obtains the named property's current computed value; the associated note says this implies property replacement and may cycle. This is the re-entry from K(x,k) to C(y), not an authorization to use y's old sample or base.
4. [Property replacement, steps 1–3](https://drafts.csswg.org/css-values-5/#property-replacement) substitutes with the property's name as context, then invalidates that property on invalid substitution or grammar failure. [Substitution, steps 1 and 3](https://drafts.csswg.org/css-values-5/#substitution) says “Guard context for the remainder of this algorithm” and checks its cycle mark again after nested work. [Cycle contexts](https://drafts.csswg.org/css-values-5/#cyclic-substitution-contexts) mark participating guarded invocations. An inner fallback cannot erase the still-active caller's mark. The specified guard lifetime is the substitution call, not an animation-wide or property-wide permanent mark.
5. [Registered computed-value rules](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation-of-computed-values) perform syntax validation at computation time. [Invalid substitution](https://drafts.csswg.org/css-values-5/#invalid-at-computed-value-time) uses initial or inherited defaulting for a typed registration, not arbitrary earlier-declaration fallback. For these registrations the corresponding invalid computation defaults to 10 or 20. This determines the value **after identifying the invalid computation**; it does not identify its animation owner.
6. [Effect-stack composition](https://drafts.csswg.org/web-animations-1/#calculating-the-result-of-an-effect-stack) combines effect values, and [publication](https://drafts.csswg.org/web-animations-1/#applying-the-composited-result) inserts the result into the cascade. Neither algorithm supplies a substitution-context parameter or explicitly keeps an endpoint's guard alive through the whole stack. The missing join is whether computing C(y) in step 3 establishes a surrounding property-replacement guard before recursively calculating y's keyframes, and exactly what value is invalidated on unwind.

## What the missing join changes

A recursive chain can be written K(x,0) → C(y) → K(y,1) → C(x) → K(x,0). The repeated property names make a cycle detectable. They do not by themselves say that C(x) and K(x,0) are the same invalidated value. If only cyclic endpoint operands become 10/20, arithmetic gives (55,110); if the final properties are invalidated, it gives (10,20). These are conditional policy illustrations, not an exhaustive list of legal outcomes. Solving the numerical equations as a fixed point is also not a specified substitute for CSS cycle detection.

The strongest endpoint-local argument is that WA asks for an individual value and explicitly leaves the element's computed values unaffected. The strongest property-wide argument is the var() note requiring property replacement of the referenced current property. The text does not locate that replacement's guard around the process that generates its animated specified value. Treating either argument as a complete normative bridge would add an ordering/ownership premise.

Similarly, all-keyframe computation is specified before interval selection, but it does not establish that an unselected endpoint's cycle mark persists into other independently computed endpoints. Arithmetic reachability alone cannot justify skipping its computation; merely appearing in any keyframe also cannot justify invalidating the entire stack.

## CSSWG discussion

The [official September 2016 minutes](https://lists.w3.org/Archives/Public/www-style/2016Nov/0073.html) resolve that keyframe var() reads the animated element's animated custom property, after rejecting an initial base-value proposal. Immediately afterward, Simon Sapin asks “So any cycles are resolved the usual way?” and Tab Atkins agrees. This is relevant positive evidence: animations do not evade ordinary cycle handling. It still gives no endpoint/stack ownership algorithm or two-endpoint registered-value result. Do not cite the earlier, superseded base-value suggestion as the resolution.

Bounded official-repository searches and the prior policy search records were inspected. No retrieved discussion supplies the missing owner/lifetime rule. This is not an exhaustive absence claim; direct GitHub API/issue requests were unavailable in this environment.

## Minimal clarification needed

Specify the substitution guard owner when a current animated property is demanded: whether the final current-property calculation, each authored endpoint, or both are guarded; which value receives invalid-at-computed-value-time defaulting; when marks are discarded before the next endpoint; and whether unselected computed endpoints can mark the final current property. Include a result for the two-effect example and a cycle confined to an unselected endpoint. No general animation cancellation rule follows from these value-level failures.

Until then, preserve C(p), K(p,e,k) and effect-prefix identities and explicit unresolved-cycle status in research plumbing. Do not publish a cached value, inherited/initial fallback, or completed ComputedValues merely because the unresolved solver cannot finish. This does not authorize shipping a new rejection policy for cyclic CSS. The already-established acyclic current-provider/defaulting work can proceed separately.
