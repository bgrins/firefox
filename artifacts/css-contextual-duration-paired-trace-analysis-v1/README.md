# Paired instrumented trace analysis

This read-only helper prepares a comparison of separately frozen instrumented-original and instrumented-candidate runtimes. No runtime is bound or read during preparation. It requires a caller-supplied FILES digest and ROOT-TERMINAL within each manifest; verifies every listed file; enforces instrumented-original/original versus instrumented-candidate/candidate metadata roles; and reproduces TRACE-INDEX exactly with the sealed strict parser. Raw and formatted logs remain separate: it uses the producer's raw-if-present selection and never merges or deduplicates their events.

The result has three independent parts:

- `terminal`, `phase_result`, `callbacks`, `endings`, `diagnostics` and `calibrated_acquisition` preserve actual execution and calibration outcomes. Candidate FAIL/exit1 is not converted to success because its trace is informative. A failed or incomplete record collection is not replaced with invented data.
- `trace` retains syntax/sequence errors, explicit cap/truncation, missing IDs and the selected capture stream. `full_key_groups` preserves separate PID/label/element/pseudo/identifier/cascade keys, first/last sequence, event counts, ordered post/removal barriers, deferred and outside-coalesced events, WillCompose preparation markers and closed witness intervals. Cascade-minus-one eligibility groups are explicitly separate from level-specific table-key counts. First/last ranges are not claims that the group's events were contiguous. Trace validity is not capture completeness or test correctness.
- `observations_by_label` joins kind/role to the same runtime's two authenticated records, including acquisition, every phase/read order, identity checks and any differing repeated values. `label_comparison` compares aggregate counts by the ten fixture labels only. Native pointers and process identities are never equated across runs.

The phase alignment is deliberately null: target IDs identify roles, but there is no JavaScript phase marker or synchronized timestamp bridge to assign a specific native request to acquisition, seek or override. A Layer request need not be an effective timing change or one model step. A dispatch marker is an attempted call; removal markers are logged boundaries. WillComposeStyle is preparation, not actual composition. Other wakeups, compositor destruction and uninstrumented paths remain external coverage obligations.

The desired hypothesis comparison is conditional: determine whether the candidate has recorded deferred-set to later outside-coalesced intervals for the failing roles, what barriers occur around them, and whether the original shows a different bounded pattern. Even such a contrast would support further source correlation, not by itself prove the model's exitWithoutDrain premise, native causality, fairness or convergence. The existing fixed-2s override controls are normative calibration; self-dependent phase numbers remain measurements.

Producer contract was read from immutable trace-original-v1 phases.py and trace.py (5c58d4/dd65c9), not from the running original's output. Expected frozen evidence includes ROOT-TERMINAL, TRACE-INDEX, DIAGNOSTICS, FEEDBACK-RECORDS, both posted records, phase raw/log/assessment/result and application metadata. This helper does not replace root's source/app/restoration, binary identity, process cleanup or raw WPT assessor replay checks.

Use `python3 -I -S -B report.py --original DIRECTORY MANIFEST_SHA256` after root freezes the original. Add `--candidate DIRECTORY MANIFEST_SHA256` only after its independent completion and freeze. Output goes to stdout. Static synthetic checks verify key isolation, witness/barrier/preparation separation, label-only cross-run comparison and changed-payload and swapped-role rejection. No browser, build, live-state guard or native/canonical/index operation is performed.
