# Disabled independent archive handoff audit

This preparation targets `css-root-font-cancellation-archive-candidate-browser-v2` and `css-root-font-cancellation-archive-candidate-browser-runtime-v1`. No owner result, terminal, archive or independent live audit is claimed. The future bindings remain null and execution is disabled.

The executed cancellation native audit is retained exactly except for the owner/runtime names and one archive verification call before writing its report. It still checks both data.rs/traversal.rs source identities, original glue context through current-state verification, source/app/extras/binaries, flags, semantic index, controls, backup inventory/removal, recorded process groups and WPT temporary roots. A successful owner must have the exact eight callbacks and one ordered OK ending; complete FAIL observations remain valid observations. The terminal must bind the actual RESULT, and the owner must report restoration. An unsuccessful owner can still have independently verified restoration; that does not make its archive usable.

`archive_audit.py` authenticates the exact future `ARCHIVE-*.json` receipt set. A successful archive requires the ownership identity, exclusive Nightly.app directory, snapshot and handoff, exact build command/result and WPT outcome hashes, candidate source claims, and original glue/custom-properties preimages. It reruns the owner's pinned inventory and existing read-only archive validator. Every copied file must match the saved source inventory, be a regular non-symlink with one hard link, and have a different inode from its original input. All build binaries inside the bundle, including firefox and XUL, are joined directly to copied file hashes. Out-of-bundle build binaries are authenticated by the build receipt and restored-live checks; they are not falsely described as archive files. A second inventory and receipt scan checks stability across verification.

Failure reports distinguish a recorded retained directory (untrusted) from no recorded retained directory. Cleanup-only ownership is considered if the separate ownership receipt is missing. A claim of removal must agree with absence. Neither a failed owner's old handoff nor its retained files grant archive authority. The audit never copies, removes, launches or modifies an archive, and its report always leaves browser authorization and native acceptance false. Successful handoff verification is a point-in-time inventory/provenance check, not authorization for later browser execution or protection against a subsequent filesystem change.

Before root execution, bind the final active owner manifest, actual terminal and RESULT hashes, launch and outer process group, and the exact filename-to-SHA256 map of all archive receipts (an empty map is meaningful for failure before copying). Root must authenticate/seal the completed bindings and enable the gate. Execute only after the owner is terminal. The inherited audit writes only the new runtime `ROOT-LIVE-RESTORATION.json`; all archive access is read-only. No audit execution is performed by this preparation.

Saved checks use the actual archive inventory and existing validator against a tiny owned synthetic archive and synthetic build/source metadata. They authenticate the exact inherited audit delta, disabled future bindings and nine pinned references. They exercise successful verification, failed retained/removed/before-ownership cases, cleanup-only ownership, and rejecting ownership/source/build/handoff/content/link controls. These are preparation checks, not a candidate build, native restoration audit or browser result. The inherited live restoration suite is not rerun.
