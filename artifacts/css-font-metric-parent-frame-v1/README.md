# Retained parent frames in the native substitution traversal

This artifact continues sealed semantic-publication `eae3ff5e`. Candidate `aa9089f3` changes the actual `substitute_all` root call to an iterative retained-frame traversal. The recursive eager `visit_value_references`, `visit_link` and `traverse` bodies are retained byte-for-byte as its comparison path. This is a source integration slice, not a metric repair: the native compatibility provider still always answers ready, and no real font prerequisite provider has been attached. No native build, browser, live source/Git/index or canonical mutation was performed.

A `TraversalFrame` owns its node identity/index, lowlink/self-reference state, original raw Arc, prepared custom AST, ReferenceWalk cursor and queued fallbacks, unit cursor, declaration cursor and outstanding reply. Its phases preserve the eager order: substitution references, selected custom preparation, semantic unit links (or priority references preceded by the existing LineHeight→FontSize link), late default ColorScheme dependency, SCC closure, then publication. Preparation and late-default decisions are not restarted after a child pauses. Closed-node publication remains owned by the preceding slice; its payload is consumed only once.

Context owns both the semantic stack and the frame stack, the outstanding reply and root identity. A post-SCC publication wait returns ComputationPending with the frame and payload retained. The parent has not received a reply, advanced its reference cursor or classified the primary/fallback. Repeated polls resume that same owner; another root and reset are rejected while it is suspended. Child completion delivers an identity-checked reply before the parent continues. No temporary Tarjan indices, copied graph snapshots or independent root traversal are used to escape the wait. The supplied declaration-reference map, attribute tracker and parser inputs must remain valid across polls; the existing native caller supplies the same local inputs, but this interface does not independently certify arbitrary future callers or mutation between polls.

An active semantic dependency gets `ReferenceReadiness::SemanticOpen`, which updates lowlink/self-reference and preserves the eager primary-classification behavior. It does not claim invalid/default outcomes are settled. `SemanticCycle` is supplied only for the whole-component settled result inherited from the preceding slice. A computation wait neither classifies the primary nor creates a semantic edge. Actual CSS cycle handling remains the existing synchronous `handle_loop` path; contextual default computation has not acquired a new readiness proof.

**Suspension retention is not scheduler progress.** The production-compatible call uses an always-ready callback; extracted tests also use finite gate schedules. Those gates do not execute a real missing font prerequisite. `poll_root` intentionally refuses a different root, so an actual provider cannot make progress by abandoning this session and starting another semantic root. The next integration must return an identified scheduling action and execute eligible prerequisite work while preserving this owner, or retain an explicitly unresolved wait when that work itself needs semantic inputs. The ordinary generated ensure path and final drain still need that action protocol and finality certificates. An indefinitely false gate remains pending; no lack-of-progress rule invalidates CSS values or chooses parent metrics. No genuine metric wait-cycle policy is selected here.

The copied staged metric preparation/drain helpers remain available but are not invoked by this new traversal. All old semantic edge/admission rules, including the published COLOR/image refinement, remain; stronger whole-font readiness and the transport-only demand prototype are not silently enabled. This candidate therefore does not claim to repair the observed weight, style, stretch, size-adjust, orientation or typed-attr metric failures, or the rejected selected-declaration candidate's scheduling regression.
