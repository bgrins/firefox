# Generalized admitted-value context collector proposal

Status: source-only proposal, not applied or compiled. No accepted bug, native proof, browser result, or canonical Lean coverage credit is claimed here.

`SpecifiedValue::context_references() -> Option<ReferenceFlags>` summarizes supported font and line-height graph demands of an already admitted specified value. Dispatch follows the actual admitted component, including each member of a space- or comma-separated list. It does not inspect descriptor alternatives or original substitution tokens. Every member must be supported; one unsupported member returns `None`, not a partial summary.

The six changed paths are `properties_and_values/value.rs` and specified `number.rs`, `angle.rs`, `time.rs`, `resolution.rs`, and `percentage.rs`. Five small `as_calc()` accessors borrow retained trees for Integer, Angle, Time, Resolution, and Percentage. Number already has its accessor. These do not evaluate a scalar, clamp, round, parse, mutate, or construct a computed value. The ordinary `ToComputedValue` implementations remain byte-identical.

Supported component kinds are Number, Integer, Angle, Time, Resolution, Percentage, CustomIdent, and String. Inline numeric values and admitted identifier/string literals contribute no modeled graph demand. Length, LengthPercentage, Color, Image, Url, TransformFunction, TransformList and Universal remain unsupported. This deliberately does not claim a complete context inventory for those types. An alternative accepting a Color component returns `None`; the caller must preserve the descriptor's implicit COLOR_SCHEME dependency. The proposed preparation caller conservatively preserves that intrinsic requirement even when the admitted component is supported.

The numeric visitor preserves the original number proposal's exhaustive operation dispatch: unary children (including inverse), all variadic operands, all binary operands, all three ternary operands, and an optional logarithm base are visited. Unsupported/dynamic nodes propagate `None`. Current font, current line-height, root font and root line-height unit flags are unchanged. Absolute lengths contribute no font/line-height graph demand, but can still read zoom during computation; `Some(empty)` never means no context reads or effects of any kind. Viewport/container units remain unsupported and require the caller's conservative fallback.

A percentage leaf is accepted only with `Optional::Some(NumericBaseType::Percent)`. Captured `CalcNode::parse_percentage` admits percentages with this hint, and `Leaf::canonical_value` treats this hint as a dimension independent of a percentage basis. Other hints and missing hints return `None`. This preserves the pure percentage scalar path while refusing to erase a possible contextual basis. The collector does not change number grammar to admit percentage arithmetic. In the saved breadth observation, the percentage-provider-to-number literal conversion itself fell back to consumer initial 7; those descendants cannot serve as calibrated normative failures.

Ordinary numeric computation remains unchanged: Angle normalizes non-finite results; Integer resolves then rounds; Time normalizes/clamps; Resolution retains non-negative handling; Percentage retains normalization/clamping. Borrowing their trees neither performs nor substitutes these operations. The visitor sees the parser's retained, simplified AST, not the lexical expression before simplification.

Integration policy A (the current proposed repair) refines an already scheduled graph dependency: keep the existing scheduling prefilter and intersect existing references with the admitted summary, or with conservative selected-substitution flags when this collector returns `None`, preserving intrinsic COLOR_SCHEME. This cannot create missing direct numeric edges or settle the disputed self-font cycle policy. Policy B would additionally schedule previously omitted numeric dependencies and is a separate unaccepted workstream. This collector can support either caller policy but implements neither policy itself.

The preparation layer must still own selected substitution, real whole-value grammar admission, provider readiness, CSS-wide/defaulting behavior, attribute taint and effects. Cached specified values must not be computed or published before SCC settlement; pending provider/prioritary states are not invalid values. No claim is made that the collector proves these caller obligations or that early URL/image parsing is effect-free.

Since the collector owns no prototype-specific API, the same six-file patch can serve head/live variants only when their corresponding original bodies match these roles.

Owned temporary outputs were removed. These checks establish transport and syntax/format only, not Rust name/type/lifetime checking. No browser, build, real index, object database, native working source, or canonical model was modified.

Formal correspondence remains manual. The sealed number context-summary model proves arbitrary finite AST union/unknown propagation and catches omitted operands, but does not yet model this outer admitted-component/list layer or the newly supported Percent-hint leaf classification. It is a useful refinement obligation, not a proof of this Rust implementation. No CSS parser, numeric evaluation, SCC, DOM invalidation, or self-font theorem is claimed.

Useful native/WPT checks for integration are: each scalar with a ready primary and unused incompatible fallback; selected invalid fallback with actual registered defaulting; alternatives in both orders; later list-member math; an unsupported list member preventing refinement; pure percentage math with fixed font; and fixed-font inverse/line-height/root-font controls. Browser-observed direct numeric scheduling failures must remain distinct from refinement-only A's acceptance gate.
