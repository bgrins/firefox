# Contextual CSS easing: experimental activation

This opens the specified easing parser after the representation, computation, selected-scope and dependency handoff. It is a browser-experiment proposal, not a complete implementation or accepted fix. All eight source roles derive from scope-v3; only specified/easing.rs changes. Generic calc (accepted 145), historical infinite-step handling (144), and the current failed-tree-reference result of one are untouched. No live source, index, epoch, build or browser changes occur here.

The activation removes unresolved-input rejection for steps counts, cubic-bezier coordinates and linear outputs/both positions. Literal range checks remain: cubic-bezier x literals must be in range, positive step literals remain positive, jump-none literal one remains invalid, and linear needs two authored stops. Existing contextual computation applies ranges and uses the same linear builder. Known linear values retain Resolved storage and canonical serialization. The old linear unwrap path is not reopened: both positions are owned AST values computed before the builder sees them.

CSS properties use their computation context. The context-free Gecko API entry Servo_ParseEasing still calls try_to_computed_value_without_context and returns false before assigning output if unresolved. This preserves current API rejection; it does not resolve CSSWG14246 or invent a default element context. The shared parser is activated without arbitrary syntax or type exceptions. Searchfox caller audit faa8ab identifies the migrated easing keyframe calls and FFI; unrelated filter/range methods with that suffix are not easing consumers. Servo-only compilation and API integration require separate validation.

## Dependency path and concrete experiment

KeyframesAnimation classifies directly typed contextual timing declarations. During the owning unvisited cascade, the selected keyframes/scope is temporarily installed and actual conversion records dependencies on that style before build. Conversion marks cache conditions uncacheable; the final cascade publishes tree-counting selector flags. A normal restyle with selected contextual keyframes requests animation reconstruction. Existing ForCSSRuleChanges requests reconstruction even if the newly selected rule becomes literal. This is source reasoning, not proof of complete invalidation: sharing bypasses, animation-only updates and effect reconstruction require observation.

The twelve-case lifecycle fixture tests five forms on both a CSS property and keyframe declaration: sibling-index steps, sibling-count steps, bezier y, linear output and linear second input. The count-only cases append/remove after the target, keeping its index fixed; the other cases prepend/remove. Only siblings change during those samples; no contextual ordinary property on the target can independently cause sibling invalidation. Each test preserves a paused CSS animation and compares sampled opacity with an independent literal-only animation. A selected-rule test starts literal, changes to contextual, mutates siblings, returns to literal and mutates again. A host-font test changes inherited font while opacity is animated, keeping that contextual input unanimated in this deliberately non-self-dependent case. Numerical assertions follow all snapshots. The exact four corrected scope tests from scope-v3 form the second page: sixteen tests total. They cannot prove exact root identity beyond saturation or repair declaring-root selection.

Variable-bearing keyframe timing declarations are an existing unsupported path (bug 1710735): KeyframesStep::new marks the typed variant only, and get_declared_property explicitly discards WithVariables. The current computation path does not use that skipped value, so this is not a newly demonstrated dependency omission. Adding a flag alone cannot establish variable or attr() substitution; the selected declaration must first be resolved in its owning context. Existing variable-easing coverage remains a known boundary/control, without discovery credit.

## Remaining boundaries

The supplied style for keyframe computation is not assumed to be unanimated. These tests avoid animating the contextual input; they cannot settle feedback or animation-only semantics. Host/root/viewport/container changes, rule replacement across tree roots, style sharing, transitions, range endpoints, inherited custom values, Servo configuration and context-free Web Animations policy remain obligations. No rejection whitelist or silent unsupported skip is introduced. The broader Round/ModRem canonical-readiness proposals remain held and are not merged into this experiment.
