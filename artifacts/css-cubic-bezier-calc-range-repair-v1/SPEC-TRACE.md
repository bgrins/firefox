# Range decision

Scenario: a well-typed, context-free numeric function in x1 or x2 of cubic-bezier(), exposed through CSS animation/transition timing functions or Web Animations timing/keyframe easing. Parsing a font-/element-dependent calculation is outside this proposal.

1. [CSS Easing cubic-bezier grammar](https://drafts.csswg.org/css-easing-1/#cubic-bezier-easing-functions) gives each x coordinate the explicit `<number [0,1]>` production; y coordinates are unrestricted numbers. The ordinary invalid-range sentence rejects out-of-range literals. It does not remove numeric-function evaluation rules.
2. [CSS Values numeric ranges](https://drafts.csswg.org/css-values-4/#numeric-ranges) supplies the allowed range. [Numeric functions](https://drafts.csswg.org/css-values-4/#numeric-function) distinguish direct out-of-range literals from functions: out-of-range numeric functions are clamped at computation when possible, rather than invalidating the declaration. [Range checking](https://drafts.csswg.org/css-values-4/#calc-range) applies this to the top-level calculation. This case has no contextual dependency preventing computation.
3. [NaN/type checking](https://drafts.csswg.org/css-values-4/#calc-type-checking) censors a top-level NaN to zero and clamps infinities to the context's bounds. Thus x=calc(NaN) produces 0, x=calc(-infinity) produces 0, and x=calc(infinity) produces 1. Finite calc(-2) and calc(2) produce the same endpoints; literal -2 and 2 remain invalid. The x range does not constrain y.
4. [WAAPI effect easing](https://drafts.csswg.org/web-animations-1/#dom-effecttiming-easing), [timing updates](https://drafts.csswg.org/web-animations-1/#update-the-timing-properties-of-an-animation-effect), and [keyframe processing](https://drafts.csswg.org/web-animations-1/#process-a-keyframes-argument) consume the easing grammar. Invalid literal syntax still raises TypeError through these APIs; a valid resolved numeric-function easing should reach timing evaluation. The fixture tests targetless effects without inventing an element/font context.
5. [Cubic-bezier output](https://drafts.csswg.org/css-easing-1/#cubic-bezier-algo) maps x to y on the curve. The fixture uses known curve points and calibrated literal counterparts, rather than treating acceptance alone as successful computation.

**REACHED:** valid context-free calculated x values are clamped to [0,1]; rejecting them solely because their resolved x lies outside that range conflicts with the current numeric-function rules. The existing Easing invalid-range sentence and unresolved-context branch are not alternative routes permitting that rejection.
