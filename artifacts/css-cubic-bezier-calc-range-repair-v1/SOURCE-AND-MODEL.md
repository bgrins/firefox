# Source contracts and proof reuse

The native preimage is pinned independently of the currently applied steps candidate. Searchfox discovery located Number::resolve; exact local contracts were then read from immutable Git objects at cc19dbffcfd2acad251c4bebe44d6ed3e36ab8da and retained in evidence/. This avoids attributing current live build bodies to the restored baseline.

`parse_number_with_clamping_mode` puts literal number tokens inline and math-function results in boxed CalcNumeric storage, even when their numerical value is known. `Number::get` returns Some only for the inline representation. `Number::resolve` resolves either representation and uses `NoCalcNumber::get`; the latter calls `values::normalize` (NaN to zero), then bounds infinities to f32::MIN/MAX. `CalcNumeric::as_number` returns the resolved number leaf. Consequently the new f32::clamp never receives NaN from a successful resolve, and infinities already converted to extreme finite values clamp to 0/1. This is a source-contract argument, not an executed native test.

The parser still requires all four resolve calls to succeed. Only its x-range check switches to get(), so a calculated operand does not accidentally exempt an invalid literal in the other coordinate. Conversion adds clamp(0,1) to x1/x2 only. Valid literals already lie in range, so applying the clamp there is identity. y conversion and Number/CalcNumeric storage, normalization, serialization and range policies are unchanged. Keeping specified storage untouched preserves calc provenance and specified serialization. CSS's ToComputedValue delegates to the same context-free conversion used by WAAPI. The patch neither invents context nor drops the unresolved rejection/unwrap invariant.

Reuse existing canonical `CssNumericClipping.clip_bounded`, `clip_fixed`, `clip_idempotent`, `CssNumericCensorship.complete_nan`, and `CssNumericFinalization.finish_bounded` / `finish_real_fixed` at real number bounds [0,1]. These supply range, identity, censorship and finalization laws. Their Rat/extended-scalar assumptions do not prove Rust f32 evaluation, parser provenance, native API wiring or Bézier inversion. The steps companion explains origin-sensitive admission but its integer minimum theorem is not a real-number theorem and is not copied here. No new Lean module, execution, audit count or coverage credit is introduced.

Source coupling: this touches the same easing.rs as steps, but different parser and conversion arms. The explicit after-steps route preserves every steps-v2 change and adds only the same cubic delta. Numeric infrastructure fixes already present at the recorded base remain prerequisites of the tested environment; no clean-upstream independence is asserted. Context-dependent x/y, sibling-index(), relative-length sign(), and non-finite-y animation behavior are not enabled or newly claimed.
