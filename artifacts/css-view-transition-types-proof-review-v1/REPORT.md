## Substantive review

I read all six semantic modules, Audit/CalibrationDriver, the complete checker/extractor/calibrator/compiler and native harness, all 25 retained complete source bindings, and the accepted native/browser provenance. The initializer scans seen keys while retaining first occurrences in vector order; its independent reference skips already-seen source values. The mutation proof relates native first-occurrence deletion to independent all-equal filtering using established uniqueness. Lazy materialization preserves native state and initializes an ordered unique backing list. Arbitrary finite successful Add/Delete/Clear/Observe histories preserve agreement and exact modeled return tags/identity. Observe's reply constructor is a tag, not an embedded value list: public contents are justified separately at every finite prefix by the invariant. The independent every_finite_prefix theorem makes that connection explicit.

The stable intern model represents exact value identity, not an immortal address. The separate LiveAtoms model permits different atom generations for the same text after deletion. Its current-live canonicality premise is materially necessary: deleting value 0 with a second equal-text atom 2 while atom 0 remains owned leaves the native entry behind. The independent counterexample and rejection of Canonical expose that boundary. Our additional admitted history deletes/recreates the same text twice (atoms 0, 2, 4). These are abstract generation identities; reuse of a physical address for different text must be represented by different generations, with immutable text and no live aliasing admitted from the actual provider.

Exact identity is UTF-16 code-unit equality. Independent kernel examples distinguish composed/decomposed spelling, NUL/empty strings and isolated high/low surrogates. These validate storage-domain semantics, not validity of those strings as parsed CSS selectors. The native Equals body uses length plus memcmp; actual atom table/caches, refcounting, JS Set conversion/realms and weak-key lifetime are inspected provider contracts, not compiled or verified implementations here.

Weak-key ownership theorems establish that a key is represented by a vector entry at the loop boundary or by the current local/vector during insertion. They do not prove allocation, destruction, GC, hashing or C++ move semantics. The source holds each inserted atom in a RefPtr until it moves into the vector; live canonicality and ownership are credible conditional admissions. The C++ facade uses shared_ptr/weak_ptr, vector, a collision-heavy unordered_set, successful JS-like helpers and simplified string/document providers. Count-based EnsureInserted and the selected initialization/mutation/bridge bodies are actual retained control flow. Full startup lifecycle, JS helpers and atom providers are bound/read but not fully executed.

Direct selector refinement requires the queried owner document, current active transition identity, installed current type vector, root/state relation and valid names. Those are explicit premises rather than inferred from a final matching answer. Independent examples show that having an active identity without installing the current vector is insufficient, and that an arbitrary cached style result can stay stale despite a correct current match. The separate reproduced mutation-invalidation bug therefore remains compatible with this acceptance. No cached computed-style or completed-transition mutation claim is accepted here.
