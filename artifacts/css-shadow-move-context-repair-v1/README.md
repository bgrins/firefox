# Preserve move context across owned shadow trees

This uncompiled three-file proposal propagates the existing move flag through `ShadowRoot::Bind` and `ShadowRoot::Unbind`. It is separate from the successfully paired PresShell/RestyleManager old-parent invalidation repair. No native acceptance, fix count, or formal coverage is allocated.

`Element::UnbindFromTree` forwards its context to light children but calls `shadowRoot->Unbind()` without it. That method creates a fresh shadow-root context with `IsMove()==false`. Shadow descendants consequently execute ordinary removal behavior, including `ClearAllAnimationCollections()`. On binding, the analogous fresh context selects connected callbacks rather than connected-move callbacks. Nested shadow roots repeat the loss. Source investigation used Searchfox definitions/callers (d3eac8,22400b,f9e58c,0fc554,4df003,b296cf,d5472f); immutable local excerpts and Git object hashes are retained here.

The patch forwards only `aContext.IsMove()` at the two Element call sites. ShadowRoot still constructs its own contexts: the unbind root remains the shadow root, its original-parent and document facts remain unchanged, and `BindContext(ShadowRoot&)` retains `SubtreeRootChanges()==false`. This avoids incorrectly treating a shadow child as the outer moved root. Default false preserves constructor attachment, FragmentOrElement destruction/unlink, and ShadowRoot unattachment callers. No root/frame clearing or notification ordering is changed.

Root's system Firefox 158 observations distinguish the defect from animation setup: root/light-child animations survive self-reference, original-gap and cross-parent moves, while shadow-child CSS animations are canceled/replaced; no-move and settled paused controls pass. Root also observed incorrect disconnected/connected callbacks for shadow and nested-shadow custom elements defining connectedMoveCallback. Adopted stylesheet controls reportedly corroborate the animation result. OBSERVATION-PINS.json pins the six primary script/result files used here; these are root-run system observations, not a local candidate result. Frame-loader, dialog, popover, fullscreen and other IsMove-dependent behavior remain source-derived implications, not observed repairs.

This is not an entirely new family: upstream `custom-element-move-reactions.html` already contains `connectedMove runs when custom element is nested within a shadow root`, with expected FAIL metadata. A future pair must retain that test as an improvement target. The earlier 70-case pair tested root animation identity and child width, not shadow descendant CSSAnimation identity. The inspected cross-shadow transition test moves the animated element across scopes; it does not cover a stable internal shadow tree carried with its host. Bounded searches do not establish exhaustive bug-history novelty.
