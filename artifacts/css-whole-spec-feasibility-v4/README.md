# Whole-CSS Lean implementation plan

Three agents extended the previous research with small executable prototypes
and an independent validation plan. Root read their reports and prototype
implementations, authenticated the delivered files, and replayed the inventory
demo and Lean component. These results do not establish additional CSS clause
coverage or Firefox conformance.

| Workstream | Concrete result | Remaining boundary |
| --- | --- | --- |
| [Inventory](inventory/REPORT.md) | SQLite schema, four source-bound examples, ten rejected structural challenges | Complete source acquisition/partition, reviewed clause extraction, genuine proof certificates |
| [Semantics](semantics/REPORT.md) | Compiled read-episode protocol; two synthetic clients; 13 theorem checks and four execution traces | Derive actual CSS requests, providers, episode boundaries and termination from normative algorithms |
| [Validation](validation/REPORT.md) | Standalone package design, independent observer challenge and real spec-change rehearsal | Execute a composed CSS pilot and independently validate its interpretation |

## What covering all CSS requires

Maintain a versioned normative universe, including surviving older rules,
errors, allowed UA choices, dynamic behavior and HTML/SVG/font dependencies.
For each requirement, distinguish three claims: a faithful mathematical model,
an executable reference proved to implement it, and a particular browser proved
to conform. Unsupported cases and unresolved assumptions remain visible.

The main technical difficulty is composition. Styling, layout, text, painting,
animation and host APIs must agree on identities, phases, permitted samples,
numeric behavior and persistent choices. Proving independent helpers cannot
establish those agreements. A browser's CSS behavior spans much more than Stylo.

The prototype demonstrates one useful interface: when two immutable providers
agree on all requests actually made by a finite plan, both its result and its
request trace are preserved. Its synthetic clients distinguish intrinsic from
used sizing and prescribed samples from newer state. It does not derive any
actual CSS caller or make a lifecycle correctness claim.

## Recommended implementation sequence

1. Make the library portable, with separate profiles, semantics, reference
   algorithms, independent contracts, validation and optional Gecko adapters.
2. Build a real source importer and reviewed requirement partitions for three
   contrasting sections: fragmentation, HTML style-block updates and font
   cluster matching. Bind selected clauses to actual Lean declarations; leave
   the rest explicitly open.
3. Close one existing custom-property-to-URL observation path. The current
   repairs supply concrete counterexamples, but parsing, metadata, substitution,
   retained state and browser scheduling still need composition proofs.
4. Implement a genuine two-consumer sizing interface and a host sampling
   protocol. Derive phase, owner and history keys from CSS requirements instead
   of supplying them as convenient inputs.
5. Rehearse a real spec change. The validation report compares the 2025 Overflow
   draft's mixed-axis normalization with the current single-axis scroll-container
   rules. A successful migration must invalidate affected interfaces and
   consumers even when old Lean files still compile.
6. Expand by spec family only after measuring interpretation, integration and
   independent review effort on these pilots. Do not estimate completion from
   theorem counts or property counts.

The clipping/scrolling challenge illustrates the review standard: a model can
correctly prove identical clipping for hidden and clip while omitting the
different scrollTop behavior. Independently chosen observations are needed to
detect that omission. The example is a proposed spec scenario, not a newly
executed browser test or bug report.

## Evidence and limits

[ROOT-REVIEW.json](ROOT-REVIEW.json) records root replay commands and artifact
identities. The inventory's positive case is synthetic; its CSS sample remains
blocked. The semantic theorems concern generic read episodes; caller admission,
state changes, foreign providers and native refinement remain open. Validation
reviewed captured peer drafts and did not independently execute them; root ran
the final producer prototypes separately.

This is a plausible sustained research program and a useful standalone artifact
can emerge early. There is no defensible whole-CSS completion percentage or
schedule from the present evidence.
