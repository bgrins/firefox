# Scope and specification mapping

ProviderObservation is generic transition/observation infrastructure. It has no normative CSS algorithm mapping and receives no additional CSS coverage credit. The module imports only CssSemantics.TransitionMachine, whose run function remains the history runner. No Firefox frame type, Subtree/Hidden adapter, browser fixture, filesystem path or CSSOM-specific type is imported by the core.

A query conditionally forces a provider, obtains the resulting world, and resolves a stable target in that world. Successful-state and successful-observation results relate the returned world and value to these actual steps. Observation erasure maps only values/logs and preserves the complete world and Option outcome through histories. Mutation/admission/force operate on world/event rather than observation logs. Stable identity is a caller-side lifetime assumption; the generic Target type alone cannot prevent reuse. Option failure has no successful returned state and does not prove native rollback or specify a CSSOM empty rectangle.

The prospective CSSOM mapping must separately instantiate box/rectangle observation, coordinate spaces, fragmentation, transforms, scrolling and rounding against their specification algorithms. Hidden-content forcing and layout readiness also require a provider/scheduling correspondence. None is supplied merely by importing this module. The earlier MathML example distinguishes [70,25,40,16] from [30,10,40,16], but its ancestor-coordinate update is stipulated arithmetic, not an implementation or specification proof.

The Gecko-specific marking/readiness example and horizontal-only Hidden.Size adapter remain outside the standalone core. EVIDENCE-LINKAGE.json preserves the authenticated historical example, rejected selected-size-only/pre-force adapters and independent replay. Those external files are provenance/validation links, not dependencies of this portable import audit. This replay does not rerun those negative controls or silently count them as new library theorems.

Integration is additive: the existing central CssSemantics.lean aggregator, check.py, coverage.json, toolchain/package files and previously present modules remain unchanged. Direct `import CssSemantics.ProviderObservation` is supported. A later authorized inventory update can register this module and audits in the central runner/aggregator; it must refresh affected pins deliberately. Any downstream observation adapter needs its own specification mapping and refinement evidence before changing coverage claims.
