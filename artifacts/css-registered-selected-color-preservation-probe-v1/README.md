# Selected-color parser and dependency preservation

This separate WPT page has 23 callbacks, each with a fresh iframe and property registry. It leaves the sealed five-case identifier reproducer unchanged. Together they form 28 callbacks on two pages, 30 callback/end signatures and four resources including the shared harness files. There is no execution owner, live-state binding, private POST, native installation, or browser result in this package.

The page exercises actual registration parsing and computation: both orders of the ambiguous CanvasText union, absolute colors, current-color literal equivalence, space/comma repetition, gradient and image-set colors, relative image lengths, a selected typed-attr length, an inherited computed image, selected/unused var and typed-attr fallbacks, CSS-wide selections, and invalid defaults. Each case changes the target's requested scheme from dark to light and reads the target custom property before any diagnostic or reference getter. Font size and line height also change; image references use matching literal metrics. The inherited-image reference retains the parent's light scheme and 12px/24px metrics rather than recomputing the value with the child's inputs.

System colors are compared with ordinary `color: CanvasText` controls under the same literal scheme, never a hard-coded platform palette. Images are compared with ordinary background-image controls. The typed-attr length control uses a literal 2em image rather than the same attr expression on both sides. Typed attr has a separate ordinary-color support calibration. List expectations join independently computed ordinary color components with the relevant serializer separator. CurrentColor compares the two registered literal computations; its serialized spelling is recorded rather than given a new resolution oracle.

The first-matching union expectation, computed component/list relationships, and normal invalid/inherited/initial relationships are grounded in the linked Properties and Values rules. The precise source-supported computation-order preservation cases are explicitly marked `conditionalPreservation`: System and light-dark initial values must actually register, then the target selects its invalid-value path while a valid registered expression and ordinary literal color serve as controls. The absent var name changes with the scheme to force a declaration change. These two cases test the existing clean handler's recomputation contract; they do not establish a general normative permission to register every context-dependent initial value or a new ruling about initial-value timing. They remain research fixtures unless a separate spec trace supports landing those assertions. Registration rejection is a setup failure, not a fabricated default result.

The additional identifier-initial case uses a valid, independent `light` initial in `<custom-ident> | <color>`. Its invalid value changes between absent var names while color-scheme consumes the registered value. The parent scheme is explicitly normal, so a mistaken cycle cannot pass by inheriting light. This distinguishes selecting the initial identifier from retaining a coarse color-union edge for every invalid value.

Every completed row contains both phases, expected/reference values, actual scheme, input syntax and attr calibration, and is exported in `window.selectedColorPreservationObservations` before numerical/string assertions. Failure messages contain the whole row. Registration or frame/setup failure can prevent a row. Successful WPT callbacks do not themselves transport this object; an observer may read it separately. There are no animation, taint-policy, cancellation, timing-pass or internal-route assertions.

Actual saved check `f596a0`, exit 0, registers the 23 names inertly, runs path/content lint with zero errors, authenticates exact shared harness bytes, and generates the genuine manifest without a Git repository scan. This does not execute CSS or validate native parser behavior. Original and candidate outcomes remain unobserved here, and any existing baseline failures must be retained and triaged rather than rewritten as expected success.
