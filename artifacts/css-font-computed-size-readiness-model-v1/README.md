# Computed-size reply and retention protocol

This Lean model checks the proposed boundary between a computed-size result and completion of a FontSize node. It is an implementation-protocol model, not new CSS specification coverage or a refinement proof for the native producer. The sealed dynamic-prerequisite source still lacks this protocol. The separate computed-size producer is being implemented and must establish the correspondence independently.

`step` separates semantic closure, size publication and ordinary completion. Only a closed node with no prior size application can publish the supplied size. That transition retains its identity and leaves ordinary completion pending. `read` admits the resulting reply only for the exact Unit/ComputedSize purpose and token; ordinary, generic-reference and stronger metric demands wait. Finishing ordinary work retains the value and application count. A settled semantic cycle cannot subsequently publish a size facet.

`arbitrary_trace_applies_at_most_once` and `arbitrary_trace_retains_identity` cover every finite accepted action sequence, not just the three-step example. `run` stops at a rejected transition; it is not a model of a native caller that ignores failures or mutates state outside these transitions. The supplied computed size is assumed final, and semantic closure and ordinary-finish actions are assumed authorized. Correct native conversion, input finality, selected declarations, eligibility, rollback, zoom, unzoom ordering and proof that ordinary prerequisites actually finished remain outside this model.

`Session.retained` models the nodes that must remain owned while their ordinary work is pending. Reset rejects a retained partial, open or closed node. A terminal session can advance its generation, and an old token cannot read a newly allocated node at the same index. This does not prove native frame movement, queue uniqueness, token allocation, index-map consistency or lifetime safety. Session lists can structurally contain duplicate tokens; native allocation must rule that out. The token's selection and context fields model identities whose validity the native code must establish, not a computed readset analysis.

A whole FontSize node returns its ordinary Complete reply even to a stronger consumer. That completes only this node: the separate font-metric aggregate must still require final family, weight, orientation and other inputs. The model does not certify that aggregate or prove progress for the raw attribute → registered length → font-size fixture. It also supplies no policy for genuine CSS cycles or scheduling cycles.

Final `run5` checks 25 theorems and six false controls with Lean 4.35.0-rc4. The controls reject ordinary and metric use of a size-only result, publication before semantic closure, reset with a retained pending node, duplicate size application, and authentication by index alone across sessions. Rejection must be an actual `decide` proof that the proposition is false, not a parse or import failure. The axiom audit rejects `sorryAx` and `Lean.ofReduceBool`. All replay scratch directories are removed.

`run1` records a reserved-identifier syntax error; `run2` passed the initial nineteen-theorem version. `run3` and `run4` preserve unfinished proofs of the added generic trace invariants. These failures are not counted as false-control successes. The final theorem source and replay inputs are pinned in `CHECK.json`.
