## Output-checker weaknesses reported before seal

The draft check_rows.py parses rows strictly but regex-extracts importance and membership fragments. Appending nondigit garbage to a set field or garbage after bits is silently ignored. Gate int conversion accepts 2 as true; extra tab fields are ignored. Unique row names are checked but not a closed expected roster. Actions come from native text and expected values are recomputed from those same actions. Golden raw equality protects subsequent replay but cannot independently validate a self-consistently mistaken initial receipt.

Producer has agreed to add whole-field/field-count parsers, exact case/action/initial-state fixtures generated independently, and targeted malformed/corrupt output challenges. Full successful variants must match the complete ordered roster. A mutation that exits 42 on broken representation may instead match an exact prefix ending in a representation failure. Final authenticated bytes still require independent review and challenge execution.

No native source defect or Lean soundness blocker was found from these concerns; they are evidence-validator admission issues. Final acceptance is pending their resolution and fresh replay.
