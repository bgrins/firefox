This successor isolates the frozen browser candidate `25e8a27a` / provider `90acb505`. It adds one best-effort diagnostic immediately before the existing `Complete | CycleSettled` terminal assertion. The assertion, unsupported branches, semantic traversal, scheduling and ownership behavior remain unchanged. It does not include ordinary-ownership successor `49c74e5a` and is not a repair.

The last already-computed `drive_metric_action` result is retained in a local Option only when that result terminates the loop. No call is repeated. The snapshot records the retained root/result/reply, action token/property, selected-reference Arc/cursor, node publication states, and ordinary ensured versus cascade/ledger completion. Static generated dependency membership and the existing conservative dynamic-declaration predicate explain uncertified prerequisites; these inspect declarations without semantic traversal, substitution or numeric computation. There is no declaration text or attribute-value dump. Custom/attribute identifiers and process-local pointer identities can appear; pointers are not persistent object identities.

Frames are bounded to the last 16, with the root separately recorded. The first 16 nodes and the exact pending-result node are shown, so a deep pending node is not hidden by the prefix limit. The first 16 semantic stack indices are shown with total counts. Priority sets are bounded by the existing generated enum. Every write result is ignored; ordinary I/O errors cannot replace the original assertion. Formatting, allocation and stderr locking add diagnostic overhead. This is not an assertion that logging has no timing or resource effects.

`check.py` reconstructs the exact parent after removing the helper and reversing only the progress-local/callsite insertion. Provider bytes are identical. The full two-file patch is relative to the existing published base; `PARENT-DELTA.patch` isolates the diagnostic change. No enabled owner, current binding or execution wrapper is added.
