## New pseudo-element case

A fresh iframe contains an unanimated host with unregistered `--font: 16px`. Its generated `::before` inherits that value and uses `font-size: var(--font)`. Two CSS animations on the pseudo are acquired through `host.getAnimations({subtree: true})`: a constant 32 px font animation with fixed 2000 ms duration and an opacity animation with `calc(1em / 16px * 1s)` duration. Both are ready, paused and explicitly held at 750 ms. The initial rendered font is calibrated as 32 px; no initial opacity or contextual-duration numeric expectation selects an own-effect timing policy.

The test sets the **host** variable to 32 px. Its first subsequent operation is `getComputedStyle(host, "::before").opacity`, before any timing or animation-membership query. Retained effect timing and current membership are then collected. Final authored base and animated font inputs are both 32 px, so duration is 2000 ms and the linear 0→1 opacity is .375 at 750 ms. The test requires both animation/effect identities, both current times and paused states to remain unchanged, and exactly two animations to remain current.

No script override applies to this new positive case. It exercises host-to-pseudo inherited input invalidation, complementing the pseudo ownership and unchanged-input controls. The custom property is not registered or animated; no cycle or registered interpolation is introduced.

Timing and membership are later sequential observations, not an atomic first-opacity snapshot.
