- SVG2, Types §4.5.2, value getter and convertToSpecifiedUnits: https://svgwg.org/svg2-draft/types.html#InterfaceSVGLength . The getter converts the stored value to absolute/user units. The associated-element percentage and font bases do not themselves specify the child CSS viewport update algorithm for vw. This probe uses a parsed viewport length, not an SVG percentage.
- CSS Values4, Editor’s Draft24August2026, §6.1.2: https://drafts.csswg.org/css-values-4/#viewport-relative-lengths . Viewport-relative lengths depend on the initial containing block, and scale when its size changes. With a400px child viewport,10vw is40px; with200px it is20px. No dynamic browser UI or scrollbar-reservation change is involved.
- CSS Containment2, Editor’s Draft15October2026, §4 and §4.5 item7: https://drafts.csswg.org/css-contain-2/#content-visibility . Skipped contents receive containment, are not painted/hit-tested, and layout/rendering work should be avoided. The iframe event loop's rendering update should be skipped where possible. §4.2 and §4.7 give informative examples of synchronous geometry queries requiring pending work. They support investigation but are not a complete normative SVGLength→hidden iframe viewport algorithm trace. No exemption explicitly freezing SVGLength was found in these sections; absence of such text is not a proof that every possible read synchronously resizes a hidden child viewport.
