# Startup through a font-size dependency chain

This unexecuted four-case diagnostic extends the single-late target-restyle fixture. At total depths 2 and 4 (root is depth 0), the first child has paused constant `font-size: 2rem` keyframes and each subsequent nested descendant has paused constant `font-size: 2em` keyframes. Every descendant has an ordinary 11px font size, and all nodes exist and are individually styled before animation startup. The animated-root case is pre-styled at 23px then starts paused constant 32px keyframes with the children. The literal-root comparator is pre-styled at 32px and starts only the child chain.

Literal-root cases are **not presumed passing**: starting the child font animations can itself change the basis of deeper em endpoints. The numeric expected value at level n is `32 * 2**n` (leaf 128px at depth 2 and 512px at depth 4). Expected values and measured strings are recorded separately. This distinguishes first-child root-relative dependence from later inherited-font dependence. No callback counts native passes, proves hint delivery, or establishes a new regression before actual baseline evidence.

Each fresh standards iframe follows this order:

1. Read pre-start root and every node's font size; check that all animation lists are empty. All ordinary node sizes must be 11px.
2. Add the activation class, then immediately read only the leaf's font size.
3. Await exactly two animation frames, then read chain nodes from leaf to first child. The leaf is therefore also the first settled getter. These reads may flush work; the array is an ordered series, not an atomic snapshot.
4. Read the root and independent ordinary 2rem sibling, then record another leaf-to-first-child series. Only after these observations enumerate animations and record count, target, CSSAnimation type, name, paused state and progress.
5. Preserve the observations, add only the inherited fixture's non-font background class to the leaf, immediately read the leaf, then record a further leaf-to-first-child series. Compare the already captured CSSAnimation and KeyframeEffect objects with the post-restyle objects. These identity checks cover only this later restyle interval; they do not prove object identity during startup. Record background/root/plain controls and post-restyle timing.

`styleReadOrder` records every explicit computed-style read with phase, node level, property and value. Animation enumeration/timing reads occur at the two explicit post-observation locations in the source; they are not included as computed-style rows. No root getter or animation enumeration is inserted between activation and the first/settled node readings. The root and plain controls must be 32px/64px. All data, including the later restyle result, are stored before any assertions. The original first/settled numerical expectations are retained for each relevant node; failures do not prevent the stored diagnostic from being extracted. No assertion assumes the non-font restyle repairs the chain.
