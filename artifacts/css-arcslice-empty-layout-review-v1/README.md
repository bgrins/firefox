# Empty ArcSlice representation review

Scoped review is clear. All 250 witness payloads and twelve logs authenticate: four ordinary successes, four debug-assertion panics before transmutation, and four debug-off dev-profile Miri invalid-reference failures after construction (Default/empty iterator, read/drop-only). The bad reference is the complete ArcInner<HeaderSlice<u64,High>> beyond its allocation. No optimized release execution or browser caller is established. The driver checks cfg!(debug_assertions); ignore-leaks does not suppress reference validity checks. Its checker classifies the four debug-off outcomes rather than asserting they are UB; this review independently checks all four actual exits and intended diagnostics.

Root's 28603b/0 read establishes committed a6 servo_arc equals6fb0d158; locally changed in the predecessor prose does not mean uncommitted. LIBRARY-DELTA.patch compares historical pinned39639576 with6fb. Only ArcUnionBorrowPtr and its tests were added; erasing them reconstructs396 exactly. HeaderSlice, ArcInner, constructor, inner/static/drop and thin alias definitions are unchanged. The witness never invokes the added API, so those local changes are not causal. This is not a fresh run on a separately established upstream checkout or a newly demonstrated browser bug.

## Sufficient singleton reuse invariant

For actual allocation A and destination representation V(T,0), require valid allocation provenance/lifetime; valid initialized refcount/canary/zero stored length; identical source/destination addresses for every refcount/header/length field; destination alignment satisfied at the allocation start; and the entire destination referent footprint contained in A, including padding required by typed references. A lucky aligned address is insufficient. The derived empty-tail pointer must also be non-null/aligned under the destination layout. Tail offsets need not be equal for length zero when both derived pointers are valid; no T value is read or dropped.

The static sentinel must prohibit mutation, uniqueness/mutable access and deallocation. If storage is non-static, eventual deallocation additionally requires the original allocator Layout: extent containment alone is insufficient. These are explicit provider obligations, not a new kernel/native theorem. The fixed repr(C) fields permit a normal-alignment compatibility argument, but that argument must cover fields and complete extent. Over-alignment can shift the outer data/length offsets and enlarge the referent. Aligning the old-sized singleton more strongly does not repair it; true-DST code must not read the new destination length offset from that old allocation either.

## Repair choice

Preserve the compatible singleton fast path and allocate a correctly laid-out typed empty ThinArc otherwise. This keeps the one-word owner and valid generic Rust callers. Calling ArcSlice::from_iter(empty) as fallback would recurse into Default. Leaking every fallback or adding TypeId caching/'static constraints is unnecessary. An unconditional panic is a safety stop but unnecessarily narrows the requested semantics.

Both current6fb and final DST reject all zero-sized tails. Permit ZST construction only when requested length is zero (or use a dedicated empty constructor); retain nonempty refusal. Empty values need no element destructor, but alignment and header extent still matter. Root authorized that bounded allowance, including over-aligned empty ZST callers.

The C++ static-empty export has no T-layout argument. Existing compatible concrete tails can retain the ABI with compile-time representation guards; arbitrary over-aligned C++ support would need a typed/layout-aware allocation route. The full generated-header probe covers nine distinct concrete C++ tail types, but the broader Rust inventory also includes ContainerCondition, generated text-shadow and generic adapters. It is not a universal restriction. Candidate runtime checks belong to the compiler agent and should include ordinary/high-alignment empty ZSTs, clone/drop, both assertion modes and continued nonempty-ZST rejection. No WPT is justified without a reachable browser caller; no production edit is included here.
