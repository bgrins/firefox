### Steps to reproduce

When `hypot` is subtracted from a value inside of `calc` in CSS, addition is performed instead of subtraction. For example, `calc(100px - hypot(30px, 40px))` should evaluate to `50px`, but it actually evaluates to `150px`. The attached demo file visualizes this issue.

**Steps to reproduce:**
1. Start Firefox by clicking on the desktop icon.
2. Open the attached file.

**Tested on**
Ubuntu 26.0.4.1, with Firefox 154.0 AND Nightly 160.0a1 (2026-10-17)
MacOS 26.6.2 Firefox 157.0.1

**AI Disclaimer**
The example code was generated using AI but checked by hand. The bug report was written by hand.

### Actual results

Multiple `calc` values were incorrectly evaluated, causing the test page to show red bars representing the delta. In each case except for the control case the value of `hypot` was added instead of subtracted.

### Expected results

`calc` should have been correctly evaluated, with `hypot` being subtracted. This would have resulted in all green bars with no red.

**2026-10-27 21:52:29** - Comment #5 by dholbert@mozilla.com
Created attachment 9669187
Bug 2083404: Remove invalid special-case for negating hypot() expressions in calc(). r?tlouw,#style


Before this patch, we mishandled negation of 'hypot()' in a special-case that
propagated the negation to the children.  This was ineffective and wrong; it
still produced a positive result, due to the squaring arithmetic that happens
in a hypot() operation.

This patch makes hypot() share the same codpath that we use for many other math
functions, implementing negation using wrap_self_in_negate().
