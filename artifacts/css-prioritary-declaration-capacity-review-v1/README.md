# Declaration-capacity candidate review

The saved source and extraction support a concrete omission hypothesis. They do not yet establish a browser bug or an accepted repair. The reviewed probe seal is `eb0a76a9a8e011c70f6ab1e4955a7380fe01e0e82789f13555bbdd7667277079`.

`Declarations::note_prioritary_property` returns when the full longhand-vector index reaches 65535, before linking the declaration. `note_declaration` still appends it. The exact extracted original loses the sole FontSize entry at 65535 and 65536 preceding Color entries; the widened version passes all five cases and restoring the old guard restores both failures. Independent authentication checked all 30 payloads, the three exact extracted variants, all 15 saved outcomes and the caller excerpts. No tests were rerun.

The ordinary pass cannot recover the omitted FontSize entry: its unvisited caller selects the late property group, and `apply_non_prioritary_properties` excludes prioritary properties. The pinned local `iter_declarations` appends every non-custom declaration it receives without a winner filter. Searchfox's unchanged `DeclarationIterator` walks the rule-node chain and returns declarations without per-property deduplication; that discovery context is saved separately and is not a proof of all earlier rule matching or tree construction. [Iterator source](https://searchfox.org/firefox-main/rev/28b7a7bffb5f82828143d9ad63839ad263b598be/servo/components/style/properties/cascade.rs#120).

The HTML has the intended ordering. Each selector has one class, both targets match all filler rules, and normal declarations share origin/layer/importance. The early target's FontSize follows the 65536 later Color declarations in descending cascade order; the late target's FontSize precedes them. Width is another unrelated declaration, so the browser probe intentionally exceeds the threshold rather than measuring its exact off-by-one boundary. Using separate rules avoids declaration-block duplicate-property replacement. The late target supplies an independent same-sheet FontSize/1em-width control; both colors and the CSSOM count detect obvious stylesheet parsing or application failure. Observations are collected before assertions.

Practical limitations remain: the repeated stylesheet costs parsing, matching and rule-tree work; timeout or resource failure is not evidence of this omission. A CSSOM count of 65538 does not by itself prove all filler declarations reached the builder. Upstream coalescing or a matching limit could mask the route; a passing browser result would not refute the extracted builder counterexample. Color checks also require ordinary test-environment color handling. No browser execution, WPT manifest/lint, full Stylo compilation, broad resource-limit specification analysis or real declaration-count instrumentation is supplied here. No changes to the sealed probe are requested.

The one-line u32 proposal raises the bound but does not prove unbounded behavior. Real native typechecking, browser reproduction and storage/layout/performance assessment remain necessary before treating it as a landable fix. This candidate is distinct from the earlier artifact-only non-prioritary synthesis cursor truncation.
