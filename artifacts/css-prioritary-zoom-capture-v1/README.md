# Required Zoom research capture

This companion closes the supplemental fixture's PASS-data gap. The sealed V1 page retains its in-page samples but ordinary WPT PASS events do not transport them. The replacement `candidate.html` adds exactly one recorder script and one awaited call after the Zoom row's existing two-phase sampling and before its assertions. It performs no additional style reads, changes no numerical expectations, and retains the same eight callback names. All other supplemental pages remain byte-identical to V1. This is a research transport adapter, not a proposed upstream WPT dependency.

`record.js` POSTs the unchanged row to a same-origin WPT Python handler. A fresh owner-generated nonce, phase role and page path bind the request. The handler is restricted to this ordinary HTTP lane: its Origin check expects `http://` plus Host. It does not support HTTPS as written, and the owner must retain the HTTP page URL. `receive.py` accepts at most 65,536 bytes and creates its fixed sibling `REQUEST.json` exclusively. No path is accepted from the request. Wrong origin/binding, duplicate delivery or persistence failure returns failure to the browser and leaves an error marker; the awaited call rejects. A successful HTTP response requires the write to have completed. It does not claim fsync durability against machine failure. Runtime configuration, handler and request live inside the owned phase test directory, not the native checkout or canonical resources.

The owner integration is required, not already enabled:

1. Authenticate this package and replace only the ordinary page resource with `candidate.html`. Merge this genuine manifest entry and the support entries into the cohort manifest; do not keep V1's old page blob. Other pages, names and metadata stay unchanged. Copy the shared harness exactly as before.
2. After the phase `tests` directory and replacement page are copied, before launching WPT, call `capture.install(tests, output, role)` with `tests == output / 'tests'` and role `original` or `candidate`. It creates the previously absent `__research__/zoom` directory and writes the bridge, handler, fresh CONFIG and exclusive `ZOOM-BINDING.json`. Do not prepopulate that support directory. Record all generated bytes/hashes as runtime resources; the nonce-bearing CONFIG is intentionally runtime-specific.
3. Run the existing native WPT lifecycle. After WPT/server termination and owned-group cleanup, but before declaring observation completeness, call `capture.review(output, events)`. Require its success in both original and candidate phases. It authenticates the page/bridge/handler/config, requires one full request with two phases/four samples each and no error marker, and joins the exact raw Zoom callback and page ending. It writes exclusive `ZOOM-OBSERVATION.json` preserving raw status/ending and all diagnostic fields. A missing or malformed row is incomplete even if WPT reports PASS. A captured ordinary FAIL is retained without being relabeled PASS. Existing full-suite completeness and cleanup checks still apply.
4. The candidate reviewer must independently replay both phase captures with the read-only `capture.replay`, authenticate the resulting receipt hashes, and use `capture.compare` (or an independently equivalent field comparison) to retain all differences in samples, font, line height, family, writing mode, zoom and references. Replay receipts retain role and page; comparison requires original/candidate roles respectively and the same exact page, rejecting accidental same-phase comparisons. Comparison reports `target_correctness: null`. Equality is not proof of correctness; a difference requires interpretation. Keep this diagnostic comparison separate from the WPT regression/status gate.

Cleanup and restoration must remain in the owner's unconditional lifecycle path even when capture install/review fails. Do not review while the server can still append an error marker, and do not remove the persisted records with a temporary profile: they belong to the retained research runtime. Existing owner process-group cleanup owns the WPT server. No new listening server, thread, external port or browser process is introduced by this companion. Browser navigation/HTTP delivery has not been executed here, so the first original run must establish the actual end-to-end WPT integration before a candidate comparison is trusted.

The Zoom callback still checks only setup/collection. Its PASS cannot establish the acknowledged active-ancestor scheduling boundary. Setup failure or timeout before the recorder can run produces no full record and therefore fails the required capture gate; there is no promise of transported partial observations. The recorder runs after all Zoom samples, so the HTTP requests cannot affect the already-collected values, though they extend callback completion time. Other callbacks' statuses and diagnostic rows are untouched.

Pure checks executed `receive.py` with mock request/response objects, persisted and independently replayed the actual request bytes, rejected binding errors/duplicates/missing/malformed records, retained an ordinary FAIL, and confirmed differing samples remain differences with no oracle. A Node VM checks the exact row and rejected HTTP/config failures; it does not emulate a browser network stack. `check_fixture.py` verifies the exact two insertions, unchanged eight names, genuine WPT manifest and zero path/content lint findings.
