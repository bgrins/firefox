## 1. Per-unit orientation must survive root metric caching

**Specification.** [CSS Values `ic`](https://drafts.csswg.org/css-values-4/#ic) uses the advance measure of the water ideograph. [`ric`](https://drafts.csswg.org/css-values-4/#ric) is its root-element counterpart. [Writing Modes `mixed`](https://drafts.csswg.org/css-writing-modes-4/#valdef-text-orientation-mixed) retains upright CJK glyphs in vertical text. Consequently root `1ic` and descendant `1ric`, at equal effective zoom, must agree even when the descendant has different font and writing-mode settings. This equality is an independent oracle; it does not depend on guessing system font metrics.

**Native boundary.** In `servo/components/style/values/specified/length.rs`, `NoCalcLength::reference_font_size_and_length` computes local `ic` through `FontMetricsOrientation::MatchContextPreferVertical`. `Context::query_font_metrics` maps that to `wm.is_text_vertical()`. Local `ch` deliberately uses `MatchContextPreferHorizontal`, while `ex` and `cap` use `Horizontal`.

`Device::update_root_font_metrics` in `device/mod.rs` instead computes all four root metrics in one `query_font_metrics` call using `root_style.writing_mode.is_upright()`, requesting both `NEEDS_CH` and `NEEDS_IC`. Under `vertical-rl; text-orientation:mixed`, `is_text_vertical()` is true but `is_upright()` is false. The resulting cached `ric` therefore takes a different orientation path from local root `ic`. Root-element `ric` takes the local helper directly, while descendant `ric` uses the cached metric, making this cache boundary especially easy to isolate.

This is legitimate differentiation between `ch` and `ic` in the local path; the suspicion is that the shared root query loses that differentiation. Replacing the root Boolean globally with `is_text_vertical()` would risk breaking `rch` in mixed text. A repair should preserve the policy for each metric and share queries only when the requested orientations agree.

**Downstream trace.** `Device::query_font_metrics` in `device/gecko.rs` forwards the Boolean to `Gecko_GetFontMetrics` in `layout/style/GeckoBindings.cpp`. That obtains an oriented `nsFontMetrics`, then calls `gfxFontGroup::GetMetricsForCSSUnits(fm->Orientation(), flags)`. That function calls `font->GetMetrics(aOrientation)` and, when required, copies the water glyph font's `ideographicWidth` using the same orientation. This establishes that the Boolean reaches the metric returned as `mIcWidth`; it is not merely an unused hint.

**Smallest proposed browser oracle, not run.** Wait for explicit font loading and set the root to `font:20px TestFont; writing-mode:vertical-rl; text-orientation:mixed; padding-left:1ic`. Give a child `width:1ric; height:1px`. Read computed root padding and child width: they must agree. Include a root `1ric` declaration as a direct-versus-cached control. Then test upright, sideways, and horizontal modes, and make the child horizontal with an unrelated font to ensure root semantics are respected. To expose the source asymmetry, the font must produce different horizontal and vertical water-glyph advances; verify this precondition with local `ic` controls first. The existing `IcTestFullWidth.woff2` can exercise the code paths, but is not established as a discriminating fixture.

**Correction to the initial audit.** The initial report incorrectly inferred horizontal 20px and vertical 40px advances from `ic-unit-001.html` and `ic-unit-003.html`. The latter has two stacked `height:5ic` blocks, so its 200px-square reference is consistent with 20px in both orientations. Those tests do not establish asymmetry, and no 40px expectation is supported. The root/local equivalence oracle remains valid, but this font may make it pass vacuously. FontTools is unavailable in the system, Firefox venv and Conda Python environments; installed `hb-shape` cannot load this WOFF2 font and `fc-scan` returned no font data. No package was installed. See `CORRECTION-v1.md` for the preserved correction record.

**Parent-run observation, no reproduction.** After the correction, parent session `89445` exited 0 using `IcTestFullWidth`: root `1ic`, descendant `1ric`, and local `1ic` were all 20px in horizontal, vertical mixed, upright and sideways modes (12/12 comparisons agreed). Raw evidence: `artifacts/css-custom-property-next-probe-v1/round2-root-ic-baseline-v1.json`; the parent recorded stable inputs. This confirms that the existing font does not expose the source asymmetry. A different font with verified unequal advances is needed before treating this as an observable bug.

**Existing coverage.** `ic-unit-002.html`, `ic-unit-003.html`, and `ic-unit-004.html` exercise local upright/mixed/sideways policies. `ric-invalidation.html` changes root font size in a horizontal document. `css-viewport/zoom/font-relative-units.html` compares local/root pairs under zoom, also horizontally. These located tests do not combine root caching with vertical mixed orientation. Bounded search is not proof that no other test covers it. Local metadata for `ic-unit-003.html` permits a small macOS pixel fuzz; the two latter tests have no metadata files. None was run here.

**Useful formal contract.** Model a finite writing-mode/orientation state, a per-unit orientation function, and an abstract metric provider indexed by font, size, orientation and glyph. Prove `rootCache(u, state) = directRootMetric(u, state)` for each root/local pair, conditional on equal zoom and provider inputs. A source-shaped single-orientation batch has a counterexample for `ric` in mixed vertical text when horizontal and vertical advances differ. Mutation controls should exchange `ch`/`ic` orientation policy, drop the root font input, and reuse a cache after a writing-mode change. Exact native branch extraction is small; font shaping, downloadable-font scheduling, numerical rounding and concurrent cache publication remain explicit assumptions. A theorem about the policy table alone would not verify those integrations.

## 2. Cached root normal line-height needs a complete dependency predicate

**Specification and oracle.** [`lh`](https://drafts.csswg.org/css-values-4/#lh) converts the first available font's `normal` line-height to an absolute length; [`rlh`](https://drafts.csswg.org/css-values-4/#rlh) uses the root's corresponding value. At equal zoom, a root `padding-left:1lh` and descendant `width:1rlh` should agree before and after a supported environment change. This does not require a universal numerical formula for `normal`.

**Native boundary.** `MatchMethods::line_height_likely_changed` in `matching.rs` recognizes changes to line-height, and for `normal`, font family/style/weight/width. The caller separately recognizes font-size changes. `Device::calc_line_height` passes `writing_mode.is_text_vertical()` to `Gecko_CalcLineHeight`, which delegates to `ReflowInput::CalcLineHeight`. Writing mode is thus an actual input to the computation but is absent from the predicate that gates updating `Device::root_line_height`. The root metric cache for `rex`/`rch`/`rcap`/`ric` is refreshed separately and cannot repair the stored root line-height.

Font variation settings and font-size-adjust are additional plausible omitted inputs, but this audit did not trace their precise influence on `normal` or all font-load invalidation paths. They are deferred hypotheses, not additional bugs. Start with the explicit writing-mode argument.

**Falsifiable probe, not run.** In a dedicated iframe, use a fixed font with distinguishable horizontal/vertical normal metrics, root `line-height:normal`, root `padding-left:1lh`, and child `width:1rlh`. Flush, then change only root writing mode from horizontal to vertical mixed, keeping font size/family/style/weight/width constant. Compare root padding, existing child width, and a newly constructed identical iframe. First assert that the root `lh` reference actually changed; otherwise the font fixture cannot witness this omission. Keep a numeric line-height control, which should not change, and a root font-size mutation as a known dependency control. No registered custom properties are necessary.

**Existing coverage.** `rlh-invalidation.html` mutates explicit numeric line-height and font-size. `lh-rlh-on-root-001.html` exercises root self-reference bases. `rlh-on-root-lengths.html` checks root non-font properties. The audited zoom tests exercise an adjacent conversion seam. Local `rlh-invalidation.html.ini` already permits `[PASS, FAIL]` for macOS non-debug; that is a known expectation, not evidence that this particular missing dependency causes it. No new failure has been observed.

**Formal scope and cost.** Model root cache state, input updates, invalidation predicate and reads. Prove that an update either preserves the computed metric or refreshes the cache before descendant reads. Abstract horizontal and vertical font metrics as independent values. This yields a small counterexample to an incomplete predicate, but connecting it to traversal order and Gecko's line-height provider is medium effort. Do not attempt a full inline layout proof. Font fallback, first-font selection, font downloads, zoom normalization and layout flush timing must be modeled later or named as trusted assumptions.

## Other inspected seams and rejected leads

- **Container-unit fallback dependency:** `ContainerSizeQueryResult::get_viewport_size` calls `Context::viewport_size_for_viewport_unit_resolution(Small)`, which records `USES_VIEWPORT_UNITS`; the container conversion separately records `USES_CONTAINER_UNITS` and disables the non-inherited rule cache. No missing viewport flag was found in this fallback path. Basic container selection, mixed axes and writing modes were already audited in round 1 and were not promoted again.
- **Viewport declarations versus queries:** `ElementStyles::viewport_unit_usage` gives query dependencies priority, inspects primary, eager pseudo and cached lazy pseudo styles, and the invalidator selects restyle versus recascade accordingly. This is a useful future state-machine contract, but there is no concrete discrepancy in the inspected code.
- **Logical viewport units:** their conversion sets both a writing-mode-dependent rule-cache condition and `USES_FONT_OR_WM_RELATIVE_UNITS`. No missing writing-mode dependency was found there.
- **Dynamic viewport variants:** the device records dynamic viewport use separately and computes a toolbar-dependent size. Proving toolbar bounds and platform event delivery would require more mobile integration than this bounded audit; no claim is made about those events.
- **Root `rlh` zoom:** there is a suspicious-looking extra zoom step in the root branch, but existing dedicated zoom tests cover related behavior. No full normalization trace was completed, so this was not promoted as a third finding.
- **Font-download invalidation/style sharing:** inspected the lazy root metrics cache, use tracking, and local font-query cache suppression. A complete proof needs font-set events and traversal lifetime; no new defect claim follows from the inspected slice.

## Evidence and limitations

`sources/` contains bounded native excerpts and relevant WPT snapshots; `PROVENANCE.json` records downloaded/local hashes, exact font hashes and metadata observations. Searchfox discovery was used before reading native code. The downloaded main files match the local files for the substantive call chain; `length.rs` differs only in unrelated `fit-tolerance` declarations/imports. `container_rule.rs` has the parent's local name-only query fix, outside the excerpt audited here.

Primary CSSWG drafts were read on 2026-10-18 through the web tool: Values Level 4 dated 20 August 2026, Writing Modes Level 4 dated 20 January 2026, and Conditional Rules Level 5. The installed Searchfox lacks permalink/spec-reference options; no hand-built source permalink is represented as content-validated. `webspec-index` is unavailable and primary-spec fallback was authorized. No `Read` tool was exposed, so `layout/AGENTS.md` and `LayoutOverview.md` were read through Python before inspecting layout code.

These are two bounded research targets, not a CSS coverage percentage or proof of native correctness. The first can be checked with a tiny equivalence experiment, but needs a font with independently established differing horizontal/vertical advances to expose the orientation asymmetry. The second likewise needs a fixture that demonstrates different normal line-height metrics before it can establish an observable stale-cache failure.
