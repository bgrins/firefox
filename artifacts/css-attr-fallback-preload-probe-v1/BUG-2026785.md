**Context**
Given **registered** custom-property `--x: 3em` and **unregistered** custom-property `--y: var(--x)`, consider the following two cases:
1. `font-size: var(--x); // Cycle caused by: --x -> depends on font-size -> depends back to --x.`
2. `font-size: var(--y);  // Cycle caused by: --x -> depends on font-size -> --y -> depends back to --x.`

Discovered with David that our cycle detection resolves 1) and 2) in different ways:
* 1 is caught in a loop during [build()](https://searchfox.org/firefox-main/rev/c836d51da4179d7b456d02d22e2f40c8b1a9b3d7/servo/components/style/properties/cascade.rs#349-352), and we eventually reach [handle_variable_in_loop](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/custom_properties.rs#2025), which is then used here to [IACVT](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/properties/mod.rs#1475).
* 2 isn't caught in a loop. When we enter [VarType::NonCustom](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/custom_properties.rs#1885), we ultimately exit [here](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/custom_properties.rs#2062) because unregistered custom-properties/attrs aren't noted during [maybe_note_non_custom_dependency()](https://searchfox.org/firefox-main/rev/34fc93ba6c4d8f57cd154677f0c4cd9907fd1339/servo/components/style/custom_properties.rs#1401-1420). But because `--x` gets deferred [here](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/custom_properties.rs#2091,2106) (and consequently `--y`), and `apply_priority_properties()` is called before [build_deferred()](https://searchfox.org/firefox-main/rev/c836d51da4179d7b456d02d22e2f40c8b1a9b3d7/servo/components/style/properties/cascade.rs#357,366), we arrive to this [IACVT](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/properties/mod.rs#1497) for font-size because the [substitution function map](https://searchfox.org/firefox-main/rev/34fc93ba6c4d8f57cd154677f0c4cd9907fd1339/servo/components/style/custom_properties.rs#2515) doesn't contain `--y`.

**Issue**
So even though 1) and 2) both result in font-size becoming IACVT, 1) also IACVT's the [stack of references](https://searchfox.org/firefox-main/rev/9233846aa396b6974783199e1bfe3a38473fc518/servo/components/style/custom_properties.rs#2043-2073) in the cycle. Scenario 2) does not, only font-size is made IACVT, the other references in the cycle are still resolved.

**The attached testcase result on browsers:**
Expected: span shouldn't print 30px 30px.
Actual:
* Nightly: 30px 30px
* Chrome: 3px
* WebKit: 3px 3px

**Fix**
Maybe should rework starting from [maybe_note_non_custom_depedency()](https://searchfox.org/firefox-main/rev/34fc93ba6c4d8f57cd154677f0c4cd9907fd1339/servo/components/style/custom_properties.rs#1401-1420).

Given that it's 1) a general issue affecting custom properties as well, and 2) it doesn't seem interoperable between Blink & WebKit makes me think that it doesn't need to block `attr()` work.

FWIW, for point 2), I'm fairly sure the bug is on WebKit side - I think there's no question that `--y` has a guaranteed-invalid value, because it's in the [cyclic substitution context](https://drafts.csswg.org/css-values-5/#cyclic-substitution-contexts) ("[...] an attempt to guard a matching substitution context again will mark all substitution contexts involved in the cycle as cyclic substitution contexts."), and guaranteed-invalid value should [serialize as if it's an empty string](https://drafts.csswg.org/css-variables-2/#guaranteed-invalid-value).
