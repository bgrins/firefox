# Selective font handoff: tree-boundary review

**No new concrete missed-work defect found in the reviewed stable, already-styled tree paths.** Shadow/slot flattening and ordinary `display: contents` do not introduce an iterator mismatch in the selective repair. This is a source-level result, not new browser coverage or a general scheduling proof. No native patch, test execution, or bug-count change is proposed.

Authority is the sealed `css-root-font-cancellation-selective-handoff-fix-v1` candidate, composed with the font-unit admission repair. Unchanged helpers are read from immutable e86 objects; exact whole-file hashes and quoted excerpts are in SOURCE-EXCERPTS.json. The package's original README predates native validation; its historical status wording is not used to infer current validation status.

| Potential omission | Source-supported disposition |
| --- | --- |
| Shadow host skips shadow descendants | Ruled out as a direct iterator mismatch. `GeckoElement::traversal_children` switches to `StyleChildrenIterator` for a shadow host. `ChildIteratorBase` substitutes the shadow root as the iterator's child container; the ShadowRoot node itself is not a skipped non-element hop. Both selective post-join seeding and normal `note_children` use this same interface. |
| Assigned nodes disappear at a slot | Ruled out for an unchanged assignment. The slot takes the style-iterator path; a filled slot enumerates `AssignedNodes`, and an empty slot enumerates fallback DOM children. The flattened-parent helper returns the assigned slot or active fallback parent. Unassigned light children and inactive fallback content are deliberately outside the rendered flat tree, not demonstrated dropped styled descendants. |
| Fixed-font host, slot, or wrapper stops propagation | Ruled out once its ancestor-font hint is seeded. Normal `element_needs_traversal` admits a nonempty hint even if the element does not need its own cascade. `RestyleHint::propagate_for_non_animation_restyle` retains the ancestor-font bit, and `recalc_style_at` calls `note_children` for that nonempty propagated hint. This is visitation without unconditional recascade. |
| Ordinary `display: contents` wrapper has no frame | Ruled out as a traversal barrier. The iterator does not use frame children, and child pruning checks `styles.is_display_none`, not absence of a frame or `display: contents`. The wrapper's computed style and conditional hint remain in the style tree. This does not extend to special elements whose display adjustment deliberately turns `contents` into `none`. |
| Missing style data hides an already-styled descendant | The existing `clear_descendant_data` implementation explicitly relies on the invariant that a node without data has no descendants with data. Transition to `display:none` clears descendant data through the same style iterator. Lazy `resolve_style` builds returned/cache values rather than installing `ElementData` down a formerly unstyled route. These facts reject the obvious stable missing-data counterexample. The stronger `has_data` versus `has_styles` invariant is not proved here: the new handoff skips either absence, so an actual styled-descendant/unstyled-immediate-parent state would still need investigation rather than assumption. |
| Restyle root differs from the caller's element | The handoff seeds the actual root returned from `driver::traverse_dom`, not a guessed DOM root. In the animation-only pass, `pre_traverse` skips the normal sibling invalidation that can widen the root. The immediately following normal call uses the original element; its pre-traversal may widen to an ancestor while explicitly propagating the dirty route. No concrete loss from the reviewed root change was found. Incorrect root selection outside this function remains a caller obligation. |
| Generated pseudos or document-level anonymous roots | Generated pseudo children are included by `AllChildrenIterator`, so they are not inherently missed by the element-only seeding loop. Document-level native anonymous content is explicitly excluded by `StyleChildrenIterator` and has a distinct document-parent relationship; this review does not prove scheduling across those separate traversal roots. No author-accessible missed-work witness was identified. |

The argument is conditional on an actual animation-only font-change signal, a stable style tree during traversal/post-join seeding, and the correct explicit traversal root. It does not prove dynamic slot reassignment/attachment cleanup, all transient `has_styles` invariants, or external consumers outside that subtree. Those are precise remaining correspondence boundaries, not evidence of a bug.

The root itself deliberately receives no new self hint. The independent root-relative keyframe identity issue is unchanged. The known initial/final-animation signal suppression and the separately observed startup endpoint-update/application queue gap are also unchanged; neither is a new tree-boundary failure, and neither is solved merely by this route argument.

Smallest useful additional coverage, if root elects to test it: reuse the existing cancellation witness in a fresh iframe, but place the existing animated rem consumer in light DOM assigned to a slot inside a shadow host, beneath one fixed-px `display: contents` shadow wrapper. Pre-style host/wrapper/slot/consumer before the root animation trigger. Keep the existing root em-animation cancellation, no intervening root read, first target getter, then settled target getter. Expected target remains 46px after restored root23, versus the known stale64 signature. Pair it with the exact root-read control and validate slot assignment and all structural/computed-style preconditions before the trigger; inspect the root/provider only after target samples. Do not reassign the slot during this test, since that adds an independent style invalidation that can mask the route. This is an **unexecuted coverage proposal**, not a new failing WPT or acceptance requirement inferred from a source defect.
