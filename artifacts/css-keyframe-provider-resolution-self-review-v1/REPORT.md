# Current-provider resolver source self-review

I authored the proposal. This is a source self-review, not independent approval. The exact proposal manifest is ad376b9f11a4f66c9ffe73b6829f7775e549e2d787ee925504253e4e96eae5c8. All 32 payloads authenticated. I reread the native/test patches, retained descriptor ownership, original animation-context constructor, custom-property substitution/defaulting, and attribute dependency traversal. No new definite blocker was found for the explicitly disabled callable-resolver stage. Native compilation, generated bindings and the two host tests remain unperformed here.

The FFI wrapper constructs a fresh derived StyleBuilder/Context, rule-cache conditions, tree-counting caches, attribute tracker and substitution map for each call. The selected original declaration is resolved in that consumed context; sibling retained declarations are not cascaded into the supplied provider snapshot. Attribute preparation uses the existing typed-attribute graph walk, but skips final map-reuse heuristics. Temporary custom-property writes, prioritary/invalid flags and other mutable builder state are confined to this context. This prevents sibling-call state leakage at the API boundary; it does not demonstrate correctness of a future context projected from an in-progress cascade.

Descriptor declarations and their URL/namespace data remain owned by the retained servo Arc context. Returned values are newly owned Strong<AnimationValue> objects containing the full CustomAnimatedValue conversion, not reconstructed numeric tokens or borrowed endpoint references. The prepared lifetime test clears temporary keyframes/pairs while retaining the descriptors. Neither this review nor the existing numeric serialization assertions proves complete taint/URL metadata preservation at runtime.

Error handling keeps unsupported/non-custom work and authored revert separate from CSS-invalid defaulting. Wrong-type or missing-variable substitution follows the actual registered invalid-value handler. There is no cached AnimationValue or underlying-value error fallback. Parsed declarations and universal registrations are intentionally rejected; the status name NotRegisteredCustomProperty also covers a registered universal syntax, so it must not be interpreted as a registration-existence test. Post-substitution revert behavior inherits the existing implementation's issue-9131 uncertainty. Authored inherit/unset value selection does not export inherited-reset/cache dependency flags: this is acceptable only at the present isolated test boundary, not a complete cascade integration.

The provider map must already be complete and coherent with the current Stylist registration, target/pseudo, parent and computed font/color state. The API does not validate that premise or repair an old provider map after registration changes. Attribute values are read currently from the element; supplying an old computed provider style while attributes change is not generally a coherent production snapshot, although the focused numeric attribute isolation test deliberately does this with unrelated style inputs held constant. The caller will need an explicit snapshot policy.

The dependency walk resolves prepared attribute references using existing SCC machinery. The ordinary provider-cycle test consumes a map whose ordinary cascade has already invalidated the cycle; it does not test cycles between pending animated roots. The API performs no winning-root selection, priority/revert/seen admission, topological scheduling, animated-SCC resolution, effect-watch publication or traversal refresh. Returning only references_attributes loses the tracker names and transient cacheability/flags at the outer boundary. Before enabling producers, those outputs and all winning dependencies must be integrated without converting evaluator failure into missing-provider/defaulted or cached values.

The only new native call sites in the candidate are the FFI definition and prepared presentation tests. Existing normal composition, public maps, commitStyles and GetComputedKeyframeValues remain unchanged. Accordingly this stage cannot itself repair the four measured dynamic-provider failures; its four WPT cases exercise future integration and are not expected to pass because the new API exists.

The two host tests meaningfully cover old descriptor ownership, current ordinary providers, missing versus wrong-type defaulting, fallback/no-fallback, repeat/order isolation, typed-attribute changes and recovery after an unsupported call. Before broader admission, add direct metadata checks, qualified attributes, dynamic registration and inherited/root/pseudo cases. Generated ABI/type checking and actual test execution are immediate gates; current-provider scheduling and animated cycles are separate implementation gates. No new browser result, memory-report completeness, performance conclusion or accepted bug is claimed.
