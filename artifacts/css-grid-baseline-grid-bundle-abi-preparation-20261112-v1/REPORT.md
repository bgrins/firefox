This frozen preparation defines two actual-TU syntax/layout commands, baseline then candidate, without executing them. Root must provide an external authorization bound to FILES.json and a fresh output directory. No live source installation, object generation, linking, browser launch or shared-objdir write is performed by the plan.

The source candidate is the separately frozen three-file grid-request bundle. Each copied CPP is identical to its selected frozen source plus the retained probe.inc suffix. The suffix defines char arrays whose lengths are sizeof/alignof of actual types and forces layout via sizeof of the probe record. It does not redefine native types or use offsetof. Baseline covers nsGridContainerFrame, CachedBAxisMeasurement and MeasuringReflowResult. Snapshot and MeasuringReflowGeometry do not exist in that baseline; the candidate additionally measures those types. Complete compiler layout output provides member/base offsets. The parser requires the independent probe-array values to equal the corresponding record footer values and requires unchanged frame size/alignment.

REQUESTS.json derives from the exact retained clangd entry, removing only -c and -o /dev/null and adding syntax-only, record-layout dump, VFS overlay and dependency-output arguments. Both source and exported aliases for the two headers are mapped, along with the CPP. No claim about code generation or browser behavior follows from this gate.

INPUTS.json pins 2,944 paths: the actual unified generic2 dependency closure plus tools, configuration, compile database, predecessor identities, current restored browser identities and the previous real layout output used for parser checks. It includes symlink resolutions and SDK headers. Each actual dependency emitted by either command must be in that closure or an explicit overlay replacement; unknown inputs reject the gate. Inputs are authenticated before, between and after commands. The unified dependency file is only a conservative inventory source, not a claim that every listed file is consumed by this individual TU.

Each command has a 180-second wall limit, a sampled 2-GiB process-group RSS ceiling and a 64-MiB stdout+stderr ceiling. Sampling is not an OS-enforced memory limit and can miss short peaks. Full stdout/stderr are retained up to termination, with no output filtering. Commands run serially in owned sessions. The inherited lifecycle helper validates ownership, records inspection failures, terminates only owned groups and verifies absence. A final independent inspection within the runner covers every recorded PID. Failure receipts are written even for compiler launch/inspection failure; later commands do not run after refusal. Process-inspection access may require a separately approved escalation when execution is requested.

Source-only checks exercise exact source/command/alias derivation, previous actual layout records, malformed/missing layout facts, authorization refusals, mock launch/compiler/inspection failures, mock resource-limit refusals and unknown/changed/empty dependency refusals. No mock process is a native compiler. The first parser check rejected unrelated duplicate templated-lambda display names in the large dump; the correction selects only the named target records while continuing to reject conflicting duplicate target records. That failed attempt and all subsequent logs are retained.

Native correctness, provider eligibility, four-query work accounting, cache context validity, unlogged performance and independence from the pending padding repair remain separate gates. This preparation does not authorize any of them.
