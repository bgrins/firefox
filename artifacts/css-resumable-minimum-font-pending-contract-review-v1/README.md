# Minimum-font Pending/Complete contract review

The observed failure is the integrated-v2 prototype's terminal custom-root assertion in `substitute_all::run_one`, called from the `seen.var` loop. Candidate metric13, phase4, typedattr4 and sizeforms4 completed PASS; minimum_off produced zero callbacks and a CRASH ending. minimum_on and inputs were not reached. The raw log does not contain the actual root name, retained action or return-progress variant. No native root cause is proved by the stack alone, and no new released-browser bug is claimed.

The strongest source-derived hypothesis is an unhandled nested scheduling request. The minimum fixture combines registered `--metric:1ch`, registered `--len:1em`, and `appearance:attr(data-length type(<length>),auto)` where data-length references --len. If the font-metric root reaches ordinary FontSize publication first, retained Appearance preparation can wait on --len while the shared FontUnits node is already computation-pending. A later --len visit is entitled to request a computed-size facet, but `Context::poll_frames`'s existing-node Pending branch only returns that facet when `computed_size_ready(index)` is already true. Otherwise it returns ComputationPending immediately; it does not enter the new-node Publish branch that can create a ComputedSize action.

The nested boundary also drops actionable progress: `poll_frames` installs a FrameStep::Pending prerequisite into `metric_action` only at depth zero. `resolve_metric_lookup_inner` calls it at the retained lookup's depth and maps any nonterminal result to Ok(false); `resolve_metric_lookup` restores the original lookup, and `drive_metric_action` returns Lookup. `run_one` treats every outcome except Published/AlreadyComplete as a reason to break, then asserts that its still-pending VisitResult is terminal. Retaining a lookup is therefore not sufficient: the outer synchronous completion contract has no scheduler path for this child request. Repeating the same action without changing readiness would repeat the wait, not solve it.

This is a conditional source trace, not a claim that this exact root order occurred. The fixture's registered metric and inherited-keyword family cases also expose independent ComputedSizeReadset rejection branches, including Family already complete while Appearance is not complete, or a claimed/active static prerequisite. The sealed diagnostic should distinguish these alternatives before a repair is selected. The fact that sizeforms4 passed does not isolate the additional minimum fixture's root, declaration form, language, or first getter.

Use the existing diagnostic candidate7523b7c0 first. For the nested-wait hypothesis, look for root --metric, retained Appearance action, Variable lookup --len (possibly reached through TypedAttribute data-length), a --len frame waiting on FontUnits, and no size facet. The contrasting readset failure prints its exact readset branch and priority ownership snapshot. A no-action Pending with a waiting FontUnits frame supports the existing-node routing gap without establishing the outer action path. The snapshot also reports active/claimed/seen/ensured FontSize and XTextScale, which distinguish legal early preparation from an unsafe replay attempt. Do not infer a form from zero callbacks; native diagnostics have not yet been run.

The smallest faithful repair, if the nested path is confirmed, is an owned child computed-size request rather than a relaxed terminal check. Route both newly visited FontUnits publication and an already-pending FontUnits revisit through the same eligibility check. Preserve the suspended outer action, lookup identity, generation, frame depth and selected-parser continuation; service the eligible computed-size child; return only a ComputedSize reply to a consumer whose demand is exactly ComputedSize; then resume the original lookup once. Keep the full FontUnits publication pending for metric consumers until real ordinary prerequisites finish. Because `metric_action_is_current` currently requires the action owner to be the last Publish frame, a child request must carry an explicit validated pending-node owner/depth; merely overwriting the single metric_action or reusing the outer action identity is not a correct patch.

If early preparation is blocked by an actual readset/claim, the driver must schedule that precise prerequisite or represent a genuine CSS dependency cycle. It must not mark all FontSize complete, return fallback/invalid for Pending, clear ownership, re-evaluate the old selector, or accept a facet whose later hooks change an already consumed value. In particular, relax neither the Family/Appearance finality condition nor the post-consumption certificate guard merely to avoid this crash. A native effect-order repair and the already recorded minimum-ratio/omission used-size obligations remain separate from nested continuation plumbing.

Required controls for a future repair are both normal root orders of metric/len; already-existing pending FontUnits versus a fresh node; a size-only child versus a 1ch metric child that cannot consume the facet; retained attribute/parser query counts across the child suspension; genuine custom/FontSize cycle handling; and the real minimum off/on omission/inherit/percentage/calc cases. The existing graph extraction stubs computed_size_ready and accepts_computed_size to false and has a unit-readiness facade. It cannot establish native reproduction of this path. This report runs no extracted or native tests and changes no candidate, fixture, owner, runtime, or canonical state.
