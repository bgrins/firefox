# Literal typed-attribute setup isolation proposal

This artifact is an unexecuted diagnostic delta against the exact a6f4 selected-declaration cascade. It is not a complete repair or a promotion candidate. Its purpose is to isolate whether ordinary priority consumption bypasses the typed-attribute cache setup that graph visitation normally supplies. The active portable experiment uses the unchanged a6f4 source; this proposal is not installed.

In the captured source, `maybe_note_non_custom_dependency` returns early for prioritary properties. Selected `visit_value_references` can populate and traverse typed attributes, but generated `ensure_prioritary_property` can call `apply_one_prioritary_property` without that visit. Ordinary substitution of `attr(... type(...))` consults `substitution_functions.get_attr` outside container queries. A missing cache entry therefore selects fallback even when the DOM attribute exists. This establishes a possible setup bypass, not the actual observed order of a particular browser result.

The delta adds a cache-only helper before the existing application call, gated by the same `longhand_is_eligible` predicate. Seen, excluded cascade-flag and rollback-rejected declarations do not query attributes. An evaluated declaration that produces rollback may prepare its direct attributes before the next reached declaration, just as its evaluation reads are real. The helper considers direct typed-attribute references only; it does not walk unused fallback references or custom-property replacements.

The existing attribute parser returns a universal token value. Only values with no var/attr/env references are inserted. No substitution or computed-value conversion occurs here; relative units and other tokens are retained for the existing consumer. Existing cache entries, including explicit invalid entries, are preserved via `contains_attr`. The helper does not mark attributes seen, add semantic edges, modify SCC state, or invoke priority application. Normal typed parsing and attr taint remain in the existing substitution path. Parsing can still query and track the reached attribute; this is not an assertion of zero additional reads. Direct attribute inventory can query several occurrences before normal substitution later fails, so declaration eligibility does not prove per-occurrence demand.

Raw attributes containing unresolved references are deliberately left untouched. Their readiness, dependency traversal, relative-unit context, active SCC and repeated publication require a consistent graph-aware consumption path. A literal-only helper risks splitting semantics and hiding that broader problem; it is retained only as an isolation experiment. In particular, it does not fix monotonic Appearance flags or a later prepared Initial that skips overwriting an early value. Passing literal controls would not establish native acceptance.

The exact portable four-case fixture supplies variable-length, literal-length, missing-attribute and literal font-family controls. Further evaluation must retain the previously failing generated Appearance diagnostics and all original PASS signatures. Additional controls needed before any general repair include an overridden typed-attribute loser, a reached rollback followed by a literal winner, an already-invalid attribute cache entry, nested attr/var/env input, and a genuine custom-property cycle. No outcomes are assigned to these controls by this artifact.

`CHECK.json` records a clean patch replay and rustfmt using the repository configuration. Neither real Stylo typechecking nor browser validation has run. Provider/value sources and all other cascade code remain the a6f4 parent bytes. The preferred eventual repair is one coherent consumption path with explicit readiness, not acceptance based on this special case.
