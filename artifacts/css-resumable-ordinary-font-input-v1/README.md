# Retained ordinary font-input action: intermediate candidate

This experimental three-source candidate extends the existing retained synthesis action to font-kerning, font-optical-sizing and font-variant-ligatures. It targets the source-policy gap identified by the actual minimum_off crash: an unfinished ordinary font input could return Pending without installing an action. The raw diagnostic does not identify which of the three declarations was encountered first. This is a prototype regression investigation, not a newly accepted release bug.

The nonlogging parent is immutable integrated-v2. PARENT-DELTA.patch contains the action/target naming changes and exactly three additional admitted longhands. Provider and properties/mod.rs are byte-identical to that parent. Native selection, substitution, parsing, declaration application, and completion bookkeeping are reused unchanged. native.patch is the full three-source patch against the saved e86 baseline, retaining its capacity u32 alias. Future live admission must explicitly preserve later accepted fixes; these saved source pins do not authorize overwriting a newer published baseline.

A pending selector keeps its state and exact longhand reply ownership. Completion is recorded only after successful native publication; failed publication retains the selector state. A repeated completed action does not run selection or application again. The existing 21-input scanner is unchanged: seven input kinds now have an action, while fourteen remain unsupported by this action. This milestone does not make those fourteen invalid, skip their declarations, or claim permanent Pending is an acceptable final implementation.

READSETS.md records the native conversion/setter evidence and remaining obligations. The added literal enum/bitflag conversions do not read a child font-size or font metric. This is not a proof of the whole native Context, dynamic substitution, CSS-wide values, cascade invalidation or nested child-action behavior. In particular, the separate singleton metric_action/lookup/reply ownership problem is not repaired here.

Saved validation: five controller tests and five compiled behavioral mutants, plus ten publication-policy controls and the three formerly orphaned cases now producing an action. ACTION-EXTRACTED.rs contains the exact candidate controller and admission predicate; its selector/provider/native application are scripted doubles. POLICY-EXTRACTED.rs contains the exact publication decision with a small set representation. Neither suite is a native reproduction or native conversion proof. Parent integration suites are historical evidence only and were not rerun for this candidate. CHECK.json separately records source normalization, exact extraction, source pins, formatting and full patch roundtrips.

Next validation must first compile these three source roles in the real native Context, then run the unchanged minimum_off page and the broader 63-callback matrix with actual restoration. Passing the formerly crashing page alone is insufficient: full 21-input support, dynamic provider requests, graph-cycle semantics, minimum-size equivalence and compatibility controls remain required. No native check, browser result, accepted-fix increment or publication authority is claimed by this package.
