# Native readsets and remaining work

Evidence is the pinned e86 snapshot of longhands.toml, specified/font.rs, computed/font.rs, generics/font.rs and gecko.mako.rs, together with the exact integrated-v2 cascade. These are saved artifacts, not reads of temporarily overlaid live source.

| Newly admitted input | Native value conversion | Native destination |
| --- | --- | --- |
| font-kerning | FontKerning Auto/None/Normal; ToComputedValue derive and computed reexport of specified type | mFont.kerning |
| font-optical-sizing | FontOpticalSizing Auto/None; same identity conversion | mFont.opticalSizing |
| font-variant-ligatures | FontVariantLigatures u16 flags; same specified/computed type | mFont.variantLigatures |

For these literal values the conversion has no FontSize, Family, XLang, zoom, viewport, device metric or cached-system-font getter. The font block in gecko.mako.rs skips only font-size and -x-lang from ordinary impl_simple generation. The three setters assign their own field through From::from; copy/reset reuse that setter. No additional font-size hook is introduced by those setters. They affect later font metrics, which is why a metric publication must wait for their actual selected declaration/application rather than simply mark them complete.

The actual selected-declaration path remains begin_font_preparation/resume_font_preparation, publish_prepared_metric and apply_one_longhand. That path retains declaration identity, substitution/parse state and the existing seen/author/revert/flags/CSS-wide/context.scope behavior before native CASCADE_PROPERTY dispatch. This package does not replace it with numeric conversion or prove those effects from the controller doubles. Inherit/default still use native application. Dynamic values can request retained substitution, but correct nested action/reply ownership and all provider effects require separate integration validation.

The existing four synthesis inputs retain their parent behavior. The fourteen still-unadmitted scanner inputs are: font-feature-settings, font-language-override, font-palette, font-variant-alternates, font-variant-east-asian, font-variant-numeric, font-variation-settings, font-variant-caps, font-variant-emoji, font-variant-position, math-style, math-shift, -moz-osx-font-smoothing and -moz-math-variant. None is silently removed from next_unprepared_font_input.

Most remaining values have identity-like enum, flags, atom or identifier-list representations; they are not all inherently context-sensitive. They still need selected-value, setter/write-order and real integration controls before admission is widened. Feature/variation settings additionally instantiate FontSettings with Integer/Number components: ToComputedValue calls each component with Context and sorts/deduplicates tags. Ordinary longhands can contain unresolved calculation even though the font-face-specific parser rejects it. Their numeric/calc/random/reference effects cannot be inferred from the three literal inputs. MathStyle's value itself is an enum; the separate MathDepth AutoAdd conversion reads parent math depth/style, so this audit does not invent a child-MathStyle-to-own-size dependency. Main system-font conversion paths must likewise be audited where actually reached, not attributed to these three setters.

Native proof obligations remain: selected declarations and prerequisite identities stay stable through suspension; each native application occurs once; invalidation cannot replay partially applied effects; any child action preserves the outer parser/drain/reply owner; all later legitimate font writes preserve already-consumed metric publications. import_priority_completion still clears the ordinary completion ledger on cascade-flag changes, and the existing singleton action architecture is unchanged. The controller tests do not prove those paths safe. Full support for all 21 inputs and broader dynamic forms remains the goal, with this seven-input patch an explicit intermediate boundary.
