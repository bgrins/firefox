# Linked declaration-index refinement

This extends the sealed capacity model with an explicit functional head/tail/next representation. The executable update does not assume its linked chain already equals a projection: the proof establishes that each tail write and new zero link preserve the representation, then shows traversal returns the admitted projection for arbitrary finite declaration lists. Below the sentinel bound that equals the complete per-property projection. The native capacity candidate remains a separate browser experiment; this model adds no accepted fix or browser result.

`State` retains the full declaration vector, one property's head and tail, and a Nat-indexed next heap. `note` always appends the declaration and initializes its fresh next slot to zero. For an admitted target declaration it either sets an absent MAX head/tail or writes the previous tail's next and advances the tail. The head MAX sentinel is distinct from the next-zero terminator. Head zero is a valid first element. `Path` records a strictly increasing nonempty chain ending at the stored tail with next zero; empty state separately requires head and tail MAX. No invariant premise asserts that note already preserves Path.

`path_append` proves the concrete heap updates extend the old chain. `note_refines` derives preservation for target, unrelated and overflow cases. `build_refines` lifts that result to arbitrary finite lists, including lists exceeding the bound. `path_walk` proves the executable traversal reaches exactly that chain when given sufficient fuel; the increasing-index invariant establishes that vector length supplies sufficient fuel. `fresh_read_admitted` and `bounded_read_complete` therefore connect actual modeled reads to the old independently defined admitted/full projections. `all_vector_entries_retained` proves the guard does not discard vector entries. The concrete zero-head and unrelated-gap examples expose the sentinel conventions. `unrelated_heap_update` additionally proves writes at indices outside a chain cannot change its representation.

The sentinel is a parameter, not a hard-coded u16 or u32 maximum. The prior imported model retains the generic overflow counterexample and finite-u32 limitation. This extension supplies the previously excluded logical linked-update obligation, rather than repeating that capacity theorem. Its six negative controls reject treating zero head as absent, omitting the previous tail update, linking through an unrelated entry, admitting the MAX index, dropping vector entries at the guard, and overwriting the oldest head with the tail.

## Native correspondence boundary

The full-vector offset and pre-push guard match the exact archived native builder. The native implementation writes the old tail before pushing the new zero-initialized record; the model initializes the fresh heap slot first. The proved old-tail < new-index invariant makes those writes disjoint. The model uses natural numbers and a total functional heap; it does not model Rust layout, allocation failures, pointer provenance, bounds checks, wrapping arithmetic or generated property identifiers. The source guard is the separate reason an admitted native cast is representable.

This is a projection for one arbitrary property. Other properties' writes can be ignored only when they target indices outside that property's chain; off-path noninterference is proved, while actual generated mapping and per-property disjoint membership remain native correspondence obligations. The model does not claim a simultaneous refinement of every concrete shared-heap field. The native cascade may stop after finding a winning declaration or follow rollback eligibility; this model covers the complete index chain, not CSS winner selection. Browser selector matching and the ability to supply a large enough declaration sequence remain external.
