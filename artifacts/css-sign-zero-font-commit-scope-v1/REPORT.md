# Sign repair commit scope

Recommend two minimal native-plus-WPT commits, with the intermediate-value transport repair first and the Sign folding repair explicitly depending on it. Separate research evidence precedes each native commit. No new bug number, accepted defect, or reviewer is assigned here.

The three-file prerequisite consists of `values/specified/length.rs`, `values/specified/calc.rs`, and `values/computed/length_percentage.rs` under `servo/components/style/`. It preserves nonfinite intermediate values during actual per-unit conversion and selects that policy in both calc mappers, while retaining the existing ordinary-property normalization wrapper. It changes a general calc boundary, including compound operands that already defer evaluation on HEAD90. It is therefore independently meaningful and broader than the Sign leaf-folding change.

The second commit changes only `values/generics/calc.rs`: Sign folds a leaf only when its canonical value is available. It repairs premature coefficient-only folding for contextual units. On its own, delaying a direct nonfinite relative operand exposes the old mapper's premature normalization. That regression makes the transport repair a prerequisite; it does not make the two source defects identical.

For the prerequisite WPT, retain the existing mixed-unit NaN opacity expression `calc(0.5 + 0.5 * sign(NaN * 1em + 1px))` as a source-supported independent witness. Add a corresponding compound-operand width case to exercise the separate length-percentage mapper, for example `calc(10px + 10px * sign(NaN * 1em + 1px))`, with expected final width zero. These are proposed split-test assignments, not newly observed browser results. Input/style/font/geometry calibration must precede semantic assertions; a wrong positive-font initial value is an eligible semantic failure, not failed input calibration. Direct single-leaf nonfinite Sign cases cannot establish that prerequisite independently because the old Sign folding gate may resolve them before the changed mapper.

For the Sign commit, retain the ordinary finite zero-font opacity and width witnesses, absolute and finite mixed-unit controls, and the direct NaN/infinity cases protecting the newly deferred path. Keep ordinary finite, viewport truncation, text zoom, and nonfinite calc preservation coverage from the full 1,032-case campaign. Splitting the landing fixtures is a packaging task; it must not reduce that campaign's control roster or loosen any oracle, retained failure, infrastructure, or calibration gate.

Before landing, test the transport-only candidate against HEAD90, and the Sign candidate against the validated transport prerequisite. Also retain the combined full proposal comparison. This distinguishes the transport witness from new Sign improvements and verifies that each commit leaves a coherent stack. The current original four-case diagnostic proves only its two zero-font failures on the preserved installed stack. The expanded fourteen-case repair remains uncompiled/unvalidated in the browser at this review checkpoint. Existing source/scalar checks are not substitutes for those isolated comparisons.

A single combined commit is technically defensible as a regression-safe Sign repair, but would merge an independently testable, general intermediate-value defect with a leaf-folding defect. Given the user's requested one-bug-per-commit policy, the explicit prerequisite split is preferable. No controller redesign or source/test mutation was performed by this assessment.
