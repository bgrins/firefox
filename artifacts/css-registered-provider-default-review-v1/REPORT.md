The scoped-cycle-bit proposal is not ready for native testing as a preservation-only repair. Its fallback descendants can change even when it skips new defaulting on a cycle-touching frame. This is a concrete source-level counterexample; no browser execution or native proof was performed.

Use registered A/B/C with A initial vertical-rl and B/C initial vertical-lr:

    A: var(B, var(C)); B: var(A); C: var(--missing)
    writing-mode: var(A, horizontal-tb)

On recursive A reentry, the draft sets encountered_cycle and returns no primary. B fails. A then evaluates C in its fallback. C temporarily isolates the previous cycle bit; its missing-reference error is locally acyclic, so the new registered default supplies vertical-lr. Restoring the bit does not undo that changed result. A's cycle-touching success returns the raw vertical-lr substitution, although its marked substitution must be invalid and its own computed default vertical-rl. The outer resolver may later repair A's stored value, which does not itself repair an earlier ordinary-property application. The selected ordering must still be established by browser observations.

The implementation owner independently found the same flaw and is preparing explicit participant marks. Required narrow control: both declaration orders of this fallback-crossing cycle, asserting A/B own initials and nonparticipant C's default, plus the outside writing-mode result. This is sufficient to exercise the newly identified branch; no additional broad framework is needed.

The existing Lean model applies directly at the boundary: marked_survives_fallback requires preserved marks and a final participant check. A boolean saying some descendant encountered a cycle is neither the participant set nor a final poison check. The model does not establish the native caller ordering or resolver correspondence.
