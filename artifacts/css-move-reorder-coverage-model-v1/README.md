# Same-parent reorder and notification coverage

This companion proves list locality for a same-parent move, extending the sealed cross-parent model without modifying it. It adds no native refinement, discovery, acceptance, or canonical coverage credit.

`World` and `WellFormed` are imported unchanged from Parent.lean: parents own finite duplicate-free ordered lists, and membership agrees exactly with each node's owner. Node and Parent types are arbitrary types with decidable equality. Count is the owner's list length; index is its `idxOf + 1`. Well-formedness ensures every modeled node is present, so the absent-element idxOf convention is not a valid-move case.

`reorder` keeps ownership and every other parent's list unchanged. Its selected list becomes `front ++ node :: back`. Validity requires initial well-formedness, ownership of node by that parent, and the concrete equation `oldChildren.erase node = front ++ back`. Thus the insertion gap is chosen AFTER removal; the result is not assumed to preserve length, membership or values. The well-formedness and length proofs derive those facts from duplicate-free erasure and reinsertion.

Eleven audited declarations establish well-formedness preservation; reinserted length; preservation of every node's count; unchanged entire sibling lists and count/index pairs outside the reordered parent; count freshness with no notifications; pair freshness when the original parent domain is notified; common-prefix and equal-length common-suffix index laws; index locality outside a moved block; and a concrete well-formed witness. Full-parent notification is conservative sufficiency, not a minimal refresh-set theorem. Count preservation also covers singleton lists and reinsertion at the original gap. The notification theorem itself is an algebraic coverage result for the constructed world, while the separate validity theorem supplies well-formedness under the erase/gap premises.

The interval statement compares `(left ++ node :: middle) ++ right` with `(left ++ middle ++ [node]) ++ right`. Any element unequal to node and absent from middle retains its idxOf. It follows from identical prefix positions and equal-length prefixes before the shared suffix, not an unchanged-index premise. This is the forward block form (and equality can be read in reverse), not a proved conversion of every numeric insertion position to an interval or a minimal refresh-set theorem for arbitrary gaps. The lemma is valid even as a plain-list equality; its valid DOM-like application additionally uses the unique-element partition assumptions.

The finite witness changes [0,1,2,3] to [2,0,1,3]. All counts remain four; moved node2 changes index3 to1, and stationary node0 changes index1 to2. False controls reject both no index notifications and notifying only the moved node. Count invariance therefore does not establish pair freshness. As in the imported refresh model, cached values are initially fresh and notified entries recompute the new value; native delivery, scheduler timing and actual cache behavior are external obligations.

The DOM mapping is manual and element-only. The normative move algorithm structurally removes then inserts, and moveBefore normalizes a reference to the moved node to its next sibling. The gap here is after removal; reinsertion at the original gap is a list/value identity, not an observable DOM no-op. DOM move explicitly does not invoke ordinary insertion/removing steps. The proposed RestyleManager notification is internal style invalidation, not a claim that DOM requires its ordinary removal algorithm. Text/CharacterData, parent ancestry, shadow trees, slots, eligibility checks, moving callbacks and mutation observers are outside the model.
