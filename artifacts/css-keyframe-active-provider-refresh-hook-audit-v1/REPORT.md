# Active provider refresh: a missing notification, but no safe isolated hook yet

The four failures have a concrete missing-refresh path. `KeyframeEffect::NotifyAnimationTimingUpdated` requests an animation restyle. `matching.rs::process_animations` explicitly returns for an animation-only traversal of an already styled element, before scheduling `EFFECT_PROPERTIES`. Normal composition therefore uses the retained `mProperties` endpoints. This agrees with the archived positive trace: provider red is composed at events 211/216/221, while the consumer composes cached 20/30 at 213/218/223. No consumer resolver calls were observed in that interval. Native-emitter identity and complete stderr delivery remain unproved; this is not an absolute absence claim.

There is a promising hook for a diagnostic experiment, but I cannot recommend it as an independently correct general repair. Enabling the existing effect-property task on changed custom properties would turn sampling into successive whole-style iterations. The existing pipeline neither establishes dependency completion for an arbitrary acyclic chain nor supplies animated-cycle handling. No native patch is proposed here because the straightforward alternatives have concrete barriers below.

## Actual context and delivery chain

1. Timing changes request Standard/Throttled animation restyle; they do not call `UpdateProperties`. `ComposeStyle` selects from cached segments, and `Servo_AnimationRuleSample_Compose` clones their cached values.
2. In an ordinary non-animation-only traversal, `process_animations` schedules `EFFECT_PROPERTIES` for an element with animations. A normal inline/style/provider mutation therefore already has this path; animated sampling is the bypass under investigation.
3. The sequential task executes after traversal work. `GeckoElement::update_animations` reads the element's stored current primary style. `Gecko_UpdateAnimations` forwards that style to `EffectCompositor::UpdateEffectProperties`, which passes the same immutable style to each effect's `UpdateProperties`.
4. `Servo_GetComputedKeyframeValues` seeds its keyframe custom-property builder from the supplied style's custom-property map. Rebuilding one effect does not update the supplied style for the next effect. The native loop's iteration order is therefore not a dependency order, and changing it does not make the provider map current within the loop.
5. A changed endpoint list causes `UpdateProperties` to request another Layer animation restyle. During traversal, `PostRestyleForAnimation` intentionally records the demand without posting to PresShell; its comment and implementation rely on `PreTraverse` before the existing second traversal. `ServoStyleSet::StyleDocument` contains that extra traversal, not a repeat-until-dependencies-complete scheduler. RestyleManager's outer loop is documented for style/frame invalidations and clears the restyle root; it is not a contractual pending-animation fixed-point drain.

For the observed one-edge literal-provider case, an extra property update after the first current-provider style is available could rebuild the registered consumer against red, produce the already-tested initial-value default 10, and publish it in the second pass. This is a source-supported hypothesis, not an executed repair. Both creation orders should behave the same because the callback receives one completed style, rather than the effect iteration order's intermediate values.

## Two concrete barriers to the obvious changes

**Refresh before composing using GetComputedStyleNoFlush:** that retrieves the previous completed style. When the provider seeks from 250 to 750 ms, the newly requested provider value need not yet be in that style. Calling `UpdateProperties` there can faithfully recompute against 20 and still produce the old consumer endpoints. Forcing a recursive style flush inside traversal is not an available substitute: the traversal and RestyleManager explicitly prohibit reentrant flushes.

**Queue EFFECT_PROPERTIES after every changed custom-property map:** consider three separate effects, with a literal unregistered provider P seeking 20→40, registered Q having constant endpoints `var(P)`, and registered R having constant endpoints `var(Q)`. All are paused; Q/R registrations are non-inherited numbers. Starting with a completed map P=Q=R=20, the first compose produces (40,20,20). The shared-style rebuild prepares Q=40, R=20. The next compose produces (40,40,20), after which the rebuild prepares R=40 and requests another pass. The existing one-extra-pass delivery is insufficient by itself to establish a current first public R read. This is an acyclic input; no cycle oracle is needed. External additional invalidations or another getter must not be treated as completion of the first requested sample. The exact resulting public observations remain a proposed browser test, not measured evidence.

Adding an unbounded drain would require a second decision. With separate registered effects X=`calc(var(Y) + 1)` and Y=`calc(var(X) + 1)`, each with identical from/to declarations, the same completed-style rebuild maps (a,b) to (b+1,a+1). Two iterations add 2 to both values while they remain exactly representable. A mere changed-value guard cannot discharge that demand. This is an operational counterexample to using equality as a cycle policy, not a claim about the conforming cyclic numeric result or infinite IEEE floating-point arithmetic. A pass cap would leave a partially resolved sample; substituting initial values for the whole effect would invent the unresolved endpoint/final-property invalidation policy.

## Recommendation and next discriminating observations

Do not remove the animation-only return or add an unconditional normal recascade as the repair. A bounded experimental hook could isolate this missing notification, but would need explicit non-production scope and must not be accepted solely because the existing four failures turn green.

The minimum safe incremental repair needs a justified completion condition: for example, a certified provider-independent changed winning value and its dependent endpoints, or a scheduler that completes an admitted acyclic dependency graph before publication. That certification must inspect real winning providers and retained declarations, not cached numeric equality. The existing source has no such certificate. General animated SCC/defaulting and computation-scope obligations remain open.

Use the unchanged ten-case diagnostic as the one-edge gate. Add the two-edge P→Q→R history with consumer-first and provider-first creation, first/repeated R reads before any provider getter, and literal40 controls. At fixed times, expect Q and R to be 40 under the already-established acyclic current-provider oracle. Compare a paused ordinary inline-provider change as a control for the existing normal traversal path. For the cyclic X/Y operational witness, record observations and termination only; do not assign a conforming numeric oracle. A single non-dependent normal style mutation after saving the stale first-read history is useful as a separate recovery observation, not part of the original acceptance sample.

No new browser fixture, native patch, compiler run, browser run, live source/index mutation, or bug count is included. The source excerpts and checks are sufficient to reject the simple hook as a general repair; they do not prove that no smaller carefully certified repair is possible.
