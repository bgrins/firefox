# Sizeforms crash diagnostic

This is an unexecuted diagnostic successor of the exact f0d computed-size candidate and failed four-case sizeforms page. It adds stage markers and terminal-only native state output. It changes neither Pending semantics nor the fixture's assertions, declaration values, getter order or callback roster. The original failure and sealed source remain immutable. The full native diagnostic has not been typechecked or run in a browser.

The separate HTML copy calls Window.dump before/after iframe append and load, registration, the initial --len getter, attributes, phase stylesheet replacement, animation-frame waits and each target/parent/reference/attribute-reference read. Records contain mode, phase, per-body sequence and stage. A script-start canary precedes the test bodies. `read` invokes its operation once, returns its result and propagates exceptions; no extra computed-style lookup is introduced. The original promise-test harness still serializes bodies. Removing the exact recorded additions recovers the sealed original HTML byte for byte.

PREFS.json enables browser.dom.window.dump.enabled for this diagnostic only. Saved Searchfox definitions show Window.dump checks DumpEnabled, writes to the dump stream (normally stdout) and flushes it; DumpEnabled consults this preference outside always-enabled configurations. These captures establish the intended transport, not a demonstrated WPT run of this page. The execution must retain the complete process output and confirm the canary. If markers are absent, do not infer a setup stage from their absence. This uses normal browser output, not altered testharness result messages or a server transport.

The native delta reuses the earlier servo_arc-compatible terminal logger. It saves only the already-computed action progress that stops the existing loop, logs immediately before the unchanged assertion, and does not retry traversal, substitution or application. It records root/result/reply, bounded frames/nodes, exact pending node, all generated priorities' ensured/completed/claimed/active state, static dynamic-chain classification, selected-reference identity/cursor, and the computed-size certificate, session/flags validity, deferred frame and retained size/text-scale preparation. Ordinary successful root completion does not invoke the logger. No declaration text, attribute values or numeric style computation are dumped. Identifiers and process-local pointer identities may appear. A pending result with no saved action progress is labelled not-driven, not a semantic cycle or a repair diagnosis.

The new facet fields read existing state and the pure valid_flags predicate; they do not rerun the facet preparation or prefix checker. A discarded unsupported size preparation is therefore not reconstructed as an exact rejection reason. The log identifies the failing root/demand boundary, not necessarily which earlier guard rejected preparation. Full restoration and future scheduling decisions remain the execution owner's responsibility.

Both outputs affect timing and resource use. JavaScript writes stdout and native diagnostics write stderr, whose capture order can differ even within one process. Interpret per-stream ordering, mode/phase sequence and unmatched before/after pairs conservatively; do not impose a global total order or identify an element solely from the latest visible marker. Asynchronous style work can run during frame/load waits. Failed writes are ignored by the native helper, preserving the terminal assertion. Formatting, static declaration scans, temporary bounded vectors and stderr locking still add overhead.
