# Repair obligation after tracing

The observed candidate repairs selected losing-declaration edges but still allows generated scheduling to cross graph ownership. Its already-failing length-a callback also worsens color. The next repair must retain real selected var/attr and rollback edges, while ensuring a property publishes one final cascade result before dependent eligibility or computed values consume it.

A defensible design separates three states: graph preparation, prerequisites for the actual selected computation, and final publication. Ordinary generated ensure must not silently claim or apply a property whose selected value is still graph-owned. Merely treating that reentry as a semantic cycle is also wrong: conservative generated font dependencies are not automatically CSS dependency edges, and literal pixel font-size can be computable independently of unresolved Appearance.

Therefore an active reentry needs either a proven narrower actual-computation dependency route that can finish the needed value without provisional publication, or explicit suspension until that route can complete. This is an implementation requirement, not a claim that general suspension is necessary. The trace identifies which computation/selection reads actually block the route. Existing generated dependencies cannot simply be removed wholesale.

If provisional mutation is retained instead, the implementation must restore and reevaluate every affected builder field, seen/reverted/ensured bit, included flag, side-effect and dependent custom/priority result before publishing. Clearing Appearance's final flag or forcing only its final Initial write cannot meet that obligation after fonts or colors consumed the provisional state. Rechecking eligibility and skipping a final prepared declaration merely preserves the premature value. Restoring eager raw attribute inventory alone cannot resolve a raw var that still depends on an unfinished custom value.

The bounded native proof obligation is concrete: between the selected-prefix decisions and their final application, every reached or skipped eligibility decision and every retained substitution/adjustment result remains valid; no same-property ordinary publication can occur inside that interval. Real cyclic inputs must still follow the existing invalid/default path, while literal and missing-attribute controls retain their intended values. These are pending native obligations, not conclusions from the abstract Lean stability theorem.
