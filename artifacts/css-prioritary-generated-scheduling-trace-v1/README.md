# Temporary generated-priority tracing

This is a diagnostic-only delta from frozen candidate cascade a6f4, not a correction or a native-ready acceptance patch. It must be a separately identified later source/build role. The portable four-case original/candidate pair stays uninstrumented. No owner, fixture, browser profile, native source, index or canonical control was changed during preparation.

Enable only in a dedicated trace process with `MOZ_CSS_PRIORITY_TRACE=1`. Other values or absence suppress output. Events are best-effort stderr lines beginning CSS_PRIORITY_TRACE, with thread ID, cascade pointer, priority name and event. Only Appearance, FontSize, FontFamily, XTextScale and ColorScheme emit events. No DOM element text, whole styles, declarations, attribute contents or full maps are dumped. Pointer/thread identity is a local correlation aid, not a persistent element identity; the pointer can be reused by later cascades. Process logs can interleave. Never merge this run with uninstrumented behavioral evidence.

The events cover the four requested boundaries:

1. `graph-enter` and `graph-eligibility`: active graph index, stack length, ensured/seen, actual Appearance and included-base flag. Skipped candidates are visible.
2. `prepared-ensure-dependency`, `ordinary-ensure-enter/dependency/return`: distinguish graph preparation from ordinary generated scheduling and show whether Appearance remains active at entry to a prepared dependency chain. `graph-attr-cache` and `ordinary-attr-cache` report only cache presence and unresolved references. No attribute query or substitution is introduced.
3. `graph-resume`, `graph-substituted`, `prepared-apply-before`: compare the retained pre-recursion eligibility with the current read-only predicate, seen bit and resulting CSS-wide keyword. Existing debug assertions remain unchanged.
4. `resolved-apply-before/return`: report the existing computed skip decision and builder Appearance/base flag, including the non-inherited Initial skip. Subsequent ensure returns expose the existing did-apply effects. These hooks are shared by ordinary and prepared application; surrounding events identify the caller.

A positive trace of the suspected route requires one correlated sequence: graph-owned Appearance remains active, generated scheduling ordinarily applies that same property before its attribute dependency closes, and final graph application skips or encounters changed eligibility. Cache events distinguish absent input from unresolved input. Absence of this sequence is not proof of impossibility: traces can be incomplete, the chosen root order can differ, or another branch may apply first. No exact element or graph-session allocator was added; ambiguous pointer reuse must be resolved using a small isolated page and surrounding sequence, not guessed.

All 15 inserted regions are explicitly marked. Removing them from the formatted postimage restores a6f4 byte-for-byte. Every original selection/substitution/computation/mutation call and its relative order is unchanged; no new such call appears inside those regions. Added calls inspect existing fields/maps and write diagnostics. This is a source-level noninterference check, not proof of identical timing, allocation, scheduling or runtime behavior: environment reads and enabled stderr locking add overhead, and native typechecking remains pending. Stderr failures are ignored rather than introducing a diagnostic failure path. The patch is never intended for publication.

Static checks authenticate the base, exact forward/reverse patch, pinned rustfmt/config and strip identity. Scratch is removed. No native crate compilation or browser execution occurred. References bind the immutable candidate, source follow-up and observed blocker. The gate remains the uninstrumented portable and Mozilla observations plus subsequent source review, not success of this tracer.
