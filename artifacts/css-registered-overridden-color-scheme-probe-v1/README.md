# Overridden declaration dependency probe

This unexecuted nine-case WPT tests whether a losing declaration introduces a false registered-property cycle. Six color cases cover separate-rule order and importance, including expression/no-loser and literal controls. Three length cases isolate the same collector without color or attr(): an independent 0px initial, a declared 2em, a losing font-size:var(--actual), and a winning literal 20px !important (then 30px). Correct lengths are 40px and 60px.

All color registrations use the independent initial red. The actual value is light-dark(green, blue), while a winning literal color-scheme changes dark to light. Expected computed colors are blue then green. A losing var(--actual, attr(...)) declaration has an unused attr fallback to enter the inspected ColorScheme dependency collector. Separate rules avoid same-block duplicate-declaration elimination. Cases include normal losers before and after important winners, and earlier same-importance losers before later normal or important winners. No contextual initial-value acceptance is required.

Each callback owns a fresh iframe and registration. Registration initial value, losing-declaration grammar, actual winning longhand and independent literal reference are calibrated separately from the tested custom-property output. The first --actual getter precedes all phase diagnostics; three subsequent animation-frame samples are recorded. Both phases are collected before assertions. Hidden diagnostics avoid pushing later frames offscreen; the frame sampling is neither a queue-drain proof nor an internal dependency trace. There is no animation or timing oracle.

window.overriddenSchemeObservations retains plain JSON rows, including both phases before any numeric/value verdict. It is not private transport. Setup exceptions or harness timeouts may leave missing or partial rows; PASS statuses alone do not expose every row without an external reporting adapter. An installed observer may copy this export at completion without extra style reads. Raw statuses, calibration and tested sample equality must remain separate.

Source analysis is in SOURCE-NOTE.md and exact excerpts in SOURCE-EXCERPTS.json. The inspected collector records qualifying losing declarations without cascade priority, while final application checks winner eligibility. This supports a concrete prediction, not an observed browser failure or attribution to V5. The route also exists in the frozen committed preimage. The independent finite closure theorem assumes its input dependency graph; it does not prove the graph contains only evaluated cascade candidates.

Normative basis: CSS Cascade sorting chooses the winning declaration before its computed value is resolved; registered lengths convert to canonical units, and registered colors resolve as colors. The relative-unit dependency rule describes actual property values, not arbitrary overridden declarations. See [cascade sorting](https://drafts.csswg.org/css-cascade-5/#cascade-sort), [registered computed values](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation), and [relative-unit cycles](https://drafts.css-houdini.org/css-properties-values-api-1/#dependency-cycles). The color control uses [light-dark](https://drafts.csswg.org/css-color-5/#light-dark). Current primary pages were read for this probe; this is not a full spec algorithm trace.
