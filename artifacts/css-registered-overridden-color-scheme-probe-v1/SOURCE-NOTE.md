# Builder equality and the missing cascade-selection premise

The original concern was custom default publication during SCC popping, before invalid NonCustom priorities are ensured. Ordinary StyleBuilder::new initializes both cached color_scheme and inherited UI from the parent (or root defaults). When the effective ColorScheme declaration is WithVariables, the invalid-priority guard makes it inherit; inherited CSS-wide application can skip rewriting it, and did_apply_prioritary_property refreshes the same bits. Thus delayed publication alone does not establish a differing scheme in this restricted path. Equality additionally requires that no winning literal/other effective declaration later changes the scheme and that this is the ordinary builder initialization path. Derived and visited builders have separate contracts.

The inspected collector does not establish that premise. iter_declarations calls note_declaration, which appends declarations, then independently calls maybe_note_non_custom_dependency. That collector accepts no priority and stores all admitted WithVariables inputs. FontSize and LineHeight admit var directly; ColorScheme enters through ATTR even in an unused fallback. Final apply_one_longhand separately rejects seen, excluded or reverted candidates. A literal winner does not enter VariableDeclaration::substitute_variables and therefore is not replaced by the invalid-priority guard.

Consequently a source-shaped witness can have the graph edge Scheme→custom from a losing var declaration and custom→Scheme from the real light-dark value. SCC invalidation can select the independent red initial even though the final literal winner is dark. The analogous FontSize↔custom graph can default a 2em property to 0px despite final font-size20px. These avoid the contested computational-independence question for light-dark initial values. They test dependency selection, not just when an invalid default was published. The frozen base already contains this collector structure; no new V5 regression is established.

The earlier contextual-initial example remains only a conditional preservation concern: a default recomputed against inherited light could differ from a later literal dark winner. It is unnecessary for the executable fixture. No generic value countermodel was added, since the source-selected-edge witness is more discriminating. The abstract closure oracle and Tarjan traversal correspondence remain distinct obligations, as do actual default computation/publication and cascade candidate selection.
