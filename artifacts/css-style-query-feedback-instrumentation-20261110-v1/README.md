# Native scheduling-boundary diagnostic

This capsule contains a diagnostic-only four-file patch against `3a6a6bfe2b0d3d551b2392206179f251002cfc7e`. It preserves the current StyleDocument drain and existing font/query handoffs. `prepare.py` reads only the previous frozen source capsule and regenerates copied sources and the patch. `check.py` authenticates the four Git bases and applies/reverses the patch in scratch space. Neither script installs live source or builds Firefox.

Enable records with `MOZ_CSS_FEEDBACK_TRACE=1` in the runtime environment. All records begin `CSSFB`; the counter is monotone within a process and includes `pid`. The first 20,000 records are retained, followed by exactly one `event=cap` record. A cap invalidates any inference that the trace contains the whole execution. The enabled diagnostic asserts the main-thread contract before shared counter access. Counters are main-thread-only: the patched entry points are native animation/sampling and StyleDocument entry points, not parallel traversal worker hooks.

Each `style` enter creates a call ID and increments depth, including early returns; RAII exit restores the prior call/depth. Scroll `refresh` and `stale` scopes similarly delimit sampling phases. They do not assert that all refresh frames are observed. Cache records read stored cache fields, document pointer, and the cached snapshot’s trivial source-element accessor only. They do not run an extra sampler.

Animation records are limited to CSSAnimation targets whose ID is `outside`. The existing animation index is ordering metadata, not an allocation ID: CSSAnimation can overwrite it. Partition fixtures by document/phase and live animation pointer; do not use the index to resolve address reuse. Rebind records include old/current and candidate timeline pointers; entry/exit pairs include start/hold nullness, pending enum, auto-alignment flag, and stored playback rate. Tick, ready, trigger, and align are paired on every return using ScopeExit. No new call computes current time, flushes style, triggers pending work, or evaluates a production branching condition twice. Timeline addresses identify live objects; they are not allocation serials and may be reused after destruction. Distinguish a persistent fallback address from a currently live provider address, but do not count total allocated providers from pointer uniqueness alone.

Suggested analysis:

1. Require contiguous sequence numbers per PID, balanced style and refresh/stale scopes, and no cap. Partition by fixture, PID, document, and live animation pointer. The animation index is not a unique identity.
2. A rebind entry where `timeline != next`, followed by exit with `timeline == next`, identifies the changed association. Same-object calls are not rebinding. Pending entry/exit alone does not establish progress; observe whether start/hold becomes resolved. Nullness does not establish full-state cycle identity or a specific sampled progress.
3. A `ready`/`align`/`trigger` exit that restores start/hold at nonzero style depth is a candidate counterexample to the no-readiness-inside-drain premise. Identify its enclosing scope and exact call; do not infer a loop from a single restoration.
4. A sequence of fallback readiness, rebind to provider, and rebind back to fallback across style calls, repeated between refresh/stale scopes, explains identical pending JS snapshots as per-rendering-update churn. If no readiness restoration occurs, investigate pending starvation instead.
5. A tick outside `StyleDocument` followed by two rebindings inside one call can still be a finite drain. To establish same-call recurrence, require a renewed resolved timing state within that same call, with repeated association changes; preserve all intervening sampling events.

The trace itself adds I/O and execution overhead; it is for causal ordering, not timing/performance measurement. The source capsule's conditional bound and the root's grouped JavaScript observations are hypotheses/context, not verdicts encoded by this patch. The independent review is in `../css-style-query-feedback-instrumentation-review-20261110-v1/`.
