# Contextual CSS updates after script keyframe calls

The existing Gecko override path is guarded. No new defect or native patch is established. This package adds four unexecuted follow-up tests; it does not alter the active fifteen-test roster or the earlier 293-test experiment.

The current CSS Animations2 rule gives a successful setKeyframes call precedence over later CSS keyframe/timing changes. A throwing call leaves keyframes unchanged and does not acquire that precedence. SPEC-TRACE.md records the bounded normative chain and its assumptions. Searchfox and immutable signed HEAD 182db9b1 source joins show that CSSAnimationKeyframeEffect returns on parse failure before recording the Keyframes override, and nsAnimationManager checks that bit before replacing keyframes and default timing. The candidate's contextual restyle request still flows through this guard. Three existing literal WPT tests already cover rule changes, timing changes and unsuccessful calls; the new cases extend those boundaries to contextual reconstruction, without claiming discovery credit.

The new page crosses sibling versus inherited-font context with successful versus rejected setKeyframes calls. Each fixture has one target and one otherwise identical CSS animation in a separate sibling holder. Both remain paused at 750ms with their original animation/effect identity. Sibling mutations change Steps 3→4→3, sampled 2/3→3/4→2/3; inherited font changes 16→32→16px change Steps 2→3→2, sampled 1/2→2/3→1/2. The unmodified CSS control must follow those curves. Independent literal Steps 2/3/4/5 references are created before mutations, checked finite/interior, and canceled during cleanup.

A successful call installs literal Steps 5 keyframes, whose opacity sample is 0.6 and whose serialized keyframes must persist through all mutations. The rejected call supplies offset 2, requires TypeError and immediate keyframe preservation, then must continue following CSS updates. This rejection does not depend on contextual WAAPI parsing or CSSWG14246. The CSS keyframes always remain present, so the last-rule-removal cancellation exception is outside the test. Only opacity is animated; no animated-font feedback policy is assumed.

There is an explicit body before callbacks. DOM roots and every created animation have cleanup. All post-call phases are sampled before assertions, with full snapshot details in failure messages. The target and its unmodified CSS control have no ordinary contextual property that independently supplies sibling invalidation. Font changes intentionally use an ancestor. The unchanged CSS control establishes what continuing CSS updates should look like rather than allowing a vacuous unchanged target to count as success.
