# Four-source configured Rust typecheck preparation

This execution capsule prepares one configured Firefox Rust-graph `cargo check` with the three-file random-index rollback proposal v2, wrapping all seven typed finalizers, and the independent one-file contextual numeric line-height proposal together. It does not link a browser, run a browser, accept either fix, or test the proposals independently. No main execution has occurred.

The lowest-disk proven route reuses `objdir-full.noindex` and the configured `toolkit/library/rust/.cargo-library-spec.json`, with two jobs, offline/frozen dependency resolution, a 35 GiB launch floor, a 15 GiB running floor, and a 30-minute deadline. The exact command/environment are composed by the same pinned `mozbuild.rust_commands` API as the prior successful full-graph typechecks. A separate source tree would require changing the configured absolute source paths and would lose the existing compilation cache.

The root agent must close its current browser before execution and grant the temporary source overlay an exclusive execution window. The script owns only four in-place source writes and a source-transition lock; all base/candidate bytes are authenticated before any write. The existing dirty provider prototype remains untouched. Compiler groups must be gone before owned restoration. Full source, binary, research, identities, root/nested semantic index, raw staged patch, staged blobs/modes, flags, and both separately installed WPT identities are checked after restoration. A failed restoration retains the lock and reports the problem instead of claiming preservation.

The exact 165-file pending signing selection is authenticated without resetting or restaging it. The observation epoch is derived from the unchanged runtime preimage by explicitly adding only those staged entries: removing the exact selected entries must recover the old index roster. The copied staged-aware guard checks the complete binary/full-index patch and each staged blob. This is an honest observation projection, not a rewrite of runtime or signing evidence.

No runtime CURRENT, ROLE, OWNED, signing selection, signing helper, or Git index/ref is published by this script. Raw index-stat drift can occur after temporary source restoration even with identical semantic staging; it is reported separately in the output. A future signing retry must freshly verify the actual state and may require explicit reconciliation. The script does not declare old signing guards valid automatically.
