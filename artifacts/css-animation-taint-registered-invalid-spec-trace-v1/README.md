# Registered invalid keyframes and animation taint

Checked 30 October 2026 against the captured current editor drafts. The normative text supports rejecting the named custom property at a non-animatable `var()` sink even when its computed value is a registered initial value. This is a property-name rule, not an explicit instruction to copy a taint bit onto a default-value object. The saved browser observations do not identify either internal mechanism.

Claim and setup: `--v` is registered as `<custom-ident>`, inherits false, initial `horizontal-tb`. A matched active `@keyframes` rule declares `--v: one two`. The ordinary sink is `writing-mode: var(--v, vertical-lr)`. The question is whether the typed mismatch exempts the resulting initial/default value from the taint restriction.

1. [Properties and Values API §2](https://drafts.css-houdini.org/css-properties-values-api-1/#behavior-of-custom-properties) extends the custom-property rules, except where it specifies differences. [§2.2](https://drafts.css-houdini.org/css-properties-values-api-1/#parsing-custom-properties) explicitly delays registered-syntax checking until computation. Thus the two-ident declaration is not rejected at parse time merely for failing `<custom-ident>`. This differs from malformed CSS that never becomes a declaration.
2. [CSS Animations 2 §3.2, step 2](https://drafts.csswg.org/css-animations-2/#keyframe-processing) finds the matching keyframes rule, groups and cascades declarations, and builds keyframe property values. [Web Animations §5.3.3, step 2.2](https://drafts.csswg.org/web-animations-1/#calculating-computed-keyframes) calls [compute a property value](https://drafts.csswg.org/web-animations-1/#computing-property-values) with the declared value and target element. That operation follows the property's computed-value rules. These are actual computation callers; no informative liveness example supplies an algorithm here.
3. [Properties and Values API §2.4](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation-of-computed-values) makes registered syntax failure invalid at computed-value time. [§4.1](https://drafts.css-houdini.org/css-properties-values-api-1/#the-registerproperty-function) expressly describes reset to the registered initial value. Its [§2.7](https://drafts.css-houdini.org/css-properties-values-api-1/#substitution) substitutes the serialized computed value. These clauses explain selecting/tokenizing a default; they do not specify clearing animation taint during that selection.
4. The [Variables definition](https://drafts.csswg.org/css-variables-1/#animation-tainted) says: “any custom property used in a @keyframes rule becomes animation-tainted”. This directly covers the named property in this matched rule; it does not predicate the restriction on a valid animated endpoint winning composition.
5. [Replace a var() function](https://drafts.csswg.org/css-variables-1/#replace-a-var-function), step 2, looks up the computed value. Step 3 then tests the **named property** and the consuming property's animation category. Step 4 selects the supplied fallback after rejection. [Writing Modes 3](https://www.w3.org/TR/css-writing-modes-3/#propdef-writing-mode) declares writing-mode not animatable. Under these stated conditions, the fallback is `vertical-lr`, regardless of whether the preceding lookup returned `horizontal-tb`.

[CSS Animations 1 §3](https://drafts.csswg.org/css-animations-1/#keyframes) separately says a missing or invalid property keyframe is treated as absent for that property. This trace does not assume that every invalid animation declaration necessarily contributes an initial-valued endpoint: the relation between that invalid-keyframe rule and registered computed-time defaulting needs care. The taint conclusion instead uses the named property’s declaration in the matched rule, without inventing a winning-endpoint prerequisite. Malformed syntax discarded before a property declaration exists is outside this setup.

This direct rule does not establish a value-provenance-only policy. The word property does not by itself establish a stylesheet-global name bit across all elements. This trace deliberately restricts the scenario to a matched, active rule on the consuming element. It does not settle per-element versus wider ownership, unused rules, canceled-animation taint lifetime, an important ordinary winner, inheritance, script-created keyframes, or implementation metadata storage. No explicit registered-default exemption or winning-value-only condition is present in the deciding clauses above; that bounded reading is not an exhaustive absence proof across every CSS specification or future resolution.

The saved defaulting observation (`horizontal-tb` custom value and sink) remains an observation. It cannot prove that an engine filtered the keyframe, computed an initial animation endpoint, dropped metadata, or implemented a different scope policy. The observed value alone is insufficient to distinguish these paths. This trace also does not establish when a particular getter must flush, native implementation conformance, or a new accepted fix.
