# CSS-BREAK-3#possible-breaks

**Possible Break Points** (heading)

**SHA**: hash:d1847a93aa9f3cf56986329c048a0701fac305502a1605858912bec8b54192ad

## Content

Fragmentation splits boxes in the block flow dimension. In block-and-inline flow, breaks may occur at the following places:

Class A 

Between sibling boxes of the following types:

Block-parallel Fragmentation 

When the block flow direction of the siblings' containing block is parallel to that of the fragmentation context: [in-flow](2011#positioning-scheme) block-level boxes, a float and an immediately-adjacent in-flow or floated box, table row group boxes, table row boxes, multi-column column row boxes.

Block-perpendicular Fragmentation 

When the block flow direction of the siblings' containing block is perpendicular to that of the fragmentation context: table column group boxes, table column boxes, multi-column column boxes.

Class B 

Between line boxes inside a block container box.

Class C 

Between the content edge of a block container box and the outer edges of its child content (margin edges of block-level children or line box edges for inline-level children) *if* there is a (non-zero) gap between them.

> **Note:** There is no inherent prioritization among these classes of break points. However, individual break points may be prioritized or de-prioritized by using the [breaking controls](CSS-BREAK-3#breaking-controls).

> **Note:** Other layout models may add breakpoints to the above classes. For example, \[CSS-FLEXBOX-1\] adds certain points within a flex formatting context to classes A and C.

Some content is not fragmentable, for example many types of [replaced elements](CSS21#replaced-element) \[CSS2\] (such as images or video), scrollable elements, or a single line of text content. Such content is considered **monolithic**: it contains no possible break points. Any forced breaks within such boxes therefore cannot split the box, and must therefore also be ignored by the box’s own fragmentation context.

In addition to any content which is not generally fragmentable, UAs may consider as [monolithic](CSS-BREAK-3#monolithic) any elements with [overflow](CSS-OVERFLOW-3#propdef-overflow) set to [auto](CSS-OVERFLOW-3#valdef-overflow-auto) or [scroll](CSS-OVERFLOW-3#valdef-overflow-scroll) and any elements with overflow: hidden and a non-[auto](CSS-SIZING-3#valdef-width-auto) [logical height](CSS3-WRITING-MODES#block-size) (and no specified maximum logical height).

Since line boxes contain no possible break points, [inline-block](CSS-DISPLAY-4#valdef-display-inline-block) and [inline-table](CSS-DISPLAY-4#valdef-display-inline-table) boxes (and other inline-level [display types](CSS-DISPLAY-4#display-type) that establish an [independent formatting context](CSS-DISPLAY-4#independent-formatting-context)) may also be considered [monolithic](CSS-BREAK-3#monolithic): that is, in the cases where a single line box is too large to fit within its fragmentainer even by itself and the UA chooses to split the line box, it may fragment such boxes or it may treat them as monolithic.
