## Concrete source boundary

`find_non_custom_references` originally adds token-derived unit references only for LENGTH-capable syntax and adds COLOR_SCHEME for COLOR-capable syntax. `cascade_custom_property` uses this result both to defer a value and to seed the graph. Thus adding `may_reference_image` is more than an extra color edge: it can move an otherwise immediately computed image into DFS, where the existing reference walker also visits unit and attribute dependencies. That makes the image length failures plausible consequences of admission, but does not prove their cause.

Commit A should retain the prepared first-success AST, selected color/image/list classifier, old application-tail extraction, precise acyclic invalid initial selection and post-edge cyclic-default closure for registrations admitted by the original COLOR eligibility. Remove the added Image-only eligibility from `find_non_custom_references`. Recursive image classification still belongs in A: an `<image> | <color>` registration was already color-capable, and its selected image can contain scheme-dependent colors. Deleting that recursion would weaken union correctness.

There is a second eligibility seam. `invalid_custom_value_depends_on_color_scheme` is currently called for every cyclic registered custom property, including pure-image registrations already deferred because they contain var/attr references. Merely deleting `may_reference_image` does not remove all newly introduced pure-image behavior. A must limit this new post-edge default classification to the original COLOR-capable syntax as well. The existing loop/default handler itself must stay unchanged. This restriction needs exact source review and an isolated A run; it is not already implemented or validated here.

Commit B can then broaden both admission and the new cyclic-default eligibility to Image-containing syntax. It should reuse A's parser/classifier/default machinery rather than reintroduce a blanket image-to-ColorScheme edge. A broad edge would create false cycles for image/color unions selecting an independent identifier or absolute-color image. B has an explicit native prerequisite on A's machinery; it remains its own behavior change, tests and review. This is a dependent commit stack, not independent cherry-pickability: B cannot be applied or compiled against the original base without its required shared native machinery. If independent application to the original base is required, the same necessary machinery must be factored into a reviewed shared prerequisite rather than copied or silently bundled. No evidence yet justifies that extra refactor commit.
