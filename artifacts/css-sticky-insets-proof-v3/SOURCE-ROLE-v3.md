# Full-frame entry source interpretation

The new module binds the same complete `GetStickyScrollRangesForAxis` and `ComputeStickyDisplacement` extraction records already authenticated in SOURCE-BINDINGS.json; the native files have not changed.

- Frame2's sticky/sameContainer fields describe the selected-frame ancestor search before the scrolled-frame stop. Parent traversal, stable identities and correct same-container lookup are the prior external provider contract. The model proves the finite scan itself against filtered selection.
- Frame2.x/y describe the same canonical first-continuation geometry and the same property-presence epoch. Their framePosition and normal fields are the canonical frame's actual position and observed normal getter result. The prior raw geometry preparation (unions, padding/content transformation, containing-block mode and margins) remains the named provider frontier.
- Frame2.currentX/currentY/normalX/normalY describe the selected sticky frame, which may be a later continuation. They are deliberately separate from the canonical geometry fields. The final native nsPoint subtraction uses the selected sticky frame's observed getter, not a guessed canonical position. Missing NormalPositionProperty is represented by the actual getter's current-position fallback before supplying these inputs.
- The native range helper first canonicalizes, reads offset presence, and checks both insets on the requested axis. Missing/all-auto exits avoid the complete geometry helper. When reached, both core coordinate expression trees are evaluated. The model's full pair is related to nativeLimits on both coordinates before the selected range is derived.
- The displacement caller returns before the full point subtraction when neither range exists. Its selected frame position/normal subtraction evaluates both coordinates. Only then is x or y selected. The model uses a delayed shift provider to preserve this execution guard.
- Selected ranges preserve the previous optional near/far defaults, rejection branch, actual encoding/sentinel/debug-assertion exclusions and strict endpoint behavior. Full entry observation exposes both intermediate results for the proof; actual native calibration observes public return values and provider calls, not an invented native intermediate API.

The 48-case driver preserves the root's three original raw states and swaps entire coordinate data for the other physical direction. It varies actual container/eligibility/multiple/missing-offset/all-auto guards in native objects, not only the Lean gate. Complete extracted bodies are regenerated through the unchanged source extractor. Provider trace expectation is derived from the admitted prefix callbacks: 907 nearest scroll lookup (flags 7), 407 offset property on frame 7, 207 containing-block lookup, 1170 frame border union, 1121 containing-block content union, 1172 margin union, 700 scrollport size and 302 containing-block mode. Full entry uses that exact sequence; missing/all-auto stops after 907/407, multiple stops after two 907 calls, and no-container/no-sticky makes none of these calls.

The additional driver reuses visible v2 nsPoint/rectangle/property adapters. Root's shift overflow occurs in the nsPoint adapter; normalization overflow occurs inside the complete extracted core body. These are finite source-model admission checks, not proof that all adapters implement all native behavior. Existing exact-sum/saturation restrictions, all geometry-provider intermediate conditions, auto-code nonalias, debug sentinel-edge exclusions, coherent property epochs, layout scheduling and machine/library/compiler assumptions remain explicit.
