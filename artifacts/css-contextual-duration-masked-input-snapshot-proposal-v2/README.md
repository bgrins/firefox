# Masked duration input verification experiment

This is an uncompiled eight-file implementation proposal. It changes normal-restyle admission, not the timing-value policy. It has not been installed or tested in a browser. V1 was not browser-tested because its build failed; no outcome is inferred for v2.

`native.patch` starts from the accepted matching implementation, original animation manager and compositor behavior. When the existing full-update predicate is false but the target has a CSS animation collection, matching schedules a distinct verification task. On the main thread, Gecko resolves a fresh base style for the actual styled element and compares its complete typed animation-duration list with the collection's previous input. A changed or unsampled list runs the existing manager update using the existing composed style. An equal list skips that update. Full-update reasons always win and seed the input independently of equality.

This targets the masked authored-font mutation: an initial base duration of 1s is recorded even though the composed duration can be 2s. Changing the authored font makes the base input 2s and admits the ordinary manager update. An outline or same-value mutation with unchanged base duration does not reapply CSS timing or disturb a script duration override. These are predictions for the existing nine-case fixture, not measured outcomes of this patch.

The snapshot is an owned `nsTArray<StyleAnimationDuration>` in the existing collection. Equality includes the computed list length, order and typed Auto/Time values. It does not normalize repeated lists or compare effective/script timing. The computed list is nonempty; an empty snapshot means unknown. Creation and every full update seed it. Empty-animation cancellation destroys it with the collection; a recreated collection starts unsampled. The seed is written at the existing animation-array swap, before the cancellation loop, without adding a later raw collection dereference. Generic collection storage also adds an empty array to transition collections; this experimental memory cost needs review.

The FFI resolves using the original styled element, including a pseudo element, and stores using the manager's existing host plus `PseudoStyleRequest` collection key. It never falls back from a missing pseudo element to the host's style. Existing null/display-none cancellation remains before snapshot comparison. The verification-only path does not create a missing collection.

All eight old task bits are occupied. V1 widened the definition and Rust bitflags but missed the handwritten `GeckoBindings.h` forward declaration. The actual v1 build failed before browser execution with conflicting `uint8_t`/`uint16_t` declarations (root-reported owner 33133/e369a3/1). That is a real preparation/review omission; the prior identifier-use list was not a complete ABI declaration census.

V2 adds exactly one native change to v1: `GeckoBindings.h` declares `UpdateAnimationsTasks : uint16_t`. The other seven native postimages remain byte-identical. The enum definition, forward declaration and Rust bitflags now all use 16 bits. New text searches in `discovery/task-abi-text-layout.txt` and `task-abi-text-servo.txt` explicitly expose the forward declaration, ServoBindings.toml whitelist and cbindgen.toml rename. The configuration entries name the type without fixing its width, so they require no source edit. Typed wrapper `tasks.bits()` and the generated bindings still need a successful real rebuild; these textual/static checks are not a complete ABI or compilation proof.

Root receipt `css-masked-snapshot-forward-declaration-equivalence-v1.json` authenticates the newly captured header against HEAD ecfe, original-build revision 20ab and its original build pin. The new saved checker joins those hashes and rejects reintroducing the old forward width. V1, its failed run and its source bodies remain immutable.

## Synchronous transaction boundary

The task carries a target and reason, not a captured duration snapshot. Existing `Gecko_UpdateAnimations` dispatch is main-thread-only. The independently examined PresShell path wraps pending restyles in `nsAutoScriptBlocker`; RestyleManager asserts unsafe-to-script, rejects reentrant style refresh and uses `AutoAssertNoFlush`. The existing driver explicitly supports base-style recascade from sequential tasks after worker execution joins. Each context drops its caches before its own tasks; this is not a claim that every TLS object has already been destroyed before the first task.

The wrapper's immutable `ElementData` borrow remains live across the C++ call. This proposal only reads published Rust styles and writes C++ collection-owned storage. It must not acquire a mutable `ElementData` borrow, publish Rust style, flush or execute author script. Fresh base resolution produces an owned temporary style using immutable current-parent reads. Under these existing synchronous contracts, a separate queued-input generation is unnecessary for this experiment. This does not establish freshness across later tasks or an alternative entry path that violates those contracts.

## Limits and next falsification

Base recascade removes the target's own animation-origin rules; it is not a specification proof of a general pre-own timing policy. The manager still uses composed values. In particular, changing the base input to a value different from the animated value is outside this patch's correctness claim. Parent, root, font-load and device inputs can still be stale, and the unchanged animation-only exclusion still applies. This is not the parent barrier, finite-depth completion or cycle policy.

Scheduling a verification task for every otherwise-skipped normal restyle with CSS animations incurs a fresh recascade and typed-array allocation. No incomplete dependency flag is used to pretend that cost can safely be avoided. Collection lifecycle and existing synchronous manager assumptions are retained, not proved by a native refinement model.

First compile the eight sources with regenerated bindings, then run the existing nine-case masked fixture using an original baseline on the same source context. Retain all ordinary failures. The discriminating predictions are final masked duration 2s/opacity .375, unchanged outline/same-value timing, and preserved script override on both element and pseudo. A follow-up should cover creation, cancellation/recreation, list count/order and Auto changes. Do not expand this experiment to inherited first-read repair based on a pass.

No current matching overlay was read. `TRANSACTION-REVIEW.json` distinguishes saved source evidence from the independent reviewer's current guard checks.
