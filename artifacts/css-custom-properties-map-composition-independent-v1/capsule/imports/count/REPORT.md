# Custom-property live-count proof component

## Result

The repair's modeled count is exactly the cardinality of independently selected nearest-owner values. This includes deletion, resurrection, valid empty values, copy-on-write and arbitrary finite insertion/removal histories. Five modules contain 55 audited theorems. Four compiled-definition semantic mutants are rejected by the kernel. Complete native source binding is retained separately from the mathematical proof.

The index result is conditional on a raw iterator that enumerates each nearest owner exactly once. The count-only native candidate does not satisfy that iterator premise; its separate duplicate-ancestor defect is retained in `raw_iterator_premise_necessary`. The combined source is pinned for a later joint count/iterator capsule. This report does not declare the original whole-map or whole-CSS obligations complete.

## Independent reference and nonvacuity

The reference filters a finite key roster using nearest-owner lookup, rather than deriving cardinality from the repaired counter. Unique complete rosters are constructed from stored keys and future input keys. Lookup uses nested Options, so a tombstone blocks an ancestor while an empty `Some` remains live.

The original removal witness retains count 1 after a live entry becomes a tombstone although the reference count is 0. The original resurrection witness starts from the original algorithm's already inflated tombstone count of 1 and reaches 2 while one live key exists. It is not presented as an initially well-counted state. Additional witnesses cover value replacement, empty strings, actual expansion threshold, unique/shared paths and the raw duplicate iterator.

## Arithmetic and caller boundaries

A present old value derives nonzero stored count before subtraction. A missing old value plus a finite-roster bound derives increment headroom. Lists model finite parents; Arc lifetime, allocator behavior, IndexMap, compiler execution and actual ancestor metadata remain admissions. A true native payload comparison must imply semantic equality only for the value-history theorem; count and index safety do not require that assumption.

All complete source, proof, checker and mutation inputs are manifest-authenticated before replay output is created. Replay uses a separately supplied pinned Lean toolchain and its standard library. It does not run Firefox, Rust compilation or browser tests. Browser matrices and independent native review remain root-owned evidence, not results of this replay.
