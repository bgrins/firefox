# Typed structured-data codec boundary

This artifact consumes the unchanged first-order escape JSON fixture; it does not derive a new CSS algorithm from prose. The reusable `JsonCodec` and standalone `Runner` import neither the old Python emitter nor any generated escape tree/reference bridge. All parser/checker recursion is structural, including the mutual fold over Lean's JSON, array and object-tree representations. There is no arbitrary fuel or partial definition in the new Lean modules.

## Universally proved layer

`Codec` defines untyped constructor data (`DataExpr`, `DataStmt`) and encodes the existing intrinsically typed `Var Γ t`, `Expr Γ t`, and `Stmt Γ t`. The expression checker infers a result type, checks every operand and variable against the explicit context, then casts only with a proved type equality. Statement checking takes an explicit result type. The fold context is scalar :: nat :: Γ; read's present branch and scan's predicate bind a scalar, scan's continuation binds a scalar list, and let binds its inferred type.

`Laws` proves variable/expression/statement encode/decode roundtrips for arbitrary finite trees, contexts and result types. The exported checked expression/statement decoder additionally compares re-encoding to normalized input. Its accepted-result theorems establish exact opcode, literal, variable-index and statement structure fidelity at this **constructor-data layer**. Normalization removes only alias scope wrappers; the preliminary checker still requires the wrapper's declared head to match the actual context. This guard is deliberate: type checking alone cannot detect a wrong in-scope variable or same-type opcode. It does not make the JSON-to-constructor adapter universally verified.

These results do not prove a JSON text serializer/deserializer roundtrip. There is no theorem for arbitrary JSON schema interpretation, no typed AST JSON encoder, no universal alias weakening theorem, and no proof of the standard JSON parser. Accepted-result erasure preservation is not a proof that the caller supplied the CSS-correct algorithm.

## Actual JSON path

`JsonCodec` traverses `Lean.Json` values and admits only exact `op`/`args` object fields and matching tag arities, primitive argument kinds and Unicode scalar literal bounds. It explicitly dispatches the existing tags into constructor data. Unknown tags and unsupported executable-text fields have no interpretation. The top-level version, field set and four definition names are checked. `source_map` must be an object and is inert provenance, not executable data; its contents are not semantically validated by the decoder.

The four legacy `use` aliases are parsed with an empty alias environment, then checked at their declared singleton context and result type. Alias references within definitions, including cycles/chains, are rejected. Use sites insert a scope wrapper and recheck the body under the actual context. Singleton checking prevents capture of extra ambient tail variables. This adapter follows the fixed old fixture schema, not a general recursive macro language.

`FixtureJson.lean` quotes the exact preserved `escape.json` bytes with Lean's standard `json%` syntax. The checker verifies literal byte equality. `fixture_decodes` is a kernel-checked `rfl` theorem that decoding this structured JSON value returns the previously proved `escapeTree`. `fixture_relation` then connects execution to the existing `CssEscape.Escaped` relation, preserving the returned scalar, exact unread suffix and EOF error. This concrete equality also checks alias expansion and JSON tag selection for this fixture. Standard JSON quotation/elaboration and the source text linkage are explicit external boundaries; quotation is not an independently proved JSON parser.

`Runner.lean` imports only `JsonCodec`, reads the actual file, uses standard `Json.parse`, checks it, and executes the resulting typed program. `RuntimeCheck.lean` independently compares its canonical encoded tree to the proved fixture before executing the parsed program. Both are run against the same expected outputs. The runtime comparator never substitutes the reference program for the decoded value. These runs are observations about the actual text parser, not universal parser proofs.

Lean's JSON object representation has already collapsed duplicate keys; its parser keeps the last occurrence. The decoder cannot subsequently reject duplicate text keys. Natural-number recognition follows `Json.getNat?`'s representation, not Python's old `int` predicate: e.g. `1e1` and `1.0e1` are accepted as 10, while `1.0` and `10e-1` are rejected. Signed zero is accepted. `PARSER-EXPECTED.json` freezes these observations, including duplicate-key order; no lexical compatibility with the old emitter is claimed. The preserved fixture itself has no such keys or numeric spellings.

## Existing semantic/source boundaries

Nine reference Lean modules and the JSON fixture are copied unchanged from signed origin `037d606ccd27`; root independently authenticated them in `ROOT-ORIGINS.json`. `PRESERVED.json` pins them for source-only replay. `CLAUSES.json` is copied unchanged from the earlier first-order artifact, retaining seven reviewed AST-pointer links, exact excerpts, original byte ranges and the full snapshot hash. These links are traceability evidence, not mechanically proved prose interpretation.

The normative source remains [CSS Syntax at c410ee5e4d2afe6d8b2e8ce53723b8d1eb3b5b67](https://github.com/w3c/csswg-drafts/blob/c410ee5e4d2afe6d8b2e8ce53723b8d1eb3b5b67/css-syntax-3/Overview.bs) ([consume an escaped code point](https://drafts.csswg.org/css-syntax-3/#consume-escaped-code-point)); character definitions were inherited from the pinned [Infra source at c67ae1fb1d161b23d0f8c9bf9917ea1993f7b19a](https://github.com/whatwg/infra/blob/c67ae1fb1d161b23d0f8c9bf9917ea1993f7b19a/infra.bs). No latest-draft coverage claim or fresh source extraction is made here. Full source snapshots remain in the preceding artifact; this capsule only needs the existing reviewed excerpts and proofs.

Shared pure arithmetic/character primitives, the reference relation's interpretation of CSS, source-to-AST choice and caller obligations remain unchanged. The input is a scalar list; CSS conformance additionally requires the earlier normalized/validated escape caller contract and an already-consumed backslash. Raw DOMString coercion, byte decoding, native cursor/reconsume behavior, Firefox execution, and memory safety are not proved.

## Validation interpretation

Every new and copied theorem is audited; only standard `propext`, `Quot.sound`, and `Classical.choice` dependencies are allowed. Semantic mutants must first compile, then fail an unchanged theorem and a concrete proposition that Lean's `decide` explicitly proves false. Same-type opcode/index and scan changes test the generic codec; bypassing its fidelity guard tests why the guard exists. Alias-head loss tests a condition not exercised by canonical encode/decode alone. JSON opcode mutation tests the concrete fixture bridge; admitting an extra field tests the schema boundary. Hash/literal drift controls test provenance refusal. No negative control is accepted merely because an arbitrary build failed.
