# Opt-in hidden embedding-frame refresh candidate

This is an uncompiled experimental candidate, not an accepted repair. The installed-stack diagnostic found hidden-only and hidden-resize viewport reads at30/15, with recovery after the combined host-geometry → iframe-geometry → child-client sequence. That does not isolate the effective recovery query or prove the native fallback branch. Hiding's pre-read computed-style and host flush may already publish fallback before SVGLength.value. Normalized HEAD reproduction is mandatory; installed114 cannot be presumed either necessary or irrelevant.

## Five-path API change

ChangesToFlush gains default-false mFlushHiddenEmbeddingFrames. Document::FlushPendingNotifications carries it through its existing recursive parent flush. The existing same-in-process DocGroup, parent MayStartLayout and child IsSafeToFlush conditions are factored into one local predicate and reused. After the ancestor request completes, a retained parent identity and the same policy must still hold. The active embedder is acquired into a strong reference, must remain in that parent document, and receives GetPrimaryFrame(Layout). No raw frame is retained across this call. The child's normal flush then completes against the updated embedding geometry. Propagation processes a nested same-observable chain from outer provider to inner consumer; it does not invent a separate cross-document traversal.

SVGLength::IsViewportRelativeUnit uses the existing private VW..VMAX range, so UNKNOWN and unrelated units do not opt in. DOMSVGLength's public API flush boundary sets the flag only for viewport-source units. Shared SVGElementMetrics remains a non-flushing provider: its callers include SVG layout/pattern/filter computations and SMIL conversion, so putting synchronous layout in that metrics accessor would broaden reentrancy substantially.

Normal calls retain default-false behavior and existing animation/relevancy flags. The additional targeted query repeats a parent layout request; no performance guarantee is made. Existing forced-hidden layout still requires its target frame to be dirty. The candidate does not bypass that requirement, force remote/cross-group documents, guarantee readiness when loading/safety gates reject a flush, or prove arbitrary navigation/callback lifetime behavior. Parent identity and active-embedder checks prevent intentionally querying a stale embedding relationship after the first flush; no frame is used afterward.

## Standalone and installed variants

standalone.patch is against exact HEAD90, with only these five paths. It preserves the old DOMSVGLength optional-target API absence, old font/percentage destination readiness behavior, and old absolute-factor table. It adds source viewport style flushing and, after readonly/invalid-unit checks, source-only viewport flushing before conversion. Ownership is reacquired by the existing subsequent conversion dispatch. A viewport source cannot equal a valid public target (1–10), so this added branch does not change same-unit identity. The existing font/percentage conversion failures must remain classified rather than be demanded to pass.

These source-viewport steps overlap the relevant subset of expanded114 and must be documented when organizing standalone commits. They do not silently import114's destination-unit conversion repair or115's factors. installed-overlay.patch composes the new flag/helper/provider behavior onto installed expanded114+115, preserving their existing conversion and factor changes. Both variants apply and reverse to exact bytes in disposable directories. Changed-line clang-format checks exit0 with no byte changes. Neither candidate has been compiled, installed, or browser-tested. SOURCE-PINS.json records both exact roles; candidate/ is standalone and installed-candidate/ is the overlay output.

## Next validation

First compare normalized HEAD with the standalone candidate. Root now plans 24 landing cases plus 28 existing controls (52 total), including first-operation getters and conversions to px. Its nested fixture hides only the outer host; hidden containers at both embedding levels remain additional follow-up coverage, not a current claim. Do not assume the one-level diagnostic proves nested propagation. Require visible and absolute controls, warm/default/reveal/reset calibrations, complete raw identities and copied observations. Record first failure only when later assertions are not reached.

Retain existing SVGLength viewport getter/SetValue controls, ordinary font/percentage conversions, invalid/readonly/detached/same-unit behavior and actual historical failure metadata. In particular, do not demand unrelated114 target-only failures to pass on this standalone candidate. Later installed-stack integration must preserve114+115 before packaging. If the candidate does not repair the normalized witness, stop and trace rather than widening the policy speculatively.

A one-file nsSubDocumentFrame trace is sufficient as the next causal probe if needed: uniquely marked iframe/case identity, GetInitialSubdocumentSize detached-shell versus fallback choice, ShowViewer FIRST_REFLOW before/after Show, and actual Reflow dimensions/callback. Bind event ordering to the same case and frame lifetime; pointer alone is insufficient. This proposal introduces no logging.
