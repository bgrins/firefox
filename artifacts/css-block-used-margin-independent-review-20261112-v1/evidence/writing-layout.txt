# CSS-WRITING-MODES-3#vertical-layout

**Principles of Layout in Vertical Writing Modes** (heading)

**SHA**: hash:9e381f5a9c2e1633fcb46e277652b032fdc2a56420cc55aed39e5b137e96920e

## Content

CSS box layout in vertical writing modes is analogous to layout in the horizontal writing modes, following the principles outlined below:

Layout calculation rules (such as those in CSS2.1, Section 10.3) that apply to the horizontal dimension in horizontal writing modes instead apply to the vertical dimension in vertical writing modes. Likewise, layout calculation rules (such as those in CSS2.1, Section 10.6) that apply to the vertical dimension in horizontal writing modes instead apply to the horizontal dimension in vertical writing modes. Thus:

*   Layout rules that refer to the width use the height instead, and vice versa.

*   Layout rules that refer to the \*-left and \*-right box properties (border, margin, padding, positioning offsets) use \*-top and \*-bottom instead, and vice versa, mapping the horizontal writing-mode rules of CSS2.1 into vertical writing-mode rules using the [flow-relative directions](CSS-WRITING-MODES-3#flow-relative-direction). The side of the box these properties apply to doesn’t change: only which values are inputs to which layout calculations changes. The [margin-left](CSS-BOX-4#propdef-margin-left) property still affects the lefthand margin, for example; however in a [vertical-rl](CSS-WRITING-MODES-3#valdef-writing-mode-vertical-rl) writing mode it takes part in margin collapsing in place of [margin-bottom](CSS-BOX-4#propdef-margin-bottom).

*   Layout rules that depend on the [direction](CSS-WRITING-MODES-3#propdef-direction) property to choose between left and right (e.g. overflow, overconstraint resolution, the initial value for [text-align](CSS-TEXT-3#propdef-text-align), table column ordering) are abstracted to the [start](CSS-WRITING-MODES-3#css-start) and [end](CSS-WRITING-MODES-3#css-end) sides and applied appropriately.

> **Example:** For example, in vertical writing modes, table rows are vertical and table columns are horizontal. In a [vertical-rl](CSS-WRITING-MODES-3#valdef-writing-mode-vertical-rl) [mixed](CSS-WRITING-MODES-3#valdef-text-orientation-mixed) [rtl](CSS-WRITING-MODES-3#valdef-direction-rtl) table, the first column would be on the bottom (the [inline-start](CSS-WRITING-MODES-3#inline-start) side), and the first row on the right (the [block-start](CSS-WRITING-MODES-3#block-start) side). The table’s [margin-right](CSS-BOX-4#propdef-margin-right) and [margin-left](CSS-BOX-4#propdef-margin-left) would collapse with margins before (on the right) and after (on the left) the table, respectively, and if the table had auto values for [margin-top](CSS-BOX-4#propdef-margin-top) and [margin-bottom](CSS-BOX-4#propdef-margin-bottom) it would be centered vertically within its block flow.
>

For features such as text alignment, floating, and list marker positioning, that primarily reference the left or right sides of the line box or its longitudinal parallels and therefore have no top or bottom equivalent, the [line-left](CSS-WRITING-MODES-3#line-left) and [line-right](CSS-WRITING-MODES-3#line-right) sides are used as the reference for the left and right sides respectively.

Likewise for features such as underlining, overlining, and baseline alignment (the unfortunately-named [vertical-align](CSS-INLINE-3#propdef-vertical-align)), that primarily reference the top or bottom sides of the linebox or its transversal parallels and therefore have no left or right equivalent, the [line-over](CSS-WRITING-MODES-3#line-over) and [line-under](CSS-WRITING-MODES-3#line-under) sides are used as the reference for the top and bottom sides respectively.

The details of these mappings are provided below.
