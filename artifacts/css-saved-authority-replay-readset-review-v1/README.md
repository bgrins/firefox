The seven-function memoization boundary is useful, but a file-content recorder alone is insufficient. This review inspected the exact proposal, recent saved refresh/admission/build-binding callees, the V118→V117 saved-admission entry and the local Python import loader. It did not execute a validator, benchmark, live operation or memo implementation. SOURCE.json retains the concrete callsites; this is not a proof that every earlier historical callee has been enumerated.

| Integrated native refresh `saved`: `not list(runtime.glob('*-wpt-*'))` and absent `original-build` | Record the directory query, pattern and result, including an empty result. Creating a matching directory must invalidate a hit even if FILES.json and every previously read file are unchanged. |

The local CPython `SourceFileLoader.get_data` uses `_io.open_code`, rather than `Path.read_bytes`. Its `get_code` attempts an existing bytecode cache before consulting `sys.dont_write_bytecode` for cache writes. Thus `-B` is not sufficient to make source-loader reads disappear. PYTHON-IMPORT-SOURCE.json pins the inspected local source. The implementer's proposed source-only `exec_module` can explicitly eliminate bytecode authority for artifact modules; that is a documented restriction, not proof that an ordinary loader was recorded by Path hooks. Reject unsupported loaders or record their actual execution inputs.

The smallest practical implementation is the proposed scoped wrapper for exactly these seven functions, with authenticated source/code-plus-qualified-name identity and complete mutable binding/argument/top-policy scope. Python callable object identity would defeat sharing across fresh module instances. Keep live observation, signatures, claims, process checks and the outer policy control flow uncached. The original successful validator remains the producer; return a deep copy only after its transitive ledger has been revalidated. Do not cache failures, incomplete recursion or inconsistent repeated reads. Before using a hit, freshly hash all consumed contents and recheck all recorded facts; a changed input never borrows old success.

Two implementation details still need focused controls. First, directly decoding captured bytes does not generally preserve `Path.read_text` newline/encoding/error behavior. Preserve the original text semantics over the byte snapshot and test CRLF plus UTF-8. Second, patching builtin/io/os `open` alone is not a general unknown-I/O barrier: `_io.open_code`, `FileIO`, pre-opened handles and other loaders can bypass those names. Bound the claim to the authenticated reviewed call graph and reject unsupported routes, or add an effective lower-level guard. This review does not establish a general Python I/O sandbox or an atomic filesystem snapshot against arbitrary concurrent writers.

The implementer confirmed coverage for Path reads, stat/lstat/existence/type/resolve queries and glob/rglob/iterdir; direct os stat/lstat/readlink/listdir; source-only artifact imports; blocked process/open operations; shared entries and child-ledger merge.
