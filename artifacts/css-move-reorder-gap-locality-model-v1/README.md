# Arbitrary same-parent insertion gaps

This extension closes the prior block-shape assumption: every valid removal/reinsertion gap is reduced to a contiguous moved interval. It imports the three sealed predecessor modules by exact hashes, without changing or duplicating their source. It adds no native refinement, discovery, acceptance, or canonical coverage total.

The initial child list contains node, and the concrete operation satisfies `before.erase node = front ++ back`; the result is `front ++ node :: back`. The gap is in the list AFTER removal. The first theorem splits the original list at node, evaluates erase, and compares the old and new prefixes using List.append_eq_append_iff. It derives either a rightward block rotation or its reverse, with explicit `left`, `middle`, `right` lists. No locality premise occurs in this derivation. The decomposition even works without uniqueness using the first occurrence; DOM-like use adds Nodup and the previously proved ownership partition.

Both directions have the same contiguous affected block: node together with middle. The existing block locality lemma now applies to arbitrary valid gaps, proving index equality for elements unequal to node and absent from middle. The numeric theorem goes further: under Nodup, every block member's ORIGINAL zero-based index lies in the inclusive interval `[left.length, left.length + middle.length]`. This is derived using list membership, prefix disjointness and idxOf bounds. An original index outside that interval therefore stays unchanged. No unchanged-value premise or assumed index correspondence is used. One-based sibling-index follows by adding one.

`valid_world_interval_fresh` composes that result with the exact parent-to-ordered-children model. For an initially well-formed partition, a node owned by the reordered parent, and any valid post-erasure gap, it derives a well-formed result, equality of every sibling-count, and count/index freshness after refreshing only nodes of that parent whose original indices lie in the derived inclusive interval. Nodes outside that parent retain their full sibling list; nodes outside the interval inside it retain index and count. The imported refresh operation presumes initially fresh cached values and actual recomputation for selected entries. Delivery, timing and native cache execution are not proved.

`original_gap_identity` proves reinsertion at an equal-length original gap gives the identical list, using prefix cancellation after erasure. This is a list/value identity, not an observable DOM no-op. The boundary example checks a leftward move to the beginning, a rightward move to the end, original-gap reinsertion and a singleton. The universal theorems impose no positive prefix/suffix/middle lengths, so these cases are not excluded. The notified interval is sufficient, not claimed minimal: when middle is empty, even the moved node retains its value, yet the interval strategy may conservatively refresh it. This package does not prove every interior index must change or an exact minimal notification set.

Two semantic false controls use the same refresh function. Rightward [0,1,2,3]→[1,2,0,3] with only moved0 refreshed leaves stationary1 stale. Leftward [0,1,2,3]→[2,0,1,3] with moved2 and only the strict interior refreshed leaves the original lower-endpoint node0 stale. They reject missing stationary updates and replacing the required inclusive interval with its interior. All indices in these witnesses refer to present unique nodes.
