# Relative overflow fragments: separate diagnostic

The exact retained flex caller passes ReflowChildFlags::Default to ReflowOverflowContainerChildren before and after the retiming patch. The ordinary block caller also passes Default. The helper builds child-writing-mode position (previous IStart, 0) and forwards the flags unchanged to FinishReflowChild. FinishReflowChild calls ApplyRelativePositioning only with its explicit flag, whose value is absent from Default. Therefore this route inherits the previous used inline offset without applying it again, and resets the block offset to zero. This explains constant inline translation and disappearance of relative block translation after the first fragment; the earlier proposed inline accumulation concern does not apply to this path.

CSS Break 4 section 5.5 applies relative positioning after fragmentation and per fragment. It explicitly defines an overflow-only fragment origin as the zero-sized box at the start of its fragmentainer. A constant pixel block inset has no dependency on where content fragments. These provisions support a constant translation diagnostic for overflow fragments as well as ordinary fragments. The retained full section is spec-relative-fragmentation.json. Browser attribution of the actual native branch still requires evidence; no new repair or acceptance is claimed here.

The new horizontal-tb diagnostic removes vertical-rl final-width conversion. It records each descendant rectangle before, during, and after 0/±17px block or inline positioning, for row-flex, column-flex, and ordinary block parents. Fixed 80px subjects create overflow-only continuation candidates; auto block-size subjects provide normal-fragment controls. Every case calibrates unshifted rectangles against four separate 100×160px boxes at inline origins 0,100,200,300. A failed calibration excludes that shape from normative comparison. The assertion is the measured shifted-minus-unshifted translation, without relying on block layout as a reference oracle. Repeated reads retain parent/subject fragments, other items, computed offsets, and exact restoration.

This is a separate preexisting-behavior lead. It does not change the standalone final-size retiming patch, and cannot establish arbitrary descendant or overflow-container conformance.
