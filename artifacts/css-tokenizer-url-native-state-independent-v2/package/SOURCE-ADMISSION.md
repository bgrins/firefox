# Actual URL state and raw capture correspondence

## Claim and independent observations

This component models the actual stored position, modulo-2^32 line-start field and packed line/block field. Its loop proofs derive those fields from helper assignments and compare them with the predecessor's independently folded source-prefix observation. They do not set the native poststate to that observation. `URLNativeBorrowed.captured_source` derives BadUrl bytes from actual raw capture endpoints and the original source; it does not assign the expected payload to the model.

The decoded URL/name/escape semantics and quoted string completion relation remain the accepted predecessor's claims. This component closes the selected actual-state and raw-slice model bridges. It is not a verified compiler translation of Rust, a Rust library correctness proof, or proof of every public Parser history.

## Source map

`SOURCE-BINDINGS.json` retains 44 complete definitions from the exact tokenizer/parser snapshots, including each complete URL function (the three nested functions are also bound separately), escape/hex helpers, byte/character movement, slices, state accessors, caller and observer providers. `FIELD-BINDINGS.json` adds five complete field/constant declarations. Both inventories are regenerated by the checker. Source snapshots and compiled vendor files must have identical hashes. `LIVE-SOURCE-COMPARISON.json` is a read-only identity observation, not a new browser/build receipt.

## Top-level versus internal admission

`TailValid` intentionally admits leading continuation bytes in an internal byte loop. It is not top-level Rust string validity. `URLNativeLeading.body_valid` derives aligned body input after an ASCII whitespace prefix from whole-input `StringUTF8.Valid`; `admitted_body_metadata` composes this with full state execution. `captured_marker` takes whole structural validity, actual entry assignment and captured endpoint. Mapping its marker to Rust `str::is_char_boundary` still uses the actual canonical UTF-8 representation/codec contract. Structural `Boundary.Unit` validity alone does not establish canonical Unicode, Rust allocation provenance or unchecked memory safety.

The source-bound entry is after a successfully consumed `url(` name/open parenthesis at a character boundary. The prior name/caller component and actual full-crate replay supply the selected caller bridge; arbitrary externally forged parser states are not admitted. The generalized prefix theorems preserve a caller-supplied earlier source prefix and start position; they do not assume the desired final raw bytes.

## Machine and provider premises

- Position/count/index arithmetic is mathematical Nat in Lean. Native admission requires source and intermediate positions within the actual input allocation and usize arithmetic bounds. Derived counts/ranges/terminal markers supply list bounds; they do not prove allocation validity or compiler behavior.
- The line-start field wraps modulo 2^32, including the u32 cast of a large byte position. No no-underflow assumption excludes astral input.
- `advanceLine` models both shifted-count truncation and packed addition. Its ordinary native/reference relation explicitly requires `count < 2^30` and `packed + count*4 < 2^32`; per-path `Admitted` supplies the latter at each newline. Leading scan counters are monotone from zero; the bulk bound also bounds their u32 increments. Behavior beyond these domains is not promoted to an unbounded line theorem.
- A stored source column is modulo 2^32. Equality to an unbounded reference column additionally requires that column below 2^32.
- Rust canonical UTF-8 decoding/encoding, byte indexing/slicing, collection allocation and normal return, standard-library implementation, compiler and machine execution remain premises. Exact-source builds exercise them on the fixed corpus; no universal heap or compiler proof is claimed.

## Seam and observer precision

`URLNativeLeading.Result.function s` is the unchanged `Err(())` seam from `consume_unquoted_url`. It is not the final Function-token state. The caller subsequently sets the Parenthesis low bits and observes the function. The native adapter records entry/exit before that caller transition and checks the final low-bit transition separately. Quoted leading whitespace is intentionally rolled back at this seam. The predecessor's completed whitespace/string relation remains appropriate; exact intermediate CSS-spec cursor equality is still false.

No URL helper writes sourceURL/sourceMappingURL annotations in the retained source. The fixed native corpus checks explicit Option absence, not a rendered-empty conflation. General initial annotation preservation and speculative cache/reset observer histories remain in their separate component scopes; this package does not claim all public-history equivalence.

## Native evidence and limits

The adapter compiles the complete actual cssparser crate and dependencies offline, in debug, release and actual fast_match_byte release modes. Instrumentation redirects selected helper and slice calls to wrappers that invoke the unchanged original methods, records the three real state fields through a read-only accessor, and records the leading bulk counters before assignment. Entry and exit are captured around the unchanged URL provider before the parent Function transition. An uninstrumented build independently retains every first token and final field tuple.

The Python reference reads Unicode scalars from the original source, derives byte-prefix/UTF-16 fields independently, and checks every actual helper argument/transition, slice start/bytes/marker and bulk counter. The Lean driver computes the entry from the name provider and original source, then executes the new complete native-state model; no actual output state is supplied as its expected final state.

The corpus is the predecessor's 57 inputs plus two documented bridge cases. One checks a bad-URL escaped close at EOF. One unquoted CRLF/CR/FF/UTF-8 counterpart was required after a bulk-field mutation survived the first 58 because their only leading-newline input rolled back to a quoted string. The failed discrimination log is preserved; the checker freshly reproduces that old-58 survival and rejection with the added case. No new browser defect is claimed.

## V2 ordered trace correction

V1's finite native validator accepted individually valid observations without requiring their complete order/presence, ignored unknown event tags and admitted trailing fields. That is a validator defect, not evidence of a native URL bug or a failure of the unchanged Lean theorems. The v1 capsule and independent failed-validator evidence are retained.

V2 derives the entire expected per-case event list from source bytes alone. Its separate Python interpreter decodes the initial name to establish URL-call eligibility, computes the leading scan/rollback, tracks borrowed versus owned output, and follows each escape, URL-end and bad-remnant branch. Actual state is not supplied to this reference. Helper fields are derived by the independent scalar-prefix observation; slice start/end/value come from the reference cursor and original source. Bulk position-before-field-update and the final Function caller bit transition are separately represented. Comparing complete lists enforces case order, event presence/multiplicity/order, exact values and continuity. Explicit grammar validation also rejects unknown tags and incorrect arities. No current trace or saved expected trace is read to generate the expected list.

The native gate additionally asserts the fixed 59-case inventory totals, but those totals are only a drift check. They are not the trace oracle. Trace mutation checks delete/duplicate/retag/alter arity at every observation and swap every adjacent pair, then challenge whole observation classes and the exact five reviewer traces. V1's accepted corruptions are freshly reproduced with its pinned historical validator before v2 rejection.

The Python control interpreter is a manually source-corresponding validation program, not a new universally verified translator. Its identifier-like entry is the fixed corpus's caller domain; the complete separate Lean/native caller gate remains. It models normal-return source paths and current trace instrumentation. Allocation failure, panics, malformed external UTF-8 and overflow outside admitted headroom have no success trace guarantee. The corpus and all Rust/Lean/native instrumentation bytes are unchanged. These stronger finite observations do not discharge the existing codec, compiler, heap or public-history premises.
