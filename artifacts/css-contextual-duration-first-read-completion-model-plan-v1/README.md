The new trace provides a much narrower bridge than an abstract starvation assumption. In all four stale first queries the child Animations entry is absent at entry, the middle key is removed for traversal, a child request then creates Pending under Servo=1/styleRefresh=1, posting defers, and the child remains Pending in the return snapshot. The returned text is 0.428571. Exact keys and sequences are in TRACE-BRIDGE.json: lh ordinary query 45, lh animated 81, rem ordinary 39, rem animated 70. There is no logged child post attempt, hint or removal after that new request before return. This is a finite observed interval, not a claim about every native removal path. Literal chain and property-only controls instead consume their child work inside the first query and return the expected value; removal itself is still not proof of actual composition.

Recommended first proof scope is a concrete finite chain, with a later optional DAG generalization. Use nodes 0..n, fixed external input at node 0, and the local deterministic transfer value[i+1] := value[i]. Start after an external change with value[0]=true and other values=false. Define local stale edges by unequal adjacent values. This symbolic change is not a CSS numeric formula or Gecko animation-generation counter. It models dependency propagation independently of sender bookkeeping.

A snapshot round takes the stale work present at round entry, moves those keys into an explicit in-flight set, and evaluates them from the pre-round predecessor values. Removing a queue entry only transfers its obligation into in-flight; completing evaluation updates its value. After the round, newly inconsistent successors are enqueued through QueueState.request in a blocked context, retaining Pending. The frontier and relevant-work coverage must be derived from these operations, not assumed as a desired freshness premise. The trace motivates late generation after an earlier selection, but does not establish that every native traversal obeys this exact round algorithm.

Proposed useful claims, in order:

1. Derive the dirty-work coverage invariant for the concrete operations: each locally stale relevant edge is represented by non-throttled queued work or in-flight evaluation. Request/attempt/removal alone must not discharge it. Cancellation or removal from the query's dependency closure requires a distinct justified transition; arbitrary consume is not successful evaluation.
2. Prove that a round can empty its entry frontier and still generate a new relevant Pending successor. Use a two-edge example matching the observed ordering to reject an entry-frontier-empty return rule. Do not assign native trace events unlogged composition-version changes.
3. Derive the exact chain propagation formula from the transfer operation: after k rounds, precisely the prefix through min(k,n) has the new input. Thus for every fixed total budget k, a chain of k+1 edges leaves its leaf stale and relevant Pending work at the return boundary. This proves no uniform fixed round bound follows merely from finite acyclicity for this scheduling class. It does not prove every native pass crosses only one edge, or that a depth-complete topological traversal cannot finish in one call. A repair adding a constant number of native passes needs a separate depth-independent closure argument.
4. Prove local consistency implies the unique current-input chain value by induction. Combine it with the derived coverage invariant and empty relevant queued/in-flight sets to establish first-read freshness. Queue emptiness alone is insufficient without coverage, and DispatchAttempted counts as unfinished until evaluation completes. Blocking all relevant Pending is conservative: some redundant requests may not change a returned value.
5. Show a depth-dependent drain reaches completion for this fixed finite acyclic chain, using the remaining stale suffix as a decreasing measure. This is an abstract successful evaluation algorithm, not a prescription for an unrestricted native loop. Only after this concrete result is useful should a finite DAG/topological-order version be considered.

The return obligation is query-relative: the current transitive dependency closure must be complete and its input/timeline snapshot stable. A global Pending entry unrelated to the requested value need not block return. A newly generated relevant Pending entry cannot be ignored merely because an earlier pass selected no more work or already attempted dispatch. The proposed invariant earns the no-work-to-freshness implication; defining Ready as freshness and proving Ready implies freshness would add nothing.

Meaningful false controls should reject: return after the initial frontier empties; treat a dispatch attempt as completion; clear an entry without evaluating it; claim two rounds suffice for a three-edge chain; and drop a dependent edge from relevance. Also include a positive unrelated queued key to prevent accidentally proving a global-drain requirement. None of these controls has been implemented or checked yet.

Native correspondence remains external. The work graph, static relevance, completed evaluation, unchanged time/input, pseudo/document/subtree eligibility and reentrant mutation rules need source and test evidence. WillComposeStyle and pre-remove-consumed are preparation/removal observations, not value evaluation logs. The four captured keys and exact returned CSS strings establish correlation; no model state should invent a native composition generation from them. The actual strict join authenticates 258 queries and 204 posted CSS fields, not effect-timing API return events.

Cycles remain a separate specification and implementation question. Self-dependent font/duration feedback does not have a topological rank and may have no fixed point or several. Arbitrary DOM/script changes during a flush can also defeat the fixed-input measure. Do not turn the finite-chain theorem into a convergence proof, silently impose a fixed iteration cap, or invent a cycle policy. A real implementation must identify its permitted cycle behavior separately. No accepted-fix or canonical Lean coverage count changes.
