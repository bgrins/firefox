# Retained registered-endpoint resolution: executable first stage

This proposal adds a callable current-provider resolver and two real-presentation host tests. It is **not the active-provider fix**: normal operation samples still contain only concrete operands, and winning pending roots are not yet admitted or scheduled. The original ten-case fixture is unchanged. No native source was applied, compiler/build/browser was run, or canonical/index/ledger state changed.

`native.patch` changes three Rust files. `tests.patch` adds two tests to the existing presentation host and a separate four-case WPT. `full.patch` composes them. PREIMAGES and SOURCE-CORRESPONDENCE pin the exact current target bodies read for the root-designated cc19 source state, without asserting a newly measured HEAD/index epoch. Easing code is outside this proposal.

## What runs when the new API is called

`Servo_KeyframeEndpoint_ResolveRegistered` accepts the retained descriptor, target/pseudo, supplied immutable computed provider style and current document data. It creates fresh animation Context, cache conditions, tree-counting caches and AttributeTracker for every call. It explicitly seeds the map from the supplied style. It does not flush style, advance timing, update an effect, mutate the input ComputedStyle or look up a cached segment AnimationValue. Parent/container/font/color inputs follow the existing animation-context constructor; caller must supply a coherent current style/target/document snapshot.

`KeyframeEndpoint::resolve_registered` consumes that Context by value. Its input is the selected original custom declaration, not the other declarations retained alongside it. Sibling keyframe declarations must not overwrite the current animated provider map. Registration is looked up anew through Stylist. The resolver preserves full CustomAnimatedValue metadata through `from_computed`; it does not compare numeric equality or reconstruct tokens from an old number.

For unparsed declarations, a narrow builder path prepares typed-attribute references with original namespace/URL provenance and uses the existing dependency walk to resolve those attributes. It omits finish_cascade_custom_properties and its map-reuse heuristics: a supplied provider snapshot is not a fresh ordinary cascade to optimize. Actual substitution, registered syntax conversion and genuine invalid-value defaulting reuse `substitute_references_if_needed_and_apply` / `handle_invalid_at_computed_value_time`. Temporary endpoint publication is confined to the consumed context. The wrapper returns a value only with Resolved status; unsupported work returns a distinct status and null, never the previously computed endpoint or underlying value.

Authored initial/inherit/unset select the current registered initial/inherited value directly; authored revert variants return NeedsCascadeSelection. Already-parsed declarations are explicitly unsupported in this first stage because retaining a typed parse is not evidence of applicability under a changed registration. Unregistered/non-custom endpoints and property-identity mismatches are explicit errors. Post-substitution CSS-wide handling preserves the existing native implementation, including its issue-9131 qualification; this proposal does not settle that specification question.

## Tests prepared, not executed

`KeyframePresentation.RetainedEndpointCurrentProviders` captures original var-provider and literal descriptors, drops temporary keyframes/computed-pair arrays, and resolves the retained inputs against provider 20, present red, absent provider, a resolved ordinary chain, an ordinary provider cycle, and 20 again. Both fallback/no-fallback endpoints and literal 30 are checked; the old computed endpoint remains 20. Red defaults the registered consumer to 10; absent/cyclic ordinary provider uses fallback 5 when authored and initial 10 otherwise. This tests ordinary provider SCC output, not mutually animated-root cycle semantics.

`KeyframePresentation.RetainedEndpointIsolationAndAttributes` resolves typed attr input, changes the attribute, interleaves a real invalid-number endpoint and a second endpoint reading current consumer 99, then performs an unsupported ordinary-property call and resolves again in reverse order. Fresh attribute values and provider 99 must survive all temporary endpoint results. This distinguishes CSS-invalid defaulting from an internal unsupported-work error and checks that one endpoint cannot overwrite the next endpoint's provider context. Namespace-qualified attrs and dynamic registration changes still need later coverage; unqualified typed attr is the focused initial native case.

The separate WPT has four ordered cases: important ordinary/higher animated provider winners, each with provider-first/consumer-first creation. It captures first and repeated consumer reads before reading the provider and checks provider/timing calibration. There is no expected runtime pass/failure count. This stage does not route those animations through the new API; these cases are future winning-root integration probes. The existing ten-case corpus remains required, including its measured four dynamic failures. The two new host cases extend the current seventeen-test selection to nineteen when root chooses to run the combined host set.

## Exact remaining integration work

1. Replace the owner’s concrete-only root representation and declaration iteration with an owned recipe item whose property/root identity reaches cascade_custom_property. Do not publish a Parsed cached companion for a pending property. Run real priority/revert/included-flags/seen handling before admission and before value_may_affect_style can discard dependency work.
2. Schedule winning provider roots and retained endpoint dependencies coherently. A completed ComputedStyle is a valid test input here; fetching computed style recursively during traversal is not an implementation. The core resolver can consume an isolated Context prepared from the current cascade’s resolved provider/font/color state, but that projection and scheduling boundary are not implemented here.
3. Establish animated dependency-cycle policy and all supported recipe admission. Ordinary provider-cycle defaulting does not establish an animated-SCC oracle. Unsupported evaluation must remain an explicit failure, not be coerced to missing-provider/defaulting or a cached number. The consumed-context API cannot determine that a supplied map already contains all current winning roots.
4. Publish the full dependency/watch and cacheability effects when integrating the resolver. This test entry reports whether attrs were referenced but does not install effect watches or transfer transient flags/cache conditions to an outer cascade. Fresh per-call state prevents leakage; it does not discharge outer dependency publication. Memory-report roots remain unfinished, and no cost measurement is claimed.

The dynamic implicit-underlying freshness oracle remains inconclusive. This stage targets explicit authored endpoints and does not impose that unproven requirement. Public concrete composition and commitStyles remain byte-identical, as does the original GetComputedKeyframeValues implementation. Existing trace evidence establishes conditional observed cached reuse; this proposal supplies no new browser evidence or accepted-bug count.
