# Structural zoom mapping contract

Six generalized Lean theorems lift a pure length mapping through structured typed values. Six concrete kernel examples and three rejected false claims passed under Lean 4.35.0-rc4. All six theorem audits report only `propext`; no custom axioms, admitted proofs, or native decision procedure is used. This is an isolated research model, not a native implementation proof or additional CSS normative coverage. Accepted fixes remain 137; the admission candidate is held.

`Value` separates length, percentage, color and opaque payload types. It includes length/percentage pairs, recursive math nodes, explicit nil/cons lists, transforms and images. Operation/kind tags are opaque and unchanged. Lists are represented as recursive constructors to keep the proof small; the model permits ill-shaped terms, so grammar/well-formedness is an external restriction. The laws hold for every term of this larger abstract datatype.

`map_identity` and `map_composition` establish the usual pure-map laws. `map_left_inverse` proves that any pointwise leaf inverse lifts to an inverse of the entire structure. `nonlength_data_preserved` removes length payloads with a Unit projection and proves that the complete remaining tree is identical after mapping: percentages, colors, opaque fields, tags, ordering and length-leaf positions all remain unchanged. It requires no inverse assumption. `structured_scale_unscale` instantiates the structural law using the earlier model's explicit `Scaling.cancel` hypothesis. `structured_storage_canonical` then reuses the earlier storage theorem; it additionally assumes the raw producer factors through the same computation scale. The original Normalization.lean is copied unchanged and authenticated.

The mixed specimen contains a transform list, a length/percentage pair, an opaque parameter, and an image with recursive math/color/percentage/list data. Doubling only lengths and halving them restores this specimen. Further examples preserve primitive percentages, colors and opaque values. Negative controls must fail decisively with a kernel-reduced false proposition: scaling the percentage part, scaling a color, or skipping an image's length child. The replay rejects unrelated parser/import failures as negative-control success.

## Native obligations and limits

A native pure mapper should preserve constructor selection, list order, non-length fields and scalar semantics while visiting every semantic length leaf. The model does not discover those leaves. In particular, matrix translation coefficients can use plain numeric storage; they must be classified and mapped according to the actual native matrix convention rather than being hidden in `opaque`. Perspective, nested transform arguments, gradients, positions, image metadata and representation-specific units require an exhaustive producer/visitor audit. A color or opaque payload is assumed to contain no semantic length requiring normalization; proving that for native representations is outside this artifact.

Math nodes are syntax structure here, not an evaluator. Their dimensional typing, simplification, percentage basis, evaluation order, and whether a native representation combines lengths with differently scaled fields are not proved. The model does not assert that arbitrary scaling commutes with all CSS math. The conditional inverse law requires the same invertible leaf conversion at both ends; the concrete natural-number examples use exactly divisible values and are not floating-point models. IEEE rounding, overflow, infinities, clamping, signed zero and nonzero-scale restrictions remain implementation obligations.

Producer completeness is separate: all stored local values must be normalized with the scale actually used to compute them, while already-canonical inherited/initial values must not be normalized again. Relative-unit dependency readiness, CSS-wide selection, producer callbacks/effects, serialization, caching, DOM, and actual Rust/Gecko correspondence are not established. The proof says what a pure structural mapping must satisfy; it cannot certify an implementation that omits a producer or misclassifies a numeric matrix field.
