# Clip rectangles: CSS arithmetic with preserved SMIL admission

`native.patch` is a three-file, copied-source candidate. It removes the shared rejection of matching `auto` rectangle components and retains that rejection at explicitly named SMIL arithmetic exports. It has not been compiled or run in a browser. This artifact adds no accepted fix or bug to the catalogue.

Source basis: `d68b16b121b4fdcc8c783f8a14fc41a6218f8e46`. `SOURCES.json` pins the original files, `ROLES.json` pins the three changed originals/candidates, and `prepare.py` regenerates the copied candidate and patch. No live source, WPT, build, browser, Git index, or commit is changed by this capsule.

## Contract

The earlier [CSS trace](../css-clip-auto-contract-20261110-v1/CSS-TRACE.md) reaches matching-auto CSS component composition; the [SVG trace](../css-clip-auto-contract-20261110-v1/SVG-TRACE.md) leaves current mixed-rectangle SVG additive admission inconclusive. This candidate therefore repairs CSS value arithmetic and preserves current SMIL behavior, without asserting that the compatibility restriction is the final SVG normative policy.

The relevant normative steps are [WA2 effect-value iteration accumulation](https://drafts.csswg.org/web-animations-2/#the-effect-value-of-a-keyframe-animation-effect), [clip animation by computed value](https://drafts.csswg.org/css-masking-1/#clip-property), [corresponding component combination](https://drafts.csswg.org/web-animations-1/#animating-properties), and [CSS Values addition/accumulation defaults](https://drafts.csswg.org/css-values-4/#combining-values). Equal `auto` components remain equal while lengths combine. A differing `auto`/length pair still cannot combine componentwise.

Searchfox consumer receipts and the bounded pinned native consumer audit identify one C++ caller of each plural arithmetic export, both in SMILCSSValueType::AddOrAccumulate. WAAPI composition uses AnimationValue.animate through composite_endpoint and accumulate_endpoint, bypassing these exports. The helper is private and has exactly two callers, which pass Add and Accumulate. Its compatibility equivalence is **not** claimed for Procedure::Interpolate, even though that enum variant is expressible at the Rust type level. Future callers must preserve the arithmetic-only premise.

The binding header is generated by cbindgen; no manual old-name declaration or export exclusion was found. Current data.py builds AnimationValue's payload type from the unboxed base_type, so the `boxed = true` property storage flag does not by itself make AnimationValue::Clip boxed. CSSPixelLength's AnimatedValue is Self. Compilation must still validate the `computed::ClipRectOrAuto::Rect` pattern and regenerated declarations; no mock typecheck is substituted for that gate.

## Why the relocated rejection preserves SMIL

For a fixed Add/Accumulate operation, each concrete rectangle component returns a length, auto, or failure. The old rectangle operation stops at the first failure or auto. The new rectangle operation stops at the first failure; if all components succeed, the SMIL result guard rejects any auto. Both therefore succeed exactly when every component returns a length, and then return the identical four component results.

The new path may evaluate later components after an earlier auto that previously short-circuited. The equivalence requires those component operations to be pure and total. This is established by source inspection for the current concrete ClipRect chain, not for arbitrary implementations of Animate:

* computed::ClipRect is GenericClipRect<LengthOrAuto>; LengthOrAuto is GenericLengthPercentageOrAuto<CSSPixelLength>.
* The derived enum operation first checks discriminants. Equal Auto returns Auto; a mismatch returns Err. No callbacks, mutation, or allocation occurs there.
* CSSPixelLength derives Animate over CSSFloat, which aliases f32. The scalar f32 implementation widens to f64, applies the Procedure weights, clamps and casts back. Add weights are (1,1); Accumulate weights are (count as f64,1).
* The f64 operation uses floating multiplication/addition and min/max, with no integral arithmetic, explicit panic, callback, mutable state, or allocation. Even a finite f32 magnitude times the largest u64 count is well within f64's finite range. The operation returns Ok. No modified zero/conversion/layout path is involved.

Thus additional work is bounded pure scalar evaluation. This does not prove timing equivalence, compiler/FFI correctness, floating-point mathematical accuracy, or behavior under an arbitrary trapping floating-point environment. It does not justify applying the same relocation to another generic value type with fallible side effects.

Outer Clip(Auto) is intentionally distinct from Rect(auto,...). The old outer derived operation accepted Auto/Auto before reaching ClipRect; the result guard must also accept it. Auto/Rect and mismatched rectangle components still fail. Existing SMIL from-by `auto`/`auto` noEffect expectations are a browser-visible control, not evidence that the low-level arithmetic rejected outer Auto.

SMILValue::Add has no count-zero bypass. AddOrAccumulate still finalizes a missing value via GetZeroValue, updates/creates its destination wrapper, then calls the arithmetic export. The wrapper can therefore be updated even when arithmetic fails; the candidate does not move its guard ahead of that update. Both-null finalization failure, zero conversion failure, property exclusions, count-zero auto rejection, and result-null failure remain unchanged. The checker verifies the C++ file is token-identical after reversing only the two names.

## Verification performed

`python3 check.py --check-git` validates pinned Git objects, source/candidate hashes, scratch forward/reverse patch replay, the C++ name-only change and the two arithmetic-only helper callers. Rust formatting was checked on the inserted block with the repository Servo rustfmt configuration; C++ copied-file formatting uses the installed repository clang-format. No native compilation occurred.

`model.py` enumerates all 81 four-component result-category combinations. It also checks 26,896 pairs/counts across top-level auto and four-component auto/numeric values at count0, count1, count2 and u64::MAX. Concrete controls include all-numeric results, CSS matching-auto addition/accumulation, SMIL matching-auto rejection, outer auto, and mismatches. Four deliberately incorrect models are rejected: omit the SMIL guard, reject outer auto, add a count-zero shortcut, and reject all clip values.

This is a finite source-linked executable model, **not a Lean theorem or proof of the native implementation**. Its numeric witnesses use exact integers; they do not claim bit-for-bit f32 arithmetic at large counts. Its universal result-category argument is the preceding case analysis under the concrete pure/total-component premise. Browser first-iteration controls do not themselves exercise a direct count-zero FFI call; the explicit model does, and a native API test is desirable if one is available.
