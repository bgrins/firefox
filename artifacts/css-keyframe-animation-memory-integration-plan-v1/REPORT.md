# Animation owner memory-report integration decision

Complete reporting requires two connected changes: a root that discovers every retained effect, and a shared allocation-identity domain across the entrypoints that can reach the same payload. Adding `MallocSizeOf` to the owner alone is insufficient. No native patch or measured byte count is supplied here; the unavoidable design choice is whether to introduce this reporting-pass/lifetime plumbing now or explicitly defer complete accounting as a landing prerequisite.

The owner-host combined package and previous memory boundary package were authenticated before this analysis. The proposed owner is still concrete-only. Provider/SCC/base semantics and unreachable-node pruning are separate work.

## Additional source finding

The retrieved `nsWindowMemoryReporter.cpp` creates a new `SizeOfState(WindowsMallocSizeOf)` inside `CollectWindowReports` for each window. `CollectReports` uses `fakeState(nullptr)` only for aggregate counters. The data-document traversal shares its parent window's state, but different windows do not share that state. The tab-size recursion also creates separate states. Consequently, merely passing `aSizes.mState.mSeenPtrs` through one style set cannot establish process-wide uniqueness. Effect cloning shares segment descriptor Arcs; attribution by different documents must not count a shared context twice in a process total.

`AnimationEffect.cpp` cycle-unlinks `mDocument` and `mAnimation`. A document-only registry must therefore specify what happens to still-allocated, unlinked effects; the document pointer is not an unconditional lifetime anchor. `EffectSet` and timeline enumeration are insufficient even before unlink: constructed-but-unattached, canceled, targetless, and script-retained effects can retain segment arrays and descriptors.

## Recommended implementation shape

| Boundary | Concrete change and invariant |
| --- | --- |
| `dom/animation/KeyframeEffect.{h,cpp}` | Maintain a main-thread non-owning registry of live effect instances, registering both construction paths and unregistering in the destructor. Do not use target registration or animation relevance as membership. Snapshot strong references before external report callbacks, or finish collection before callbacks; never enumerate dangling raw pointers. The registry must not keep effects alive between reports. Include a defined unattributed bucket when the effect has no document/window. |
| `dom/base/nsWindowMemoryReporter.cpp`, `nsWindowSizes` / reporting context | Introduce one explicit dedup context for the animation-related shared allocations for the whole collection pass and carry it through window/data-document/style reporting and an orphan-effect sweep. Keep existing general per-window accounting semantics unless deliberately changing them. Do not implement a process-global persistent seen set: it must be reset for each report and must not suppress a later report or confuse reused addresses. |
| `layout/style/ServoStyleSet.cpp`, `servo/ports/geckolib/glue.rs`, `servo/components/style/rule_tree/core.rs` | Thread that context through `Servo_StyleSet_AddSizeOfExcludingThis` using the existing `Gecko_HaveSeenPtr` callback convention. Walk sampled `StyleSource` owners while visiting rule nodes; ordinary sources retain their existing accounting policy. Count a sampled owner once, then its materialized PDB, root table and arena. No new selector traversal is needed. |
| `layout/style/DeclarationBlock.{h,cpp}` and its reporting callers | Add an accounting-context route to `DeclarationBlock::SizeofIncludingThis` / `Servo_DeclarationBlock_SizeOfIncludingThis`; use the same PDB Arc identity and conditional deep traversal as the sampled-owner route. The current malloc-callback-only interface and unconditional Arc count cannot deduplicate with it. Audit the CSS declaration/rule and stylesheet callers before declaring this route complete. Do not silently skip a PDB on the assumption another root will report it. |
| `dom/animation/AnimationPropertySegment.h`, `KeyframeEffect`, new narrow Gecko/Rust sizing FFI | The all-live-effect root walks every initialized segment's from/to descriptor, including inactive effects. The FFI conditionally measures the outer descriptor Arc and invokes the existing `KeyframeEndpoint::size_of`; its shared context then uses `conditional_size_of`. Count the C++ segment/property array capacity once if adding those previously unreported containers, separately from the shared Rust payloads. |
| `servo/components/style/animation_rule_sample.rs`, `deferred_animation_operations.rs` | Measure the owner's `FrozenAnimationRule` root hash table and its owned property-name payloads. Conditionally measure the `std::sync::Arc` arena allocation, node-vector backing storage, and deep allocations of every initialized node. Include unreachable-but-retained nodes: reachability from current roots does not determine retained allocation size. A retained `SampledAnimationProperty` in any future persistent cache will require its own reporting root, using the same arena identity. |

This is an implementation plan, not evidence that every declaration-block caller has already been migrated. The most consequential prerequisite is approval of the all-live-effect registry and cross-entrypoint reporting context. A separate reporter with its own private set would still double count PDBs reported elsewhere. A document list without an orphan/unlink rule would still miss live allocations. Changing the global window reporter's existing attribution policy should be a separate explicit review decision, not an incidental owner patch.

## Allocation identity and attribution contract

Use the established servo Arc conditional sizing identity for sampled owners, PDBs, descriptors and contexts on every path. Measure a PDB under the existing shared style lock. Mark before deep traversal, and deep-traverse it only on its first visit. Passing a new context to one PDB caller while leaving another unconditional is not sufficient. Cross-window shared attribution can be first-visited-window plus a documented orphan bucket, but the process total must not depend on traversal order; per-window attribution may. Keep reporting categories separate from the dedup identity.

For `std::sync::Arc<AnimationOperationArena<_>>`, `Arc::as_ptr` is a live data/interior pointer, not a malloc base. Use the existing enclosing-allocation callback with a consistent identity; do not subtract a guessed Arc header or multiply `size_of` by a reference count. Its nonzero-sized arena object contains the node vector. Measure vector/hash-map backing allocations through existing allocator-aware shallow traits, then initialized elements' deep payloads. `AnimationValue` has an existing `MallocSizeOf` derivation in `properties/helpers/animated_properties.mako.rs`; reuse it and audit shared leaf handling against the same context, rather than inventing numeric value sizes. Nested retained declaration/token/URL ownership follows the existing payload traits and their intentional exclusions; no claim of newly measuring globally owned atom/URL infrastructure is made.

The descriptor context's vector owns cloned declarations, while the sample's PDB owns materialized declarations. These are distinct container allocations even when they refer to shared leaf data. Deduplicate the shared leaf allocation, not the distinct vectors or PDB identity merely because contents compare equal. Conversely, two different Arc handles to one context must not trigger two context-vector measurements. Stack-borrowed iterator views and temporary resolution caches are not persistent retained allocations; accounting them as owner storage would be wrong.

## Decisive native checks after implementation

Use real Gecko allocator callbacks and the actual reporting entrypoints, extending the presentation/owner host tests. Assert relations and independently observable lifetime transitions, not fixed allocator byte totals.

1. Report one owner twice with one context: the second retained-payload increment is zero. Start a new report context: the allocation is measured again.
2. Visit the same materialized PDB through the owner and `DeclarationBlock` in both orders: equal combined totals, exactly one PDB deep traversal. Include an independently retained PDB after dropping its sample owner.
3. Report two property roots sharing one arena, and two separately allocated arenas with equal contents. The first shares its arena increment; the latter must not be merged. Retain an unreachable node with an owned allocation and verify it is measured, without pruning it.
4. Report from/to descriptors sharing a context, a cloned effect sharing those descriptors, and a second context with equal declarations. Distinguish allocation identity from equality. Exercise two window attribution orders using one pass context.
5. Exercise a real effect with no `Animation`, then cancel/detach its target while retaining the effect, and finally release it. The all-live-effect registry must find its descriptors before release and remove the object at destruction. Add an unlink/orphan-lifetime test rather than assuming every effect always has `mDocument`.
6. Confirm observer/report callbacks cannot invalidate the registry iteration, and registry membership itself does not retain an otherwise dead effect. Include the registry's own backing storage in reporting if it allocates.

Current host tests establish ownership/layout and descriptor association, not these reporting properties. No compiler, browser, memory reporter or allocator measurement ran for this assessment. Searchfox source snapshots are discovery evidence, not a claim that unmodified local files were freshly verified against them. Existing sealed packages remain unchanged.
