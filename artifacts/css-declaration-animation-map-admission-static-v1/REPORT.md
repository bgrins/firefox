# Animation-map constructor admission addendum

Separate bounded follow-up to the sealed public-operation audit. No bug found and no native/browser execution. Complete source snapshots retained; Searchfox discovered the actual provider path.

`PropertyDeclarationBlock::from_animation_value_map` is called by Gecko wrapper `get_animation_rule`, which allocates a fresh FxHashMap and asks Gecko_GetAnimationRule to populate it. That function forwards to EffectCompositor::GetServoAnimationRule; sorted effects compose their styles. KeyframeEffect's segment composition passes the owning AnimationProperty.mProperty and its selected segment into Servo_AnimationCompose. The Rust function decodes that property ID, obtains underlying/base values as needed, calls compose_animation_segment, and inserts `(property, result)` into the map. It does not independently verify result.id() == property at insertion.

The representation conversion itself has a clear intended identity contract: generated AnimationValue::id returns its variant longhand tag or custom name; uncompute emits the same named longhand variant, or in grouped generated arms copies its tag into PropertyDeclarationVariantRepr. Custom AnimatedValue::to_declaration clones the same custom name. Thus ordinary uncompute does not intentionally remap aliases. Alias/canonical property normalization happens before the map key; the uncompute tag/name path is not another alias resolver.

Remaining exact admission: every selected segment endpoint, cached underlying value and accumulation/interpolation result belongs to the owning AnimationProperty ID. To discharge it fully, follow keyframe/transition construction, logical-to-physical normalization, base-value lookup and compose_animation_segment result preservation; then bind generated tag layouts and custom-name preservation. This bounded audit did not complete that larger animation graph or prove Rust unsafe representation. The public-storage constructor theorem should retain key == uncompute(value).id as its premise until that provider composition exists. Hash-map key uniqueness alone cannot substitute for it.

The main audit also explicitly records that clear changes declaration/importance/membership storage while preserving the immutable atomic flag. Root's three-field representation may leave flags outside its selected scope, but that exclusion must remain stated.
