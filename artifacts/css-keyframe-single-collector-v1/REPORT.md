# Single cascade collector checkpoint

This is an uncompiled integration candidate, not a repair or an activation patch. It changes the actual ordinary `apply_declarations` path and its direct `Stylist::compute_for_declarations` caller to use one collection/completion boundary. It replaces the separate-collector approach in the unfinished `css-keyframe-winning-admission-v1` draft. The earlier collection-interface blocker is only partly addressed; pending source transport and joint native completion remain unfinished.

## Actual changes

`CascadeDeclaration` distinguishes a concrete borrowed declaration from an owned unresolved custom recipe. The real `DeclarationIterator` now wraps its concrete entries in this type; its payload parameter remains `Infallible`. The ordinary direct-declaration iterator in `Stylist::compute_for_declarations` wraps entries identically. The public `cascade`, `cascade_rules` and `apply_declarations` routes still complete synchronously and return `Arc<ComputedValues>`.

The actual `iter_declarations` loop performs both ordinary and pending admission through `Cascade::admit_custom_property`. This extracts the existing reverted-priority, included-flags and vacant-seen gates in their existing order. Ordinary revert/revert-layer updates the actual `RevertState` without retaining a winner; revert-rule keeps the previous no-cutoff behavior. Accepted values reserve the real seen entry before any `value_may_affect_style` optimization. The immediate keyframe-custom builder path also calls this same admission method through `cascade_custom_property`, then applies its accepted declaration.

`CollectedDeclarations` retains the actual `Cascade`, original longhand records/PDB identities and accepted ordinary declarations. On the normal route, `resolve_concrete` exhaustively eliminates its impossible pending payload using `match property {}`, applies the accepted ordinary declarations and runs the existing ordinary SCC/prioritary resolver. Only then does it produce `ResolvedDeclarations`, after which the existing cache, non-prioritary, visited derivation and style publication sequence runs. The visited branch retains the existing already-resolved unvisited map, writing mode and color-scheme reuse and avoids recollecting custom values.

The same collector can accept actual `PendingProperty` payloads. Its `into_pending_owner` moves pending recipes and clones accepted native `CustomDeclaration` values into an `AdmittedNativeWinners` owner. Both ordinary and animated winners are admitted as unresolved work: an ordinary `--q:var(--p)` cannot be mislabeled ready while sampled `--p` is still pending. The incomplete owner retains the real cascade and longhands and exposes no conversion to `ResolvedDeclarations` or a finished style. This method is source-level native ownership code, but no real iterator currently calls its pending instantiation.

## Required predecessor and current validation limits

The exact cascade preimage is the sealed `css-keyframe-typed-attribute-demand-v1` candidate, not an assertion that its current root build has the same bytes. The native adapter preimage comes from `css-keyframe-winning-provider-completion-v1`; that proposal's module additions and scheduler are required predecessors. This incremental patch does not add those modules by itself. Stylist is pinned from the local branch at capture time. Root must rebase any eventual integration over build corrections before applying; this package never writes live sources.

Rustfmt parsed/formatted the three exact candidate Rust files using the repository configuration. The transport checker verifies the exact three preimages/postimages and forward/reverse patch application in disposable scratch. Its additional source assertions identify intended structural joins only. No native typecheck, native host test, browser test, benchmark or formal equivalence proof was run. No claim is made that the candidate compiles or preserves every ordinary-cascade behavior.

This structural refactor defers ordinary declaration application until collection finishes and adds a vector of accepted custom winners to every ordinary cascade. Source inspection of `maybe_note_non_custom_dependency` and `update_attributes_map` found that collection-time longhand dependency gathering records references and retrieves attributes, not partially-applied custom values. Nevertheless, ordering equivalence and the allocation/performance cost require real native and browser regression checks; they are not established by textual checks.

## Exact unfinished boundary

1. The real rule-tree iterator still emits only concrete entries. `AnimationRuleSource` remains its concrete `FrozenAnimationRule<Infallible>` owner. This package does not activate the separate draft's pending map, test-only constructor or pending-only rule-retention changes. Pending-only sources must survive `RuleTree::update_rule_at_level`'s `any_normal` filtering when native ownership is eventually introduced.
2. `IncompleteCascade` has no completing evaluator. The prior generic scheduler accepts custom-property-name demands, but typed endpoints can demand native prioritary properties. Ordinary and animated work, prioritary dependencies, typed attribute nodes and SCC invalidation must share a native resolution operation before this owner can issue a resolved capability.
3. The normal heterogeneous rule tree cannot simply start containing pending roots. Its public cascade callers still require a completed style. A disabled producer or `cfg(test)` constructor does not make a pending branch exhaustive. The choices remain a synchronous total native scheduler or a true incomplete result propagated through traversal. This candidate deliberately keeps the normal payload uninhabited instead of unwrapping, discarding, defaulting or panicking on incomplete work.
4. The scheduler must receive isolated current endpoint contexts without publishing a partial `ComputedValues` just to seed `StyleBuilder::for_derived_style`. A builder fork, tracker/cache/style-effect transfer and stable registration/sample scope remain to implement. Endpoint callback success alone cannot authorize publication of another incomplete owner.
5. Animated/ordinary/prioritary cycle ownership must specify the invalidation target and continuation semantics. The existing scheduler's cycle path is evidence of unresolved work, not permission to turn every participating property into a numeric initial value. Computed-keyframe scope, implicit base inputs, endpoint-level revert and unsupported results remain separate semantic obligations.

These are concrete missing implementations, not a request for user permission. Native implementation can continue independently with the shared collector refactor, a real rule-source transport and harness bridge, and a transactional context builder, but the full production path must wait for joint resolution semantics. This checkpoint does not close `css-keyframe-winning-provider-collection-interface-v1/BLOCKER.md`.

## Actual host harness next step

No test constructor or host bridge is supplied here. A `cfg(test)`-only style constructor would not normally be available to Gecko GTest's dependency build. The next harness change must expose a normal-compiled, explicitly testing-only Gecko/style bridge, construct genuine rule nodes and retained operation roots, invoke this same rule iterator and collector, and inspect the incomplete owner without building a style. It must test important/revert/revert-layer/seen/flag exclusion, pending-only retention and original longhand PDB identity. Caller-provided winner lists or Boolean priority surrogates do not satisfy that requirement.

The ordinary refactor first needs compilation and existing cascade/WPT regressions. The pending path then needs real host tests and the unchanged ten-case animation browser diagnostic, including both creation orders and the four previously failing dynamic histories. No new bug or fix is claimed, and no standalone-bug ledger entry is warranted.
