L758: ### 6.5. Precedence of Non-CSS Presentational Hints
L759: The UA may choose to honor presentational hints in a source document’s markup, for example the `bgcolor` attribute or `【294†s†html.spec.whatwg.org】` element in 【274†[HTML]】. All document language-based styling must be translated to corresponding CSS rules and enter the cascade as rules in either the 【259†UA-origin】 or a special-purpose author presentational hint origin between the regular 【260†user origin】 and the 【261†author origin】.
L760: For the purpose of 【111†cascading】 this 【295†author presentational hint origin】 is treated as an independent 【151†origin】; however for the purpose of the 【296†revert】 keyword (but not for the 【27†revert-layer】 keyword) it is considered part of the author origin.
L761: A document language may define whether such a presentational hint enters the 【111†cascade】 as 【259†UA-origin】 or 【261†author-origin】; if so, the UA must behave accordingly. For example, 【297†[SVG11]】 maps its presentation attributes into the author origin.
L762: Note: Presentational hints entering the 【111†cascade】 as 【259†UA-origin】 rules can be overridden by 【261†author-origin】 or 【260†user-origin】 styles. Presentational hints entering the cascade as 【295†author presentational hint origin】 rules can be overridden by author-origin styles, but not by non-【257†important】 user-origin styles. Host languages should choose the appropriate origin for presentational hints with these considerations in mind.
L763: ## 7. Defaulting
L764: 
L765: When the 【111†cascade】 does not result in a value, the 【115†specified value】 must be found some other way. 【298†Inherited properties】 draw their defaults from their parent element through 【113†inheritance】; all other properties take their 【114†initial value】. Authors can explicitly request inheritance or initialization via the 【299†inherit】 and 【300†initial】 keywords.
L766: ### 7.1. Initial Values
L767: 
L768: Each property has an initial value, defined in the property’s definition table. If the property is not an 【298†inherited property】, and the 【111†cascade】 does not result in a value, then the 【115†specified value】 of the property is its 【114†initial value】.
L769: ### 7.2. Inheritance
L770: 
L771: Inheritance propagates property values from parent elements to their children. The inherited value of a property on an element is the 【203†computed value】 of the property on the element’s parent element. For the root element, which has no parent element, the 【301†inherited value】 is the 【114†initial value】 of the property.
L772: For a 【266†[DOM]】 tree with shadows, inheritance operates on the 【199†flattened element tree】. This means that slotted elements inherit from the `【302†slot†html.spec.whatwg.org】` they’re assigned to, rather than directly from their 【303†light tree†dom.spec.whatwg.org】 parent. 【232†Pseudo-elements】 inherit according to the fictional tag sequence described for each pseudo-element. 【235†[CSS-PSEUDO-4]】
L773: Some properties are inherited properties, as defined in their property definition table. This means that, unless the 【111†cascade】 results in a value, the value will be determined by 【113†inheritance】.
L774: 
L775: A property can also be explicitly inherited. See the 【299†inherit】 keyword.
L776: 
L777: Note: Inheritance follows the document tree and is not intercepted by 【304†anonymous boxes†www.w3.org】, or otherwise affected by manipulations of the box tree.
L778: ### 7.3. Explicit Defaulting
L779: 
L780: Several CSS-wide property values are defined below; declaring a property to have these values explicitly specifies a particular defaulting behavior. As specified in 【173†CSS Values and Units†www.w3.org】 【174†[css-values-3]】, all CSS properties can accept these values.
L781: 
L782: The keywords 【296†revert】, 【27†revert-layer】, and 【305†revert-rule】 are cascade-dependent keywords; some contexts may restrict their use while allowing the other 【209†CSS-wide keywords】.
L783: #### 7.3.1. Resetting a Property: the 【300†initial】 keyword
L784: 
L785: The initial 【209†CSS-wide keyword】 represents the value defined as the property’s 【114†initial value】.
L786: 
L787: If the 【202†cascaded value】 of a property is the 【300†initial】 keyword, the property’s 【115†specified value】 is its 【114†initial value】.
L788: #### 7.3.2. Explicit Inheritance: the 【299†inherit】 keyword
L789: 
L790: The inherit 【209†CSS-wide keyword】 represents the property’s 【203†computed value】 on the parent element.
L791: 
L792: If the 【202†cascaded value】 of a property is the 【299†inherit】 keyword, the property’s 【115†specified】 and 【203†computed values】 are the 【301†inherited value】.
L793: #### 7.3.3. Erasing All Declarations: the 【306†unset】 keyword
L794: 
L795: The unset 【209†CSS-wide keyword】 acts as either 【299†inherit】 or 【300†initial】, depending on whether the property is 【298†inherited】 or not.
L796: If the 【202†cascaded value】 of a property is the 【306†unset】 keyword, then if it is an inherited property, this is treated as 【299†inherit】, and if it is not, this is treated as 【300†initial】. This keyword effectively erases all 【201†declared values】 occurring earlier in the 【111†cascade】, correctly inheriting or not as appropriate for the property (or all longhands of a 【159†shorthand】).
L797: #### 7.3.4. Rolling Back Cascade Origins: the 【296†revert】 keyword
L798: 
L799: The revert 【209†CSS-wide keyword】 rolls back the cascade to the 【202†cascaded value】 of the earlier 【151†origin】.
L800: 
L801: If the 【202†cascaded value】 of a property is the 【296†revert】 keyword, the behavior depends on the 【151†cascade origin】 to which the 【176†declaration】 belongs:
L802: 【259†user-agent origin】
L803:     Equivalent to 【306†unset】.
L804: 【260†user origin】
L805:     Rolls back the 【202†cascaded value】 to the user-agent level, so that the 【115†specified value】 is calculated as if no 【261†author-origin】 or 【260†user-origin】 rules were specified for this property on this element.
L806: 【261†author origin】
L807:     Rolls back the 【202†cascaded value】 to the user level, so that the 【115†specified value】 is calculated as if no 【261†author-origin】 rules were specified for this property on this element. For the purpose of 【296†revert】, this origin includes the Animation 【151†origin】.
L808: Note: Effectively the 【296†revert】 keyword is substituted with the value from the earlier 【151†cascade origin】. Thus, reverting a 【159†shorthand property】 reverts all its longhands; reverting any 【35†property alias】 of a property reverts all of them; reverting one of the paired properties in a 【307†logical property group】 also reverts the other one; etc.
L809: #### 7.3.5. Rolling Back Cascade Layers: the 【27†revert-layer】 keyword
L810: 
L811: The revert-layer 【209†CSS-wide keyword】 rolls back the cascade similar to 【296†revert】, except it works by 【21†cascade layer】 rather than by 【151†cascade origin】.
L812: If the 【202†cascaded value】 of a property is the 【27†revert-layer】 keyword, the cascaded value is rolled back to the earlier 【21†layer】, so that the 【115†specified value】 is calculated as if no rules were specified in the current cascade layer—​or between its 【263†normal】 and 【257†important】 levels in the 【111†cascade】—​for this property on this element.
L813: For revert-layer in important 【308†element-attached styles】, however, it only reverts the 【308†element-attached styles】 and the intervening 【309†animation origin】, and not any of the intervening 【261†author-origin】 important rules.
L814: For example, applying 【27†revert-layer】 to the 【245†height】 in layer `two`, reverts the height property to the value defined in layer `one`, yielding a height of `100px`.
L815: 
L816:     @layer one {
L817:       div { height: 100px }
L818:     }
L819: 
L820:     @layer two {
L821:       div { height: 200px }
L822:       div { height: revert-layer }
L823:     }
L824: Note that since 【245†height】 and 【310†block-size】 are paired properties in a 【307†logical property group】, the following layer `two` declaration would also revert to the height defined in layer `one`.
L825: 
L826:     @layer two {
L827:       div { height: 200px }
L828:       div { block-size: revert-layer }
L829:     }
L830: 
L831: 
L832: Note: If there are no lower-precedence 【112†declarations】 in the same 【151†cascade origin】 as the 【27†revert-layer】 value, the 【202†cascaded value】 will roll back to the previous origin.
L833: Note: The 【309†animation origin】 is not collapsed with the 【261†author origin】 for this purpose as it is for 【296†revert】, and thus effectively forms its own 【21†cascade layer】.
L834: #### 7.3.6. Rolling Back Rules: the 【305†revert-rule】 keyword
L835: 
L836: The revert-rule 【209†CSS-wide keyword】 rolls back the cascade similar to 【296†revert】 and 【27†revert-layer】, except it works by 【311†style rule】 rather than 【151†cascade origin】 or 【21†cascade layer】.
L837: 
L838: If the 【202†cascaded value】 of a property is the 【305†revert-rule】 keyword, the cascaded value is rolled back such that the 【115†specified value】 is calculated as if the current 【311†style rule】 had not been present at all.
L839: The 【305†revert-rule】 keyword can be combined with 【312†if()】 to conditionally ignore a declaration:
L840: 
L841:     div {
L842:       border-radius: 5px;
L843:     }
L844:     .apply-sharp {
L845:       border-radius: if(style(--mode:sharp): 0px; else: revert-rule);
L846:     }
L847: 
L848: 
L849: Given an element `<div class=apply-sharp>`, the above style sets border-radius to `0px` only when the 【203†computed value】 of `--mode` is `sharp`.
L850: 
L851: The 【305†revert-rule】 keyword behaves like 【27†revert-layer】 in the 【309†animation origin】.

L1811: 
L1812: Note that 【171†substitution】 takes place at the level of CSS tokens 【997†[css-syntax-3]】, not at a textual level; you can’t build up a single token where part of it is provided by a variable:
L1813: 
L1814:     .foo {
L1815:       --gap: 20;
L1816:       margin-top: var(--gap)px;
L1817:     }
L1818: This is not equivalent to setting 【776†margin-top: 20px;】 (a length). Instead, it’s equivalent to margin-top: 20 px; (a number followed by an ident), which is simply an invalid value for the margin-top property. Note, though, that 【420†calc()】 can be used to validly achieve the same thing, like so:
L1819: 
L1820:     .foo {
L1821:       --gap: 20;
L1822:       margin-top: calc(var(--gap) * 1px);
L1823:     }
L1824: This also implies that the post-substitution value might not be directly serializable as-is. Here’s a similar example to the preceding:
L1825: 
L1826:     .foo {
L1827:       --gap: 20;
L1828:       --not-px-length: var(--gap)px;
L1829:     }
L1830: The serialization of the computed (post-substitution) value of --not-px-length is not 20px, because that would parse back as the single combined dimension; instead, it will serialize with a comment between the two tokens, like px, to enforce that they are separate tokens even when re-parsing.
