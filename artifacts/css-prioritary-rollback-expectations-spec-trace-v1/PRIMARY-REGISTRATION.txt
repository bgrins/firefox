L92: ## 1. Introduction
L93: 
L94: CSS defines a comprehensive set of properties that can be manipulated in order to modify the layout, paint, or behaviour of a web document. However, web authors frequently wish to extend this set with additional properties.
L212: ### 2.7. Substitution via 【89†var()†drafts.csswg.org】
L213: 
L214: Like unregistered custom properties, the value of a registered custom property can be substituted into another value with the 【89†var()†drafts.csswg.org】 function. However, registered custom properties substitute as their 【25†computed value】, rather than the original token sequence used to produce that value.
L215: Any 【89†var()†drafts.csswg.org】 function that references a registered custom property must be replaced with an equivalent token sequence, which is equal to the token sequence that would have been produced by 【111†serializing†drafts.csswg.org】 the computed value, and 【112†tokenizing†drafts.csswg.org】 the resulting string.
L216: Suppose that --x is registered with <length> syntax, and that --y is an unregistered custom property.
L217: 
L218:     div {
L219:       font-size: 10px;
L220:       --x: 8em;
L221:       --y: var(--x);
L222:     }
L223: 
L224: 
L225: Because the computed value of --x (when serialized) is "80px", the computed value of --y is a 【113†<dimension-token>†drafts.csswg.org】 with a value of "80" and unit "px".
L226: #### 2.7.1. Dependency Cycles via Relative Units
L227: 
L228: 【81†Registered custom properties】 follow the same rules for dependency cycle resolution as unregistered 【77†custom properties†drafts.csswg.org】, with the following additional constraints:
L229: 
L230: For any registered custom property with a 【114†<length>†drafts.csswg.org】 or 【115†<length-percentage>†drafts.csswg.org】 syntax component:
L231:   * If the property contains any of the following units: 【116†em†drafts.csswg.org】, 【117†ex†drafts.csswg.org】, 【118†cap†drafts.csswg.org】, 【119†ch†drafts.csswg.org】, 【120†ic†drafts.csswg.org】, 【121†lh†drafts.csswg.org】; then add an edge between the property and the font-size of the current element.
L232: 
L233:   * If the property contains the 【121†lh†drafts.csswg.org】 unit, add an edge between the property and the line-height of the current element.
L234:   * If the property contains any of the following units: 【122†rem†drafts.csswg.org】, 【123†rlh†drafts.csswg.org】; then add an edge between the property and the 【124†font-size†drafts.csswg.org】' of the root element.
L235: 
L236:   * If the property contains the 【123†rlh†drafts.csswg.org】 unit, add an edge between the property and the 【125†line-height†drafts.csswg.org】' of the root element.
L237: For example, given this registration:
L238: 
L239:     CSS.registerProperty({
L240:       name: "--my-font-size",
L241:       syntax: "<length>",
L242:       initialValue: "0px",
L243:       inherits: false
L244:     });
L245: 
L246: 
L247: the following will produce a dependency cycle:
L248: 
L249:     div {
L250:       --my-font-size: 10em;
L251:       font-size: var(--my-font-size);
L252:     }
L253: 
L254: 
L255: and font-size will behave as if the value 【126†unset†drafts.csswg.org】 was specified.
L256: ### 2.8. Shadow DOM
L257: 
L258: Unlike many concepts in CSS (see 【127†CSS Scoping Module Level 1 § shadow-names†drafts.csswg.org】), property registrations are not scoped to a tree scope. All registrations, whether they appear in the outermost document or within a shadow tree, interact in a single global registration map for the `【78†Document†dom.spec.whatwg.org】`.
L259: 
L260: Why can’t registrations be scoped?
L261: There are clear use-cases for property registrations to be scoped—​a component using Shadow DOM and registering some custom properties for its own internal use probably doesn’t intend for the outer page to see the registration, since the outer page doesn’t even know the component is using that property.

L140: ### 2.4. 【95†Computed Value†drafts.csswg.org】-Time Behavior
L141: 
L142: The 【95†computed value†drafts.csswg.org】 of a 【81†registered custom property】 is determined by the syntax of its 【96†registration】.
L143: 
L144: If the 【96†registration’s】 syntax is the 【97†universal syntax definition】, the 【95†computed value†drafts.csswg.org】 is the same as for unregistered 【77†custom properties†drafts.csswg.org】 (either the specified value with variables substituted, or the 【87†guaranteed-invalid value†drafts.csswg.org】).
L145: Otherwise, attempt to 【86†parse†drafts.csswg.org】 the property’s value according to its registered syntax. If this fails, the declaration is 【98†invalid at computed-value time†drafts.csswg.org】 and the 【95†computed value†drafts.csswg.org】 is determined accordingly. If it succeeds, the 【95†computed value†drafts.csswg.org】 depends on the specifics of the syntax:
L146: 
L147: For `"<length>"`, `"<length-percentage>"`, `"<angle>"`, `"<time>"`, `"<resolution>"`, `"<integer>"`, `"<number>"`, and `"<percentage>"` values:
L148:   * If the specified value is a 【99†dimension†drafts.csswg.org】 literal (such as 50em or .2s), the computed value is the same value, but with the unit converted to the corresponding 【100†canonical unit†drafts.csswg.org】 for the type of value.
L149: 
L150:   * If the specified value is any other numeric literal (such as 5 or 20%), the computed value is as specified. (In particular, percentages are never resolved against anything.)
L151:   * If the specified value is a function that evaluates to one of those types (such as a 【101†math function†drafts.csswg.org】), the computed value is defined by that function.
L152: 
L153: For `"<string>"` values, the computed value is as specified.
L154: 
L155: For `"<color>"` values, the value is computed by resolving color values, per 【102†CSS Color 4 §  15. Resolving <color> Values†drafts.csswg.org】.
L156: 
L157: For `"<custom-ident>"`, ident, or `"*"` values, the computed value is as specified.
L158: For `"<url>"` values, the computed value is one of the following:
L159: 
L160:   * if the URL is a relative URL, the computed value is the resolved absolute URL as described in 【103†[css3-values]】.
L161: 
L162:   * otherwise, the computed value is as specified.
L163: 
L164: URL behavior examples
L165: 
L166: Because URLs resolve against the base URL of the stylesheet they appear in, we can end up with multiple relative URLs that resolve against different base URLs, even though they appear in the same property.
L167: For example, suppose --url-foo and --url-bar are registered custom properties with <url> syntax, and that we have a stylesheet at `/style/foo/foo.css`:
L168: 
L169:     div {
L170:       --url-foo: url("foo.png");
L171:     }
L172: 
L173: 
L174: and another stylesheet at `/style/bar/bar.css`
L175: 
L176:     div {
L177:       --url-bar: url("bar.png");
L178:     }
L179: and finally a document at `/index.html`:
L180: 
L181:     <link href="/style/foo/foo.css" rel="stylesheet" type="text/css">
L182:     <link href="/style/bar/bar.css" rel="stylesheet" type="text/css">
L183:     <div style="background-image: var(--url-foo), var(--url-bar);">
L184:     </div>
L185: 
L186: 
L187: Here, the var(--url-foo) reference would produce a URL that resolves against `/style/foo`, and the var(--url-bar) reference would produce a URL that resolves against `/style/bar`.

L403:     【112†Declarations】 within each 【151†origin】 and 【267†context】 can be explicitly assigned to a 【21†cascade layer】. For the purpose of this step, any declaration not assigned to an explicit layer is added to an implicit final layer.
L404: Cascade layers (like declarations) are sorted by order of appearance, see 【57†§ 6.4.3 Layer Ordering】. When comparing declarations that belong to different layers, then for 【263†normal】 rules the declaration whose 【21†cascade layer】 is latest in the layer order wins, and for 【257†important】 rules the declaration whose cascade layer is earliest wins.
L405: Note: This follows the same logic used for precedence of 【263†normal】 and 【257†important】 【151†origins】, thus the !important flag maintains the same “override” purpose in both settings.
L406: Specificity
L407:     The 【271†Selectors module†www.w3.org】 【255†[SELECT]】 describes how to compute the specificity of a selector. Each 【176†declaration】 has the same specificity as the style rule it appears in. The declaration with the highest specificity wins.
L408: Order of Appearance
L409:     The last 【176†declaration】 in document order wins. For this purpose:
L410:   * Style sheets are ordered in 【272†final CSS style sheets】 order.
L411:   * Declarations from 【121†imported style sheets】 are ordered as if their style sheets were substituted in place of the @import rule.
L412:   * Declarations from style sheets independently linked by the originating document are treated as if they were concatenated in linking order, as determined by the host document language.
L413:   * Declarations from style attributes are ordered according to the document order of the element the style attribute appears on, and are all placed after any style sheets. 【270†[CSSSTYLEATTR]】
L414: The output of the cascade is a (potentially empty) sorted list of 【201†declared values】 for each property on each element.
L415: ### 6.2. Cascading Origins
L416: 
L417: Each style rule has a cascade origin, which determines where it enters the cascade. CSS defines three core 【151†origins】:
L418: Author Origin
L419:     The author specifies style sheets for a source document according to the conventions of the document language. For instance, in HTML, style sheets may be included in the document or linked externally.
L420: User Origin
L421:     The user may be able to specify style information for a particular document. For example, the user may specify a file that contains a style sheet or the user agent may provide an interface that generates a user style sheet (or behaves as if it did).
L422: User-Agent Origin
L423:     Conforming user agents must apply a default style sheet (or behave as if they did). A user agent’s default style sheet should present the elements of the document language in ways that satisfy general presentation expectations for the document language (e.g., for visual browsers, the EM element in HTML is presented using an italic font). See e.g. the 【273†HTML user agent style sheet†html.spec.whatwg.org】. 【274†[HTML]】
L424: Extensions to CSS define the following additional 【151†origins】:
L425: 
L426: Animation Origin
L427:     CSS Animations 【262†[css-animations-1]】 generate “virtual” rules representing their effects when running.
L428: Transition Origin
L429:     Like CSS Animations, CSS Transitions 【258†[css-transitions-1]】 generate “virtual” rules representing their effects when running.
L430: ### 6.3. Important Declarations: the !important annotation
L431: 
L432: CSS attempts to create a balance of power between author and user style sheets. By default, rules in an author’s style sheet override those in a user’s style sheet, which override those in the user-agent’s default style sheet. To balance this, a 【176†declaration】 can be marked 【257†important】, which increases its weight in the cascade and inverts the order of precedence.
L433: A 【176†declaration】 is important if it has a !important annotation as defined by 【153†[css-syntax-3]】, i.e. if the last two (non-whitespace, non-comment) tokens in its value are the delimiter token ! followed by the identifier token important. All other declarations are normal (non-【257†important】).
L434: 
L435:     [hidden] { display: none !important; }
L436: An 【257†important】 declaration takes precedence over a 【263†normal】 declaration. Author and user style sheets may contain important declarations, with 【260†user-origin】 important declarations overriding 【261†author-origin】 important declarations. This CSS feature improves accessibility of documents by giving users with special requirements (large fonts, color combinations, etc.) control over presentation.
L437: 【257†Important】 declarations from all origins take precedence over animations. This allows authors to override animated values in important cases. (Animated values normally override all other rules.) 【262†[css-animations-1]】
L438: 
L439: 【259†User-agent style sheets】 may also contain 【257†important】 declarations. These override all 【261†author】 and 【260†user】 declarations.
L440: The first rule in the user’s style sheet in the following example contains an !important declaration, which overrides the corresponding declaration in the author’s style sheet. The declaration in the second rule will also win due to being marked !important. However, the third declaration in the user’s style sheet is not !important and will therefore lose to the second rule in the author’s style sheet (which happens to set style on a 【159†shorthand】 property).
L441: Also, the third author rule will lose to the second author rule since the second declaration is !important. This shows that !important declarations have a function also within author style sheets.
L442: 
L443:     /* From the user's style sheet */
L444:     p { text-indent: 1em !important }
L445:     p { font-style: italic !important }
L446:     p { font-size: 18pt }
L447: 
L448:     /* From the author's style sheet */
L449:     p { text-indent: 1.5em !important }
L450:     p { font: normal 12pt sans-serif !important }
L451:     p { font-size: 24pt }
L452: Property  | Winning value
L453: --- | ---
L454: 【275†text-indent】  | 1em
L455: 【165†font-style】  | 【276†italic】
L456: 【104†font-size】  | 12pt
L457: 【169†font-family】  | 【277†sans-serif】
L458: ### 6.4. Cascade Layers
L459: 
L460: In the same way that 【151†cascade origins】 provide a balance of power between user and author styles, cascade layers provide a structured way to organize and balance concerns within a single origin. Rules within a single 【21†cascade layer】 cascade together, without interleaving with style rules outside the layer.
