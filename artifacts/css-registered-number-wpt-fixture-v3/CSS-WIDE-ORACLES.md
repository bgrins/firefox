# CSS-wide registered-number controls

Verdict: **REACHED** for the twelve fixed keyword controls and three inheritance-mutation controls. These are regression oracles, not additional bug claims. Primary editor drafts were read on 2026-10-27. `webspec-index` was unavailable in this environment; this is a positive manual call-chain trace, not an exhaustive invocation-index result.

1. Both registrations have exact `<number>` syntax and `inherits:false`. Their initial values are 3 (`--n`) and 7 (`--provider`). Registered properties accept CSS-wide keywords irrespective of registered syntax. Their values otherwise undergo registered grammar checking at computed-value time. [Properties and Values API, specified value-time behavior](https://drafts.css-houdini.org/css-properties-values-api-1/#specified-value), [computed value-time behavior](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation-of-computed-values).
2. For a selected `var(--missing, keyword)` fallback, substitution supplies the fallback tokens. Values 5 explicitly treats a result consisting solely of one CSS-wide keyword as if originally specified. `inherit` therefore selects the parent's computed value (11), while `initial` and non-inherited `unset` select 3. [Values 5, invalid substitution and property replacement](https://drafts.csswg.org/css-values-5/#invalid-substitution), [Cascade 5, explicit defaulting](https://drafts.csswg.org/css-cascade-5/#defaulting-keywords).
3. A provider's own CSS-wide declaration is processed before its computed value is substituted. The provider tests intentionally use registered `--provider`: initial/unset yield 7; inherit yields the parent provider's 11. These are numeric values supplied to `--n`, not literal keyword token transport. Values 5 expressly distinguishes a custom property's own defaulting from a keyword in a var fallback. [Values 5, property replacement](https://drafts.csswg.org/css-values-5/#property-replacement).
4. `inherit extra` is two identifiers, so it does not meet the single-keyword condition. The complete component-value list also does not match `<number>`. Generic CSS grammar parsing consumes the whole component-value input before matching; the trailing identifier cannot be ignored. Grammar failure makes the registered property invalid at computed-value time. With `inherits:false`, the result is its registered initial value: 3 for direct/selected-fallback `--n`, 7 for `--provider`. [Syntax 3, parse according to a grammar](https://drafts.csswg.org/css-syntax-3/#parse-grammar), [Values 5, property replacement](https://drafts.csswg.org/css-values-5/#property-replacement).
5. For each inherit path, changing the relevant parent's computed number from 11 to 13 and back changes the child's number and consuming font size accordingly. This checks externally visible inheritance invalidation. It does not inspect or prove a particular native cache flag.

The fixtures test only initial/inherit/unset and the malformed inherit-plus-token control; revert/revert-layer and registration changes are outside this package. No browser result is claimed here.
