# Direct execution gate for the missing-pseudo query helper

Use a temporary privileged window-utils driver plus a focused mochitest. This exercises the actual helper on a live document before introducing the final CSSOM caller/cache/recascade. A pure GTest of copied arrays would not exercise the target, EffectSet, pres context, real timelines or style conversion; building those facilities into a new GTest would be a larger fixture than the existing browser harness. No driver or browser test has been implemented or run in this capsule.

## Concrete native seam

Add one temporary XPIDL method to `nsIDOMWindowUtils.idl` and implement it in `nsDOMWindowUtils.cpp`, next to `GetUnanimatedComputedStyle`. Suggested interface: target element, pseudo string, one longhand property name, and existing FLUSH_NONE/FLUSH_STYLE policy; return JSON containing admission, nullable serialized values from both origins, output-map distinction, and captured animation/transition effect counts. The exact diagnostic return schema should be frozen with the runner before building. The driver is research instrumentation, not a proposed shipping API.

The implementation should follow existing property lookup, pseudo parsing and `Servo_AnimationValue_Serialize` patterns. Hold the document/pres shell/target strongly. Complete an explicitly requested flush before acquiring the style/effect inputs. Resolve the raw missing-pseudo style via the unchanged `ResolveStyleLazily` and return from its C++ traversal guard/Rust borrow before calling `ComposeServoAnimationRulesForMissingPseudo`. Inspect values using `Servo_AnimationValueMap_GetValue`. Do not recascade or install either map, update effect properties/masks, create pseudo elements, or call renderer composition as a reference during this query.

For the first bounded fixtures, pass that raw style as both base and endpoint style. This is justified only where endpoint providers are stable and the target's own sampled animation rules are not needed to compute them. The pinned `StyleResolverForElement::match_pseudo` constructs empty animation declarations; the missing-pseudo lazy path therefore provides the underlying pseudo style while preserving originating-element inheritance. Use fixed endpoints, stable inherited fonts, and separately flushed ordinary style changes. Do not generalize this to animated custom-property/font providers on the queried pseudo. Assert the base's known literal value independently in the fixture.

Do not reuse `GetUnanimatedComputedStyleNoFlush`: it requires the actual pseudo element. Do not feed the originating element and pseudo style to `GetBaseContextForElement`: the Rust helper recascades as an ordinary element, not with the necessary pseudo inheritance context. A provider-style donor from a different element also fails the candidate's same-target premise.

FLUSH_NONE means the driver does not request a document flush; it is not a proof that every lazy-style preparation operation has no side effects. Record pre/post timing and pending state and reject a test if its prerequisite pending state disappears before the helper. The helper's entry/exit should also report whether live hold/start/pending data changed, using raw fields or already-safe getters rather than another style query. This diagnostic may need a narrowly scoped friend/test accessor; avoid publishing broad production setters or getters solely for the test.

## Minimal useful cases

| Case | Setup and independent expectation | What it tests |
| --- | --- | --- |
| Exact target admission | Missing before/after target accepted; generated pseudo, ordinary element and unsupported pseudo rejected. Retarget one held effect between two origins and query each. | Actual target registration, full pseudo identity and generated/missing distinction. |
| Explicit linear endpoints | Held WA animation, 0px to 100px, time 500 of 1000; animation map is 50px and transition map has no value. | Actual query invocation and simple value oracle. |
| Implicit/additive base | Base margin 10px, single 100px endpoint at half gives 55px; base changed to 20px and flushed gives 60px. Replace 50px followed by add 20px gives 70px. | Fresh base extraction and composite ordering, not stored renderer arrays. |
| Fresh maps/properties | Query margin, replace keyframes with opacity, query margin and opacity; former is absent and latter 0.5. Repeat unchanged query and require same values. | Fresh union/map behavior and stale-property exclusion. |
| CSS endpoint generation | Create a real linear CSS animation with only a to-keyframe, hold at half, retarget its effect to missing before with base 10px; require 55px and diagnostic CSSAnimation identity. | Owned CSS generation rather than only WA arrays. Confirm current native ownership after retargeting before interpreting the result. |
| Stable relative providers | Inherited font 10px and endpoints 1em/3em give 20px; separately change inherited font to 20px and flush, then require 40px. | Current endpoint style supplied to conversion without assuming animated same-pseudo provider closure. |
| Held/zero-rate/null timeline | Hold known local time; zero-rate preserves expected sample. Separate null timeline and unresolved named-timeline cases: distinguish resolved hold behavior from the existing unresolved-timeline exclusion. | Selection branches with explicit timing preconditions. |
| Pending play/pause | Set up ready animation first, then enqueue pause/play and query before a frame. Require the intended pending/null-hold/non-null-start admission before evaluating a sample. | Shared pending selector; no synchronous ready transition caused by query. Do not count a case whose setup instead has a non-null hold as covering the flicker branch. |
| Finite range/boundary | Use a real scroll/view timeline with measured scroll geometry, settle provider sampling, and query fixed endpoints at interior and exact boundary positions. Explicitly assert timeline/progress prerequisites. | Owned offset refresh, finite duration normalization and Exclusive endpoint policy. Do not infer provider freshness from a request to scroll alone. |
| Animation/transition maps | Create a genuine CSS transition on an unchanged live owner, then retarget its KeyframeEffect to a missing pseudo while preserving its CSS ownership. Add an animation-level effect at that target. Inspect both maps and captured native levels. | Fresh union and origin split on an actually transition-level effect. |

For the transition case, the inspected `KeyframeEffect::UpdateTarget` changes target registration and invokes `Animation::NotifyEffectTargetUpdated`, which only schedules replacement checking; it does not clear the transition's owning element. `CSSTransition::CascadeLevel` remains Transitions while `IsTiedToMarkup` is true. Keep the original owner unchanged and avoid an intervening style cancellation. A cancelled/replayed transition is not an adequate substitute: `CancelFromStyle` clears ownership, changing its level to Animations. The driver must report actual native levels, so failed setup cannot silently pass as overlap coverage.

Use two properties to make map behavior decisive: a transition-only property must appear only in the transition map; a property also affected at animation level must follow the animation-origin composition/underlying path and be absent from the transition map. Choose fixed numerical endpoints, paused/held progress and add/replace composition so values are calculable from the fixture. This tests existing composition semantics; it does not establish the final important-rule cascade until a transient recascade is added.

Admission failures for nonempty/aliased output references are not web-observable. The temporary driver can perform these two negative calls internally after capturing valid inputs, confirm false and unchanged output ownership, then perform the ordinary empty/distinct-output call. Label these as API-contract controls, separate from semantic value tests. Never expose arbitrary pointer or mask construction to script.

## Harness and build scope

A new standalone mochitest using `SpecialPowers.getDOMWindowUtils(window)` can sit beside the existing `file_domwindowutils_animation.html`, with its own manifest entry in `dom/base/test/mochitest.toml`. Keep the test independent of the larger `test_domwindowutils.html` window-opening sequence. The production helper remains in the cumulative eight-file candidate; instrumentation adds the XPIDL and window-utils implementation, plus one test/manifest. XPIDL changes require generated bindings and a real native build; the existing retained browser cannot execute this method. Root owns the reversible installation/build/run/restore transaction.

Run the ordinary 130-record preservation suite and the new direct-driver suite as separate gates. Preserve all original 20 CSSOM-lifetime plus nine underlying controls; they still exercise the unchanged public path and their failures are not repaired merely by this unused helper. Freeze every direct callback name, precondition, expected result and diagnostic schema before the candidate run. Reject crash/ERROR/missing/duplicate callbacks, not only assertion failures. Verify full native/app restoration afterwards.

A first driver can cover fixed/implicit/additive/fresh maps/admission/held timing without new CSSOM integration. Pending, finite-range and CSS-transition setup should be calibrated for reachability, then added with exact observed prerequisites. Do not claim those branches covered by a test title alone. A meaningful direct-driver success advances this helper's readiness; it still leaves animated provider context, final CSSOM cache clearing/admission/visited handling and pseudo-aware recascade unresolved. The final missing-pseudo debug transform-hint gate is unchanged.
