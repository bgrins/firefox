# NameRepeat context-computation proposal

Unaccepted implementation proposal for known bug2037744: two Rust files and one ten-case WPT. No Round or Sign code changes. The intended parent includes fix122's saturated-cache/native-consumer correction. No live native source, index, browser, build, signing or canonical-library action occurred.

NameRepeat now retains its typed Integer expression. The parser still rejects literal nonpositive counts, auto-fit, duplicate auto-fill and absent name groups, but no longer resolves contextual counts or calculates their cache. A specified LineNameList carries an unused zero cache. Its explicit ToComputedValue implementation first computes entries with the supplied Context, then folds their resolved group lengths with saturating multiplication and addition. Auto-fill contributes zero; an ordinary empty name group contributes one. No expanded repetition is allocated.

The computed type is still LineNameList<i32>; native layout and field types do not change. from_computed_value converts each resolved count back to an inline specified Integer and resets only the unused specified cache. Recomputing therefore preserves inherited computed counts rather than retaining the parent's contextual expression. A separate clone identity implementation for LineNameList<i32> honors the computed-as-specified contract. The initial unsealed generic implementation also covered i32 and was corrected before sealing because resetting its cache in the inverse would violate that identity.

GenericGridTemplateComponent::Subgrid gains compute(field_bound). The retained derive source shows that this produces the exact mapped associated-type bound for the boxed field. ToAnimatedValue, ToResolvedValue and ToShmem remain derived; cache shape is unchanged and Subgrid animation remains unsupported. The parser is the sole source constructor found by discovery; Default makes an empty list/cache0, conversion builds a fresh computed cache, inverse builds inline specified entries, and the computed identity is a clone. The native consumer uses computed LineNameList, not the specified placeholder. Full Gecko compilation must still validate the real derive/OwnedSlice integration.

## WPT scope and baseline interpretation

Four cases cover columns/rows with and without auto-fill across fonts16/32/8/16, using calc(2 + sign(1em - 16px)). Two cases cover calc(0) and contextual negative-result positive clamping. The remaining four cover empty groups/truncation, inherited computed counts with a differently sized child font, sibling-index changes after bounded sibling insertion/removal, and literal/grammar safeguards. Each target admission assertion follows independent font/em/parent-geometry and explicit literal expanded-name calibration. The target labels are `target name-repeat: declaration admission` and `target name-repeat: setter retention`; their baseline failure is a legitimate known-admission witness, not a calibration waiver. All other calibration failures remain invalid for that inference.

Explicit small expanded-name strings validate the literal controls rather than deriving expected cache values from candidate code. The inheritance test uses an explicit-name child twin (no repeat count in its oracle), with parent count3 and child font8; this checks computed inheritance instead of re-evaluating the parent's expression as count1. Histories within each case stop at a first failed assertion; no later assertion is claimed reached. Browser syntax/admission, resolved names, tree invalidation and inheritance remain unexecuted until root's comparison.
