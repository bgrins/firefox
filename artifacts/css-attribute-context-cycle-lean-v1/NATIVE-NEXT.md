# Next native boundary

Keep the shared raw DOM snapshot by expanded name, and the existing per-URL parse snapshots. Replace the owned caller's reliance on a shared computed attribute slot with an **owned evaluation attempt**, whose identity includes the actual root generation, parent substitution request identity, expanded name and exact URL context. Results are delivered only back to that request. Do not satisfy another request merely because a previous context produced the same CSS bytes, or because a generic attribute node is Complete.

1. At `SubstitutionReferenceStage::Lookup(TypedAttribute)`, retain a child continuation for the parsed raw attribute text. `CapturedAttributeInput::parse` supplies the request's URL-specific parsed source; RawAttribute has already retained missing/present status. Begin the semantic attribute guard before consulting any completed-body cache. The child keeps its parser/output/taint/active expansion state across Pending. Its eventual result is fed into the existing per-consumer `parse_typed_value` using that consumer's URL and syntax. Body invalidity selects the existing attr fallback; pending never does.
2. Put guard identity and cycle marks in the same retained Context authority used by actual custom-property frames, rather than in an isolated attribute evaluator. The logical identity is the dependency kind plus expanded name; URL belongs to computation identity. When an actual recurrence is discovered, mark participating invocation tokens. A registered property's `handle_invalid_at_computed_value_time` can publish its initial, but must not remove those ancestor marks. Check marks at both entry and completion of each guarded body.
3. Replace both ReferenceWalk's and the eager walker's attribute use of the shared `(name, namespace)` value with this actual-attempt result/discovery boundary. The selected variable/property links encountered by the child still have to enter the existing semantic graph. A side traversal's foreign SemanticOpen or ComputationPending is not automatically a CSS cycle. Preserve the parent cursor/lowlink/semantic floor while the actual edge is classified; no ready reply merely because lookup storage exists. This graph join is required before the new adapter can replace the guard in shipped code.
4. Deliver terminal replies by exact attempt/request identity, then retire the attempt only after its parent consumes the reply. Do not retain its computed body as an automatic cross-root cache. The raw fixed-element snapshot may remain; immutable final custom-property bindings keep their existing authority. Do not clear/recompute those custom bindings or retract prior publications to make a new attribute attempt succeed. Actual reset must still reject every live continuation and rotate generation only after complete retirement.

This deliberately trades attribute recomputation for a simpler initial cache contract. It does not yet prove that repeated nested computation has identical effects: raw query retention, once-per-attempt parsing, environment snapshots and wrapper/cache effects must be tested at the actual boundaries. It also does not settle the global native custom-property graph's finality when a newly encountered attribute context reveals another dependency. That is a required integration obligation, not permission to choose a default or emit CSS Invalid on an unsupported wait.

The first extracted successor should exercise the actual provider/Context methods with two URLs and one raw snapshot: valid env results in both evaluation orders; cyclic env fallback versus an acyclic primary; A/context1 → registered B/context2 → A/context2 with a real default publication; legitimate outer attr fallback; wrong request/generation; repeated Pending without query/output/effect replay; and a previously completed receipt retained while another attempt cycles. Add mutations that merge context results, include URL in guard identity, erase marks on B's default, or treat pending as fallback. No standalone facade result should be called native scheduling validation.

None of these steps are installed by this model artifact. Caller-v2 remains sealed with its explicit multi-context invalidation limitation. The next implementation must preserve the accepted u32 capacity change and pass a fresh controlled native typecheck before browser claims.
