# Finite conditional-default edge closure

This isolated Lean module proves a general result for the abstract closure oracle used by the sealed cyclic-default review. It does not prove the dynamically extended Tarjan algorithm equivalent to that oracle, nor verify Stylo scheduling, source dependency discovery or invalid-default publication.

A system has an arbitrary vertex type, fixed base edges, one existing target vertex and a fixed Boolean default-eligibility predicate. `Path` has only edge and append constructors, so cyclic membership requires a nonempty path back to the same vertex; reflexive reachability alone is insufficient. A round retains previously enabled default edges and enables v→target when v is eligible and cyclic in the current graph. Base edges are never removed. Graph inputs, eligibility and the target do not change during iteration.

The finite witness is an exhaustive list containing every vertex. Duplicates are allowed: each enabled occurrence contributes to the count, and the bound by list length becomes looser. No distinctness premise is silently assumed. An existing target makes these systems nonempty; an empty vertex type is not a system instance. Finite termination derives from monotonic count growth, rather than assuming eventual completion or imposing a native pass budget.

`finite_stabilization` proves that every inflationary Boolean activation operation on this finite domain reaches a fixed point within the remaining list-count budget. `fixed_persists` proves subsequent rounds remain fixed. For the conditional-edge operation, `path_mono`, `cyclic_mono`, `graph_mono` and `round_mono` derive monotonicity. `run_contained` shows each stage lies inside every closed supergraph containing the base. `finite_least_closure` combines bounded stabilization with that leastness property. `arbitrary_finite_graph` supplies the abstract least closed graph for any fixed base relation and finite witness.

The `System.cycle` Boolean oracle must be exact for the nonempty `Path` definition; this is an explicit interface obligation, not an assumed native capability. `fromGraph` constructs such an oracle using classical decidability, so the mathematical result is not vacuous or restricted to an unspecified implementation. That construction is noncomputable: this module does not provide a general executable cycle detector or establish a complexity bound for one. The generic constructive interface accepts any separately justified exact detector.

A separate executable three-vertex witness uses bounded nonempty path search only for its concrete graph. Initially 0 has a self-edge, 1→0 and 2→1, and 0/1 may add edges to target 2. Round 1 adds 0→2, making 1 cyclic; round 2 adds 1→2. The positive witness and false controls reject one-round completion and self-edge-only cycle recognition. That bounded example is not used in the arbitrary-graph proof. Other false controls reject discarding an enabled bit, ignoring eligibility, activating an acyclic vertex, and treating an empty non-exhaustive count as equality evidence. All six fail because Lean's decide tactic proves their propositions false. They are abstract false propositions, not mutations of native code.

The frozen source bridge is deliberately limited. The native post-edge hook uses lowlink/self-reference/stack state to detect a cyclic custom node and asks whether its actual invalid/default computation depends on ColorScheme; it then calls visit_link before SCC popping. In this abstraction those facts are represented by exact cyclic membership and a fixed eligibility bit. The prior Python experiments compare a small dynamic DFS against a closure oracle; their 12,288/98,304 cases are not converted into a general equivalence theorem here. Actual default eligibility, selected-edge completeness, changing context and post-pop publication must still be related to this model separately. No CSS cycle policy, native pass count or browser result follows from the theorem.
