# Parent publication barriers for descendant animation completion

The actionable mechanism is a staged traversal that does not release a parent's child work until the parent has applied its selected timing input, rebuilt the required effect data, sampled its animation rule and published its final computed style. This is materially different from repeatedly draining Pending or adding another document traversal. For a finite inheritance tree with fixed external inputs and target-local evaluation that does not depend on unfinished descendants, an iterative parent-before-child worklist terminates by advancing through the tree, independent of its depth. Existing APIs provide most of the operations, but the current traversal does not provide the barrier or the required private intermediate-style contract. No native patch has been installed or compiled here.

The actual Chrome depth results support pursuing this mechanism: all four first reads pass with the same literal and initial controls that calibrate both Firefox runs. They do not prove this is Chrome's algorithm. Same-element Chrome output instead agrees with Firefox original; a pre-own-effect timing input is an independently testable policy choice, not a consequence of the descendant completion evidence.

## What the exact branch does

1. `Servo_TraverseSubtree` performs any needed animation-only traversal and then a normal traversal. `traverse_subtree` chooses the optional Rayon pool and calls `driver::traverse_dom`.
2. `parallel::style_trees` calls `RecalcStyleOnly::process_preorder`, which borrows `ElementData` and calls `recalc_style_at`. That computes/cascades the element, `finish_restyle` queues animation tasks and publishes its style, and `note_children` immediately exposes descendant work. Parallel workers may begin descendants while other branches are still running.
3. `SequentialTask::UpdateAnimations` is not an inline callback. Tasks execute when `SequentialTaskList` drops after traversal contexts are released. `driver.rs` explicitly explains that these tasks may call `Servo_StyleSet_GetBaseComputedValuesForElement`, which creates another main-thread style context; retaining the outer TLS borrow would panic. Merely disabling Rayon or invoking tasks inside `compute_style` does not satisfy the borrow/lifetime contract.
4. `EffectCompositor::PreTraverseInSubtree` selects eligible map entries, updates cascade results, posts animation restyle hints and calls `WillComposeStyle`, then removes entries. These are preparation/admission operations. Actual rule composition occurs later: `replace_rules_internal(RESTYLE_CSS_ANIMATIONS)` → `GeckoElement::animation_rule` → `get_animation_rule` → `Gecko_GetAnimationRule` → `GetServoAnimationRule` → `ComposeSortedEffects`; the resolver then cascades that rule and `finish_restyle` publishes values.
5. The current `StyleDocument` permits one compositor follow-up, not an element publication barrier. Thus a child can use its parent's old animation output even though its own CSS timing is subsequently corrected. The observed stage8 duration/progress equality with old font output is not itself an acknowledgement of fresh composition.

SOURCE-EXCERPTS.json retains exact local traversal bodies and their whole-file hashes. All eight match the previously frozen closure captures; context/traversal/matching/wrapper/cascade also match the recorded original build pins. Driver/parallel/gecko-traversal are not individually present in that build pin map: their current-to-frozen equality is not represented as an independent compiler-input proof. Root's current six-file capture supplies glue/manager/resolver/rule-tree/StyleSet. The tested tri-state compositor postimages remain separate from the ordinary original source.

## Concrete two-boundary API design

Implement the scheduling boundary in Gecko's style transaction, with Rust doing short, nonrecursive frontier batches. Do not place a main-thread callback inside a worker's borrowed cascade context.

**Prepare a frontier.** Refactor `compute_style`/`finish_restyle` so the style resolution result can be retained privately before `data.set_styles`, child-hint propagation, display:none descendant clearing, frame damage publication and cache insertion. Each record owns target/pseudo identity, the original before-change style, the provisional `ResolvedElementStyles`, task flags and captured parent/root-input generations. It does not export borrowed `ElementData`, an `AtomicRefCell` guard, a rule-cache borrow or a TLS reference. `StyleResolverForElement` already returns owned styles; this is a separation of existing resolution from publication, not a new CSS evaluator. The new ABI needs an owned batch, not pointers into a worker vector.

**Execute main-thread tasks.** End the Rayon scope and drop all main/worker traversal contexts. Transfer the task list explicitly rather than relying on its destructor at an unknown later point. Main-thread code updates CSS animation timing and the requisite keyframe/effect data using the batch's explicit style arguments. The current `GeckoElement::update_animations` reads `styles.primary()`; it must gain an explicit-input path for the private provisional style. Otherwise the batch would accidentally use the old published primary. Preserve the original before-change style for transition processing. Validate target/document/pseudo/effect ownership again after callback-capable native operations; no hash-map entry handle survives the operation.

**Compose and publish the same frontier.** Extract an exact-target preparation helper from the existing `PreTraverseInSubtree` body. It must preserve throttle eligibility, removed-effect cleanup, cascade updates and both cascade levels, but must neither consume descendants nor clear unselected work. Reuse actual rule replacement and cascade, with fresh short-lived contexts, after the updated timing/effect data exists. Only this completed cascade can publish the parent's style. Publish root font/line-height caches here, using the existing `finish_restyle` logic, before any descendant root-unit calculation. Diff the original style against the final style, then propagate child hints and perform the existing post-traversal/frame processing at its appropriate outer boundary. Do not transiently clear children or create/remove frames based on a provisional style.

Only now may `note_children` release descendant work. Store continuations in an iterative Vec/queue, not recursive C++ calls. A level can remain parallel once all its inheritance predecessors have published; a simple first implementation may serialize batches without changing the semantic order. Main-thread tasks cannot overlap a worker reading the target/effect state they mutate.

`API-SKETCH.md` gives the explicit phase/result contracts and names the functions requiring refactoring. It is not a compilable/applyable patch. The required changes span driver/parallel/traversal/matching/context, Gecko's glue/task ABI and selective compositor admission; presenting a small `while (PreTraverse())` patch would conceal these obligations.

## Why this handles the demonstrated arbitrary-depth family

For each depth-fixture node, its duration depends on the final inherited input metric, and its output endpoint literals are16px/32px. The parent is already published. At paused1500ms, update duration to1000 or2000, compose the existing stepped effect, and publish the opposite output metric. Child scheduling then observes that output. The opacity leaf repeats the same dependency step. There is no dependence on how many nodes are in the chain and no iteration-until-numerically-equal rule.

After root font32 is published, the first intermediate obtains duration2000 and publishes line-height16; the next obtains duration1000 and publishes font32; induction repeats this alternation to the leaf. Each intermediate plus leaf is evaluated once with its final ancestor input. This is a conditional implementation argument for the fixture's dependency family, not a native proof or a promise that two generic recascades per element solve all CSS. Changed-node admission must still include every affected descendant through the existing inherited-value/root-unit invalidation; an entirely clean node that is skipped cannot be repaired by a barrier it never reaches. A correctness-first experiment can traverse the complete affected inheritance subtree, with incremental pruning deferred until coverage is demonstrated.

The established Completion/DAG models explain coverage and rank under explicit evaluation assumptions. They do not prove this native batch has evaluated every endpoint or handled every pseudo. The new native acknowledgement is final style publication after actual rule sampling, not map removal, timing equality, or `WillComposeStyle`.

## A concrete admission route for a first executable experiment

The ordinary source keyframes have not been erased: `KeyframeEffect::mKeyframes` retains each `PropertyValuePair::mServoDeclarationBlock`; the current computed `mProperties` is rebuilt from them. A correctness-first opt-in path can therefore classify **specified** endpoints rather than guessing dependence from their already-computed numbers. A new Rust declaration-block classifier can positively admit only explicit complete replace endpoints with no variable/attribute references, relative units, additive/accumulate/missing base operands or range offsets. For the first path, the concrete forms needed are font-size:px, line-height:px and opacity:number with existing easing/composition code. Reject other forms before performing experimental publication; do not reinterpret them as CSS invalidity. Validate the entire effect stack (and own SMIL/transition presence), not just the selected visible property.

Combined with stable hold-time/document-sample input and the selected pre-own timing rule, this gives the parent-barrier experiment an implementable local admission test covering arbitrary depths of the demonstrated inherited-metric family. It does not require a speculative graph inferred from Pending. It is deliberately not broad CSS support or a production fallback guarantee. Base-style computation still requires stable parent/root/style/layout inputs; a mode that cannot establish those conditions must remain outside the completion claim. Do not infer endpoint independence from `AnimationValue` being a number/length: the number can have been computed from a relative specified value.

The new classifier is not written here. Its concrete source input and rejection surface are now identified; implementing it together with the phase split is a bounded next native experiment. Subsequent support should remove this restriction through property-stage/deferred endpoint resolution, not widen it by recognizing the test's class names or numerical outputs.

## Target-local evaluation is the remaining separate problem

Pre-own-effect timing makes the timing-list input independent of the target's own CSS/WA/SMIL/transition rule outputs under the proposed all-own exclusion. It retains current parent composition. It therefore removes the timing self-loop in the demonstrated stepped own-font case, but says nothing by itself about keyframe endpoints or additive base values. Do not automatically restart timing-list updates during the final composition-only stage. Capture the timing-input generation; redispatch is for an actual changed external input/rule generation, not the broad `needs_animations_update` predicate firing again on the same batch.

`KeyframeEffect::UpdateProperties` builds properties from the supplied computed style, refreshes base values even when segments compare equal, and can request Layer after either changes. A font animation with independent fixed duration plus a width animation with1em→3em endpoints is a concrete local acyclic dependence: publishing the new font can make the previously computed width endpoints stale. An implementation that assumes the first endpoint build completes the whole target is incomplete even though all timing inputs are stable.

The existing normal cascade applies custom and prioritary properties (including font-size and line-height), then late properties. The saved deferred-animation prototypes retain original endpoint declarations and compose actual `AnimationValue` operations in an append-only arena. Those are useful ingredients for sampling endpoints at their correct cascade dependency stage. They are not a ready full solution: the retained endpoint resolver currently handles registered custom properties, and the rejected rule-transport draft has no valid general needs-resampling/error propagation path. It cannot be enabled for ordinary width/font/line-height by relabeling endpoint IDs.

A concrete second implementation milestone is to carry selected effect operations/declaration provenance to the existing cascade stages, resolve early outputs before late endpoints, and publish only resolved winning property roots. Complete replacement must discard earlier dependencies; additive/implicit endpoints retain them. Public CSS serialization and commitStyles may not receive unresolved values. Custom-property SCC/defaulting policy, taint and registration changes remain explicit. This would avoid repeatedly rebuilding a whole target to discover an ordinary property order, but it is a larger integration than the parent barrier.

## Counterexamples and invalidation boundaries before any drain loop

- **Local endpoint feedback remains possible without timing feedback.** An animated registered length `--x` with em endpoints, `font-size: var(--x)`, and fixed duration exposes a potential endpoint→font→endpoint cycle if every new composed font is fed back through `UpdateProperties`. This is a source-derived falsifier to test, not an executed result or a chosen CSS cycle policy. The existing declaration cycle logic cannot be assumed to see dependencies already erased into concrete animation values. Freeze/reconstruct/resolve policy must be explicit.
- **Transitions are not repeated CSS animation updates.** The before-change style and transition start/reversal bookkeeping belong to the original style change. Replaying CSS_TRANSITIONS on provisional and final intermediate styles can start/cancel/reverse transitions that should not exist. Preserve one before-change snapshot and a separately defined transition phase; do not replay the complete SequentialTask flags on every retry.
- **Timeline time is not universally a constant argument.** Paused `mHoldTime` is returned directly; document timelines use the refresh driver's most-recent timestamp, and the inspected scroll timeline reads cached geometry/time data. This supports stable inputs inside an unchanged sample, not across timeline rebinding, scroll-timeline updates or later layout/scroll resampling in the outer transaction. Capture sample/timeline identity and invalidate the batch on a change; no unbounded automatic restart is justified.
- **Layout-dependent sources break the inheritance rank.** Container units/queries, anchor queries and view/scroll timeline geometry may depend on layout influenced by descendants. They cannot be silently completed by a strict ancestor style walk. Preserve the existing layout/container transaction policy and distinguish needs-layout from a ready style batch. A ready getter may need the existing outer pipeline; it does not permit a new recursive flush from inside Servo.
- **Global/pseudo inputs require real predecessor ordering.** Root rem/rlh caches must be published before descendants, never temporarily replaced with target base values. Element-backed and eager pseudos, display:contents layout parents, NAC and shadow/flattened inheritance do not share one raw DOM-child relation. The scheduler must use the existing traversal/inheritance relations, with eager pseudo styles finalized as part of their originating-element batch before consumers are released.
- **Rules/effects/membership can change internally.** New keyframes, CSS animation cancellation, missing pseudos, display changes and timeline scope updates invalidate stored identities or generations even under a script blocker. Aborting an invalid batch must preserve unprocessed work, not mark it complete. Returning stale output as a successful query would need an explicit existing policy, not a fresh arbitrary fallback.

These are reasons not to turn pre-own timing into an unrestricted queue drain. They are not reasons to cap the depth of a certified inherited chain.

## Recommended next implementation

Implement an isolated parent-barrier traversal experiment for the ordinary fixed-sample inherited-metric path, using explicit provisional styles and exact-target main-thread task/rule boundaries. Start with the entire affected inheritance subtree so missed dirty admission is not hidden by incremental pruning. Keep pre-own timing as the separately reviewed input-policy change. Exercise arbitrary generated depths, wide siblings and multiple changing ancestors, and retain first-read assertions; also test relative late endpoints, transitions, script-owned timing, pseudos and invalidated batches before broadening the supported path.

Do not claim a complete production fix until the selected path's target-local endpoint semantics and exclusion/fallback rules are executable and reviewed. This package supplies a concrete staging/ownership design and identified existing calls, not an enabled owner, native patch, compiler result or new accepted fix. It neither repeats the prior Pending-only certificate sketch nor claims that CSS is globally a DAG.
