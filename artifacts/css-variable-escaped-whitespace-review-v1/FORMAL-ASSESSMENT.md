# Limited companion proposal (not implemented)

The accepted registered-token-boundary component supplies a useful first/last accumulator pattern and independent flattening reference. Its actual event semantics cannot directly serve this scanner: Boundary omits comments and flattens a block through its closing Other, whereas declaration scanning retains comment DelimSlash and an outer opener class. Reusing class constructors or list lemmas requires an explicit projection; do not claim its theorem proves this scanner's exact last class.

A substantive new component can model finite outer-token segments, each with a raw byte list and class, with whitespace segments carrying exact raw payloads. The reference splits the concatenated source at the independently identified terminal whitespace segment. A source-shaped scan overwrites trailing length with the current whitespace payload length, or zero otherwise. Prove its final length equals the reference suffix length under actual coalescing/nonempty-token premises. Then derive index bound, retained prefix equality, and that all bytes belonging to preceding non-whitespace tokens survive, even if their own final bytes are spaces/tabs. Do not assume non-whitespace payloads cannot end in whitespace bytes: that would exclude the bug.

The constructor relation should distinguish old standalone leading trim from current initial-token skipping. Saturating subtraction handles all-whitespace overlap on the former; prove that overlap separately rather than assuming subtraction never underflows. EOF-generated suffixes need a source-derived compatibility premise: a repaired unclosed outer token is non-whitespace, so terminal trim length is zero. Reference offset bounds apply only to retained prefix spans.

Track original last class and last non-whitespace class independently. Derive the replacement rule only when length actually shortens; avoid claiming exact closing-token class correspondence for opener summaries. Token serialization separator adequacy is a different theorem. Original raw-byte trim must have a concrete escaping witness; mutants trimming every final ASCII whitespace byte, resetting length incorrectly on a comment/block, or using decoded/normalized whitespace length should be discriminated.

Explicit admissions: actual parser produces the coalesced outer span partition; raw Rust string length/UTF-8 slicing and EOF transformations; comments and nested blocks project as stated; usize/source-length bounds; reference offsets and typed/substitution providers; compiler/runtime. Backslash delimiter followed by newline is outside any retokenization-preservation claim, despite its whitespace suffix being correctly measured. No native build, Lean replay, or theorem is performed by this assessment.
