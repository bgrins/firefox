# Getter-specific property computation route

A concrete reusable route exists, but this is an API/source design, not a patch-ready conformance claim. Baseline conformance now reproduces five getter failures with three specified/token controls. Native implementation is deferred behind the separate font sampling diagnostic and direct-query prerequisite experiment.

Introduce a getter-only FFI computation boundary at the non-null authored declaration branch in KeyframeEffect::GetKeyframes. Keep metadata/group ordering, offsets, property-name conversion and generated null-declaration base serialization intact. Gate computation on BOTH current association with CSSAnimation and keyframes not replaced through setKeyframes. AsCSSAnimation alone is insufficient; GetComputedKeyframes true alone is also insufficient after an effect is detached. Re-evaluate ownership/source state after style flushing rather than presuming the preflush bool remains authoritative. Detached, null-target and missing-style paths need explicit admission/fallback tests before claiming a complete repair.

For each requested authored property, create a fresh create_context_for_animation-derived context from the current computed style and real target/pseudo/parent/container/attribute context. Follow the pseudo-aware parent/container setup of Servo_GetComputedKeyframeValues, but do not run that function's per-keyframe custom declaration batch. Each result must be independent of other authored endpoint declarations; current element values supply dependencies. A fresh disposable context per property prevents a computed endpoint from becoming another property's dependency. It costs repeated context setup, which should be measured before introducing any shared context optimization.

For an ordinary declaration, AnimationValue::from_declaration provides existing variable substitution and typed computation in that context. Audit its computed-to-animated-to-serialized roundtrip for the accepted property classes; a rendering representation is not automatically a complete CSS computed-value serialization proof. Preserve logical/physical property identity and shorthand-expanded declaration selection. The current serializer's first-declaration assumption is not a license to compute an arbitrary first entry if a block is broader.

For CustomDeclarationValue::Unparsed, use existing public custom_properties::substitute_references_if_needed_and_apply(name, None, value, stylist, context, tracker), then read that named value from the disposable context and use CustomAnimatedValue::from_computed. Unlike CustomAnimatedValue::from_declaration's universal branch, this performs reference substitution. It also uses existing registered syntax/computation, invalid-at-computed-value handling, CSS-wide fallback handling and taint-aware value construction. There is no need for a second string evaluator. No computed endpoint is published to the element or shared with another property's context.

This custom helper mutates its local substitution map; that is intentional only inside the disposable per-property context. Its inherited/initial fallback reads require a correct actual parent style. Typed-attribute preparation remains an explicit gap: rendering uses KeyframeCustomPropertiesBuilder.prepare_attributes before substitution. Reusing this lower-level helper without auditing preparation/cache readiness for attr(), fallbacks and nested references is insufficient. Keep a real AttributeTracker and preserve attribute-taint semantics, while avoiding any persistent getter-result cache based on discarded dependency outputs.

Parsed custom values and direct CSS-wide declarations can use existing typed/custom computation only after auditing their semantics. Existing from_declaration and substitution paths contain revert/revert-layer/revert-rule limitations and different fallback treatments. Do not erase that distinction with a blanket success/empty-string fallback. Distinguish valid guaranteed-invalid serialization from unsupported/missing context and computation failure; specify which cases retain prior behavior and what remains unsupported. Self-reference/cycle, fallback, registration initial/inherits, URL/attribute taint, logical/shorthand and disconnected/pseudo cases require focused controls before a broad native helper is accepted.

The first concrete candidate should leave rendering/SMIL and ordinary WAAPI/replaced-CSS serialization untouched, establish the isolated getter contract, and pass the new eight-case suite plus existing getter/grouping/range/attribute controls. The currently failing animated-font precondition is a separate observation; it must not be “fixed” by changing the computed-value oracle or by adopting endpoint-local dependencies. No native/browser/Git changes or new bug count occur in this capsule.
