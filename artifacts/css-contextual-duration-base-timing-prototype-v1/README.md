# Experimental pre-own-effect timing input

This is a compile/test payload, not a settled CSS policy or accepted fix. The patch separates CSS animation-list input from the current style used to resolve keyframes and effect properties. It adds no traversal loop, pass budget, queue drain, or completion claim. It is designed as a successor to the tested three-file duration/tri-state candidate: retain both EffectCompositor postimages, replace matchingc3b2 with this package's postimage, and add the captured nsAnimationManager.cpp change. No owner, native installation, build, browser, or Git operation was performed.

## Concrete implementation

`nsAnimationManager::UpdateAnimations` keeps `ServoCSSAnimationBuilder(aComputedStyle)` unchanged. A local owning `RefPtr<const ComputedStyle>` holds the timing input through `DoUpdateAnimations`. For an existing actual target/pseudo element, `GetBaseContextForElement` recascades without that target's own animation-origin rules, using the inheritance parent's current primary style. Only `timingStyle->StyleUIReset()` becomes the manager's animation-list input. Keyframe lookup/resolution, `SetKeyframes`' composed style, `Gecko_UpdateAnimations`' EffectProperties and transition inputs, and per-field JS ownership checks retain their existing code and input. No new pointer survives the call.

This deliberately takes the whole animation UIReset list input, not only duration: names, duration/delay/iterations/direction/fill, default easing, play state, timeline/ranges and composition retain the manager's existing list matching/defaulting semantics but use the selected base style. Other UIReset fields are not consumed by this manager path. A missing generated pseudo element falls back to the existing composed input, matching the base-style API's need for an actual target. That fallback is explicit incomplete coverage, not a claim that every pseudo path now follows the new policy. Display:none and null-style handling still occurs on the original composed input before this selection.

The Rust companion makes admission conservative for CSS-animation targets whose styles are already being recomputed. It drops composed `animations_equals` as the animation-only exclusion and makes the eligible final fallback of `needs_animations_update` true. Existing-or-specified CSS animation filtering, no-old-style/pseudo logic, display transitions, writing-mode/scroll cases, ordinary transition handling and existing task dispatch remain. This also preserves inactive-but-specified eligibility. Equal composed lists cannot justify skipping a base timing change hidden by an own effect. There is no new persistent base cache and no attempt to infer base equality from rule-pointer equality. This may rebuild keyframes and recascade timing more often; performance and scheduling regression tests are required. It does not create restyle roots for elements that were never invalidated/recomputed, nor prove external-variable/root invalidation completeness.

## Explicit experimental policy and hazards

| Input | Chosen behavior / unresolved boundary |
| --- | --- |
| Own animated font used by em duration, including multiple effects | Remove all target animation rules before resolving timing. Another same-element fixed font effect is excluded too; this intentionally changes the same-element DAG timing choice. Expected bounded observation is original/Chrome-like effect1000ms/.75 rather than candidate1375ms/6⁄11, provided parent/base inputs are current. Computed CSS serialization remains on the existing composed style and may still differ from Chrome. |
| Own animated line-height used by lh duration | Same all-own exclusion. A target's self-font/lh feedback is not solved by iteration; timing reads the recascaded underlying own font/line-height plus composed inherited inputs. This is a proposed policy, not a self-cycle theorem. |
| Descendant inherited em/lh | Inheritance parent primary remains composed. This does not settle late parents or advance a descendant chain before the first getter; the depth completion gap remains a separate mechanism. |
| Root rem/rlh | No device root cache is swapped or published by this patch. Root-target and non-root root-unit computation have distinct existing paths; descendants may consult composed device root metrics independently of the supplied parent. Removing own rule levels is not a guarantee of a globally pre-animation root basis. Root cache freshness and root-unit cycles require their own tests. |
| Animation origins | The existing helper removes levels classified as animation, including SMIL, CSS/Web Animations animation rules and transitions. It is neither CSS-only nor per-effect. Important/static rules are retained. Excluding own transitions/SMIL is an explicit experiment and requires validation, not an inference from the two Chrome fixtures. |
| Custom properties | The existing cascade recomputes local variables from the filtered rules while inheriting parent values; registration, fallbacks, inheritance and the held custom-property provider remain prerequisites. No animation-taint rule is added or bypassed. Own-origin exclusion is not equivalent to animation-taint handling, and inherited tainted/registered values or base animation names masked by other origins can exceed current admission coverage. |
| CSS/script ownership | Existing `PropertiesOverridenByJS` handling remains byte-identical. Applied duration overridden through `updateTiming` stays script-owned even if selected CSS timing changes; keyframe ownership and element/effect identity must be tested. |
| Other dependencies | Viewport/container/layout/font metrics, root cache generation and rule/variable changes retain existing invalidation. This prototype neither proves that all such dependencies are acyclic nor introduces a general dependency graph. |

## Exact applicability

The manager base comes from root's read-only six-file capture at HEADecfe/epoch3a0b/indexaf90, not from an assumed upstream match. Its SHA is3b24c4e0. Captured glue, resolver and rule-tree bodies establish the recascade/parent path. The branch rule-tree helper has an explicit fast-path/filter implementation different from the public version previously studied; the branch body is authoritative. The C++ builder, old-animation ownership update, BuildAnimation and DoUpdateAnimations bodies are unchanged by exact comparison. Matching's starting SHA is the already tested experimentalc3b2; this is not a patch directly against accepted matching41e. SOURCE-ROLES records exact base/postimage paths and hashes.

The existing helper omits visited styles. It can return the supplied style unchanged when no animation rules are removed; this patch does not change that behavior. Its local recascade context is not a new cross-restyle cache. The parent can still be stale, and helper reads can use device caches; a freshly allocated timing object is not proof of fresh contextual inputs.

## Falsifying validation before any landing decision

First compile the four-file combined experiment, preserving the tested EffectCompositor pair. Reuse the exact same-element and depth fixtures: compare effect timings and rendered outputs separately from computed CSS, preserve all first/passive samples, and retain self-feedback as diagnostic without an endpoint oracle. Re-run existing updateTiming, inactive-but-specified, property-only width, literal and restyle suites because conservative task admission changes work frequency.

Additional policy cases are required before broader claims: own font/em and own line-height/lh; inherited parent metrics; root and descendant rem/rlh with animated root metrics; multiple CSS/WAAPI effects plus transitions/SMIL; actual/generated/missing pseudos; custom-property registration/fallback/inheritance/taint and masked base changes; script-owned timing/keyframes. A test showing base timing changed without any CSS task falsifies admission completeness. A computed CSS/effect mismatch alone does not identify which policy is required. No current fixture demonstrates all these boundaries.
