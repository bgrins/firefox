# Ordered numeric font-setting conversion and effects

This executable Lean contract models the prospective retained conversion boundary for `font-feature-settings` and `font-variation-settings`. It is separate from the 19 identity-like font inputs. It proves preservation of the entire ordered conversion/effect receipt list before last-value lookup; it does not implement a native queue or certify a native readiness classifier.

The exact e86 `FontSettings<T>::to_computed_value` maps **every** specified entry through native conversion, collects the resulting vector, and only then stably sorts and deduplicates it. A superseded tag can still have read font metrics or tree scope and set dependency/cache flags. Therefore preserving the final value map alone is insufficient. The model retains the original occurrence sequence, including identical repeated entries. Positions, not tags, identify conversion occurrences.

`poll` inspects only the next entry's declared AST demands. If they are not ready, the entire state is unchanged. Otherwise it converts that entry under its recorded scope, appends exactly one receipt, and removes exactly one queue occurrence. A completed queue does not replay. `run` allows any finite sequence of environment snapshots; it preserves completed receipts and their ordered effect trace, and conserves the original entry projection. `publish` is unavailable until the queue is empty. Its receipt projection equals the complete original list, so every original occurrence is represented once and in order. `lookupLast` represents the deduplicated map lookup, while `effects` still includes every receipt. `last_append_wins` holds for an arbitrary earlier list, not just the two-entry counterexample.

All entries in a native setting list belong to the same selected declaration scope. `published_selected_scope` explicitly transports that common-scope premise through the queue. The general queue also permits different recorded scopes, but the native single-property mapping must establish the common-scope premise. The concrete duplicate example uses scope 7 for both entries; its discarded entry contributes a distinct effect event. Scope identifiers and effect IDs are natural-number abstractions, not actual shadow roots or Gecko flag constants.

`ready_list_finishes` gives conditional progress: under a fixed environment that reports every entry's declared demands ready, exactly the remaining list length of polls converts the list and yields the same receipts as mapping the total converter once. This does not prove that providers eventually become ready, that a CSS cycle resolves, or that changing environmental inputs preserve published consumers. The existing computed-size publication model covers a different abstract no-stale-consumer obligation; neither model supplies native refinement for the other.

Native `ToComputedValue` returns a plain computed value. The examined Number and Integer implementations normalize/clamp results; their calc fallback includes a debug assertion for an unexpected non-number leaf, not a normal `Result::Err` protocol. Accordingly this model has no invented conversion-rejection or rollback channel. CSS parsing and selected-declaration rejection occur before admitted entries. Readiness waits happen before an entry conversion. Allocation failure, panic, arbitrary runtime interruption midway through native conversion, and partial effects on such failures are outside the model. Conversion is treated as one atomic value-plus-effect relation; native leaf-level read/effect interleaving is not proved.

`Expr.reads` is an explicit abstract projection of the selected AST, not a proved parser or exhaustive demand extraction. Empty reads permit an immediate literal conversion; there is no blanket all-font wait. Parent-size and parent-metric labels reflect the current normative investigation, not e86's CurrentStyle implementation. Viewport, selected-tree and random-seed labels show heterogeneous inputs, but are not an exhaustive unit taxonomy. The native adapter must establish both readset completeness and temporal finality. An arbitrary `Env.convert` is total and receives the exact recorded scope; proving that native conversion corresponds to that relation, that effect records represent actual cache/flag writes, and that later mutations cannot stale earlier receipts remains external.

Effects here are an ordered event trace. Native ORed flags may be idempotent and a cache may be populated already; the model does not claim every duplicate conversion visibly changes state. Its counterexample shows why an implementation may not discard an entry before determining its conversion effects. Random conversion is not modeled as consuming a global RNG sequence: exact e86 hashes the key, optional element and document seed, constructs a fresh seeded generator, and also mutates cache/flag state when applicable.

Actual final run5 passes **21 audited theorems and seven genuine false controls**, using only `propext`/`Quot.sound` where needed. The existing isolated publication-model runner/toolchain is reused with a small recorded delta; there are no imported project modules. All five owned scratch directories are absent. Run1 failed on a proof projection, run2 passed 17/7, run3 failed because `prefix` is reserved syntax, and run4 passed 20/7. Run5 adds the common selected-scope proof and makes the example use one native-compatible scope. No native/browser operations or canonical coverage increments occurred.

The seven controls reject deduplicating before retaining effects, wrong selected scope, treating Pending as a completed invalid value, publishing a partial list, replaying an already converted prefix, requiring an unrelated unresolved input, and unconditional progress while demands remain unready. The saved compile logs establish actual false propositions, not syntax-failure controls.
