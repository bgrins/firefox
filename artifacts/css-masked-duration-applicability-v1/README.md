## Can an older variable input reproduce the same masking?

An ordinary unanimated `--duration: 1s` → `2s` consumed by `animation-duration: var(--duration)` avoids dimensional arithmetic and animation taint. It is a useful ordinary-update control, but changes the composed timing list directly; it does not reproduce a hidden base-font change behind a fixed own-font effect. Substituting an em-based expression through a variable still needs the same deferred/typed time support. Registering a time or number and changing it normally has the same limitation.

Animating the variable to mask its ordinary underlying value is not a justified substitute. The current [Variables 1 animation-taint definition](https://drafts.csswg.org/css-variables-1/#animation-tainted) covers custom properties used in keyframes. [Variable replacement step 3](https://drafts.csswg.org/css-variables-1/#replace-a-var-function) substitutes the guaranteed-invalid value when an animation-tainted property is used by a non-animatable property, then step 4 permits a fallback. [Animation duration](https://drafts.csswg.org/css-animations-1/#animation-duration) is not animatable. For that explicit keyframe-defined variable scenario, the route to the animated time value is **NOT REACHED** at step 3; a fallback measures fallback behavior, not the proposed masked input. No registration-based exemption was established. The registered-property draft's animation section discusses typed interpolation, which alone does not establish an exemption from variable substitution restrictions.

There is therefore no claimed equivalent arithmetic-free standalone witness from this audit. Prefer the existing exact fixtures on the installed stock browser. Preserve the earlier first-getter specification trace's INCONCLUSIVE invocation/input bridge; this transport audit neither resolves it nor establishes a new defect.
