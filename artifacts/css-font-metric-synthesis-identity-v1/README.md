# Native priority identity compatibility correction

The first real Cargo check rejected the sealed synthesis candidate with four errors: the generated PrioritaryPropertyId has neither Eq nor PartialEq. The private FontTarget derive and two direct priority comparisons incorrectly required those traits. The completed Cargo log and exact diagnostics are pinned here; this package does not claim owner restoration or a successful native retry.

The successor changes only four cascade.rs hunks. FontTarget.same_as preserves the Metric/Synthesis variant and compares metric IDs through their existing to_longhand identity. Both direct priority comparisons use that same mapping. The provider remains byte-identical. PRIORITY-API.json pins the actual generator: both enum and to_longhand table enumerate the same prioritary longhands, so mapping preserves identity. No generated enum or global trait implementation changes, and no missing reference producer, pending policy or scheduling behavior is added.

The action token has one FontTarget comparison, now using same_as; the other uses only construct or match its variants. MetricDrain searches retained continuations by longhand identity, and publication clears an action only when the published priority matches its requested longhand. These maintain the intended equality behavior without requiring a new native enum contract.

The extracted harness now uses distinct priority and longhand enums. Priority IDs intentionally lack Eq, PartialEq and Hash; longhands retain equality/hash. Existing test expectations convert priority IDs explicitly. Fifteen tests pass, including exhaustive identity checks over eleven priority IDs and four synthesis IDs, variant distinction, retained rollback/reference behavior and the 65,535 synthesis cursor boundary. Sixteen compiled behavioral mutants fail their assertions. Three additional controls reintroduce the invalid derive or either direct comparison and fail compilation with E0277/E0369. All scratch outputs are removed.

The initial tightened harness exposed one old test pattern that incorrectly treated a longhand reference result as a priority ID; TEST-INITIAL retains that compile failure. The final harness corrects that test pattern. A mutation-generator uniqueness check also rejected an ambiguous replacement before compilation; the final generator targets the exact match arm. Neither required additional production changes.

Configured rustfmt and zero-fuzz forward/reverse patch checks apply only to artifact copies. native.patch is relative to the same published two-file baseline; PARENT-DELTA.patch shows the complete compatibility-only change. The next actual root-owned Cargo check is still required. Passing extraction is not native typecheck, metric repair, browser correctness or scheduler progress evidence.
