The change-bit closed form examines the **initial** block:

```
actions.any(new => new.important || !hasImportant(initial, new.id))
```

This is valid because every rejected prefix preserves the complete state. If a first accepted action occurs, the accumulated Boolean is already true regardless of later actions. The proof's accepted branch does not assert that later individual push flags still equal their initial-state predicates. `pushResult` continues the state fold even after the bit becomes true; `returned_flag_and_state` proves the complete fold state.

False implies all pushes were rejected and the state was retained. True can accompany identical final state, value, order or serialization, as the concrete equal-value example confirms. The nine kernel examples are useful nonvacuity/discrimination controls, including the reduced importance witness and early-stop loss; they are not compiled native mutations or substitutes for the universal proofs.

## Native source interpretation and precise boundary

Retained declaration_block.rs SHA-256 is `8474218db02f8787c212f47a08be33a468553b4ab809e774f2d26d4ae098812a`. Fresh checker reconstructs the complete `push` and `extend` bodies and matches their positions, bytes and hashes.

Actual `push` inserts the identity into the membership set before scanning an existing declaration. Under valid membership and unique aligned storage, this insertion leaves the existing identity membership unchanged. Existing important plus incoming normal returns false and preserves the block. Other replacements remove both matching vector slots, append the incoming declaration/importance, and return true even for equal payloads. Missing identities append. These are the modeled branches. Stale membership, duplicate initial IDs or mismatched declaration/importance vectors are outside the representation premise; the proof must not be applied to such states.

Actual `extend` reserves capacity, drains ordinary declarations, then processes all-shorthand expansion. **One call passes one importance value to every push.** The arbitrary mixed-priority mathematical history describes a flattened sequence of multiple parser calls; it is not the signature of a single native extend invocation. Actual generated iterator contents/order, shorthand expansion and identity providers are still admitted. Identity means the retained declaration ID, not an assumed physical-property quotient of logical aliases.

Both native accumulation sites use non-short-circuit bitwise operations: `changed |= self.push(...)` and `changed | self.push(...)`. The source therefore continues all pushes after a true result. The mathematical state fold matches that normal-completion intent. No proof of allocator, reserve-count arithmetic, iterator side effects, exceptions/panics, destructor behavior, compiler evaluation semantics or machine bounds is supplied.

Parser validity, rejected declarations, generated names, cascade across distinct origins/layers, computed values and serialization remain outside scope.
