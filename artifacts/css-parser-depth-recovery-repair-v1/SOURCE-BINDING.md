# Source correspondence and premises

The proposed production delta is one call to `parser.consume_until_end_of_block(block_type)` in the existing `TooManyNestedBlocks` branch, after `take_at_start_of` has consumed the pending opener. The limit, callback, normal branch, error kind and provider implementation are unchanged. Original and candidate complete parser files, the complete current tokenizer, and the complete declaration iterator are retained. `native/build.py` builds the actual full cssparser crate against each source variant, not an extracted replacement parser. Optional fast-match features are disabled; this scope is recorded in TOOLCHAIN.json. Dependencies and compiler identity are pinned.

## Lean mapping

| Native operation | Model | Admission |
|---|---|---|
| `BlockType::{Parenthesis,SquareBracket,CurlyBracket}` | `Kind` | The three matching kinds correspond; Function and ParenthesisBlock both project to paren. |
| `next_unchecked`, `take_at_start_of`, `BlockType::closing` | `Token.open`, `Token.close`, `Token.atom` | Every native token maps to exactly one class, an opener sets its correct pending kind, and nonempty input advances to a valid next byte boundary. Comments/strings/URLs are atoms regardless of internal punctuation. |
| `SmallVec` initialized with outer block; push on pending opener; pop only matching top; return on empty | `advance`, `run` | Model stack is top-first whereas native vector is bottom-first. Normal allocation, valid nonempty stack before `last().unwrap()`, and finite lexical input are premises. `run` structurally consumes one token per active iteration. |
| lexical CSS function/block contents | independent `Leaf`, `Body`, `AtEOF` grammar | `Body` is tree-shaped: nested complete child components are described separately from continuation, unlike the flat stack loop. Mismatched closers are leaves. `AtEOF` permits an unfinished child chain. These are token-level grammars; tokenizer-to-byte/spec refinement is not proved here. |
| taken opener and early error cleanup | `rejected`, `rejectAtLimit` | Pending opener is a precondition. Model `noOpener` denotes an inadmissible call; native panics on this API misuse. It is not a proposed new native error. `rejected` returns the post-cleanup state; `rejectAtLimit` packages that with `tooDeep`. |
| `current_block_depth`, `nested_block_limit`, `stop_before` | `State.depth`, `limit`, `stop` | Native depth/limit are u8, model naturals; values are admitted in 0..255. Rejection does not increment them. Model stop is an opaque closing-kind context, sufficient for this branch's noninterference; arbitrary native delimiter masks are unchanged by inspection, not encoded bitwise. |
| parent's normal cleanup after child's error | `parent_after_rejection` | Caller propagates error or otherwise applies normal block cleanup; independent child and parent bodies satisfy the grammar. Exact arbitrary caller callback side effects are outside the theorem. |

`grammar_cleanup` proves the actual stack algorithm for arbitrary grammar-generated body, arbitrary surrounding stack and arbitrary following suffix. `body_prefix` and `eof_cleanup` derive no output at EOF for unfinished nested content. `remaining_suffix` covers all finite token lists, including malformed lists; `active_progress` gives strict input consumption while active. `limit_recovery`/`limit_eof_recovery` combine pending consumption, cleanup and the error branch. `rejection_preserves_context` preserves depth, limit, stop and clears pending. The parent witness distinguishes the old branch from the repair without assuming the desired final vector.

The normal branch's u8 wrapping arithmetic is retained unchanged and is not re-proved. `limit_zero_not_rejected` establishes branch selection at disabled limit; it does not establish bounded native stack use for unbounded recursive callback parsing. Metadata observers can change during recovery just as they do in ordinary iterative block consumption. Their semantic completeness, reset/cached-token correctness and final source-map selection are separate open obligations from the scout.

## Native evidence and limits

The driver uses real public parser APIs and the complete declaration iterator. Its `calc` callback is deliberately reduced; it reproduces the relevant recursive parser/error structure but is not full Gecko CalcNode or generated longhand code. Direct API cases check exact error kind, callback nonexecution, matching/mismatched block kinds and EOF positions. Original/candidate output retains the separate observer counterexamples, showing this repair does not silently claim to repair them. Candidate-sensitive omission and wrong-kind mutants compile successfully and are rejected by semantic assertions.

The independent grammar proof is universal at the modeled token boundary. Native comparisons are finite source execution. Neither is a proof of Rust compiler/std, allocation, arbitrary byte decoding, full parser state packing, CSS generated property dispatch, DOM execution, browser resource limits or whole-cssparser correctness. The root browser receipt is separate runtime evidence. No desired browser output is fed into native or Lean execution.
