# Intermediate archive-sweep boundary

This is a disabled owner-local proposal for a future original77/candidate77, not a change to the active original74, its reviewer, or the shared epoch helper. No current epoch, activation, consumed-input map or runtime is bound. The exact call-site diffs use saved74 owners only to identify the integration seam; they are not a runnable77 successor.

Root measured 29,278 archived research files totaling 2,654,777,370 bytes in its saved CURRENT map. That measurement motivates omitting the archive sweep at intermediate boundaries; this package does not independently remeasure the archive or predict wall-clock savings. Three-map deduplication alone saved only 153 of 30,534 reads in root's measurement. There is no mtime cache, skipped byte check for native inputs, or full-verification claim for a limited check.

`intermediate.py` is a narrow derivative of the pinned shared `verify_current`. It keeps the complete `pins` and `staged_working` maps, every installed inode/device identity, root and nested semantic/raw indexes, empty staging, exact native modified/untracked sets, and before/after index stability. It omits only the `committed_research_working_payloads` loop and adds an explicit, nonempty consumed-input fingerprint map. Thus an archival path that is also a pin, staged input or consumed input remains byte-checked. The canonical epoch object is never projected, rewritten or mutated.

The returned snapshot has `archival_research_not_rechecked: true`, a distinct `verification_scope`, a digest of the consumed-input map, and `working_sources_binaries_preserved: true`. It has no `working_sources_binaries_research_preserved` field. This is a bounded observation, not a full archive-preservation statement. Archive drift can intentionally go undetected until the mandatory full final sweep; that sweep must reject it even if intermediate checks and WPT passed.

## Minimal owner integration

Copy the small helpers into the new owner/reviewer package and pin their actual bytes. Change only the call inside `candidate_verify`, which serves build-complete and WPT intermediate guards for both original and candidate roles. `ORIGINAL-CALLSITE.diff` and `CANDIDATE-CALLSITE.diff` show that seam. Keep initial admission, the initial BUILD-PRE snapshot, pre-backup/overlay full verification, final restoration, and independent final verification on the original shared full helper. The shown call-site deltas do not modify any of those calls or the cleanup tail.

Before enabling that successor, bind `policy.intermediate_consumed_inputs` to external immutable inputs from authenticated saved records. It must include all policy reference pins; every directly or transitively loaded runtime helper that is not already in `pins`; suite/capture manifests and payloads actually read; all lane page/harness/source resource bodies, installer-managed Zoom files, manifest/configuration/metadata descriptors and bodies. Include a consumed archive-only helper even though unrelated historical research is skipped. Do not put owner POLICY or FILES hashes into that policy map: doing so would create a self-referential seal. At admission, `inputs.bind_inputs` authenticates the owner manifest bytes against the invocation digest and adds its payload hashes plus FILES itself to the external map. It derives pins from authenticated manifest records, not current payload hashes. Duplicate paths must agree. The reviewer independently repeats that derivation from the saved authenticated owner manifest, rather than accepting a producer-supplied map. The exact effective map must be reviewed against the successor's imports and file reads, then independently reconstructed/checked by its saved checker and reviewer. Do not fill it by copying the complete archive map or by hashing current files to accept whatever bytes happen to exist. This package deliberately leaves that future owner-specific binding pending.

Retain the owner checks surrounding this helper: source-role SHA/identity claims, rebuilt binary pins, unaffected working diff, all source-context/accepted claims, application inventory checks, control-file bytes, flags, metadata presence/absence and index checks. Keep lane staging verification, all STAGED.json body checks before and after execution, actual wptrunner config-root validation, runtime Zoom CONFIG/nonce/role checks and post-cleanup capture replay. Runtime-generated files cannot be presealed; retain their existing creation-time pins and exact subsequent verification. This proposal changes none of those paths. Application inventory coverage remains whatever the existing owner actually checks; the new snapshot does not assert an extra app-wide scan.

## Independent review and publication

`REVIEWER-CALLSITE.diff` derives the effective consumed map from the authenticated owner and passes it into the intermediate build-snapshot assertion; it leaves full restoration verification unchanged. `review_scope.require_intermediate` requires the exact limited schema and the bound consumed-map digest. Every phase snapshot must still equal the built intermediate snapshot, and all existing binary/source/raw/metadata/config/capture joins remain required. The successor reviewer must verify the complete owner/guard diff and consumed-input coverage before execution; a matching digest alone cannot establish that coverage.

Initial and final snapshots remain the exact original full schema. The reviewer must independently call the unchanged full verifier against the complete restored epoch, including the entire archive map, before accepting restoration. `review_scope.require_full` is a schema guard only, not a replacement for that actual sweep. A limited snapshot must never be compared/projected into canonical CURRENT or promoted into a full-preservation result. Existing exact final-versus-original snapshot comparison, raw-index-only reconciliation, process/profile/backup checks and cleanup policy remain unchanged.

An incomplete lane or false repair gate must continue retaining observations and performing unconditional restoration. Archive drift discovered at final verification is a preservation failure, not an accepted experiment merely because tests completed. This proposal does not change any WPT status, expected-failure metadata, target roster, callback gate or numerical Zoom oracle.

Root reported ordinary74 at 44 PASS / 24 FAIL, including winning-variable and three rollback failures beyond the original nine-case page. Their target-policy classification needs the separate spec trace and a reviewed future gate change. This package neither authenticates those live observations nor silently categorizes the four as controls; the current74 reviewer remains untouched.
