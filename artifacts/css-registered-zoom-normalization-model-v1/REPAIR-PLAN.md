# Source boundary and proposed repair order

The pinned baseline has two inconsistent paths at zoom 2: literal registered 5px serializes as 2.5px while width consumes 5px and renders 10px; the equivalent ready provider with unused em fallback serializes as 5px, consumes 10px and renders 20px. Invalid selected input using registered initial 10px also consumes 20px on the deferred path. These are observations, not new accepted fixes. Source/spec and exact snapshots are in the referenced zoom trace. The existing root-rlh repair is a separate unit-conversion path.

The candidate invariant is canonical, unscaled lengths in registered computed storage. `SpecifiedValue::compute` currently parses then directly calls `to_computed_value(context)`. The ordinary cascade's retained admitted AST also calls that conversion after SCC completion. Absolute length conversion uses the builder's current effective zoom; that value can differ from final zoom because custom/prioritary scheduling runs before all remaining prioritary properties. `Value::to_variable_value` serializes stored values directly. `Servo_GetCustomPropertyValue` uses `ToResolvedValue`, and computed CSS pixel lengths remove final style zoom. A normal consuming property applies its own zoom again. These boundaries must agree on one storage representation.

Merely scheduling zoom earlier moves both local paths toward scaled storage and does not repair canonical var-token export. Merely deleting CSSOM unzoom leaves deferred storage and consumers wrong. Normalizing with final zoom after computation is also unsafe when the computation used a different scale. Setting computation zoom to one without auditing relative reference values can misinterpret already scaled fonts and root lengths.

1. Enumerate every producer and copy path before changing the representation. The captured `Value` implementation exposes `SpecifiedValue::compute`, direct `Parsed` declaration computation, `from_computed_value` in `to_declaration_value`, CSS-wide initial/inherited/unset selection, and animation of components. Ordinary retained-AST computation is another producer. Include stylist initial cache creation, registration mutation, animation/keyframe interpolation and recascade, typed-attribute results, and inherited cross-zoom copies. The latter producer call chains still need complete audit; no patch is ready to activate.
2. Implement a side-effect-free length scaling operation, or prove an equivalent computation-context mechanism. It must recurse over component alternatives, multiplier lists, length-percentage length portions, transform translations, and lengths inside supported image structures. Numbers, percentages, angles, time, resolution, URL metadata and taint must remain unchanged. Transform/image traversal and relative-reference factoring remain unimplemented and unaudited obligations.
3. Normalize newly computed local results using the exact scale used for that computation. Preserve already canonical initial and inherited values without another removal. A fallback that actually recomputes an initial expression uses the local result boundary. Preserve CSS-wide selection semantics and attr taint. Establish that recomputation, inheritance across different zooms and animation do not reapply normalization to canonical values.
4. Export canonical var tokens directly and revise custom-property CSSOM resolution to avoid unzooming stored canonical length leaves again, while preserving legitimate non-length resolution. Ordinary property CSSOM stays governed by its existing resolved-value semantics. Do not globally bypass `ToResolvedValue` for custom properties until every producer and nested component is covered.
5. Convert the paired diagnostic into narrow WPT oracles only after candidate preservation and the source/spec review. Start with absolute scalar length: literal, ready provider with unused fallback, selected invalid fallback, CSS-wide initial/inherit/unset, parent-child differing zoom, zoom mutation, and registered initial cache. Then lengths in +/# lists, alternatives, length-percentage, transforms and images, plus fixed-font/root-font relative inputs, animation and recascade. Check CSSOM custom value, consuming width/font, and scaled DOM geometry separately. Include currentColor and tainted URL preservation controls so a normalization helper cannot silently resolve unrelated state.

## Why general ToResolvedValue is not a normalization helper

`Value`, `ValueInner`, `ComponentList`, and `GenericValueComponent` derive recursive `ToResolvedValue`. Its conversion reaches all typed members, not just the outer scalar. The captured `computed::Color` resolved conversion normally calls `context.style.resolve_color(&self)` and returns an absolute color. Thus using the generic conversion for storage normalization would also resolve color state early. This is not a pure zoom transform. The Searchfox captures in this package provide that concrete obstruction; the existing source capture of registered values supplies the recursive derives. Searchfox sources are not asserted byte-identical to the active checkout in this package.

The Lean `store` function models the intended boundary, not existing Rust behavior. `exports_agree` relies on canonical exports defined as identity; it does not prove that CSSOM serialization currently does so. `computation_scale_independent` assumes the correct raw factoring law, so it does not justify ignoring graph ordering or font readiness. No global dependency policy, numeric self-font cycle policy, parser correctness, DOM behavior or floating-point equivalence follows from this artifact.
