# Process-local saved refresh prototype

This artifact implements the proposed cache only for the seven exact `validate_refresh` source paths in FUNCTIONS.json. All historical files and the active native owner are untouched. The separate real saved replay entry remains disabled in POLICY.json. The second authorized saved-only replay passed; production deployment and general completeness are not claimed.

`Session` shares entries across fresh module instances. A key includes the complete mutable outer scope, repository root, canonical code path/function/hash, binding file hash, in-memory binding dictionary and serialized direct arguments. Arguments are copied before calling the original validator. Input mutation during evaluation rejects. Successful results and ledgers are copied; exceptions and in-progress recursion never become successes. A changed hit rejects and removes the stale entry.

Within a recorded saved function/import frame, Path byte reads record actual returned bytes; text reads decode those bytes through TextIOWrapper(BytesIO), preserving universal newlines and encoding/error parameters. Stat/lstat/existence/type/symlink/resolve queries and glob/rglob/iterdir results are recorded. Empty directory matches and absent paths remain dependencies. Direct os stat/lstat/readlink/listdir are also recorded. Byte reads additionally retain actual file identities/types/sizes, and directory queries retain base/matched-entry identities. Every cache hit freshly reruns the entire transitive ledger, hashing payload bytes rather than trusting manifests or metadata alone. Child-hit ledgers merge into all active parent frames.

An exact-source loader records before module initialization and attaches the import ledger to each wrapped function. It executes the recorded .py bytes, avoiding bytecode-cache authority even if -B would ordinarily permit an existing pyc. Code and BINDINGS bytes are freshly authenticated before each wrapped invocation. New module objects share a source-identity key. Each hit separately validates the invoking module’s import ledger before validating the cached result ledger, so stale imported globals cannot borrow another instance’s success. This deliberately restricts eligible imports to source loaders; it is not a transparent Python import-system cache.

During recorded frames, the reviewed code's direct open/process/write routes are rejected, and paths resolving outside the configured saved roots or into forbidden canonical controls are rejected. Outside recorded frames all ordinary hooks delegate to original behavior. Live source claims, full-current verification, signatures, Git, process checks and staging are never cached. Only the saved functions are wrapped; `native_head_view` and outer policy decisions still run normally. A future wrapper could span repeated saved admissions in native prepare/require_ready/observe, but this prototype is NOT installed there.

This is a bounded reviewed-callgraph mechanism, not a Python sandbox. Arbitrary pre-opened handles, captured aliases to old I/O functions, ctypes, extension loaders and unreviewed APIs are not proved intercepted. Exact saved callees must be audited for those routes; unknown use blocks deployment. The implementation explicitly rejects the ordinary direct open and bytecode-loader routes used in its controls. It does not claim general adversarial code containment or an atomic filesystem snapshot against arbitrary concurrent writers. Natural filesystem fact changes can conservatively reject a hit even when bytes are restored. Full stat fingerprints retain access times too; filesystems that update atime on reads may therefore reject conservatively. No field is silently dropped from a recorded stat observation. The session requires one thread and rejects nested sessions; it restores hooks on exit.

## Disabled real saved replay

`replay.py` first authenticates the exact current checker, preserved disabled policy preimage, seven code/binding pairs and memo source. The exact audited standard-library import set is preloaded before recording, including urllib.parse used by the Cargo assessor and argparse/configparser imported by the archived-validation assessor. These interpreter-library modules remain trusted runtime dependencies, as in the original validators. Unknown source loads outside saved artifact roots still reject; no broad import delegation is added. STDLIB-SCAN.json records the bounded static inventory, not an exhaustive proof of earlier ancestry.

It would perform the original valid policy twice (to exercise a hit), the original eleven mutation cases and active-two-gates positive with each complete policy represented in the scope. It then leaves the recording context and executes the exact unchanged original stream/staging/identity-test tail. It cannot install/build/run a browser or update canonical state. Outputs go only to a fresh child of this artifact; failed attempts retain error and count information.

POLICY.execution_enabled is false. Root review is required before a separate saved-only run. Any unsupported access found in that run must be investigated and documented, never silently bypassed. Successful future replay must retain all original negative results and output meanings; aggregate counts alone are insufficient. Deployment to an actual capture/native/publication/checkpoint owner would be a later separately reviewed adaptation. The taint publications do not wait for this prototype.
