# Loaded FontFace descriptor candidate

## Status and integration

This is an artifact-only implementation candidate, not a compiled or accepted patch. No production files, index, browser, or shared build were changed. `common.patch` changes six common files; `backend/backend-clone.patch` is the ten-file backend dependency, narrowed here after root's fontconfig review. The earlier backend-v1 directory is unchanged and must not replace this dependency. Complete original/candidate snapshots and deterministic generators are included. Root owns integration, formatting, all platform compilation, WPT and final review.

The candidate assumes the already landed worker family-detachment repair. The copied worker context includes that repair; neither patch here modifies it. Existing unrelated changes remain in complete context snapshots but are absent from these patch deltas.

## Publication path

1. `FontFaceImpl::SetDescriptor` clones the current Servo descriptor rule. Parsing and the existing quoted-family fallback operate on that detached rule. Syntax failure and unchanged values publish nothing. Rust's actual Servo_FontFaceRule_Clone creates a new locked rule, rather than aliasing its mutable descriptors.
2. If the face has a wrapper, derive new attributes from the candidate rule, including a newly computed Unicode-range map. `UpdateFontFaceDescriptor` owns the old wrapper and attributes and dispatches to main with the caller's ErrorResult. It holds no set/entry mutex across the sync dispatch.
3. Main-thread `UpdateFontFaceDescriptorOnMainThread` checks the actual native load state. For STATUS_LOADED, it creates a fresh FontFaceImpl::Entry from a copied source list and the new attributes, then initializes a fresh platform entry through CloneUserFontEntry. It never looks for an existing equivalent wrapper or updates the old loaded wrapper/provider/cache key.
4. Initialization copies provider metadata field by field, retains sanitized FontData, retains successful source information and local admission, and rebuilds downloaded-font Skrifa state from retained sanitized bytes when enabled. Platform feature defaults come from the backend clone; new CSS features/variations are appended once. Family, ranges, language override, metrics and sizeAdjust are assigned from the new wrapper. The new provider is deliberately not put in UserFontCache. Its later ForgetFont uses exact pointer identity, so deleting an uncached clone does not evict the old provider.
5. Native state is marked loaded directly on the still-detached wrapper, with no owner callbacks or new loader. On return, the owning thread checks descriptor and wrapper identities plus owner liveness before publishing the descriptor rule and attaching the new wrapper. No user script is invoked between these assignments. The attachment suppresses its normal eager status update. All current set memberships are then marked dirty through NonRuleFontFaceChanged, which also sets mNonRuleFacesDirty. This matters for workers, whose existing MarkUserFontSetDirty method is inherited as an empty operation.

`DescriptorUpdated` now only invalidates memberships; provider preparation formerly performed there is moved into SetDescriptor before publication. Constructor parsing with no wrapper still does not create/load one. Existing setter calls and their pre-flush behavior remain unchanged.

## Native-loaded / DOM-loading interval

FontFaceImpl::Entry::SetLoadState records native state first and may queue the DOM status/promise change on the worker. Therefore selecting the new path only when FontFace.status is loaded would miss a reachable interval. This candidate selects on main-thread native state. The queued callback captures FontFaceImpl itself and the status value, so it remains capable of finishing the same face after its wrapper is replaced. `SetUserFontEntry(entry, false)` preserves the existing DOM status and pending/fulfilled promise until that callback executes. Already fulfilled promises remain the same objects; the candidate calls neither load nor promise replacement/rejection.

This is source reasoning, not a race-tested guarantee. Root should gate native-loaded/DOM-loading if a controlled runnable test can expose that interval; ordinary awaited-load WPT does not exercise it.

## Ownership, shutdown and rollback

The new runnable stores RefPtr set/entry/result and an owned attributes value; it has no borrowed stack output. MainThreadRun returns true after preparation. WorkerMainThreadRunnable::Dispatch reports shutdown/failed sync-loop state through the caller's ErrorResult. No normal clone failure is smuggled through MainThreadRun's Boolean, whose false result means an uncatchable worker exception.

The loaded branch has no normal fallible allocation/activation step: existing admitted backend handles/locators are retained, source arrays/metadata use Gecko infallible allocation, and no source is consumed or activated again. Release assertions state required loaded-provider/metadata/non-null-clone invariants. All inspected successful local, downloaded, buffer, and cached-provider paths establish a platform entry with user metadata. A future backend violating this contract terminates rather than publishing mismatched descriptors/provider; this invariant policy requires root review. Allocation exhaustion remains process failure, not a recoverable success theorem.

Parse failure, dispatch failure before preparation, or stale/abandoned publication leave the loaded old rule/wrapper/provider untouched. An abandoned fresh wrapper's destructor already proxies platform release to main. The runnable retains its raw-set dependency until result transfer; the FontFace retains that primary set during owner publication. The copied descriptor rule and strong old entry provide identity guards. The worker sync loop processes control work and may initiate shutdown; this is why post-dispatch identity/liveness checks are present. If those checks fail despite a successful dispatch, the candidate uses ErrorResult::ThrowUncatchableException, the existing worker termination channel, rather than introducing a catchable InvalidStateError for a valid descriptor setter. This guard is for stale/abandoned publication, not a specified ordinary setter failure. The candidate does not claim arbitrary JS reentry is impossible, nor assume pointer identity would detect in-place mutations performed by unrelated legacy code.

## Deliberately retained existing limitations

* For native states other than STATUS_LOADED, main performs the existing UpdateUserFontEntry operation on the existing wrapper and returns it. That legacy in-place behavior includes shared in-flight ownership problems. It is **not** transactionally rolled back if shutdown/reentry occurs after main has updated it but before owner publication. The loaded branch does not have this side effect. This is a visible review boundary, not an all-state fix.
* FontFace.status may remain loaded while native state was reset by ForgetLocalFace/LoadCanceled after platform font-list changes. The main native-state branch preserves that existing reset/reload behavior. It does not invent a resource when no loaded native provider remains.
* FreeType/fontconfig lazy file consumers may reopen the retained locator when constructing fresh derived caches. The patch retains baseline lazy resource semantics; it does not guarantee immutable bytes across external font removal/replacement. It avoids a new local-name lookup or visibility/admission decision.
* CSS-connected setters retain their existing early rejection. A separate repair is required for that behavior.
* Whole async font loading, local-font-list invalidation interleavings, platform cache concurrency, allocator behavior and all backend ownership contracts are not formally proved here. Earlier conceptual Lean ownership theorems do not establish these C++ obligations.

## Compile-sensitive details and review gates

The backend dependency introduces CloneUserFontEntry in gfxFontEntry and all four concrete providers. On DirectWrite its stream constructor parameter changes to the stored IDWriteFontFileStream interface. On fontconfig the protected clone constructor must use direct `new`, and its new Fontations lazy initializer is required for a retained FT face. These are uncompiled platform changes. Common initialization does not copy owning raw Skrifa pointers or populated shaping/metric/font-instance caches.

The original backend draft's unconditional fontconfig InitSkrifaFontFace override would have changed normal entries by permitting earlier file opening. The embedded dependency corrects this: a MOZ_FONTATIONS-only mIsUserFontClone flag defaults false and is set only in the new clone constructor; the override acts only when that flag and mFTFaceInitialized are true. Installed entries, ordinary local/data entries, and ordinary system Clone() retain the prior no-op hook. A user clone without a retained FT face uses the original GetFTFace path. A user clone with retained FT face can initialize Skrifa when GetSkrifaFont requests it. GetSkrifaFont returns an existing pointer before calling the hook, and SetSkrifaFont atomically installs only into null, deleting a losing candidate. Thus repeated/racing attempts cannot overwrite an owned pointer; the existing initializer may still create and discard a loser under races, which is not a proof of exactly one allocation. Data clones normally get Skrifa directly from retained sanitized FontData in common initialization.

Searchfox's concrete class survey and the retained backend declarations identify CTFontEntry, gfxDWriteFontEntry, FT2FontEntry and gfxFontconfigFontEntry. gfxFT2FontEntryBase remains abstract and gfxUserFontEntry is the placeholder, not a platform target. Those four cover the current loaded-provider call sites; ordinary installed-font Clone() is untouched. The default new virtual implementation rejects misuse rather than relaxing the existing installed-font API.

nsTArray::Clone returns an owned infallible copy; gfxFontFaceSrc's URI/principal/referrer/buffer references remain valid. Buffer data already taken from a source is not taken again. Metadata cloning uses AppendElements, not an unavailable implicit nsTArray copy constructor. Existing CSS resource fields are deliberately distinct from backend feature defaults.

Minimum integration gates are the root's fixed window/worker URL/buffer mutation and peer-isolation matrices, existing/new/readded/never-added faces, invalid-syntax/no-change controls, and existing worker lifecycle regressions. The worker-removal gate is a prerequisite, not evidence that loaded-provider cloning works. Local font coverage needs calibrated resources on each supported backend; lack of an installed matching font is not a pass. Status/promise identity must be checked separately from geometry. No browser outcome is claimed for this candidate.

## Reproducibility

`check.py --manifest-sha <SHA>` authenticates all inputs before running either generator. It regenerates both patches/candidate trees in a temporary directory, checks exact bytes, and verifies the live originals only with explicit `--live-root`. It performs no native compilation or execution. `MANIFEST.json` and the explicit filenames/hashes in `FREEZE.json` identify the review unit. Source identities come from the captured local files; Searchfox discovery was used first, but its newer indexed APIs are not silently substituted for this checkout.
