## Concrete source review

Immediate UTF-16 and Latin-1 provider calls now classify the current contribution's language instead of reusing a preceding buffered word's script. Both missing Latin-1 buffering sites update language: a nonempty continuation contributes its language before publication, and the final incomplete word records its language before deferral. A delimiter-only contribution with zero buffered characters does not steal the preceding word's language. The UTF-16 existing update sites remain. Nowrap suppression stays byte-for-byte unchanged.

The original bool helper proposal conflated a valid non-CJK language with a failed locale parse. It would store the invalid atom, so a later valid contribution could spuriously mark a word mixed and change hyphenation. `Maybe<bool>` preserves this distinction. Null is `Some(false)`; a successful locale gives its classification; parse/likely-subtags failure is `Nothing`. Immediate words default Nothing to false. For a fresh buffered word, Nothing clears stale script state and returns without committing the invalid language atom. This deliberately repairs stale script, while preserving the prior failure bookkeeping. Valid mixed-language handling and the early mixed-word return remain unchanged. No general mixed-language hyphenation policy is claimed.

Null resetting is also deliberate: FlushCurrentWord clears buffered language and mixed state but not the script flag. Leaving that flag untouched would carry a prior CJK word into an implicit-language word. The extra probe compares identical text and widths while changing only preceding language, and distinguishes omitted/empty/und/invalid. Saved upstream caller excerpts show nullptr admission through the explicit-language flag; they are discovery evidence, not a branch-byte or executed-path proof.

The one-entry cache still holds its atom through StaticRefPtr, registers ClearOnShutdown once, and updates key and result only after successful parsing. Failed parses and null do not poison its successful entry. This remains a main-thread layout cache: the saved ClearOnShutdown contract asserts main-thread registration. Extraction expands the existing cache's use to both immediate AppendText routes; it does not add synchronization or establish safety for hypothetical off-main-thread users.
