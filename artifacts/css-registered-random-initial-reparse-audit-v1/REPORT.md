# Registered initial random keys: bounded source audit

The proposed reparse-churn mechanism is NOT REACHED in the captured current Gecko source. RandomKey::auto creates a deterministic property/index name plus element scoping, not a fresh parse UUID. PropertyDeclarationContext resets its index on entry/exit; each initial validation/computation creates a fresh parser context. Context::random_base_value derives a fresh PRNG from the key and document identity, so the same key in the same document gives the same base. Rebuilding the initial map reparses, but that alone does not establish changing random identity. No browser test of rebuild stability ran here.

Auto/element-scoped random is rejected by the existing computationally-independent parse mode through has_element_context. Explicit non-element named/property/index keys and fixed numeric keys do not have that element requirement. The current local preference defaults layout.css.random.enabled to IS_NIGHTLY_BUILD. A release browser may therefore report unsupported; this packet does not enable preferences or infer release support from source. Existing random-computed.tentative.html supplies auto-initial rejection and explicit key-sharing controls. Its auto test is not evidence that every non-element random initial must be rejected.

## Separate source-only lead: failed alternatives consume indexes

Specified registered-value parsing opens one property-declaration context around its entire ordered component loop. Each component uses cssparser try_parse, but Random parsing increments a Cell in ParserContext before completing. Input rollback does not restore that Cell. A failed <length> branch followed by successful <number> parsing can therefore leave the selected random(property-index-scoped,0,1) carrying index2 rather than index1. A two-failed-alternative and a repeated-value variant are included for diagnosis.

This is not reparse churn: validation, rebuild and ordinary declaration parsing may deterministically reproduce the same wrong index. It is a distinct source-reachable rollback concern, not yet an observed bug or allocated fix. The current ledger search found no random-related entry in new_queue, pending_queue or unaccepted_candidates. This is a bounded dedup search, not proof of absence from all history/upstream.

The [Values5 random cache-name rules](https://drafts.csswg.org/css-values-5/#random-caching) make explicit identical cache names share the base. [Random-key simplification](https://drafts.csswg.org/css-values-5/#random-key-simplification) assigns the index from the parsed value before canonical reordering. Failed syntax alternatives are not functions in that selected parsed value. The [JS registration algorithm](https://drafts.css-houdini.org/css-properties-values-api/#the-registerproperty-function) stores the selected parsed initial after independence validation. For fixed or non-element cache keys with constant numeric bounds, the available inputs are the specified key and document identity; no element CSS input is required. This is the source/spec basis for the probe, not a blanket certificate for arbitrary nested random expressions.

observe.js is an unexecuted standalone diagnostic. It checks support before registration, creates an isolated iframe, records11 cases across3 phases, and removes the frame in finally. It compares initial and explicit declared values to same-document explicit ua key1..4 references, and has fixed/named/property-scoped/list/admission controls. An unrelated registration forces the initial-map rebuild; a stylesheet change provides a second stability observation. The expected same-key equalities do not require distinct random samples to differ. Coincidence or unsupported/error controls must remain diagnostic, never accepted as a demonstrated defect.

The probe was syntax-checked only; no callbacks or browser execution. Independent probe review is pending at this signing checkpoint. Native source, index, epoch and build are untouched. No new acceptance, bug count or formal coverage.

## Provenance caveat

Searchfox discovery located the actual APIs before local capture. Current indexed random parsing matches the local key scheme, but the indexed document PRNG has moved to a keyed hasher, whereas this captured checkout still uses its document pointer as the seed. Do not claim whole-source equality or an independently attested release implementation. SOURCE-PINS records full local hashes; random-pref.txt is only an excerpt of the full pref file whose hash is recorded. The primary specifications were browsed live; this checkpoint preserves the links and reading receipts rather than a new full HTML capture.
