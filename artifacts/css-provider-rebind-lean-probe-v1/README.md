# Provider rebinding with mixed font dependencies

This small extension addresses a premise excluded by the finite-tree model: the identity of a provider can change while its numeric value stays equal. The existing tree proof fixes topology and computation throughout its history. It therefore does not establish correct dependency rebinding after a DOM move. This package adds a bounded two-parent/one-root model and one unrun WPT probe; it does not identify a new observed browser defect.

`Rebind.lean` imports the ten pinned modules unchanged. A consumer depends on its selected parent's value and the root value, with expected midpoint `2 * parent + root`. `invalidate` changes the parent identity, advances context and endpoint generation, preserves the numeric endpoint, retains an old in-flight job, and sets refresh/application obligations. Advancing generation even when the value is equal is the wrapper's explicit strengthening of the imported value-change rule. The context field records rebinding; stale completion is rejected using the existing endpoint-generation guard. This is a proposed semantic contract, not a statement that Gecko stores this extra context field or uses these exact generations.

The proofs preserve local validity and dependency coherence across invalidation, refresh, selection and completion. A pre-rebind selected job cannot install, including after an equal-value refresh. The selected parent can change independently of the root; changes to the departed parent do not affect the expected value. Once edits stop, the unchanged chain settlement theorem gives a finite enabled history reaching the current mixed expected value. Quiet readiness requires coherence; the concrete bad rebind demonstrates why merely retaining a quiet old endpoint is insufficient after the new parent changes.
