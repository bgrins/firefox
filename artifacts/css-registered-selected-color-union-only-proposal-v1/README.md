# COLOR-eligible union/default candidate A

This is a self-contained three-source native patch against the committed clean preimages, derived from the combined V5 candidate. It restricts new selected-value/default behavior to registrations with the original COLOR dependent-type eligibility. It is uncompiled and unexecuted as an isolated candidate. Root reports the combined native candidate passing all 42 cases; that observation does not establish this narrower candidate's outcomes.

`V5-DELTA.patch` changes only cascade.rs. `find_non_custom_references` is restored byte-for-byte to its original function, removing newly added Image-only admission. Traversal computes `color_eligible` directly from the registration syntax's dependent types before walking references. This gates the entire new selected-value preparation/refinement block, including removal of COLOR_SCHEME, and the post-edge invalid/default hook. The existing registered check and singleton/SCC guards remain. Registrations without COLOR eligibility, including pure Image registrations that already enter through var/attr, retain their original direct admission and graph/application path.

The provider and specified-value postimages are exact V5 bytes: retained first-success AST, CSS-wide application extraction, root/inherited invalid-initial selection, taint handling and the compiled two-lifetime SubstitutionInput remain. Recursive image classification is still necessary when a COLOR-eligible union selects an image. This candidate does not remove shared machinery simply because a helper's name mentions images. Existing unit flags and application/default behavior outside the guarded path are retained.

Eligibility separation is not a theorem of outcome isolation. A COLOR-eligible node can share custom/priority dependencies with an Image-only node; changes in one can affect graph outcomes in the other. The original COLOR function's coarse admission is preserved so the selected-value/default refinement has the same entry class, not because coarse edges are asserted correct.

The complete `native.patch` includes its required native helpers and applies to the committed base without the image-only bugfix. This makes it a standalone base-relative candidate, not proof that two overlapping bug commits can be cherry-picked together without reconciliation. It shares helper bodies with the separately prepared image-only alternative. The independent-split note's unresolved composition and minimality requirements still apply.

Validation authenticates sealed V5 and all source pairs, exact V5 delta and original admission-function equality, repository-config formatting for three files, and native patch forward/reverse replay in removed scratch. The unchanged classifier and tracker-lifetime tests are inherited by hash from V5; they are not rerun or represented as native type checking. No browser, native checkout, Git/index, canonical control or application operation occurs here.

Next root-owned validation is an actual isolated native build and original/A-only comparison using the existing 42 plus the separate 3 absolute-color image-unit cases. No fixture or expected status is changed here. Pure-image improvements or regressions must be attributed from that evidence, not inferred from test titles. Existing conditional System/light-dark initial cases remain research-preservation checks pending their separate normative interpretation. This package adds no execution owner or acceptance gate.
