# Independent oracle review

The scalar literal/selected-valid-primary expectation is reached by the existing pinned Properties and Values API computed-value/substitution plus Viewport zoom/CSSOM trace: canonical absolute px are exported to var and CSSOM without zoom; geometry reflects ancestor and local zoom. Thus width5px at effective zoom4 has custom CSSOM5px, width CSSOM5px and rectangle20. This does not invoke the disputed self-font numeric policy.

For scalar invalid syntax (including wrong selected primary), registered grammar failure is invalid at computed-value time and non-inherited registration uses initial10px; a ready wrong-type var primary does not retry its fallback. The pinned CSS-WIDE-ORACLES trace establishes acceptance of direct keywords, the Values5 single-keyword result rule after substitution, and Cascade explicit defaulting. Initial and non-inherited unset choose10px; inherit and inherited unset copy parent20px. Applying the same canonical/used zoom distinction gives the existing scalar expectations. Revert, declaration precedence and registration replacement are not tested.

Compound validity is checked independently of raw spelling: compare selected registered serialization with a separate element's computed initial serialization at zoom1, verify the ordinary literal parses, and compare ordinary consumer values at zoom1 before mutations. This closes the old false calibration where computed gradient colors differ from the raw initial string even after defaulting. Each fixture uses a supplied value distinguishable from its initial. The subsequent canonical-string invariance tests zoom only, not a guessed cross-engine serialization. Ordinary controls share the same zoom; transform/width geometry additionally compares their rectangles. Lists use actual margin/background-position consumers. These remain calibrated differential oracles, not proof that every ordinary control is correct; browser execution is still required.

The [Values4 font-relative lengths](https://drafts.csswg.org/css-values-4/#font-relative-lengths) definitions bind em to current font-size, lh to current explicit line-height, rem to root font-size and rlh to root line-height. The new fixed-reference page uses twice those values. Step0 expected lengths are40/48/80/120px; step1 are60/72/100/140px. The target never uses the custom property for font-size or line-height. Root style is restored even after failure; the target is nonroot. All snapshots are captured before assertions, so font mutation and zoom1→2→0.5→1 are observable together. These expectations do not cover normal line-height font metrics, root self-reference or container-relative units.

The [Conditional Rules5 style-container rules](https://drafts.csswg.org/css-conditional-5/#style-container) admit style ranges, substitute a custom-property operand as var(), compute comparable same-type operands and then compare. For a registered selected5px, equality5px, greater4px and less6px are true; less4px and greater6px are false. Those statements remain true across zoom because the comparison concerns canonical computed lengths. The named ancestor ensures the intended query container. A separate unregistered5px equality condition must pass, providing a grammar/evaluation calibration rather than a silent optional skip. This is the current draft's normative expectation; no claim is made that the present default browser configuration implements that feature. The test is not counted as zoom evidence until calibration executes.
