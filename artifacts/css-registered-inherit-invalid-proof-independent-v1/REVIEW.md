## Substantive proof review

The reference `expected` selects the registration initial value for the root and the parent's registration-selected optional value otherwise. It does not reuse the optimization gate or publication function. `gate` models the native early inherited-registration return, then existing-value None versus Some, then the original parent-presence test or corrected root guard. `update` sets the reset-inheritance bit before reading the parent's reset bucket, and separates Some insertion from original-preserve/candidate-remove on None. `run` composes these definitions.

The selected native projection has no missing gate arm: an inherited registration skips; a reset registration with current None proceeds, including a root with no initial; a reset registration with current Some skips only for a corrected root. Some parent data is cloned and published; absent data is removed in the candidate. Other declaration kinds, priority/revert/seen filtering and successful entry into this route are external admissions, not secretly included in the proved state machine.

`Ready` has two substantive premises: the selected entry equals the ordinary seed, and a root's parent reset getter is None. The latter is needed when the root has no initial and reaches the update. The inherited branch relies on the parent-seeded selected value, while the root Some branch relies on the initial seed. Readiness is not tautological with the result; concrete original and corrected-root witnesses inhabit it. Nonroot reset publication and its dependency theorem do not need a ready-map assumption.

The store is a pointwise Bool-bucket/key map with arbitrary optional payloads. The main result quantifies over arbitrary keys, values and flags and returns an independent expected selected value while preserving every unrelated key and bucket. There is no payload equality assumption; DecidableEq is required only for keys. The proofs do not replace the state with a singleton or assert whole-map equality after constructing the desired answer. Their native relevance nevertheless depends on the explicitly admitted persistent-map/getter/clone/mutation contracts.

The bit theorem preserves the incoming bit and characterizes the actual corrected control condition: incoming OR `!inherited && (!root || initial.isNone)`. In particular, an absent-root-initial execution still sets the bit; this is faithful to the implementation and not a minimal-dependency claim. Arbitrary `otherFlags` are preserved in the model. Actual add_flags OR semantics and any state omitted from the model remain source-admission assumptions. The helper update is mathematically total, but its source correspondence is the reached non-inherited branch; it is not an independently callable inherited native operation.

The 17-result roster contains twelve general results and five concrete counterexample/branch results. `both_sites_necessary` rejects either one-site-only repair; `root_guard_necessary` shows the overcorrection from blindly publishing the empty root-parent map. The original wrong value and the absence-preserving correction are demonstrated separately from the abstract correctness theorem.
