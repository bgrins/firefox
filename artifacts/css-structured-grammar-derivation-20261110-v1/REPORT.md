# Feasibility and next step

Mechanical extraction is practical for this restricted structured-grammar slice. The prototype derives a data program from actual Bikeshed property/production definitions, follows three finite references, and checks the resulting language in Lean. It rejects notation it does not understand instead of guessing. This is useful independently of Stylo: it can produce source-linked grammar fixtures, token-language tests, and explicit review diffs when the specification changes.

The result does not make arbitrary prose mechanically derivable. Operator interpretation, normative source selection, token abstraction, implicit CSS-wide extensions and contextual prose exceptions remain reviewed choices. The Lean kernel proves the formal grammar facts; it does not read English or establish that every relevant specification clause was selected.

The existing prose-derived Syntax work already supplies verified execution/codec components. This prototype adds a genuinely different front-end experiment: structured value notation. Do not combine the two successful examples into a CSS-wide derivation percentage. No held-out protocol or native conformance result is claimed.

The next useful step is a frozen small benchmark of additional property grammars selected before expanding the recognizer, with a source-context classifier and explicit records for implicit grammar extensions. A universal source-token parser relation and checked lowering could then replace the present Python notation parser. Expanding to `&&` or `||` should come with separately reviewed permutation/grouping semantics, not treating them as another spelling of `|`. Converting arbitrary algorithm prose should remain a distinct, openly partial effort.

The source-only checker retains command logs, exact axiom inventory, actual-file observations and all refusal/mutation evidence. The three deliberately wrong implementations must compile, fail unchanged generic proofs and satisfy explicit witnesses of their wrong behavior. README.md gives the theorem boundaries and reproduction instructions. No canonical library, native implementation, Git state, browser or existing build target was modified.

A current-source comparison found real drift: the 2026-10-21 css-align commit adds flow-start/flow-end to a referenced production, while leaving the selected Value field unchanged. The unchanged extractor and actual-file runner demonstrate six newly admitted normalized token sequences. The historical 26-sequence theorem remains explicitly historical; the current-file comparison is separately pinned, and separate current fixture/reference theorems establish its 32-sequence normalized language using the same generic laws. A practical next step is to promote this dependency diff into a reviewed current-snapshot fixture/proof update without overwriting the earlier result.
