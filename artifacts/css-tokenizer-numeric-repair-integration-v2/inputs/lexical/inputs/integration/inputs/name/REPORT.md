# Name and escape return-boundary component

This component covers the complete control flow of `consume_name`, `consume_escape` and their local byte/hex helpers at the returned output, consumed byte count, suffix and borrowed/owned-selection projection. It preserves the original source. During this work, independent identifier-start modeling exposed the nested escape lookahead defect; the confirmed browser defect and narrow repair are separately sealed in `css-tokenizer-escaped-newline-repair-v1`. The original counterexample remains here.

## Universal results

- The native hex loop equals a separately selected maximal hexadecimal prefix (capped at six), independently classified by a literal digit table and accumulated by a fold. Bounds cover bytes consumed, exact remainder, value growth and the six-digit u32 result domain.
- Escape parsing equals the independent hex/scalar/optional-whitespace reference. CRLF counts as two raw bytes. NUL, invalid scalar values, EOF and the six-digit boundary remain explicit. The non-hex character decoder/encoder is a named Rust standard-library boundary.
- The complete modeled name loop equals a semantic reference using independently classified name bytes and the independent escape reference. It proves bounded consumption, exact unconsumed suffix, output equality and an ASCII-or-EOF return point. The reference does not infer its expected output from a native observation.
- Fast-run fusion is instantiated with the actual `takeWhile simple` prefix, rather than an assumed token list. Every byte admitted by the exact fast table satisfies `advance`'s debug-domain predicate. Both 2/3-byte leaders and 4-byte slow paths are retained.
- Returned name positions satisfy the standard byte-boundary marker. Escape consumption preserves a suffix of complete UTF-8 units using a concrete encoding-shape structure: one non-continuation head, continuation tails, and the head's byte width. ASCII consumption, arbitrary hex prefix and optional whitespace preserve that representation. This structure is a superset of valid scalar encodings; admission of Rust's valid `str` and its codec primitives remains explicit.
- The original actual identifier-start predicate implies positive progress and a name return-boundary marker. This does not imply the predicate is spec-correct: the hyphen/backslash/newline counterexample is retained.
- Kernel witnesses preserve a temporary interior UTF-8 position after the fast prefix, complete non-ASCII copying afterward, zero progress for an unadmitted leading escaped newline and empty name, and partial consumption after the wrongly admitted hyphen.

## Source correspondence and limits

`SOURCE-BINDINGS.json` retains 21 complete native definitions with exact byte spans, body hashes and original source bytes. The checker regenerates those bindings independently of the theorem-side classifiers. The signed dispatch-v2 closure is unchanged and freshly replayed. No native source is generated by translating Lean back into Rust.

The model normalizes the two native name loops into a recursive byte machine with an ownership-mode bit. The fast-prefix theorem justifies grouping its simple-byte steps into each actual `advance_while` run. On a backslash or NUL the mode becomes owned; an invalid backslash-newline can select owned storage yet consume zero bytes. Source `consume_continuation_byte` and `consume_4byte_intro` each advance one byte, so intermediate positions need not be character boundaries. The final stop property is derived, not assumed for each loop iteration.

This is a reviewed full-body source projection, not an automatically verified Rust compiler or universal FFI/heap proof. Mathematical positions require valid source offsets and defined native `usize` sums. Rust's `str`, `chars().next()`, character width, `char::from_u32` and `encode_utf8` supply the valid-code-point/encoding contract; the pure model exposes the corresponding arithmetic encoding and width. Output equivalence is conditional on those primitive operations. The clipped non-hex take totalizes invalid byte lists in Lean; invalid Rust strings are not admitted. The component does not prove arbitrary UTF-8 decoder implementation correctness or heap allocation success.

Line number and UTF-16 column metadata are deliberately outside the selected return-boundary/output projection. Their complete source bodies are retained so this exclusion is visible. This component does not assert that those fields are unchanged; escape whitespace can update them. Native memory ownership, performance and allocator behavior are not inferred from the mode bit.

## Caller trace

`next_token_unchecked` calls `consume_name` under `is_ident_start` after `@` and `#`; its hash fallback also admits ASCII digit or hyphen, which are ordinary name bytes. The hyphen token arm calls `consume_ident_like` after the same predicate. Direct ASCII letter, underscore and NUL arms admit progress; non-ASCII branches occur on valid tokenizer entry boundaries. The direct backslash arm excludes a following newline. `consume_numeric` calls `consume_name` only after the predicate approves the remaining unit suffix. All these predicates and functions are retained in full. The universal caller theorem covers the actual `is_ident_start` guard; the remaining direct byte arms are covered by the individual ordinary/NUL/escape progress lemmas and reviewed source mapping.

`consume_escape_and_write` is reached from the owned name loop after consuming the backslash and rejecting a following newline. The helper itself permits EOF and returns replacement without consuming another byte; progress of the encompassing name step comes from the consumed backslash. String/URL consumers also call this helper, but their complete loops and admission are outside this name component. No all-tokenizer admission claim is made.

## Verification and remaining review

The source-only checker authenticates everything before helper imports, regenerates 21 full definitions, replays signed dispatch admission, compiles all nine modules and audits only standard Lean axioms. Four semantic mutants remove continuation consumption, retain zero instead of replacement, underconsume CRLF, or allow seven hexadecimal digits. They must fail the unchanged theorem/witness suite.

No native build or browser was run by this component. Root's separate escaped-newline browser baseline is not used as a proof oracle. Independent review remains required. The next genuine scope beyond this component is the whole-tokenizer entry/return relation, including other token consumers and parser-block bookkeeping; this component does not silently close that broader obligation.
