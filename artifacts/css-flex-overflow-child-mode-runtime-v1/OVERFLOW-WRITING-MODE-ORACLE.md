# Relative and child-writing-mode diagnostic

Thirty independent cases: vertical-rl parent, same/opposite/orthogonal child writing mode, row/column flex, and logical relative offsets0/±17px along one child axis. All physical sizes are explicit, so changing the child's writing mode does not rotate the declared dimensions accidentally. The actual flex fixture retains the already calibrated break-before:always on ordinary items. The ordinary block-flow reference uses break-before:column in the same multicol context; its own same-mode numeric calibration is mandatory.

For the same-mode child, the exact expected descendant union rectangles are logical[i*100+inlineOffset,blockOffset,100,160]. This distinguishes an unchanged relative translation from a per-continuation accumulating offset. The ordinary block reference is also checked against this independent same-mode numeric oracle; agreement between two wrong algorithms is not counted as normative calibration.

For opposite and orthogonal modes, the block reference is a behavioral comparator only. The probe does not assume orthogonal descendants fragment into four OCs, nor that parent and child block directions agree. It records every child/item fragment, actual computed mode/offsets, and size calibration. A mismatch is a review lead requiring source/spec attribution, not by itself a normative bug claim. A passing no-continuation orthogonal control cannot stand in for an OC branch proof.

The native source concern is specific: ReflowOverflowContainerChildren constructs normal pos in the child's writing mode using predecessor IStart and B0. Its final-size sensitivity is on the child's reversed block axis; horizontal-rtl inline conversion cancels container width. Relative offsets on predecessor IStart may also carry used rather than normal position, a preexisting possible accumulation issue. Paired baseline/candidate outcomes are needed to separate that from the changed reflow ordering.
