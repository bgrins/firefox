# Standalone additive-symbol weight candidate

This alternative is based on the exact recorded HEAD90 bodies and does not require the pending generic Integer range repair. It adds one AdditiveTuple::resolve_weight helper that resolves the stored Integer and clamps the resulting i32 to zero. The existing all-weight validity guard, adjacent strict descending comparison, and Servo_CounterStyleRule_GetAdditiveSymbols export all use that helper. The stored Integer and derived specified serialization are unchanged. The minimal patch contains two Rust files and the same three WPT files as the comparator-only proposal.

The 32 CSSOM cases and eight-row rendering reftest are byte-identical to the prior proposal, including all negative/fractional controls. The important independent-base guard is calc(-1),calc(-2): both now resolve to zero at ordering and export, so equal weights are rejected. A positive weight followed by calc(-1) is admitted with a zero weight and can render the zero ordinal correctly. Unresolved contextual math still fails the existing guard; this does not broaden descriptor admission.

The local policy preserves existing Integer rounding and saturation while enforcing the additive descriptor's nonnegative range consistently. POLICY.md explains finite/nonfinite and signed-zero behavior and why this agrees with the proposed generic nonnegative clamp. Integer rounding fix118 remains separate: this patch does not fix unrelated historical positive fractional or large odd-integer rounding errors. It is independently applicable and scoped to additive ordering/weight projection, not a claim that all Integer arithmetic on HEAD90 is correct.
