# Completed variables and stable selected prefixes

This extends the existing prefix certificate using actual completed variable substitution, rather than assuming two arbitrary declaration evaluators agree. For arbitrary finite declaration lists, accepted prefixes preserve the selected result, evaluated declarations, logical variable-read trace, and complete visited declaration/rollback-state trace when APPEARANCE_BASE is added and settled bindings remain immutable. Pending bindings may become settled. The theorem does not implement native support or prove the running browser candidate correct.

Bindings distinguish Pending, settled-invalid, and settled token lists, including a valid empty list. The resolver reuses `CssSemantics.VariableExpr`: literals, concatenation, references and used fallbacks. Pending cannot select a fallback. Settled-invalid may select one. An unused fallback need not be settled and contributes no read. A successful resolution includes the exact logical substitution reads; `completed_resolution_stable` proves both tokens and reads unchanged under monotone binding completion. `completed_resolution_matches_substitution` connects that result to the existing Variables.substitute semantics. Its projection deliberately collapses Pending and invalid, but the correspondence theorem requires prior successful resolution, so it never authorizes fallback from Pending.

`completed_alias_extension` permits an absent/pending alias name to receive a successfully resolved output while preserving all existing settled bindings and the producing resolution. Later alias use reads the final alias binding; the producing expression's reads remain its separate provenance. This is sequential completion, not a theorem discovering aliases, checking their graph or resolving cycles. In native code an alias's settled output must be backed by transitive finality evidence; mere presence in the custom-property map cannot satisfy the premise.

The executable prefix certificate rejects every encountered base-gated entry before checking its current eligibility, skips other-ineligible/rollback-disallowed entries, and requires a completed resolution for an eligible dynamic declaration. It follows the decoded rollback operation and stops at a terminal result or exhaustion. Static rollback and dynamic rollback use the same actual reached-state traversal. Acceptance derives Stability.agreesAt from immutable completed bindings, then applies the unchanged scan_eq_of_reached_agreement. A second theorem preserves the full visited trace, including skipped decisions. Neither theorem assumes evaluator agreement or requires unrelated pending values to complete. Extends deliberately preserves every already-settled binding, including settled-invalid, not just the reads of this expression; a native receipt producer must establish that strong session assumption.

The general certificate admits completed fallback and dynamic revert results. `literalReferenceCertificate` is deliberately separate: it illustrates the earlier narrow source proposal and rejects fallback/revert even when stable. It is not used to prove the general prefix theorem and is not a native grammar restriction. The model's decoder uses absolute/revert/unsupported tokens and a fixed interpretation; absolute numbers are abstract value labels, not a CSS parser or font calculation. Invalid terminal output can be stable without being suitable for a computed-size facet. Final absolute-AST classification, input readiness and application effects remain separate obligations. The 20 and 30 examples are different immutable environments; the theorem does not permit changing a completed 20 binding to 30 within one certificate/session.

Native correspondence remains open. The currently sealed f0d21a checker still rejects WithVariables. Retained MetricPreparation already owns resolved rollback declarations and the next cursor; the proposed reusable witness must additionally retain completed binding outcomes and identity for raw Arc, longhand, substitution context, session, flags and visited rollback prefix. ReferenceWalk completion alone is insufficient: it can encounter SemanticOpen and does not retain this completed-binding/read receipt. The model's short-circuit logical substitution order is not semantic dependency-graph discovery and is not an assertion that the native sibling/LIFO traversal has that order. An invalid left append operand can skip the right operand for value evaluation; no theorem removes that right operand from CSS graph analysis. The finite linked-list view, completed negative lookup provenance, static operation stability, fixed rollback eligibility relation, native parsing/context effects, actual attributes/env(), and graph finality are external. No Tarjan edge, defaulting policy, native reset/progress or single-publication proof is added here.
