# Resuming completed-variable substitution

This model gives an explicit retained machine for the existing VariableExpr grammar and proves it refines the sealed CompletedPrefix resolver. Its theorem preserves the exact completed tokens and logical read log across arbitrary finite pauses and binding-completion schedules. It is separate from the in-progress native substitution prototype; no parser, CSS evaluation, browser or native-refinement claim is made.

The machine stores Eval, Await or Value control, a continuation stack, and the consumed-read log. Eval(reference/fallback) creates an explicit Await request. Pending returns the same request and poll leaves the whole machine unchanged. A settled value or settled-invalid outcome consumes the request once, appends its name, and moves control. Invalid chooses the specified fallback; Pending cannot. Append-left preserves the remaining right expression; append-right preserves the completed left tokens while the right pauses. The machine never restarts a completed prefix to service a later request. A terminal poll is idempotent. These are occurrence-level claims: two distinct references to the same name may legitimately contribute two reads, and this does not prove global caching or native side-effect counts.

`completion` is a denotation of the retained control and stack using CompletedPrefix.resolve. The tick theorem proves this denotation unchanged by an actual operational step. Every environment in a polling schedule must preserve all its settled bindings in the chosen final environment, including invalid outcomes; unresolved names may complete. Cached left values therefore remain final. The theorem permits arbitrary polling order and stalls but no contradiction of an already consumed binding. Precisely, each polling environment is extended by the final environment; pairwise growth is not required. An environment may temporarily omit an unconsumed binding again and stall, but cannot supply a different settled value or invalid status. Ordinary monotone completion schedules satisfy this final-consistency condition. The theorem does not construct the final environment. Starting completion equals the existing resolver. If an actual finite sequence reaches Done, the resulting tokens and entire read log equal that resolver's result. This is partial correctness for arbitrary finite schedules. A separate conditional progress theorem below handles a fixed environment whose resolver result already exists; neither result promises an unavailable provider will complete. Concrete controls execute complete left/right/fallback/alias cases without a readiness Boolean shortcut.

Conditional progress uses the structural rank requested in root review: Eval literal 1, reference 2, fallback 2 plus its expression, append 3 plus both expressions; Await 1 plus its optional fallback; Value 0; append-left frame 2 plus its right expression and append-right frame 1. Each actual Next strictly decreases the sum. Pending implies the remaining completion denotation is absent, so cannot occur when that denotation is Some. Well-founded induction constructs a Done state within the retained rank; extra polling cannot change a Done state. Thus an expression with `resolve env expression = some result` finishes by rank(start)+1 polls in that fixed environment. This premise permits an unused fallback to stay pending, but requires every reached value lookup to be settled. It establishes neither native SCC progress nor eventual environmental completion. The new false control rejects asserting this bound for an actually pending root.

`tick_read_accounting` proves each progressing step either preserves the log or appends exactly the currently awaited name. `pending_poll_preserves_entire_machine` preserves cursor, frames, values and log. `consumed_request_moves_control` prevents the same outstanding request from being consumed again by an immediate poll. Together with final exact-log refinement these rule out replaying the already consumed prefix in the modeled execution. They do not count repeated external attempts to obtain a still-pending reply. No raw attribute acquisition or typed-cache request exists in this grammar.

Aliases use a final binding value supplied after their separate computation. The prior completed_alias_extension theorem justifies adding such an output to a pending name without changing existing settled bindings; this machine's alias test resumes the exact retained request and appends that alias name once. It does not expand raw alias CSS, retain an active DFS name set, or prove a cycle/fallback policy. The negative/invalid distinction is explicit even when a fallback or concatenation remains unfinished. The short-circuit value-read trace is not semantic dependency-graph discovery: invalid left append can suppress right value evaluation without proving that the right reference is absent from a CSS graph.

The native implementation boundary includes parser positions and token kinds, byte serialization/separators, attribute/environment dependencies, URL/taint tracking, pending reply identity/session authentication, child alias ownership and transitive finality, context invalidation, and native output side effects. The source agent's draft additionally retains CSS chunks and typed-attribute stages; those are not represented by this model and are not assumed correct. The synchronous provider remains the pinned source baseline. The model does not remove semantic SCC edges, invent completed-map certificates, or bless dynamic-priority readiness. A native implementation must map its states to these abstract states and prove the omitted operations preserve the contract.
