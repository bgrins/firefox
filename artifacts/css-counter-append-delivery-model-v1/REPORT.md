# Named counter delivery companion

`COUNTER_APPEND_DELIVERY_MODEL_PASS`: actual single-thread Lean 4.35.0-rc4 replay passed 14 named declaration audits, 12 closed examples and five decisively rejected false claims. The audits use no axioms beyond `propext`. This is standalone implementation support, with no native refinement, canonical integration, normative coverage increment or accepted-bug credit.

## Result

`dirty_delivery_equals_current` proves that a cache-reusing, name-selective delivery algorithm produces the same complete sequence of counter stacks as full current recalculation. The proof is induction over an arbitrary finite normalized operation sequence. Each dirty operation calculates from the table already extended by preceding operations; each clean operation keeps its old cached stack. A clean-name table invariant is maintained through both kinds of operation. This is not a definition equating the two algorithms: one skips clean computations and consumes old cached results, while the other computes every result.

The premises are explicit: old caches equal the old full calculation, clean names have equal initial tables, and every clean name's complete recipe (including source binding) is unchanged. Changed source selection cannot be hidden behind unchanged numeric values. All dependencies are same-name by construction. `append_then_deliver` composes a parent append calculation/table publication with the descendant pass: marking that name preserves the clean-name invariant, and all affected descendant USEs then see the new parent source. The childless fast path has no descendant cache obligation. These laws support a dirty-name delivery repair; they do not establish that Gecko always marks/delivers the obligation.

## Counter-specific representation

- A counter binding is `(scope identity, Int value)`. A stack is innermost first. `counter` projects its innermost value; `counters` returns outer-to-inner values. Text formatting and separators are outside this model.
- RESET installs a new binding and retains an explicitly selected outer stack suffix. `dropInner` is supplied by counter-scope resolution: sibling replacement and nested reset differ. SET changes the existing binding value without replacing its identity, or instantiates an implicit binding when no local source exists. INCREMENT likewise updates the selected value or starts at zero. USE preserves the full selected stack.
- `Owner` is a containment path, unrelated to counter binding identities. A containment scope can contain multiple counter scopes, and a counter scope can be referenced by a contained USE. Empty intermediate containment scopes require no table rows; ancestry can skip them.
- Per-name source indices address already-produced rows. `Ordered` requires each selected row to exist and belong to the same or an ancestor containment owner; `orderedB_sound` proves the executable check implies this predicate. Ordered recipes are the interpretation boundary, not an implementation of `SetScope`. The model does not choose which preceding row is correct from a DOM/frame tree.
- For a change node after a cross-boundary USE, the supplied local recipe must respect native isolation rather than increment the inherited outside value. The explicit empty-local-stack example distinguishes `0 + 2` from inherited `1 + 2`. We do not claim to derive all native `mScopeStart`/outer-chain details from that example.

This differs from the quote model: named identity-bearing stacks, RESET/SET/INCREMENT semantics, dependency-source rebinding, per-name selective caches and a full clean-name preservation invariant are essential. No quote theorem was copied or relabeled.

## Checked distinctions

The three append forms RESET 3, SET 3 and INCREMENT 2 give nested contained USE values `[3,3]` instead of `[1,1]`, while a different clean name remains 7. The normalized example includes an empty intervening containment scope. Old and new dependency orders pass the executable ordering check. Keeping the dirty bit false retains stale values. Recalculating numeric values with old source indices also leaves the first contained USE stale: dirty calculation must include source rebinding. Equal innermost values do not imply equal `counters()` stacks; equal values do not imply equal reset identities.

Five same-claim false controls reject: lost dirty-name delivery; attempting descendant reads before the parent row exists; retained old source indices; scalar-only equality of different full stacks; and incrementing inherited outside state as though it were local. The wrong-order case is deliberately outside `Ordered`; the total function's missing-index empty-stack result is not claimed as browser behavior. Negative evidence requires one exact decisive `decide` diagnostic and exit 1. Reduction failure, unknown identifier, duplicate diagnostics and exit 0 are rejected. An actual earlier stuck-reduction log is included as a gate regression, not a semantic false control. Draft compile failures are retained separately and receive no control credit.

## Limits and replay

Scope selection, DOM order, fresh pointer/identity ownership, proper lifecycle scheduling, cache alignment after insertion, dirty-name persistence until every affected scope is processed and native text notification are assumed or outside the model. Original and updated recipe lists are aligned descendant worklists; the newly appended parent row is added separately. The theorem does not prove arbitrary insertion/removal normalization or frame traversal. Same/ancestor ownership alone is necessary, not sufficient to select the correct counter scope; `dropInner` and source indices need a native correspondence argument.

Arithmetic is mathematical `Int`. Native use requires bounds excluding overflow/wrap divergence, or a separate machine-arithmetic refinement. Reversed/content-based resets, implicit list-item rules/preferences, counter-style/language/bidi rendering, dynamic names and changes across unrelated sibling containment subtrees are not covered. No concurrent scheduling or performance claim is made. No current native patch is certified.
