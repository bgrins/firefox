# Typed attr animation-provenance audit

Two provenance-loss boundaries are present in the sealed four-file candidate 982c5bc9. These are exact source findings, not browser outcomes. The current native trial and its files were not read or changed.

In `substitute_references_if_needed_and_apply`, the attribute branch rebuilds a universal value with `VariableValue::new_resolved`, then copies only `substitution.attr_tainted`. The new constructor's animation flag is false, so a true animation flag on the resolved substitution is lost before `insert_attr`. Later, the typed `Attr` consumer obtains `get_attr(...).to_variable_value().css`, parses that string again, and constructs a fresh substitution. Even preserving the first marker would not preserve it through this second conversion. The attr bit is deliberately set true at that consumer; animation provenance is independent.

These helpers have actual frozen callers: the dependency walker constructs `VarType::Attr`, loads attribute values, and calls the shared apply routine with `var.namespace()` after dependency resolution, including the acyclic completion path. Thus the source shape supports a concrete attribute containing `var(--v)` where active unregistered `--v` supplies a valid custom-ident. Runtime reachability/order and support still require a focused observation.

The two cases below separate obligations:

| Case | Input | Conditional prediction of current candidate source |
| --- | --- | --- |
| Direct sink | `writing-mode: attr(data-v type(<custom-ident>), vertical-lr)`; `data-v="var(--v)"`; active `--v: horizontal-tb` | Cached attribute substitution uses a custom-property ID formed from the attribute name, not the ordinary writing-mode sink. The final sink filter handles only `Var`. Merely copying animation metadata through the two conversions may therefore leave this direct route admitting horizontal-tb. |
| Custom-property intermediary | `--alias: attr(data-v type(<custom-ident>)); writing-mode: var(--alias, vertical-lr)` with the same attribute/active value | The two lossy conversions can make the alias appear untainted, so the outer var guard may admit horizontal-tb. Preserving both conversions would make the intended active-value provenance available to the outer var guard, subject to correct dependency invalidation. |

Use parent/default horizontal-tb, animated horizontal-tb, and fallback vertical-lr only if the initial nondefault fallback assertion is included; preferably calibrate the active variable and an ordinary literal-attribute control separately. A direct `attr()` fallback and an alias's outer `var()` fallback are different decisions. Raw-string and number/unit attr branches do not recursively substitute attribute text and are not equivalent tests. Container-query handling explicitly bypasses the cache, so it is outside this proposed ordinary-style observation.

The primary text supports recursive evaluation but does not supply a native metadata algorithm. Values 5 attr substitution step 6 substitutes functions in typed attribute text with an attribute context before parsing; failure step 7 evaluates the attr fallback. Variables 1 replacement step 3 rejects an animation-tainted variable in a non-animatable property, and step 4 selects its fallback. The direct case therefore needs the ordinary-property context to remain effective during nested var substitution. The intermediary additionally needs a justified dependency/provenance bridge from the typed attribute to the custom property; the infectious-custom-property wording supports the concern but does not explicitly describe this cache/typed-conversion boundary. This audit does not turn that remaining bridge into a proved conformance verdict.

Animation-taint and attr-security taint are different restrictions. The former controls variable substitution into non-animatable sinks; the latter marks attr-derived values and rejects URL use. Neither loss identified here demonstrates URL-taint loss or a security vulnerability. The current code visibly restores attr taint at typed consumption.

Actionable follow-up: observe both routes with a valid literal attr control and retained active-variable calibration before changing the patch. If the intermediary fails, preserve animation provenance through both cache reconstruction and typed parsing, and test metadata-only changes in the attribute map. The direct route separately requires a correct sink-context strategy; rejecting every tainted Attr at its outer boundary can choose a different fallback than correctly rejecting the nested var, so that is not assumed to be an equivalent repair. No additional Lean model is added: the existing selected-value model already shows marker loss matters, while another Boolean example would not establish these runtime/spec-context obligations.
