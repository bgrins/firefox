# General sibling-list locality for a cross-parent move

This companion derives notification locality from list removal and insertion, rather than assuming that changed values belong to affected parents. It does not claim a native refinement, new discovery, or canonical coverage increment.

A World maps each parent to a finite child list and each modeled node to its owner. WellFormed requires every list to be duplicate-free and node membership to agree exactly with ownership. Thus nodes cannot be duplicated across parents, and every modeled node is present in its owner's list. Parent and Node types are arbitrary types with decidable equality; they need not be finite. Count and index are the actual list length and idxOf+1, not uninterpreted functions.

The operation erases the moved node from its old list, inserts it between front and back in the destination list, and changes only that node's owner. Validity requires distinct old/destination parents, original ownership of the moved node, and destination.children = front ++ back. That decomposition admits any existing insertion gap, including beginning/end. No desired freshness or unchanged-outside property occurs among the premises.

Nine audited statements establish: destination initially excludes the moved node; removal decreases the old length by one; the moved node is absent from old/present in destination afterward; the resulting world remains well formed; nodes outside both original sibling domains retain their entire sibling list; consequently their count/index pair is unchanged; notifying both original domains suffices for pair freshness; a valid move combines well-formedness with this freshness guarantee; and a concrete well-formed witness shows destination-only notification stale for both count and index.

The notification union uses original old-parent and destination-parent membership. It includes the moved node through original ownership. The list partition proof ensures this covers all affected existing nodes without treating the moved node as newly created. The refresh function comes byte-for-byte from the sealed preceding model: notified nodes recompute the new value, others retain the original cached value. Initially fresh cache entries and actual recomputation are therefore explicit external premises. The proof does not show native flags cause notification, that notifications are delivered, or that recalculation happens at the right time.

The witness starts [1,0] and [2,3], moving1 to destination end. Old stationary0 changes count2→1 and index2→1 while destination-only notification retains (2,2). Separate false controls demand a fresh count and a fresh index from that insufficient notification set. The model does not imply every context change must notify if the relevant value remains equal; the predecessor's value-change characterization remains the precise necessity statement.

This is a flat sibling partition, not a complete DOM forest: parent ancestry, cycle rejection, document connectivity, shadow scopes, pseudo-elements, selector dependencies, state-preserving DOM eligibility and same-parent moves are outside this theorem. Root Servo data, frame reconstruction, animation identity/time, focus and iframe state remain independent native obligations. The earlier finite same-parent example remains only an example; this package adds general cross-parent locality, not a universal DOM-move proof.
