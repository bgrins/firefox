# Uncompiled provider-readiness draft

This file has not been passed to Lean. It is a proposed local control/identity extension, not a checked proof or native refinement. No accepted theorem counts are added. It uses only Std, without importing/copied proof infrastructure.

World records actual-frame-shaped kind, dirty predicate, parent, in-flow parent and hidden marker. `dirty` represents the combined IsSubtreeDirty result, not only NS_FRAME_IS_DIRTY. The explicit provider computation follows checked immediate parent links. It does not invent a provider for arbitrary descendants. `newGate` is the intended pure predicate of the C++ branch sequence; its full source translation remains to be checked.

Nine proposed general results cover predicate extension, absent/clean provider, ordinary clean target, actual group/column parent chains with dirty table, and original-target ancestry preservation. Two concrete examples distinguish clean provider plus dirty hidden ancestor (candidate remains closed) and hidden table provider lost by substituting the table as the query-walk start. The former is a graph countermodel, not a reachable native history or a new bug claim.

`ancestors` is fuel-bounded solely to state the local identity result on arbitrary graphs. No fuel sufficiency, native acyclicity/termination or complete ancestor coverage theorem is claimed. The first entry considered is the original target's in-flow parent, matching the source. No current frame is automatically added.

Full provider publication, post-flush geometry correctness, frame lifetime, raw-pointer identity, scheduling/interruptibility and constructor/history invariants remain open. Ordinary target equivalence is local control equivalence; additional layout may have observable consequences not represented here. The native dirty-table premise still awaits root's actual diagnostic trace. The existing Hidden/Subtree components' provider/lifetime admissions are not implicitly discharged by this draft.
