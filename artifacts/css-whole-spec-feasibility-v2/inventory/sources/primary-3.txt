L856: ### 8.4. Toggling Between Values: the cite539†cycle() notation
L857: 
L858: The cycle() expression allows descendant elements to cycle over a list of values instead of inheriting the same value.
L859: 
L860: The following example makes `<em>` elements italic in general, but makes them normal if they’re inside something that’s italic:
L861: 
L862:     em { font-style: cycle(italic, normal); }
L863: The following example cycles markers for nested lists, so that a top level list has cite540†disc -shaped markers, but nested lists use cite541†circle , then cite542†square , then box, and then repeat through the list of marker shapes, starting again (for the 5th list deep) with disc.
L864: 
L865:     ul { list-style-type: cycle(disc, circle, square, box); }
L866: 
L867: The syntax of the cite539†cycle() expression is:
L868: 
L869:     cite539†<cycle()> = cycle( cite58†<whole-value> cite427†# )
L870: The cite539†cycle() notation is a cite58†<whole-value> . However, it is not allowed to be nested, nor may it contain cite144†attr() or cite426†calc() notations; declarations containing such constructs are invalid.
L871: 
L872: The following cite539†cycle() examples are all invalid:
L873: 
L874:     background-position: 10px cycle(50px, 100px);
L875:     /* cycle() must be the sole value of the property */
L876: 
L877:     list-style-type: cycle(disc, 50px);
L878:     /* ''50px'' isn't a valid value of 'list-style-type' */
L879: To determine the computed value of cite539†cycle() , first evaluate each argument as if it were the sole value of the property in which cycle() is placed to determine the computed value that each represents, called `C_{n}` for the `n`-th argument to cycle(). Then, compare the property’s cite543†inherited value with each `C_{n}`. For the earliest `C_{n}` that matches the inherited value, the computed value of cycle() is `C_{n+1}`.
L880: If the match was the last argument in the list, or there was no match, the computed value of cycle() is the computed value that the first argument represents.
L881: Note: This means that repeating values in a cite539†cycle() short-circuits the list. For example cycle(1em, 2em, 1em, 4em) will be equivalent to cycle(1em, 2em).
L882: 
L883: Note: That cite539†cycle() explicitly looks at the computed value of the parent, so it works even on non-inherited properties. This is similar to the cite544†inherit keyword, which works even on non-inherited properties.
L884: Note: The cite179†computed value of a property is an abstract set of values, not a particular serialization cite110†[CSS21] , so comparison between computed values should always be unambiguous and have the expected result. For example, a Level 2 cite545†background-position computed value is just two offsets, each represented as an absolute length or a percentage, so the declarations cite389†background-position: top center and background-position: 50% 0% produce identical computed values.
L885: If the "Computed Value" line of a property definition seems to define something ambiguous or overly strict, please cite546†provide feedback so we can fix it.
L886: If cite539†cycle() is used on a cite547†shorthand property , it sets each of its longhands to a cycle() value with arguments corresponding to what the longhand would have received had each of the original cycle() arguments been the sole value of the shorthand.
L887: 
L888: For example, the following shorthand declaration:
L889: 
L890:     margin: cycle(1px 2px, 4px, 1px 5px 4px);
L891: is equivalent to the following longhand declarations:
L892: 
L893:     margin-top:    cycle(1px, 4px, 1px);
L894:     margin-right:  cycle(2px, 4px, 5px);
L895:     margin-bottom: cycle(1px, 4px, 4px);
L896:     margin-left:   cycle(2px, 4px, 5px);

L207:   * A plus (+) indicates that the preceding type, word, or group occurs one or more times.

L212:   * An exclamation point (!) after a group indicates that the group is required and must produce at least one value; even if the grammar of the items within the group would otherwise allow the entire contents to be omitted, at least one component value must not be omitted.
L213: The + and # multipliers may be stacked as +#; similarly, the # and ? multipliers, {A} and ? multipliers, and {A,B} and ? multipliers may be stacked as #?, {A}?, and {A,B}?, respectively. These stacks each represent the later multiplier applied to the result of the earlier multiplier. (These same stacks can be represented using grouping, but in complex grammars this can push the number of brackets beyond readability.)
L214: For repeated component values (indicated by *, +, or #), cite158†UAs must support at least 20 repetitions of the component. If a property value contains more than the supported number of repetitions, the declaration must be ignored as if it were invalid.
L215: ### 2.4. Combinator and Multiplier Patterns
L216: 
L217: There are a small set of common ways to combine multiple independent cite159†component values in particular numbers and orders. In particular, it’s common to want to express that, from a set of component value, the author must select zero or more, one or more, or all of them, and in either the order specified in the grammar or in any order.
L218: 
L219: All of these can be easily expressed using simple patterns of cite23†combinators and cite24†multipliers :
L220:  | in order  | any order
L221: --- | --- | ---
L222: zero or more  | `A? B? C?`  | `A? || B? || C?`
L223: one or more  | `[ A? B? C? ]!`  | `A || B || C`
L224: all  | `A B C `  | `A && B && C`
L225: 
L226: Note that all of the "any order" possibilities are expressed using combinators, while the "in order" possibilities are all variants on juxtaposition.
L227: ### 2.5. Component Values and White Space
L228: 
L229: Unless otherwise specified, cite153†white space†www.w3.org and/or comments may appear before, after, and/or between components combined using the above cite23†combinators and cite24†multipliers .
L230: Note: In many cases, spaces will in fact be required between components in order to distinguish them from each other. For example, the value 1em2em would be parsed as a single cite160†<dimension-token> with the number 1 and the identifier em2em, which is an invalid unit. In this case, a space would be required before the 2 to get this parsed as the two lengths 1em and 2em.

L1617: ### 10.9. Type Checking
L1618: 
L1619: A cite181†math function can be many possible types, such as cite127†<length> , cite279†<number> , etc., depending on the cite715†calculations it contains, as defined below. It can be used anywhere a value of that type is allowed.
L1620: 
L1621: For example, the cite347†width property accepts cite127†<length> values, so a cite181†math function that resolves to a <length>, such as calc(5px + 1em), can be used in width.
L1622: Additionally, cite181†math functions that resolve to cite279†<number> can be used in any place that only accepts cite147†<integer> ; the value is cite306†rounded to the nearest integer as it resolves.
L1623: 
L1624: Operators form sub-expressions, which gain types based on their arguments.
L1780:   * Dividing zero by zero, dividing ±∞ by ±∞, multiplying 0 by ±∞, adding +∞ to −∞, or subtracting two infinities of the same sign produces NaN.
L1781:

L1783: 
L1784:   * Certain argument combinations in cite181†math functions are defined to produce cite772†NaN (for example, asin(2) produces NaN).
L1785: 
L1786:   * Any operation with at least one NaN argument produces NaN.
