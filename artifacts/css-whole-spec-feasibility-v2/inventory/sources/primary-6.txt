L146: #### 3.1.1. Commas in Function Arguments
L147: 
L148: cite120†Functional notation often uses commas to separate parts of its internal grammar, and occasionally other syntax (such as `:` or `;` in cite121†if() ). However, some functions (such as cite122†mix()†www.w3.org ) allow values that, themselves, could contain these argument-separating tokens. These values (currently cite58†<whole-value> , cite123†<declaration-value> , and cite124†<any-value> ) are free-form productions.
L149: To accommodate these sorts of grammars unambiguously, the cite125†free-form productions can be optionally wrapped in curly braces {}. These braces are syntactic, not part of the actual value, and only serve to explicitly indicate the bounds of the production. A free-form production can either (after optional whitespace) start with a cite126†<{-token> , or not:
L150: 
L151: If it does not start with a "{" token
L152: The production does not match any top-level commas or {} blocks. (The production stops parsing at that point, so the comma or {} block is matched by the next grammar term instead; probably the function’s own argument-separating comma.) Individual usages of the production can define additional tokens that are similarly restricted from matching at the top-level.
L153: 
L154: If it does start with a "{" token
L155: The production matches just the {} block that the "{" token opens. It represents the contents of that block, ignoring the {} block wrapper itself.
L156: 
L157: Note: General restrictions defined for a particular cite125†free-form production , like cite123†<declaration-value> not matching cite127†<semicolon-token> s, apply regardless of whether it’s {}-wrapped or not.
L158: 
L159: For example, the grammar of the cite128†random-item() function is:
L160: 
L161:     random-item( cite129†<random-key> , [cite123†<declaration-value> ?]# )
L162: The # indicates comma-separated repetitions, so randomly choosing between three keywords would be written as normal for functions, like:
L163: 
L164:     font-family: random-item(--x, serif, sans-serif, monospace);
L165: However, sometimes the values you want to choose between need to include commas. When this is the case, wrapping the values in {} allows their commas to be distinguished from the function’s argument-separating commas:
L166: 
L167:     font-family: random-item(--x, {Times, serif}, {Arial, sans-serif}, {Courier, monospace});
L168: 
L169: 
L170: This randomly chooses one of three font-family lists: either Times, serif, or Arial, sans-serif, or Courier, monospace.
L171: This is not all-or-nothing; you can use {} around some arguments that need it, while leaving others bare when they don’t need it. You are also allowed to use {} around a value when it’s not strictly required. For example:
L172: 
L173:     font-family: random-item(--x, {Times, serif}, sans-serif, {monospace});
L174: 
L175: 
L176: This represents choosing between three font-family lists: either Times, serif, or cite130†sans-serif , or cite131†monospace .
