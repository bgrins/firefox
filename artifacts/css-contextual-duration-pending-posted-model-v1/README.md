# Pending versus posted animation-restyle protocol

Seven Lean theorems describe a conditional starvation mechanism: a pending entry is not the same as a posted restyle request. Under an explicit final-traversal-without-drain premise, repeated changed-timing Layer requests can coalesce without waking composition. An independently posted ordinary restyle can recompose. This is a small protocol model for the instrumentation obligations in the sealed pending-restyle review; it is not proof that Gecko takes this path.

State separates pending, posted, insideServo, appliedGeneration and composedGeneration. The two natural-number generations are logical versions of effective timing input and its last composition, not Gecko's concrete animation-generation counter, numerical durations or actual traversal counts. Every changeTiming call assumes an effective timing change, increments its logical generation, and requests Layer work. Equal-value setter fast paths are outside this event. requestLayer coalesces a previously pending request; a new request posts only outside traversal. Existing posted work is preserved.

service consumes work only if posted and outside Servo. It models one successful composition using the current timing version and clears the request. This explicitly abstracts away filters, subtrees, cancellation, compositor throttling, other wake sources, and any timing update caused during composition itself. In particular it cannot establish convergence for self-dependent font duration. A paused animation receiving a script-owned fixed 2000ms override motivates the finite fixed-input service obligation; no cyclic numerical equation is used.

exitWithoutDrain is the crucial native-unproved premise: it exits traversal without consuming the pending entry or posting new work. final_exit_premise_creates_stalled proves the consequence of that chosen boundary operation, not that the real final pass executes it. Stalled means pending=true, posted=false, insideServo=false. The induction arbitrary_requests_remain_unposted gives the exact state for every natural-number request count: timing generation increases by that count, while posted/pending/inside and last-composed generation remain unchanged, even though service is polled after every request. no_composition_after_arbitrary_requests preserves an initial stale-generation inequality. There is no fairness theorem and no infinite-time browser claim.

external_restyle_can_recompose states that one independent post followed by service updates composition to the latest timing generation and clears pending/posted. It is a can-recompose result in this transition system, not permanent quiescence or a proof that a native outline mutation always drains all animation work. fresh_outside_request_does_post distinguishes an unoccupied queue from the stalled case: outside requests are not inherently suppressed.
