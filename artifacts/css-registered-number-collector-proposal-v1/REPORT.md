# Admitted registered-number dependency collector

This uncompiled native proposal adds `SpecifiedValue::number_context_references() -> Option<ReferenceFlags>` to `properties_and_values/value.rs`. It collects font and line-height scheduling edges from the real admitted specified Number AST. It does not replace the registration parser or compute/publish a value.

The single changed source file has identical captured working-tree and committed HEAD preimages at `eb9c04b94cf3007d4f4b4d45ba99cd826829e455`. The patch therefore has identical clean-HEAD/live transport and postimages. It contains no pending-animation APIs. The preparation owner supplies separate ordinary and pending integration patches. No integration patch or runtime result is included in this collector's validation.

## Contract and computation correspondence

The caller must select substitution, parse the exact `<number>` registration with the real parser, and preserve pending/SCC readiness before using this method. Lists and non-number components return `None`; the caller separately excludes registration alternatives and multipliers. A successful parse of a ready but wrong-type provider must not retry that provider's fallback.

`Some(flags)` permits replacement of the contaminated lexical font/line-height inventory. `Some(empty)` means no represented font/line-height graph edge; it does not mean no context access. Absolute lengths still use effective zoom, metrics may read writing mode, and the eventual normal conversion must preserve all dependency/effect tracking. `None` means the collector has not certified this value: retain the existing conservative path, never silently replace its flags with empty.

The path examined is `SpecifiedValue::parse` → `SpecifiedValueComponent::Number` → `Number::as_calc` → `CalcNumeric.node`. The numeric parser simplifies and checks the resulting numeric type before retaining the AST. The later computation is `Number::to_computed_value` → `CalcNumeric::resolve` → specified `CalcNode::to_computed_value` → generic `map_leaves` → `resolve`. Mapping computes all surviving leaves before numeric resolution. This justifies collecting every supported operand of min/max, clamp, rounding, logarithms and other math functions, including operands whose eventual numeric value would not win. Already simplified-away nodes are absent and are not reintroduced from source text.

The exhaustive match covers all 27 captured CalcNode variants and all nine specified Leaf variants. Supported arithmetic includes sums, products, inverses, unary math functions, min/max, clamp, round, mod/rem, atan2, pow, hypot, optional log bases and progress. `calc(1em / 1px)` remains a valid number with a font requirement; the result's Number type is not used to erase its length operands. This code does not use `Number::get`, `Number::resolve`, or `CalcNumeric::as_number` to infer dependencies.

Length leaves use `LengthUnit`, matching the actual current-font/current-line-height conversion path: em/ex/ch/cap/ic add FONT; lh adds FONT and LH; rem/rex/rch/rcap/ric add ROOT_FONT; rlh adds ROOT_FONT and ROOT_LH. Existing `ReferenceFlags::for_each_non_custom` handles root-element mapping. Absolute lengths and number/angle/time/resolution leaves add no represented edge. Viewport, container, internal character widths, percentage/color/tree-count/random-key leaves and random/anchor nodes return `None`. These exclusions are conservative boundaries, not claims that those values are invalid. A partial visit cannot leak partial certification: any unsupported subtree makes the whole method return `None`.
