# Existing Stylo counters: broad versus selective workload

Use the existing **Styles** interval marker (marker type `Styles`, category `LAYOUT`) on the content process **GeckoMain** track. Its unsigned32 payload fields are `elementsTraversed`, `elementsStyled`, `elementsMatched`, `stylesShared`, and `stylesReused`. `AutoProfilerStyleMarker` surrounds `PresShell`'s `ProcessPendingRestyles`, attaches the inner-window ID and optional causing backtrace, and emits one interval on destruction. The checked e86 sources already contain this mechanism; no instrumentation patch is needed. [Marker schema](https://searchfox.org/firefox-main/rev/7a315fc898bbd3e61ba7dd220a8fb1d0721a1eb7/layout/base/AutoProfilerStyleMarker.h#56).

| Field | Actual counted operation | Interpretation limit |
|---|---|---|
| elementsTraversed | Each `recalc_style_at` entry, before choosing `restyle_kind` | Element visits, including visits that skip styling; not unique DOM nodes or every text node. |
| elementsStyled | Each `compute_style` entry, when `restyle_kind` is Some | Includes initial styling, matching, recascade, animation-rule replacement and sharing hits; not an exact count of expensive declaration-cascade calls. |
| elementsMatched | `MatchAndCascade` branch after failure to share a style | Selector matching work; does not count recascade-only visits. |
| stylesShared | Successful `share_style_if_possible` | Sharing-cache hits. |
| stylesReused | Successful primary-style reuse via rule-node comparison in `StyleResolverForElement` | Another reuse path; do not subtract this mechanically to claim an exact cascade count. |

The `PerThreadTraversalStatistics.elements_styled` comment says has_styles false→true, but **the executable e86 increment is unconditional at compute_style entry**, before checking whether the element already has styles. That comment does not describe the current counter correctly. The same executable behavior is visible upstream. [Traversal decision](https://searchfox.org/firefox-main/rev/7a315fc898bbd3e61ba7dd220a8fb1d0721a1eb7/servo/components/style/traversal.rs#375). Exact e86 source hashes/excerpts, including the increment and existing-style branch, are in SOURCE.json.

The counters are accumulated in each main/worker ThreadLocalStyleContext during traversal. After workers finish, `driver::traverse_dom` sums all TLS slots and `report_statistics` adds the aggregate to the active C++ singleton **on the main thread**. Thus the Styles payload includes parallel worker work without separately profiling worker threads. Workers are named `StyleThread#N` and registered with the profiler; include that thread filter only when worker CPU stacks/timing are also wanted. [Main-thread aggregation](https://searchfox.org/firefox-main/rev/7a315fc898bbd3e61ba7dd220a8fb1d0721a1eb7/servo/components/style/driver.rs#158).

Configuration: ensure the content GeckoMain thread is selected and collecting markers before the operation. The `firefox-platform` preset supplies GeckoMain and native stackwalking; no special Styles feature or DUMP_STYLE_STATISTICS setting is required. It does not include StyleThread in its default thread list. These exact event counters are not sampling estimates, so lowering the sample interval does not improve their count resolution. Use an optimized build for timing. The aggregate is per enclosing Styles interval, potentially summing multiple traversal roots and normal/animation-only/final traversals; the payload has **no traversal-phase, restyle-kind, depth or element-ID field**. It cannot alone prove which leaf or pass caused a count. Keep setup outside the measured interval and compare identically isolated operations/window contexts. A reduction in styled visits with similar traversed visits would support avoided per-element styling; that remains a measurement hypothesis until captured.

Existing alternative, if individual traversal aggregates are needed: Gecko's `DUMP_STYLE_STATISTICS=1` and `STYLE_STATISTICS_THRESHOLD=0` print `[PERF]` statistics from the same counters, plus traversal timing and stylist information. Default threshold is50 traversed elements, so unconfigured stdout can omit small cases. This is a launch-time option, not enabled here, and still does not attach the missing traversal-phase/element identity. The profiler marker is the shortest first comparison.
