The A candidate exposes an existing inconsistent registered-length representation: an early literal stores unscaled pixels, while a deferred reference path can store zoomed pixels. A removes the false edge that previously delayed the ready-primary path, changing its storage scale. Direct var-token serialization exposes the stored scale; CSSOM then removes the final style zoom regardless of which scale produced the value. This explains why fixing the consuming layout can simultaneously halve the custom-property CSSOM value. The source/spec trace and paired observations are maintained by the parent project; this artifact does not accept a new fix.

A smaller alternative to a new whole-value length mapper is a scoped canonical-length conversion mode. Keep builder zoom and computed font/root data intact. Replace the outer registered Value<Component> derived ToComputedValue with an explicit wrapper that enters the scope; the existing inner conversions already visit length leaves in lists, images, transforms and calc expressions. Normalize at the actual checkout's NoCalcLength::to_computed_value_for_math boundary. Its public to_computed_value_with_base_size wrapper adds final clamping; calc::Leaf calls the math boundary directly. Normalizing only the public wrapper would miss calc leaves, while adding finite() in the math boundary would regress the existing nonfinite-math repair.

The scope must use a guard that restores its prior state, including nested conversion and unwind. The trait accepts &Context, so a plain mutable boolean assignment is insufficient; a small Cell-backed scope or explicit derived subcontext is needed. This is different from temporarily setting builder.effective_zoom to one: current font and line-height references are already computed, inherited references use effective_zoom_for_inheritance, and root references explicitly apply local scale.

For already zoom-factored absolute/font/root/viewport leaves, producing an unscaled length at that boundary keeps percentages, number/angle/time/resolution leaves, URLs, attr taint and color conversion untouched. Length ratios cancel the common factor; mixed length-percentage values retain their percentage parts. The existing color conversion must run normally. Do not call generic ToResolvedValue as a storage normalizer: it also resolves currentColor.

CSSOM export should preserve canonical registered length leaves while retaining the rest of resolved-value behavior. The existing resolved Context already identifies PropertyId::Custom; CSSPixelLength and LengthPercentage resolved conversion can avoid their length unzoom only for that property kind. Ordinary longhand CSSOM keeps its current unzoom. Computed registered var-token export is then direct canonical serialization. Cached initial values, inherited copies and from_computed_value round trips must be audited against this invariant; copied canonical values must not be normalized again. The parallel producer audit confirms custom animation application bypasses the ordinary longhand ToAnimatedValue conversion, but that finding must remain part of final source review.

There is a concrete blocker to treating a single unconditional divide by current builder zoom as a complete repair. ContainerSizeQueryResult stores only raw Au dimensions. Gecko_GetQueryContainerSize obtains frame->GetContentRectRelativeToSelf().Size() without removing the container's effective zoom. Rust carries that size through get_container_width/height and container_relative_to_computed_value without applying the querying element's local zoom. A missing-axis fallback returns viewport dimensions directly. Therefore the container unit's raw result need not equal current-local-zoom times a canonical value. Changing when the querying element's zoom is computed can change the proposed normalization even though its container result is unchanged. The same obstruction applies to a whole-value mapper that blindly divides all lengths by the current scale.

A complete scoped design must first establish the normative coordinate frame for container dimensions. One candidate to evaluate is carrying source-scale provenance, then removing the actual container scale and handling viewport fallback separately from the querying element. This is a hypothesis, not a justified prescription: the raw Au path alone does not establish expected cross-zoom cqw behavior or prove a browser defect. Width and height can come from different containers, so any provenance design must consider each axis. Current CSS Viewport and container-unit clauses, or an independent ordinary-CSS calibration, must determine the intended conversion before implementation; no new container-unit bug is accepted here. Merely moving all registered computations after Zoom could introduce cycles for properties that feed zoom and does not fix var export by itself.

Another bypass is registered style-range query evaluation, which constructs Component::Length directly and compares it with stored custom values. Its operand must enter the same canonical conversion scope. Context-free conversion shortcuts (to_computed_pixel_length_without_context and transform matrix helpers) cannot be blanket-unzoomed: their values are already context-independent and numeric matrix coefficients are not generic lengths. Preserve numeric matrix coefficients and percentage components. These shortcuts require an explicit caller audit, not an assumption that every pixel-looking number is a zoomed leaf.

Computation-scale metadata on Value is not by itself a smaller complete repair. It can explain CSSOM exposure but still requires scale-aware var serialization, equality, cross-zoom inheritance and animation between differently scaled inputs. Recomputing from an uncomputed intermediate under reciprocal zoom could re-run colors, effects and rule-cache dependencies, so it is not established as a pure normalization operation.

Recommended next prototype is the scoped conversion design, with style-query operand scope included and container handling held until its normative coordinate-frame calibration is resolved. Do not claim that a uniform inverse-scale hypothesis already covers that producer. Before any native activation, require direct/reference/CSS-wide/initial/inherited length cases at different zooms; 1em/lh/rem/rlh and viewport units; container and fallback units with different parent/child zooms; length-percentage/list/transform/image members; currentColor and taint controls; and custom animation plus style-range comparisons. Check custom CSSOM, consuming property CSSOM and geometry independently. This artifact deliberately contains no incomplete patch advertised as a full repair.
