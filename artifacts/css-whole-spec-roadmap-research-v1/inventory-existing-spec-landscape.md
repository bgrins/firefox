## Recommended implementation sequence

The broad objective is an evolving, independently useful CSS research artifact.
Prioritize new algorithm/semantic families and important input boundaries over
additional small selector rejection classes. Each package needs a versioned
primary trace, independent relation, executable correspondence, explicit domain,
universal laws, distinguishing cases and independent review.

1. **Syntax declaration and rule consumption, then whole-source style.** Start
   with [declaration consumption](https://drafts.csswg.org/css-syntax-3/#consume-declaration)
   and bad-declaration remnants over the checked token/component stream. Prove
   exact remainder/progress, priority extraction and recovery boundaries before
   adding contextual blocks/rules/stylesheets. Then replace the important
   already-separated `RawRule` input assumption with a checked source bridge.
   Original source text for custom-property values and unicode-range reconsumption,
   property/rule validity in context, and unknown-versus-invalid outcomes need
   explicit interfaces. A token-only parser must not claim those source duties.
   The block-contents terminal declaration-run text is under independent trace;
   preserve that correspondence issue instead of silently choosing a behavior or
   inferring a browser defect. The [dated call-chain trace](declaration-scope-text-trace.md)
   identifies the existing CSSWG issue #11017 and the separate scope-order wording
   mismatch, including the recorded weak-proximity resolution.
2. **Values 4 dimensional types and typed math.** Begin with the independently
   specified [calculation type algebra](https://drafts.csswg.org/css-values-4/#calc-type-checking),
   including unit exponent maps and percentage hints, then a bounded calculation
   parser/typechecker with soundness. Connect a selected property family to the
   cascade only after specifying percentage/context resolution and computed-versus-
   used values. Existing exact decimal token arithmetic is a prerequisite, not
   this result. Nonfinite values, signed zero and native rounding need separate
   contracts rather than implicit rational arithmetic assumptions.
3. **Cascade 6 scoped rules and proximity.** Model roots, limits, applicability
   and [scoping proximity](https://drafts.csswg.org/css-cascade-6/#scope-proximity),
   then prove winner order using the
   [cascade sorting algorithm](https://drafts.csswg.org/css-cascade-6/#cascade-sort).
   Trace the draft's differing scope-effects wording before fixing an
   interpretation. Keep nested/implicit scopes, namespace hosts and featureless
   shadow elements explicit; existing DOM query scope does not establish these.

After these slices, conditional/container environments, general component-token
custom-property substitution and selected layout/property algorithms offer
substantial further coverage. Fonts/text, rendering and animation require their

## Review gates for sibling support

CSS adjacency ignores non-element nodes; both sibling combinators require a
shared document parent. [Next sibling](https://drafts.csswg.org/selectors/#adjacent-sibling-combinators),
[subsequent sibling](https://drafts.csswg.org/selectors/#general-sibling-combinators),
[DOM sibling definition](https://dom.spec.whatwg.org/#concept-tree-sibling).

Our interface should establish, or explicitly delegate to an adapter:

- Unique positions within a coherent sibling group.
- An immediate predecessor does not skip an element in that order.
- Predecessor traversal terminates and visits every preceding element.
- Sibling-group membership agrees with concrete parentage, including
  non-element containers such as document fragments.
- Unrelated roots with `parent = none` do not become siblings by accident.

The ordered-forest extension now establishes its explicit uniqueness, position,
coherence, shared-element-parent, and completeness laws; finite indexed search
establishes predecessor-search correspondence. Concrete document-parent
fidelity, including non-element container identity, remains an adapter duty.
See [extension review](extension-review.md) for the exact checked checkpoint.

## Gates for relative selectors and specificity

The ordered parent forest is not necessarily finite: finite ancestor paths and
finite sibling lists permit an infinite descending chain. Forward searches
therefore need another completeness contract, such as a finite enumeration of
all nodes, or complete child enumeration plus a downward well-founded bound.
The existing parent-depth law only justifies upward traversal.

[The relational pseudo-class](https://drafts.csswg.org/selectors/#relational)
uses anchored relative selectors. A witness must preserve every relation from
the anchor through the relative chain. Omitted leading combinators mean strict
descendant; explicit sibling combinators can select outside the anchor subtree.
The CSS syntax layer must reject nested `:has()` and ordinary pseudo-elements
inside it, even if a larger semantic IR can represent those expressions.
Negating an existential witness differs from finding a witness satisfying
negation; tests should distinguish these quantifier orders.

A syntax-aware specificity layer should retain explicit `:is`, `:where`,
`:not`, `:has`, and filtered-`nth` constructors. Use natural-number triples
with lexicographic comparison and componentwise addition. Logical-pseudo
argument maxima are static; the top-level selector-list result is the maximum
among matching branches. Represent the unmatched result separately from a
matched zero-specificity selector. Repeated simple selectors count repeatedly.
If a future implementation uses fixed-width storage, overflow must clamp rather
than wrap. These are [Selectors specificity](https://drafts.csswg.org/selectors/#specificity-rules)
requirements, not properties recoverable from the existing matching IR.

## Cascade entry point after selector integration

Use [Cascade 5 sorting](https://www.w3.org/TR/css-cascade-5/#cascade-sorting)
as the initial stable profile. Candidate declarations should carry explicit
origin/importance, context, element-attached status, resolved layer order,
specificity, and source order. Normal and important declarations reverse
origin, layer, and encapsulation preferences. Unlayered rules occupy an implicit
final layer. A layer rank is already-normalized input; it does not prove nested
layer-name resolution. Initially pin one context and omit scope, rollback,
animations, transitions, and property-value interpretation unless explicitly
implemented.

Useful proof targets are winner membership and maximality, comparator laws,
and independence from input enumeration when distinct source positions resolve
ties. Preserve enough ordered candidates for later `revert`/`revert-layer`
semantics; treating rollback as an ordinary winning value is insufficient.
Keep declaration filtering, cascade ordering, and specified/computed-value
processing as distinct operations.

[Cascade 6 introduction](https://drafts.csswg.org/css-cascade-6/) calls
itself an exploratory diff over Level 5 and directs implementers to Level 5.
Its [sorting order](https://drafts.csswg.org/css-cascade-6/#cascade-sorting)
places scope proximity after specificity, whereas
[effects of scope](https://drafts.csswg.org/css-cascade-6/) retains
wording about prioritizing proximity regardless of specificity. This is a
source-level interpretation risk; a future scoped profile should explicitly
pin the sorting-rule interpretation and track the discrepancy instead of
silently presenting all draft prose as one consistent formal source.

### Proposed closed Cascade 5 package

For one already-filtered element/property pair, compare these keys in order:

| Priority | Key | Winning direction |
| --- | --- | --- |
| 1 | Origin/importance band | Transition; important UA, user, author; animation; normal author, user, UA |
| 2 | Encapsulation context | Outer normally; inner when important |
| 3 | Element-attached status | Attached wins |
| 4 | Resolved layer order | Later normally; earlier when important |
| 5 | Specificity | Lexicographically larger triple |
| 6 | Source order | Later declaration |

This table paraphrases [Cascade 5 §6.1](https://www.w3.org/TR/2022/CR-css-cascade-5-20220113/#cascade-sorting).
An initial closed package can omit synthetic transition/animation candidates
and fix one encapsulation context. Require an input contract that attached
styles use their legitimate origin and that every layer rank comes from one
coherent resolved order. Use `unlayered` as an explicit final position, not an
arbitrary guessed integer. Non-CSS presentational hints remain excluded.

Suggested distinction tests:

- Low-specificity important author beats high-specificity normal author.
- Important user beats important author; normal author beats normal user.
- Later normal layer beats earlier; important layer comparison reverses.
- Unlayered normal beats layered; layered important beats unlayered important.
- Attached normal beats an ordinary author rule with many IDs, but loses to
  author important.
- Specificity only decides after layer; source order only after specificity.
- An unmatched high-specificity selector contributes no candidate.
- Reordering candidate enumeration preserves the winner when source positions
  are unique; equal keys need an explicit tie policy and a scoped theorem.

Defaulting can be a separate generic operation over literal values and the
three supported keywords. Its inputs are `inheritedProperty`, `initialValue`,
`parentComputedValue : Option Value`, and `cascadedValue : Option DeclaredValue`.
Parent absence falls back to the initial value. Missing declarations and
`unset` follow property inheritance; `initial` and `inherit` force their
respective choices. [Cascade 5 §7](https://www.w3.org/TR/2022/CR-css-cascade-5-20220113/#defaulting)
provides the source interpretation.

Test both inherited and non-inherited properties with a distinct parent and
initial value, explicit inherit on a non-inherited property, explicit initial
on an inherited property, root fallback, literal precedence, and unset after
a lower-priority literal. Do not treat missing/invalid values as literal zero.

For a closed model, declare ordinary literal values to be final values with
identity computation; this permits a precisely scoped computation theorem.
A general CSS computation model instead needs distinct specified/computed
value types, environment-dependent conversion, and the parent's computed
value. Shadow inheritance requires a flattened-tree adapter; the current
selector parent relation is insufficient to establish that mapping.
`revert` and `revert-layer` require additional candidate filtering and remain
outside this package until their rollback semantics are separately modeled.

## Queued document/content selector package

[:root](https://drafts.csswg.org/selectors/#root-pseudo) identifies the document
element, not every node without an element parent. A minimal single-document
observation contract can add `documentElement : Option Node` plus a proof that
the selected document element has no element parent. Detached and fragment
roots remain in the forest but are not selected by this field. Multiple
documents require owner-document identity and a root observation per document.
The root must not be inferred from the local name `html`.

[:empty in Selectors 4](https://drafts.csswg.org/selectors/#empty-pseudo)
permits document-whitespace-only content, whereas
[Selectors 3](https://www.w3.org/TR/selectors-3/#empty-pseudo) rejects any
nonempty text content. Both ignore comments/processing instructions and
zero-length content nodes. A child element prevents matching regardless of
its own emptiness or rendering. Generated pseudo-element content does not
change the underlying document children.

[CSS Text 4](https://drafts.csswg.org/css-text-4/#white-space-processing)
defines document whitespace using spaces, tabs, and document-language segment
breaks; it explicitly distinguishes this from CSS syntax whitespace. Therefore
the attribute tokenization helper `cssWhitespace` is not automatically a
valid emptiness classifier. Prefer an explicit profile with a decidable
whole-content predicate, after a specified host-language normalization step.
A sequence predicate can represent segment conventions without pretending
that every convention is a single-codepoint classification.

Proposed observations: complete element-child projection from the parent
forest plus complete direct text/content chunks; ignored node kinds do not
enter that projection. The concrete adapter must prove or audit completeness,
CDATA/entity handling, and host-language normalization. A stronger later model
can retain an explicit sum of element/text/comment/processing-instruction
children and prove the projections. Empty matching then checks no element
children and every content chunk acceptable under the chosen profile.

The proposed explicit contract requires projected element-child membership
iff the forest parent relation and projected order equal to each child's
coherent sibling group. This also implies no duplicate or self element-child
observations. A selected document root has no element parent and a singleton
element-sibling group. These are abstract observation consistency laws;
completeness of text/content observations still depends on the concrete
adapter. The two empty profiles can share an executable/declarative interface,
with strict-text matching implying any supplied profile that accepts the
empty string. Arbitrary supplied predicates are not thereby certified as
CSS document-whitespace classifiers.

Keep strict-text and draft-whitespace profiles named separately. A
[BCD maintainer's direct test report, 30 June 2026](https://github.com/mdn/browser-compat-data/issues/29834)
says whitespace-only elements failed to match in Chrome, Firefox, and Safari
at that time. This is dated evidence, not an October 2026 measurement or a
proof of current interoperability. Attempts to fetch the relevant live WPT
results during this review failed; no new browser run was performed.

Distinguishing fixtures: real document root versus detached/fragment roots;
a non-html document element; no children; empty text; comment-only content;
space-only text under both profiles; nonbreaking space; script-created CR/FF
under a pinned host profile; mixed whitespace and non-whitespace chunks; an
empty child element; generated content with no DOM children.

## Queued variables package and version boundary

A useful bounded next module is a finite, per-element custom-property
interpreter over already-parsed literal/reference/concatenation expressions.
Use an explicit invalid sentinel distinct from an empty token sequence,
exact codepoint names, optional fallback (including present-empty fallback),

The [Variables 1 dated snapshot](https://www.w3.org/TR/2022/CR-css-variables-1-20220616/#cycles)
uses a directed graph including fallback references, invalidates properties
in cycles, and substitutes before inheritance. This makes cycle membership
and a terminating acyclic substitution evaluator useful distinct proof goals.
Depending on a cyclic variable need not itself mean membership in the cycle:
a valid fallback can still recover. Invalid-at-computed-value-time behavior
must not reveal an earlier losing cascade declaration.

The [Variables 2 draft](https://drafts.csswg.org/css-variables-2/) instead
references the generalized substitution machinery in
[Values 5 Appendix A](https://drafts.csswg.org/css-values-5/#arbitrary-substitution).
The latter guards substitution contexts dynamically and only traverses outer
substitution functions; nested ones are evaluated through function-specific
rules. Variables 2 evaluates a fallback when the reference result is invalid.
These drafts are a separate profile, not a proved refinement of the snapshot.

The version-difference witness `--b: 1; --a: var(--b, var(--a));` now has
an [exact source-hashed algorithm trace](variables-substitution-trace.md).

algorithms reach `1` without evaluating the fallback. This remains source
reasoning, not a browser result or a Lean theorem. The trace also records
cycle-owner marking and final unwind checks: a successful fallback cannot
rescue a marked owner, while an outside consumer may recover. These are
separate profiles, with no equivalence claim.

Prioritize a selector/DOM adapter and observable end-to-end checks before
adding this larger interpreter. The already-proved cascade/defaulting boundary
provides a natural integration point once the new value semantics are scoped.
