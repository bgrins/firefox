# Reset-rule-cache exclusion lifetime

The proposed sibling-count `set_uncacheable()` cannot be undone by later condition setters in the inspected ordinary cascade pipeline. This is a bounded source argument plus an abstract accumulation model, not a Rust refinement or a new bug claim. Immutable source is signed HEAD `19b09cce1a9b03ab19c46addc6fa46242f1544f9`; the proposed one-line query change is referenced separately.

`StyleResolver::cascade_style_and_visited` creates fresh default conditions once for that resolved style, passes the same mutable object through `Stylist` and the cascade, and supplies it to `RuleCache::insert_if_possible` after computation. `Context::new` borrows that object; it does not replace it. The exclusion bit is private to rule_cache.rs. Its sole explicit assignment sets it true, and font-size, line-height, writing-mode and color-scheme setters only write their own fields. `insert_if_possible` rejects the result before insertion when `cacheable()` is false.

There is no inherited-pass conditions reset in this captured pipeline. The generated property cascade changes `for_non_inherited_property`; this selects which conversions record reset-cache dependencies, but it does not reset conditions. Some inherited conversions can conservatively mark the shared object uncacheable (tree counting's setter is unconditional); that may suppress insertion and does not reopen it. Fresh defaults in separate style, animation, declaration or initial-value computations are lifetime boundaries, not permission to erase the current resolved style's exclusion. The source trace makes no claim about an older historical pipeline that might have had an inherited/reset reset boundary.

The visited cascade borrows the same conditions object while using no rule-cache lookup; its own dependencies can add restrictions, not clear the unvisited ones. Cached-reset reuse skips reset conversion, then explicitly marks the result uncacheable before returning, avoiding insertion with incomplete freshly collected conditions. Style adjustment which modifies reset structs also sets the exclusion. The final insertion is consequently not rescued by a later safe property or visited conversion.

This does not repair a stale entry already admitted by another producer: correctness still requires every producer of element-dependent reset values to register the necessary exclusion or matched key. The sibling-count change closes its identified producer omission. This audit does not establish universal dependency completeness, correctness of arbitrary assignments through the public context reference, custom-property provider semantics, or browser cache-hit provenance. Existing style sharing and tree-counting caches remain distinct.

`Accumulation.lean` models an append-only stream of relevant reads, classifying each as covered by valid cache conditions or untracked. Five claims prove initial blocking survives all later reads, concatenated computation composes, an untracked read blocks admission, admission implies no such read in the collected stream, and a blocked earlier segment cannot be reopened by a later segment. The explicit semantic premise is that every reset-result dependency has been collected and every `covered` classification is justified by a matched input or context invariance. The theorem does not supply that premise. It models only the exclusion gate, not numeric values, matching keys or all reasons insertion can be rejected.

Two rejected controls demand that a later covered read clears an earlier exclusion, or that a fresh empty computation is interchangeable with one containing an untracked read. The latter demonstrates why resetting the object mid-computation would invalidate the argument. Actual isolated replay `efc2a8/0` checked five claims and rejected both controls; scratch was removed. The initial `f73047/1` attempt had a proof simplification error and used Lean's reserved word `prefix` as a binder; its log is retained and is not successful evidence. Final source has no warnings or sorry axiom; canonical coverage increment is zero.
