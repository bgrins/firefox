# Sibling-count reset-rule cache hypothesis

The source supports a precise preexisting cache omission, exposed by the contextual easing candidate. This is not yet a confirmed root-cause attribution or accepted native fix. Original-browser ordinary-property evidence and a candidate comparison remain necessary. No native source, build, browser, index or canonical state was changed by this review.

The candidate's two failing callbacks are the static `steps(sibling-count())` cases for animation and transition timing. Each callback retains nine observations. The third target, under a different parent, receives counts 2→3→2 instead of its own 3→4→3; the two first-parent targets match throughout. Literal references, topology, repeat reads and no-animation controls pass. Other index-based static easing cases passed. The raw failure messages establish wrong computed values, not a particular native cache hit. Root separately owns restoration and archiving.

Three mechanisms must be distinguished:

1. `have_shareable_element_dependent_functions` checks `USES_SIBLING_COUNT` and rejects style sharing across different parents. Sibling-index rejects sharing outright. No missing cross-parent guard was found here.
2. `TreeCountingCaches::get_or_compute` keys count by the opaque parent node, separately from index keyed by element. No count-key alias was found here.
3. `RuleCache` caches reset properties by rule node plus `CachedConditions`. Those conditions track font size, line height, writing mode, color scheme, zoom and an appearance-subtree flag, but no sibling count or parent identity. `Context::query_sibling_index` marks rule-cache conditions uncacheable; `query_sibling_count` only sets the computed-value usage flag. A computed sibling-count reset property can therefore enter the rule cache and be reused under another parent.

`Cascade::try_to_use_cached_reset_properties` copies cached reset values and skips applying the relevant declarations. It copies the sibling-count usage flag too; retaining that flag does not correct the value or force recomputation. This explains how the reset-rule cache can bypass an otherwise correct style-sharing rejection. The saved activation cascade retains this path. New easing support exposes another reset-property consumer, but the cache omission is already present in immutable original HEAD 182db9b1 and upstream source.

The minimal artifact proposal adds the existing sibling-index `set_uncacheable()` operation to `query_sibling_count`. It prevents insertion of reset results depending on count, conservatively forgoing caching even for same-parent or fixed-scope-default cases. No performance claim is made. Adding a correctly scoped count/parent cache condition would be a separate optimization. Changing style-sharing checks or the tree-counting result cache would not address this path.

The ordinary probe owned by typed_demand_review is `css-sibling-count-cross-parent-probe-v1`: width and opacity test reset properties; font-weight supplies an inherited-property contrast; each has count and index forms. Equal computed parent styles, direct-DOM topology, literal references and width geometry calibrate the observations. Prediction: count width/opacity can reuse the first parent's value, while index forms and inherited font-weight should compute correctly. This remains a prediction until root executes the original binary. The probe does not require contextual easing admission and cannot by itself identify a cache hit.
