# Typed attribute substitution needs the consuming context

The smallest sound direct-route repair must retain the nested attribute expression until substitution can use the consuming property context, or cache a result keyed by that context. Copying animation-taint metadata alone cannot repair the observed source route: it has already replaced the nested `var()` and discarded its fallback. This is a design obligation on frozen corrected proposal V2, not a native patch or a browser outcome. The dependency-walk analysis includes the held branch's fallback-aware resolution redesign; independent applicability to the committed provider is not established by this note. Native session 46619 and all live sources were excluded.

## Concrete discriminator

Use `data-v="var(--v, vertical-lr)"`, active unregistered `--v: horizontal-tb`, and `writing-mode: attr(data-v type(<custom-ident>), vertical-rl)`, with parent writing-mode vertical-rl. Under the direct ordinary-property interpretation, the nested var guard rejects the animation-tainted value and chooses **vertical-lr**. Horizontal-tb matches the tainted token; the output alone does not prove the internal admission route. Vertical-rl means the outer attr fallback or inheritance was selected; it does not demonstrate correct nested fallback. Typed's separate observer supplies the actual fixture; this package adds no runner.

The primary-text chain is retained in the sealed typed-attr spec follow-up: Values 5 Appendix A starts property substitution with the property context; typed attr step 6 adds an attribute guard and substitutes the attribute text; Variables 1 replacement step 3 rejects tainted input in a non-animatable property, then step 4 uses its fallback. This is conditional on interpreting “being used in a property” through the retained outer context; the text does not provide a separate formal selector for that phrase. It is not a complete getter/scheduling proof. See [Values 5](https://drafts.csswg.org/css-values-5/#attr-substitution) and [Variables 1](https://drafts.csswg.org/css-variables-1/#replace-a-var-function). Our indexed query failed with a read-only database error (retained log); the sealed follow-up supplies the manual primary trace, not a claimed successful index query here.

## Exact frozen route

`ComputedSubstitutionFunctions.attributes` indexes namespace and name. `insert_attr` / `get_attr` have no consuming-property key. `get_attr_value_for_cycle_resolution` reads and parses raw attribute text for the dependency walker. The walk shares its custom/attribute branch and gives both `Some(PropertyIdRef::from(name))`; for an attribute, that is a custom-property-shaped context from the attribute name, not the eventual writing-mode sink.

`substitute_references_if_needed_and_apply` likewise uses that context. Its attribute branch constructs a resolved universal value and copies attr-security taint but not animation taint. Later, the typed Attr arm of `substitute_one_reference` obtains cached `.to_variable_value().css` and reparses it with the actual property_id. That second conversion also loses animation provenance. By this time an admitted nested var has become a keyword: the original inner fallback is unavailable.

The final animation-taint filter is restricted to Var references. Merely adding Attr to that filter, even after preserving metadata, would reject the entire cached value and choose vertical-rl. It would not reconstruct the required vertical-lr branch. Conversely, only fixing the two metadata copies leaves direct inner substitution in the wrong context. These are separate issues.

The existing unresolved custom Var path deliberately evaluates its referenced custom value with `suppress_animation_taint_sink=true`, then applies the caller's filter. Preserve this distinction: a direct typed Attr must retain the caller's context; a custom Ref computes its primary in custom-property context. In the alias-through-attr case, whether animation provenance must cross the fetched-text bridge remains separately INCONCLUSIVE in the primary trace. The direct decision does not settle that policy.

## Minimal implementation obligations

1. Retain a raw parsed attribute expression (or equivalent recoverable reference/fallback structure), not just final CSS tokens. Evaluate typed attr text under the caller's property_id and suppression mode before typed parsing. Adding an attribute-cycle guard must not replace the outer property context. Keep the existing custom-reference context transition.
2. Alternatively cache evaluated attribute results per real substitution context. A single non-animatable bit is not established as a sufficient key: property_id already enters typed parsing and held-provider attr/context semantics. Cache validity also needs current custom-value/provenance dependencies and attribute contents. A final-value cache independent of context is disproved by the model discriminator.
3. Integrate dependency/cycle handling before adding recursion. The current SCC walk precomputes attr nodes; its fallback reachability was decided under custom context. A newly rejected var can activate a previously unchosen fallback. A consumer cannot safely assume every dependency in that fallback is already resolved. `SubstitutionState` presently tracks custom names/cyclic names, not an expanded attribute guard stack. Re-evaluating raw attrs naively would introduce recursion without the existing attr-cycle guarantees.
4. Preserve AttributeTracker invalidation, namespace/target identity, URL data, serialization boundaries, and attr-security taint independently of animation taint. Return owned substitutions if the raw parsed input is temporary; existing substitution lifetimes may borrow its text. Preserve ordinary registered/default/CSS-wide behavior rather than silently routing those cases through a universal-value shortcut.
5. Keep raw-string/unit attr branches separate; they do not follow this recursive typed route. Container-query handling already bypasses the populated cache and has a documented chained-attr limitation. Namespaced chained refs also have an existing TODO. Neither is solved here. No security issue is inferred.

This is not a two-line flag fix. The smallest plausible implementation experiment is a consumer-context typed-attr evaluator with preserved raw structure, explicit attr guards, and a dependency handoff that can resolve the newly selected fallback. It must first demonstrate direct inner fallback, untainted and literal controls, custom-alias boundary, parse failure choosing outer fallback, attr cycles and fallback dependencies. No native patch is proposed before those ownership/dependency details are resolved.

## Formal boundary

The separate `css-animation-taint-attr-context-model-v1` extends the earlier AliasGuard idea with an Attr constructor that retains context, while Ref resets only its primary to custom context. It checks arbitrary finite nesting and the cache/blanket-rejection counterexamples. The input-selection model can express a cache certification premise that includes context, but cannot establish that native cache keys or invalidation satisfy it. Neither model refines CSS parsing, native SCCs, scheduling, inheritance, registered defaults, or the unresolved alias-through-attr infectious-taint policy. There is no canonical coverage increment or acceptance claim.
