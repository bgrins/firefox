## Recovery

Install saves one LOCAL-PRE control set in its output directory for recovery, not repeated committed snapshots. Small hash references are the publication payload. On installation failure it removes only owned new test files, restores the exact source preimage, verifies semantic prestate and untracked census, reconciles only observed raw-index drift and restores OWNED/epoch. An unknown rollback failure retains the transition lock and records manual recovery required.

Signing failure with unchanged HEAD is verified against the installed pending state, exact file hashes, full untracked census and controls; the real index remains untouched and the lock is released. Interrupted/unknown/post-HEAD failures retain the lock. There is no automatic signing retry or automatic native acceptance. Existing log names use exclusive creation, so any explicitly authorized later retry requires a reviewed successor/output decision preserving failure evidence.

The app is never rewritten or claimed rebuilt. After success it still has the restored prior accepted build. If root later wants the installed app to contain MinMax, that is a separate actual build obligation.

Commands for a future enabled, sealed successor are `python3 -I -S -B run.py install MANIFEST` and, after actual delivery checks and fresh successor bindings, `python3 -I -S -B run.py commit MANIFEST`. `check` only authenticates payloads/helpers and syntax; it is not a live state admission check. No mode has been executed during preparation except this read-only static check.
