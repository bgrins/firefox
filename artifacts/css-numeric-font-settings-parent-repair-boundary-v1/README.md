# Prospective parent-metric conversion boundary

Source analysis only, pending the calibrated browser probe. No native patch, new waits, build, browser execution, or accepted bug is produced here. The strongest initial target is ordinary `font-variation-settings` with a `wdth` number containing an em/px ratio. Feature settings are separately disputed as potentially shaping-only; do not silently enable a broader property category on the strength of that first case.

The smallest principled boundary is **the actual selected property's specified-to-computed conversion**, carrying a scoped metric-base policy down to numeric length leaves. It is not the generic Number/Integer default and not the font scheduler. Exact e86 `Context` has no selected-longhand or numeric metric-base field. `Leaf::to_computed_value` hardcodes both bases to CurrentStyle; `NoCalcLength::to_computed_value_for_math` already accepts explicit `FontBaseSize` and `LineHeightBase` and dispatches each unit appropriately.

Two actual property conversion entry points must be covered: generated `cascade_property` in `properties/helpers.mako.rs`, and `AnimationValue::from_declaration` in `properties/helpers/animated_properties.mako.rs`. Both directly call the specified value's `ToComputedValue`. A change only in `Cascade::apply_one_longhand` misses animation/keyframe conversion. Conversely, changing generic Number or CalcNumeric globally would alter unrelated properties such as ordinary numeric expressions outside the font-affecting category.

A concrete implementation option after reproduction is a private, scoped numeric-font-base override in `Context`, defaulting to CurrentStyle, with one property-policy helper shared by those two conversion entry points. Around the actual selected variation value's conversion only, select `(FontBaseSize::InheritedStyle, LineHeightBase::InheritedStyle)`; restore the old override on exit, including unwinding, using the existing `with_registered_value` reset-guard pattern. Have the numeric `Leaf::Length` path consult that override rather than embed a property test. This is a proposed interface, not implemented or typechecked code. An explicit base parameter threaded through CalcNumeric/Number is an alternative, but the existing `ToComputedValue` trait does not carry such a parameter and needs an equally complete call-site audit.

Do not infer property identity merely from `FontSettings<T>`: the same specified aliases have @font-face parsing paths. Exact descriptor parsing rejects unresolved contextual numeric expressions, but that is not a license to change every generic use or future caller. Ordinary property identity is available at the two generated entry points. CSS-wide inherit/initial paths that copy existing computed values do not need fresh leaf conversion. Registered custom-value computation, media/container evaluation, and other specified-value conversion calls must retain their own policy. Constrain the scope to the native conversion call rather than leave a persistent field set for the next longhand. Keep selected cascade `scope`, element context and cache conditions unchanged.

## Unit-specific preservation

| Input | Existing reusable branch | Required preservation / remaining control |
| --- | --- | --- |
| `em` in numeric variation settings | `FontBaseSize::resolve(InheritedStyle)` reads parent font size and applies effective inheritance zoom | Parent/child differing-size probe is the first concrete discriminator; retain existing zoom operation, do not substitute a fixed px result |
| `ex`, `ch`, `cap`, `ic` | Existing inherited base reaches `Context::query_font_metrics`, parent font and inherited writing mode, with inherited-metric dependency flags | Preserve full font query and cache effects; query-font-metrics' comment that inherited mode is only used for font-size would need updating if expanded |
| `ch` fallback | `zero_advance_measure_or_default` additionally receives current style's upright bit | Do not claim the two-base switch proves all writing-mode cases. Parent/child differing orientation and unavailable-metric fallback need their own source/spec calibration |
| `lh` | `LineHeightBase::InheritedStyle` selects parent font/line-height in `StyleBuilder::calc_line_height`, including inheritance zoom | Its explicit writing-mode argument still comes from the caller; parent/current orientation policy needs review for normal line-height before a full-unit claim |
| `rem`, `rex`, `rch`, `rcap`, `ric` on a non-root child | Existing helper uses device root values, not the passed local base | Preserve these branches. They must not become parent-relative merely because the property is font-affecting |
| Those root units on the root itself | Existing root branch uses the passed base; StyleBuilder's inherited style falls back to default computed values when no parent exists | Inherited base naturally uses the initial/default font path. Test root vs descendant explicitly; no proof of all default-font preference interactions here |
| `rlh` | Root case uses the selected line-height base; non-root case uses device root line-height | Preserve the root special case, zoom and media-query branch; do not change every rlh to parent line-height |
| Absolute lengths | Existing absolute branch applies effective zoom, except canonical registered-value mode | Both numerator and denominator must retain existing math conversion; do not clamp/normalize intermediate leaves earlier |
| Viewport and container units | Separate `to_computed_value_for_math` branches independent of font base | Keep viewport/container lookup and flags unchanged. `vi`/`vb` currently use current writing mode and a cache dependency; a font-base override must not redirect them to parent writing mode |
| Tree-counting/random leaves | Separate calc leaf branches using the same Context | Preserve selected scope, deterministic seed/key behavior, dependency flags and cache writes; no early precomputation under a fabricated parent Context |

The existing helper already separates inherited font/line-height choice from root, viewport and container semantics. Replacing the whole Context with a parent builder would lose that separation and also corrupt element/scope/cache authority. The current draft's parent rule is qualified by the element a unit refers to; non-root root units still refer to the root. The proposed override changes only the existing base parameters, not that dispatch.

## Every entry and effects

Leave `FontSettings::to_computed_value`'s map/collect-before-dedup order intact. Do not deduplicate specified entries, skip losing numeric entries, or use a preview evaluation to discover dependencies and then evaluate again. Each entry converts once under the selected scope and chosen policy; only afterward does stable sort/last-wins dedup run. Number/Integer normalization, rounding, clamping and non-length calc branches remain unchanged. The sealed queue model establishes that abstract preservation contract, not that native conversion or the proposed policy has been implemented correctly.

Parent metrics remove the demonstrated reason to wait on the child's own font size/metrics for these leaves; they do not prove any global dependency edge removable. ASTs can still read root metrics, viewport/container state, tree scope or random seed. Any future retained numeric producer needs selected-AST demands and exact input finality, not all-font waiting. Palette/emoji remain independent scanner-versus-metric-demand questions.
