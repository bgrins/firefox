# Pre-publication size finality obligations

This is the implementation review for an experimental source checkpoint, not a native correctness certificate. The stored ComputedSizePublicationWitness is an additional misuse check. A mismatch cannot repair a consumer; its equality is not the construction argument.

The implementation invokes the real generated cascade setter and existing hooks. It does not replace FontSize conversion, quantization, keyword composition, font-metric queries or system-font resolution with numeric arithmetic. Its readset decision distinguishes parent keyword metadata and inheritance zoom, and selects Family only where later keyword conversion can affect the result.

The flag allowance is conditional on construction: FontSize/XTS and any retained Family record flags of every declaration actually visited by the selector, including skipped entries and entries reached after dynamic rollback. Any visited currently-ineligible Appearance entry blocks early publication; an unvisited lower entry cannot displace the selected winner. Already completed Family requires Appearance completion. Other finalized inputs use the existing static prefix proof, with full-chain exclusion still conservatively required for writing-mode inputs. Removed flags and other additions fail the certificate. Merely invalidating a post-consumption certificate is not counted as correct handling: the guards (both before and after ordinary recursive prerequisites) prevent replay/unchecked skipping and expose an implementation invariant failure. All valid future native steps still need to follow the ordering/no-op argument above.

Parent/root/device reads are not proven immutable by a pointer. The immutable inherited ComputedValues supplies parent font, size/keyword information and line height; actual parent metric conversion uses that font, while ch fallback and lh also read the now-final child writing mode. Root length branches use parent/default fallbacks while computing the root itself. For descendants, root style/size/line-height writers are in matching's post-cascade publication; root metrics lazily query that stored root style under its lock and retain native usage tracking. Searchfox discovery:5ba3bf,5dd4b7,3b2033,fd6c17,63c435,914fc7,893428. The draft keeps those native calls rather than caching fabricated numeric substitutes. A comprehensive cross-thread/font-loading and container/viewport lifetime proof is not supplied here; source correspondence for those inputs remains a review obligation before a broad finality claim.

System FontSize still enters the generated cascade_property path, which calls resolve_system_font before ToComputedValue. Its native cache and FFI computation are not inferred from the enum alone. Keyword/Math operations still run did_apply_prioritary_property. Full computed::FontSize equality in the witness also includes used-size metadata; a later harmless used-size change may conservatively fail this guard even when em's computed_size is unchanged. This needs native validation and must not be described as full CSS progress.

Actual semantic custom-property/FontSize cycles remain distinct from unresolved native prerequisites. The draft does not turn Pending into invalidity. Dynamic writing-mode/other prerequisite continuations and nested dependency actions remain explicit remaining scheduling work; these are not permanent exclusions from intended supported CSS.

Focused current controls: actual selector/provider extraction passes 22 positives and 13 compiled failing mutants. New controls retain optional Family replies without reparse, rollback-to-absence, lower-unvisited versus higher-skipped/revert-reached Appearance, and actual LengthUnit child-orientation classification. These do not execute the native Context/application hooks; the numeric family parser remains an explicitly limited selector test facade. The calc classification uses the actual AST traversal API but that full AST traversal is not exercised by this extraction. Full native compilation, integrated action routing, real 16px→13px generic-family compatibility and browser observations remain required.

Additional exact native minimum hook evidence: Searchfox f57e2c/ad6952, Gecko_nsStyleFont_ComputeMinSize: zero-size/MinFontSizeEnabled short circuits, otherwise GetFontPrefsForLang(GetLangAtom())->mMinimumFontSize multiplied by mMinFontSizeRatio. This explains the retained XLang effect dependency.

The minimum-size ordering is not a claim of complete used-size equivalence for every pre-ensured combination. In particular, an already-ensured ratio does not replay its hook; omission has no ordinary FontSize hook. Integration must exercise the actual native ordinary schedule with minimum-size preferences, language changes, explicit/omitted size and zoom, checking used-size as well as computed-size. The prerequisite preflight rejects externally claimed/active inputs before consuming retained selections. The subsequent local static ratio application has no generated dependencies and must complete; it cannot silently fall through after partial Family effects.

Source-bound browser controls must include both the 15 historical original failures in ORIGINAL-TARGETS.json and the independently observed passing System Firefox controls. Known compatibility: parent medium/serif16px + child monospace gives13px for omission/inherit/unset/100%/bare1em but16px for calc(100% + 0px)/literal16px. These are native compatibility controls, not newly accepted bugs. The 48 first-read/mutation cases in css-font-input-dependency-browser-probe-v1 are preservation evidence on System Firefox only; this candidate has not run them.
