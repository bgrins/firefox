# Integrated retained attribute and computed-size selection

This experimental three-file candidate combines the sealed attribute root-entry and computed-size-selection-v2 implementations. It preserves the published u32 declaration index. It has passed extracted-source checks, but has not been compiled against native Stylo or run in a browser. It is not an accepted native fix.

The common parent is css-resumable-font-selection-caller-v2. MERGE.json records the disjoint common-parent edit ranges: 24 attribute ranges and 44 size ranges in cascade.rs, with no overlap. The resulting source is their exact union; no manual production edits followed the merge. Provider and properties/mod.rs retain the attribute parent's bytes. BSD diff3 failed internally with “invalid print range”; MERGE-DIFF3-FAILED.json preserves that attempt. The saved checker independently reconstructs the successful disjoint-range union.

SOURCE-ROLES.json binds the published base, common parent, both completed parents and candidate. ATTRIBUTE-DELTA.patch and SIZE-DELTA.patch independently reproduce the integrated candidate from either completed parent. native.patch applies to the three published u32 base files. The three copied parent patches preserve the attribute step and both size-selection steps; the size-v2 parent patch alone is not cumulative from caller-v2.

The merge keeps the attribute parent's exact action authorization, owned PropertyId, invocation guards, per-context attribute input handling and retained custom-root engine. Authorization permits evaluation to start; it does not certify that references are complete. The size parent's ComputedSize target retains FontSize, XTextScale and optional Family selection through that same lookup/action path. Visited-prefix flags, actual selected-operation readsets and separate computed-size publication remain intact. Scheduling waits do not become CSS invalidity or whole-property completion.

## Required native and browser validation

ORIGINAL-TARGETS.json is copied exactly from the size parent: the historical core contains 15 original failures and six original passes. The historical f0d candidate passed all 21, but that result does not apply to this integrated candidate. PRESERVATION.json also binds the separate System Firefox 48 first-read observations from css-font-input-dependency-browser-probe-v1. Those observations compare registered lengths across six consuming properties, four forms and two sizes. They do not assert every consuming property's result, and stylesheet replacement is not isolated attribute mutation. No fixture, expected status or historical raw result was changed here.

A new source-bound native check must overlay all three roles, require Cargo build-finished success plus style/geckoservo library artifacts, and restore the original sources and application. Mach exit zero alone is insufficient. Subsequent browser validation must preserve the original six passing cases, address all 15 historical failures, and run the independent passing controls against the actual merged binary. No native acceptance follows from these extracted checks.

SIZE-WRITE-SET.md preserves the size parent's effect-order and finality obligations. In particular, minimum font preferences, language changes, omitted size, pre-ensured minimum-ratio and Family/XTextScale effects require actual used-size/geometry checks as well as computed-size checks. The stored publication witness is a misuse guard, not a proof that all future writers are harmless. Parent/root/device, font-loading and container lifetimes remain native correspondence obligations. Keyword-family compatibility and actual calc-tree conversion require source-bound validation.

The legacy seen.attr sweep and synchronous non-priority consumers remain outside the completed retained route; there is no global once-only DOM-query claim. Nested dynamic prerequisites and genuine feedback cycles still need complete progress/policy handling. Existing terminal assertions expose unsupported progress; they are not acceptable shipped handling of ordinary valid styles. This merge retains those limits rather than waiving readiness. Deep fallback copies and guard-chain scanning also retain the parent performance limitations.
