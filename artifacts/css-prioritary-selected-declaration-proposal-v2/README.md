# Selected prioritary declaration experiment

This one-file committed-base-relative prototype addresses dependency edges from overridden declarations. It is separate from the selected-color/image proposals. The captured preimage is cascade.rs 2cc7b3d4; the formatted postimage is 2e2daeeb. Installed Firefox's nine-case probe has five target failures and four passing controls; Chrome passes all nine. Those observations motivate the experiment, not a result for its native patch.

The prototype shares the existing seen/flag/rollback eligibility helper and the priority linked list with ordinary application. A reached variable candidate's dependencies are visited while its SCC is active. The substituted declaration becomes owned before further graph visits. Its forced-color adjustment and deferred entries are retained once; the completed rollback chain is committed without resubstitution or another adjustment. Origin/layer/rule rollback uses the existing allows_when_reverted predicate. An evaluated candidate that produces rollback contributes its reads; a never-reached lower declaration does not.

Rejected V1 promoted every generated computation prerequisite into a semantic cycle edge. V2 removes that promotion and keeps the base LineHeight-to-FontSize edge. It restores generated scheduling ensures at commit. Added graph edges represent selection inputs: Appearance only for a reached candidate missing APPEARANCE_BASE but otherwise eligible, and ForcedColorAdjust only for a reached author's non-CSS-wide declaration that the forced-color adjustment can change. Exact admitted metadata has ColorScheme as the only ignored-when-colors-disabled prioritary property. The current-set contract is checked; adding another such property requires reviewing its actual adjustment reads.

Candidate selection does not permanently skip a missing Appearance flag: it resolves that input where the candidate is reached and reevaluates eligibility. Seen, rollback and other missing flags are checked first. STARTING_STYLE is an external input; admitted flags contain only it and APPEARANCE_BASE. Earlier winners stop before lower Appearance candidates. Generated scheduling at commit retains the base behavior; it does not prove every computation dependency is represented by a semantic edge.

Backedges/lowlinks and unresolved stack suffixes prevent premature substitution. Cyclic priorities discard staged chains. Their existing invalid-priority wrapper runs only after the whole SCC is popped; literal members retain its existing literal behavior. Non-prioritary attribute preparation stays unchanged; prioritary attributes are discovered from reached reference walks. Monotonic cache flags remain part of substitution; deferred forced-color entries are published once at commit.

Peer review found no new concrete blocker in the narrower V2 delta (255340); bb1820 confirms the current metadata read contract. This is a coherent experiment pending real Stylo type checking and native browser validation, not an accepted fix. Rustfmt parsing and exact patch forward/reverse passed dc223a, with owned scratch removed. No native build, browser, Git, app or canonical-state operation was performed by the author.

An inherited scheduling boundary remains explicit: a generated ensure after an acyclic priority pop can evaluate against an active custom ancestor (for example Zoom consuming custom 1em while FontSize is pending). V2 restores that scheduling rather than claiming to solve it. Compare original and candidate, and stop acceptance on introduced changes. General contextual-attr repair, taint policy and selected-color/image default closure are outside this patch.

VALIDATION.md distinguishes the observed defect cohort from rollback/selection preservation and source-only once-evaluation checks. The now-empty legacy NonCustomPropertyReferences plumbing is retained in this bounded prototype; cleanup is separate from the semantic fix. The two-stage committed-base patch is self-contained; V1 is generation provenance, not a patch dependency.
