# Winning animated providers: next implementation boundary

The next useful change is a pending custom-property item carried by the real animation rule, admitted by the existing cascade winner gates, and resolved by the cascade's dependency walk. Calling the new endpoint FFI with an already completed style does not implement this change. The current normal producer still clones cached AnimationValues and the owner still eagerly materializes them into declarations.

This is a source-level implementation proposal, not a patch, executed experiment, or new fix. SOURCE-PINS records the seven locally modified bodies inspected while the provider host build was active. No live sources, indices, library, build outputs or test destinations were modified. REFERENCES authenticates the complete existing resolver, policy and ten-case diagnostic capsules. Their normative qualifications are retained; no new specification decision is claimed.

## Observed target

The unchanged ten-case diagnostic samples the provider at 250, 750, then 250 ms and the consumer at 0, 500 and 1000 ms. Consumer reads precede the provider calibration read. In the four previously measured dynamic cases, the red phase retained [20, 25, 30] for both consumer reads. The fixture's justified target is [10, 20, 30]: red is present but invalid for the registered numeric consumer, so that endpoint defaults to the consumer's initial 10 before interpolation with 30. An authored var fallback does not rescue a present value's numeric type mismatch. Both creation orders must work. This source proposal adds no runtime observation.

The new callable resolver supplies the endpoint-level defaulting operation, but its complete provider snapshot is currently supplied by its caller. The remaining fault is supplying current winning providers during normal animation sampling, not another numeric interpolation formula.

The compact `StyleSource` owned/borrowed representation need not grow. A new iterator item is transient; its sampled branch can borrow the owner and retain a `SampledAnimationProperty` when admitted. Existing longhand records continue carrying the original concrete PDB. Any source consumer that treats `get()`/`clone_declarations()` as the complete set of custom declarations needs an explicit audit: the current compatibility PDB cannot silently become an exhaustive pending-value representation.

## Smallest faithful interface contract

The following are proposed interfaces, not compiled Rust declarations:

* `CascadeItem = Concrete(&PropertyDeclaration) | SampledCustom { name, owner, root }`. Property identity is independent of a value. A property must occur once per sampled source, never as both a concrete companion and a pending entry.
* `WinningCustom = Ordinary | Pending(owned_root) | Resolving | Ready`. The ready computed-value map and pending winner table remain separate. The scheduler, not an endpoint-local map lookup, decides which state supplies `var()`.
* `resolve_endpoint(retained_declaration, current_registration, scheduler_context) -> endpoint_result`. The context has current target/pseudo, parent/font/container state, original URL/namespace provenance, prepared typed attributes and access to the same provider-resolution guard chain. Registration is looked up at this sample, not captured with the cached keyframe.
* `endpoint_result` distinguishes a computed endpoint, genuine CSS-invalid/defaulting work, cascade-selection work and internal unsupported/error states. A genuine invalid endpoint can resolve to the registered initial/inherited value through the existing rules. An internal error cannot produce that value, return the cached endpoint, drop the declaration or panic.

The initial safe implementation chunk is the source-item/winner-table plumbing with the producer still disabled. Tests must enter the actual rule-tree iterator and cascade gates and prove an important/reverted/already-seen winner prevents pending admission. This is preparation only; it does not repair the four failures. The first repair experiment must connect **all three** producer, winner admission and dependency resolution through the ordinary animation rule path. A host test that passes a prepared provider ComputedStyle to the existing FFI is insufficient for that gate.

The tested operation arena remains responsible for Add/Accumulate/interpolation and their native fallbacks. It is not a provider scheduler. Preserve earlier same-property roots for additive/implicit operands, the existing no-animation base route, and complete replacement semantics. Do not replace a pending earlier root with `mBaseValues`. The current cached-base provenance and the final winning provider context are different contracts; this proposal does not assert a new dynamic implicit-base oracle.

## Blocking contracts before enabling normal producers

1. **Resolver re-entry and context effects.** `Servo_KeyframeEndpoint_ResolveRegistered` creates an isolated context from a completed ComputedStyle; `KeyframeEndpoint::resolve_registered` consumes its context. Neither accepts a request to resolve another pending winner. A scheduler-aware internal resolver must perform dependency requests before token substitution and preserve the shared substitution guard chain while keeping temporary endpoint results out of the final provider map. Repeatedly invoking the current fresh-context FFI during traversal would lose that chain. The existing no-publication extraction can help, but it is not pure: style flags, attribute tracking and cache conditions must be returned/merged deliberately.
2. **Complete endpoint admission.** The current resolver explicitly rejects Parsed declarations, unregistered endpoints and revert variants. Registration can change after descriptors were retained. Do not assume a descriptor remains a registered numeric recipe merely because it was one at construction. Supporting all requested cases requires original retained declaration semantics plus current registration/cascade handling; producer admission cannot turn unsupported states into CSS invalidity. Non-custom operations and explicit concrete values remain the native concrete route, rather than a fallback after a failed recipe.
3. **Animated cycles.** The retained policy trace establishes current-provider ordering and ordinary defaulting, but not blanket final-property SCC defaulting for mutually animated endpoints. Existing `substitute_all::handle_loop` defaults an ordinary custom property. Reusing it unchanged for an animated root chooses a new invalidation owner without justification. Keep endpoint computation, property publication and same-property stack prefixes distinct. An unresolved-policy result cannot escape as a production value; this prevents enabling the full producer today, not permission to reject cyclic CSS in a shipped repair.
4. **Computation scope.** Arena reachability is numeric reachability. Web Animations computes keyframes before interval selection. Pruning an unused endpoint or replaced lower numeric root is not proof that its substitution/cycle work is irrelevant. Conversely, unused var fallbacks must remain short-circuited. Retain per-effect keyframe computation identity/scope in addition to the selected arithmetic root before claiming complete semantics.

These are concrete API/semantic blockers to a full runnable repair, not reasons to insert a cached Parsed companion. No patch is supplied because enabling the current resolver at the producer would violate at least the first two contracts, and choosing an animated cycle result would invent a policy.
