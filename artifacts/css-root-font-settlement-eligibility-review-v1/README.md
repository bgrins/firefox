The existing pending-animation queue cannot safely identify a font-only acyclic settlement domain. A targeted ordered implementation is conceivable, but a guard such as paused + font-size + pending is not supported by the current metadata. The smallest useful domain matching the witnesses is a fixed finite parent/root-dependent font chain with stable effect definitions and timing; proving membership requires information that is not carried into the queue.

This read-only review uses exact e86 objects, the sealed selective/trace source capsules, and the sealed wave model. SOURCE-EXCERPTS.json records hashes and exact excerpts. Searchfox discovery covered EffectCompositor::RequestRestyle, KeyframeEffect::UpdateProperties, animation/property headers, and matching.rs; conclusions use local pinned bytes because e86 includes additional attribute-provenance handling absent from upstream discovery. No live source, queue, browser, Git index, or publisher was modified.

RequestRestyle does not retain the requesting effect, property, dependency reason, endpoint version, or parent generation. An implementable *candidate domain*, not an existing predicate, could initially require: ordinary fixed-tree element targets; a stable absolute-pixel root/provider; one effective replace-composed font-size animation per node, explicit endpoints restricted to identical primitive em or rem declarations; resolved fixed progress with no pending timing operation; no missing endpoints, additive/accumulating effects, competing transition/animation, custom properties, attr(), calc(), container/font-download-dependent metrics, or style changes to animation definitions during the settlement. em dependencies point to the inheritance parent, rem to the selected root. Nonanimated fixed-font intermediates are provider nodes too. Root-relative font-size on the root itself must use its separate initial-metric rule; excluding that case initially avoids assuming the pending root-identity correction. Pseudos need the exact normalized host/pseudo identity and provider edge, rather than treating a generated node as an ordinary child.

This narrow grammar is sufficient to express the current constant-endpoint chain experiment, but is intentionally not a general CSS eligibility policy. Equal **computed** endpoints cannot substitute for it: 2rem and 4em may coincide for one root/parent pair and diverge after only one provider changes. Restricting all computed properties to font-size still does not exclude specified variables or mixed reasons coalesced into the same target entry. Excluding current transitions does not prove that normal recascade cannot create one. A future targeted path must define what happens if these conditions cease to hold, retaining ordinary invalidation rather than dropping work.

The three conceptual phases are endpoint refresh, selection of an application, and completed style installation. For a parent-only proof, each endpoint must be known to use the current installed provider, every newest endpoint must remain covered by installed/queued/in-flight work, and only actual provider installation changes may invalidate child computations. Existing fields do not establish those invariants: the posted Boolean loses request identity, WillComposeStyle records timing before traversal, and UpdateProperties compares/replaces computed arrays without recording which provider generation was read. The source has a broad animation generation counter, but RequestRestyle advances it for layer work, not specifically for each provider-font installation; this review does not equate it with the model generation.

Consequently, depth ordering alone is insufficient. A candidate would need a bounded classification step over the relevant specified declarations and effective cascade, stable provider identities, and version/phase coverage (explicit metadata or an independently proved equivalent synchronous invariant). It must preserve coalesced unrelated requests and removed-effect cleanup; selecting a target currently processes its effect set, not just one chosen font property. Nothing here demonstrates an existing cheap guard that supplies these facts. A proof for a fixed chain does not authorize restricting all normal CSS processing to that domain.

Recommendation: keep the 16-pass diagnostic observational and use its evidence to decide whether targeted machinery is worth implementing. Do not replace its eligibility with paused/font-size tests or claim the existing posted map refines the three-phase model. The sealed wave model proves a finite schedule only under explicit fixed-graph/function/provider and complete-wave premises. The coalesced three-phase successor was still being checked when this note was written; its premises supplied by its author are design inputs here, not a claimed checked native theorem. Neither model establishes native metadata completeness, creation/cancellation stability, pseudo normalization, or installation coverage.

This note identifies a concrete metadata boundary, not a new patch or runtime acceptance. No source hooks, queue framework, runner, or model extension was added.
