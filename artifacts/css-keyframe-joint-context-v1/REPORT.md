# Disposable native keyframe context

This candidate implements one necessary native completion dependency: evaluating a retained endpoint from an in-progress cascade without first constructing or publishing `ComputedValues`. It uses the real typed-demand resolver and native style structs. It is not a joint ordinary/animated/prioritary scheduler, heterogeneous rule-tree integration, or a fix for the four pending-animation browser histories.

## Native ownership and effects

The existing `resolve_registered` and `resolve_registered_with_pending_context` entry points consume `computed::Context` and return only an `AnimationValue`. They cannot hand a future completion owner the final builder flags and cache conditions. This patch keeps those signatures and behavior routes, extracting borrowed-context internal functions used by both the existing wrappers and the new `resolve_from_cascade` entry.

`StyleBuilder::fork_for_keyframe` copies current substitution state, writing mode, zoom, color scheme, invalid non-custom state, inheritance/root/pseudo metadata and flags. Already-shared Borrowed style structs stay borrowed. Each Owned UniqueArc style struct is cloned into a distinct UniqueArc. Converting an Owned struct to a Borrowed pointer would be unsafe if child `build()` converted it into a shared Arc while the parent retained unique ownership; this implementation avoids that shortcut. A temporarily Vacated style struct prevents the fork and yields `EndpointDemand::ContextPreparation`, with no fabricated default, panic or completed style.

`Context::fork_for_keyframe` preserves the current target/scope and computation modes, uses a fresh rule-cache condition object and tree-counting caches, and recomputes the system-font cache when needed. Container-size lookup remains lazy; its callback may populate the parent's memoized container result. This is isolation of style/attribute/cache-condition effects, not a claim that all device caches or DOM reads are transactional.

`resolve_from_cascade` invokes the exact borrowed pending resolver in the disposable context. Success returns the native AnimationValue and an `EndpointEffects` record containing builder flags, attribute references and cache conditions. Provider/prioritary/unsupported/context-preparation failure returns no publishable effect record. Temporary value maps, style structs and effects are dropped on failure. The caller must retain success effects privately until the whole admitted owner completes; this patch deliberately provides no global completion or effect-publication operation.

## Actual harness proposal

A new normal-compiled `Servo_KeyframeEndpoint_ResolveIsolatedForTesting` bridge calls the real context fork and resolver. It is visible to Gecko/GTest through the existing cbindgen export route; no `cfg(test)` dependency constructor or standalone/mock Rust harness is used. The existing native presentation fixture gains 22 additional endpoint calls using its actual retained descriptors, DOM attribute mutations, registration syntax, ready/missing/wrong-typed providers, nested typed attrs and prioritary font-size requests.

For every proposed call the C++ assertions check native status/demand/value, unchanged parent custom map/flags/font-size/cache-condition state, distinct Owned font-struct allocation, and `ContextPreparation` when the source font struct is temporarily vacated. Failed attempts return no AnimationValue or attribute-effect publication. The old endpoint calls and their assertions remain present. These tests were authored but have not been built or executed; passing root tests from before this patch do not validate them. The tests start from a real animation context seeded from a complete style and force an Owned font struct. They do not yet demonstrate an endpoint invoked by the live middle of a mixed ordinary/animated cascade.

## Minimal unresolved completion boundary

The next owner must handle ordinary accepted declarations, sampled roots and actual PrioritaryPropertyId nodes jointly. An ordinary custom winner may depend on a sampled winner. Conversely a sampled registered length may demand font-size, whose winning declaration may depend on that sampled custom property. A custom-name-only scheduler cannot represent that dependency without falsely declaring font-size ready. Typed attribute resolution can reveal the dependency after parsing current attribute text, so scanning only original endpoint reference flags is insufficient.

The existing `substitute_all_with_pending` owns the ordinary/attribute/non-custom SCC walk and can return typed demands, but its locals are not a suspended graph owner and it can have already changed the disposable computation state before returning. A correct continuation must either retain that graph state or restart from a coherent private snapshot while keeping completed provider identities/effects in one owner. The endpoint context fork here supplies the latter's endpoint prerequisite, not a total ordinary-cascade checkpoint.

A production completion policy must distinguish dependency edges for ordinary computed values, sampled values and endpoint computation contexts; define mixed SCC invalidation; preserve implicit base inputs and all computed-keyframe scope; and merge admitted endpoint watch/cache effects only after all required work completes. Returning an incomplete Result and unwrapping/defaulting it in the existing Arc-returning cascade is forbidden. Pending sources therefore remain absent from the production rule iterator. No blocker is claimed closed merely because the producer is disabled, and the previous collection-interface blocker remains open.

The independently implementable next work is an owned resumable ordinary SCC or a full private cascade checkpoint, plus a real node-keyed ordinary/animated/prioritary completion owner. Native rule-source transport must connect to that same owner and the shared collector; a parallel winner facade or caller-provided winning table does not meet the requirement. Cycle semantics need explicit specification analysis before any activation; they cannot be inferred from this endpoint helper.
