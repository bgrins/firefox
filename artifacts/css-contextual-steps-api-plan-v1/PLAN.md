# Contextual steps(): publication and API plan

The next useful work is a CSS computation/publication implementation, with a separately explicit Web Animations computation policy. Removing the parser guard is insufficient. The newly traced CSS publication gate is also insufficient by itself: a font-only change can rebuild property values without rebuilding the stored keyframe easing. This is source-derived, not a reproduced additional bug.

This advances the existing `css-contextual-integer-prerequisite-design-v1`; it does not repeat NameRepeat, now handled by accepted fix127. Bug 2037743 already covers computed-time easing expressions, including cubic-bezier and linear. A steps-only change cannot close that entire bug. Bugzilla was read through the Mozilla connector; its returned record is retained. No patch, compilation, browser result, new fix count or acceptance is supplied.

## What the API actually promises

1. `AnimationEffect.updateTiming()` invokes [update the timing properties](https://drafts.csswg.org/web-animations-1/#update-the-timing-properties-of-an-animation-effect). Step4 validates easing against the easing-function grammar before step5 publishes timing members. The constructor and keyframe-argument processing also admit easing without requiring a non-null target. A failed update must leave the old timing intact.
2. The inspected algorithm does not select an element, specify an eager computed-value snapshot, or establish a retargeting computation rule. `getComputedTiming().progress` is meaningful for an associated targetless effect, so deferring all computation until target attachment is not a complete solution. Per-keyframe easing and effect-level easing need not have the same eventual contextual contract merely because Gecko currently shares a parser.
3. [Values4 font-relative lengths](https://drafts.csswg.org/css-values-4/#font-relative-lengths) does define initial font/line-height metrics when used outside an element. Thus a genuinely elementless route is not permission to invent a fixed16px font. What remains unresolved here is whether this WAAPI position is elementless even when an effect has a target, its owning document/realm, and when a context-sensitive value is recomputed. [Values5 tree-counting functions](https://drafts.csswg.org/css-values-5/#funcdef-sibling-index) describes an element and tree-scoped reference; its failed-reference zero rule does not by itself establish this API's missing-target contract.

**Verdict:** REACHED for grammar validation and atomic publication; INCONCLUSIVE for the API computation-context/time choice. The old design's statement that no default font rule exists was too broad: there is an outside-element rule, but applying it to this API still needs an explicit integration decision. Ask the standards/implementation owner this exact question before accepting new WAAPI results: “Are effect-level and keyframe easing expressions computed once in an elementless document context, or reevaluated using the current effect target; how do null target, retargeting and getters behave?” Do not silently turn valid-but-unresolved syntax into a permanent TypeError policy or fabricate a target to settle it.

## Source findings beyond the earlier design

Committed source snapshots are from explicit commit `19a313060adbaf6e4817df03bcb965302dff9ef9`, not the working animation prototype. Searchfox independently located the same parser and caller seams. The full source hashes and snapshots are retained; no live epoch equivalence is asserted.

| Seam | Concrete constraint |
| --- | --- |
| specified/easing.rs `parse_steps` | Stores `Integer`, but rejects `resolve()==None`; `jump-none` also rejects every resolved value<=1, including calc. |
| `TimingFunction::to_computed_value` | Ignores Context and calls the context-free helper; Steps unwraps resolve. |
| glue `Servo_ParseEasing` | Takes string/output only, parses transition-timing-function, writes computed output immediately. |
| `TimingParams::ParseEasing`, `FromEffectTiming`, `MergeOptionalEffectTiming` | Return/store computed functions; optional update validates all fields before assignments. The null optional represents linear, not unresolved data. |
| KeyframeUtils array/object processing | Both use the same TimingParams parser; repairing only effect options misses keyframe easing. |
| glue `Servo_StyleSet_GetKeyframesForName` | Has element/style/per-document data, but resolves each keyframe timing without Context before building/grouping keyframes. |
| `needs_animations_update` / `process_animations` | Ordinary font change with equal animation UI data need not queue CSS_ANIMATIONS. Existing animations still receive EFFECT_PROPERTIES during normal processing. |
| nsAnimationManager / KeyframeEffect | CSS_ANIMATIONS builds keyframes and calls SetKeyframes unless JS overrode them. UpdateProperties builds properties from already stored keyframes; it does not by itself reread the original keyframe easing declaration. |
| Servo `IntermediateComputedKeyframe::update_from_step` | Also resolves timing without Context, despite having shared context/base style. Must be repaired or explicitly kept outside the feature gate; do not leave an unwrap reachable in another backend. |

`create_context_for_animation` is the actual reusable CSS bridge: per-document stylist/device, supplied computed style and parent style, rule-cache conditions, container query, element context and tree-counting caches. Supply these real inputs; a dummy ElementContext or discarded dependency output would only move the defect.

## Minimal coherent implementation sequence

1. Split parsing from computation. Keep specified Integer syntax and range policy. Implement a fallible context-free conversion, with output assignment only after success; preserve all existing successful literals/context-free calculations and atomic API failure behavior. Make all current callers explicit. This is safety groundwork, not full API support.
2. In the CSS conversion, compute Steps with `Integer::to_computed_value(&Context)`, then enforce the position-dependent lower bound. Preserve positive integer rounding/saturation from accepted118/121. Reject literal0/negative and literal1/jump-none, but do not use resolved calc<=1 as a parser rejection. Do not discard the specified tree or replace it with a unit coefficient. Leave cubic-bezier/linear admission gates unchanged in this bounded change.
3. Repair CSS keyframe publication in the same change. Resolve timing with the real animation Context before computed-easing grouping. Retain a dependency fact that is independent of the current integer result; an initially unchanged count must still subscribe to future context changes. On a relevant normal style update, request CSS keyframe reconstruction for effects retaining CSS-owned contextual easing; preserve the existing JS-override and retarget ownership rules. A conservative contextual-easing flag can bound this work to affected CSS effects, rather than all animations or every animation-only frame. Export element/tree/font/viewport dependency information to the invalidation path that actually schedules this reconstruction. A temporary Context flag which is thrown away is insufficient. Implement the corresponding Servo backend context route.
4. Resolve the API decision above before widening `Servo_ParseEasing` admission. If computation is a document-context snapshot, pass a real document/device context through constructors, updateTiming and both keyframe forms and retain existing concrete storage; identify the specified serialization rule separately. If it is target-live, retain a specified easing descriptor alongside its concrete cache in TimingParams/keyframes, compute before progress/segment publication, and invalidate on target/context changes. This second choice necessarily touches getters, cloning, equality, retargeting and compositor publication. Never send unresolved descriptors to the numeric/compositor type, reuse the previous count after failure, or infer a target by inspecting the first animated property.
5. Admit the Round candidate only after the selected policy is tested on every previously reachable steps caller. A CSS-only stage can be useful and safe with the API guard still present, but must be labeled partial support and cannot satisfy a claim that all contextual easing APIs are implemented.

The unresolved API choice is a real remaining decision, not a request to weaken the computed-function invariant. No complete universal implementation can honestly be specified from the inspected algorithm without resolving it.

## Small discriminating test matrix

Reuse existing `css/css-easing/{timing-functions-syntax-valid,timing-functions-syntax-invalid,timing-functions-syntax-computed,step-timing-functions-syntax}.html` and `css/css-transitions/parsing/transition-timing-function-computed.html`. The retained committed tests already ask for contextual em/sibling-index counts and calc(1)/jump-none→2. One older test instead rejects `steps(calc(0/0), jump-none)`; retain/report that conflict explicitly and resolve its intended NaN/range oracle before changing metadata. The accepted fix121 number-range behavior is not authority to silently waive an easing test.

Add one focused CSS lifecycle fixture: retain `steps(calc(2 + sign(1em - 16px)), end)` across target fonts16→32→8→16 (counts2→3→1→2), with literal twin and independent font/em calibration. Sample progress0.6, giving literal outputs0.5,2/3,0,0.5 away from discontinuities. Test both an ordinary animation-timing-function declaration and an explicit @keyframes timing declaration while the animation longhands remain identical. This distinguishes correct Context conversion from missing CSS_ANIMATIONS reconstruction. Check same effect identity and getKeyframes easing as well as actual output. Include a pseudo target and sibling insertion variant to expose dummy element context/discarded dependency flags.

For transitions, check computed serialization after context change and a newly triggered transition against a literal twin. Do not assert that changing transition-timing-function retroactively changes an already-running transition: its creation-time snapshot is a different lifecycle contract.

API regression set: existing `web-animations/interfaces/AnimationEffect/{updateTiming,getTiming,getComputedTiming}.html`, `KeyframeEffect/{constructor,processing-a-keyframes-argument-002,setKeyframes,copy-constructor,target}.html`, `Animatable/animate.html`, and shared `resources/easing-tests.js`. Add null-target effect-level and per-keyframe cases, valid context-free count controls, and mixed duration+invalid-easing updates proving atomic failure. After the context decision, add attached→null→different-font-target, document adoption, clone, pseudo target, style change and getter serialization expectations. Before that decision these are explicit diagnostic observations, not invented conformance assertions.

Test literal1/jump-none rejection separately from calc1 clamping; include negative calc, fractional ties, huge values and NaN. No broad metadata edits, fabricated font basis, unrelated Round/held120 installation, per-frame matching, or new harness is needed to begin the CSS stage.
