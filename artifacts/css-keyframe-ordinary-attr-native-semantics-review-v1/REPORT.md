Preparation and evaluation order

Servo_GetComputedKeyframeValues retains the custom-only priority pass. A second reset pass prepares WithVariables values, skipping null blocks and the same pure simulated-computation-failure predicate, then resets before builder.build and final evaluation. prepare_attributes delegates only to Cascade::update_attributes_map. It does not populate decls, apply ordinary declarations, change append priority, or consume the final seen set.

Preparing all WithVariables declarations is intentionally broader than the final retained output: shorthand expansion, duplicate precedence, pseudo restrictions and the display preference can filter results later. The existing evaluator already substitutes WithVariables before those append filters or its eventual non-animatable return. Eager preparation supplies attribute roots rather than making an ordinary property a custom-property dependency. No new ordinary declaration-to-custom edge or output is added. This can do extra provider work for subsequently discarded values; it is not evidence that those values were animated. I found no source mechanism by which the broader preparation alone creates a reverse ordinary-property cycle edge.

Resolver ownership and semantics

Each keyframe constructs a fresh builder and replaces substitution_functions with a new map seeded from base computed custom properties and no attributes. Qualified attribute entries therefore do not leak from an earlier keyframe. The real AttributeTracker survives across keyframes, but contains the element provider and accumulated queried names, not cached resolved values. Its sequential mutable borrowing follows the existing builder-build lifetime and locked declaration ownership; source reasoning is not a substitute for the actual Rust compiler result.

update_attributes_map keys by namespace and name and prepares typed raw token entries, including references inside fallbacks. substitute_all remains the established cycle resolver: it follows a semantic fallback dependency only when the primary reference is invalid, handles nested attr/var references, and resolves the prepared attribute roots after custom roots. A prepared root is not automatically a dependency edge from every declaration. Requested type parsing remains per substitution rather than caching the first type view. Namespace qualification inside attribute text still has the existing bug 2021110 limitation; direct qualified CSS references are a different supported path.

The final real-provider query is also necessary: type() requires both the provider and computed map, while number/unit/raw-string use the actual attribute text. Replacing only the dummy tracker preserves the existing recursive from_declaration/substitute_variables pipeline and its AttrTaint into ParserContext. Valid attr-derived data remains tainted; fallback selection continues to use the existing substitution rules. Neither identical-URL taint cases nor this review establish attribute exfiltration. Distinct inert URL provenance cases and the prior accepted taint suite remain useful comparison controls.
