## Minimal causal hypothesis, still unconfirmed

A request generated by CSS timing updates during the last/second animation traversal can set a pending compositor-table entry to true while skipping the actual PresShell post. If that entry remains pending without an independently reachable restyle root, subsequent seek/updateTiming Layer requests find true and coalesce without posting. Ordinary outline invalidation supplies a root, allowing pending animation work to run. This explains the observed asymmetry with one scheduling mechanism; it is not proven by external records.

Searchfox source already read and rechecked supports the candidate edges: EffectCompositor::RequestRestyle uses LookupOrInsert(false), exchanges the entry to true, and invokes PostRestyleForAnimation only when the prior bit was false. PostRestyleForAnimation returns during Servo traversal or PreTraverse. AnimationEffect::SetSpecifiedTiming requests Layer after changing timing. Animation::SetCurrentTime calls PostUpdate for a genuinely changed time, and PostUpdate requests Layer (fresh d1cd09/0). ServoStyleSet::StyleDocument performs an explicit second traversal; StyleNewSubtree separately uses FinalAnimationTraversal. The exact local matching.rs candidate queues its timing task before the final-traversal return. KeyframeEffect tracks last-composed progress and compares it when deciding whether timing changed.

The boolean table entry is not itself evidence that a PresShell request was posted. However this review has not traced every removal/filter/reset of that entry or every caller establishing a restyle root. Full PreTraverse retrieval was unavailable: Searchfox definition output stopped near its beginning; --get-file failed DNS (164ca5/1), and web raw fallback missed cache. No unread branch is claimed. Source links and earlier exact tool receipts are retained by the prior sampling/task-trace packages. No live unmodified source, Git, app, canonical-state guard or browser action was used.

## Smallest discriminating instrumentation

Instrument only the target/pseudo and animation cascade level, with a bounded per-target sequence number:

1. At RequestRestyle: request type, prior entry bit/presence, new bit, current Servo/pre-traverse flags, whether PostRestyleForAnimation is called; at PostRestyleForAnimation: deferred branch versus actual PresShell post.
2. At StyleDocument/StyleNewSubtree boundaries: entry/exit restyle-root presence and traversal flags, first-versus-second/final pass, and pending entry state after sequential timing tasks drain. At PreTraverse: eligibility/filter decision and exact entry removal/retention. Do not infer these transitions from a frame count.
3. At CSS timing update and the script duration override/seek: animation identity, before/after duration and local time. At WillComposeStyle/ComposeStyle: current progress and last-composed progress, plus whether the target's animation rule/value was regenerated.

The decisive witness would be a traversal-time request setting true without a post, the entry persisting after the last pass, later changed seek/override finding true and skipping a post, and the outline-triggered traversal consuming it and composing. If a post/root is actually present or ComposeStyle runs with .375 yet output stays stale, reject that hypothesis and inspect downstream animation-rule/style caching instead. This is a request for causal instrumentation, not a patch to clear entries blindly, force recursive flushes, or add iteration caps. Preserve the current failure evidence and self-dependency oracle caveat.
