## Finding R1: no complete absolute scroll-range refinement

`StickyRanges.clamped_inner_contained` proves one `moveInside` operation for independently supplied ordered one-dimensional intervals. It is not connected to the source-shaped computation performed by `GetScrollRanges`:

1. `ComputeStickyLimits` and first-continuation normal position;
2. `nsRectAbsolute::FromRect`, including its overflow test;
3. finite-sentinel comparisons that decide which outer/inner edges are assigned;
4. the actual two-axis `Intersect` result;
5. cross-axis emptiness and `SizeTo(0, 0)` behavior;
6. conditional `MoveInsideAndClamp`;
7. the result passed to the observer.

The Python finite oracle implements this pipeline and the extracted C++ executes it, but no Lean definition/theorem composes it. Two-axis emptiness matters: a disjoint x intersection resets both dimensions to zero, including an otherwise overlapping y interval. Proving only separate one-axis `moveInside` containment does not establish that source behavior. The core `ArithmeticSafe` and `machine_range_refines` predicates also do not cover this pipeline's edge subtractions, interval widths, `left + width`, the `newLeft - rect.left` / `newTop - rect.top` translation deltas, or `MoveBy`'s individual edge additions.

Required correction: add a source-shaped two-axis absolute-rectangle observer model with every return/empty branch; an independent declarative reference for the actual promised observer invariant; a complete source-to-reference theorem joined to `nativeLimits`/first-continuation normal geometry; and explicit executed-intermediate bounds/signed32 refinement for its arithmetic. Preserve finite sentinels and explicit-edge collisions rather than replacing them with infinities. Where outer intervals are reversed or an active edge collides with a sentinel, retain concrete counterexamples and name the necessary premises instead of asserting unconditional containment. Compile semantic mutations of intersection, cross-axis reset, and final clamp, with independent witnesses and corpus calibration to the new model.

## Finding R2: endpoint Int lemmas lack signed32 source joins

`StickyRanges.earliest`, `latest`, `endpoint_interval_ordered` and `endpoints_only_differ_at_threshold` correctly model the source's differing strict/non-strict branch boundaries over Int. The complete actual C++ methods are extracted and finite-tested. However no source-shaped machine-expression construction, executed-branch admission predicate, or signed32 refinement theorem joins them to the source operations. `machine_range_refines` only covers construction of the `(scroll threshold, max offset)` pair; it does not cover subsequent endpoint addition/subtraction.

The independent kernel challenge `endpoint_requires_additional_bound` proves that `latest machineMax 0 0 0 1` evaluates to `machineMax + 1`, outside signed32. This demonstrates a missing premise, not a reachable Firefox bug: geometry/provider reachability of those arguments was not established. Merely carrying the existing range-pair bounds does not prove the endpoint operation safe.

Required correction: model actual `Earliest`/`Latest` branch truthiness and threshold comparisons, exact selected `offset - endMax` / `offset + startMax` operations and every executed intermediate. Prove machine/Int equivalence under named bounds and compose with optional range defaults, selected ancestor identity and axis. Distinguish positivity derived from range construction from arbitrary raw displacement structs. Add nonempty-domain examples at each strict boundary, both-absent/default sides, and independent overflowing counterexamples when premises are removed. Retain genuine compiled semantic mutants and kernel witnesses.
