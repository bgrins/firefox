This disabled preparation builds the published color and image fixes and observes the unchanged 77-case suite. HEAD, canonical control hashes, source identities, application capture and consumed-input binding remain unset until the actual V88 checkpoint is committed and independently captured. No baseline outcomes are predicted.

The executed original77 lifecycle always restores the application. It has no permanent-build publication branch. This recipe therefore keeps that backup/restore path: build the current published source, record all three lanes and real Zoom capture, then restore the actually admitted pretrial application and extras. The canonical application role stays `built:false`; the restored old application is not represented as a current-HEAD build. Keeping the newly built app would require a separate role/epoch/application publication transition and is outside this recipe.
