# Sticky sentinel: extracted native consumer calibration

This source capsule executes complete retained native consumer/caller bodies against explicit provider facades. It supplies source calibration to the separate Lean companion. It contains no Lean theorem, browser run, or proof of the geometry providers.

Run `python3 -I -S check.py --manifest-sha <externally authenticated FILES.json SHA256> --out <new directory outside this capsule>`. The checker authenticates the closed source roster before loading local modules or dispatching the compiler. The manifest hash must come from the handoff, not merely from an untrusted adjacent manifest. Final reauthentication detects ordinary source changes during the run; this is not a filesystem race-resistance or malicious-OS claim.

The checker regenerates and compares the entire 856-case roster, validates the supported input profile, rejects 20 named malformed/provider cases, byte-checks selected source bindings, compiles old/new variants in debug and optimized modes with UBSan, compares every output and trace with the independent oracle, and compiles seven semantic mutants. A compiler failure never counts as a successful mutant detection. Compiler products go only into the supplied output directory. The actual compiler executable is pinned; the SDK, compiler dynamic dependencies, operating system and Python implementation remain trusted. Dependency files retain consumed header paths, not a complete immutable toolchain inventory.

Read SOURCE-CONTRACT.md before interpreting agreement. Arithmetic and geometry conditions are substantive premises. CASES.json contains synthetic consumer inputs as well as patterns motivated by the browser reproduction; the number of cases is not a browser/spec coverage count. Retained full native files preserve comments. The limited brace extractor supports these pinned signatures and ordinary strings/comments; it rejects raw strings in selected bodies and is not a general C++ parser.
