# Independent symbolic rounding review

The input is a free 32-bit bitvector reinterpreted as IEEE binary32; the sole domain exclusion is NaN or infinity. Signed zeros, subnormal values and both finite extremes remain included. Every complete query has the identical authenticated common prefix. The candidate uses binary64 RNE promotion/addition of exact half, RTN integral rounding, then guarded signed32 conversion. The reference uses binary32 nearest-even rounding and corrects only a positive-half residual. It does not repeat the candidate add-half/floor computation.

The reference argument is valid: nearest-even supplies an integer within a closed half interval. Its upper tie needs addition of one; its lower tie already chooses the larger integer. Residual subtraction is exact by the zero case or Sterbenz, and a half-integer binary32 operand is small enough for the corrected integer to be exact. The three auxiliary queries corroborate residual agreement with the promoted subtraction, exact correction and finite integral outputs; they are not independent kernel proofs of the floating-point semantics. Saturation explicitly catches values at or beyond ±2^31. The remaining integral interval is representable by signed32, so unspecified out-of-range fp.to_sbv results do not determine the comparison. At −2^31 the selected saturation value equals the representable conversion; at +2^31 it selects MAX.

The independent witness check decodes all four SAT model bitvectors to exact rationals and evaluates floor(x+1/2) with signed32 saturation, plus each incorrect adapter separately. All reported references and incorrect results agree. The input/output models are byte-identical to the author logs. These controls distinguish binary32 addition, nearest-even, ties-away and truncation.

The separate Lean theorem has genuine quantified positive-divisor/closed-nearest-interval hypotheses and proves the upper-tie adjustment through integer floor division. The proof uses the standard division characterization and omega, with no sorry or custom axiom. Positive replay has the exact original axiom log; both false tie controls fail as expected. It does not connect IEEE values to the interval or certify Z3.

The [SMT-LIB floating-point theory](https://smt-lib.org/theories-FloatingPoint.shtml) supports the sorts and RNE/RTN/RTZ interpretation; [Rust casts](https://doc.rust-lang.org/reference/expressions/operator-expr.html#numeric-cast) support the manual widening/saturating-cast mapping. Source binding covers only the two final expressions in Integer::resolve and Integer::to_computed_value. Proposal v2 preserves those source bytes exactly. NaN/infinity normalization, parsing, upstream expression evaluation, compiler/hardware/subnormal behavior and CSS property wiring remain outside this symbolic result. This is neither Lean verification of the solver nor a native/browser acceptance result.
