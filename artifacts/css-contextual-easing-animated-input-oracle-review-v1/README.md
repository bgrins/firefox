# Animated inherited-font easing oracle

**Verdict: INCONCLUSIVE for an unqualified release-bug claim; strong intended-behavior inference.** The proposed values are correct if CSS-owned keyframe timing metadata is recomputed from the changing target context. The reviewed text supports that behavior, but this review does not establish an explicit context-change-to-metadata-regeneration algorithm. This is not a finding that stale easing is permitted.

Scenario: a paused ancestor font-size effect alternates 16px/24px, the child inherits that value, and its existing paused opacity CSSAnimation remains at 750ms of 1000ms. The child keyframe has steps(calc(1em / 8px), end). There is no same-element font animation, changed keyframe rule, or successful setKeyframes override in the discriminating callback.

1. **Direct contextual value rule.** [CSS Values 4, font-relative lengths](https://drafts.csswg.org/css-values-4/#font-relative-lengths) defines em from the element's computed font size; inheritance transfers computed values. Once the actual inherited input is calibrated, the count is exactly 2 or 3. [CSS Easing 2, step functions](https://drafts.csswg.org/css-easing-2/#step-easing-functions) then gives 0.5 or 2/3 at progress 0.75; literal steps(5,end) gives 0.6. These arithmetic expectations are not the disputed bridge.

2. **Direct property dependency and liveness rules.** [Web Animations, computing property values](https://drafts.csswg.org/web-animations-1/#computing-property-values) uses the target's computed context and orders dependent computations. [Computed keyframes](https://drafts.csswg.org/web-animations-1/#calculating-computed-keyframes) resolves property values before effect evaluation. [Composited results](https://drafts.csswg.org/web-animations-1/#applying-the-composited-result) enter the cascade. [Model liveness](https://drafts.csswg.org/web-animations-1/#model-liveness) states: “Changes made to any part of the model cause the entire timing model to be updated and any dependent style.” Its separate rule that API operations normally do not produce a style-change event does not excuse stale dependent style. However, the ordinary property-value algorithm alone does not recompute keyframe easing metadata. Treating that metadata as dependent style is the additional interpretation needed here.

3. **Direct metadata acquisition; incomplete refresh bridge.** [CSS Animations 2, processing keyframes](https://drafts.csswg.org/css-animations-2/#keyframe-processing), step 2.2, groups keyframes using the declaration's computed timing-function value. [Animations](https://drafts.csswg.org/css-animations-2/#animations) requires updates when animation properties change. The fixture leaves the target's ordinary animation-timing-function at linear; its context-sensitive declaration is inside the keyframe rule. The text reviewed does not expressly say when an unchanged rule's dependent computed descriptor must be regenerated after an ancestor animation changes font size. [Pending style changes](https://drafts.csswg.org/css-animations-2/#pending-style-changes) requires observable API results consistent with processed pending computed values, but does not supply that missing dependency definition. The setKeyframes ownership exception is explicit and directly supports the literal override control.

| Rejected shortcut | Why insufficient |
| --- | --- |
| Ordinary keyframe property recomputation proves easing refresh | Easing is separate metadata, not an animated opacity property value. |
| No style-change event permits caching | Liveness separately requires dependent style to update. |
| Not-animatable timing properties cannot depend on animated font | The probe changes a dependency, not an animation interpolating the timing property. |
| A normal-restyle repair proves the exact native traversal | It is diagnostic correlation; observable reads may trigger additional processing. |

Keep the tentative probe. An eventual discriminating failure is proposal-boundary evidence until the metadata refresh interpretation is confirmed, ideally by a focused CSSWG clarification covering dependency changes caused by ancestor animations without keyframe/property declaration edits. No such exact resolution was established by this bounded search. Existing CSSWG issue 5125 discusses property-value dependency contexts; it is not treated as a ruling on this metadata case. No browser observation or new native bug is claimed.
