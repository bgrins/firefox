# Prioritary declaration capacity candidate

The native declaration builder uses a u16 index and stops linking prioritary properties when the full longhand vector reaches 65535 entries. Unrelated higher-priority declarations count toward that index. A lower-priority font-size declaration can consequently be absent from its property chain even when it is the only declaration for that property. This is a source/extraction candidate, not a browser-confirmed bug or accepted fix.

The invariant under test is that inserting declarations for another property preserves the sole font-size declaration. replay.py extracts the exact native builder block from the published source, compares its linked projection with an independent full-vector property filter, and tests both sides of the limit plus a high-priority control. A proposed u32 change and an independently compiled restored-limit control distinguish the cause. The Vec storage, two-property mapping and CascadePriority are support doubles; this is not full Stylo compilation or proof of layout equivalence. The patch is an unapplied proposal and extends the bound rather than proving unbounded capacity.

The browser probe uses equal-specificity class selectors. Both targets match all 65536 filler rules; one font-size rule precedes them and the other follows. It checks the CSSOM rule count, both colors, computed font sizes and 1em widths. It has not run in a browser and is outside the installed WPT tree. The active computed-size browser pair must finish and restore before this probe runs.

CSS Cascade defines selection per property and element, so declarations for color should not suppress an otherwise winning font-size. See [cascading](https://drafts.csswg.org/css-cascade-5/#cascade) and [font-size](https://drafts.csswg.org/css-fonts-4/#font-size-prop). The official drafts were read on 2026-11-02 after webspec-index failed with a read-only cache error. No general UA resource-limit exemption analysis is claimed. Searchfox's matching implementation is [DeclarationIndex](https://searchfox.org/firefox-main/rev/28b7a7bffb5f82828143d9ad63839ad263b598be/servo/components/style/properties/cascade.rs#608). A bounded Searchfox search for 65536 under WPT css-cascade returned no match; that is not an exhaustive coverage audit.

Discovery came from inspecting the native linked-list construction obligation left open by the selected-prefix Lean proof. The proof itself did not report this candidate. No source, browser application, Git index or canonical experiment state is changed by this package.

The ordinary application path does not repair the omitted link: apply_non_prioritary_properties rejects prioritary properties in its input set and skips declarations outside that set. The retained source excerpts show both the caller and callee. This strengthens the source hypothesis; actual full-browser reachability remains untested.

Executed extraction run1 (f58fe2/50600/a9dcee, exit 0) observed the original and restored-limit control lose the sole font-size at 65535 and 65536 preceding declarations; both preserve the below-limit and first-entry controls. Widening passed all five cases. JavaScript syntax checking passed. No WPT manifest, lint or browser result is claimed.
