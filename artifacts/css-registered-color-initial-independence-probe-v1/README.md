# Tentative JavaScript registration independence test

Three WPT callbacks separate an accepted independent `red` initial from expected `SyntaxError` for `CanvasText` and `light-dark(red, blue)` with `<color>` syntax. This is the narrow JavaScript registration guard traced in the sealed initial-value spec review, not an assertion about the newer `@property` descriptor wording or an invalid-value default recomputation test. No browser execution or native change is claimed.

Each callback creates a fresh iframe and registry. It checks ordinary color syntax support, registers an independent red calibration under a different name, and compares its computed initial with a literal red reference. The tested registration uses a fresh `--candidate` name and records acceptance or the actual caught exception before verdict. The exception assertion uses the iframe’s DOMException constructor. After expected rejection, registering red under that same name verifies the failed attempt did not reserve the name. Unsupported syntax, missing API, or failed setup/calibration remain failures; a syntax-only rejection cannot satisfy the test without the support check. An early setup failure can omit its diagnostic record.

The tentative contextual-initial expectations follow [registration step 4](https://drafts.css-houdini.org/css-properties-values-api-1/#register-a-custom-property), [computational independence](https://drafts.css-houdini.org/css-properties-values-api-1/#computationally-independent), [system-color computation](https://drafts.csswg.org/css-color-4/#resolving-other-colors), and [light-dark computation](https://drafts.csswg.org/css-color-5/#light-dark). The preserved trace distinguishes current Editor’s Draft and published text and does not treat either browser as the normative oracle. System palette dependence is a semantic input requirement; the test does not assert particular palette RGB values or compare forced-color modes.

The existing 42-case preservation suite is unchanged. This separate page needs installed Firefox/Chrome observations before triage. It has no animation, private receiver, run identifier, preference changes or new execution owner. `window.registrationObservations` and hidden JSON hold diagnostics; ordinary WPT PASS callbacks do not transport those records. Three callbacks, one page, four strict signatures and three resources are prepared. Genuine manifest generation, inert callback registration and scoped WPT path/content lint are static checks only.
