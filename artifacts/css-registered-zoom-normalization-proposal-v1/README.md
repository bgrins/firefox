# Registered-value zoom normalization experiment

This six-file proposal is isolated under `candidate/`. It is not installed, compiled or accepted. Its bases are the actual checkout at signed HEAD `1c7870c6d36d002b1c785ec2a6251ddc4ca2a040`; the two live admission edits are unchanged.

The scoped outer `Value` conversion comes from the signed scope proposal. Absolute registered lengths avoid CSS zoom, font-relative lengths remove the computation context's effective zoom, and viewport-relative lengths avoid zoom before their existing app-unit truncation. The shared math conversion retains its existing nonfinite-value handling. Ordinary property computations keep their existing paths. Custom-property CSSOM output keeps these stored lengths rather than removing zoom again; percentages and other component types retain their existing conversions. All six numeric style-range operand types enter the same computation scope, including lengths within their math expressions. Custom-value clones and substitution keep their existing paths.

Container-relative computation is still an unresolved integration point. Its existing raw container/viewport size path is unchanged in this experiment. Bug 1894104 already tracks ordinary container-unit zoom behavior, so matching ordinary values alone cannot establish the normative result. The separate container diagnostic measures both paths, ancestor/target zoom, writing modes, fallback viewports and mutations before this proposal is finalized. This is not a claim that all registered length producers are normalized.

The admission-only build completed the four-page calibration: 50 failures and six passes, with all 56 identities, page completions, process cleanup and preservation checks present. Simple lengths failed 26/26, compound values 16/18 and relative values 8/8; two matrix and four style-range controls passed. These observations are saved in `css-registered-zoom-wpt-calibration-runtime-admission-1`. They establish the failure surface of that binary, not the correctness of this proposal.

Rustfmt parsed the six candidates with edition 2024. An initial edition-2021 attempt rejected an existing let-chain in the query implementation; no live file changed. Native compilation, regression comparisons, container semantics, animation/recascade behavior and final WPT lint remain outstanding. The accepted-fix count and formal-coverage count do not change.
