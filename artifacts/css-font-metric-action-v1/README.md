# Retained metric prerequisite actions

This experimental source slice connects the retained parent frame to the existing staged MetricDrain through an explicit scheduling action. It is based on the sealed parent-frame candidate aa9089f3, with published cascade 5b7204 as the full-patch base. It does not repair the observed font-metric bug: the native compatibility entry still supplies `PublicationDemand::Ready`, and no real unit-demand classifier or general scheduler has been connected.

A publication provider can return `Metric(id)` or `Unresolved`. The former retains the root, owner, index and prerequisite in an opaque allocation-identity token. Context owns the token, completion ledger and MetricDrain. While the token is outstanding, polling the root returns computation Pending before invoking the provider again. A changed callback answer cannot bypass the wait. Executing a matching token drives real staged declaration preparation and publication; only successful publication or an independently completed ledger entry clears it. Replayed, foreign or stale-frame actions cannot consume work. The prerequisite publication does not publish the waiting custom value or alter its Tarjan stack, frame cursor or lowlink.

The current semantic NonCustom node uses SingleNonCustomReference and can own FontSize, LineHeight or ColorScheme. These are disjoint from the supported action properties; this slice does not solve ownership conflicts for a future expanded semantic node set. The allowed actions remain FontWeight, FontWidth, FontStyle, FontSizeAdjust, Direction, WritingMode and TextOrientation. A generated prerequisite returns its identity; a selected variable declaration returns its exact retained Arc and longhand. Neither is a semantic CSS backedge. This slice deliberately does not supply a reference-ready reply, apply unsupported properties, treat old `ensured_prioritary` bits as completion, or classify stalled work as a cycle. The completion ledger is an obligation to prove final publication, not a substitute for that proof.

The positive extracted test pauses a real action on Appearance, executes a literal prerequisite through the existing completion helper and an application double, then runs the actual staged Weight preparation/publication. The waiting frame remains intact. Further checks cover repeated selected-reference waits without substitution, action replay and tampering, invalidation, unsupported work, stale frames, and completed prerequisites without republication. Six tests pass with debug assertions disabled. Six compiled mutants fail behavioral assertions: foreign identity acceptance, bypassing the pending action, trusting the old ensured bit, clearing a generated wait, clearing a reference wait, and accepting a stale frame. The initial extraction-marker and mutation-pattern failures remain archived.

`test.py` extracts the actual staged/drain/publication/action bodies and the actual action-mint and poll-block statements. Its frame and Stylo value types are doubles; it does not run the full parent traversal, resolve CSS, exercise real fonts, or check Context's four native lifetimes. The preceding sealed parent-frame package separately tests eager/frame traversal equivalence. `check.py` authenticates the tested bodies, preserved recursive eager methods, exact parent/full patches, zero-fuzz forward/reverse application, pinned formatting, compiled test receipts and scratch removal. No native typecheck or browser run occurred.

Remaining integration is concrete: connect a justified per-value demand provider; produce generated and selected-reference readiness under the same retained semantic session; maintain once-only substitution and valid caller context; and propagate final completion through root draining. The current method returns foreign work but cannot progress it automatically. The literal Appearance action in the harness is a controlled external producer, not a native selection proof. Finality must account for eligibility changes and later font fixups; the seven supported fields are not a complete metric-consumer inventory. SemanticCycle still requires settled invalid/default map outcomes. Genuine metric wait-cycle behavior remains unresolved. Compatibility eager bodies remain unchanged, and no independent accepted-fix or native acceptance claim follows from these tests.
