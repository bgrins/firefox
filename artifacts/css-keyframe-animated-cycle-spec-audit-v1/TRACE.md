Question: how should two selected animated registered `<number>` properties resolve when each keyframe value reads the other?

Scenario: same target, `--x` and `--y` registered with `inherits:false`, initial values 10 and 20; explicit constant endpoints, replace composition, finite paused progress, no transitions, no important declaration unless stated. The animation dependency graph is not assumed to be the ordinary declaration graph.

1. [Web Animations, computing property values](https://drafts.csswg.org/web-animations-1/#computing-property-values) resolves keyframe values against the target's computed dependency values. Those dependencies must be calculated first. [Computed keyframes](https://drafts.csswg.org/web-animations-1/#calculating-computed-keyframes) feeds those results into the effect calculation. [Applying the composited result](https://drafts.csswg.org/web-animations-1/#applying-the-composited-result) then inserts the composed value into the cascade. This establishes a circular ordering obligation for mutually selected providers; it does not itself specify an effect-cancellation operation.

2. [CSS Variables, var() replacement](https://drafts.csswg.org/css-variables-1/#using-variables) reads the target's computed custom property. A fallback is evaluated only for a guaranteed-invalid result. This is not a general fallback for a consumer's type mismatch, nor for an implementation's unsupported recipe.

3. [CSS Values, cyclic substitution contexts](https://drafts.csswg.org/css-values-5/#cyclic-substitution-contexts) marks the participants in a repeated guarded substitution context invalid. An internal fallback does not rescue a detected cycle. [Invalid substitution](https://drafts.csswg.org/css-values-5/#invalid-at-computed-value-time) gives non-universal registered properties unset/defaulting behavior, rather than returning to a lower cascade declaration.

4. [Properties and Values API, computed values](https://drafts.css-houdini.org/css-properties-values-api-1/#calculation) applies registered syntax checking; [substitution](https://drafts.css-houdini.org/css-properties-values-api-1/#substitution) uses the computed registered value; [dependency cycles](https://drafts.css-houdini.org/css-properties-values-api-1/#dependency-cycles-via-relative-units) follows custom-property cycle rules. For the stated non-inherited registration, an ordinary invalid declaration therefore yields its registered initial value.

The unresolved bridge is the identity/lifetime of substitution guards while a dependency requires calculating another animated effect, and how a cycle covering endpoint computations maps back to the selected composed property. Treating the selected animation recipes as ordinary declarations in a single SCC is a plausible implementation interpretation, not an independently established equivalence here. In particular, it must not turn all endpoints into graph edges when some endpoints or fallback branches are unused, or conflate one invalid endpoint with invalidating an entire multi-property effect.

**Verdict: INCONCLUSIVE** for the mutually animated cycle's exact numeric result. The ordinary invalid/defaulting and acyclic provider cases below have supported oracles. This audit does not establish that the animated cycle is underspecified in every possible reading; it does not certify a numeric animated-cycle oracle or an effect-disable rule.

Rejected shortcuts: an ordinary base value does not automatically break a selected animation's dependency; effect-stack base values are not a license to substitute a previous sampled cache. Animation taint concerns non-animatable consumers, whereas these registered numeric consumers are animatable. An implementation admission failure is not CSS invalid-at-computed-value-time.
