# Shadow move controls

One artifact-only WPT page adds four callbacks to the proposed shadow move-context experiment. It has not been executed in a browser. No native source, installed WPT, index, or epoch was changed.

Three controls require ordinary appendChild to retain disconnected/connected custom-element reactions even when a move callback exists, moveBefore without a move callback to use that fallback, and ordinary removal with a disconnected style flush to cancel a shadow CSS animation before reinsertion creates a new paused animation. The fourth checks that moveBefore preserves the same animation and time while inherited color changes red → blue → red. It is an improvement target; the other three are strict preservation controls.

The [DOM move algorithm](https://dom.spec.whatwg.org/#concept-node-move) traverses shadow-including descendants. [HTML callback selection](https://html.spec.whatwg.org/multipage/custom-elements.html#enqueue-a-custom-element-callback-reaction) uses the disconnected/connected fallback when the move callback is absent. Ordinary removal cancellation follows existing `css/css-animations/cancel-events-on-remove.html`, freshly read with Searchfox (293b53), including its ancestor-removal oracle and [CSS animation event-dispatch reference](https://drafts.csswg.org/css-animations-2/#event-dispatch). This page asserts cancellation state after explicit style/animation flushing, not synchronous cancel-event delivery. Stable animation applicability is isolated from inherited color; it does not assert preservation when animation names, keyframes, or display applicability change.

All mutation phases are collected before outcome assertions. The CSS controls calibrate the original paused animation at 375 ms and 3.75 px; reaction controls capture node/root identity and final connection state. Explicit body creation precedes test registration. Cleanup is registered before fixture connection. The only external resources are `/resources/testharness.js` and `/resources/testharnessreport.js`.

`python3 -I -S -B artifacts/css-shadow-move-control-wpt-v1/check.py` generates a genuine testharness subset manifest, checks all four registrations without invoking their callbacks, and runs scoped WPT lint in private scratch. The first run stopped at an unavailable Python YAML import, before test validation; the checker now explicitly uses the existing vendored PyYAML. The corrected run (263041/0) passed with zero lint errors. Typed review 42a0fa/0 found no setup or oracle blocker. Static checks do not establish browser behavior or a native repair.

This is additional control coverage for the existing shadow-boundary flag-loss hypothesis, not a new bug or accepted-fix count. Internal shadow iframe/frame-loader retention remains an untested source-derived follow-up and is outside these four callbacks.
