# ArcSlice static-empty caller audit

The generic safe API does not enforce the singleton's alignment assumption. No over-aligned production element was identified in this bounded caller audit, so it does not establish browser reachability or a new UB witness. The compiler agent owns the separate current-library Miri experiment.

The exact immutable a6 ArcSlice source (SHAfe42c2cb81c698ce91a4fa9796e79d5d44803e1e00e66493d956b61859a52405) is byte-identical to the indexed Searchfox dcafde486e11b7a7776137b92fec2a6f56744eab source and the previously pinned client copy. SOURCE.json authenticates22 immutable a6 files. Indexed results are discovery evidence, not a claim that every current upstream callsite equals a6.

`ArcSlice<T>` is public in the public style_traits arc_slice module. Its tuple field is private, but safe `Default` and `from_iter` have no alignment trait, sealed-type bound, or documented unsafe caller obligation. Default only debug-asserts align_of(T) <= align_of(u64), clones the static ArcSlice<u64>, and transmutes it. Empty exact-size iterators delegate to Default. Deserialization constructs a Vec and delegates to from_iter, so an empty input takes the same route when T implements Deserialize. This does not let a web page choose a Rust T. from_iter_leaked constructs a fresh typed allocation and is a different route; its behavior is not inferred from the singleton path. The nearby comment that ThinArc cannot support larger alignments is not an enforced API restriction or a proof about the current ThinArc implementation.

The C++ `StyleArcSlice<T>` default constructor also reinterpret-casts `Servo_StyleArcSlice_EmptyPtr()` and checks the canary; the inspected constructor does not constrain alignof(T). The generated template and existing C++ text-shadow member are saved in discovery logs. This is an additional generic API surface, not evidence of an over-aligned browser instantiation.

ELEMENTS.json lists eleven direct element families: Symbol, PiecewiseLinearFunctionEntry, ContainerCondition, SingleFontFamily, CustomIdent, QuotePair, LinkParam, DashedIdent, AtomIdent, PositionTryFallbacksItem and PathCommand. The property template adds a twelfth family: computed SimpleShadow for text-shadow. That result is derived from exact a6 longhands.toml plus the inherited/no-initial vector branch in helpers.mako.rs; merely searching for literal ArcSlice<T> would miss it. Generic computed/resolved/animated adapters can propagate their associated element types and are not a finite API restriction.

The inspected concrete definitions use floats, ordinary enums, atoms/strings, pointers/containers and CSS value structs. Targeted indexed style/style_traits searches found no u128/i128, SIMD or explicit repr(align) candidates. These negative searches and field inspection do not prove all transitive field layouts or all target configurations: ContainerCondition, color/length representations, generated bindings and dependencies still require target-specific layout evidence to make such a claim. No complete style crate or native target was compiled here. A future or external safe caller can instantiate a repr(align(64)) element, or u128 on a target where its alignment exceeds u64; that is a plausible library-level consumer, not an observed production caller.

Web content controls CSS values and list lengths, not monomorphized Rust element alignment. Empty browser lists are real reachable paths (for example quotes:none, default container conditions and text-shadow:none), but no type above was demonstrated to violate the alignment bound. Therefore a successful synthetic over-aligned Miri witness should be reported as a generic client/library safety defect unless a concrete production type and constructor path are separately established. No browser probe, native build, shared-source edit, index mutation or fix/count change occurred here.
