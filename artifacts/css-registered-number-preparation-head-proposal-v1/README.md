# Registered-number preparation proposal: committed ordinary path

This is the minimal ordinary-path counterpart to `css-registered-number-preparation-proposal-v1`, based exactly on signed HEAD `eb9c04b94cf3007d4f4b4d45ba99cd826829e455`. It introduces no pending-demand APIs, declaration-source prototype, typed-keyframe scheduler or `data_type.rs` changes. Together with the separately pinned numeric collector and a future WPT, it is intended to form a standalone bugfix. It has not been compiled or browser-validated.

`fix.patch` modifies only `custom_properties.rs` and `properties/cascade.rs`. The required collector changes only `properties_and_values/value.rs`; its base is identical in committed HEAD and the live prototype. `BASE.json` pins the two committed preimages. The companion live overlay preserves pending demands independently and must be validated separately when restored to the working tree.

Exact scalar `<number>` values enter the existing dependency graph when lexical unit flags indicate possible context use. After selected provider traversal, preparation is permitted only if every visited primary node has left its graph component. This explicitly detects still-open var and typed-attribute nodes; it does not mistake `lowlink == index` for full readiness. Existing custom/attribute cycle invalidation remains in place.

The actual selected value is parsed against the registration once and retained as an owned Invalid, CSSWide or specified Value result. Supported numeric AST context flags replace the conservative lexical expression flags; unsupported collector results retain the old flags. Bare `1em` and selected wrong-type values fail number admission before they can add a spurious font edge. An unused fallback no longer contributes contextual edges when the selected primary is an admitted number. Real admitted length division retains its current-font requirement.

The traversal-local result is published only after SCC settlement and the existing in-loop return. Parsing is separate from computation; admitted values call the existing `to_computed_value` once at application. URL data, registration parser namespace argument, property identity, attr-taint propagation, and CSS-wide keyword behavior are preserved. The extracted CSS-wide match and the underlying substitution primitives are checked against the committed preimages. True unresolved cycles use the existing path rather than a guessed fallback rescue.

The explicit exact-number dependency prefilter preserves noncyclic dimension-cancelling math without importing the live prototype's broad numeric type mask. Consequently the committed-HEAD candidate can route a self-font numeric expression through graph invalidation where its original type mask did not. The spec does not yet establish a definitive expected default for that case; its result is observation-only. This patch does not resolve that policy question or claim that scheduling need proves normative cycle invalidity.

Validation: Rust syntax/formatting; exact two-path patch apply, reverse and reapply on owned scratch; and static preservation checks. No native typecheck or runtime has run. The combined collector patch must be compiled with this variant before claiming viability. Controlled browser/WPT gates must cover the eight defensible numeric oracles, genuine cycles, CSS-wide behavior, taint/typed-attribute regressions and noncyclic font mutation. Native errors or failed semantic gates require a new versioned proposal.

No live native sources, Git state, source epoch, browser or build outputs were modified. Transport scratch was removed. The sibling's source and normative provenance are bound in `REFERENCES.json`; no new normative coverage or accepted-bug credit is claimed.

To repeat the bounded checks, run `python3 -I -S -B artifacts/css-registered-number-preparation-head-proposal-v1/check.py`; it prints JSON and removes its owned scratch. This does not invoke Mach or a browser.
