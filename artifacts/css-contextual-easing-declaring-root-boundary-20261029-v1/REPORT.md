The useful new obligation is narrower than “cover shadow roots”: a declaration-root change can require a different selected keyframe expression while the element, serialized animation name, dependency support, and dependency values all stay equal. The easing candidate transports the scope of the rule its existing lookup selected; it cannot establish that the selected rule is the normative winner.

The [candidate page](declaring-root-easing.tentative.html) defaults to the independently runnable literal case. Its WPT variants are `?variant=literal` and `?variant=contextual`, one callback per variant. Both use the same shadow target and two same-name rules, then toggle the winning `animation-name` declaration between a shadow rule and a document `::part()` rule. The test samples all three phases before numerical assertions. It checks the unchanged computed animation name, a background-color marker that independently confirms the winning declaration context, and unique-name local/outer animation controls. It does not assume CSSAnimation identity survives a root change; every phase samples the current animation at 750ms without overriding its keyframes.

| Phase | Reference root | Required easing | Opacity at 750ms |
| --- | --- | --- | --- |
| Initial shadow declaration | Shadow root | `steps(2)` | `1/2` |
| Document `::part()` declaration | Document | `steps(3)` | `2/3` |
| Shadow declaration restored | Shadow root | `steps(2)` | `1/2` |

The contextual variant uses `steps(calc(1em / 8px))` locally and `steps(calc(1 + 1em / 8px))` in the document. Both read the target's fixed 16px font, so both supports are `{ownFont}` and both input vectors are equal. The literal variant uses `steps(2)` / `steps(3)` directly. Syntax admission is asserted first. Before any collision assertion, the unique-name controls must each expose font-size 16px, the correct computed keyframe easing, and the corresponding opacity. A contextual syntax or control failure is therefore a readiness failure, not evidence about declaring-root selection. The ordinary timing property is `linear`, producing 0.75 if the keyframe easing is ignored; that is distinguishable from both expected samples. No sibling counting, failed-reference fallback, variable substitution, CSS-wide descriptor, animated font, or move operation is involved.

Fresh primary-spec trace, read 2026-10-29:

1. [CSS Shadow, tree context](https://drafts.csswg.org/css-shadow-1/#tree-context): “Declarations inherit the tree context of the selector that was matched to apply them.” Thus the document `::part()` declaration retains document context even though its target is inside the shadow tree.
2. [CSS Shadow, tree-scoped reference](https://drafts.csswg.org/css-shadow-1/#css-tree-scoped-reference) captures the declaring stylesheet's root; global-name lookup starts there, then searches ancestor trees if necessary. It explicitly includes `animation-name` and `@keyframes`. Both roots have a matching rule here, so no ancestor fallback is needed. A document reference cannot select the descendant shadow rule.
3. [CSS Animations 2, processing keyframes](https://drafts.csswg.org/css-animations-2/#keyframe-processing), steps 2.1–2.2, selects the matching rule and groups frames by the last declared timing function's computed value. The selected rules explicitly animate opacity 0→1 and give the first frame the two- or three-step easing.

**Verdict: REACHED under CSS Shadow's explicit tree-scoped-reference requirements.** The expected selected curve changes with the declaration root. Specification integration remains qualified: CSS Shadow still contains a TODO to update all referencing properties/at-rules, while Animations 2 step 2.1 still says document order without spelling out the tree lookup. The candidate is therefore tentative; this trace applies the Shadow requirements to Animations' name match and does not claim an exhaustive generated algorithm graph. `webspec-index` was unavailable, so the primary drafts were read directly. The referenced fragments were checked in downloaded HTML; the current reference fragment is `#css-tree-scoped-reference`, not the stale `#tree-scoped-reference` used by older research.
