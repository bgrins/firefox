# Prepared selection and final publication

This extension imports the exact existing `Selection.scan` and `PreparationStability.scan_eq_of_reached_agreement`. It adds a small state/publication model, not another CSS evaluator. It is separate from the nested CSS repository and all native proposals.

The store holds one protected value, unrelated state, a publication history, and values already consumed by dependents. Intervening actions can update unrelated state, publish a protected value, or consume its current value. `isolated` permits only unrelated updates. This is a sufficient discipline, not a necessary characterization: native work classified as unrelated must actually preserve all relevant selection and publication state. In particular, absence of target writes alone does not prevent a dependent from consuming a value before it is final.

`isolated_run_preserves_publication_state` proves noninterference for arbitrary finite action lists by induction. `stable_preparation_single_final_publication` then composes that result with the existing arbitrary-declaration-list scan agreement theorem. Given agreement on every reached selection decision, an initially default-valued protected field, no prior target publication, and isolated intervening work, the prepared optimized application equals explicit application of the newly evaluated result. It records exactly one final publication, preserves prior observation history, and a dependent read after publication sees the resolved final value. Skipped and rollback candidates retain exactly the existing scan theorem's obligations; agreement only on retained declarations is not substituted for them.

The finish-to-assignment decoder is an arbitrary shared parameter. This theorem does not decide how CSS blocked/exhausted/invalid outcomes become Initial, nor prove that a native context satisfies reached-decision agreement. Assignment `initial` models the non-inherited Initial optimization; `literal` models an already-resolved value. The optimized Initial case records a semantic publication but does not physically reset the field. A publication log therefore counts abstract publication events, including a skipped assignment's logical completion; it is not a count of native memory writes.

Three failure modes have concrete witnesses. Even with identical selection and an arbitrary losing declaration suffix, an earlier base write followed by optimized Initial leaves base, whereas explicit Initial resets to none. Resetting the final value does not undo a dependent's earlier consumption of base. Conversely, intervening observation without any target write can consume none before final literal base, so no-target-write discipline alone does not establish correct dependent values. Finally, restoring the field before the final commit does not erase multiple earlier publication events. Four separately compiled false propositions reject the corresponding overly strong claims.

SOURCE-MAP.json pins five exact cascade excerpts and explicitly lists the refinement assumptions. The source follow-up identifies ordinary generated ensure potentially publishing an active graph-owned Appearance, followed by Initial's skip or changed seen state. The observed-review package supplies actual endpoint failures and within-FAIL color worsening, but not an instrumented execution trace. The model's base/none counterexample matches the isolated skip mechanism conditionally; it does not prove that this mechanism caused the browser result. The protected field abstracts away seen bits, flags, cached font/scheme/custom values, rollback effects and SCC state. Native correspondence must account for those effects and establish readiness before consumption. A final field or flag reset alone is not justified by this model.
