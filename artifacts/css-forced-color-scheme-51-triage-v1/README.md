The saved raw callback fails with `assert_equals: expected "light dark" but got "normal"`; its page ends OK. Since the first assertion throws, this callback does **not** establish the second opt-out assertion's actual result. ## Manual specification trace

1. CSS Color Adjustment defines `forced-color-adjust` with initial `auto` and the opt-out `none`. The connected test elements use those two cases. [Opting out](https://drafts.csswg.org/css-color-adjust-1/#forced-color-adjust-prop).
2. Its forced-properties rule applies when forced mode is active and adjustment is auto. The additional computed-value effects explicitly state “color-scheme computes to light dark”. The ordinary property definition preserves the listed keyword order. [Forced properties](https://drafts.csswg.org/css-color-adjust-1/#forced-colors-properties), [color-scheme](https://drafts.csswg.org/css-color-adjust-1/#color-scheme-prop).
3. CSSOM `getComputedStyle()` returns resolved longhand values for connected elements. Its general resolved-value rule uses the computed value; color-scheme has no listed used-value exception. [getComputedStyle](https://drafts.csswg.org/cssom/#dom-window-getcomputedstyle), [resolved values](https://drafts.csswg.org/cssom/#resolved-values).

A bounded search found sync reports and broader color-scheme work, but did not establish whether an existing dedicated implementation bug should own this issue; this is not an exhaustive duplicate search.

The frozen published source declares color-scheme inherited, initially normal, and `ignored_when_colors_disabled`. `tweak_when_ignoring_colors` bypasses UA/user declarations and `forced-color-adjust:none`; for the author color-scheme declaration it has no special computed `light dark` branch and replaces the declaration with `Revert`. This is consistent with the observed inherited/root normal result. It is a source-supported mechanism, not an instrumented runtime trace. The selected-declaration repair changes preparation/selection around this adjustment and does not promise to replace its underlying color-scheme policy.
