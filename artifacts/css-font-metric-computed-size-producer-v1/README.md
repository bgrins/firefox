# Computed-size publication before whole FontSize completion

This artifact-only successor to the sealed dynamic prerequisite producer separates the computed size needed by registered `1em` from whole FontSize/XTextScale completion. It keeps the original raw-attribute case as its target: retained `--len:1em` can compute, then the exact attribute primary and dynamic Appearance declaration resume. It does not replace that case with a literal attribute. No native typecheck or browser run of this successor has occurred.

The candidate cascade is `f0d21abeca15883f01c0fa06df860a17192deb33bb42f8b1cc062fc7bec22819`; the provider remains `90acb50533dc62edca87c9f51dea6731888fd7087c4316d97733fb40605919f9`. `PARENT-DELTA.patch` is against c6c0; `native.patch` is the complete two-file patch against the preserved published bases. ## Supported operation and finality

A FontUnits node must close its semantic SCC normally before the narrow path runs. The caller must be a registered unit consumer whose accumulated demand is exactly ComputedSize. The producer owns the selected FontSize and XTextScale declaration sequences, including static rollback candidates. It recognizes only an actual retained absolute-length FontSize AST through `to_px_if_absolute()`. It does not manufacture pixels, hand-convert registered units, change semantic edges, or grant readiness from an existing ensured bit.

`size_input_prefix_is_stable` follows the actual linked prioritary declaration order and current rollback relation for size and its selected inputs. It rejects any encountered APPEARANCE_BASE-dependent entry, including an ineligible higher entry; an unvisited lower loser is irrelevant. It rejects reached dynamic input declarations. Static rollback advances through the same chain; selection stops at the winning non-revert declaration. Other cascade flags must remain unchanged. The certificate permits only adding APPEARANCE_BASE afterward, and the full retained preparation still has its own stricter invalidation checks.

The narrow selection gate owns FontSize/XTextScale ASTs before the full generated scheduling list. It then completes selected Zoom, XLang, MathDepth and minimum-size ratio through the existing ordinary path, requiring their real completion records. At publication it rechecks retained flags, initial rollback state, complete selection and absence of prior application. The immutable declarations, parent style, device inputs and one computed context are the same session's inputs; no cross-style cache reuse is introduced.

Publication invokes the existing application and bookkeeping methods. XTextScale's hook runs only if its selection was actually seen, and runs before fresh FontSize. An absent XTextScale declaration does not synthesize an unzoom. Fresh absolute FontSize gets the native setter, effective/text zoom, quantization and hooks; the real implementation retains minimum-size handling rather than equating computed and used size. Later Family/Math keyword hooks have no keyword-derived absolute size to recompute. These readset claims are tied to the source support capsule; the extracted test's numeric conversion is not a native CSS evaluator.

Unsupported absolute-selection attempts issue no certificate. Their pure, uncomputed static selection copies may be discarded before returning to the original full-dependency path. Dynamic size/input declarations, keyword/relative/percentage/default sizes and unresolved readsets gain no early readiness. They can finish only through that existing full path; if its real requirements remain unresolved, they stay pending. No fallback/default is chosen merely to make progress.

## Typed reply and retained whole-property work

`ComputedSizeCertificate` retains the owned absolute operation, selection flags and session identity in the shared ledger. Neither whole priority completion nor `NodePublication::Complete` is set. `VisitResult::ComputedSize(index)` is accepted only for a FontUnits Unit reply with exact ComputedSize demand and the same semantically closed pending node and session. Generic reference walks, ordinary callers and stronger metric consumers cannot use it. Both registered-value preparation and publication check the same certificate.

The original FontSize Publish frame is retained. The custom root may finish using the size facet; before the session can retire, the retained frame is restored and drains the full ordinary dependencies. Existing owned dynamic Appearance/Family handling then consumes the finalized child. XTextScale and FontSize ordinary finalization still traverse all generated dependencies first; only afterward does their authenticated certificate suppress the already-run application/hook. Thus XTextScale is applied-but-not-ordinary-complete, not early ensured. Reset remains forbidden while the frame, root result, action, semantic/publication state or preparation is retained. It clears the facet only after generic retirement.

An Appearance action that changes cascade flags can still apply once and return Invalidated under the predecessor's existing rule. The facet's limited flag predicate does not prove restart or arbitrary context-change progress. Nested scheduling, literal-lh progress and true metric feedback policy remain separate unresolved work. Passing a future full matrix would not establish a general scheduler/refinement theorem.
