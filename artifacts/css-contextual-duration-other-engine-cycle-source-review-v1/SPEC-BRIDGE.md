# Same-element timing-source bridge

Question: after seeking a fixed-duration font effect on an element, must a separate CSS opacity effect on that same element immediately use a duration computed from the resulting animated font? Is the pre-effect timing snapshot seen in implementation source an explicit specification exception?

Scenario: the sealed acyclic callback has two paused CSS effects, no script duration override, no animation of custom properties, explicit font endpoints, and a time-based timeline. Font time changes from 0 to 750 ms with fixed duration 2000 ms. Opacity time stays 750 ms. The numerical 22 px / 1375 ms / 6/11 derivation is exact if the post-effect font supplies duration.

1. [CSS Animations 1, animation model](https://drafts.csswg.org/css-animations-1/#animations) makes animation effects participate in computed property values and says changes to animation-property values apply to an existing animation. This supports updating genuinely changed CSS timing; it does not identify a separate pre-animation timing-source style.
2. [CSS Values 4, font-relative lengths](https://drafts.csswg.org/css-values-4/#font-relative-lengths) defines `em` from the element's computed font size, with specific parent-metric exceptions for font-affecting properties. Duration is not itself a font-size declaration. There is no duration-specific base-style exception in this consulted definition.
3. [CSS Animations 2, animations](https://drafts.csswg.org/css-animations-2/#animations) requires animation-property changes to update associated CSSAnimation objects and lists API-ownership exceptions. Pause/current-time control does not constitute a duration override. [Duration](https://drafts.csswg.org/css-animations-2/#animation-duration) specifies the effect's iteration duration. These passages do not affirmatively license a permanent computed-CSS/effect-duration mismatch.
4. Web Animations' [composited-result procedure](https://drafts.csswg.org/web-animations-1/#applying-the-composited-result) calculates the base value of a *target property* without animations, then inserts its composited value into the cascade. This is not an explicit CSS animation-timing update algorithm: opacity's target-property base value is not its duration. Using this rule alone to justify pre-effect duration would conflate those two objects.
5. [The not-animatable rule](https://drafts.csswg.org/web-animations-1/#not-animatable) prevents processing that property in keyframes and transitions. Its explanatory recursion note is not a normative ban on indirect font-relative dependencies. Neither our fixture nor this argument puts duration in a keyframe.
6. [CSS Animations 2 §6.2](https://drafts.csswg.org/css-animations-2/#requirements-on-pending-style-changes) requires relevant animation APIs to behave as if pending computed-value changes were processed. That is additional consistency pressure once a changed timing value is established; it does not itself define which same-element metric snapshot establishes that value. The fixture's first style getter is distinct from its later timing/membership getters.

**Verdict: INCONCLUSIVE** for an explicit, fully traced intra-element timing-source/order rule or an explicit snapshot exception. The consulted normative text supports the authored acyclic expectation by composition, but the missing step is a precise integration algorithm feeding the newly composed font back into CSS timing within the same query/update. The two pinned engine paths are concrete contrary implementation evidence, not normative authority and not proof of a permitted mismatch. This finding weakens a claim of established interoperable same-element behavior; it does not disprove the conditional arithmetic, change a frozen result, or settle self-cycle policy.

This is a manual focused bridge, not an exhaustive graph proof of absence. `webspec-index --help` failed because the executable is unavailable; its automated route/anchor machinery was not run and no tools were installed. The principal links were checked directly against fetched primary HTML, recorded in `SPEC-ANCHORS.json`. Existing broader cycle-policy research is referenced unchanged. Neither source ordering nor passing one engine's candidate is enough to answer that question.
