# Numeric admission component

## Result

The selected lexical and decoded-unit model is kernel checked against an independent digit/fraction/exponent grammar and the accepted decoded-name reference. The complete retained native tokenizer is replayed against it. This closes useful model-level numeric entry, maximal lexical prefix, token choice, exact suffix and selected unit-summary composition obligations. It does not close the complete tokenizer or native arithmetic/representation proof.

The baseline is the original numeric arithmetic with the corrected identifier-start guard. Its known compensated-exponent numeric-value failures remain intact. The subsequent rare-value repair is outside this seal.

## Original target ledger

1. **Entry:** Actual digit/sign/dot dispatch conditions imply a nonempty numeric source and nonempty first integer-loop input. A leading dot legitimately allows zero integer digits.
2. **Prefix:** Three digit scans consume maximal literal decimal prefixes. Separate guarded grammar functions characterize fraction/exponent admission. Incomplete `e`, `e+`, `e-` and a dot without a following digit remain in the suffix; subsequent identifier consumption may turn those suffixes into Dimension units.
3. **Reads/progress:** Every digit-loop recorded read is in bounds. Fraction/exponent short-circuit guard reads and body entry/read shifts are proved. Exact cover and positive total count follow under actual entry. Native machine arithmetic and heap/codec/metadata normal completion remain explicit.
4. **Type/sign/token:** Syntactic integer/type and outer sign are preserved. Native percent-first selection equals identifier-first reference because a leading percent cannot be a corrected identifier start. Percentage payload division ordering is retained.
5. **Unit/boundary:** The accepted complete name/escape output reference composes with the numeric prefix. Exact total count, remainder and return boundary follow. Temporary interior UTF-8 positions are retained; borrowed/owned state is not an independently specified universal ownership theorem.
6. **Dependencies:** Exact native unit classification and constants are extracted. The model proves case-folded lookup equivalence, including combined LH/root-LH bits. Both complete Dimension-only sinks are source-bound. Numeric units are decoded before classification; inert string/comment/URL controls are included in native replay. Whole declaration/graph execution is not proved.
7. **Payload:** Ordered floating expression construction and the syntactic int option/clamp branch are represented. Original numerical fidelity is refuted, not assumed. General saturation correctness, Rust FromStr admission/correctness and IEEE/compiler semantics remain open.
8. **Fresh suffix:** One numeric token's selected summary and next suffix are derived from actual entry and unit decoding. General tokenizer restart equivalence, other token paths, block handling and whole custom-property graph admission remain open.

## Evidence and sensitivity

The source-only replay builds full retained cssparser and the actual classifier/scanner. Ninety targeted native cases include 81 numeric rows compared directly to the Lean execution on seven observations: token kind, byte count, decoded unit bytes, dependency flags, explicit sign, syntactic integer and remaining bytes. Nine additional rows check scanner controls. Both observations and native payload bits are retained in replay output.

Four native mutations compile successfully and change a retained observation: discarded sign reporting, fraction incorrectly retaining integer type, exponent incorrectly retaining integer type, and missing LH dependency bit. Corresponding Lean mutations also compile and produce false semantic witness checks. These are sensitivity gates for the selected observations, not exhaustive mutation coverage or an automatic proof of source translation.

No new browser/build results are claimed here. The historical source discovery/spec material and arithmetic witnesses are retained in `inputs/static`. Root's separate native repair and browser acceptance must stay separate.

## Acceptance boundary

All eight original targets retain their actual model/native/provider limitations; none is silently replaced by a finite case count.
