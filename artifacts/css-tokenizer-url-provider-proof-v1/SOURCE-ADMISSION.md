# Source correspondence and admission

This is a source-bound mathematical component with executable correspondence checks. It is not a compiler-verified refinement of Rust, an unconditional UTF-8 memory-safety proof, or a proof of every public parser history. The full retained Rust bodies and their dependencies are compiled; the Lean models are manually related to those bodies.

## Exact source

`SOURCE-PINS.json` identifies complete files. `SOURCE-BINDINGS.json` contains 44 complete definitions, regenerated by strict unique-name extraction. The checker requires the compiled vendor copies of those files to equal the retained source. The tokenizer includes the earlier bad-URL, identifier-start and numeric repairs. The parser includes depth-limit recovery. No native changes are proposed here.

The direct driver compiles the complete cssparser crate and actual dependency sources. Its only appended wrapper exposes lexical tokens and private state and clears pending-block state between raw token requests. This deliberately exercises the lexical provider seam; it does not simulate public `Parser::next`, token caching, reset, speculative parser rollback, or automatic block skipping. Both ordinary dispatch and the actual `fast_match_byte` procedural macro are compiled. The unrelated `fast_match_color`, serde and allocation-accounting features are excluded.

## Independent references

`native/reference.py` implements normalized scalar CSS Syntax algorithms and full escape/remnant consumption, without reading native outputs. It retains raw offsets to compare source location. For quoted URL delegation it records the independently calculated opener endpoint and permits only that exact native rollback tuple. Other Function divergences fail; two deliberate output corruptions test this rejection. Its lexical domain is the fixed URL/name/string fixture domain, not a claimed complete tokenizer.

Lean has independent classifier tables, bulk whitespace decomposition, slash-parity boundary selection, full-escape bad-remnant semantics, independently structured name/string references inherited from accepted components, and a backward whitespace summary versus forward native counters. `URLDispatch.providers_refine` shares `finish` between its two sides: it composes provider results; it is not an independently implemented full CSS dispatch algorithm. The normative quoted-cursor relation is the separately proved completed observation relation.

## Native and environment premises still required

- Complete native Rust source is manually extracted/bound, not mechanically translated to Lean. Rust/LLVM, Rust standard library operations and procedural macro correctness are trusted.
- Native input is a valid Rust string at an admitted character boundary. Shared decode/encode primitives and canonical Unicode validity are not established by list-shape proofs.
- Normal return from allocation; object and source-buffer lifetimes; exact Cow ownership; unsafe slicing and vector capacity are outside the list model.
- `usize` and line/UTF-16 arithmetic must have headroom. Natural-number bounds do not prove all machine arithmetic checks on arbitrary platform-sized strings.
- The body metadata and exact native raw-slice refinements above remain explicitly unproved universal source bridges. No claim of native memory safety or whole tokenizer correctness follows from the 57 observations.
- Direct lexical events are covered. Public iteration/cache/reset, speculative observer persistence, stylesheet caller admission, downstream CSSOM serialization and browser rendering remain separate components.

The prior bad-URL repair is a retained baseline, not a new defect. No new observable browser bug is claimed by this capsule.
