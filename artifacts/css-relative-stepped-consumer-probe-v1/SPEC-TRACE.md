# Stepped zero-basis and consumer boundary

Fresh primary sources were fetched on2026-10-28. Anchors were checked against the captured HTML. webspec-index was unavailable in PATH or ~/.cargo/bin; direct official-spec retrieval supplied the content. Searchfox supplied the easing source, with the exact branch delta separately captured.

[Argument ranges](https://drafts.csswg.org/css-values-4/#round-infinities) make a zero step/divisor produce NaN for round/mod/rem. [IEEE handling](https://drafts.csswg.org/css-values-4/#calc-ieee) propagates NaN through enclosing arithmetic and sign, censoring only the top-level result to zero. [Simplification](https://drafts.csswg.org/css-values-4/#simplify-a-calculation-tree) requires enough information to evaluate a function; [computed values](https://drafts.csswg.org/css-values-4/#calc-computed-value) provide contextual unit conversion. Equal relative units alone do not exclude a zero basis.

REACHED for the original finite width expectations: at bases10/0/10, mod/rem widths are20/0/20; nearest-round widths50/0/50. The original division controls expect11/0/11, while cancellation and zero-product retain10. For ordinary integer z-index, calc(1 + sign(op(3em,2em))) is2/0/2; the separate sign(1em) control is2/1/2. These differ because a zero divisor generates NaN, rather than an ordinary zero intermediate.

[Step easing](https://drafts.csswg.org/css-easing-2/#step-easing-functions) uses positive integer counts. [Cubic Bézier](https://drafts.csswg.org/css-easing-2/#cubic-bezier-easing-functions) and [linear easing](https://drafts.csswg.org/css-easing-2/#linear-easing-function) consume numeric parameters. [Math range checking](https://drafts.csswg.org/css-values-4/#calc-range) must be distinguished from literal rejection. The steps(1,end) zero-state literal is a comparison calibration, not a settled assertion about all contextual easing entry points. All easing rows remain diagnostic, particularly WAAPI target/context policy and keyframe invalidation. Unsupported=false, an empty specified declaration, or an API exception is recorded, never promoted into acceptance of the native repair.

The current branch retains resolve-None rejection in all three easing parsers and context-free conversion. The bounded source prediction is that deferring the stepped node can turn formerly admitted scalar expressions into rejected easing values. This is a native integration risk requiring actual original/candidate comparison; it is not a completed proof of every CSS or WAAPI policy. Accepted contextual subgrid handling is a separate consumer and must not be described as having the same retained rejection merely from older source.
