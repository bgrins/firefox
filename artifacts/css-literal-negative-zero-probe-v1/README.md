# Literal negative-zero parser probe

This is an unexecuted six-callback research fixture, not a native min/max fix or a confirmed browser defect. It follows the scoped tie-ordering dismissal in `css-minmax-signed-zero-audit-v1`; that immutable audit remains historical.

[CSS Values 4, signed zero](https://drafts.csswg.org/css-values-4/#calc-ieee), observed in the 24 August 2026 Editor's Draft, treats literal zero spellings as positive zero. Arithmetic can generate negative zero, and nested calculations retain it. The observer maps positive zero to opacity 0.75 and generated negative zero to 0.25 by taking its sign, reciprocal, and sign again. NaN reaches top-level zero instead, so it cannot masquerade as either expected result. Each callback separately verifies declaration support and a 0.375 calibration.

The inspected parser does not normalize literal negative zero at the numeric-token-to-math-leaf boundary. Searchfox `consume_numeric` applies the input sign to its zero-valued accumulator and casts the result to f32. The local, previously changed `CalcNode::parse_one` passes `Token::Number.value` directly into `NoCalcNumber::new`; its constructor and accessor preserve the value. The length path likewise passes the token value through `parse_dimension_with_context`, `parse_dimension_with_flags`, and `NoCalcLength::new`. No sign-clearing step was identified along these paths. These source observations predict that literal negative zero can be observed as negative inside math. An actual branch observation is still required; no complete parser-to-layout execution proof is claimed.

The indexed `signed-zero.html` already tests literal `-0` as negative, including reciprocal/sign observers around min/max. A direct local existence check and narrow Searchfox search found no `signed-zero.html.ini`; the indexed css-values directory metadata only sets the random-function preference. Thus no per-file expected-FAIL annotation was found to explain those expectations. This does not certify all inherited platform configuration or assert an upstream WPT verdict.

The six authored cases compare positive literal, negative literal, and arithmetically generated negative zero for numbers and pixel lengths. There is no native patch, model, build, browser run, owner, or accepted ID. A later authorized observation must distinguish assertion mismatches from parser/setup failures. Deduplication of this distinct literal-normalization lead remains incomplete; the previous min/max ordering lead remains dismissed.
