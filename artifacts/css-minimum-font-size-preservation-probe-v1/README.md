# Minimum font-size used-size preservation harness

This is an unrun artifact-only Gecko preservation harness, not a new accepted bug or native result. Two distinct pages use explicit off/on preference metadata and the matching PREFS.json profiles. Each has two calibration callbacks FIRST, then five scheduling comparisons (omitted, explicit16px, inherit,100%,calc(100% + 0px)). Four phases change monospace→serif→Japanese monospace at CSS zoom1.25→English monospace at zoom1. Both minima and font-size defaults are explicit; no preference is changed by page script.

Each comparison reads the target registered length first, then records immediate and three-animation-frame text width/height and computed values. All phases are collected before assertions. The target uses the existing raw typed-attribute→registered em scheduling route plus registered ch demand. The ordinary sibling has the same specified size/family/language/zoom but no typed-attribute scheduling declaration. A third sibling uses the ordinary sibling's computed pixel size. Equal computed size alone is insufficient: the actual sixteen-zero geometry must agree, and the target registered ch must match the ordinary/pixel references directly. No proportionality between ch and minimum-clamped text geometry is assumed. Kerning, ligatures and optical sizing are disabled to reduce unrelated typography variation. No external fonts or fixed glyph dimensions are invented. The ordinary registered references can share a common metric defect; these comparisons test ordering/preservation, not complete metric correctness.

Calibration compares8px text geometry to24px/32px ordinary references with minima on, or8px with minima off;48px text must remain distinctly larger. Thus a missing preference override is not silently treated as successful on-mode coverage. These are geometry controls, not a proof that every platform font preference has been neutralized. The two language groups are explicit and other languages are outside this page.

The baseline ordinary/reference comparisons preserve current Firefox behavior without treating the earlier observed13px generic-family compatibility behavior as a new normative bug. REFERENCES separately pins the root's default-preference System Firefox48 matching registered-length controls (six consuming properties × four size forms × two sizes), and the distinct keyword-family48-observation capsule (24 unique combinations, both CSS1Compat) plus known family13px triage. The first set checks registered length, not every consuming property's fallback. Those default-preference observations are historical references only: neither they nor this new harness are a PASS result for the current candidate. The new explicit-pref profiles are different experiments.

SOURCE.md identifies the actual raise-only clamp and the unresolved pre-ensured-ratio reachability question. There is no fabricated browser trigger for that state. CSS zoom is tested; browser full/text zoom is not. This does not replace the original21-callback matrix or establish complete scheduler progress. Browser crashes must remain page crashes; do not infer an individual callback outcome from missing events.

No live files, browser, build, Git, index or canonical state were changed. INTEGRATION.json provides exact resource/metadata hashes for a future reviewed owner. A genuine WPT manifest/lint and fresh original/candidate execution remain pending; JavaScript syntax and inert callback roster are checked only. No runner is enabled here.
