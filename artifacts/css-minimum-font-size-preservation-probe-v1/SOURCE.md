# Native ordering and reachability

The source review found that constrain_font_size_if_needed only raises mFont.size. Gecko_nsStyleFont_ComputeMinSize reads language preferences and the minimum ratio; computed mSize is distinct. Hence getComputedStyle(fontSize) alone cannot detect a stale used-size clamp. Searchfox reads fb26fa/03cbe6/142f87 authenticate the native functions and ratio's empty generated prerequisite set. Relevant source: https://searchfox.org/firefox-main/rev/28b7a7bffb5f82828143d9ad63839ad263b598be/layout/style/GeckoBindings.cpp#1241 . The current draft restores XLang before the early effects and applies Family then XTextScale then minimum ratio then FontSize. These harness bytes do not certify that draft.

The actual target route is registered --len:1em plus appearance:attr(data-length type(<length>),auto), with raw attribute var(--len), matching the existing original variable-length failure. A registered --metric:1ch additionally consumes actual font metrics. Reference siblings have no typed-attribute/registered-em scheduling declarations; their independent registered ch values are recorded directly. No relationship between ch units and minimum-clamped glyph geometry is assumed. Font-size forms and family/language/CSS-zoom changes are real browser inputs; no internal state is forged.

Pre-ensured minimum-ratio before retained Family is NOT a demonstrated browser route. The author reports normal traversal precedes the ordinary priority sweep, the normal FontSize dependency orders XTextScale/Family before ratio, and the facet rejects already ensured Size/XTextScale. Other prototype paths remain unproved. No case here is labelled as exercising that internal state. If a reachable input is established later, add it as a separate case rather than rename these cases.
