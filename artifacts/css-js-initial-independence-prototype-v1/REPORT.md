# JS initial-value independence prototype

This is an inactive, uncompiled native inspection prototype, not a registration fix. The seven-path patch adds a callable normal-grammar inspection entry point and recursively examines the resulting actual Stylo types. It does not change JS registration, CSS-rule registration, initial caching or ordinary declaration behavior. It must not be applied as a finished fix: the returned audit is evidence about the admitted representation, not a proof of computational independence.

## What is concrete

`SpecifiedValue::inspect_script_initial_value` invokes the existing parser with `AllowComputationallyDependent::Yes`, then inspects the owned result. Independence findings cannot make the parser retry another syntax alternative. The result retains both the actual `SpecifiedValue` and its audit. The callback is available without cfg(test), so a real Gecko host test could exercise it after a controlled native build.

The visitor covers every current `SpecifiedValueComponent` variant and every current numeric AST operation. It visits all list members, all eager math operands, transform matrix entries and operations, recursive transform lists, gradient stops and geometry, cross-fades, image-set candidates, color mixes, contrast colors and relative-color origins. Length conversion to `LengthPercentage` exposes the stored tree without computing a scalar. Five small `as_calc` accessors are carried explicitly from the earlier sealed collector research; they are not assumed to exist in the live build. Number already has its accessor.

Absolute and physical viewport lengths, percentages, literal scalar values, identifiers, strings, URLs and symbolic currentcolor retain their supported context-free classification. Font/container/logical viewport leaves expose contextual demand. System-color computation actually passes the builder's color scheme to the device. Equal independently computed color light-dark branches can avoid that branch-selection demand; their equality is checked on actual computed color representations, not text. The existing image light-dark(none, none) control is retained. Other image light-dark cases are explicitly unresolved, as are opaque image forms, random state and cases where context-free relative-color computation fails.

`element_context` and `unresolved` are independent bits, joined across children. No caller maps unresolved to success or failure. A child with unknown semantics cannot disappear when other children are understood. The visitor is deliberately an inspection operation, not a syntax-name whitelist or a parser rejection mode.

## Exact remaining integration blockers

1. **Admitted AST versus erased history.** Numeric parsers run `simplify_and_sort` before returning these trees; color parsing also performs context-free simplifications. This visitor can describe retained contextual reads, but cannot establish whether the normative independence test permits every erased dependency. A zero or cancellation may no longer carry the original unit. A successful all-clear audit must not become an admission certificate until this correspondence is resolved. If dependencies must survive those simplifications, record them transactionally inside the successfully admitted parser branch; reset records on failed alternatives/internal backtracking. Scanning raw text or collecting all failed alternatives is not an equivalent substitute.
2. **Initial cache must preserve selection.** `PropertyRegistration` currently stores the token initial, descriptors and URL data. `compute_initial_value` reparses those tokens with `AllowComputationallyDependent::No`. Even a correct JS-only normal parse/check is insufficient if this later parse can reject the chosen branch or choose another. The concrete integration is an optional owned validated specified initial on the registration (or an equivalent script-registry record), populated only after successful JS validation and used directly by initial-cache computation. CSS-rule registrations retain their existing path until their policy is resolved. Keep the original descriptor/token text for CSSOM; preserve name/duplicate/error ordering. This prototype returns the owned AST needed for that handoff but does not add the field or activate validation.
3. **Not all dependence is resolved by a Context parameter.** Physical viewport inputs are globally dependent yet permitted by the registration definition. Some color-function computations need context for numeric inputs; failure of `to_computed_color(None)` is therefore recorded as unresolved, not automatically rejected. Direct unequal image light-dark has a separate computed-stage policy question. The source uses `ld.compute(context)`, but the design's spec caveat still applies. Unhandled cases cannot be silently certified or rejected.
4. **Native compilation remains necessary.** Rustfmt and exact patch transport pass; no native typecheck or execution has been performed. The new module and accessors have not been linked into Gecko. These checks are not a Rust refinement proof or canonical Lean coverage.

## Provider-default implications

The root-reported completed provider v4 experiment repaired the readiness cases but changed four color observation messages: invalid/missing defaults that previously followed target color scheme now use the globally cached initial. This JS-only prototype cannot settle the separately disputed CSS-rule initial-value policy and cannot justify accepting that change.

The four observed color changes come from the ordinary post-graph IACVT handler changing from target-context recomputation to the cached initial. Restoring that ordinary handler's previous computation is a separate, narrower preservation step; these observations alone do not prove that every recursive provider default needs a wider resolver. The boundary below applies specifically when a recursive default actually needs context not yet ready.

`substitute_internal` currently borrows substitution storage and `computed::Context` immutably and returns only success or invalidity. `ensure_prioritary_property` requires the mutable cascade, declarations/cache, context and attribute tracker. Calling it inside recursive default selection would violate that ownership boundary; the actual failed v3 build already illustrated the borrow lifetime constraint for ordinary mutations.

If CSS-rule defaults must recompute against the target, introduce an explicit contextual-demand outcome at this existing substitution/completion boundary. Release borrowed substitution results/state, ensure the requested prioritary property, and retry without losing cycle-participant marks or duplicating taint/tracker effects. For the observed light-dark case the demand is ColorScheme; that does not prove all legal initial forms need only ColorScheme. Readiness must be checked before target-context computation, and a genuine color-scheme/default cycle must remain visible. Simply restoring `compute_initial_value(context)` inside the recursive cached-default helper recreates the early-context hazard. No new synthetic edge or type whitelist is proposed here.

## Validation and provenance

`check.py` authenticates captures/references, checks Rust formatting and applies/reverses/reapplies the exact seven-path patch in disposable scratch. Run 3e6b91 exited 0 and removed its scratch. No live source, index, epoch, build, browser, staged artifact or canonical model was modified. Source bodies in `base/` are authenticated local captures. `SOURCES.json` explicitly distinguishes equality to captured upstream from mere local identity; several accepted local source changes differ from upstream. Searchfox discovery was performed before local capture; initial sandbox DNS failure was followed by successful read-only network requests.

The current official JS algorithm parses before testing computational independence, and syntax alternatives are ordered. The source inspection and integration recommendation follow that ordering. The official CSS-rule descriptor wording remains separately disputed. See the sealed design's policy references and the primary algorithm at https://drafts.css-houdini.org/css-properties-values-api/#the-registerproperty-function.

Useful next host controls are Canvas under color-first versus identifier-first syntax, a failed color-list alternative followed by a successful identifier-list alternative (Canvas blue), same-name retry after rejection, late dependent list members, nested gradient colors/currentcolor, numeric transform entries, all six container units, and retained-vs-erased math dependencies. The existing API21 remains a baseline, not proof of all these cases. No browser outcomes are asserted by this prototype.
