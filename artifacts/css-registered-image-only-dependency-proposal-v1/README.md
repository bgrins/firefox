# Image-only dependency candidate

This standalone three-source patch applies to the frozen committed clean preimages. It adds dependency scheduling for registrations whose syntax contains Image and lacks the existing COLOR eligibility. It does not apply the new color-union refinement to COLOR-eligible registrations. It has not been compiled or run as an isolated variant.

The combined V5 prototype built and passed the existing 42-case suite; its frozen runtime and independent restoration review are referenced here. That evidence supports the copied helper implementation and its actual tracker lifetime types, but does not establish this variant's behavior. The three supplemental absolute-color image unit probes require the new 45-case baseline and trial.

`native.patch` is the complete base-relative patch. `V5-DELTA.patch` shows the narrower difference from the compiled combined prototype. Only cascade.rs differs from V5; provider and specified-value/classifier postimages are identical. The provider preimage is committed 8a4, not the held 2675 working overlay. This package changes neither checkout nor execution-owner restoration policy.

`registration_needs_image_dependencies` tests the complete registration syntax: at least one Image component and no COLOR dependent-type eligibility. Repetition remains attached to the original component; the selected parser still honors syntax clause order and list rules. Pure Image and Image/identifier or Image/length registrations qualify. Image/Color registrations remain on the original COLOR path.

The same predicate controls all three changes:

1. `find_non_custom_references` retains its original length handling and complete COLOR block verbatim, then admits the additional image class with the existing deferral marker. This includes absolute-color images with font-relative lengths and no var/attr reference.
2. Traversal captures eligibility before reference walking. Only an eligible custom node enters the entire new COLOR_SCHEME removal, selected-substitution/AST preparation and edge-refinement block. Existing singleton, lowlink and self-reference guards remain. Other nodes have no prepared value and follow their original application route.
3. Only an eligible cyclic custom node can add the post-edge dependency from its actual invalid/default initial selection. The hook remains before SCC popping. This covers image nodes already admitted through var/attr as well as newly admitted direct images; restricting admission alone would miss this scope boundary.

Existing unit flags and reference walking are retained. Removing the scheme marker does not clear font/line-height flags. Parsing and selection occur before the dependencies close; computation of the same retained AST occurs afterward. The recursive image classifier still handles system/light-dark colors inside gradients, cross-fades and image sets, including every component visited by current computation. Non-color selected alternatives and computed-parent copies remain distinguished from specified initial recomputation. Existing CSS-wide handling, invalid-handler paths and attribute-taint behavior are inherited unchanged from V5. This does not claim that the older contextual-attr or all conservative unit-inventory issues are repaired.

No COLOR-eligible node directly enters this variant's new preparation or default-classification path. This source boundary is not global outcome isolation: eligible image nodes may share custom/priority SCCs with COLOR nodes, and their corrected edges can affect those consumers. The shared application extraction remains in the provider even for noneligible calls; it preserves the original operation path, using V5's two independent tracker/input lifetimes. Isolated native validation is still required.

The A-only alternative and this image-only alternative each include their necessary helpers against the committed base. They overlap in helper additions and traversal edits. They are standalone alternative patches, not a conflict-free two-commit stack; merging or sequential cherry-picking requires reviewed reconciliation and further testing. No necessity or minimality theorem for a shared refactor is asserted. This version retains the already reviewed common helpers rather than duplicating implementations to conceal overlap.
