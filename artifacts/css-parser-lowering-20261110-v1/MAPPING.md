# Parser-to-effect lowering boundary

All nineteen imported Lean dependencies are unchanged copies of the preceding
number-transfer artifact, pinned in PRESERVED.json. This includes the data-only
typed ParserIR, old first-order interpreter/lowering, old effect interpreter,
number tree, independent number reference relations, and existing bridges.
The original CSS Syntax snapshot and exact clause map are retained and checked.
The canonical standalone library and prior artifact are not edited.

The new backend adds only old-program embedding, complete-state read/write, and
sequencing. Pure return is an embedded old pure program. Its continuations are
ordinary Lean functions generated by lower; no new arbitrary-function fields
are added to the source parser AST. This is an effect backend, not a new
first-order serialization format or native executable compiler.

| Source parser | Lowered effect behavior |
| --- | --- |
| legacy | Reuse FirstOrder.lower under old-program embedding; return its value as present |
| take | Read once, test the unchanged typed predicate, roll back the complete state on EOF/mismatch |
| scan | Read the current state; invoke the old scanner with exactly remaining input.length; preserve the old error flag |
| nonempty | Run child; reject empty character-list output inside a complete-state transaction |
| pair | Sequence left then right; return their ordered pair; restore the pre-left state on any failure |
| right | Sequence left then right; return the right value; restore the pre-left state on any failure |
| optional | Use the child's atomic failure contract, converting absent value to successful optional absence |

The generic theorem preserves every successful value and complete resulting
state. On failure it returns (none, originalState). This atomic failure contract
is an explicit strengthening because the source interpreter exposes no state
when it returns none. It is proved, not inferred from source erasure. The
observable_lowering theorem separately erases backend failure state and recovers
exactly the source interpreter's existing Option (value × state) result.

Transaction theorems cover arbitrary backend programs and initial states,
including an already-true error flag and a child that raises an error before
failing. A snapshot is the complete State record; it is not a cursor-only mark.
Maximal scanning reuses scan_matches_length_bound and FirstOrder.scan_lowering.
No finite cap independent of remaining input or additional loop fuel is chosen.

The number instance preserves lexical parts, remainder and prior error through
number_parts. executeNumber maps that result through the unchanged, separately
proved numeric projection; number_execute_equal and number_relation compose
with the independent NumericResult relation. StartsNumber remains explicit in
number_ready. The two off-domain observations are model behavior, not accepted
CSS caller inputs. Exact significand/scale and optional sign remain mathematical
values; machine floating point is not modeled.

No number-specific opcode, new source parser constructor, widened primitive
vocabulary, serializer, JSON decoder, or prose translator is introduced. Numeric
projection is not itself lowered. This closes a previously missing reusable
lowering edge, rather than removing an unchecked compiler that was already used
by the number artifact. The earlier translator refusal and development-target
protocol are preserved.

The CSS source is unchanged revision c410ee5e4d2afe6d8b2e8ce53723b8d1eb3b5b67;
SOURCE.json and CLAUSES.json bind its exact consume-number, digit, and caller
clauses. The compiler proof is about typed program meaning. The manually reviewed
source-to-tree interpretation and shared pure primitive semantics remain distinct
obligations. No browser/native refinement, allocation/stack/performance bound,
or broader spec coverage rate follows.
