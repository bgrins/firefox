# What the admission proof establishes for cancellation8

This note maps the sealed models to source map4aa5c89d and the pending cancellation8 experiment. It adds no theorem, executable model or native result. Actual candidate owner91300 is root-owned; no moving native files were read.

`FontUnitAdmission.finite_history_consistent` proves, for every finite history of the model's register/unregister/destroy transitions, that each active effect's flag owner remains marked. `member_has_animations` then derives the exact logical target's membership query. `registered_normal_hint_admitted` concludes admission for any remaining member with **normal=true and hint=true**, for either value of the ordinary retained-style flag. Its conclusion is a Boolean admission, not an effect task or converted value.

For the intended trace, root disturbance registration/removal and the later child effect registration can be represented as separate events with distinct effect/target keys. The theorem covers the resulting child member once registration is complete. It does not say Cancel generates/delivers a root-font hint, nor that the child was already registered during eager SetKeyframes conversion. The native construction path can call UpdateProperties with GetComputedStyleNoFlush before the later relevant-animation membership boundary. Assigning the model's register event to allocation or to every animate() substep would assume the missing correspondence.

Native bridge, still unproved: `KeyframeEffect::UpdateTargetRegistration`/`UnregisterTarget` and Gecko membership must implement the modeled completed boundaries. The candidate `recalc_style_at` queries relevant animations only with `RESTYLE_IF_AFFECTED_BY_WM_OR_ANCESTOR_FONT` outside animation-only traversal. Its `needs_to_recascade_self` decides the normal recascade branch. Existing `process_animations` inserts `UpdateAnimationsTasks::EFFECT_PROPERTIES`; sequential animation processing and `EffectCompositor::UpdateEffectProperties` must deliver that work to the intended `KeyframeEffect::UpdateProperties`. That function rebuilds before comparing values, but admission alone proves none of this delivery chain.

Conversion/publication are a second independent gap. `matching.rs::finish_restyle` updates Device root metrics and produces the ancestor hint. `BuildProperties` reaches `Servo_GetComputedKeyframeValues`; child rem/rlh reads Device root size/line-height. Neither Admission.State nor its imported entry's numeric payload models this conversion, its inputs, a timestamp/revision, installation of mProperties, or output composition. The tests'46/74 values are not theorems of admission.

The already sealed provider model is complementary, not a completed bridge: `provider_current` and `history_read_sound` prove reads correct **inside its coherent transition system**; `stale_finish_no_publication` rejects modeled stale requests. `cancellation_dirties_provider` means executing abstract invalidate makes the provider unavailable, not that native Cancel invokes such an operation. `finish_begin_current` and `discard_then_refresh` establish conditional finite traces, not eventual native delivery. `pseudo_requires_current` and `root_font_independent` separate current-root pseudo reads from root initial-reference reads. The atomic native getters have no modeled revision check, and no existing proof maps their states to this model.

## One conditional next refinement target

Keep task/target/pseudo identity and the distinction between eager pre-flush conversion and later rebuild explicit. Stop at rebuilt endpoint publication; do not claim final compositor output or global progress without a further argument.

If eight cases pass, this is an optional explanation/refinement of the known repair, not a prerequisite for counting another fix. If failures remain, first use the three source-map observation points to identify the first false premise; a missing hint/task or stale same-Device read cannot be repaired by assuming this correspondence. If rebuilt endpoints are already correct, this target is insufficient and output installation/composition is the observed boundary instead. No new Lean implementation is proposed until that evidence identifies the relevant native seam.
