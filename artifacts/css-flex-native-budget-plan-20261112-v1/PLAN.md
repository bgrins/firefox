## Assessment

No counterexample to the original admitted-model BudgetTarget was found. Its strict reverse bound is plausible because actual stored binary64 shares are representable and the source-shaped fractionDelta keeps the share==1 exact-copy bypass. Arbitrary real shares, or always applying rounded multiplication at share 1, would invalidate the contraction needed here. The remaining work is principally execution-prefix induction; original scalar History, a desired final-sum fit, or complete traversal must not be added as caller premises.

The main native-relevant distinction is that the claim bounds successfully acquired signed32 MBP, gap, base and current-size values. It does not establish upstream getter definedness or ideal CSS sums. Entry gap and inner are signed32, with no positivity premise; preserve negative/cancelling inputs and the wrapped-gap admission boundary. The unrestricted model's nonfinite distribution branch also remains present. Only the conditional admitted history excludes that branch by the already checked ProducerTarget; there is no universal finite-factor claim for every native entry.

## Proposed proof dependency order

1. **Entry/reset budget join.** Obtain LineAdmitted from Admitted and RoundAdmitted from the actual native history. Use entry_acquisition_target's prefix theorem for the exact currentSize list. Prove a reset event lookup/induction that records free before and after each subtraction plus the acquired used operand. This discharges acquisition events, fixed operands, initialSpace and count before touching Projection.

2. **Prepared finite-loop inputs.** Use step_shape and prepare_matches for the actual Prepared record. Derive entry domain through source_domain's actual prior-round witness, not an unrelated existential scalar History. In the distributing branch use producer_source, run_correspondence, reset validity/count preservation and existing active-input bounds to establish finiteSum=true, active finite shares in [0,1], and acquired32 mains. Frozen rows may retain arbitrary factor/base/share metadata; do not strengthen their domain globally.

3. **Reverse correction prefix theorem.** Induct on the actual NativeReverse.loop with its exact counter, reports and ordered pairs. The local contraction theorem yields abs(d)+abs(F-d)=abs(F), including share=1 and share<=0. With acquired32 main b, projection_correction_bound yields abs(c)<=abs(d). Derive the induction invariant abs(acc)+abs(F)<=abs(accStart)+abs(Fstart), and the separate delta telescope sum(abs(d))+abs(finalFree)=abs(Fstart). At run entry accStart=0. The invariant is proved from initial conditions, not assumed of an arbitrary caller. Each prefix totalBefore/totalAfter and correction then fit64. Show abs(raw)<=2^60+2^31 and stored32 bounds; skip frozen rows without reading their arbitrary share. No projection-row semantic equality is needed for these arithmetic bounds.

4. **Stage and clamp budget.** Derive all actual stage main values signed32: frozen inputs from history Bounds, active reset values from InputValid, visited reverse rows from project32, unvisited rows from their existing acquired32 bounds. Admitted seed min/max range is preserved by the actual loops. One clamp changes main by at most D=4294967295, with both operands representable. Induct on NativeClamp.loop with actual left/index/acc, proving event-prefix and terminal accumulator bounds against input length. This works for a zero counter or skipped frozen tail without a complete-traversal premise. Derive the input length equals current row/seed length using preserved ordered records.

5. **Original BudgetTarget assembly.** Split NativePass.step's actual distributing/non-distributing cases; in the latter correction accumulator is zero. Assemble every FitsPass field, all fixed scalar bounds, final clamped total, derived count and both prefix conclusions exactly. Projection65's staged row helper may be reused only once checked, but Budget need not depend on its scalar main/flag equality or on unfinished Step/History/Capture. No source/target edits are needed to state the original endpoint.

## Numeric margins and controls

Let F=2^60, N=2^27-1 and D=2^32-1. Exact integer arithmetic gives F+N*D=1729382252481085441, below INT64_MAX=9223372036854775807 by 7493989784373690366. Raw target abs bound F+2^31=1152921506754330624 is also safely within signed64. NUMERALS.json records calculations only; future Coq lemmas must derive these bounds.

Required controls should include empty/all-frozen lines (no last event), non-distributing zero space and zero weight, negative/cancelling MBP and used operands, negative acquired gap, positive and negative whole-space shares, zero shares, positive/negative projection corrections, and the first/last clamp prefix. Keep both optional-report branches; reports do not change arithmetic, and delta's fit follows from the same execution.

The following tempting strengthenings are false or unjustified:

- Fits64 for each independent raw/delta does not bound their sum. Two independently fitting INT64_MAX contributions overflow their sum. Such independent inputs are excluded by the correlated execution proof, not by an added final-budget assumption.
- The prefix bound cannot be established from final cancellation alone. A final zero accumulator says nothing about a preceding large positive prefix; use actual ordered induction.
- Arbitrary real shares in [0,1] do not imply exact contraction. The retained SignBoundary proof exhibits nonrepresentable share 1-2^-100 and F=2^59-1 giving delta=F+1. Its forced Fraction(1) control also overshoots; actual fractionDelta share==1 returns F exactly. These are mathematical mutation controls, not admitted native counterexamples.
- All row factors/bases/shares finite or acquired32 is too strong. SeedValid restricts factor/base only when initially unfrozen, and producer/reverse loops skip frozen rows. A frozen record may have an unconstrained mathematical base/share while its clamped current main is bounded. Report-base or arbitrary metadata safety is not included in FitsPass and must not be smuggled in as a proved global invariant.

## Open boundary and stopping point

The concrete missing proof is ordered prefix safety on native-shaped executions, particularly stored-minus-raw corrections and a no-event final total. No new actual native bug is established by this audit. It does identify why older scalar event equality or a loose floating-error envelope is insufficient for the original tight BudgetTarget. Actual native getter acquisition, factor-origin/ABI realization, memory validity and independent geometry widening remain open joins, not conclusions of this conditional arithmetic proof.

This is a source plan only. Root review and a separately frozen proof proposal are required before any compiler work. Proposal65 remains unchanged and has priority under root's single-lane scheduling.
