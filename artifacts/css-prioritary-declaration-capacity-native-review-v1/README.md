The alias is private to cascade.rs. Indexed identifier discovery and the exact archived candidate-base scan cover head/tail positions, their MAX defaults, per-declaration next index, the pre-push length guard and cast, previous-tail linking, zero initialization, and `apply_one_prioritary_property` traversal. ## Storage cost

Each position contains two scalar indices, so its field storage grows from four to eight bytes. Each Declaration next-index field grows by two bytes. The aggregate position array therefore adds four bytes per prioritary property before surrounding-structure padding. Declaration and Declarations use Rust layout, not a declared external ABI; they are transient private cascade storage, with 64 Declaration slots inline before heap spill. Indexed CascadePriority has an explicit four-byte size assertion. With an eight-byte reference and that four-byte priority, the wider next field fits the usual 16-byte Declaration layout; a four-byte reference gives the usual 12-byte layout in either version. These are layout expectations, not a measurement of the actual production compiler. Rust layout/padding and the enclosing SmallVec must not be inferred solely from field sums. This review does not claim zero memory cost or a measured performance result. The fixed position-array growth is concrete; any per-entry stride increase should be checked with actual compiler layout if it becomes material during native review.

No serialization, FFI field, or externally stored index consumer appeared in the scoped alias search. u32 adds no extra vector capacity reservation and does not change the allocator/resource-failure behavior. It also does not promise that billions of declarations are practically allocatable.

## Matching and coalescing

DeclarationIterator walks each matched block in reverse declaration order and then its rule-node parent; it filters importance and pseudo restrictions, not earlier declarations by longhand winner. The builder consequently sees unrelated color entries before the early font-size. The indexed RuleTree does coalesce adjacent equal `(source.key(), cascade_priority)` pairs. This is pointer identity, not content equality: StyleSourceBorrow::key points to its declaration block, and the ordinary qualified-rule parser allocates a fresh Arc for each parsed rule block. Thus the probe's separate identical filler rules are not collapsed by this particular coalescing path. This is a source-path argument, not an instrumented count of the actual browser's builder input. The indexed source-order bound is 24 bits, above this probe's 65,538 rules.

The exact archived native builder block equals the indexed builder block. Parser/rule-tree and CascadePriority captures are indexed-source discovery evidence, not an assertion that every unchanged local file was separately byte-authenticated. Actual paired behavior remains the end-to-end reachability check.

## Browser oracle and required interpretation

The input capsule retains the original HTML byte-for-byte, one callback and one ending, genuine manifest and pinned testharness resources, no prefs and no expectation metadata. Its two divs have equal-specificity rules in one normal author sheet. Both receive 65,536 matching filler color rules. The early font-size rule is below them in cascade order; the late font-size rule is above them. Each also has width:1em. The width declaration means this is a practical overflow discriminator, not an exact single-index boundary measurement.

All observations are assembled before assertions. The CSSOM count, late font-size/width, both colors must pass before an early font-size failure constitutes the intended witness. A timeout, crash, parse-limit failure, missing callback, failed color/late control, or original PASS is not evidence of the claimed original capacity failure. Candidate acceptance requires the fresh original to reach the early-size assertion with expected control values and the fresh candidate to pass the same complete callback and ending. The original failure message preserves all observed values; a candidate PASS does not itself archive each successful getter value. One callback's PASS is sufficient for its assertions, not general CSS acceptance.

The test uses synchronous style/layout reads deliberately to observe this cascade outcome. The long timeout accommodates its large rule set. It uses real DOM elements rather than a synthetic declaration count and avoids inline-style specificity asymmetry. The prior source/extraction controls and root's bounded spec-limit review remain supporting evidence; neither substitutes for the original/candidate browser comparison.
