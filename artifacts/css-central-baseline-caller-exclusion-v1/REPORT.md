# Exceptional cached-margin caller audit

The proposed combined-text route does **not** expose the outer absolute-positioned negative margin for the requested default-First container families. This is now supported by actual frame-construction and dispatch code, rather than assumed frame shapes. No reachable new-overflow witness was found. The existing arithmetic proofs were not rerun or changed; this capsule adds source correspondence only.

## Explicit First requests

The discovered `GetLogicalBaseline` call inventory has one production caller supplying an explicit sharing group: `nsLineLayout::PlaceFrame`. Its frame is the frame on the line. `nsFrameConstructorState::AddChild` places an absolute/fixed frame on its out-of-flow list and puts a **distinct placeholder** on the in-flow list. `CreatePlaceholderFrameFor` obtains a dedicated placeholder style through `ResolveStyleForPlaceholder`; it does not give the placeholder the positioned box's cached margin property. PlaceFrame does not replace its frame with the out-of-flow target. Its only analogous lookup in the surrounding reflow code is float placement, not this baseline query.

Consequently, `baseline-source:first` on an absolute-positioned box does not by itself cause this explicit First call on that box. The text-parent query uses the no-group overload and the parent's **default**, not its CSS baseline-source preference.

The other margin-synthesis call sites are the base/block/fieldset fallback overrides reached by logical-baseline queries. Direct helper calls with an explicit First in flex/grid/empty-container and table-row paths use **border/content boxes**, not the positioned frame's margin box. Scroll fallback is separate margin-edge code.

## Combined-text immediate parents

|---|---|---|
| Ordinary positioned block, including blockified inline content | `blockify_if_necessary` includes absolute positioning; normal flow construction yields nsBlockFrame. Its default group is Last. | Its direct text-parent query uses Last. The prior full-query analysis applies; this is not the new inverted First case. |
| Flex/grid, including legacy box wrapping | Text construction sets FCDATA_IS_LINE_PARTICIPANT. `NeedsAnonFlexOrGridItem` returns true for that bit; `CreateNeededAnonFlexOrGridItems` moves the items into a wrapper constructed by NS_NewBlockFrame. | Combined text queries the anonymous block, not the outer flex/grid. That block defaults Last and is not the outer abspos-margin owner. |
| Fieldset, including display:flex/grid | `ConstructFieldSetFrame` always creates a separate contentFrame and invokes ProcessChildren with that frame. Flow content uses NS_NewBlockFrame; flex/grid content goes through the preceding item wrapper. A rendered legend is another frame, not bare fieldset text. | The outer fieldset's First default for flex/grid cannot be reached by the direct text-parent query. Ordinary fieldsets default Last anyway. |
| Text input/textarea/list control | `nsTextControlFrame` is a ScrollContainerFrame subclass and explicitly defaults Last. | MathML | MATHML_DATA sets FCDATA_DISALLOW_OUT_OF_FLOW and FCDATA_WRAP_KIDS_IN_BLOCKS for internal/token frames, explicitly including mtext. | SVG text/foreignObject | SVG text/foreignObject and SVG text inline children explicitly disallow out-of-flow. Input buttons/combobox controls derive through ButtonControlFrame from nsBlockFrame. | No author bare-text direct-parent route to a default-First positioned leaf. Native anonymous children need their own frame, rather than becoming the outer frame's text. |
| Media/date-time controls | HTMLMediaElement::BindToTree and HTMLInputElement::SetupShadowTree attach UA shadow roots. The datetime widget imports a div root with display:flex. | Author light-DOM text is not the immediate frame child. Widget text is below an element frame; bare datetime flex text follows the anonymous-block rule. The outer control's negative auto margin is not transferred to that inner parent. |

The flex/grid wrapping assertion is not based solely on the wrapper's name: the constructor points to NS_NewBlockFrame and the original child items are moved into its child list. Fieldset and canvas similarly pass the actual new inner frame to child construction. These distinctions also cover ordinary display:contents flattening into these layout parents, since wrapping operates on the resulting construction items.

## Other default queries

`nsLayoutUtils::GetFirstLinePosition` uses GetLogicalBaseline for nonempty flex/grid/table containers; its recursive block search follows normal line children. Flex baseline item resolution excludes placeholders, and grid item handling distinguishes them from grid items. Empty containers use border-box synthesis. The last-line fallback query is specifically on a scroll container, which bypasses the changed central helper. The ruby normalization query is on the first principal child of a ruby text container. The remaining text/SVG calls operate on text frames; the only discovered transfer to an arbitrary text parent is the orthogonal branch analyzed above.

A placeholder is not a route for passing the positioned frame's UsedMarginProperty through these calls. Likewise, a parent-element relationship in the DOM is insufficient: the relevant call follows nsTextFrame::GetParent(), whose immediate layout parent is established by the constructors above.

## Remaining scope, and what this establishes

The specific default-First families requested for the ordinary HTML/CSS combined-text hypothesis are structurally excluded. This substantially strengthens the scoped no-new-overflow argument together with the earlier lower-bound proofs for normal in-flow margin writers. It is not a Lean proof of frame construction, a whole-program proof over every nsIFrame subtype, or evidence that arbitrary callers may safely supply any int32 geometry.

The media/date-time root templates and display rules were additionally read to establish the immediate-parent separation; this is not a complete widget audit. `nsImageFrame::IsLeafDynamic` explicitly permits a UA-widget shadow root, while excluding author shadow roots: that uncommon image-widget case and privileged mutations of native anonymous trees have not been classified in this audit. XUL/native anonymous frame construction and malformed/intermediate frame trees are also not exhaustively classified here. No concrete path in these residual families was found that combines the exceptional cached margin with an inverted First central query. These limits are explicit rather than inferred away from likely frame shapes.

If an unconditional helper contract for arbitrary frame states is required, the prior integer counterexample still prevents a complete int32 proof; the documented first/last offset contract provides no general saturation policy. This audit does not implement a clamp, legacy-raw fallback, or wide API migration. Passing the paired browser experiment remains separate from these source-domain claims.
