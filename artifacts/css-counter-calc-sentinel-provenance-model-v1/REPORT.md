# Counter integer provenance model

Five general Lean laws and four rejected claims, tied to the revised two-file candidate. This is implementation-specific support, not new normative CSS coverage or a whole Rust/C++ pipeline proof. Author replay succeeds with the pinned Lean toolchain, two threads, only standard axioms and no sorry. Temporary negative sources are removed; no new compiler target, canonical-library change, native/index mutation or browser run.

The model distinguishes inline Integer from boxed math. A boxed value contains its already resolved i32 result for one computed context; it does not claim to evaluate CSS math or prove floating-point normalization, rounding, context acquisition, grammar or parsing. InRange captures the native return type's signed32 domain. The four Mode constructors encode successful increment/set/reset/reversed-reset parser contexts, not rejected grammar.

The actual parser clamps authored inline MIN but leaves math boxed; omitted reversed reset creates inline MIN. CounterInteger then preserves an inline MIN and clamps every other computed value to at least MIN+1. `authored_normalizes` characterizes this composition for either representation; `authored_preserves_nonmarker` proves preservation of every other valid result. `parsed_domain` proves full output range and that MIN is returned exactly for omitted reversed reset among those successful CSS parser inputs. `marker_observation` proves that inline get()==MIN and computed MIN agree for every modeled representation; with the unchanged reversed flag, this binds the omission check used by GenericCounterPair serialization.

`raw_roundtrip` proves compute(fromRaw(n))=n for every signed32 n, including MIN. This is essential for the two geckolib mapped-attribute constructors and ToComputedValue inverse; it is NOT an authentication theorem. The negative controls reject boxed-authored MIN preservation, clamping away the automatic marker, claiming raw inverse excludes MIN, and structural recovery of a boxed expression after numeric inverse. Numeric roundtrip does not preserve an AST or establish how a computed value was obtained. Copies/discrete selection can retain a supplied valid-domain value; no theorem here infers that all future raw producers are in the CSS parser domain.

The provenance audit found a real source counterexample to the former parser-only premise: ordinary ol start=−2147483647 produces predecessor MIN through defined start−1 arithmetic, with is_reversed=false. HTML integer parsing admits this input. li valueMIN separately supplies a valid raw SET value. Both paths construct specified pairs in servo/ports/geckolib/glue.rs, outside the earlier style-only search. They also exposed the old one-file candidate's missing type adaptations. Revised landing-v2 uses CounterInteger::from_computed_value in both places, preserving raw values exactly and correcting the misleading comment. No new constructor assumes that raw MIN must mean omitted CSS reset.

The checked mapped arithmetic instance confirms MIN+1 and its predecessor both fit signed32 and the raw lift retains MIN. Native IsContentBasedReset still interprets RESET/MIN as automatic regardless of reversed. That mapped alias is a separate unaccepted lead with four prospective exact-rendering cases, not a repair or browser finding in this model. Inputs start=MIN or reversed start=MAX have additional preexisting C++ arithmetic questions and are outside that witness.

Exact source hashes are bound in INPUTS/REFERENCES; SOURCE-MAP names each native operation and limitation. The prior one-file proposal/review remain historical HOLD evidence. A real full Stylo/Gecko build, independent source review, and normalized paired23-case landing/controls execution remain required for the revised repair. This model neither closes generated-producer completeness nor changes the accepted bug count.
