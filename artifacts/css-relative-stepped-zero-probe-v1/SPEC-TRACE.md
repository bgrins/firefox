# Finite relative stepped operations at zero basis

Source hypothesis: premature same-unit folding can discard the fact that a relative divisor/rounding interval becomes zero. This is distinct from the held Sign fold and atan2 lead, and from accepted finite remainder arithmetic or infinity repairs. DEDUP.json captures related ledger entries; the held Round infinite-value/contextual-step proposal addresses a different branch. No accepted bug count is added.

The current [CSS Values argument-range rules](https://drafts.csswg.org/css-values-4/#round-infinities) make round/mod/rem produce NaN when the second argument is zero. [IEEE handling](https://drafts.csswg.org/css-values-4/#calc-ieee) propagates that through an enclosing sum and censors only the top-level result to zero. [Simplification](https://drafts.csswg.org/css-values-4/#simplify-a-calculation-tree) requires sufficient information for a function evaluation; the [computed-value stage](https://drafts.csswg.org/css-values-4/#calc-computed-value) supplies relative-unit ratios. Same units alone do not establish a nonzero ratio.

For width:calc(10px + mod(3em,2em)), font10px resolves the operands to30px/20px and yields20px. Font0px makes the divisor0px, so the whole expression produces0px. Folding mod to1em first incorrectly predicts10px at zero. rem has the same positive-input witness. round(nearest,3em,2em) resolves the tie upward:50px at font10px, but0px at font0px; premature4em predicts10px at zero.

Verdict: REACHED for these finite positive-coefficient conditional expectations. Browser support and values remain unobserved here. The probe tests em/rem/cqw with an explicit zero/nonzero basis and independently resolved px expressions. Division, cancellation and zero-product are separate controls: relative division must preserve0/0; unit-preserving cancellation/product can legitimately remain zero lengths. It does not claim that all algebraic cancellation is invalid, or that all initial-value independence cases are adjudicated.
