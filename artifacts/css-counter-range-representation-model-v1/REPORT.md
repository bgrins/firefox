The proposed implementation admission invariant makes resolved export total and equal to inclusive membership, while preserving the distinction between inline and boxed storage. The old inline-only accessor fails for an admitted boxed constant range. Validating only pairs with two finite endpoints is insufficient: an unresolved finite endpoint can otherwise pass beside an infinite endpoint.

`Range.lean` deliberately separates three layers:

- `IntegerRep` distinguishes inline integers, boxed values with a supplied resolved integer, and unresolved values. `inlineGet` and `resolve` model the different accessor contracts. They do not evaluate a native calc tree.
- `admitted` independently checks both finite endpoints and then finite/finite ordering. This is the proposed implementation publication invariant. It does not state that all unresolved or context-dependent CSS expressions are normatively invalid.
- `SemanticRange`, `ordered`, and `member` define representation-independent integer endpoints and inclusive membership. An infinite lower endpoint is unbounded below; an infinite upper endpoint is unbounded above. Unresolved storage has no decoded semantic range, rather than being assigned false membership.

Eight audited results are retained: admission iff successful decoding with ordered finite endpoints; every finite endpoint resolves; resolved export equals semantic membership; admitted export is total and correct; representation-independent export; both finite endpoints are inclusive; boxed resolvability does not imply inline storage; and the general admitted boxed n/n counterexample to old export. One private bound-decoding helper supports the formal vocabulary. No previously credited project proofs are copied or re-registered.

Ordering is part of admission, but export correctness itself only needs successful decoding.
