# Computed defaults versus specified initial recomputation

This small extension isolates the preservation gap found in the standalone ColorScheme draft. An invalid parse does not determine whether later work needs the color scheme: copying a computed inherited/default value and computing a specified initial value are different operations.

`DefaultSelection.lean` imports the preceding `Selection.lean` unchanged. Its input supplies the selected fallback route: a computed result, a specified initial value, or absence. A successful parse takes precedence over that route. Computation is deliberately finite: a system-color-like value returns one of two distinguishable results according to a Boolean scheme; an absolute color or identifier is constant. This represents dependency, not actual RGB values or the full CSS parser.

Ten audited theorems establish that copying a computed value is stable, that a specified scheme-dependent initial keeps its dependency, and that scheduling according to the selected route matches evaluation in the requested scheme. A concrete counterexample gives an invalid parse plus a scheme-dependent specified initial: deciding independence from the invalid parse alone evaluates the initial with the old scheme and produces a different result. Four false controls reject universal invalid-parse independence, conflating computed/specified defaults, premature evaluation, and adding a scheme edge to every computed default.

The source bridge is conditional and narrow. The frozen handler copies a parent wrapper on its applicable inherited route but can call `compute_value` on `registration.initial_value` on the non-inheriting/root route. The accompanying source finding traces acceptance of contextual color initial values; the model assumes the caller chooses the correct route. It does not prove that route selection, registration acceptance, root/inheritance conditions, native SCC ordering, invalidation, or any browser endpoint. The corrected scheduler theorem is not a native implementation proof, and it does not license re-evaluating a previously computed inherited value.
