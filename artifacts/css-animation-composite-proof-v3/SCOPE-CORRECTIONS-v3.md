# V3 delivered-readiness obligation

The original SCOPE and addendum remain the approved contract. V2's substitution of historical cache certification for current coherence at admitted equal-setter steps was incomplete; the retained v2 correction text is historical evidence, not this version's contract.

`Admitted` now requires the transition-maintained delivered-ready state at every equal setter. `AdmittedSequence` enforces that discipline recursively. The strengthened `finite_sequence_refinement` carries the full cache invariant, deriving valid offsets from readiness. `every_equal_prefix_current` proves current offsets, consumer properties and active base values both before and after each equal-setter prefix, preserved readiness and exact skip state. `every_ready_prefix_current` covers all additional ready observation prefixes while preserving the invariant for their remaining arbitrary suffix. No admission premise equates a final cache with an expected answer.

Readiness is connected to dispatch. Changed-setter dispatch, changed-default dispatch, context offset delivery and subsequent supplied-style delivery have generic kernel theorems. Raw geometry/timeline input identity establishes offset freshness from the last completed offset certificate. Actual style delivery then establishes current consumer/base state. These results cover arbitrary prior finite actions through invariant preservation; parsing failures preserve state and readiness. Relevant target/style/timeline gates remain explicit.

The native monitor records raw immutable provider versions and the actual completed compute/refresh/update/build/base traces. It admits ready skips only after the required dispatch and matching raw input certificates. It validates independently computed current offsets/properties/base after readiness is established; these outputs are never inputs to admission. The finite native bridge and the universal Lean result are separate evidence, not a verified translation theorem.

All-actions history preservation and pending→equal-skip→delivered-restore diagnostics remain separate. A pending equal skip can occur in the browser and remains executed in the native corpus, but it is not an admitted current-cache step. The scheduler must deliver applicable refresh/rebuilds before claiming a current consumer-cache observation. We prove conditional safety under that external delivery premise, not eventual delivery or unconditional getter freshness. Neither the native getter nor the model inserts an unconditional rebuild.

All 691 v2 cases, all 29 complete definitions, original native/provider source snapshots, optional-null cases and 20 mutation families remain. Nine new cases add ready skips, failures, defaults, absent target/style, null ranged frames, missing timelines and offset-then-style restoration. No production/WPT/build/browser/Git changes are part of this artifact.
