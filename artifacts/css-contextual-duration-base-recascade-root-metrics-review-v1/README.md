# Base recascade and root-relative metrics

The examined branch does not publish the temporary root base style into Device. The direct concern that the new verification call overwrites the document's composed root font size with its unanimated base font size is ruled out by the current call-path separation. This is a source result, not a browser result or proof that recascade has no side effects.

`Gecko_UpdateAnimations` calls `ServoStyleSet::GetBaseContextForElement`; `Servo_StyleSet_GetBaseComputedValuesForElement` removes animation rules, creates a fresh context, and calls `resolve_rules_for_element_with_context`. The latter calls `StyleResolverForElement::cascade_style_and_visited_with_default_parents`, then the stylist/property cascade, and returns the resulting Arc. It does not call matching's `finish_restyle`, replace ElementData styles, or enqueue the normal `process_animations` path.

The exact flags are `TraversalFlags::empty()` and `RuleCascadeFlags::empty()`; these are not special root-write suppression flags. Root recognition still reaches `StyleBuilder` through `pseudo.is_none() && element.is_root()`. The root unit conversion branches in `values/specified/length.rs` explicitly use `context.builder.is_root_element` (or media-query conditions) to select a local reference font/line height instead of Device's root values. This is a read-selection rule, not a global root-font update.

Device's actual root-style/font-size/line-height updates occur in `matching::finish_restyle`, after `data.set_styles(new_styles)`. `IS_ROOT_ELEMENT_STYLE` gates the root block. `set_root_style` stores the newly published style; `font_size_changed` gates `set_root_font_size`; `line_height_likely_changed` gates `set_root_line_height`. Used root font metrics may then be recomputed and a descendant restyle hint propagated. The snapshot patch changes only the task-admission portion of matching and leaves this publication block unchanged. A temporary resolver result does not enter that block.

There are narrower mutations on reads. `Device::root_font_size` and `root_line_height` mark their usage booleans. Root metric getters for rex/rch/rcap/ric can set `used_root_font_metrics` and lazily call `update_root_font_metrics`. That method reads Device's already-published `root_style`, not the temporary base style. Resolver rule caches and general font-metric usage/caches also mean the operation should not be called globally pure or side-effect-free. None of these identified paths substitutes the temporary root base font into the root-size value used by descendant rem computations.

Public text discovery found the root-style/root-size setters only in the publication path, and the lazy root-metric update in Device plus that same publication path. ## Minimal preservation diagnostic

A useful one-callback regression test can use an isolated iframe with a CSS font animation holding the root at 32px, authored root font-size initially 16px, and a descendant whose width is 1rem. Confirm composed root font 32px and width 32px. Mutate only root outline, query root style to exercise normal verification, then independently change the descendant width to 2rem and require 64px. Change authored root font-size to 24px while the animation still holds 32px, query root style again, then independently set descendant width to 3rem and require 96px. Keep a literal 32px-root control in a separate iframe.

The independent descendant width mutations avoid a false pass from an already-cached width computed before the root verification task. The diagnostic need not assert disputed root animation-duration initialization or opacity policy. It would cover the direct preservation concern without claiming to solve inherited first-read freshness, font-loading/device invalidation or feedback cycles. No fixture or browser run was produced here, because the direct overwrite route was not found and the immediate work is correcting the separately observed ABI build failure.
