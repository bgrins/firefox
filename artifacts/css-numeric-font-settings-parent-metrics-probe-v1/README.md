# Numeric font settings: parent metrics probe

Prepared, not browser-executed. This probe tests whether admitted length-ratio numbers in font settings use parent or child metrics. It changes no preferences, native sources, installed tests, or existing experiment. No bug or accepted fix is counted.

Root may evaluate the exact `probe.js` expression in a fresh owned `about:blank` tab on each browser and save the returned object, browser identity, and binary/source provenance separately. `probe.html` is an optional local empty host; it does not execute the probe automatically. All generated documents are fresh standards-mode `srcdoc` frames, removed in `finally`; no external resources are requested. Do not run concurrently with the active native owner.

The primary case is `font-variation-settings: "wdth" calc(1em / 1px)`. A registered width-axis tag avoids treating the feature-settings shaping-policy dispute as the strongest lead. This is computed-property testing, not proof that the selected system font implements that axis. Literal `20` and `calc(20px / 1px)` controls distinguish general property support from dimensional-division support. Additional `"XPRB"` variation and feature settings exercise `em` and `ch`; the unused-looking tag reduces accidental shaping feedback but font axis/feature absence is not independently proved.

Eleven property/tag/form cases each record three phases: parent/child font sizes 20/40, 30/40, and 30/60 px. Each phase records the target setting first, then metrics and font controls, and repeats after fonts-ready plus two animation frames: **66 observations**. Parent changes and child-only changes are therefore distinguishable. The metric probes are ordinary width declarations on sibling/descendant boxes with the corresponding font; `100ch / 100` reduces layout quantization. They are not assertions about glyph widths. The `wdth` branch intentionally omits `ch`, avoiding a reference-font feedback ambiguity for a genuinely supported width axis.

`CSS.supports` and surviving stylesheet serialization are both recorded. Rejected syntax is `not-admitted`; a computed serialization that the narrow one-tag numeric reader cannot parse is `unparsed-computed-value`. Neither is a conformance failure. Every raw string is retained. For feature-setting integers the parent/child alternatives round positive numbers to nearest integer; near-half `ch` cases are flagged rather than classified. The 0.03 tolerance is diagnostic, not a general WPT precision claim. `matches-both` and nondiscriminating metrics do not establish a metric source. Require literal/absolute controls, CSS1Compat, actual font sizes, and distinguishable metrics before interpreting relative cases.

`expectedUnderCurrentDraft` implements the explicit current draft rule traced in `SPEC-TRACE.md`. `alternativeChildMetrics` is an independently measured alternative, not a normative oracle or a promise about every intermediate native font state. Feature settings remain separately labeled because CSSWG issue 14306 questions shaping-only members of the category. The historical rule already referred to font-* properties before the August 2026 category rename; this artifact establishes neither a Firefox regression date nor settled cross-engine interoperability.

`SOURCE-MAP.json` pins exact e86 source and excerpts. Numeric parsing is admitted only if the actual browser accepts the expression. Native `FontSettings::to_computed_value` converts every entry before stable sorting/deduplication; `Number`/`Integer` conversion returns a value, not a recoverable rejection result. The source path supplies CurrentStyle for length leaves. That path motivates the probe; it does not prove its runtime output.

Validation is JavaScript syntax, exact source/excerpt/reference authentication, and saved primary-anchor checks only. No browser, WPT, native build, or Lean proof ran in this capsule. The forthcoming conversion-effects contract must preserve all entry conversions (including discarded duplicates), scope and cache effects, and actual AST reads. It must not infer all 21 scanner inputs are prerequisites of every metric or add blanket child-font waits. Font-palette and font-variant-emoji remain separate dependency questions.
