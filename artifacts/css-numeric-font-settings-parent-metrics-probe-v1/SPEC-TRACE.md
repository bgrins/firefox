# Trace: dimensional numeric font setting to metric base

**Verdict: REACHED under the current saved drafts, conditional on parser admission.** Both named properties are expressly in the current font-affecting set, so their font-relative leaves select parent metrics. Browser reachability and observed result are pending. The broader shaping-only membership policy is disputed; the current text and that dispute are separate evidence.

Scenario: an ordinary element with a parent, absolute differing parent/child font sizes, and a declaration such as `font-variation-settings: "wdth" calc(1em / 1px)`. No registered custom properties, font-size inheritance shortcut, root-unit special case, zoom, transition, or scheduler prototype is involved.

1. [Fonts 4 variation settings](https://drafts.csswg.org/css-fonts-4/#font-variation-settings-def) permits a tag paired with a number. [Feature settings](https://drafts.csswg.org/css-fonts-4/#font-feature-settings-prop) permits a nonnegative integer (or on/off). The ordinary-property grammar is distinct from @font-face descriptor restrictions.
2. [Values 4 math type checking](https://drafts.csswg.org/css-values-4/#calc-type-checking) permits math in matching numeric grammar positions. For `/`, the denominator type is inverted and combined with the numerator; length divided by length yields number. Integer positions accept number math and round. A font-relative length remains a length before this cancellation; cancellation does not stipulate a different metric base. Older implementations may reject this arithmetic, which is why admission is measured.
3. [Fonts 4 font shorthand](https://drafts.csswg.org/css-fonts-4/#font-prop) lists feature and variation settings as reset-only subproperties. [Interaction with font-relative units](https://drafts.csswg.org/css-fonts-4/#font-relative) includes “All longhands (including reset-only sub-properties)” of font, excluding emoji and line-height. Neither tested setting is excluded.
4. [Values 4 font-relative lengths](https://drafts.csswg.org/css-values-4/#font-relative-lengths) then selects “the computed metrics of the parent element” in any font-affecting property. `em` uses font size; `ch` uses its specified metric, not general shaped-text width. This scenario has a parent, so the initial-font fallback is not reached.
5. The computed setting is serialized as tag/value. Unknown variation axes can be ignored by the actual font without removing their computed-property value. The probe observes this computed value, not glyph shaping or axis clamping at use time.

This is a grammar/definition/used-base chain, not an event algorithm. Saved `TRACE.log` found no indexed graph route within depth three; that tool result is not semantic disproof. The complete decisive prose and six successful `exists` results are retained in `evidence/`. The initial multi-anchor `exists` invocation was invalid and is retained as `ANCHORS.log`; individual retries succeeded. ## Change history and alternatives

[CSSWG issue 14306](https://github.com/w3c/csswg-drafts/issues/14306) was opened August 11, 2026 to clarify the old font-* category. The saved exact [commit 4f50f67](https://github.com/w3c/csswg-drafts/commit/4f50f67fa049d5786fe1fdd4e3048378fc119f61), dated August 11, changes that name and adds an explicit list; the parent-metric requirement itself appears as unchanged context. This rules out describing that sentence as newly introduced in August. It does not date Firefox's behavior or establish which earlier tests exercised dimensional ratios.

The issue was closed August 25, reopened August 27 after the [shaping-only objection](https://github.com/w3c/csswg-drafts/issues/14306#issuecomment-5442362323), and remains open/Needs Edits in the saved primary API response. The September 11 [follow-up](https://github.com/w3c/csswg-drafts/issues/14306#issuecomment-5627627342) still asks which properties affect only shaping. No final resolution excluding feature settings was found in that saved thread.

[Issue 14396](https://github.com/w3c/csswg-drafts/issues/14396) was opened August 27 and closed September 11. The [closing explanation](https://github.com/w3c/csswg-drafts/issues/14396#issuecomment-5627617686) confirms reset-only membership, removes duplicate list entries, excludes line-height because of its special handling, and leaves palette outside because color does not alter the relevant metrics. This is not a resolution that all shaping properties need parent metrics; nor does it remove the two numeric settings from the current list. The present draft also excludes emoji.

Alternative interpretations to keep distinct: rejection of unsupported dimensional arithmetic; current-draft parent metrics; implementation child metrics; and a potential future narrowing of shaping-only membership. The wdth variation case is the strongest font-metric-affecting lead. The feature-setting case remains useful observable evidence, but does not by itself settle that policy dispute. No patch to native dependency scheduling is proposed here.
