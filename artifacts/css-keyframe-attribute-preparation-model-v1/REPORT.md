This isolated companion closes a preparation/evaluation correspondence gap. It does not prove Stylo, CSS animation context selection, attribute parsing, or cycle resolution. The existing ProviderObservation module proves observation/state and erasure transport after a provider has been supplied. The older qualified-key models prove namespace identity, preload isolation, graph encoding and history noninterference. Neither connects a freshly prepared per-keyframe map to the subsequent real-provider-plus-cache read. No existing theorem is copied or credited again.

Preparation.lean constructs a map from a finite list of fully qualified keys, a supplied element provider, a supplied frame context and an arbitrary partial resolver. The lookup theorem proves exactly which entries exist, including absent preparation keys, missing attributes, duplicate keys and failed resolution. It does not assume the desired output. Its proof reduces the actual finite-list preparation algorithm.

Evaluation deliberately has two gates: the provider must find the attribute, and the prepared map must supply a value accepted by that request's type parser. The direct reference instead calls the resolver on the provider's raw value without a cache. prepared_evaluation proves equality from reference membership alone, for arbitrary provider/resolver/parser functions. frame_correspondence lifts that statement to every request in a frame, and history_correspondence lifts it to arbitrary finite frame histories, with arbitrary provider/context/preparation changes and fresh preparation for each frame. The result retains the payload and taint bit, not just an erased numeric observation. A successful attribute result is tainted; a supplied fallback retains its supplied taint. Neither fallback evaluation nor the security meaning of that bit is proved here.

There are five audited declarations. The preparation lookup is a supporting lemma, frame_correspondence an application bridge, and successful_attribute_tainted an explicit output contract. The useful new high-level obligations are prepared_evaluation and history_correspondence. No canonical registration or normative coverage increment is proposed; there is no duplicate credit for the prior namespace or observation results. The history theorem's list-map lifting is simple: its content is that each element uses the proved fresh preparation algorithm rather than carrying an old map forward.

Nine closed kernel examples exercise the two distinct failure gates, qualified same-local-name lookups, namespace erasure, context history 10→20→0→10, stale map reuse, two distinct type views of one cached value, and preservation of supplied fallback taint. Five deliberately false claims are rejected by kernel decision: dummy provider suffices, no cache needed, namespace erasure safe, old frame cache safe, and successful attribute untainted. These are small implementation-contract witnesses, not browser examples or new defect reports. The stale-map example says only that a map computed in supplied context 10 is not valid for supplied context 20; it does not identify a normative CSS source for either context.

Source mapping and external premises:

- Provider corresponds to the real AttributeTracker query, using the same element snapshot for preparation and evaluation. Mutation between those stages, dependency publication, inactive replay, target selection and pseudo-origin selection remain outside the model.
- Key contains a resolved namespace URI and local name. None means the known null namespace, not an unresolved prefix. Namespace resolution/admission is external. The old namespace proofs already address collisions; the closed aliasing example is only a regression discriminator.
- prepare models the completed, qualified preparation result. The source implementation uses update_attributes_map and substitute_all, with seen sets, nested references and cycle work. The supplied resolver must represent that completed computation for the chosen context. We do not equate a direct function call with the native SCC algorithm by theorem. Eager preparation must not imply that unused fallback edges participate in semantic cycles.
- Preparation coverage is an explicit requirement for every ordinary request. The model does not prove that native declaration iteration discovers the correct roots, that resolver dependency closure is complete, or that shorthand/fallback traversal and iterator resets preserve CSS priority.
- Prepared values precede per-request type parsing. Thus one cached attribute can be requested through different parsers. Resolver and parser failure are permitted. Parsing grammar, invalid-at-computed-value-time behavior and namespace references inside attribute text (the documented bug 2021110 boundary) remain external.
- The source builder resets its map for each keyframe. The model proves isolation under that supplied contract. Which computed context CSS requires is deliberately unresolved here: no claim is made that endpoint custom declarations should provide a frame's context, nor that an unregistered --n with endpoint values .25/.75 normatively implies opacity .5 at the midpoint. Root's Web Animations context question must be settled separately.
- Taint is carried structurally through output equality. The actual substitution-to-ParserContext path, registered-value metadata, URL rejection, serialization, interpolation and fix 70 preservation are not kernel-refined by this model. No security conclusion follows.
