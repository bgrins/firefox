# Final model review

Root authenticated the producer's external seal, manifest, checker and report
before executing any capsule code. A manifest-only copy under a fresh temporary
directory rebuilt the Lean object and every native harness from source. The
replay result exactly matches the frozen receipt; see `ROOT-REPLAY.json`.

## Accepted mathematical component

The reverse planner and indexed executor refine a separately defined forward
setter under unique destination identities. This is not an equality between two
aliases of one algorithm. The proof uses a real target split and derives valid
indices. It preserves the ordered sequence of unrelated entries, membership and
uniqueness, then composes across arbitrary finite action sequences.

The preparation gate is tied to an actual changing intermediate step. The model
retains a concrete case where two moves restore the original final list, so it
does not substitute final serialization inequality for that contract.

Raw storage uses separate declaration and importance lists and a membership
function. Each raw action operates on those fields independently; it does not
encode the desired abstract result. `decode_representation` justifies reading
the next planner state. `arbitrary_raw_sequence`, `arbitrary_raw_prefix` and
`guarded_raw_refinement` compose that relation. Temporary move removal retains
the identity bit, matching the native executor; the public invariant is restored
after append.

The pair-order theorem uses a fixed, unique expansion containing both opposing
identities. It proves the final pair projection equals the expansion projection.
It neither selects an absolute canonical order nor closes CSSWG issue 5741.

## Native connection and trust boundaries

The final model, facade and driver are byte-identical to the last root static
review. Later changes tighten validation, add source filenames to extraction
records and recompute receipts. Complete original/candidate bodies are retained
and re-extracted. The ordinary planner's move into the private helper preserves
its token sequence. The final native candidate and WPT still match the tested
patch pins in `PATCH-INPUT.json`.

The harness executes actual generated property metadata and complete lazy all
iteration, but substitutes containers, custom names, payloads, equality and
preference providers. Its separate forward oracle and strict Python case roster
do not consume native plan decisions. Initial inputs, actions, carried actual
states, field grammar and deliberate early termination are checked independently.
The shared metadata inputs remain a correspondence premise.

Native `PropertyDeclaration` is only PartialEq. The model's DecidableEq is an
admitted congruent abstraction for all-created values; it is not a proof of
reflexivity for arbitrary floating-point payloads or native vector equality.
Six keyword variants, including RevertRule, are typed provider witnesses, not
claims about parser acceptance or release preferences.

The six native mutants compile and produce semantic discrepancies. Six successful
kernel witness theorems explain those discrepancies; no rejected mutated Lean
proof count is claimed. Compiler/kernel implementation, standard libraries,
allocation, native container/layout correctness, full parsing, callback stability,
serialization and rendering remain outside this universal component.

Ordinary batched update code has finite native controls, but its universal theorem
is separate work. The root's later bounded batching exploration and three index
helpers do not enlarge this all-shorthand acceptance.
