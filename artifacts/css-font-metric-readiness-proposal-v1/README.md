# Staged metric-property preparation

This is an unwired native implementation checkpoint against the published cascade (SHA-256 `5b7204f81c999516c617ac05ab619258eb18a05d628845cc1c424f8256013573`). It is not a repair of the observed registered `1ch` failure. The patch adds preparation and publication methods with no call sites; no generated dependency, semantic cycle edge, custom-value computation, or active cascade behavior changes. It does not incorporate the rejected `a6f4` selection candidate. Root reported signed HEAD `a1e0ffba3651cf27853c33d22bb7b1b5368f658f`; the local cascade bytes were independently compared to the frozen published source, without reading Git.

Preparation walks the actual declaration list for weight, width, style, size-adjust and the three orientation properties. It retains a local rollback state and each substituted declaration. An unresolved input returns a request without substitution, publication, global rollback mutation, `seen`, `ensured`, or fixups. A resolved input must identify the exact waiting `Arc`; after substitution, the same owned declaration is retained. Variable-produced rollback advances the local cursor. A terminal declaration stops before lower declarations. Empty and CSS-wide/default chains go through the existing application function when published.

The continuation checks eligibility flags, the property's original rollback state, and prior application before resuming and publishing. Publication consumes the retained declarations once and marks ensured only after applying them. A dependency set supplied by the future scheduler must mean **completed and still final**; the existing early-set `ensured_prioritary` bits cannot supply that certificate. The `Arc` check does not prove resolution in the correct longhand/cascade/context: that caller contract remains unimplemented. Invalidation is reported rather than silently restarting already-performed substitutions; the restart/cache/random/attribute policy also remains an integration obligation.

The missing integration is concrete. Ordinary `ensure_prioritary_property` currently sets ensured before recursively applying its generated dependencies. `traverse` then pops its semantic SCC before applying a non-custom property and returns `None` unconditionally. A generated dependency returning Pending must be propagated through both boundaries; semantic graph closure cannot certify a computed value is ready. The final priority loop and custom-property finishing must drain resumable work. This patch does not do that, and must not be wired by treating a pending read as successful. No speculative DFS snapshot/restore or parent-metric cycle policy was added.

The seven supported preparation IDs are **not** a complete font-metric prerequisite inventory. The current metric query passes the whole font to the device. `FONT-INPUTS.json` authenticates the generated priority mapping and selected metadata: variation settings, optical sizing, feature settings and language override are font fields outside the current priority set. Their actual influence on glyph metrics and required readiness remains to be traced; absence from this API is not evidence of irrelevance. Family, language, zoom, size and default/inherited paths also need final-value certificates. No four-field completeness claim is made.

`DESIGN.md` preserves the size/metric false-cycle discriminator, the unresolved genuine cycle case, and the generated LineHeight reentry counterexample. Current specification issue 9517 leaves registered font-unit circularity unresolved. This does not excuse the observed acyclic metric failure, but it prevents claiming a normative result for a newly invented cycle policy.

Validation: rustfmt parses/formats the complete candidate; zero-fuzz patch forward/reverse and exact removal of the added block recover the published source. Four isolated Rust tests exercise the exact added methods, with `Vec` replacing `SmallVec`, standard `Arc`, and explicit test doubles for native declarations, priority ordering, substitution and application. Six mutant programs compile and fail assertions. The completed-state test independently changes flags, seen, rollback, ensured and prerequisite completion between preparation and publication. These tests do not parse CSS, resolve real attributes/aliases/cycles, validate Gecko defaulting, or typecheck Stylo. Native typechecking may reveal additional API or lifetime issues. Initial test-double compilation errors and the subsequently fixed real continuation-return lifetime error are retained.
