This diagnostic captures ordinary and registered container-unit behavior on the unaccepted admission-only build2 candidate. It does not assert numeric container-unit results or accept a native fix.

Open report.html directly for a standalone page; results appear as JSON and window.containerZoomResult. The owned runner uses the same page with ?submit=1 and posts its capture to a private loopback route. There are 42 scenarios with 94 initial target observations, plus three sequences with ten snapshots and 30 target observations. Each mutation sequence retains its existing nodes. Two animation frames precede each measurement. All registrations have distinct names, inherit:false and initial-value:17px. Registration failures are retained, not misclassified as dependency defects.

The page copies CASES.json and PROTOCOL.json from the sealed design. It measures viewport and ancestors before targets, then the registered value before ordinary computed properties, client/offset dimensions and DOMRect. Raw CSSOM strings and numeric geometry are preserved; deltas are recomputed by validate.py. The fixed, clipped stage has no size containment; explicit-size relative ancestors contain absolutely positioned sibling targets. This prevents target sizing from changing the selected container dimensions. The optional reversed-query-order design extension is not implemented.

PRIOR-ART.json records bug 1894104, whose description identifies existing zoom handling work for ordinary container units. Ordinary/registered parity is diagnostic evidence, not a normative oracle. The sealed design's SPEC-TRACE.md also records why CSSWG issue 10268's query-condition resolution does not by itself determine all cross-zoom unit results. No new bug or severity claim follows from this package.
