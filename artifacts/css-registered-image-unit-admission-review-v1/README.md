# Image unit admission versus selected scheme refinement

Static assessment: the frozen combined V5 and image-only postimages do retain FontUnits and LhUnits dependencies for the three supplemental absolute-color image probes. Removing COLOR_SCHEME does not remove those unit bits. The original direct-image path can compute before graph traversal; the new image marker changes admission so the existing walker actually collects the unit dependencies. This is a source argument and testable prediction, not an observed combined45 result.

The path is explicit in the pinned bodies:

1. Parsing a gradient's nested function body uses the same `References` accumulator. Dimension tokens call `ReferenceFlags::from_unit`; `em` adds FONT_UNITS and `lh` adds FONT_UNITS plus LH_UNITS. These bits exist even when the value contains no var/attr references.
2. Original `find_non_custom_references` includes unit bits only for LENGTH-capable registration syntax. The root-admitted `DataType::Image` mapping is empty, so a pure Image declaration without substitutions can miss graph admission. The original `cascade_custom` early path then computes the image immediately. Root capture SOURCE.json joins the exact datatype body to HEAD ecfe; its 693d5011 hash is also byte-identical to the historical frozen copy. The retained cascade/provider operations are exact frozen patch preimages. The extra historical syntax-union excerpt is context, not a separate new whole-tree admission.
3. Combined V5 admits Image using COLOR_SCHEME as a deferral marker. Image-only does the same only for Image without COLOR eligibility. During `traverse`, `visit_value_references` unconditionally ORs the root's `refs.flags` before iterating its substitution references. An empty reference list therefore does not lose the image's direct unit flags.
4. The new preparation block removes only COLOR_SCHEME. For an absolute red/blue gradient the selected classifier does not put that bit back, but FONT_UNITS/LH_UNITS survive. `for_each_non_custom` visits FontUnits and LhUnits; the line-height node also links font-size. Non-custom nodes apply the appropriate priority properties before the custom node's final retained-AST computation on this acyclic path. No scheme dependency is needed to carry these unit edges.

For the direct probe, the source predicts image computation with the target's own font/line-height after these edges, rather than its inherited parent metrics. For the inherited probe, the important scheduling site is the parent's own direct registered image: that image must compute using the parent's explicit metrics before the target copies its computed value through `var(--missing, inherit)`. Recomputing the copied image against the target would be wrong. The existing CSS-wide parent-copy route is not changed by this diagnosis.

The typed-attribute probe already has ATTR in its top-level references and therefore enters the original walker independently of Image's syntax admission. Its root `1lh` and resolved attribute `2em` supply flags through the existing walker. That distinguishes its provisional PASS from the two provisional failures without inferring that a ColorScheme dependency was present. The fixture deliberately uses only red/blue colors and a separate literal width calibration for typed attr support.

The earlier CanvasText image tests could exercise different scheduling because they retain a real scheme edge and use different values. This review does not infer that their PASS proves correct unit scheduling, or that any one priority property incidentally masked another. The direct root-flags path above supplies a concrete independent reason to expect the new probes to improve.
