# Root reference selection and provider ordering

This separate Lean extension models two obligations exposed by the saved root-animation ordering experiment: selecting the correct initial/current-root reference, and obtaining a current provider result after invalidation. It does not identify the native cause of those observations or validate either native repair candidate.

The existing `CssRelativeUnit` library classifies unit spellings. Its residual resolution relation consumes a supplied numeric environment without deriving its freshness. `FontConsumerDemand` proves sufficient input projections against a fixed final tuple; the phase/readiness extensions require finality certificates. The separate 18-audit animation admission model derives exact-target membership and conservative admission through cancellation/retarget histories. It has no metric provider or conversion state. Admitting a recascade, establishing current metrics, and rebuilding a consumer remain distinct obligations.

`Provider.lean` reuses the exact `FontConsumerDemand.FontState`, `Inputs`, and `reads` primitive. Its bounded reference relation covers rem/rlh in font-size, line-height, and ordinary length conversion. Root font-size selects initial metrics for both units; root line-height selects initial line-height for rlh but the current root font size for rem. A root-host pseudo is a separate target and selects current root metrics. Other font-affecting properties, parent-relative units, media queries, axes and normal-line-height calculation are outside this relation.

The provider protocol has a semantic revision, desired metrics, a cached publication and at most one retained request. `begin` snapshots the semantic revision and desired tuple. `invalidate` advances the revision, changes the desired tuple and retains the old cache/request. `finish` publishes only a matching-revision request; it discards a stale request without replacing the cache. A cache read requires the current revision. These are executable transitions, not assumptions that every read already equals the desired value.

The proof derives record coherence for every finite sequence of these transitions. From that invariant, every successful selected read equals its current semantic reference. Equal values at different revisions do not authorize an old reply. Requests do not restart while outstanding, and a stale completion cannot silently become current. The provider may remain unavailable indefinitely: no fairness, native progress, or eventual delivery theorem is claimed. With no intervening invalidation, begin/finish establishes a current provider; after a stale request, discard/begin/finish does so. These are conditional finite traces, not a promise that a native scheduler executes them.

Initial-reference reads do not wait for this provider. Current-root reads, including pseudo reads, do. The executable witness separates both defects: refreshing a dirty provider makes the child read current while the root still must select initial metrics. A wrong root identity cannot be repaired merely by refreshing the provider.

These observations motivate the distinction but do not reveal Device cache contents, native revision numbers, flush counts or a unique source cause. The model uses unscaled integer metric witnesses16/23/32; its line-height19 is abstract and is not the measured19.2px oracle. It does not reproduce browser interpolation or feedback arithmetic.

The native mapping must establish all of the following:

- Correct target and property classification, including root-host pseudos and the applicable root-unit exceptions.
- Every relevant semantic change invalidates the provider revision before a dependent conversion can read it. Cancellation is modeled as such a change only when its underlying metric state actually changes.
- `begin` corresponds to a certified snapshot of the selected semantic inputs. Copying `desired` here is a specification operation; no theorem says the native Device currently contains that tuple. Native asynchronous computation, fonts, zoom and line-height derivation must produce the captured revision's tuple before completion is represented by `finish`.
- Requests and publications retain the same provider identity and revision. The natural-number revision has no wraparound; the model concerns one fixed document/provider lifetime, so destruction/reuse requires a separate identity mapping.
- Native operations refine these transitions, including atomicity and rejection of late completion. A provider revision covers the whole tuple, conservatively; selective per-metric invalidation is not proved.
- Admission/event delivery actually schedules provider work and conversion. Previously computed keyframes must be invalidated/rebuilt; this model proves newly performed selected reads, not freshness of old consumer caches or a compositor result.

The selected reference relation is a specification-side subset of the saved Values4 trace. It is deliberately independent of the old native `is_root_element:false` route. `SOURCE-MAP.json` pins the exact existing source/trace records and distinguishes correspondence obligations from proved transitions. No Boolean setter, native font semantics, browser acceptance, live source, canonical coverage or accepted-fix count is changed.
