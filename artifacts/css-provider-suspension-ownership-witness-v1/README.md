# Distinct continuation ownership witness

The earlier readiness model tracked a retained property owner but did not distinguish two continuations for that property. This small successor checks the missing ownership condition: only the continuation that holds the suspension may release it. Six declarations and two false-proposition controls pass the pinned Lean kernel; no Rust refinement, borrow-checker or complete scheduler theorem is claimed.

The source review found unowned resume/Drop removal in an unsealed draft of provider-v3. Read ccc57f showed resume removing suspended_prioritary[id] without a per-instance ownership field, and Drop doing the same. Important correction: the author pointed out that the ordinary ensure entry already asserted against an existing suspension. That ordinary-entry scenario would panic before clearing, not silently reapply. The bad primitive nevertheless allowed a directly constructed second continuation to clear the first marker. The model's unownedResume represents that primitive, not a complete ordinary native call trace. No shipped bug or browser failure is claimed.

The final sealed provider-v3 adds a checked constructor that rejects Applying/suspended ids before acquiring the marker, an owns_suspension field, owner-only release in resume/Drop, and an ownership assertion for servicing dependencies. Review229b64/0 plus3b8bee/0 verified the correction and sole constructor call. In this single-threaded borrowed owner design, checked acquisition plus local ownership corresponds to the distinct model identities; that correspondence is a source-review argument, not a native theorem.

The model abstracts one property, with an optional owning continuation identity. It proves foreign release preserves the marker, any successful release identifies its owner, foreign resume demands, and owning retry may release. Two concrete identities distinguish the formerly conflated states. It does not model allocation, lifetime checking, panics, actual Tarjan lowlinks, context completion, default selection or effect rollback. Actual code still has only a None readiness caller; a real demand scheduler and complete initial-context certifier remain absent.

Bounded provider-v3 source review also checked declaration-selection staging (cache/attributes/revert/winner bookkeeping), classification-at-construction forcing Invalid for invalidated participants, borrowed registration identity, current parent reads, and the default-false initial_context_ready hook. These close specific prototype gaps, not all integration requirements. The prioritary-only set is insufficient without external-context stability, as the separate complete-context review demonstrates. No native compile was run by this reviewer.
