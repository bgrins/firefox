Current [Animations 2 processing](https://drafts.csswg.org/css-animations-2/#processing-keyframes) groups by declared computed timing values and falls back when no declaration exists. [Animations 1](https://drafts.csswg.org/css-animations-1/#timing-functions) describes the property as non-inherited with initial `ease`. If ordinary property defaulting applies here, `initial` and `unset` would select `ease`; `inherit` would select the inheritance parent's computed property, not the target's underlying/default curve. [Cascade 5](https://drafts.csswg.org/css-cascade-5/#inheritance) defines that parent through the flattened tree, with pseudo-element rules separately applicable. This is a conditional implication, not an established keyframe descriptor oracle. A single-valued parent avoids a further list-selection ambiguity.

The critical newer history is [CSSWG issue 14096](https://github.com/w3c/csswg-drafts/issues/14096). Discussion proposes replacing the special keyframe properties with corresponding descriptors having singular syntax. CSS-wide keywords are automatically supplied to properties by [Values 4](https://drafts.csswg.org/css-values-4/#common-keywords); that rule does not establish the same allowance for a descriptor with only `<easing-function>` grammar. The proposal therefore challenges the premise of the source lead. The issue does not explicitly resolve `initial`, `inherit`, or `unset`.
