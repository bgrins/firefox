# CSS logarithm boundary review

This bounded primary-source review establishes the text and its origin, but does not resolve the intended behavior at base zero or argument zero/infinity with a base between zero and one. No browser, native, build, Git, index, or canonical-state operation was performed. No issue or external message was submitted. The earlier sealed log audit remains unchanged.

The [current CSS Values argument-range rules](https://drafts.csswg.org/css-values-4/#exponent-infinities) explicitly assign argument zero negative infinity, argument one positive zero, and argument positive infinity positive infinity, without qualifying these results by the base. They also permit bases strictly between zero and one. Base zero is omitted from the explicit invalid-base condition, which covers one and negative values. The source capture is hashed; its `main` URL is mutable.

The [original specification commit](https://github.com/w3c/csswg-drafts/commit/57591b1fb0498885d1089ddd53debe0cc63259dd), dated 23 January 2020, already has all these boundary clauses. Its message attributes adding log/exp to a working-group resolution but gives no resolution link. This review did not locate the underlying discussion. The current paragraph moves the invalid-base rule before the argument rules; this review does not attribute that later edit or claim an exhaustive history.

[WPT PR 62956](https://github.com/web-platform-tests/wpt/pull/62956), merged 25 September 2026, adds base-zero NaN expectations and the positive-zero expectation for `log(1,.5)`. Its argument-zero/infinity tests use the default base or base two, leaving the below-one combinations untested. The five captured inline review comments concern NaN citations and additional coverage; they do not explain base zero or settle the below-one boundary question. The earlier [WPT PR 35941](https://github.com/web-platform-tests/wpt/pull/35941) fixes an ordinary sum, not these boundaries.

The current wording is direct evidence for the specified exceptional values; the unresolved issue is whether those values are intentional overrides of logarithm limits. Mathematical reasoning alone must not silently replace them. Likewise, a WPT NaN expectation is not a substitute for a missing base-zero rule, especially when its computed-value observer also accepts a zero result. The WPT helper uses `scale` for `type: number`; our exploratory and model observer uses opacity. The predecessor audit documents that observer limitation and exploratory System Firefox observations; neither is new branch evidence here. Literal `-0` is not a generated CSS negative zero.

The precise questions are in RESULT.json: explicitly define both zero bases and precedence; confirm or correct the infinity signs for `0 < B < 1`; confirm the explicitly positive result zero for argument one. Recommend deferring the first two from an acceptance oracle until clarified. Base-one invalidity and argument-one positive-zero behavior can be investigated separately with the existing complete observer, without importing those unresolved expectations.
