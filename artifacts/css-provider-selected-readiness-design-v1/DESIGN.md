# Selected provider readiness and target-context defaults

Recommendation: reuse the parked demand transport, but move default preparation and provider settlement into the ordinary cascade owner. Do not make recursive substitution choose a document-cached initial or immediately compute an initial against a partially prepared Context. This is an implementation design, not a compiled patch, spec-admission decision or proof of native correctness.

## Concrete current boundary

The two partial-v5 sources and accepted computed::Context capture match the saved actual input epoch byte for byte (SOURCES.json). The parked sources are separately authenticated by RESTORATION-PLAN and are not active. No browser result is predicted as already observed here.

`substitute_one_reference` recursively reads an unresolved universal entry from `ComputedSubstitutionFunctions`. On registered grammar failure, missing substitution or a marked cycle participant, it calls helpers which select `Stylist::get_custom_property_initial_values()`. That cache can contain a document-context result. In contrast, restored ordinary `handle_invalid_at_computed_value_time` calls `compute_value(initial.css, initial.url_data, registration, target_context, ...)`. An inherited non-root computed value is a different case: the parent's finalized value should be copied, not recomputed against the child.

`ensure_prioritary_property` inserts the ensured bit before traversing dependencies and calling `apply_one_prioritary_property`. The latter invokes `apply_one_longhand`, whose substitution happens before `seen.longhands` insertion. This is the practical suspension point. `LineHeight` schedules FontWeight, WritingMode and other properties via the real dependency table, while the current SCC `NonCustom` nodes cover only FontUnits/LhUnits/ColorScheme. Consequently an early FontWeight consumer can read an unresolved registered provider outside the provider's finalization order.

The Context exposes mutable builder state and interior mutable caches/effects; an immutable `&Context` is not evidence that its required values are ready. The accepted `with_registered_value` closure only controls canonical length representation and nested/unwind restoration. It does not establish scheduling readiness.

## Reuse instead of a second mechanism

The parked prototype already defines `SubstitutionDemand::{Provider(Name), Attribute{...}, Prioritary(PrioritaryPropertyId), ContextPreparation}` and `SubstitutionError::{Invalid,Demand}`. Recursive demand propagation there bypasses fallback. `first_pending_prioritary` traverses existing prioritary prerequisites. Extract these interfaces and their propagation, rather than importing the whole parked keyframe/animation implementation or restoring all 50 native files.

Two parked shortcuts must not be carried forward: its invalid-substitution handler runs before the pending-context gate, and its CSS-wide initial branch also returns before that gate. Both can publish a default before its context is settled. Its lexical `find_non_custom_references` gate is not a complete proof of dependencies of the selected typed initial. A syntax-name whitelist, the existing conservative registration mask, or a post-simplification AST alone cannot supply that proof.

## Minimal API changes and control flow

1. Replace recursive default materialization with an owned classification: inherited computed value, selected initial specified value, final universal invalidity, or selected specified value. Preserve the provider name, registration identity, URL data, attr taint and required effect flags. Keep a distinct cycle-participant state; default values never erase that mark.
2. Give substitution an explicit readiness view. A selected unresolved registered provider produces `Demand::Provider(name)` before returning raw tokens or selecting fallback. A ready invalid universal provider may select fallback. A registered provider whose final computed value is its initial is Ready only after that initial is finalized. Map absence alone must not mean both 'missing' and 'still pending'.
3. Propagate Demand through `substitute_variables_if_needed` and the declaration substitution boundary to `apply_one_longhand`, then through `apply_one_prioritary_property` and `ensure_prioritary_property`. Do not convert Demand to ordinary parse failure, an invalid shorthand cache entry, CSS-wide unset, or a lower cascade candidate. Preserve the same declaration/priority on retry, including revert handling.
4. Replace the overloaded ensured bit with separate Applying and Ready states. Ready is set after actual longhand application and `did_apply_prioritary_property`. No `seen.longhands`, author-specified bit, revert bookkeeping, shorthand cache result, computed map entry or style effect may certify a suspended consumer as applied. Borrowed substitution results/state must be dropped before the owner mutates Context; demands carry owned Name/attribute data.
5. The owner resolves the demanded provider through the same SCC traversal that owns its declaration, then retries the selected consumer. If that provider is still on an open SCC stack, it is pending rather than invalid. Complete participant classification before publishing each participant's own registered default. The nonparticipant outside consumer then reads the finalized default.
6. Initial computation is another prepared plan. Resolve the actually selected initial's required context, then invoke the existing registered computation path with the target Context. Use its accepted canonical registered-value scope; do not change builder zoom/font data or serialize raw initial tokens into the consumer's grammar. Preserve one typed selected representation across suspension where feasible, to avoid selecting a different grammar alternative or repeating parsing effects.

A practical first code cut is provider demand propagation and the Applying/Ready split. The second is a shared `prepare_registered_default`/`finish_registered_default` used by ordinary and recursive resolution. Both cuts must land together if the first alone leaves contextual default publication unsafe. The existing dynamic substitution interface above is reusable; declaration-substitution return-type plumbing outside the authenticated cascade capture still needs implementation inspection and typechecking. No compile-plausibility claim is made for the illustrative interface sketch.

## Context requirements and cycle policy

Do not run every prioritary property before every initial. That introduces false prerequisites and can manufacture cycles. Derive scheduling obligations from the actually selected specified value/default and the context reads its computation performs, including font metrics, writing mode, color scheme, zoom and container-axis selection where applicable. Retain selected lexical obligations when a parser simplification erases a context-dependent expression; the earlier sign/zero findings prevent treating a context-free-looking AST as sufficient evidence. Invalid CSS grammar must choose a default before collecting obligations for the rejected value.

Prefer explicit computation-readiness requirements at the relevant registered computation boundary, with a completion certificate for the selected representation; a generic `ContextPreparation` marker alone cannot tell the owner what to finish. If required reads are not yet covered, that is an implementation blocker to general acceptance, not permission to treat the set as empty or substitute a cache. This requirement is independent of syntax kind: lists, transforms, images, numeric math and colors stay supported.

Scheduling prerequisites and semantic cycle edges are different. Keep existing SCC links and their policy intact when transporting demands. Do not mechanically add every PrioritaryPropertyId dependency to the invalidating SCC graph: the fixed-line-height/variable-writing-mode counterexample already disproves that shortcut. Reentering an Applying property indicates unresolved scheduling, not by itself a spec-authorized invalidation. Genuine selected substitution reentry still marks all participants; the A→B→A cycle with A's fallback reaching acyclic C must not be rescued by C's newly available default. Where a new context-read backedge needs normative adjudication, record that limitation rather than silently expanding cycle policy.

## Taint, effects and retry ownership

Keep attr taint on owned prepared substitutions, computed inherited values and retry continuations; preserve namespaced attribute identity and raw versus typed attr semantics. Reset/discard taint only where the actual default-selection algorithm does so, not because a retry occurred. Selected URLs retain the provider's URL base. `INHERITS_RESET_STYLE` for explicit inheritance, dependency tracking, rule-cache conditions and attribute tracking must be committed or accumulated coherently; a failed speculative attempt must not insert a final cache/result. Parse once or record an explicit effect journal if preparation has effects. Tree/context generation changes invalidate a continuation; retries cannot reuse a result after color-scheme/zoom/provider mutation.

## Admission remains a separate question

The contextual @property initial probes are conditional. Their acceptance by the current engine does not settle whether CSS registration rules should admit them. The separate JS registerProperty independence work must determine admission and preserve selected-alternative semantics. Rejecting a currently accepted initial is not a substitute for making ordinary and early recursive consumers agree on a target value. Conversely, a scheduler repair must not be credited as fixing admission. Preserve both result sets and report conditional behavior separately.

No additional Lean theorems or normative coverage are claimed. Existing guarded-cycle and readiness models specify useful conditional laws, but do not prove parser effects, actual scheduler progress or production correspondence.
