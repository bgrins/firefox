# Registered unit-fallback policy model

This artifact proves consequences of two explicit unit-dependency interpretations. It does not decide which interpretation the specification requires. The parent reports both installed Firefox158 and Chrome156 produce registered0px/inherited font for the defined-primary probe, while the genuine-cycle and literal controls pass. Those shared observations motivate the comparison; this package does not replay or authenticate their runtime evidence and does not call them an interoperability difference or an accepted bug.

`UnitFallback.lean` imports the unchanged `Demand.lean` and five unchanged CSS model modules, authenticated by `IMPORT-PINS.json`. The eight audited theorems have these scopes:

- `successful_primary_classifier_independent` lifts the existing demand evaluator's successful-primary theorem through **any** classifier. For arbitrary fallback expressions, stack, cyclic set, fuel and successful result, changing the unused fallback cannot change a classifier of that result. Successful evaluation is a premise; this is not a proof that the native scheduler can first obtain that result.
- `retains_all_base_edges` and `retains_base_cycles` preserve an arbitrary supplied custom-reference graph when a unit edge is added. This applies whether that supplied graph follows the historical eager fallback-reference rule or the current substitution-context rule. The unit model does not silently remove custom-reference edges.
- `path_decreases` is an arbitrary-type rank lemma for nonempty paths. `cycle_iff_unit` uses it to characterize all path lengths in the two-node registered/font graph, with the genuine font→registered read present under both policies. Reflexive reachability without an edge is not a cycle.
- `missing_primary_policies_agree`, `defined_absolute_separates`, and `selected_relative_cycle_preserved` compare selected-output classification with conservative fallback inventory for the abstract Px/Em grammar, for arbitrary natural magnitudes. Defined absolute primary plus unused em separates the policies; missing primary plus selected em remains cyclic under both.

The concrete graph projects away the primary's independently resolved, terminal absolute value. It does not prove that projection for a primary with its own dependencies, SCCs, CSS-wide/default behavior or inheritance. The generic graph-preservation theorems remain available when those dependencies are supplied explicitly. Length is an abstract two-constructor semantic datatype, not a token parser: no claim about strings containing unit-looking text, other units, percentages, nested images, typed attr conversion, unions, zero-unit simplification or real computed-value serialization is made.

The `lexicalInventory` policy is narrowly the selected value's unit flag OR the literal fallback flag. In this probe it models the extra unused-em edge and predicts a cycle compatible with both parent-reported engines. It is not a model of either engine's full lexical parser. Neither policy computes the observed default0px or inherited11/17px; those endpoints require separate defaulting semantics.

## Specification boundary

Fresh current primary reads and tool limitations are recorded in `PRIMARY.json`. [Variables ED replacement](https://drafts.csswg.org/css-variables-1/#replace-a-var-function) requests the primary computed value and evaluates fallback only on invalid primary. [Values5 property replacement](https://drafts.csswg.org/css-values-5/#property-replacement) substitutes before parsing, and its [ordering rule](https://drafts.csswg.org/css-values-5/#resolve-property) puts substitution before other transformations/introspection. These support a selected-output interpretation.

[PVAPI relative-unit cycles](https://drafts.css-houdini.org/css-properties-values-api-1/#dependency-cycles), however, still expresses an additional edge constraint using whether the property contains relevant units, without naming the phase at which that predicate is evaluated. Interpreting this edge classification as introspection after replacement is the substantive integration premise. Alternatively, treating it as a scheduling constraint while obtaining computed values yields the inventory policy. The model exposes the different consequences rather than assuming the former to prove itself.

**Normative bridge verdict: INCONCLUSIVE in this package.** The current pre-introspection rule is evidence for the selected interpretation, and no contrary current explicit unused-unit rule was found in the sections read. A complete registered-computation integration argument or CSSWG clarification is still needed before calling the shared behavior a specification violation. The sealed probe's stronger REACHED interpretation is retained unchanged, not silently rewritten. This kernel result cannot settle that timing bridge; the current independent reassessment also treats it as unresolved.

The [2022 Variables CR](https://www.w3.org/TR/2022/CR-css-variables-1-20220616/#cycles) explicitly counted var references in unused fallbacks. Current Variables ED replaces that graph description with substitution contexts, following [issue11500](https://github.com/w3c/csswg-drafts/issues/11500). A historical eager custom-reference rule must not be passed off as current ED text, and its presence would not by itself settle the distinct literal-unit question. This model preserves supplied custom edges under either policy.

## Actual verification and integration

Run2 completed in actual session39475/76bfa6/660b38/0 with eight theorem audits and four genuinely false propositions rejected by Lean's `decide`. Audits report only standard axioms (see `run2/Audit.log`), with no sorry or native-reduction axiom. Run1's proof-script errors are retained. False controls refute policy equivalence, ignoring a selected fallback, ignoring lexical unused units, and selecting fallback despite a valid primary. They are semantic model controls, not native mutation tests.

Reproduce only into a new output directory: `python3 -I -S artifacts/css-registered-unit-fallback-model-v1/replay.py run3`. The script authenticates the pinned Lean binary and imports, compiles in owned temporary storage, retains all commands/logs, and removes that storage.

Minimal integration is a new module importing the existing demand evaluator, after the unit-timing policy is resolved and its premises are reviewed. No existing nested module, canonical coverage count, native source, fixture, browser or control is changed here. A native refinement would separately need selected semantic-unit classification, unchanged required custom-reference edges, scheduling before computation, cycle/default publication, and metadata preservation. Replacing raw token scans alone is not established as sufficient.
