# Enclosing grid-template transaction

This four-source successor preserves all three v2 candidate bodies exactly: the ParserContext counter transaction, registered whole-alternative handling, and seven typed numeric finalizers. Its only additional change wraps grid::parse_value's existing speculative grid_template::parse_grid_template call with the same counter rollback helper, outside cssparser try_parse. Source and syntax/transport validation only; no live installation, build, native acceptance or new bug count.

The successfully parsed row AST can be followed by a rejected template-column grammar. In that case every row/column/area value is owned inside parse_grid_template and discarded on Err; the caller assigns its local longhands only after Ok. The first ordinary track-list branch stores template_rows locally, consumes '/', and then parses template columns. The accepted auto-flow fallback reparses the rows after the failed whole-template attempt. The typed row parse itself succeeded, so typed-finalizer transactions correctly retain its counter increment and cannot repair this later rejection. The new outer transaction restores the entry counter only on that enclosing Err. A successful explicit-template parse keeps all its indices, and prior successful nested increments are not reset to zero.

The wrapper adds no output mutation or new parsing call. Existing local vectors, line names, TemplateAreasParser and temporary Arc values are returned only through the Result; no failed output is published into the longhand result. The shared parser context and ordinary parser side effects are otherwise unchanged. This is specifically random_count rollback, not general rollback of allocations, use counters, diagnostics, arbitrary context state, or panic unwinding. The later row-prefix trial and nested grammar speculation remain separate audit boundaries; this change does not claim all CSS speculative callers are transactional.
