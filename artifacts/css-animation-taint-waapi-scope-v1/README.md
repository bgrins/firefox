# Script-keyframe scope of the animation-origin producer

The compile-corrected producer includes script-generated animation effects. Frozen `CascadeOrigin::Animations` explicitly covers CSS and script effects, and the V2 producer tests that origin. `is_animation()` would additionally include SMIL and transitions and was correctly avoided. The current 106 callbacks exercise CSS-keyframe producer cases; they do not validate this script-generated scope.

Current Variables Level 1 and Level 2 define the taint producer by use in an `@keyframes` rule. Their var replacement guard then rejects a tainted custom property in a non-animatable sink. Pure script keyframes with no corresponding CSS rule do not directly satisfy the stated producer condition. This is a boundary in the inspected wording, not proof that script animations must be exempt. [Variables 1](https://drafts.csswg.org/css-variables-1/#animation-tainted), [Variables 2](https://drafts.csswg.org/css-variables-2/#animation-tainted), [replacement guard](https://drafts.csswg.org/css-variables-1/#replace-a-var-function).

Web Animations permits unregistered custom properties with discrete animation behavior. Its compositing algorithm adds the resulting value to the animation origin by default. That explains why the native origin test reaches script effects; it does not itself define animation-taint metadata. The inspected keyframe-processing, custom-property and compositing sections did not establish an explicit bridge from script keyframes to Variables' @keyframes predicate. A missing-term search alone is not the evidence for exemption. [Custom properties](https://drafts.csswg.org/web-animations-1/#custom-properties), [keyframe processing](https://drafts.csswg.org/web-animations-1/#processing-a-keyframes-argument), [composited result](https://drafts.csswg.org/web-animations-1/#applying-the-composited-result).

CSSWG issue 13933 remains open and explicitly distinguishes the written property-name rule from Blink's active-value implementation. That discussion does not resolve pure-WAAPI scope. The broader side-effect issue 6398 includes Web Animations in its motivating scope but is not an adopted taint algorithm. [Issue 13933](https://github.com/w3c/csswg-drafts/issues/13933), [issue 6398](https://github.com/w3c/csswg-drafts/issues/6398). Primary sources read on 2026-10-30.

Verdict: **INCONCLUSIVE** for whether a pure script-generated custom-property effect is normatively required to taint its result. The shared animation-origin applicability is established; a normative producer bridge is not. Do not call origin-wide taint a preservation-only change or accept it solely on CSS-keyframe test results.

A narrow separate probe should use three fresh iframe documents so a CSS @keyframes name cannot contaminate the pure-WA case under property-name semantics:

1. Pure WA: no CSS @keyframes rule anywhere in that iframe; ordinary `--v: vertical-rl`, `writing-mode: var(--v, vertical-lr)`. Create `target.animate([{ '--v': 'horizontal-tb' }, { '--v': 'horizontal-tb' }], { duration: 2000, fill: 'both' })`, pause, await ready, then seek 750. Record sink before any timing/member read, then three passive samples and full details. The active value must calibrate horizontal-tb and time/progress 750/.375. The sink observation distinguishes animated-value use (horizontal-tb) from fallback (vertical-lr); neither is assigned a normative PASS oracle yet.
2. Matched CSS control: same values/timing via a constant CSS @keyframes animation in its own iframe. This preserves the existing active-keyframe taint question with the strongest written producer basis.
3. Literal sink: vertical-lr with the same pure script driver, calibrating the proposed fallback geometry/value and driver operation independently.

For each arm record the base-only state before creation and the state after cancel plus an ordinary style flush; ordinary --v and sink are vertical-rl for the two var arms after the effect is removed under an active-value interpretation. Record that cancellation result diagnostically for the CSS arm because name-global taint wording remains disputed. Check no remaining current animation after cancellation, with the cancelled effect object retained only for identity diagnostics. Preserve all observations before assertions and keep any unexecuted scope verdict explicit. A script setKeyframes removal control can follow if needed, but is not required to establish the initial origin-scope distinction.

This is a proposed observation protocol only: no fixture, runner, browser/native operation, new model, or change to the 106-case trial was made. Cross-engine agreement would inform compatibility but would not resolve the specification bridge by itself.
